## TL;DR

- **General DSA-pipeline optimizations (backend-agnostic — GLM-5.2 & DeepSeek-V3.2):**
  End-to-end on 8×H200 (TP8/EP8/DP8), the bf16 FlashMLA baseline itself gains +8.8–10.3%
  saturated throughput and +4.4–6.3% single-request TTFT (positive = faster) on GLM-5.2,
  and +4.3–6.7% saturated throughput on DeepSeek-V3.2 (DS TTFT ~flat at +0.3–0.9% — the DS
  pipeline gain lands almost entirely in throughput; see table), across 3.5k–160k context.
- **Q8KV8 vs the already-optimized bf16 FlashMLA baseline** (measured on this
  PR's head, both arms fp8 KV): GLM-5.2 single-request TTFT +9.6–13.6%, saturated throughput
  +3.4–6.8%; DeepSeek-V3.2 TTFT +8.1–20.9%, saturated +5.0–10.1% across 3.5k–160k context.
- **Net effect vs out-of-the-box bf16 baseline** (upstream defaults vs this PR's
  recommended config + code): GLM-5.2 saturated throughput **+13.1–17.5%**, TTFT
  **+14.4–20.0%**; DeepSeek-V3.2 saturated throughput **+9.5–17.4%**, TTFT **+8.4–21.3%**.
- **Accuracy q8 vs q16 (shipped lossless config):** gsm8k per-rung Δ +0.3 to −0.6% across the
  shipped-config and PR-head ladders (full 1319q/rung, σ ≈ 0.3–0.6% — parity); forced-sparse
  MMLU (N=14,042, every question through the sparse kernel) +0.26% (within 1 per-arm SE,
  ~0.33%); LongBench-v2 −0.8 to −1.0% (σ ≈ 0.8–1.5%; an earlier unoptimized-config
  measurement was −2.3%) — within 1σ. DeepSeek-V3.2 gsm8k −0.6% (≈1σ).

## Motivation

DeepSeek-V3.2's Q8KV8 fp8 sparse-MLA prefill path (#25751 kernel, #30514 DSA integration — both now in main) is
dispatch-gated only on backend/KV-dtype/SM90 — model-agnostic across DSA architectures. This
PR (a) validates it end-to-end on **GLM-5.2** (`GlmMoeDsaForCausalLM`): zero new integration
code needed (64 q-heads = the kernel's native tile; kernel-facing shapes byte-identical to
V3.2); and (b) contributes **seven optimizations, two fixes, and a recommended-flags
config** (plus two experimental opt-in levers, below) found during this validation work —
each gated by bitwise/numeric tests plus a gsm8k probe; the assembled stack additionally
passed the c=512 stress suite and full DeepSeek-V3.2 cross-validation.

The performance contribution is **two independent stages, reported separately**
(protocol: 8×H200, TP8/EP8/DP8, both arms fp8 KV cache):

- **Stage 1 — general DSA-pipeline optimizations (every deployment benefits, q8 not
  required):** the bf16-sparse (upstream-default) arm itself gains **+8.8–10.3% saturated
  throughput and c=1 TTFT +4.4–6.3%** on GLM-5.2 from the shared levers
  (NVLS + GATHERV + JIT-DeepGEMM restore + fp8 DP-gather). Of this, +6.9–8.0% saturated
  comes from enabling existing upstream default-off flags (NVLS, GATHERV); the remainder
  comes from new code in this PR.
- **Stage 2 — Q8KV8 fp8 sparse prefill, measured against that already-optimized baseline,
  measured on this PR's head:** q8 wins all 14 rows — **saturated +3.4–6.8%,
  c=1 TTFT +9.6–13.6%** (3.5k single-request TTFT 361 ms).
  Both arms run the same optimized config, so this A/B is conservative: the baseline arm
  includes every shared optimization in this PR.
- **Net effect vs upstream out-of-the-box (Stage 1 × Stage 2): GLM-5.2 saturated
  +13.1–17.5%, c=1 TTFT +14.4–20.0%; DeepSeek-V3.2 saturated +9.5–17.4%, c=1 TTFT
  +8.4–21.3%.**
- **DeepSeek-V3.2 (same two-stage treatment, full lever stack, measured on the PR
  head): Δ saturated +5.0–10.1% / c=1 TTFT +8.1–20.9%**; the q8-only levers (born-fp8 is
  1.68× on DS) fully transfer.
- **Accuracy — near-lossless:** 9 of 10 levers bitwise-exact or numeric-neutral
  (test-asserted). LongBench-v2 (LBV2) official protocol on the final stack: q8-vs-q16
  **Δ −0.8 to −1.0% (≈1σ)**; an earlier unoptimized-config measurement was −2.3±0.8%
  (the difference between the two measurements is within ~1σ). The only lossy lever
  (fp8 DP-gather wire-quant) is gsm8k-neutral (full-1319q ladder Δ +0.001) with a measured
  LBV2 cost of ~1.8% on GLM — therefore the **recommended default is the lossless lever
  set** (the always-on code paths plus the envs/flags in §Usage); wire-quant stays opt-in
  for throughput-first deployments (labeled below).

## Modifications (levers, each a separate commit / env)

| lever | scope | default | numerics | measured effect |
|---|---|---|---|---|
| vectorized 16B KV-gather + fused pad-zero + cached buffer (`kernels/ops/attention/dsa/dequant_k_cache.py`) | q8-only | always-on | bit-exact | 7.2× (112→15.6 µs/call) |
| born-fp8 q: fused absorbed-bmm+concat+cast (`SGLANG_ENABLE_DSA_Q8KV8_BORN_FP8_Q`) | q8-only | opt-in | bit-exact | 1.31× GLM / 1.68× DS q-prep |
| per-row topk_length early-exit + backscan derivation (`SGLANG_ENABLE_DSA_Q8KV8_TOPK_LENGTH`) | q8-only | opt-in | bit-exact (bitwise-asserted) | raised the 3.5k tput delta from +2.1% to +6.5% at adoption (lat3.5k from +4.3% to ~+14%); kernel time −25.9% @ s_q=437 |
| persistent kernel-output buffers | q8-only | always-on | bit-exact | removes 3 allocs/layer-call |
| fused non-prefix KV prep (`SGLANG_ENABLE_DSA_Q8KV8_KV_CAT_FUSION`) | q8-only | opt-in | bit-exact (canary-verified) | 3 kernels+1 alloc → 1 kernel; c=1 +0.5–0.7% (individually sub-noise e2e; accepted on the kernel-level win) |
| fp8 DP-gather wire format (`SGLANG_ENABLE_DP_GATHER_FP8`) | shared (dp-attention) | opt-in | **lossy on the wire; gsm8k-neutral proven** (q16 on/off full ladder; measured LBV2 cost ~1.8% — see §Accuracy) | GLM sat +1.2–1.4% / **DS sat +4.9%** |
| DLPack stride shim (`jit_kernel/dsa/paged_mqa_logits.py`) | shared bugfix | always-on | n/a | fixes the bs=1 crash on upstream-default JIT-DeepGEMM; this shim is what makes the upstream-default JIT-DeepGEMM usable — "JIT-DeepGEMM restore" in Stage 1 refers to it |
| MAX_LEN pad-row MoE dispatch mask (`SGLANG_OPT_MASK_DP_PAD_MOE`) | shared | opt-in | lossless (the masked rows' outputs were already discarded) | efficiency fix — pad rows waste MoE compute; numerics unchanged, hence safe to keep opt-in pending the upstream issue |
| SM90 WGMMA q-prep kernel (`SGLANG_OPT_Q8KV8_QPREP_VARIANT=cuda`) | q8-only | opt-in | bit-exact (7 shape configs) | q-prep 1.25× GLM / 1.16× DS over the Triton optimum; e2e +0.2–1.1% (individually sub-noise; accepted on the kernel-level win) |
| recommended flags: `--enable-nccl-nvls`, `SGLANG_DP_USE_GATHERV=1` (upstream, default-off) | shared | opt-in | numeric-neutral | sat +6.9–8.0% combined |
| tests | — | — | — | kernel suites 21 → **42** (bitwise topk-length/backscan sweeps + WGMMA q-prep suite) |

Default policy: the bit-exact internal rewrites (KV-gather, persistent buffers) and the
DLPack bugfix are always-on; every behavior-selectable lever ships opt-in (default-off) to
keep this PR's diff conservative — we propose promoting the bitwise-verified levers to
default-on in a follow-up once CI covers them. (Env-var naming — `SGLANG_ENABLE_*` vs
`SGLANG_OPT_*` — will be aligned to project conventions during review.)

Archived negative results (in-tree, documented, not wired): grouped-GEMM q-prep variant
(+0.5% e2e, sub-noise — 173 µs = the Triton practical optimum; dropped because it was later
dominated by the shipped SM90 WGMMA kernel above, not on the e2e number alone);
dispatch-level split-topk (the wave-fill gain is real, but the LSE-merge traffic cost
cancels it); DeepGEMM masked-GEMM m-cap (`SGLANG_OPT_DG_MASKED_M_CAP`, blocked by an
upstream pad/dummy-routing issue — a detailed report will be filed as a separate upstream
issue). Two further opt-in, default-off experimental levers ship in-tree: MoE quantize-once
(`SGLANG_OPT_MOE_QUANT_ONCE`; bitwise-verified but e2e-negative on these models, kept for
future architectures) and q-prep/indexer overlap (`SGLANG_ENABLE_DSA_Q8KV8_QPREP_OVERLAP`;
no effect on GLM's shared-indexer schedule).

## Usage

```bash
# RECOMMENDED optimized config (lossless: bitwise / numeric-neutral levers only):
SGLANG_DP_USE_GATHERV=1 SGLANG_ENABLE_DSA_Q8KV8_BORN_FP8_Q=1 \
SGLANG_ENABLE_DSA_Q8KV8_TOPK_LENGTH=1 SGLANG_ENABLE_DSA_Q8KV8_KV_CAT_FUSION=1 \
SGLANG_OPT_Q8KV8_QPREP_VARIANT=cuda \
python -m sglang.launch_server --model-path zai-org/GLM-5.2-FP8 \
  --dsa-prefill-backend flashmla_sparse_q8 --dsa-decode-backend flashmla_kv \
  --kv-cache-dtype fp8_e4m3 --tp-size 8 --ep-size 8 --dp-size 8 \
  --enable-dp-attention --enable-dp-lm-head --chunked-prefill-size 32768 \
  --mem-fraction-static 0.84 --context-length 163840 --reasoning-parser glm45 \
  --enable-nccl-nvls --trust-remote-code

# (SGLANG_OPT_MASK_DP_PAD_MOE is also lossless but stays opt-in pending the upstream
#  MoE pad-dispatch issue — see Known upstream issues.)
# OPTIONAL throughput-first variant — additionally prefix the same launch command with:
#   SGLANG_ENABLE_DP_GATHER_FP8=1
# (wire-quantizes the DP-gather to fp8; gsm8k-neutral, measured LBV2 cost ~1.8% on GLM —
#  see §Accuracy; +1.2–1.4% sat GLM / +4.9% sat DS)
```

The bf16 baseline is `--dsa-prefill-backend flashmla_sparse` (the only change needed for an
A/B). Contexts ≤ `index_topk` (2048) take the dense path, where both backends are identical.
DeepSeek-V3.2 runs used identical flags (except the reasoning parser) with `--model-path deepseek-ai/DeepSeek-V3.2` and
the same chunked-prefill/mem-fraction.

Note on configs: the q8-vs-q16 A/B tables were measured with the optional wire-quant
enabled **on both arms** (arm-symmetric, so those deltas are unaffected by it); in the
pipeline and net-effect tables it is part of the optimized config being measured. Running
the recommended lossless-only default lowers saturated absolutes by ~1.2–1.4%
(GLM) / ~4.9% (DS). The accuracy ladders were run on the recommended lossless config.

### MTP / speculative decoding compatibility (GLM's recommended deploy mode)

Both backends were validated with EAGLE MTP enabled (`--speculative-algorithm EAGLE
--speculative-num-steps 5 --speculative-eagle-topk 1 --speculative-num-draft-tokens 6`,

+# default.  N=512 is a multiple of every block_n here; block_m stays power of 2.
+SWEEP_TILES = [

+def time_fn(fn, iters: int, warmup: int) -> float:
+    """Median wall time of fn() in microseconds per call (lower = faster)."""
+    for _ in range(warmup):
+        fn()
+    torch.cuda.synchronize()
+    times = []
+    start = torch.cuda.Event(enable_timing=True)
+    end = torch.cuda.Event(enable_timing=True)
+    chunk = 10
+    for _ in range(max(1, iters // chunk)):
+        start.record()
+        for _ in range(chunk):
+            fn()
+        end.record()
+        torch.cuda.synchronize()
+        times.append(start.elapsed_time(end) * 1e3 / chunk)  # ms -> us
+    times.sort()
+    return times[len(times) // 2]

+def analytic_bytes(num_tokens: int, num_heads: int, k_nope: int):
+    """(old_bytes, new_bytes) of DRAM traffic per call, analytic lower bound."""
+    t, h = num_tokens, num_heads
+    a_read = t * h * k_nope * 2  # q_nope bf16
+    w_read = h * k_nope * N_LORA * 2  # w_kc bf16
+    nope_bf16 = t * h * N_LORA * 2  # bmm bf16 out (written then re-read)
+    rope_read = t * h * R_ROPE * 2  # q_rope bf16
+    fp8_write = t * h * (N_LORA + R_ROPE)  # q_fp8 out
+    old = (a_read + w_read + nope_bf16) + (nope_bf16 + rope_read + fp8_write)
+    new = a_read + w_read + rope_read + fp8_write
+    return old, new

+def make_check_ctx(num_tokens, num_heads, k_nope, device, seed, magnitude):
+    """Fresh inputs + old-path fp8 output + fp64 bmm reference (once/config)."""
+    q, q_nope, q_rope, w_kc = make_inputs(
+        num_tokens, num_heads, k_nope, device, seed, magnitude
+    )
+    q_fp8_old = torch.zeros(
+        (num_tokens, num_heads, N_LORA + R_ROPE),
+        dtype=torch.float8_e4m3fn,
+        device=device,
+    )
+    old_path(q_fp8_old, q_nope, w_kc, q_rope, num_heads)
+    torch.cuda.synchronize()
+    # fp64 reference: which path's fp8 lands closer to the exact bmm?
+    ref = torch.bmm(
+        q_nope.transpose(0, 1).to(torch.float64), w_kc.to(torch.float64)
+    ).transpose(0, 1)
+    err_old = (q_fp8_old[..., :N_LORA].to(torch.float64) - ref).abs()
+    return {
+        "q_nope": q_nope,
+        "q_rope": q_rope,
+        "w_kc": w_kc,
+        "num_heads": num_heads,
+        "q_fp8_old": q_fp8_old,
+        "ref": ref,
+        "meanerr_old": err_old.mean().item(),
+        "maxerr_old": err_old.max().item(),
+    }

+def check_variant(ctx, **new_kwargs):
+    """Correctness of one new-path variant vs the old path + fp64 reference."""
+    q_fp8_old = ctx["q_fp8_old"]
+    q_fp8_new = torch.zeros_like(q_fp8_old)
+    new_path(
+        q_fp8_new,

+        ctx["w_kc"],
+        ctx["q_rope"],

+    nope_old = q_fp8_old[..., :N_LORA]

+        (nope_old.view(torch.uint8) == nope_new.view(torch.uint8)).float().mean().item()

+    diff = (nope_old.to(torch.float32) - nope_new.to(torch.float32)).abs()

+        "rope_bitexact": rope_bitexact,
+        "nope_bitwise_match_frac": match,
+        "nope_max_dequant_absdiff": max_diff,
+        "nope_meanerr_old_vs_fp64": ctx["meanerr_old"],
+        "nope_meanerr_new_vs_fp64": err_new.mean().item(),
+        "nope_maxerr_old_vs_fp64": ctx["maxerr_old"],
+        "nope_maxerr_new_vs_fp64": err_new.max().item(),

+// SM90 (Hopper) Q8KV8 born-fp8 q-prep kernel.
+//
+// Computes, per head h:
+//   out[:, h, :512]    = fp8_e4m3(bf16(fp32_accum(q_nope[:, h, :] @ w_kc[h])))
+//   out[:, h, 512:576] = fp8_e4m3(q_rope[:, h, :])
+//
+// This is the CUDA replacement for the Triton absorbed_bmm_concat_cast_q_fp8
+// kernel (triton_ops/cache_ops.py).  The epilogue keeps the exact rounding
+// chain of the Triton variants: fp32 WGMMA accumulate -> bf16 round-to-nearest
+// (cublas-equivalent output rounding) -> fp8_e4m3 rn/satfinite on store.  The
+// K dimension is consumed as one in-order chain of k=16 WGMMA steps into a
+// single fp32 accumulator, i.e. the same fp32 add order as the Triton
+// "two_dot"/"grouped" variants (128+64 chained tl.dot), so the nope half can
+// come out bitwise identical to them.
+//
+// Phase-2 design (2 CTAs/SM + double-buffered B):
+//   grid = (ceil(T / 128), H); one CTA = two WGMMA warpgroups (256 threads)
+//   owning a 128-row m-tile of one head (warpgroup w computes rows
+//   [64w, 64w+64)).  The A tile [128, K] bf16 is cp.async'd to smem once (L2
+//   evict_first: streamed) and the rope path runs under that load's wait.
+//   The N=512 output is produced in N_SLABS n-slabs of BN columns; the B
+//   slab [BN, K] bf16 is double-buffered (L2 evict_last: re-read by every
+//   CTA of the head) and prefetched one full round ahead.  Per round, the
+//   fp8 stage-write -> barrier -> refill-issue -> coalesced-flush order
+//   makes one barrier serve both the stage handoff and the CTA-wide WGMMA
+//   drain of the buffer being refilled, and the flush plus the next round's
+//   gemm overlap the refill.  BN is sized so that A + 2 B buffers + the fp8
+//   stage fit in half an SM's smem, keeping 2 CTAs co-resident per SM
+//   (register cap 128 via launch bounds; measured faster than every
