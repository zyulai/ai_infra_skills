## PR body
```markdown
## Motivation

`DRAFT_EXTEND_V2` currently cannot use the draft-extend CUDA graph path with `trtllm_mha` because the v2 Eagle draft worker whitelist does not include `TRTLLMHAAttnBackend`.

The previous V2 graph replay computed full-logits `softmax + topk/reduce` work, while `EagleDraftWorker` later recomputed `softmax + fast_topk` on the selected logits it actually consumes. The graph-produced `ret.topk_p` and `ret.topk_index` are therefore dead work in the current V2 worker contract.

This PR enables draft-extend CUDA graph for `TRTLLMHAAttnBackend`, fixes the associated V2 replay metadata, and removes that graph-side dead top-k work without changing TRTLLM MHA attention kernel routing.

## Modifications

- Add `TRTLLMHAAttnBackend` to the v2 Eagle draft worker CUDA graph whitelist.
- Include `DRAFT_EXTEND_V2` in the `trtllm_mha` draft-extend CUDA graph capture/replay metadata branches.
- For `DRAFT_EXTEND_V2` replay, use uniform `num_tokens_per_req` semantics for `cu_seqlens_q` and `max_seq_len_q`. The v1 `accept_lens` path is unchanged.
- Make the V2 logits/top-k contract explicit: `EagleDraftWorker` owns the selected-row `softmax + fast_topk` result used by speculative sampling; graph replay should not compute or return full-logits `ret.topk_p` / `ret.topk_index`.
- Replace graph-side full-logits `softmax + topk/reduce` with a cheap max-reduction anchor (`torch.amax`) in the shared draft-extend CUDA graph runner. The anchor still materializes full logits for the CUDA graph dependency/lifetime contract, but avoids producing unused top-k outputs.

### DeepSeek-R1 / TRTLLM MLA

The max-reduction anchor cleanup is implemented in the shared `DRAFT_EXTEND_V2` graph runner, so it can affect backends beyond `trtllm_mha`. Additional validation covers DeepSeek-R1 FP4 TP8, Spec V2 EAGLE, `trtllm_mla`, GB200, `isl=1024`, `osl=1024`, with `cuda-graph-bs=[32,64,128,256]` and `max-running-requests=256`.

| Concurrency | TPOT delta | Output TPS delta |
|---:|---:|---:|
| 32 | +0.20% | +2.17% |
| 64 | -2.49% | +1.19% |
| 128 | -1.49% | +1.29% |
| 256 | +0.17% | +3.03% |

Output throughput improved at all four tested concurrencies. TPOT was mixed: c=64/c=128 improved, while c=32/c=256 were effectively neutral. MLA c=512 profiling also shows the removed full-logits work is not free on this backend: graph-correlated GPU time decreased from `400.105 ms / 100` replays to `344.707 ms / 100` replays after replacing full-logits `softmax + MaxOps` with the max-reduction anchor.
