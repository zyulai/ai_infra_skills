## Motivation

<!-- Describe the purpose and goals of this pull request. -->
Under `unified_kv`, DSv4 keeps KV in bf16 across the full latent — `qk_nope_head_dim` 448 plus `qk_rope_head_dim` 64, **1024 B per token per layer**. The nope half actually does not need that precision. Storing nope as fp8 with per-tile E8M0 scales while leaving rope in bf16 cuts the row to **640 B** (512 B of fp8 nope at a fixed stride, plus the same 128 B of bf16 rope), which measures out at **1.51× the KV capacity at identical memory** on gfx950. At fixed HBM more tokens stay resident, so longer contexts and higher concurrency fit on the same node.

Off by default behind `SGLANG_DSV4_UNIFIED_KV_FP8`; it requires gfx950 and implies `is_unified_kv_triton()`. Other architectures warn and fall back to bf16, so nothing on the existing path changes.

## Modifications

<!-- Detail the changes made in this pull request. -->
Two pools instead of one, then every writer and reader of the pool:
- **layout / sizing** — nope is a 512 B fp8 row (448 values + inline e8m0 scales, padded so the stride stays a power of two); rope stays 128 B of bf16. PD disaggregation and HiCache offload are refused for now because both assume one pool per layer.
- **writers** — SWA scatter, fused QK norm+RoPE store, compressor norm+rope store, and the packed ring store used by prefill and target-verify.
- **readers** — decode through aiter's `mla_a8w8` v4 nm asm kernel; prefill through aiter's opus kernel.
- **decode overhead** — drop a `masked_fill_` on empty segments the builders cannot produce, cache `qo_indptr` (it only depends on the token count), skip a `kv.contiguous()` the group-quant kernel does not need (it already takes the row stride), and cap `num_kv_splits` to 4 above 40 tokens where aiter's occupancy heuristic over-splits.

Everything stays behind `SGLANG_DSV4_UNIFIED_KV_FP8` (default off) plus the gfx95 gate. The DSv4 unified_kv path is ROCm-only; the only common-code touch is one new `elif` in the JIT norm+rope-store template, existing branches unchanged.

## What this buys: KV capacity

Four configurations, each a pair of servers with byte-identical CLI differing only in the env switch. Taken on this rebase (`ec07b65ed6 `):

| config | `available_bytes` | bf16 `full_token` | fp8 `full_token` | ratio |
|---|---|---|---|---|
| TP8 | 135.59 GB | 16,126,208 | 24,223,744 | **1.5021×** |
| TP8 + MTP | 132.97 GB | 15,417,344 | 23,161,088 | **1.5023×** |
| TP8 + DP8 | 119.85 GB | 14,399,488 | 21,605,120 | **1.5004×** |
| TP8 + DP8 + MTP | 115.35 GB | 13,612,288 | 20,424,448 | **1.5004×** |

`available_bytes` matches exactly within every pair, which it has to — otherwise a weight-footprint difference would land in the ratio. `bytes_per_full_token` goes 8918.00 → 5945.00 in the no-MTP cells and 9064.20 → 6042.46 in the MTP cells: **0.6666× in all four**, not the row's 0.625, because the indexer term in `_get_bytes_per_full_token` does not scale with the KV row width — it was already fp8 with its own scales.
A fifth pair at a different `mem-fraction` on the previous stack gave 14,211,840 → 21,451,520 (**1.5094×**), so the ratio is not an artefact of one memory setting.

The cell to flag is **8192/1024 at c=8** under TP=8: 7.6% less throughput, ITL +1.18 ms. That is the worst of the 14 TP=8 cells; everything else there is within 4.3%, and every cell at concurrency ≥ 16 is within 3.2%. 

The leftover gap is the decode reader, not anything this PR still owns. fp8 goes through aiter's `mla_a8w8` asm kernel, which is tuned for 64 q heads; TP=8 leaves 16 local heads, so it is occupancy-bound — it loads *less* per row (640 B vs 1024 B) and is still slower. The DP=8 table above shows the gap falls into noise. A Triton rewrite was measured and was slower at every shape, so it was dropped. Closing the TP=8 gap needs an `mla_a8w8` variant for 16 q heads on the aiter side; that is a separate PR.

## Reproducing this
One branch, one env variable, two commands, no code edits to switch arms. Taken on MI355X, ROCm 7.2, TP=8, DeepSeek-V4-Pro.

**1. Rebuild `sgl_kernel`** — needed for #37140's AOT half, if your image is earlier than #37140, you need to rebuild as so, otherwise 6 related tests would fail.
```
cd python/sglang/kernels/aot
cp pyproject_rocm.toml pyproject.toml
AMDGPU_TARGET=gfx950 MAX_JOBS=$(nproc) python3 setup_rocm.py build_ext --inplace
cd -
export PYTHONPATH=$PWD/python/sglang/kernels/aot/python:$PWD/python
```
AMDGPU_TARGET is not optional — `setup_rocm.py` defaults to gfx942, which keeps the software cast.
**2. Start a server.** This is the CLI the accuracy matrix was taken on. The two arms differ only in the last export.
```bash
export SGLANG_DEFAULT_THINKING=1
export SGLANG_DSV4_REASONING_EFFORT=high
export SGLANG_USE_ROCM700A=0
export SGLANG_HACK_FLASHMLA_BACKEND=unified_kv_triton
export AITER_BF16_FP8_MOE_BOUND=0
export SGLANG_OPT_USE_AITER_BATCHED_GEMM=1
export SGLANG_OPT_UNIFIED_CACHE_FREE_OUT_OF_WINDOW_SLOTS=1
export SGLANG_TIMEOUT_KEEP_ALIVE=900
export SGLANG_DSV4_UNIFIED_KV_FP8=1      # the fp8 arm adds exactly this line

python3 -m sglang.launch_server \
  --model-path <DeepSeek-V4-Pro> --served-model-name deepseek-ai/DeepSeek-V4-Pro \
  --host 0.0.0.0 --port 8888 --trust-remote-code \
  --tensor-parallel-size 8 --attention-backend dsv4 --page-size 256 \
  --swa-full-tokens-ratio 0.10 --kv-cache-dtype fp8_e4m3 \
  --enforce-shared-experts-fusion \
  --tool-call-parser deepseekv4 --reasoning-parser deepseek-v4 \
  --chunked-prefill-size 8192 --mem-fraction-static 0.89 \
  --max-running-requests 64 --cuda-graph-max-bs 64 \
  --speculative-algorithm EAGLE --speculative-num-steps 3 \
  --speculative-eagle-topk 1 --speculative-num-draft-tokens 4 \
  --watchdog-timeout 3600
```

**3. For the capacity number** the server need not finish starting — the sizing line comes before CUDA-graph capture, and `unified_fp8=True` is the only reliable confirmation that the switch took effect, since `is_unified_kv_fp8()` also requires gfx95 and `is_unified_kv_triton()`.

```bash
