## 正文(PR 描述)

## Motivation

When the scheduler aborts a request with an error status (a disaggregated decode whose KV transfer failed, a request whose `logprob_start_len` lies past the prompt, ...), the Python server and the Rust frontend answer a native `/generate` **stream** differently.

Python's `TokenizerManager._handle_abort_finish_reason` yields the abort as a normal terminal frame: the output so far, the request's counts, `e2e_latency`, and `meta_info.finish_reason` `{type: "abort", message, status_code, err_type}`, followed by `[DONE]`. Only a non-streaming request turns that abort into an HTTP status.

The Rust frontend turned the same scheduler frame into a bare `{"error": {"message", "code"}}` item on the stream and dropped the frame. A client, router or proxy that classifies an in-band error item by its code then reads a 429/503 abort as "overloaded" in Rust mode where Python reports a finished request with an abort reason. The abort message also named the request by the suffixed rid this server hands the scheduler (`Rid::from_client`), not by the rid the client sent, so the message leaked a request-id suffix the client never saw.

This PR makes a native Rust stream end on the abort's frame, as Python's does, and names the request in the abort message by the client's own rid. Non-streaming responses are unchanged.

## Modifications

- **`core/error.rs`**: `CoreError::RuntimeRejected` now carries the request's terminal `CoreOutput` (boxed; finish reason and counts included). `from_runtime_rejection` takes it, and a new `into_rejected_output` hands it back for the one surface that reports the abort as an output: a native `/generate` stream. Any other `CoreError` comes back as is.
- **`core/handle.rs`**: `generation_event` passes the scheduler's terminal output into the rejection. `RuntimeCall::recv` / `try_recv` run the terminal item through a new `name_client_rid`, which strips this server's rid suffix from the abort message so the message names the request as the client does. The message may hold the rid raw (`{rid}`) or as Python's `repr` (`{rid=}`, `{rid!r}`); the suffix is ASCII hex after `#`, so dropping it leaves the client's rid in whatever form the scheduler wrote, including `repr`'s escaping and quoting.
- **`http/native_api.rs`**: `generation_event_stream` maps every event through `stream_event`, which turns a `Failed` whose error is a scheduler rejection back into `Finished(output)`. The stream then ends on the usual terminal frame (`meta_info.finish_reason` is the abort, `e2e_latency` is set) and `[DONE]`. Unary responses, batch unary items, the OpenAI surfaces and gRPC still answer with the abort's status and message, matching Python's unary path and its OpenAI stream.
- **`message/finish_reason.rs`**: `FinishReason::replace_in_abort_message` rewrites a substring of an abort's message and leaves any other reason alone.
- **`grpc/native_api.rs`**: the error-mapping test fixtures gain the new field.

This deliberately replaces `scheduler_rejection_preserves_legacy_http_status`, which pinned the error-item shape on a native stream, with `scheduler_abort_ends_a_stream_on_a_frame_and_fails_unary`: Python is the reference for the native `/generate` surface, and Python has always ended a stream on the abort frame (see `_handle_abort_finish_reason`, which only raises when `is_stream` is false). The legacy status is still preserved; it now reaches a unary client as a status and a streaming client inside `finish_reason.status_code`, as it does from Python.

Tests:

- `scheduler_abort_ends_a_stream_on_a_frame_and_fails_unary` (`http/native_api.rs`): a stream that already sent a frame ends on the abort frame (`text` so far, `prompt_tokens`, `completion_tokens`, the abort as `finish_reason`, `e2e_latency` set, no `error` item), then `[DONE]`; the same abort on a unary call answers the abort's status with `error.code` and `error.message`.
- `status_abort_names_the_client_rid` (`core/handle.rs`): a status abort fails the call with that status and keeps the terminal output, and the message names the client's rid for raw and `repr` forms, including rids with backslashes, newlines and quotes.
- `from_runtime_rejection` status mapping and the gRPC code mapping tests updated for the new field.
