## Motivation & background

Traditional HPC application kernel-level optimization pays more attention to 
- the memory accessing (sparsity, low bits, memory hierarchy caching, reigsters level accum ...) and 
- workload balancing (persitent, stream-k, split-k ...)

Complementary to the proposal in https://github.com/vllm-project/vllm/issues/22799, however there is trend that communication between chips becomes more and more important and **Decoding Stage FFN-Attention Model Sharding Pipelining without PMF** (noted as Attention-FFN Disaggregation (AFD) in step3) opened up this opportunity for the future, especially useful for scientific research even though we are not confident it will bring immediate benefits to our infra.

Growth of NIC and scales for MoE model Sparisty is amost double each product release:

- bandwith up 1.5x (600 GB/s -> 900 GB/s) from Ampere to Hopper , and 2x (900 GB/s -> 1.8 TB/s) from Hopper to Blackwell
- higher FLOPS but lower utilization, everything else is bounded by network
- reduction inside switches when routing data from one node to another node cross switches

Hence, in a broader future, for performance lead, we should support this feature with faster and faster IB/RoCE network communication speed.

Both researchers from NVIDIA and AMD recently utilized the latest communication powerness and released **Two Shot** communication libraries among devices, long before that, **one shot** communication pattern dominates in the area device-device communciation, which unlock the future of more complex pipelining schemes.

Morover FFN-Attention Model Sharding itself exposes some interesting parts to inferences worloads .

In **decoding stage**, attention may be either bounded by computing ceilings (MLA) or memory ones (GPT-OSS 8:1 GQA for example ~ 1 TFlops over tens of GB bytes):

1. for current computing bound attention arch (deepseek v3), and a single micro batch size, MoE FFNs are distributed to all cards in Expert parallel (dp), and attention is distributed to the same group of cards in TP parallel.
2. for those memory bounded attention, flops of GEMM (here we refer to MoE FFN) in decoding stage has nothing do with historical token lengths and is computing bound. And flops of memory bound Attn, such as GQA, in decoding stage, is linearly affected by historical token lengths;
3. compared to MoE Expert parallel, sharding experts to a different groups of cards do not have load-balance problems, with the expenditures communication time.

Consider GPT-OSS for example as we calculated [1], MoE parallel is much faster than sharding Attn and FFN to distinct gorups of cards.

But for expensive routing (domestic NIC cards), we cannot easily draw solution theoretically, by supporting this feature we can verify immediately.
