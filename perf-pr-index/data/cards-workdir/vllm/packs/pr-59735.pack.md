## Overview

Keep ordinary GDN execution on the existing standard path when speculative decoding is not configured. Addresses #59520 without changing the speculative CUDA kernel or the backend default.

## Claims

- Avoid the packed fused-normalization wrapper when the model cannot produce an MTP batch.
- Preserve the existing fused CUDA path for models configured for speculative decoding.
- Improve measured non-speculative Qwen3.5-9B throughput by 1.31% and 1.47% on two H100s under the two tested prefix-cache policies.

## Details

The fused CUDA recurrent operator is eligible for speculative/MTP batches. The outer forward path currently selects its packed wrapper solely from the configured CUDA backend, so an ordinary model still takes that wrapper and its fallback normalization even though it cannot use the fused recurrent operator.

Gate that outer selection on the model's existing speculative configuration. The flag is named `enable_fused_gdn_spec_decode` to make its scope explicit. This is a static construction-time decision, not a new per-batch host read or synchronization. Ordinary models retain the existing standard recurrent and normalization path. Models configured for speculation retain their current dispatch, including their prefill and mixed-batch fallbacks.

This differs from #53463, which enables the fused CUDA recurrent operator for ordinary decode with draft width one. It also does not duplicate the FlashInfer decode backend being developed in #41966 or the SM120-specific work in #53645. #51954 removes gate copies within standard decode; this patch changes which outer route an ordinary model selects. No new kernel, hardware-selection heuristic, dependency, or public option is added.
