## 正文(PR 描述)

## Summary

Four small fixes for requests that a pause, a memory release, an abort, or a PD role switch could leave in a broken state.

## Changes

- **Beam groups on a retract pause.** `pause_generation(mode="retract")` now aborts live beam groups instead of requeueing their leaders. `retract_all` frees each leader's member rows before its KV is released and records the abort reason, which is the same path `ScheduleBatch.retract_decode` takes under KV pressure. The running batch is now emptied through `filter_batch`, so its beam tail is stripped with the requests. Before this change, the stale tail tripped `reqs changed while a beam tail was attached` on the first `filter_batch` after resume. A pause-retracted beam leader that could not resume also leaked its member rows.
- **`release_memory_occupation` on a busy scheduler.** The idle check was a bare `assert`, which crashed the scheduler, or was skipped under `python -O`. The scheduler now returns a refusal instead: `ReleaseMemoryOccupationReqOutput` carries `success` and `message`, and the check runs before any memory is paused. A refused release must not be silent for callers that ignore return values, so `TokenizerManager.release_memory_occupation` raises `RuntimeError` with the merged message, and `Engine.release_memory_occupation` raises with it. `/release_memory_occupation` turns the error into a 400 through its existing error path. The later `flush_cache()` cannot be refused, because its idle gate is the same check.
- **Abort of a HiSparse-staged request.** After prefill, a HiSparse request waits in the staging list until its host copy lands, and it is in no batch while it waits. An abort that arrived after the prefill batch had moved on matched nothing, so the request ran to completion. `collect_inflight_reqs` now includes staged requests. The abort marks them, and they finish at their first decode step, as a running request does.
- **PD role switch with held requests.** `is_fully_idle` deliberately skips requests held by a retract pause (`PD_HELD`), so that a weight update can flush the cache. The role switch used the same check, so it tore down the decode queues and dropped the held requests without answering them. The switch now rejects with `safe_to_restore=True` while any request is held.

## Behavior changes

- During a retract pause, a beam-search request is aborted with 503 and is not resumed after the pause.
- `release_memory_occupation` on a busy scheduler no longer crashes the scheduler. `Engine.release_memory_occupation` raises `RuntimeError`, and `/release_memory_occupation` returns 400 with the message. A successful release returns what it returned before.
- An abort sent while a request is in HiSparse staging now finishes it.
- A PD role switch during a retract pause that holds requests is rejected until generation resumes and the held requests drain.
