## Motivation

Bump FlashInfer from 0.7.3 to 0.7.4 ([release notes](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.7.4)).

## Modifications

Ran `scripts/release/bump_flashinfer_version.py 0.7.4`. It updates the pin in the four usual files: `docker/Dockerfile`, `docker/Dockerfile.cu134`, `python/pyproject.toml`, and the `engine.py` version check.

One code change was needed in `python/sglang/srt/speculative/uno_utils.py`. `_build_sparse_target_support_tensors` now calls `flashinfer.top_k` eagerly, and only the normalization that follows is wrapped in `torch.compile(dynamic=True)`. Its signature is unchanged. Before, `top_k` ran inside the compiled function, so Dynamo traced into FlashInfer's Python wrapper. FlashInfer 0.7.4 (flashinfer-ai/flashinfer#8696) builds its per-stream scratch-buffer key with `torch._C._cuda_getCurrentRawStream(index)`. Under `dynamic=True` that call receives a symbolic device index and fails with `invalid argument to getCurrentStream`. This broke `test_uno_compact_preserves_original_top_p_nucleus` and the UNO compact verify path. `top_k` is an opaque kernel that Dynamo graph-broke on anyway, so moving it out of the compiled function costs nothing. The long-term fix, which makes the helper traceable again, is flashinfer-ai/flashinfer#9354.

Details of the compatibility check are below.

### Compatibility check against v0.7.3

- **Packages.** `flashinfer-python==0.7.4` is on PyPI. `flashinfer-cubin==0.7.4` and `flashinfer-jit-cache==0.7.4` (cu129 and cu130, x86_64 and aarch64) are on flashinfer.ai/whl. The 0.7.4 dependency list matches 0.7.3. SGLang's pins already satisfy it (`nvidia-cutlass-dsl[cu13]==4.8.0`, `apache-tvm-ffi==0.1.11`).
- **Python API.** An AST scan of `python/sglang` and `test/` checked every FlashInfer import, attribute access and call site against both releases: 299 symbols and 512 call sites. No symbol SGLang uses was removed. No function SGLang calls changed its signature. No public method of a class SGLang uses changed either.
- **C++ headers used by SGLang kernels.** `sampling.cuh`, `norm.cuh` and `quantization.cuh` changed in 0.7.4. The parts SGLang uses did not change: `DeviceSamplingFromProb`, `SamplingTempStorage`, `FusedAddRMSNorm` and `SegmentPackBits`.
- **Private internals.**
  - The FA2 paged-prefill `_cached_module.plan` still takes the 21 arguments that `fast_prefill_plan` passes.
  - `fast_prefill_plan` still resets `_eagle_verify_fp8kv_sm90_state`, as before.
  - The MegaMoE knob-cache format is still `KNOB_CACHE_VERSION = 2`, so `_NATIVE_CACHE_VERSION` in `flashinfer_megamoe_autotune.py` stays.
- **Behavior changes that do not reach SGLang.**
  - flashinfer-ai/flashinfer#5188: on Hopper, the paged prefill wrapper with `backend="auto"` now picks FA2 when every request has at most 64 query tokens. SGLang creates its paged prefill and verify wrappers with `backend="fa2"`, so this does not apply.
  - flashinfer-ai/flashinfer#5286: on SM100a, the ragged prefill wrapper with `backend="auto"` can now send sliding-window and attention-sink calls to cuDNN. On SM10x, SGLang passes `fa2` or `cutlass` explicitly, so this does not apply either.
- **Upgrade notices.** The Prims-TS attention argument renames and the source-install requirement for `flashinfer.experimental` do not affect `main`. `main` does not import `flashinfer.experimental` and uses Prims-TS only through `prims_ts.gemm` (FLUX.3).
- **torch.compile traceability.** The API scan does not catch this kind of break, so I also audited every SGLang `torch.compile` region that reaches a FlashInfer API using the per-stream scratch helpers (`_get_stream_cache_buf` and `_get_row_states_buffer`). Only the UNO site above did. The GEMM call sites (`bmm_fp8`, `gemm_fp8_nt_groupwise`, `mm_mxfp8`, `mm_fp4`, `mm_bf16`) are wrapped in `register_custom_op`, so Dynamo does not trace into them.
- **Deterministic MoE workaround.** flashinfer-ai/flashinfer#8831 is still open. The `--enable-deterministic-inference` workaround from #48468 stays.

## Accuracy Tests

On an L40S with torch 2.14.1 and FlashInfer 0.7.4, `test/registered/kernels/ops/speculative/test_speculative_sampling.py` fails 1 of 11 without the `uno_utils.py` change, and passes 11/11 with it. The new compiled helper matches an eager reference on four shapes, including vocab 151936, k=64, and no top-p, with no graph breaks. I did not run GPU end-to-end model tests locally. They rely on CI. As on earlier FlashInfer bumps, the first jit-kernel run may hit a cold JIT cache.
