# [Feature] Paged Experts: serve MoE models whose weights do not fit in VRAM

<!-- Successor to #29971 (closed), cut down to a reviewable first step. -->

This is a smaller, first-iteration version of #29971. That PR tried to make the feature fast and complete at once (pinned windows, a disk tier, breakable decode graphs, NVFP4, six new flags; ~7k lines). This one ships only the core: **page experts between host RAM and the GPU, keep the computation on the GPU, change no results.** Everything else is a follow-up that plugs into the seams added here.

## Motivation

A lot of laptops and gaming PCs typically pair 4–16 GB of VRAM with 32–64 GB of RAM. MoE models are increasingly the default open-weight architecture (Qwen3/3.5 MoE, DeepSeek, GLM, gpt-oss, Mixtral), and their expert weights are most of the parameters. For example, Qwen3-30B-A3B in int4 has ~15 GB of expert weights, which is all of the usable VRAM on a 16 GB card. Currently, SGLang either does not load such a model on these machines, or loads it with `--cpu-offload-gb`, which streams *every* offloaded weight to the GPU on every forward pass, whatever the routing.

llama.cpp and Ollama keep the experts of some MoE layers in system RAM and **compute them on the CPU** (`--n-cpu-moe N`, or `--cpu-moe` for all of them).

**What this PR does instead.** Each token is routed to only `top_k` of the `E` experts per layer, and consecutive tokens reuse most of them. Paged Experts keeps **K of the E experts per layer in a K-slot table on the GPU**, holds all E in pinned host memory, and copies in only the experts a step needs that are not resident. The layer's own fused-MoE kernel then runs on the GPU as usual. It is the HiCache idea applied to expert weights: the GPU holds the working set, host RAM the rest.

**It is a memory knob as much as a speed feature.** K trades directly against the KV cache, so a deployment can choose more context or concurrency (smaller K, more paging) or more speed (larger K). Models that already fit can give up some resident experts for longer context, or to share the GPU with another model.

## Where it helps, and where it does not

Measured against each alternative at its best setting (methodology and full numbers in [Speed Tests](#speed-tests-and-profiling)):

- **Against SGLang today** (`--cpu-offload-gb`): paging moves only the experts a step routes to and does not have, instead of every offloaded weight. 12× (int4) and 30× (FP8) faster single-stream decode on the 16 GB card, 27× on the 8 GB laptop.
- **Against llama.cpp tuned** (`--n-cpu-moe` at the best fitting value, byte-matched `IQ4_XS` / `Q8_0`):
  - when most of the model fits (a 16 GB int4 model on a 16 GB card), or the host link is slow (int4 on an 8 GB laptop over PCIe 4.0 x8), the two are **close**: 205.7 vs 194.4 tok/s single-stream decode and 379 vs 312 tok/s with 4 requests on the 16 GB card; 30.6–32.9 vs 23.0–32.4 tok/s single-stream decode on the laptop;
  - when a large share of the experts must live in host RAM and the host link is fast (FP8 on a 16 GB card over PCIe 5.0 x16), paging **decodes faster**: 87.7 vs 45.2 tok/s;
  - **llama.cpp has the lower time-to-first-token on short prompts.** A prefill touches nearly every expert, so it pages in all non-resident experts once (≈4 GB for Qwen3-30B int4 at K=92, ≈80 ms over PCIe 5), while llama.cpp computes its few CPU-side layers in place. For long prompts paging wins, since its transfer is a fixed cost and the GPU computes the tokens faster: 2,048-token prompt 267 vs 344 ms (int4, 16 GB), 443 vs 984 ms (FP8, 16 GB), 1,441–1,538 vs 2,396 ms (laptop); short prompts 89–90 vs 68 ms, 284–285 vs 226 ms, 872–953 vs 620 ms;
  - **with several concurrent requests and a small K/E**, each step routes to more experts than fit, and paging can fall behind: 11–12 vs 41 tok/s with 4 requests on the laptop (K = 26 of 128); FP8 on the 16 GB card gives 84 tok/s at K = 40 but 31 at K = 24 (llama.cpp: 55).

Note: #29971 compared only against llama.cpp `--cpu-moe` (all experts on the CPU), which overstated the advantage. The numbers here compare against llama.cpp's tuned offloading.

## Scope

**In this PR**
- Unquantized (bf16/fp16), block-quantized FP8 (triton runner) and GPTQ int4/int8 (Marlin runner) experts.
- A single GPU.
- Works with SGLang's default CUDA graphs: decode is captured (full graph) up to `K // top_k` concurrent requests, and in breakable prefill graphs the paged MoE layer runs as an eager break. CUDA graphs can also be off entirely.
- K is sized automatically from the memory budget, or set with `--paged-experts-num-resident`.
- **Results are unchanged.** Bit-identical logprobs for bf16 and FP8 versus the unpaged model, eager and with CUDA graphs; GPTQ stays within Marlin's own batch-to-batch noise.

**Not in this PR** (each is a follow-up on the seams below)
- Stores larger than pinnable RAM (pinned window, pageable or disk cold tier).
- Capturing decode beyond `K // top_k` requests (breakable decode graphs fail on these models upstream, with or without paging, so they are rejected for now).
- Computing a short prefill's non-resident experts on the CPU instead of paging them (the short-prompt TTFT gap above).
- More formats: NVFP4 (via Marlin W4A16 for exact results), AWQ, MXFP4.
- Tensor or expert parallelism.

Two new server flags: `--enable-paged-experts` and `--paged-experts-num-resident`.

## Modifications

**New package `srt/layers/moe/paged_experts/`** (~1,150 lines). It wraps a layer's existing fused-MoE method and splits paging into replaceable parts:

| Module | Responsibility |
|---|---|
| `method.py` | `PagedExpertsMoEMethod`. Creates the layer's expert tensors with K rows and redirects their weight loaders into a host store, so checkpoints load through SGLang's **native** per-expert loader (sharding, gate/up order, scale layout). Also holds the startup guard and the capture-size cap. |
| `formats.py` | One `ExpertFormat` per quantization method: which tensors are loaded and paged, and what happens after loading. GPTQ's Marlin repack runs over the host store K experts at a time; a check rejects post-load transforms the store would not replicate. **Adding a quantization is one subclass.** |
| `runners.py` | One `RunnerContract` per runner backend (triton, Marlin). The runner returns router-weighted per-(token, expert) outputs (`no_combine`), and the contract performs the same top-k sum the runner would. That is what makes multi-wave steps bit-identical. |
| `store.py` | The pinned host store: `page_in` for host-planned steps, `gather` for device-planned steps. |
| `residency.py` | LRU slot assignment and wave planning on the host, plus `DeviceResidency`, the same LRU state on the GPU. |
| `executor.py` | `EagerExecutor`: host-planned waves, any step; inside a breakable prefill graph it runs as an eager break. `DeviceExecutor`: one wave decided and paged on the GPU with no host sync, so the decode graph captures it. |
| `sizing.py` | Auto-K from exact checkpoint bytes (safetensors headers), `--mem-fraction-static`, and a KV reserve. |

**New JIT kernel** `kernels/jit/csrc/moe/paged_experts.cuh` with wrapper `kernels/ops/moe/paged_experts.py` (~290 lines; no sgl-kernel change):
- an on-device LRU decide that writes the page-in plan to GPU buffers;
- one gather launch that copies every paged tensor from the pinned host store through its UVA address, reading the count on the device.

**Upstream touches** (82 lines):
- `MoeRunnerConfig.no_combine_keep_router_weight`;
- the triton fused-MoE tail factored into `moe_combine_topk`;
- `fused_marlin_moe(no_combine=)`;
- `FusedMoE.weight_load_method` and the paged-experts hook in `FusedMoE.__init__`;
- the two server flags.

**Docs:** `docs/advanced_features/paged_experts.mdx` and the server-argument entries.

## Speed Tests and Profiling

**Machines:** an RTX 4070 Laptop (8 GB, PCIe 4.0 x8, 54 GB RAM under WSL2) and an RTX 5070 Ti desktop (16 GB, PCIe 5.0 x16, 62 GB RAM, native Linux).

**Methodology** (each engine at its best setting, identical workload):
- Real prompts (ShareGPT, 256 output tokens) as the headline workload: paging speed depends on how consecutive tokens route, so synthetic prompts mis-measure it. One 2,048-token prompt phase for long-prompt TTFT.
- Fixed prompt set per phase (a seed each, identical across engines and runs, never repeated across phases); prefix caching off in both engines; warm-up before measuring.
- Same KV capacity for both (10,240 tokens, 4 slots); byte-matched quantization (GPTQ int4 vs `IQ4_XS`, FP8 vs `Q8_0`).
- llama.cpp at its best: `--n-cpu-moe` searched in steps of 1 and counted only when its own memory projection fits physical VRAM, thread count swept per machine, `--load-mode none` and mmap both tried; `--fit on` and `--cpu-moe` reported too.
- Each headline cell measured twice.

Metrics: TTFT p50/p99 and ITL p50/p99 at bs=1, decode tok/s (`1000 / median TPOT`) at bs=1, output tok/s at bs=4, TTFT for a 2,048-token prompt, peak VRAM, time to ready.

## Known limitations

- **Startup is long for GPTQ.** The Marlin repack runs over the host store K experts at a time (slower at small K), and on the first start without a warm JIT cache, compiling upstream's `gptq_marlin` kernel takes minutes on a laptop CPU. With CUDA graphs off, that compile happens on the first request and can exceed the scheduler watchdog; this is upstream behaviour, not specific to paging.
- **The host store is pinned**, so the whole store must fit pinnable memory (WSL2 caps it at about half of system RAM).

+// One warp. The evictions depend on each other and are committed one at a time by lane 0; each
+// victim search and the per-entry bookkeeping are spread over the warp.
+__global__ void paged_experts_decide_kernel(
+    const int32_t* topk,  // [T] routed expert ids of the step (negative: padding)
+    int T,
+    int E,
+    int K,
+    int32_t* step,          // [1] step counter, advanced on the device so replays age the LRU
+    int32_t* slot_expert,   // [K] expert in each slot (-1: empty)
+    int32_t* expert_slot,   // [E] slot of each expert (-1: not resident)
+    int32_t* slot_lastuse,  // [K] step each slot was last used
+    int32_t* src,           // [K] out: experts to page in
+    int32_t* dst,           // [K] out: their slots
+    int32_t* count) {       // [1] out: number of page-ins
+  const int lane = threadIdx.x;
+  int now = 0;
+  if (lane == 0) now = ++(*step);
+  now = __shfl_sync(0xffffffff, now, 0);
+  for (int i = lane; i < T; i += 32) {
+    const int e = topk[i];
+    if (e < 0 || e >= E) continue;
+    const int s = expert_slot[e];
+    if (s >= 0) slot_lastuse[s] = now;
+  }
+  __syncwarp();
+  int n = 0;
+  for (int i = 0; i < T; ++i) {
+    const int e = topk[i];
+    if (e < 0 || e >= E || expert_slot[e] >= 0) continue;  // the same for every lane
+    // Victim: the least recently used slot holding no expert of this step, lowest slot on
+    // ties. Every slot used this step carries `now`, so one is always left while T <= K.
+    int oldest = INT_MAX, victim = K;
+    for (int s = lane; s < K; s += 32) {
+      const int lastuse = slot_lastuse[s];
+      if (lastuse != now && lastuse < oldest) {
+        oldest = lastuse;
+        victim = s;
+      }
+    }
+    for (int offset = 16; offset > 0; offset >>= 1) {
+      const int other_oldest = __shfl_down_sync(0xffffffff, oldest, offset);
+      const int other_victim = __shfl_down_sync(0xffffffff, victim, offset);
+      if (other_oldest < oldest || (other_oldest == oldest && other_victim < victim)) {
+        oldest = other_oldest;
+        victim = other_victim;
+      }
+    }
+    victim = __shfl_sync(0xffffffff, victim, 0);
+    if (victim == K) continue;
+    if (lane == 0) {
+      const int old = slot_expert[victim];
+      if (old >= 0) expert_slot[old] = -1;
+      slot_expert[victim] = e;
+      expert_slot[e] = victim;
+      slot_lastuse[victim] = now;
+      src[n] = e;
+      dst[n] = victim;
+    }
+    ++n;
+    __syncwarp();  // the next search reads this eviction
+  }
+  if (lane == 0) *count = n;
+}

+"""Per-quantization-method expert layout, one ``ExpertFormat`` per fused-MoE method.
+
+A format answers three questions for the method it wraps:
+
+* which per-expert tensors the checkpoint loads (``checkpoint_params``) and which are paged at
+  run time (``paged_params``);
+* what happens after loading, so the host copy holds exactly what the GPU slots would hold
+  (for methods that repack their experts, the repack runs over the host copy K at a time);
+* which runner contract (``runners.py``) its base method's runner follows.
+
+Adding a quantization method means adding a subclass to ``FORMATS``.
+"""
+
+from __future__ import annotations
+
+from abc import ABC, abstractmethod
+from typing import Optional, Tuple
+
+import torch
+
+from sglang.srt.layers.moe.paged_experts.runners import (
+    MARLIN,
+    TRITON,
+    RunnerContract,
+)
+from sglang.srt.layers.moe.paged_experts.store import HostExpertStore
+
+# Prefixes of FusedMoE's per-expert parameters.
+_EXPERT_PARAM_PREFIXES = ("w13_", "w2_")
+
+
+class ExpertFormat(ABC):
+    #: Per-expert tensors the base method creates for loading.
+    checkpoint_params: Tuple[str, ...] = ()
+    #: Per-expert tensors paged at run time.
+    paged_params: Tuple[str, ...] = ()
+    #: Whether the base post-load step repacks the experts; it then runs over the host copy K
+    #: experts at a time.
+    repacks_after_loading: bool = False
+    contract: RunnerContract = TRITON
+
+    @classmethod
+    @abstractmethod
+    def supports(cls, base_method) -> bool:
+        """Whether this format handles ``base_method``."""
+
+    def check_params(self, layer, num_slots: int) -> None:
+        """Raise unless the layer's per-expert tensors are exactly the declared ones."""
+        per_expert = {
+            name
+            for name, p in layer.named_parameters(recurse=False)
+            if name.startswith(_EXPERT_PARAM_PREFIXES)
+            and p.dim() > 0
+            and p.shape[0] == num_slots
+        }
+        if per_expert != set(self.checkpoint_params):
+            raise RuntimeError(
+                f"Paged experts: {type(self).__name__} expects per-expert parameters "
+                f"{sorted(self.checkpoint_params)}, the layer has {sorted(per_expert)}"
+            )
+
+    def after_loading(self, layer, base_method, store, num_slots: int):
+        """Run the base post-load step; return the store to page from, whose experts 0..K-1
+        the GPU slots then hold."""
+        if self.repacks_after_loading:
+            return self._repack(
+                layer=layer,
+                base_method=base_method,
+                staged=store,
+                num_slots=num_slots,
+            )
+        for name, host in store.host.items():
+            getattr(layer, name).data.copy_(host[:num_slots])
+        base_method.process_weights_after_loading(layer)
+        # Paging copies host rows verbatim, so the base method must not transform the
+        # loaded weights (e.g. a kernel-specific shuffle or row interleave).
+        for name, host in store.host.items():
+            gpu = getattr(layer, name).data[0]
+            if not torch.equal(gpu, host[0].to(gpu.device)):
+                raise RuntimeError(
+                    f"Paged experts: {type(base_method).__name__} transforms {name} "
+                    "after loading, which the host store does not replicate"
+                )
+        return store
+
+    def _repack(self, layer, base_method, staged, num_slots: int):
+        """Run the base post-load step over the staged checkpoint layout, K experts at a time,
+        collecting its per-expert output into a new store. Only valid for steps that treat
+        every expert independently."""
+        num_experts = next(iter(staged.host.values())).shape[0]
+        templates = {name: getattr(layer, name) for name in staged.host}
+        packed = None
+        for start in range(0, num_experts, num_slots):
+            n = min(num_slots, num_experts - start)
+            # Fresh parameters in the checkpoint layout: the step may replace or rewrite them.
+            for name, template in templates.items():
+                fresh = torch.nn.Parameter(
+                    torch.empty_like(template.data), requires_grad=False
+                )
+                fresh.__dict__.update(template.__dict__)
+                fresh.data[:n].copy_(staged.host[name][start : start + n])
+                layer.register_parameter(name, fresh)
+            base_method.process_weights_after_loading(layer)
+            if packed is None:
+                packed = HostExpertStore(
+                    layer=layer, names=self.paged_params, num_experts=num_experts
+                )
+            for name, host in packed.host.items():
+                host[start : start + n].copy_(getattr(layer, name).data[:n])
+        for name, host in packed.host.items():
+            getattr(layer, name).data.copy_(host[:num_slots])
+        return packed
