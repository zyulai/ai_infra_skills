## 正文(PR 描述)

## Motivation

`test_deepseek_r1_mxfp4_8gpu.py` (`stage-c-test-large-8-gpu-amd-mi35x`) was failing with a catastrophic GSM8K accuracy drop:

```
AssertionError: 0.1379833206974981 not greater than 0.94
```

i.e. accuracy collapsed from **>0.94 to ~0.09–0.14** on `amd/DeepSeek-R1-MXFP4-Preview` (MI35x, TP=8).

**Root cause:** commit `63df86f5` (PR #28188, *"Skip eplb bookkeeping and topk remap when EPLB is not in use on mori-ep / HIP"*) accidentally moved the padded-region masking **inside** the `_eplb_remap_enabled()` guard in `_post_process_topk_ids`:

```python
# After #28188 (broken for models without EPLB):
elif _is_hip:
    if _eplb_remap_enabled():                                  # False for MXFP4
        _mask_topk_ids_padded_region(topk_ids, ..., fill_value=0)   # never runs!
        topk_ids = topk_ids_logical_to_physical(...)
    _zero_topk_weights_padded_region(topk_weights, ...)
```

For models that do **not** use EPLB (the common case, including DeepSeek-R1-MXFP4), `_eplb_remap_enabled()` returns `False`, so `_mask_topk_ids_padded_region` is **never called**. The padded slots of `topk_ids` keep garbage/out-of-range expert IDs from the kernel. Although routing weights are zeroed, the aiter MoE / MXFP4 indexer kernels read `topk_ids` directly to index expert weight tables **before** the weighted sum, so the garbage IDs corrupt the computation and wreck accuracy.

## Modifications

- In `_post_process_topk_ids` (HIP branch), call `_mask_topk_ids_padded_region(topk_ids, num_token_non_padded, fill_value=0)` **unconditionally**, so padded tokens always get a valid in-range expert id (`0`; aiter cannot handle `-1`).
- Keep only the logical→physical remap (`topk_ids_logical_to_physical`) inside the `_eplb_remap_enabled()` guard — that part of #28188's intent is correct.
- `_zero_topk_weights_padded_region` remains unconditional (unchanged), so padded tokens still contribute nothing to the hidden state.

Net diff is small (+9 / −8 in `python/sglang/srt/layers/moe/topk.py`).

## Accuracy Tests

Validated end-to-end on **AMD Instinct MI355X (gfx950), TP=8** via the registered test (CI run [27598431399](https://github.com/sgl-project/sglang/actions/runs/27598431399)):

```
TestDeepseekR1MXFP4.test_a_gsm8k       -> Accuracy: 0.950   [PASS]   (was ~0.09)
TestDeepseekR1MXFP4.test_bs_1_speed    -> speed=152.01      [PASS]
TestDeepseekR1MXFP4MTP.test_a_gsm8k    -> Accuracy: 0.950 / 0.960   [PASS]
```

The masking logic was also unit-tested directly on MI355X: padded `topk_ids` are correctly clamped to `0`, real tokens are untouched, and the pre-fix garbage behavior is reproduced.

> **Note — one unrelated MTP failure remains:** `TestDeepseekR1MXFP4MTP` reports `avg_spec_accept_length=1.45 (<2.04)`. This is **not** caused by this PR (accuracy is a perfect 0.95, and this change only touches padded tokens). It is the cross-stream race fixed by #28410 — the MTP test enables `SGLANG_ENABLE_OVERLAP_PLAN_STREAM`, which triggers the `predict.to(torch.int64)` plan-stream race introduced by #28043. This PR will be rebased and re-validated once #28410 lands.

## Speed Tests and Profiling

No performance impact: the change only adds an unconditional in-place mask of the padded region (which the original pre-#28188 code already did). `test_bs_1_speed` is green at **152.01 token/s**.
