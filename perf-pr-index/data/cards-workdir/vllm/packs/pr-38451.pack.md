## Purpose
From profiling trace it seemed like DeepEP HT backend wasn't fully overlapping the compute and communication. 
<img width="1058" height="187" alt="Screenshot 2026-03-26 at 8 54 34 PM" src="https://github.com/user-attachments/assets/5bf3d5a0-81b3-4781-8384-566c6f13ac04" />
The only thing being overlapped is one of the ubatch combine with the other ubatch non-moe compute.

Going through the DBO code it seems that the core issue is the `previous_event` that is passed to DeepEP dispatch/combine. The way it's implemented, DeepEP will wait for the entire compute stream to finish before launching dispatch. Since we have yielded via `dbo_yield_and_switch_from_compute_to_comm()` right before this point, the compute stream will contain compute enqueued by the other ubatch that the current ubatch doesn't need to depend on. The fix is to move the DeepEP event capture right before yield so it correctly captures the compute tail of the current ubatch.

After, the same model trace:
<img width="1338" height="196" alt="Screenshot 2026-03-28 at 8 02 57 PM" src="https://github.com/user-attachments/assets/04a17584-3ae6-48b1-a2cb-cf453abb7232" />
so now there is more overlap but the core dependency is still preserved.
