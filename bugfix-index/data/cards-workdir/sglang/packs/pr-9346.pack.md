## 正文(PR 描述)

# Background
When using FP4 quantization with the glm4.5-air model, the inference outputs may contain corrupted/garbled text. #8814 
# Root Cause
The quantization operator in sglang used `torch.empty` to create tensors;
* During padding, `empty` could introduce random values;
* These random values were later converted into NaN when mapped to nvfp4 format;
* In glm4.5’s first MLP layer, the intermediate size is 10944, which under tp=2 triggers padding. This may caused NaN values to be introduced into the matrix and propagated into subsequent GEMM computations;
* Therefore, the issue is always triggered in glm4.5’s first layer. In other layers or other models, the same issue may also occur whenever irregular shapes cause padding during quantization.
# Fix
* Replace torch.empty with explicitly initialized tensors (e.g., torch.zeros);
* Ensure padding regions are zeroed out, preventing random values from being converted to NaN in nvfp4 format and propagated downstream.
# Validation
* After the fix, glm4.5-air FP4 inference no longer produces corrupted output;
* Multiple benchmarks ran successfully with correct results.
