## PR body

## Summary

- enable the existing diffusion breakable CUDA graph runner for `meituan-longcat/LongCat-Image`
- keep LongCat's fixed 512-token DiT prompt shape unchanged so the generic BCG buckets do not capture unused expanded signatures
- document the deployment command and refresh the checked-in diffusion performance/profile skills

## Why

LongCat's native eager DiT trace is launch-heavy between attention calls. The existing BCG runner can capture those regions as 31 graph segments, but LongCat was not admitted by the model and pipeline allowlists.

LongCat always sends the full 512-token prompt body to the DiT. A small model-specific pass-through padder therefore preserves one reusable signature for short and long raw prompts instead of applying generic prompt padding.

## Production-shape visual and end-to-end A/B (B300)

Prompt from the checked-in LongCat diffusion benchmark preset: `A red panda reading a book beside a sunlit window.`

Configuration: NVIDIA B300 SXM6 AC, native `--backend sglang`, BF16, 1 GPU, 1024x1024, 50 steps, guidance 4.5, seed 42, prompt rewrite disabled, `quality=lossless`, `--performance-mode manual`.

![LongCat main eager versus PR BCG](https://raw.githubusercontent.com/BBuf/sglang/pr-media/diffusion-prs/35724/main-vs-pr.jpg)

The main and PR PNGs are byte-exact (`sha256=6a44ff30a185993f50d23da660b3cbe42fb8fdf8ac1d0d612d0086f35c723372`).

| Path | Saved-request e2e runs | Mean e2e | Mean denoise stage |
| --- | --- | ---: | ---: |
| main, eager | 7.422 / 7.421 / 7.445 s | 7.429 s | 7.109 s |
| this PR, BCG | 7.178 / 7.174 / 7.175 s | 7.175 s | 6.261 s |

That is a **3.42% end-to-end reduction** and an **11.93% denoise-stage reduction** on B300. Request e2e starts immediately before `generate()` and ends after the output file exists and its SHA256 is recorded, so it includes prompt encoding, DiT, VAE decode, materialization, and PNG saving. Model loading, the one-time 16.43 s BCG capture, and one benchmark warmup are excluded. Logs confirm the native backend with no diffusers fallback.

The task-owned B300 LongCat cache was deleted after this model group: 29,316,959,360 bytes removed and zero residual model-cache files verified.

## Validation

- `pre-commit run --files ...` on all changed files
- `python -m pytest -q python/sglang/multimodal_gen/test/unit/test_diffusion_bcg_padding.py`: 22 passed
- H200, BF16, 1 GPU, 1024x1024, 50 steps, guidance 4.5, prompt rewrite disabled, lossless quality:
  - eager: 177.3 / 177.0 / 177.2 ms per denoise step across three different prompt lengths
  - BCG: 173.1 / 173.3 / 173.1 ms per denoise step (about 2.3% faster)
  - all three BCG outputs were pixel-exact against eager
  - one 31-segment graph was captured and reused for all three prompts
- default BCG text buckets also captured exactly one graph without bucket warnings; the 8-step output remained pixel-exact
- task-owned LongCat cache cleanup: removed 58,644,690,730 bytes and verified zero residual model-weight files

BCG remains opt-in and resolution-specific. The H200 peak was about 33.4 GB with BCG versus 31.7 GB eager.
