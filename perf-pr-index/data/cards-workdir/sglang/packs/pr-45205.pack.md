## Motivation

This PR enables HiCache for DSA (For GLM and DeepSeek models) DCP on ROCm, including the packed MTP draft, for device + host (L1/L2) and for L3 storage backends. Under DCP the DSA index-K is replicated on every rank rather than row-sharded like the MLA KV, so this PR also gives it its own L3 page span: one L3 key covers `dcp_size` of its pages instead of one page per rank.

**Result** (GLM-5.2-MXFP4, TP4/EP4 + DCP4, MI355X, AgentX):

| Conc | P90 interactivity (tok/s/user) | Throughput (tok/s/GPU) | P90 TTFT (s) |
|---|---|---|---|
| 40 | 21.51 → **24.42** (+14%) | 27,749 → **29,444** (+6%) | 2.57 → **1.90** |
| 48 | 6.03 → **18.91** (3.1x) | 18,361 → **32,764** (1.8x) | 11.74 → **2.57** |

## Scope

- Only affects ROCm with `dcp_size > 1`. On CUDA, DSA DCP + HiCache is still rejected; nothing changes without DCP.
- L1/L2 and L3 are supported. L3 was checked with the file and Mooncake backends; `buffer_only` host memory is still rejected under DCP. 
- #48877 enabled the DSA L3 path for a row-sharded index-K. This extends it to the replicated layout DeepSeek-V3.2 and GLM use. 
- Speculative decoding: DSA MTP (EAGLE) on ROCm, whose draft KV packs into the target's DCP host rows, plus the DSPARK / DFLASH drafts that were already allowed. Other draft models are rejected, since their host pools have no DCP index translation.
- Still rejected under DSA DCP: HiSparse, LMCache, PD disaggregation (except on NPU), and `--speculative-eagle-topk` other than 1.

## Correctness

MI355X, `amd/GLM-5.2-MXFP4`, TP4 + DCP4, fp8 KV, MTP (EAGLE), HiCache `write_through`.

**Result: all pass.**
