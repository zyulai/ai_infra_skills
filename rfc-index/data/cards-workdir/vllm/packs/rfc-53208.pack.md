## 正文(PRD / 提案全文)

### Motivation.

`kernel_warmup()` (vllm/model_executor/warmup/kernel_warmup.py:98-215) runs a fixed warmup sequence from `Worker.compile_or_warm_up_model` (vllm/v1/worker/gpu_worker.py:728), just before CUDA graph capture. Per the module docstring (kernel_warmup.py:3-7) the sequence exists for JIT'ed kernels. Some entries are already individually controllable — `VLLM_DEEP_GEMM_WARMUP=skip` (:162-166), `kernel_config.enable_cutedsl_warmup` (:149), `kernel_config.enable_flashinfer_autotune` (:176-183) — and `kernel_config.enable_jit_warmup` (:110) is an all-or-nothing gate for the registry. But the set is ad hoc, and some entries have no switch at all: `qwen_triton_warmup` (:126) sits outside every gate.

We maintain an out-of-tree hardware platform plugin for a non-CUDA accelerator, which redirects the GDN ops to an AOT-compiled kernel library. With no JIT to hide, the warmup is pure startup cost for us — and the dummy inputs upstream builds for the reference Triton kernels do not satisfy our AOT kernels' host-side argument validation. Concretely, `_warm_fused_sigmoid_gating_delta_rule_update_kernel` (vllm/model_executor/warmup/qwen_triton_warmup.py:203-241) builds `initial_state` as a rank-2 tensor (:216-220) and passes it at :235. The reference Triton path never notices, since it only reads `initial_state.stride(0)` (vllm/third_party/flash_linear_attention/ops/fused_sigmoid_gating.py:231) and forwards the tensor as a raw pointer (:253). Our kernel requires rank 4 and rejects it, so engine startup fails.


### Current workaround.

Our plugin monkeypatches the private `qwen_triton_warmup._warm_fused_sigmoid_gating_delta_rule_update_kernel` into a no-op. It depends on a private symbol and breaks on any upstream refactor, which is what prompted this RFC.


### Proposed Change.

One generic opt-out axis, rather than a new env var per warmup. Two sketches:

**A — named warmups + skip list.** Give each entry in `kernel_warmup()` a stable name and add e.g. `VLLM_SKIP_KERNEL_WARMUPS=qwen_triton,deep_gemm`. This mirrors `VLLM_FLASHINFER_AUTOTUNE_SKIP_OPS` (vllm/envs.py:1716-1724, consumed at kernel_warmup.py:218-234), which is already a comma-separated name skip list.

**B — platform hook.** `current_platform.get_skip_kernel_warmups() -> set[str]`, consumed where `KernelConfig.set_platform_defaults` (vllm/config/kernel.py:285-311) already calls `current_platform.get_default_ir_op_priority` (vllm/platforms/interface.py:1299). A platform knows whether its kernels are JIT or AOT, so a plugin can declare this itself instead of asking operators to set env vars.

The two compose: B supplies the default, A lets a user override it. Default behaviour is unchanged — an empty skip list or an unimplemented hook runs every warmup exactly as today. Purely additive and backward compatible.
