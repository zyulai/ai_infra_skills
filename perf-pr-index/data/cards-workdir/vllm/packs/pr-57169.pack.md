## PR body
```markdown
## Purpose

Move kernel block splitting from the block table into each attention group. Previously `BlockTable` split every manager block for the whole KV cache group (`kernel_block_sizes`). All backends in a group had to share one kernel block size, block tables and slot mappings were at kernel granularity, and packed (block-outermost) caches could not be split at all, since other layers' pages sit between a layer's blocks. Now block tables stay at manager granularity, and each `AttentionGroup` maps manager blocks to the kernel blocks its own backend needs.

On top of this, GLM-5.3-Flash moves to the generic packed KV layout, and its model-specific KV code is removed.

## Design

### Kernel block mapping

**Choosing the kernel block size**
- `prepare_kernel_block_sizes` picks a size per KV cache group with `select_common_block_size(manager, backends, specs)`. Packed groups keep the manager block size and are never split group-wide.
- Each `AttentionGroup` then picks its own size for its backend and spec. It sets `kernel_block_size` only when that is smaller than the manager block.

**Mapping block tables**
- The group maps manager block `b` to kernel blocks `b * stride + j` (`j < block_size / kernel_block_size`).
  - `stride` is the number of kernel blocks per manager block.
  - For packed caches it is the packed block stride in kernel blocks.
- The mapped table is persistent and preallocated per ubatch, so CUDA graphs capture a stable buffer.
- Mapping happens inside `build_metadata`, `build_metadata_for_cudagraph_capture` and `build_metadata_for_drafting`. All runners and drafters (V1/MRv2, EAGLE, Gemma4, Step3.5, DFlash) go through these. Fused multi-step draft decode re-maps before replaying a FULL graph.
- `BlockTable`/`InputBatch` (V1 and MRv2) drop `kernel_block_sizes`. Slot mappings, CP and DFlash stay at manager granularity.

**Mapping KV views**
- When KV caches are bound, each group views its cache in kernel blocks. Packed caches use `as_strided` with the packed block stride.
- Only compressed caches (`tokens_per_state > 1`) may be split this way, because their write slots come from the mapped block table. Token and pooled caches are written through manager-block slot mappings, so they are rejected.
- The KV block zeroer maps the views back to manager blocks.

**Alignment**
- `block_stride_alignment` accepts `MultipleOf(n)`, meaning whole kernel blocks of up to `n` tokens, so a packed block always splits into whole kernel blocks.
- Fixed-size backends get it automatically; sparse MLA backends set their own in `customize_spec`.
- Bytes per block: block-outermost layouts round to the lcm of all alignments; layer-outermost layouts pad each layer's page separately.

**Consumers:** NIXL, Mooncake and HiSparse pick kernel block sizes the same way as the worker.

### GLM-5.3-Flash

- Uses the packed `BLHNC` layout. Removed its custom groups, byte layout, `KpoolTailSpec` and `storage_block_size`.
- The kpool indexer is a compressed spec whose backend declares DeepGEMM page sizes (32/64; 64 on SM120). The tail is a `CircularBufferSpec` ring of `kpool + num_speculative_tokens`.
- FlashMLA fp8 on SM90 reads 64-token pages over flat rows, so packed blocks need not be split.

**Example** (GLM-5.3-Flash on H200, manager block = 640 tokens, `index_kpool = 4`):

| Attention group | States per manager block | Kernel block | Kernel blocks per manager block |
|---|---|---|---|
| Sparse MLA (`FLASHMLA_SPARSE`) | 640 | 640 (no split) | 1 |
| kpool indexer (`tokens_per_state = 4`) | 160 | 32 (DeepGEMM page) | 5 |

For a request with manager block table `[7, 2]`:
- **Sparse MLA** builds its metadata from `[7, 2]` unchanged.
- **The indexer group** maps it to `[7·S, …, 7·S+4, 2·S, …, 2·S+4]`, where `S` is the stride between manager blocks in kernel blocks:
  - In a plain (layer-outermost) cache, `S = 5`, giving `[35..39, 10..14]`.
  - In the packed `BLHNC` cache, each manager block also holds the other layers' pages, so `S` is the packed block size divided by the indexer's 32-state page. `MultipleOf` alignment keeps that an integer.

The scheduler, slot mappings and other groups never see kernel blocks. On main, the whole group had to share one kernel block size, so the indexer needed the GLM-only `storage_block_size` workaround instead.
```
