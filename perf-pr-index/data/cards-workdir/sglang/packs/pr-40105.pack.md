## Motivation

@humansand

Default to unfused FlashInfer MoE finalize for better numerical accuracy. Users can opt in to fused atomic finalize with `SGLANG_FLASHINFER_MOE_FUSED_FINALIZE=1` when they prefer more aggressive performance.

- **History:** [#28354](https://github.com/sgl-project/sglang/pull/28354) introduced this environment variable with `EnvBool(True)` and made deterministic inference force it to `0`.
- **Prior behavior:** immediately before #28354, the [CUTLASS calls](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/layers/moe/moe_runner/flashinfer_cutlass.py#L221-L238) and [CuTe DSL v2 wrapper](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/sglang/srt/layers/moe/moe_runner/flashinfer_cutedsl.py#L287-L302) omitted `use_fused_finalize`. SGLang [pinned FlashInfer 0.6.17](https://github.com/sgl-project/sglang/blob/c4271c3fe1262fc2adbd162c33b25de5255251c5/python/pyproject.toml#L36), whose [CUTLASS API](https://github.com/flashinfer-ai/flashinfer/blob/a0a6b019b9b27d49d209f85d028a1ae5a9b347d7/flashinfer/fused_moe/core.py#L943) and [CuTe DSL wrapper](https://github.com/flashinfer-ai/flashinfer/blob/a0a6b019b9b27d49d209f85d028a1ae5a9b347d7/flashinfer/fused_moe/cute_dsl/fused_moe.py#L464) both defaulted to `True`. Thus #28354 exposed the existing fused-finalize default as a SGLang setting; this PR changes that default to `False` for the callers that honor it. The separate CuTe DSL v1 DeepEP masked path is outside this flag's scope.

## Modifications

- **Default:** change `SGLANG_FLASHINFER_MOE_FUSED_FINALIZE` from `EnvBool(True)` to `EnvBool(False)`.
- **Documentation:** update the default and explain the performance opt-in.
- **Existing paths:** CUTLASS and CuTe DSL callers continue to read the same flag; deterministic inference continues to force it off. No kernel changes or new tests.

## Speed Tests and Profiling

- **Result:** Disabling fused finalize has a measurable W4A4 cost in this EP8 sweep. CuTe W4A4 per-tensor latency increases **21.75% at 1 token**. At **16,384 tokens**, latency changes by **+7.82% for CUTLASS**, **+12.55% for CuTe W4A4 per-tensor**, **+10.70% for CuTe W4A4 per-token**, and **-9.20% for CuTe W4A16**. These single sweeps do not support a blanket claim of negligible regression. Users can retain `SGLANG_FLASHINFER_MOE_FUSED_FINALIZE=1` when this performance tradeoff matters.
- **Scope:** [`benchmarks/bench_moe_deepseek.py`](https://github.com/flashinfer-ai/flashinfer/blob/8bc3b578027791336c6ae87db5c9d76f82cef8bc/benchmarks/bench_moe_deepseek.py) at official release [`v0.6.18.post1`](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.6.18.post1), commit `8bc3b578027791336c6ae87db5c9d76f82cef8bc`. All four configurations were measured with simulated EP=8 using the benchmark-only patch below: forward the existing finalize option to CUTLASS and add a W4A4-only selector. No FlashInfer runtime/kernel changes. This directly compares the FlashInfer flag used by SGLang PR head `e3bcc8f7b4337565baea1d2b44fd4f0f838b1953`.
- **Hardware/image:** 1× NVIDIA B300 SXM6 AC (SM103; GPU 0 of an allocated 8-GPU node), 275,040 MiB reported memory, 1,100 W power limit, driver `590.48.01`. Image `lmsysorg/sglang:nightly-dev-cu13-20260918-20518d85`, runtime digest `sha256:d46a59f4b98658f728a1e006c003ad5ee0628e999fd8b2bef71ac1bb61b814da`. Run date: 2026-09-18 UTC.
- **Software:** Python `3.12.3`, PyTorch `2.13.0+cu130`, CUDA toolkit `13.0.88`, `flashinfer-python==0.6.18.post1`, `flashinfer-cubin==0.6.18.post1`, `flashinfer-jit-cache==0.6.18.post1+cu130`, `nvidia-cutlass-dsl==4.6.2`, `apache-tvm-ffi==0.1.11`, `cupti-python==13.4.0` (`nvidia-cuda-cupti==13.4.92`). The image shipped FlashInfer 0.6.18; all three FlashInfer packages were updated to the matched official post1 release before measurement.
- **Workload:** DeepSeek-V3 MoE: hidden 7,168, intermediate 2,048, 256 experts, top-8, 8 routing groups/top-4 groups, routed scale 2.5, random seed 42, routing bias scale 0.01; simulated EP=8, TP=1: rank 0 holds experts 0–31 of 256. The token count is the global input batch routed across all 256 experts; this single-GPU benchmark computes the local expert contribution. Powers of two from 1 through 16,384 tokens. CUTLASS uses NVFP4 W4A4 per-tensor activation scaling. CuTe DSL covers NVFP4 W4A4 per-tensor, NVFP4 W4A4 per-token, and NVFP4 W4A16 with BF16 input, using its wrapper API.
- **Timing:** one complete flag-True sweep followed by one flag-False sweep for each configuration; no repeated or reverse-order sweeps. Independent autotuning caches per backend/activation/finalize mode; 10 warmups, 100 measured iterations per case, native median GPU latency, CUDA graphs and CUPTI with cold-L2 flushing. Routing, input activation quantization (`--include-activation-quant`, for W4A4), both expert GEMMs, and finalize are included. Weight preparation, compilation, and autotuning are excluded. W4A16 consumes BF16 input directly. All six commands exited 0, yielding all 120 requested latency rows with no CUPTI fallback warnings.
- **Build/provenance:** all EP8 runs used the same physical GPU (UUID `GPU-aa4e94df-96de-22b9-87c2-9960d6b27cb8`), image, and package versions. JIT was left enabled. The release wheel provides `fused_moe_103.so` and `fp4_quantization_103.so` for CUTLASS MoE and FP4 quantization; no CUTLASS build was needed.
- **Limits:** single sweeps provide no repeat/order-variation statistics. This covers local MoE only: no inter-GPU communication, other EP/TP layouts, model accuracy checks, or end-to-end serving. No numerical-error reduction is measured here.

**Speedup = latency with `use_fused_finalize=True` (old default) / latency with `False` (proposed default); greater than 1 means disabling fused finalize is faster.** CUTLASS `True` permits eligible fused-finalize tactics; autotuning can still choose an unfused tactic.
