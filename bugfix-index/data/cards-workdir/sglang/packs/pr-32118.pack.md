## 正文(PR 描述)

## Summary

Independent fixes for failures found triaging the Nightly Test (Nvidia) run, each reproduced with a full traceback and root-caused before fixing.

2. **`nvila.py`**: `test_vlms_mmmu_eval.py` crashed with `stack expects each tensor to be equal size` — `get_image_feature` used `torch.stack` on per-image vision-feature tensors whose patch count varies with image resolution, then immediately flattened the stacked dim away with a rearrange. Replaced with `torch.cat` directly (what the code actually wanted).

3. **`flash_attn/cute/interface.py`**: `test_disaggregation_dwdp_mimo.py` / `test_mimo_cp.py` crashed with `ValueError: Expected size in shape to be strictly positive, but got 0` in the CuTe FA4 paged-KV kernel. Root cause: the SM100 diff-headdim (`head_dim != head_dim_v`, e.g. 192/128) SMEM-saving optimization shrinks `n_block_size` to 64 under split-KV, but for `q_stage==1` (decode) with paged KV, the non-TMA load path uses 128 threads, so `page_entry_per_thread = n_block_size // num_threads` floors to 0. Skip the shrink for that specific combination. Reproduced standalone on real B300 hardware with MiMo-V2.5's actual config (`head_dim=192`, `head_dim_v=128`, default `page_size=1`, forced split-KV) — crashed before the fix, produced finite correct-shaped output after.

4. **`kimi_vl.py` / `kimi_vl_moonvit.py`**: `test_vlms_mmmu_eval.py` also crashed on Kimi-VL. MoonViT's vision tower forced HF's `sdpa` attention path (dense attention over all packed image tokens) instead of sglang's own flash-attn, causing an OOM; fixed by routing MoonViT's attention through sglang's `VisionAttention` wrapper (same pattern `kimi_k25.py`'s MoonViT-style vision tower already uses), which also required remapping the vision checkpoint's `wqkv`/`wo` weight names to the wrapper's `attn.qkv_proj`/`attn.proj` names in `load_weights`.

## Test plan

- [x] All changed files compile and pass `pre-commit` (isort/ruff/black).
- [x] CuTe paged-KV fix verified with a standalone repro script directly calling `flash_attn_varlen_func` with MiMo-V2.5's real head_dim/head_dim_v/page_size, both batch_size=1 and batch_size=8 — crashes on `main`, succeeds with finite output after the fix.
- [x] NVFP4 pinned-memory fix verified with a standalone repro directly capturing `nvfp4_quantize(..., backend="cute-dsl", per_token_activation=True)` in a real `torch.cuda.graph()` — crashes on unpatched flashinfer, succeeds after the upstream fix.

- [ ] `/rerun-test` on the originally-failing files (posting next).
