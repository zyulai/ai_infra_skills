## PR body
```markdown
## Motivation

This PR enables `--dcp-size > 1` for the RoPE DSA models on the `triton` DSA backends, which is the path ROCm runs. Previous work [#43735](https://github.com/sgl-project/sglang/pull/43735) brought DCP to these models on the `trtllm` backends; this builds on that work and supplies the pieces the triton path additionally needs:

- The triton sparse-MLA kernel now returns its LSE(Log-Sum-Exp), so the per-rank partials can be merged.
- The HIP FP8 KV cache now works under DCP: writes land on the row the reader looks up.
- Fixes the GPU memory access fault the ROCm DSA MTP draft hit under DCP, by putting the draft on the target's sharding and addressing rule.

## Correctness

MI355X, `amd/GLM-5.2-MXFP4`, TP4/EP4, FP8 KV, MTP (EAGLE, 5 steps, 6 draft tokens), real draft acceptance.

| check | no DCP | PR after; DCP=4 |
|---|---|---|
| passkey 8K / 34K / 96K | 3/3 | 3/3 |
| GSM8K (400 questions, few-shot) | 0.953 | 0.953 |
| MTP accept length (4 prompts x 400 tokens, greedy) | 3.11 | 3.47 |
| KV capacity (tokens) | 2.83M | 8.81M (2.20M rows per rank x 4) |

The FP8 write kernel test passes with 4 simulated ranks, and the triton LSE matches at the kernel level.

## Modifications

Correctness:

- **`DSA DCP on the triton sparse-MLA backend`** 811248c80b
    - The triton sparse-MLA decode now returns an LSE, which DCP needs to merge each rank's partial result — letting decode, target verify and paged extend reuse upstream's DCP path.
- **`Shard the DSA FP8 latent KV write under DCP`** fa4f2fc48f
    - The FP8 quant write only writes `slot % dcp_size == dcp_rank`, at row `slot // dcp_size`, the same rule as the BF16 write.
- **`Shard the DSA MTP draft KV like the target under DCP`** 20107f85b8
    - Fixed GPU memory access fault on DSA EAGLE/NEXTN draft. Puts the ROCm DSA draft on the target's allocator page and owner rule, with extend on the owned-slot path.

Performance:

- **`Bound the triton DCP sparse-MLA scan by the owned top-k count`** 171e960082 
    - `localize_dcp_page_table` already returns the per-row owned count, but the triton path dropped it and scanned all top-k slots, masking about (W-1)/W of them. The kernels now stop after the owned tiles.

- **`Split DSA prefill indexer rows across the DCP group`** d7f9605feb 
  - DCP now splits the rows evenly across ranks instead of computing the same top-k `W` times. The results are all-gathered directly into the destination buffer when possible.

- **`Gather the DSA DCP Q in the FP8 KV dtype`** b8a0a1ac70
  - Halves the Q traffic between DCP ranks with no change in results, because the kernel converted Q to that same format on arrival anyway.

Scope: Without DCP nothing changes: the new arguments default to the old behavior. CUDA is untouched; the draft sharding is gated on `is_hip()`. On ROCm, pass `--dsa-prefill-backend triton --dsa-decode-backend triton`, because #43735 defaults to `trtllm` when they are unset.

## Known issues

- DCP rejects HiCache, so once the DCP pool is full (c48 above), evicted prefixes are recomputed rather than reloaded from host. HiCache under DCP is a #43735 fast follow.
- Add feature to enable DCP+HiCache at #45205
```

```diff
+def dcp_split_rows(rows: int) -> Tuple[int, int, int, int]:
+    """``(per, slot, lo, hi)``: every rank owns a stride of ``per`` rows starting
+    at ``slot``, and scores the rows ``[lo, hi)`` of it that exist.
+
+    The uniform stride makes the rank-major concatenation of the strides land
+    row ``i`` back at row ``i``. ``slot`` is not clamped to ``rows``: the
+    in-place all-gather needs this rank's own slot even when it has no rows.
+    """
+    group = get_parallel().dcp_group
+    per = -(-rows // group.world_size)
+    slot = group.rank_in_group * per
+    return per, slot, min(slot, rows), min(slot + per, rows)
```
