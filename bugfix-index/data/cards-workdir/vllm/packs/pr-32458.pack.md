## 正文(PR 描述)

related issue: https://github.com/vllm-project/vllm/issues/32391

## Purpose
CI was not reliably running shellcheck due to invalid find invocation, so issues could slip through unnoticed.
Initially started as a small one-line fix but after correcting the find command, CI began failing due to pre-existing shellcheck errors in the affected scripts. This PR restores a working signal by fixing the CI invocation and introducing a baseline, so CI only fails on newly introduced warnings.

## Summary
- Fix CI script issues causing silent failures
  - Enable set -euo pipefail
  - Correct invalid find usage that caused the shellcheck hook to behave incorrectly
- Add a shellcheck baseline for existing warnings
  - The corrected find command exposed ~350 pre-existing issues (mostly minor lint errors). Full log: [gist link](https://gist.github.com/junuxyz/047a464666c6b5b3a618a78ec7971f35)
  - CI now fails only on warnings not in the baseline, preventing regressions while deferring cleanup
- Error reporting uses shellcheck's --include flag to show only new issue codes per file, avoiding noise from baselined issues
- Add -generate-baseline flag to regenerate the baseline file if needed
All changes are limited to CI and tooling — no runtime or example behavior is modified.

## Details

### Initial Fix
```bash
find . -path ./.git -prune -o -name "*.sh" -not -path "./.buildkite/scripts/hardware_ci/run-amd-test.sh" -print0 | xargs -0 -I {} sh -c 'git check-ignore -q "{}" || shellcheck -s bash "{}"'
```

However this revealed errors that had been silently ignored:

```bash
❯ find . \
  -type d \( -name .git -o -name .venv -o -name .deps \) -prune -o \
  -type f -name '*.sh' -print0 \
| xargs -0 ./shellcheck-stable/shellcheck -f json -s bash 2>/dev/null \
| grep -oP '"level":"\K[^"]+' \
| sort | uniq -c
      2 error
    303 info
     12 style
     34 warning
```

Since fixing all ~350 issues at once isn't practical, I introduce shellcheck.baseline to track known issues. This allows CI to catch new errors while deferring cleanup of existing ones.

Only errors not in the baseline are reported. shellcheck is invoked with --include filtered to only the new SC codes for each file, so baselined issues in the same file are excluded from output.
