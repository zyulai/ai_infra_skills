## 正文(PRD / 提案全文)

### Motivation.

## Summary

Add `vllm bench eval`, a new `vllm bench` subcommand that runs an [lm_eval](https://github.com/EleutherAI/lm-evaluation-harness) accuracy evaluation and a Prometheus `/metrics` performance collection pass **in the same server session**, producing a single JSONL record per run that contains accuracy results, latency/throughput metrics, and structured environment info (`vllm collect-env`).

## Motivation

We already run lm_eval suites in CI and on hardware validation rigs. Those runs spin up a `vllm serve` process, send thousands of requests through it, then tear it down, consuming significant GPU-hours.

Today we get accuracy numbers from those runs but **nothing about inference performance**: no TTFT, no TPOT, no throughput, no cache utilisation. As a result:

- **Performance regressions go undetected** until a user reports slowdowns after a release.
- **Hardware-specific pathologies** (e.g. a ROCm kernel regression on MI300X, a NCCL change on a 8-GPU node) are invisible in CI accuracy dashboards.
- **Accuracy and performance are tracked in separate systems** with no shared provenance it's impossible to correlate "this commit improved accuracy by 0.3 points but regressed TTFT p95 by 40%".

The fix is not to add a second job but to instrument the job we are already paying for.

### Proposed Change.

### High-level flow

```
vllm bench eval --model <M> --tasks <T> [--tp N] [--output results.jsonl]

  1. collect-env          (before GPU is loaded, ~2s)
  2. vllm serve <M>       (managed subprocess)
  3. /metrics polling     (background thread, 2s interval)
  4. lm_eval              (subprocess -> /v1, same requests CI already sends)
  5. stop collector
  6. append JSONL record
  7. shutdown server
```

Steps 3 and 4 run concurrently, no extra GPU time. Total overhead versus a plain lm_eval run: ~10s for server startup + `collect-env`.

### Performance metrics source

Metrics are read from vLLM's existing Prometheus `/metrics` endpoint, no new instrumentation needed. The collector parses histogram buckets directly so it can report **p50/p95/p99**, not just averages derived
from `_sum/_count`. Key metrics include TTFT, TPOT, end-to-end latency, token/request throughput, and peak GPU cache and queue usage.

### Output format

Each run appends **one JSON line** to the output file containing three top-level sections:

- **`metadata`**: run ID, model, tasks, timestamp
- **`accuracy`**: per-task results as reported by lm_eval
- **`performance`**: latency percentiles, throughput, peak resource usage
- **`environment`**: full `vllm collect-env` output (system, PyTorch, GPU, pip packages, env vars)

Runs accumulate in a single file; downstream tooling filters by `metadata.run_id` or `metadata.timestamp`. Each record is self-describing, no need to correlate with a separate environment log.

### Environment provenance

`vllm collect-env` is called **before** the server starts to avoid timing interference with GPU initialisation. Embedding the full output in every record means any single result can be understood in isolation.

### Connecting to an existing server

To support multi-step CI pipelines or local development, `vllm bench eval` accepts an `--existing-server` flag that skips server lifecycle management and connects to an already-running instance:

```bash
vllm bench eval \
  --model meta-llama/Llama-3-8B \
  --tasks hellaswag \
  --existing-server http://localhost:8000 \
  --output results.jsonl
```

## Usage

```bash
# CI integration - replace existing plain lm_eval invocation
vllm bench eval \
  --model meta-llama/Llama-3-8B \
  --tasks hellaswag,gsm8k,mmlu \
  --tp 8 \
  --output /artifacts/results.jsonl

# Quick local smoke test
vllm bench eval \
  --model meta-llama/Llama-3-8B \
  --tasks hellaswag \
  --limit 50 \
  --existing-server http://localhost:8000
```

Results accumulate across runs, enabling regression detection. Example:

```python
import json, pandas as pd

records = [json.loads(l) for l in open("results.jsonl")]
df = pd.json_normalize(records, sep=".")
# plot performance["ttft_p95_s"] over time, grouped by metadata["model"]
```
