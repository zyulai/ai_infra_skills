## Motivation

#33037 forced off `--enable-symm-mem` on Kimi hybrid under CUDA graphs because a PyTorch caching-allocator bug made per-forward symm-mem allocations land at different offsets on different ranks, corrupting DSPARK spec decode.

That bug is fixed upstream in PyTorch ([#183489](https://github.com/pytorch/pytorch/pull/183489)), which is in torch==2.13.0 (#28836). SGLang now runs on 2.13.0, so the guard is no longer needed.

## Modifications

Removed the disable_kimi_k3_symm_mem guard added in #33037, so Kimi hybrid honors --enable-symm-mem under CUDA graphs again:

  - python/sglang/srt/arg_groups/kimi_k3_hook.py — deleted disable_kimi_k3_symm_mem.
  - python/sglang/srt/server_args.py — in _handle_cuda_graph_config, dropped the import, the stale comment, and the call.

No new deps/APIs and the symm-mem alloc/register path is untouched.
