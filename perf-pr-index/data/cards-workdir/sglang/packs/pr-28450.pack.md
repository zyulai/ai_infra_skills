## Motivation

On the AMD aiter / DeepEP-class MoE path, every layer runs the shared-expert
append (`fused_append_shared_experts`) immediately followed by the eager DeepEP
interleaved remap (`_remap_topk_for_deepep`). The remap is a sequence of small,
launch-latency-bound elementwise ops (floor-div, add, arange, fill, copy) that
each cost a kernel launch. With one shared-expert append + remap per MoE layer
across many layers, this launch overhead is pure dispatch cost on top of work the
append kernel is already doing.

This PR fuses the append and the remap into the **single Triton kernel** that
already iterates over the topk rows, so the remap math runs on the rows already
resident in registers instead of as extra eager launches. It also fuses the HIP
padded-token masking into one Triton kernel.

The change is **numerics-preserving by construction**: the fused kernel produces
bit-identical `topk_ids` / `topk_weights` to the eager append+remap pair it
replaces (proven by the unit test below).

## Modifications

**`python/sglang/srt/layers/moe/moe_runner/triton_utils/fused_moe_triton_kernels.py`**
- Add `_fused_append_remap_shared_experts_deepep_kernel` and the
  `fused_append_remap_shared_experts_deepep` wrapper. In one pass it:
  - appends the shared experts,
  - applies the DeepEP interleaved routed-id remap (`e -> e + e // num_local_routed`),
  - assigns the per-rank shared-expert ids (`shared_id_base + s`),
  - writes the shared-expert weight as a host-computed scalar.
  Host code computes the scalar remap params so the kernel stays branch-free.

**`python/sglang/srt/layers/moe/topk.py`**
- Wire the fused path into `_post_process_topk_ids`: when shared experts are
  fused **and** the backend is DeepEP-class on aiter, call the new fused kernel
  instead of `fused_append_shared_experts()` + `_remap_topk_for_deepep()`. The
  aiter-only / deepep-only branches are preserved unchanged.
- The shared-expert weight on this fused branch is `1.0`: on aiter,
  `aiter_biased_grouped_topk` folds `routed_scaling_factor` into the routed
  weights and `forward_deepep` skips the post-MoE multiply, so the always-on
  shared expert must contribute 1.0x. (This matches the aiter behavior of
  `_remap_topk_for_deepep` addressed in #28237.)
- Add `_fill_padded_rows` / `_fill_padded_rows_kernel`: a single Triton launch
  that zeroes/fills the CUDA/HIP-graph padded rows (`row >= num_token_non_padded`,
  read from device memory), replacing the eager `arange + (>=) + index_put_`
  sequence. Used by `_mask_topk_ids_padded_region` and
  `_zero_topk_weights_padded_region` with an eager fallback for non-2D /
  non-contiguous tensors.
- Remove the redundant first HIP weight-zeroing pass (the final pass already
  re-zeros after the shared-expert append/remap; zeroing is idempotent).
- Add the `SGLANG_MORI_NO_PAD_MASK` env gate (default **off**) to optionally skip
  the HIP padded-mask pass entirely. This is numerics-affecting and must be
  validated with an accuracy run before being enabled, hence off by default.

**`test/registered/moe/test_fused_append_remap_deepep.py`** (new, registered for
both CUDA and AMD CI)
- `test_matches_golden_reference` — kernel output vs a pure-torch reference of the
  documented remap/append math, across shapes and EP ranks.
- `test_equivalence_with_eager_append_then_remap` — bit-identical to
  `fused_append_shared_experts()` + `_remap_topk_for_deepep()`.
- `test_shared_weight_is_one_on_aiter_path`.
- `test_no_shared_experts_is_noop`.

> Note on overlap: the padded-token masking fusion (`_fill_padded_rows`,
> `SGLANG_MORI_NO_PAD_MASK`, redundant-pass removal) overlaps with #28084. It is
> kept here for now; if #28084 merges first this branch will be rebased to drop

+def _reference_append_remap(
+    topk_ids, topk_weights, s, scale_factor, shared_id_base, num_local_routed
+):
+    """Pure-torch golden reference mirroring the kernel's documented contract.
+
+    Routed IDs:   e -> e + e // num_local_routed
+    Shared IDs:   shared_id_base + arange(s)
+    Routed wgt:   passthrough
+    Shared wgt:   scale_factor
+    """
+    m, k = topk_ids.shape
+    out_ids = torch.empty((m, k + s), dtype=topk_ids.dtype, device=topk_ids.device)
+    out_w = torch.empty(
+        (m, k + s), dtype=topk_weights.dtype, device=topk_weights.device
+    )
+    out_ids[:, :k] = topk_ids + topk_ids // num_local_routed
+    out_w[:, :k] = topk_weights
+    shared = shared_id_base + torch.arange(s, device=topk_ids.device)
+    out_ids[:, k:] = shared.to(topk_ids.dtype)
+    out_w[:, k:] = scale_factor
+    return out_ids, out_w
