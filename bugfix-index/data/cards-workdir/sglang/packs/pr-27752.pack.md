## 正文(PR 描述)

## Motivation

Fix MTP (Multi-Token Prediction) speculative decoding accuracy regression on NPU with `--disable-cuda-graph`. Three places unconditionally called `mark_forward_metadata_ready()`, which prevented attention metadata from being properly initialized on the non-cuda-graph (eager) path for NPU backends.

## Modifications

- `eagle_info_v2.py` ( `prepare_for_extend_to_fill_draft_kvcache` ): Only mark metadata ready on the cuda-graph path. On NPU non-graph, `init_forward_metadata` runs pre-padding and produces wrong block_table shapes after `prepare_mlp_sync_batch` pads the batch.
- `multi_layer_eagle_worker_v2.py` ( `verify` ): Only mark metadata ready on the cuda-graph path. NPU non-graph verify needs forward_extend to init metadata post-padding.
- `multi_layer_eagle_worker_v2.py` ( `_draft_extend_for_decode` ): Only mark metadata ready on the cuda-graph path. The batch-level marker was blocking `draft_runner_list[1+]` from initializing their own per-runner attention metadata.
- `npu_graph_runner.py`: Replace hardcoded `self.attr_name[AttentionArch.MLA]` with `self._get_update_attr_name()` in graph replay. The old code always used `"actual_seq_lengths_kv"`, which is incorrect for MiMoV2 models — they require `"actual_seq_kvlen"`. The dynamic selector returns the correct attr_name per model architecture. This caused graph-mode-only accuracy regression (gibberish output) when cuda graph was enabled without MTP.
