## 正文(PR 描述)

EPLB records load per physical location. After a reshuffle, a different expert may occupy that location, but the old measurements remain. Elastic EP can force another reshuffle before a full window of new measurements replaces the old measurements, causing EPLB to attribute the old load to the wrong expert.

On Elastic EP-triggered reshuffles, use the last saved load for each expert instead of the current load history, which may be wrong or incomplete.

Note that regular EPLB can hit the same stale-history problem when step_interval is smaller than window_size. That should be fixed separately.
