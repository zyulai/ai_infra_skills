## PR body
```markdown
## Purpose
Forwarding fp8 combine flag to increase perf when low precision is supported in FlashInfer combine

## Test Plan
Use GB300 cluster to A/B test with and without the flag `VLLM_FLASHINFER_MOE_A2A_LOW_PRECISION_COMBINE` on, using DeepSeek-R1-0528 NVFP4, 8k input / 1k output.

## Test Result
- For the microbenchmark, there is a small gain at DEP8 (2–8 us per dispatch+combine, about 1–2%), mixed at DEP4. I ran this with just DeepSeek R1 shapes and a sweep across tokens per rank (benchmarks/kernels/benchmark_moe_a2a_combine.py)
- Then I did the serving with nsys (DEP4 and DEP8): the combine kernel is about 17% faster on decode-sized calls but slower on large prefill-sized calls. The fp8 kernel uses 191 registers per thread vs 96 for bf16, could be causing slowdown due to spilling for prefill-sized ones.
- I also tried serving without the profiler, DEP8 (2 nodes); fp8 gave +4.0% output throughput and 2.7% lower median ITL vs bf16. I ran that over 4 server launches (bf16, fp8, fp8, bf16) to balance the order with the benchmark running 3 times each.
- Had a small issue in one of the runs because one of fp8 runs hung shortly after the profiler was stopped. No run hung without the profiler.

```
