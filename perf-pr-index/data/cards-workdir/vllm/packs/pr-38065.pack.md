## Purpose

For visual understanding workloads with large images and relatively short text prompts/generation, the ViT encoder attention becomes a significant bottleneck, especially when the text model is quantized, e.g. with nvfp4. This PR adds optional FP8 quantization for ViT encoder attention via the FlashInfer cuDNN backend.

This is part of the efforts of NVIDIA MLPerf Inference Submission V6.0 @wangshangsam. Credit to @ybgao-nvidia for the dynamic scaling!

**Update**: We also implemented a scale dumping way to make it easy to use.

**Usage**: Enable via environment variables:

```bash
# Requires FlashInfer cuDNN backend + cuDNN >= 9.17.1, e.g. (Blackwell):
# uv pip install -U nvidia-cudnn-cu13==9.18.1 nvidia-cudnn-frontend==1.18.9

# Enable FP8 ViT attention (dynamic scaling by default)
--mm-encoder-attn-dtype fp8 --mm-encoder-attn-backend FLASHINFER

# Optional: static per-layer scales from calibration file
--mm-encoder-fp8-scale-path /path/to/scales.json

# Optional: auto-save calibrated scales after dynamic calibration
--mm-encoder-fp8-scale-save-path /path/to/save/scales.json
--mm-encoder-fp8-scale-save-margin 1.5  # safety margin (default)

# e.g., for calibration
vllm bench mm-processor \
    --model Qwen/Qwen3-VL-8B-Instruct \
    --mm-encoder-attn-backend FLASHINFER \
    --mm-encoder-attn-dtype fp8 \
    --mm-encoder-fp8-scale-save-path /path/to/save/qwen3_vl_8b_vit_scales.json \
    --mm-encoder-fp8-scale-save-margin 1.5 \
    --dataset-name hf --dataset-path lmarena-ai/VisionArena-Chat \
    --max-model-len 32768 \
    --num-prompts 100 --num-warmups 5
```

**Perf Consideration**
1. **This should not be enabled by default:** Since we generally don't quantize ViT with PTQ, Q/K/V are quantized on-the-fly, which introduces extra overhead (3 quantization kernel launches + output un-padding). Performance improvements are only observed with large image token sequence lengths. The FP8 attention kernel speedup is more pronounced on GB300 than GB200 due to better FP8 tensor core throughput. We see speedups for shorter image token lengths on GB300.
2. **Calibration first and run with static scales:** While we support dynamic scaling, it introduces extra overheads. So if you care much about the perf, conduct the calibration first and run.

**Notes:**
- The dynamic scaling feature is not compatible with ViT full CUDA graphs for now.
- Currently only supports Qwen3-VL family models (`qwen3_vl`, `qwen3_vl_moe`, `qwen3_5`, `qwen3_5_moe`, and other models using Qwen3 ViT).
- cuDNN FP8 prefill attention requires head_dim to be a multiple of 16. For models with non-aligned head_dim (e.g. 72), Q/K/V are padded to the nearest multiple of 16 via a Triton kernel, with the output un-padded after attention.

|----------|-----------|----------|---------------------|

The performance of head dim=128 is similar to head dim=72 in our benchmarks.

+# FP8 ViT Encoder Attention
+
+For visual understanding workloads with large images (e.g. QHD, 4K) and relatively
+short text prompts/generation, the ViT encoder attention can become a significant
+bottleneck, especially when the text model is quantized (e.g. NVFP4). vLLM
+supports optional FP8 quantization for the ViT encoder attention via the
+FlashInfer cuDNN backend. Q/K/V are quantized on-the-fly to FP8 before the
+cuDNN attention call.
+
+!!! note
+    - Currently supports Qwen3-VL family models only (`qwen3_vl`, `qwen3_vl_moe`,
+      `qwen3_5`, `qwen3_5_moe`, and other models using Qwen3 ViT).
+    - Dynamic scaling is not compatible with ViT full CUDA graphs.
+    - Performance gains are mostly visible at QHD/4K resolutions or multi-image
+      requests. Smaller images may see no speedup due to quantization overhead
+      (3 quantization kernel launches + un-padding).

+
+- FlashInfer cuDNN backend with cuDNN >= 9.17.1.

+## Usage
+
+Enable FP8 ViT attention by passing `--mm-encoder-attn-dtype fp8` together
+with `--mm-encoder-attn-backend FLASHINFER`:
+
+```bash
+vllm serve $MODEL \
+    --mm-encoder-attn-backend FLASHINFER \
+    --mm-encoder-attn-dtype fp8
+```
+
+By default (no scale file), **dynamic scaling** is used: a 16-entry circular
+buffer of observed Q/K/V amax values drives per-forward scale updates. This
+matches BF16 accuracy without any calibration but adds a small per-forward
+overhead.
+
+## Calibrate-Once, Reuse Workflow (Recommended)
+
+For production, calibrate static scales on a representative dataset once and
+reuse them to avoid the dynamic overhead:
+
+```bash
+# Step 1: calibrate and save scales (runs dynamic scaling for 16 passes,
+# then dumps the learned scales to JSON).
+vllm bench mm-processor \
+    --model $MODEL --mm-encoder-attn-backend FLASHINFER \
+    --mm-encoder-attn-dtype fp8 \
+    --mm-encoder-fp8-scale-save-path /path/to/scales.json \
+    --dataset-name hf --dataset-path lmarena-ai/VisionArena-Chat \
+    --num-prompts 100
+
+# Step 2: serve with static scales (no dynamic overhead).
+vllm serve $MODEL \
+    --mm-encoder-attn-backend FLASHINFER \
+    --mm-encoder-attn-dtype fp8 \
+    --mm-encoder-fp8-scale-path /path/to/scales.json
+```
+
+Saved scales are multiplied by `--mm-encoder-fp8-scale-save-margin` (default
+`1.5`) to leave headroom against activation outliers not present in the
+calibration set. The default has been validated to generalize across datasets
+(e.g. VisionArena-Chat calibration maintains BF16 accuracy on ChartQA).
+
