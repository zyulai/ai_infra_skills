## 正文(PR 描述)

## Motivation
Related issue #5372 
When turning on hierarchical cache, the memory usage of GPU0 device was significantly higher than that of other devices.

tp=8  DeepSeek R1:
![image](https://github.com/user-attachments/assets/ede6cd0f-4047-4846-a51b-5e4314c21890)
In HiCacheController, asynchronous multi-threads (write_thread and load_thread) and multi streams (write_stream and load_stream) are used. The reason for this phenomenon is that asynchronous multi-threads lose some cuda context information, which causes the default current_device of asynchronous threads are all device0. Except for gpu0, when executing `with torch.cuda.stream(write_stream or load_stream)`, current_device needs to be switched from device0 to other devices, and then switched to device0 after the end, as shown in the figure below, which may causes gpu0 to occupy more memory.
![image](https://github.com/user-attachments/assets/d5c08fe6-16db-429e-b588-f407b26e24a5)

Using the following script, it can be seen that gpu0 needs to occupy more memory, 320M * (tp - 1) for H20
```
from pynvml import *

def get_gpu_memory():
    nvmlInit()
    device_count = nvmlDeviceGetCount()
    for i in range(device_count):
        handle = nvmlDeviceGetHandleByIndex(i)
        name = nvmlDeviceGetName(handle)
        mem_info = nvmlDeviceGetMemoryInfo(handle)
        
        try:
            processes = nvmlDeviceGetComputeRunningProcesses(handle)
            for proc in processes:
                pid = proc.pid
                used = proc.usedGpuMemory / (1024 ** 2)
                print(f"GPU{i}    PID: {pid}, memory usage: {used} MB")
        except NVMLError as err:
            print(f"  Can't get process information: {err}")
    nvmlShutdown()

if __name__ == "__main__":
    get_gpu_memory()

```
result (tp4 DeepSeek-V2-Lite):
![image](https://github.com/user-attachments/assets/f50ef5dd-629c-4124-91f8-91a5cdd95141)

## Modifications
When multi-threads starts, switch current_device to the device of the corresponding scheduler process.
Result after fixing the bug(tp4 DeepSeek-V2-Lite)：
![image](https://github.com/user-attachments/assets/2795595b-5065-46ec-8a6a-f1ab673d942a)
