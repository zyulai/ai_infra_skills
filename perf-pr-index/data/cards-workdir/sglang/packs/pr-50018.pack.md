## PR body

## Motivation

GLM-5.3-Flash splits post-weight memory into a KDA state pool and a KV pool at `--mamba-full-memory-ratio` 0.9 by default. Under agentic multi-turn traffic this leaves the KV pool below the sessions' working set: every session is evicted before its next turn and the prefix-cache hit rate collapses (0.056 below). The state pool meanwhile sits mostly idle.

## Modifications

New model override for `Glm5NextForConditionalGeneration` (`model_overrides/glm5_next.py`), each default yielding to an explicit value:

- `--mamba-full-memory-ratio 0.25`: a smaller state pool, the rest to KV.
- `--mamba-radix-cache-strategy extra_buffer_lazy` where `auto` would pick `extra_buffer` and the lazy variant is supported (no PD disaggregation, overlap scheduler on, no pipeline parallelism): one tracking slot per request instead of two, so the smaller pool still admits enough requests.
- Follow-up #50041 pins the cookbook's High Throughput recipes (and `TestGLM53FlashB200HighThroughput`) to `--mamba-full-memory-ratio 0.9`: with many short concurrent requests the smaller state pool caps running requests (the B200 DP-attention CI cell drops to 17 per rank at 0.25).

## Accuracy Tests

- Unit tests in `test/registered/unit/test_model_overrides.py` cover the defaults, explicit ratio / strategy, unsupported extra buffer, PD, overlap off and PP; each condition was negative-controlled.
- Real resolution on a GLM-5.3-Flash checkpoint: default -> `extra_buffer_lazy` / 0.25; explicit `extra_buffer` -> kept; explicit ratio 0.9 -> kept; `--disaggregation-mode prefill` -> `extra_buffer`; `--disable-overlap-schedule` -> `extra_buffer`.
- GSM8K (sgl-eval 0.1.3, 1319 questions, temperature 1.0, top_p 0.95, TP2 B300): this PR 97.50%, main 97.57%.

## Speed Tests and Profiling

AgentX closed-loop trace replay with the FlashStates harness: GLM-5.3-Flash NVFP4, TP2 on B300, 48 sessions, 2700 s, scored over 900-2700 s, device only, total pool memory at FlashStates' 67 GB KV budget, same host.

| | Mamba slots / KV tokens / max running | hit rate | TTFT p50 / p90 (s) | output tok/min/GPU |
|---|---|---|---|---|
| main, default | 429 / 5.89M / 85 | 0.056 | 54.8 / 65.6 | 7,563 |
| main + this PR, default flags | 179 / 8.91M / 44 | 0.767 | 0.20 / 9.58 | 25,777 |
| #49886 + this PR, default flags | 179 / 8.91M / 44 | **0.887** | **0.13 / 4.42** | **35,165** |
| FlashStates (vLLM fork) | - / 10.45M / - | 0.878 | 0.21 / 1.86 | 32,846 |

The ratio was chosen from a slot sweep at the same budget: 144-192 slots (ratio 0.19-0.27) hold the 48 sessions; 300 slots (ratio 0.48) is past the cliff (hit 0.217), and 120 slots caps running requests and loses about 15% throughput.

This PR alone lifts output throughput 3.4x over main; with #49886 (Mamba checkpoints only at fork points and request ends) it reaches 4.6x and exceeds FlashStates at the same memory budget.

+    # Replaces the extra_buffer pick "auto" would make, where the lazy variant
+    # is supported; the mamba radix-cache pass then leaves it alone.

+        and supports_mamba_cache_extra_buffer(cfg, hf_config)
+        and cfg.disaggregation_mode == "null"
+        and not cfg.disable_overlap_schedule
+        and cfg.pp_size == 1
+    ):
+        overrides["mamba_radix_cache_strategy"] = "extra_buffer_lazy"
+    return overrides
