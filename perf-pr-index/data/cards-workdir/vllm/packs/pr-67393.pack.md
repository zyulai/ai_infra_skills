## Overview

Extend the Qwen3.5 NVIDIA path's fused Gemma add-RMSNorm + input quant (#64509) to dynamic per-token FP8, the activation scheme of llm-compressor `FP8_DYNAMIC` checkpoints (e.g. `RedHatAI/Qwen3.5-*-FP8-dynamic`) and online PTPC FP8. Until now these models ran a separate `dynamic_per_token_scaled_fp8_quant` after every `input_layernorm` and `post_attention_layernorm`.

## Claims

- The fused kernel produces the same FP8 codes and `(M, 1)` token scales as the unfused chain (`gemma_fused_add_rmsnorm` + `scaled_fp8_quant(..., use_per_token_if_dynamic=True)`): bitwise on every row whose normed bf16 values match, at most one code apart on the rare rows with a 1-ulp normed difference (same contract as the static FP8 path).
- 1.6-1.9x faster norm + quant at decode sizes (M = 1-64) and 1.27-1.56x at prefill sizes on SM120. The separate quant kernel after both norms of every decoder layer goes away at TP1 and wherever FlashInfer AR+norm does not run (e.g. PCIe-only GPUs): 128 kernels per decode step for a 64-layer model.
- -1.2% (c1) / -1.7% (c8) TPOT serving a 27B Qwen3.6 FP8-dynamic checkpoint at TP4 x DP2 with MTP-2 on 8x RTX PRO 4500 Blackwell (SM120); GSM8K unchanged.

## Details

- `gemma_add_rms_norm_quant(scale=None)` computes the row amax of the bf16 normed activation and quantizes with IEEE divisions by `max(amax / 448, 1 / (448 * 512))`, matching `dynamic_per_token_scaled_fp8_quant`. Above 384 rows it uses 8 warps instead of the static path's 4 (the row amax needs them; swept on SM120).
- `CutlassFP8ScaledMMLinearKernel.input_quant_key()` now also exposes `kFp8DynamicTokenSym`: the kernel already takes the unpadded `(M, 1)` token scales from its own `QuantFP8`. No other CUDA producer is registered for that key, so only this path changes.
- FlashInfer has no per-token AR+norm+quant pattern. Where its AR+norm runs (NVLink), `forward_fused` keeps it and the linear quantizes as before; elsewhere (PCIe-only GPUs, or above the workspace budget) it all-reduces explicitly and runs the fused norm-quant.
- The GDN gated norm and the attention sigmoid gate keep the static-only fusion: one program there owns a head, not a row, so a per-token amax would need a cross-program reduction.
- `test_forward_fused` expected bitwise equality whenever the norm absorbs the all-reduce below the workspace budget, which only holds where FlashInfer AR+norm runs. On SM120 it failed on main for that reason (19 of 1.7M normed values 1 ulp apart); it now keys exactness on `flashinfer_allreduce_gemma_rms_norm_applies`, unchanged on B200.
- Duplicate check: no open or merged PR fuses per-token FP8 into this path. #65497 and #45770 change the torch.compile RMSNorm+quant pass and its CUDA kernels; #45364 and #61073 add manual fusion for Llama-style RMSNorm.
