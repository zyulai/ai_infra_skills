## 正文(PRD / 提案全文)

### Motivation.

Distributed / disaggregated inference is now a first-class vLLM workload, but there is currently no upstream CI that continuously validates disaggregated P/D or Wide-EP on ROCm. 

As a result:
* Regressions in the ROCm disaggregated path (accuracy on PD, KV transfer, MoRI-IO connector, expert-parallel all2all) are only caught manually and late.
* The multi-node / RDMA code paths (prefill to decode KV push over RoCE NICs) get zero automated coverage, despite being the most fragile part of the stack.
* Accuracy drift undetected: no gating on end-to-end accuracy (e.g. GSM8K) for the disaggregated path.

## Summary
This RFC proposes establishing a dedicated Distributed Inference (DI) CI pipeline for ROCm/AMD GPUs in vLLM, covering disaggregated Prefill/Decode (P/D) serving with the MoRI-IO KV connector, in both TP and Wide Expert-Parallel (DP+EP) topologies, running on multi-node AMD clusters via Buildkite + Slurm.

The initial implementation is proposed in vLLM PR #47030. This RFC captures the broader plan, architecture, test matrix, staged rollout, infra requirements, and open design questions so the community can align on direction before we expand coverage and make the pipeline gating.

### Proposed Change.

### Overview
Add a self-contained DI CI harness under `.buildkite/amd-disagg/` (PR #47030) that:
- Stands up a full P/D topology (proxy/router + prefill + decode) on a multi-node AMD Slurm / spur allocation.
- Health-gates every server before sending traffic.
- Runs an end-to-end GSM8K accuracy check (and optionally a benchmark mode) through the disaggregated pipeline.
- Supports two modes via `WIDE_EP_MODE`:
  - `WIDE_EP_MODE=0` : general P/D with independent TP8 servers.
  - `WIDE_EP_MODE=1` : DP + Expert Parallelism (e.g. DP8/EP8/TP1, and 2P2D DP16/EP).
  
### Components (as in PR #47030)
- `vllm_disagg.sh` — launcher for proxy/router, prefill, decode; runs accuracy/bench.
- `cluster.sh` — single-sourced, per-cluster config (ports, topology, RDMA/NIC, MoRI env).
- `run-slurm-disagg-test.sh` — foreground Slurm submitter (the single command CI invokes).
- `run_xPyD_disagg.slurm` — the xPyD Slurm job (container launch, per-node image pull, cleanup).
- `pipeline.disagg.yaml` — Buildkite step snippet for the AMD DI test matrix.
- `models.yaml` — per-model, per-role (prefill/decode), per-mode flags.

### Proposed test matrix (initial to expanded)
| Stage | Topology | Parallelism | Connector | Router | Gate |
|-------|----------|-------------|-----------|--------|------|
| 1 (initial) | 1P1D | TP8 | MoRI-IO | toy proxy & vllm-router | GSM8K accuracy |
| 1 (initial) | 1P1D | DP8/EP8/TP1 (Wide-EP) | MoRI-IO | toy proxy & vllm-router | GSM8K accuracy |
| 2 | 2P2D | Multiple-PD with TP8 | MoRI-IO | toy proxy & vllm-router | GSM8K accuracy |
| 3 | 2P2D DP16/EP (Wide-EP) |  Wide-EP | MoRI-IO | toyproxy & vllm-router | GSM8k accuracy |

The initial model for target is DSV3 and we can add more models into coverage. 

### Staged rollout
- Stage 1 — Non-gating nightly: land the harness (#47030), run 1P1D TP8 nightly on a fixed image, publish accuracy for both toy proxy and vllm-router. Depends on PRs - 46482, 47764
- Stage 2 — Broaden matrix: add 2P2D Multi TP mode and add more models.
- Stage 3 — Wide EP features 1P1D DP8 & 2P2D DP16
