## Motivation

The `select_router_for_request` function in `RouterManager` was identified as a performance bottleneck in the request routing hot path. Previously, it called `worker_registry.get_all()` for every incoming request. This method clones the atomic reference (`Arc`) for every worker in the registry and allocates a new `Vector` to hold them (O(N) complexity).

Under high load or with a large number of workers (e.g 5,000), this constant allocation and atomic reference counting creates significant allocator pressure and CPU overhead, limiting the gateway's maximum throughput.

## Modifications

* **`sgl-model-gateway/src/core/worker_registry.rs`**: Added a new method `get_worker_distribution()`. This method leverages the existing `type_workers` `DashMap` index to retrieve the count of regular and PD workers in O(1) time without iterating or allocating memory.
* **`sgl-model-gateway/src/routers/router_manager.rs`**: Updated `select_router_for_request` to use `get_worker_distribution()` instead of `get_all()`. This removes the memory allocation entirely from the routing decision path.

## Benchmarking and Profiling

I implemented a benchmark using `criterion` to compare the old `get_all()` approach against the new `get_worker_distribution()` optimization with a simulated registry of 5,000 workers.

**Results (5000 workers):**
* **Old (`get_all`)**: ~222.25 µs per call
* **New (`get_worker_distribution`)**: ~10.47 µs per call
* **Improvement**: **~21.2x Speedup**
