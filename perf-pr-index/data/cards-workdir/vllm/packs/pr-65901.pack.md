## Overview
Add opt-in FlashInfer autotuning for multimodal encoders and projectors, which are skipped by the existing language-model warmup.

Enable with:
```
  --kernel-config '{"enable_flashinfer_mm_encoder_autotune": true}'
```


## Claims
- Tunes encoder kernels using multimodal profiling inputs and FlashInfer’s per-operation token buckets.
- Improves offline image embedding throughput for Nemotron 3.5 Embed NVFP4 by 6.2–7.7% at 448×448 on RTX PRO 6000.
- Remains disabled by default because additional profiling increases startup time.


## Validation
Benchmarked `nvidia/Nemotron-3.5-Embed-1B-NVFP4` with `flashinfer_cutlass`, compiled vision encoding, and identical LM tactics between configurations. Measurements used an off/on/on/off sequence on the same GPU, with two runs per configuration and unique images to avoid multimodal cache hits.

| Image size | Batch | Disabled, images/s | Enabled, images/s | Improvement |
|---|---:|---:|---:|---:|
| 448×448 | 1 | 43.59 | 46.97 | 7.7% |
| 448×448 | 4 | 153.74 | 163.35 | 6.3% |
| 448×448 | 8 | 262.12 | 278.48 | 6.2% |
| 1120×1120 | 1 | 32.89 | 33.04 | 0.5% |
| 1120×1120 | 4 | 34.26 | 34.50 | 0.7% |
| 1120×1120 | 8 | 34.05 | 34.69 | 1.9% |

Throughput variation between repeated runs was up to 2.1%; the smaller gains at 1120×1120 should be interpreted accordingly. Fresh encoder tuning increased startup from **16.1 s to 29.2 s** with compilation and LM caches warm. Embedding agreement checks passed.

For a ViDoRe finance_en image-only workload `enable_flashinfer_mm_encoder_autotune` gives about +2.6% throughput: 54.03 req/s against 52.67 for main:
| Config | Start 1 (req/s) | Start 2 (req/s) | Mean (req/s) | vs main |
|---|---:|---:|---:|---:|
| main (upstream/main 831dd92674) | 52.73 | 52.61 | 52.67 | 1.000 |
| autotune | 54.07 | 53.99 | 54.03 | 1.026 |

- `tests/model_executor/test_flashinfer_autotune_warmup.py`: **78 passed**.
- All three cases in `tests/models/multimodal/test_nemotron_embed.py` collected successfully.
- Two-GPU startup validation passed for skipped profiling, fresh tuning, and cached tuning. Vision tactics agreed across ranks, embeddings agreed across runs, and cached startup left cache files unchanged.
- All pre-commit hooks passed.


## Details
Requires FlashInfer autotuning and Model Runner V2. Encoder profiling is skipped with `--skip-mm-profiling`. The pass runs after synchronized warmups, retaining the tuning process group in weights TP mode.

Legacy tuning uses one complete cache file per rank. When encoder tuning is enabled, its cache identity includes the multimodal profiling settings, preventing skipped profiling or different processor settings from falsely satisfying encoder coverage.

The Nemotron regression is wired into B200 CI and checks actual vision GEMM tactics and embedding agreement. This checkpoint does not exercise true encoder data parallelism.

Open-PR searches found no matching encoder-warmup implementation. Related [#63159](https://github.com/vllm-project/vllm/pull/63159) changes bucket handling in the existing LM sweep; it does not add encoder profiling.
