## 正文(PR 描述)

## Problem

The RDNA3 (gfx11) W4A16 GPTQ kernels accumulate split-K partials in
bf16/fp16 via CAS atomics. The narrowing happens **before** accumulation,
and low-precision addition is not associative — so whichever split block
wins the CAS first changes the result. That numerical error is present on
**every affected forward pass**, in every decoding configuration.

Greedy decoding is merely where it becomes visible: at temperature 0 the
rounded logit wobble can flip `argmax` between repeated identical
generations (the trail in #50603). Under sampling (e.g. T=0.6) the same
error hides under the sampler's own noise while still sitting under every
reported metric.

## Root cause

```
FP32 per-block partial
  -> bf16/fp16 narrowing (8 / 11 mantissa bits)
  -> CAS-atomic accumulation in execution-dependent order
```

gfx11 has no packed bf16/fp16 atomic, so the epilogue emulated one with a
CAS retry loop — which also made the accumulation order scheduler- and
contention-dependent.

## Fix

Keep the compute kernels and dispatch unchanged; replace only the epilogue
on both paths:

```
FP32 per-split partials
  -> fixed ascending-z FP32 reduction
  -> one final bf16/fp16 cast
```

* Every path writes each output element exactly once; `k_split == 1`
  (WMMA) and `z_count == 1` (scalar) keep/store directly — no scratch, no
  reduce, no atomics.
* The FP32 partials scratch is `at::empty`: coverage is total by
  construction (every reducer-visible `(z, m, n)` slot has exactly one
  writer in all seven WMMA variants and the scalar kernel; the invariant
  is documented at `alloc_wmma_partials`), so there is no zero-fill pass.
* Scratch is per-call via the caching allocator, row-tiled so the bound is
  independent of the caller's M.

## Accuracy (W7900/gfx1100, FP32 dequantized reference)

Max abs error, synthetic uint4b8/group-128 weights, K=4096:

| path | dtype | legacy CAS | this PR | factor |
|------|-------|-----------:|--------:|-------:|
| scalar | bf16 | 0.24–0.37 | 0.0625 | 4–6x |
| WMMA | bf16 | 0.15–0.23 | 0.09–0.11 | ~2x |
| WMMA | fp16 | 0.024–0.038 | 0.011–0.018 | ~2x |
| scalar | fp16 | ~0.95 | 0.002-0.015 | **94-201x** (see 2026-10-01 update: exact factored dequant) |

bf16 is the headline; fp16 carried 11 mantissa bits so the removed CAS
rounding cost it ~8x less (as expected). The scalar-fp16 row was the
classic exllama bit-trick rounding the per-group offset constant to fp16
— fixed by the exact factored dequant in the 2026-10-01 update below
(now 0.002-0.015 on the same shapes).

The earlier "0.028 → 0.0061" measurement is the same bf16 improvement
factor on real Muse weights. bf16 residual error now sits at the final
output cast (1 ulp); WMMA at the B-tile narrowing.

## Determinism

Fixed inputs now produce bit-identical outputs on every call: 20/20
benchmark shapes repeatable; real Muse q_proj at M=1 gives 1 distinct
result / 100 calls (previously up to 200/200 distinct). Repeatability
alone is not correctness, so the tests also check values against the FP32
reference — a stale `at::empty` scratch slot would be bitwise-repeatable
and wrong, and is caught by the tolerance analysis in the test module.

## Why not FP32 atomics?

gfx11 does have `global_atomic_add_f32`; an FP32 scratch accumulated with
native atomics plus one cast pass would remove nearly all the rounding
error with no reduce kernel. We still chose the fixed-order reduce:
FP32 addition is also non-associative, so atomic accumulation remains
order-dependent — vastly better numerically, but not bit-reproducible.
Since bit-exact reproducibility is an explicit goal of this PR, the
fixed ascending-z reduction is the design that guarantees it.

## Update (2026-10-01): exact fp16 dequant, M>=12 WMMA dispatch, fused fp16 split-K reduce

Addressed @JartX's two review items (semantically ported from
dafcde3f8bb9 and 5e8db861e02 — neither cherry-picks cleanly) and rebased
onto current upstream/main `ccda9098`.

### 1. fp16 dequant is now exact (the "~0.95" row is gone)

The old bit-trick bakes `z = scale * (-1024 - zero)` into an **fp16**
constant; that representation rounding (~0.008 abs at scale≈0.02, repeated
for every weight of a group×column) was the error — not the epilogue. The
dequant now uses the exact factored form

```
sum_k a_k * w_k  =  y * sum_k a_k * (1024 + q_k)  +  z * sum_k a_k
```

with **fp32** (y, z) pairs per nibble slot and the z·sum_a correction
applied once per 32-K round (same structure the bf16 path already had).
Ported to the dense scalar kernel **and** the MoE kernel (its baked error
was previously masked by the dense reference being equally biased).

Accuracy vs the FP32 dequantized reference on gfx1100 (public op path,
100-repeat calls, K=4096–6656, M=1/4/8):

| path | dtype | before | after | factor |
|------|-------|-------:|------:|-------:|
| scalar | fp16 | 1.03–1.37 | 0.002–0.015 | **94–201x** |
| scalar | bf16 | 0.06–0.12 | 0.06–0.12 | bit-identical (unchanged) |

### 2. WMMA dispatch: both dtypes from M ≥ 12

Measured scalar/WMMA crossover on this gfx1100 (both ops timed directly,
identical inputs, median of 300; full table in the dispatch comment): at
M ≥ 12 WMMA wins or ties on every measured shape for both dtypes
(1.00–1.69x); below that scalar wins and is the more accurate path. fp16
previously stayed scalar until M=64 — that speed came with ~100x more
dequant error; with the exact dequant the crossover moved to 12, same as
bf16. An M=11 (scalar) / M=12 (WMMA) boundary test pins it via profiler
kernel names.

### 3. Split-K reduction fused into the fp16 kernel — with per-call state

The fp16 scalar path now reduces in the GEMM kernel: each block publishes
arrival on its tile's ticket; the last z block sums the z-slices in fixed
ascending order (batched loads) and rounds once — still bit-reproducible,
one launch fewer, partials read while L2-hot.

**The ticket array is per-call** (`at::zeros`, one int per tile,
re-armed in-kernel), **not** the device-global `g_w4_tickets` of the
reference: nothing in vLLM serializes quantized W4A16 GEMMs on one device
(DeepSeek V4/V4.1 aux-stream forks, LoRA dual-stream, and the
SharedExperts side stream all overlap quantized linears today), so
cross-launch global state would be a correctness hazard. Per-call tickets
from the stream-aware caching allocator keep concurrent invocations
independent by construction; verified by a two-stream concurrent-vs-serial
(bit-exact) test and CUDA-graph capture/replay tests.

The **bf16** path keeps the separate reducer: measured on gfx1100, fusing
it was neutral at M=1 and up to ~10% slower at M=4–8 (the fused reduce
serializes a multi-row tile's reduction into one block per tile), so bf16
behavior is unchanged.

Performance, interleaved A/B/C in one session (original baked / exact +
separate reduce / final; min of 4-rep medians × 3 rounds; public op):

| dtype | M | vs original | vs separate-reduce |
|-------|--:|------------:|-------------------:|
| fp16 | 1 | **−6.3 … −11.3%** | −8.1 … −8.8% |
| fp16 | 4 | −6.7 … −8.2% | −11 … −12% |
| fp16 | 8 | −2.2 … −7.6% | −6 … −16% |
| bf16 | 1–8 | −1.4 … +0.1% (noise) | — (unchanged path) |

i.e. the final fp16 kernel is both ~100–200x more accurate **and**
6–11% faster at decode than the pre-review state.
