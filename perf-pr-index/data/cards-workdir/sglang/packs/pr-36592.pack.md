## Motivation

Wan's feed-forward blocks execute the first projection and `gelu_pytorch_tanh`
as separate kernels. On H100, the standalone GELU accounts for 401 launches and
159.064 ms in a five-step denoising profile of Wan2.1-T2V-1.3B.

This PR reuses the existing quality-gated cublasLt linear+GELU epilogue so the
optimization remains opt-in under `quality=high`; `quality=lossless` keeps the
existing operator sequence and output exactly.

## Modifications

- add a Wan-specific `_WanGELUMLP` for the standard and VSA transformer blocks;
- mark its input projection as an existing fused-linear-GELU site and dispatch
  to `fused_linear_gelu_tanh` only when the quality gate and shape/backend guards
  pass;
- preserve the original `fc_in -> gelu_pytorch_tanh -> fc_out` fallback;
- add a CUDA unit test for the unmounted, mounted, and exact restored paths; and
- document the Wan `quality=high` path in the diffusion performance skill.

## Accuracy Tests

Hardware: 1x NVIDIA H100 80GB.  
Model: `Wan-AI/Wan2.1-T2V-1.3B-Diffusers` at revision
`0fad780a534b6463e45facd96134c9f345acfa5b`.  
Workload: 832x480, 81 frames, 50 denoising steps, guidance 3, seed 42,
native SGLang backend.

Two repeated candidate outputs had the same SHA-256. Against the unfused
`quality=high` baseline, first/middle/last key frames measured:

| Frame | SSIM | PSNR (dB) |
|---|---:|---:|
| first | 0.960655 | 36.12 |
| middle | 0.954638 | 34.32 |
| last | 0.947188 | 33.75 |

The unit test also verifies that unmounting the fast path restores bit-exact
lossless output.

## Speed Tests and Profiling

Same-GPU A-B-B-A results, with one warmed request per process:

| Run | Path | Denoising (ms) | End-to-end (ms) |
|---|---|---:|---:|
| A1 | baseline high | 45,206.34 | 47,033.41 |
| B1 | fused high | 44,332.17 | 46,159.79 |
| B2 | fused high | 44,396.44 | 46,224.51 |
| A2 | baseline high | 45,268.19 | 47,095.86 |
| mean A | baseline high | 45,237.27 | 47,064.64 |
| mean B | fused high | 44,364.31 | 46,192.15 |

This is a **1.93% denoising** and **1.85% end-to-end** speedup.

Five-step GPU traces on the same source revision show:

| Metric | Baseline high | Fused high |
|---|---:|---:|
| GPU kernel time | 5,859.373 ms | 5,720.200 ms |
| Kernel launches | 14,268 | 13,911 |
| Standalone GELU | 159.064 ms / 401 | 0.030 ms / 12 |

The same path was also validated on
`FastVideo/FastWan2.2-TI2V-5B-FullAttn-Diffusers` revision
`3e187042a324f6f5fb68fd22110a78725253de8f` at 1280x720x81, using its native
three-step `WanDMDPipeline` preset. Against current main `5adc2880f9`, the
same-GPU A-B-B-A means were 1,374.930/1,352.524 ms denoise and
7,106.139/7,070.196 ms E2E (baseline/fused): **1.63% denoise** and **0.51%
end-to-end**. Candidate outputs were repeatable within the arm; candidate
versus baseline first/middle/last key frames measured SSIM
0.938424/0.928753/0.931103 and PSNR 32.16/30.47/30.27 dB.

Its three-step trace confirms the kernel mechanism independently: total CUDA
launches fall from 2,400 to 2,311, standalone BF16 GELU falls from
90 launches / 32.571 ms to 2 launches / 0.007 ms, and the corresponding GEMM
uses the cublasLt `gelubias` epilogue. Total GPU kernel time falls from
1,330.489 to 1,310.310 ms (1.52%). This sibling result is supporting evidence;
the primary Wan2.1 workload above remains the end-to-end performance gate.

Wan does not currently support BCG, so no BCG performance claim is made.
