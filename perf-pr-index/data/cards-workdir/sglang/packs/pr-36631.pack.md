## PR body
```markdown
## Motivation

Sampling masks currently do not support overlap scheduling because materializing the masks inside the sampler synchronizes the GPU with the CPU.

## Modifications

1. Remove CPU synchronization from sampling-mask capture. Keep sampling-mask outputs on the GPU inside the sampler, then copy them asynchronously to the CPU and materialize the response data during result processing.
2. Introduce `--sampling-mask-max-tokens` (default: `4096`) to set the maximum number of tokens per sampling mask.
3. Reject sampling-mask requests upfront if `top_k` exceeds the configured mask capacity.
4. Abort the request with an overflow error if the realized mask exceeds the capacity, including when cutoff ties produce more tokens than `top_k` even though `top_k` is within the limit.
5. Mark sampling results as invalid if validation fails, such as when the selected-token logprob is non-finite (`NaN` or infinity). Abort the request before committing the failed step's sampled token.
6. Replace `SGLANG_DISAGGREGATION_SAMPLING_MASK_MAX_TOKENS` with the server argument `--sampling-mask-max-tokens` for both ordinary and disaggregated serving. PD metadata remains off by default: set `SGLANG_ENABLE_DISAGG_SAMPLING_MASK=1` on both prefill and decode servers. Without it, requests asking for masks receive HTTP 400 with the required setting; unused metadata buffers are neither allocated nor transferred. Startup rejects the retired `SGLANG_DISAGGREGATION_SAMPLING_MASK_MAX_TOKENS` variable with explicit migration instructions.
