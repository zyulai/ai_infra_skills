**Breaking: AITER FSE with MiniMax M3 and DeepSeek V4 now requires `VLLM_ROCM_USE_AITER=1`, like all other models. Updating the recipe https://recipes.vllm.ai/MiniMaxAI/MiniMax-M3 for that.** AITER will be enabled by default with: https://github.com/vllm-project/vllm/pull/62092

## Disclosure

AI assistance was used. The changes were reviewed and tested manually.

## Overview

Allow compatible layers to use AITER fused shared experts (FSE) while other layers retain higher-precision shared experts.

Current vLLM rejects the entire model in case FSE can't be enabled for all layers, and various places assume all-or-nothing selection.

**Motivation: certain layers are less sensitive to MXFP4 shared expert quantization than others, and fusion can be enabled for them.**

## Claims

- Enable per-layer FSE through the existing `resolve_layer_fused_shared_expert` API for models migrated to layer-scoped checkpoint loading.
- Redirect checkpoint weights only for layers that allocated fused shared-expert slots; preserve separate MXFP8 shared experts alongside MXFP4 routed experts.
- Explicitly reject mixed FSE with EPLB, expert parallelism, and the `nixl_ep` all2all backend, which assume uniform expert geometry across layers.
- Migrate the model loaders previously left to other PRs (MiniMax M3, DeepSeek V4, DeepSeek V2, DeepSeek V3.2, GLM5Next, AXK1, GLM4 Lite and the applicable MTP loaders) and route the EP/DP eligibility policy through explicit call-site flags (`disable_under_ep`) instead of model-type lookups.
- Report the resolved per-layer policy at startup: `vllm serve` logs the MoE layers that use FSE, those that keep a separate shared expert, and one line per distinct skip reason (deduplicated, not one per layer).

### End-to-end

#### Offline quantization

End-to-end mixed-precision checkpoint, using the Quark `quantize_quark.py` example script to quantize `deepseek-ai/DeepSeek-V2-Lite` to MXFP4 while keeping the shared experts of layers 5, 6 and 7 in BF16 (published as `fxmarty-amd/DeepSeek-V2-Lite-mixed-shared-expert-mxfp4-testing`):

  ```bash
  python quantize_quark.py \
      --model_dir <DeepSeek-V2-Lite> \
      --quant_scheme mxfp4 \
      --exclude_layers "lm_head" "*self_attn*" "*mlp.gate" \
                       "*layers.5.mlp.shared_experts*" \
                       "*layers.6.mlp.shared_experts*" \
                       "*layers.7.mlp.shared_experts*" \
      --model_export hf_format --data_type bfloat16 \
      --num_calib_data 8 --seq_len 128 --skip_evaluation \
      --output_dir <mixed-mxfp4-checkpoint>
  ```

(`--exclude_layers` replaces the template defaults, hence the repeated `deepseek_v2` entries; DeepSeek-V2-Lite's legacy remote code needs a small transformers-5 shim for `is_torch_fx_available` and `_tied_weights_keys` to run the example script.)

`VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1 vllm serve fxmarty-amd/DeepSeek-V2-Lite-mixed-shared-expert-mxfp4-testing` on MI350 then reports the resolved per-layer policy:

#### Online shared experts quantization

`amd/Qwen3.5-35B-A3B-MXFP4` keeps the shared experts in BF16 while the routed experts are MXFP4. Targeting a few layers' shared experts to `mxfp4` online should fuse only those layers. This is the exact server command that produced the results below (mixed FSE, layers 10 to 20):

```bash
HIP_VISIBLE_DEVICES=2,3 \
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS=1 \
vllm serve amd/Qwen3.5-35B-A3B-MXFP4 \
  --served-model-name amd/Qwen3.5-35B-A3B-MXFP4 \
  --port 8101 \
  --gpu-memory-utilization 0.5 \
  --tensor-parallel-size 2 \
  --quantization-config '{"targets":{"re:.*layers\\.(1[0-9]|20)\\.mlp\\.shared_expert\\..*":"mxfp4"}}'
```

### Left to other PRs

- [ ] Move FHMOE's separate model-wide eligibility policy to this per-layer API: https://github.com/vllm-project/vllm/blob/12b005eefa06f97eeebfae3e14bcac5fa3b81197/vllm/models/deepseek_v4/amd/model.py#L212-L240 and https://github.com/vllm-project/vllm/blob/12b005eefa06f97eeebfae3e14bcac5fa3b81197/vllm/models/deepseek_v4/amd/model.py#L1077-L1092
- [ ] Make the DeepSeek V4 MTP loader and the DeepSeek V4.1 (AMD) loader consume `fused_shared_expert_layers`. They build MoE blocks through the per-layer resolver but still load as if unfused; construction now raises `NotImplementedError` if any MTP/V4.1 layer resolves fused, until this follow-up lands.
- [ ] Remove the fused-shared-expert logic from the NVIDIA model definitions, which cannot enable FSE.

### Limitations

- Mixed FSE with EPLB or expert parallelism is unsupported.
- Routed and shared experts must have compatible quantization within each fused layer; heterogeneous precision inside one fused GEMM is unsupported.
- Fused layers must share routing-buffer geometry; mixed FSE is also rejected with `nixl_ep`, and Mori remains unsupported with FSE requested.
- Forward execution, graph replay, model evaluations, and performance are not validated. The NVIDIA model paths were updated too, although FSE is not supported there.

### Compatibility changes

- Compared with `main`, migrated models accept mixed fusion eligibility with EPLB and expert parallelism off, retaining incompatible shared experts separately at their configured precision.
- Internal breaking changes: `maybe_fuse_shared_experts()` requires a `fused_shared_expert_layers` collection instead of the optional `enabled` boolean/environment fallback; migrated model-wide FSE booleans become layer sets; `FusedMoEConfig.aiter_fmoe_shared_expert_enabled` becomes `is_fused_shared_expert_requested`.
- `is_model_fused_shared_expert_compatible()` is removed; `get_fused_shared_expert_layers()` collects the fused layer indices and rejects mixed FSE with EPLB, expert parallelism, or `nixl_ep`.
- `resolve_layer_fused_shared_expert()` takes an explicit `disable_under_ep` flag (set by MiniMax M3 and DeepSeek V4) instead of branching on model type. DeepSeek V4 performs its own `data_parallel_size > 1` fail-fast in `DeepseekV4MoE.__init__`. MiniMax M3 now enables FSE through the resolver (AITER-based) instead of the raw `VLLM_ROCM_USE_AITER_FUSION_SHARED_EXPERTS` flag.
- The DeepSeek V4 CPU model keeps its `is_fused_shared_expert_enabled = False` scaffolding; only the removed `is_model_fused_shared_expert_compatible()` call is replaced with that constant, so the broader dead-FSE cleanup can be split into a separate PR.

### Related work

- This addresses per-layer policy, not the ModelOpt MXFP8 compatibility support in https://github.com/vllm-project/vllm/pull/57916; the duplicate-work search found no open PR implementing this same policy migration.
