```markdown
## Overview

Lets HiSparse run on the extensible KV cache (#56492), which previously excluded it. HiSparse's device pool is reserved and grown like any other KV cache. Its host pool stays outside it.

## Claims

- HiSparse uses the extensible KV cache by default.
- At default flags, GPU+host KV capacity grows by 16% and throughput matches `main`. GSM8K under heavy host offload also matches `main`.
- HiSparse with NIXL P/D and with the Mooncake store connector works on the extensible cache.
- Fixes two warmup crashes that removing the gate exposed:
  - the FlashInfer HiSparse autotune read hot blocks that had not been committed;
  - context-prefill warmup overflowed the hot group's fixed-size block-table rows.

## Validation

All runs on B200 with `VLLM_USE_V2_MODEL_RUNNER=1`, against base 3b6eeb0606.

**Default flags.** GLM-5.3-NVFP4, TP4, no `--gpu-memory-utilization`. Two runs each, server restarted for every point.
```
vllm serve RedHatAI/GLM-5.3-NVFP4 -tp 4 --max-model-len 17408 --max-num-seqs 256 \
  --max-num-batched-tokens 4096 --kv-cache-dtype fp8 --block-size 64 \
  --attention-config '{"hisparse_config":{}}' \
  --kv-transfer-config '{"kv_connector":"HiSparseConnector","kv_role":"kv_both","kv_connector_extra_config":{"host_pool_gib":64}}'
vllm bench serve --dataset-name random --random-input-len 16384 --random-output-len 1024 \
  --num-prompts 2c --max-concurrency c --ignore-eos --seed 42

```
## Details

- **Host-resident tensors stay out of the extensible paths.** `ExtensibleKVCache`, `committed_views`/`committed_kv_cache_tensors` and `shrink_kv_cache_configs` skip `host_resident` tensors. `host_resident` is an existing generic field.
- **The post-extend cache dict matches the fixed path's.** The runner keeps the dict `init_kv_cache` returned (`kv_caches_by_layer`); `extend_kv_cache` swaps in the committed views and passes it to `runner.kv_caches` and the connectors. Host layers keep their views and HiSparse's hot slabs stay out. `committed_views` gives layers laid out over the raw buffer (`has_layer_views=False`) the committed prefix, and `rebind_hisparse_device_caches` rebinds HiSparse's resident and hot views over it, so they span the committed blocks rather than the reservation. CUDA graphs captured before extend stay valid: the base address does not move.
- **Autotune:** the HiSparse autotune commits `cdiv(topk, hot_block_size)` blocks before tuning.
- **Warmup:** clamps reservations to the spec's block-table row length (`max_num_blocks_per_req`), which bounds HiSparse's fixed-size hot rows. Mamba is exempt: in non-align modes `MambaManager` can hold more blocks than its row length.
- **Considered:** feature-owned `if hisparse:` branches in the model runner and `extend_kv_cache`. That is more code, and it still needs the same planning changes.
- **Not covered:** sleep/wake with HiSparse on the extensible cache.
```
