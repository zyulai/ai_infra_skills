## Motivation

The LingBot Video MoE router computes group-limited expert selection with a sequence of small CUDA operations: a per-group top-2 reduction, group top-k, mask construction, masked expert scores, and the final expert top-k. This path is launch-bound for large token counts, so the selection can be fused without changing the selected expert-id set.

The PR is also updated to the latest SGLang `main`, whose diffusion kernels now use a facade + registry layout and consolidated registered tests. The kernel documentation and diffusion benchmark/profile skill need to describe that current layout rather than the pre-refactor file paths.

## Modifications

- Add `sglang/kernels/ops/diffusion/routing/group_limited_topk_triton.py`: one Triton program per token loads the score row once, computes the per-group top-2 sums, selects the allowed groups, and writes the final expert ids.
- Add an explicit `can_use_group_limited_topk` predicate. Supported NVIDIA CUDA inputs use the fused path; unsupported dtype/layout/group configurations retain the eager PyTorch path. Kernel failures are no longer silently swallowed on every router call.
- Register `diffusion.group_limited_topk` in the diffusion kernel registry and export both the predicate and implementation through the public diffusion facade.
- Register the launch as a custom op with a fake implementation, including `torch.compile(fullgraph=True)` coverage.
- Move the correctness test into registered kernel CI as `test/registered/kernels/ops/diffusion/test_routing.py`. The matrix now includes LingBot Video's production configuration: 128 experts, 4 groups, 2 selected groups, and top-8 experts.
- Refresh the public fused-kernel inventory and package README. The current registry contains 45 operators / 51 implementations, including the LingBot routing operator and recently registered KDA kernels.
- Refresh the diffusion benchmark/profile skill's fast-path map: add LingBot routing guidance and replace stale pre-refactor kernel/test paths with their current locations.

This is a selection-equivalent, default-on path for supported inputs and is independent of the request quality tier. The output order remains unspecified, matching the reference `torch.topk(..., sorted=False)` contract.

Hardware: one NVIDIA H200. Microbenchmark uses 8,192 tokens and the production LingBot Video routing configuration (128 experts / 4 groups / `topk_group=2` / `top_k=8`), with 100 warmup iterations and 500 measured iterations.

+"""Fused group-limited MoE top-k index selection for diffusion routers.
+
+The reference LingBot Video router builds the group-limited top-k with a chain
+of small kernels: per-group top-2 and sum, group top-k, a ``scatter_`` into a
+zero mask, an ``expand``/``reshape`` broadcast, a ``masked_fill`` with
+``-inf``, and the final expert top-k. On a launch-bound single GPU that chain
+is pure overhead: every intermediate tensor is tiny and the whole computation
+is bandwidth- and launch-bound. The later score gather remains in the caller.
+
+This module fuses the entire selection into a single Triton kernel: one
+program per token loads its score row once, reduces the per-group sums in
+registers, masks non-selected groups with ``-inf``, and writes the top-k
+expert ids. The selected expert-id set matches the reference CUDA
+``torch.topk`` chain for the guarded layouts, including the production
+128-expert / 4-group / 2-selected-group / top-8 configuration. The output
+order is intentionally unspecified, matching the reference's ``sorted=False``
+contract.
+"""
+
+from __future__ import annotations
+
+import torch
+import triton
+import triton.language as tl
+
+from sglang.srt.utils.custom_op import register_custom_op
+
+
+@triton.jit
+def _group_limited_topk_kernel(

+    out_idx_ptr,  # [T, TOP_K] i64
+    stride_st,
+    E: tl.constexpr,
+    N_GROUP: tl.constexpr,
+    TOPK_GROUP: tl.constexpr,
+    TOP_K: tl.constexpr,
+    EPG: tl.constexpr,  # experts per group = E // N_GROUP
+    BLOCK_E: tl.constexpr,  # padded E
+    BLOCK_EPG: tl.constexpr,  # padded experts-per-group
+    BLOCK_G: tl.constexpr,  # padded N_GROUP
+):

+    e_mask = offs_e < E

+        scores_ptr + t * stride_st + offs_e, mask=e_mask, other=float("-inf")

+    # never win the per-group top-2 reduction.
+    g = tl.reshape(scores, (BLOCK_G, BLOCK_EPG), can_reorder=False)

+    g = tl.where(epg_mask, g, float("-inf"))

+    group_e = tl.arange(0, BLOCK_EPG)[None, :]

+    # to m1 would lose the second top-k entry when a group contains duplicate
+    # maxima, which changes both the group score and the selected experts.
+    m1_idx = tl.min(
+        tl.where(g == m1[:, None], group_e, BLOCK_EPG),

+    )
+    g2 = tl.where(group_e == m1_idx[:, None], float("-inf"), g)
+    m2 = tl.max(g2, axis=1)
+    group_scores = m1 + m2

+    # left tie-break. Correctness tests compare the selected set because the
+    # reference uses torch.topk(..., sorted=False).
+    group_idx = tl.arange(0, BLOCK_G)
+    gs_valid = tl.where(group_idx < N_GROUP, group_scores, float("-inf"))
+    selected_group = tl.zeros((BLOCK_G,), dtype=tl.int1)
+    for _ in tl.static_range(TOPK_GROUP):
+        picked_idx = tl.argmax(
+            gs_valid,
+            axis=0,
+            tie_break_left=True,
+        )
+        is_pick = group_idx == picked_idx
+        selected_group = selected_group | is_pick
+        gs_valid = tl.where(is_pick, float("-inf"), gs_valid)
+
+    # Mask experts in non-selected groups, then flat top-k (same tie-break).
+    masked = tl.where(selected_group[:, None], g, float("-inf"))
+    flat = tl.reshape(masked, (BLOCK_E,), can_reorder=False)
+    flat = tl.where(e_mask, flat, float("-inf"))

+        tl.store(out_idx_ptr + t * TOP_K + kk, idx.to(tl.int64))
+        flat = tl.where(offs_e == idx, float("-inf"), flat)
