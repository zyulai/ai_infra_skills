## Overview

Let Qwen GDN's Triton/FLA prefill export internal prefix-cache checkpoints, so an align-mode prefill can cross its last cache boundary in one forward pass. Use a per-sequence buffer and the existing Mamba checkpoint exporter, following [ZJY0516/vllm#30](https://github.com/ZJY0516/vllm/pull/30).

## Claims

- The existing dense `chunk_gated_delta_rule` gains only optional `checkpoint_state` and `checkpoint_offsets`. It retains its initial-state/final-state contract; the kernel receives no cache block indices.
- At an internal 64-token chunk boundary, the recurrence snapshots its FP32 accumulator into the cache-dtype buffer. The existing exporter copies it into the checkpoint block with the convolution window; existing gather/scatter handles initial and final states.
- Qwen GDN advertises internal checkpoints for Triton on CUDA. All Mamba layers must support the checkpoint; unsupported or misaligned cases retain scheduler splitting. Calls without checkpoint tensors compile out the checkpoint store.

## Details

The kernel writes one contiguous `[N, H, V, K]` checkpoint row per sequence; offset 0 disables that row. Only offsets on the 64-token chunk grid strictly inside a sequence are stored. Workspace is reserved during profiling and the checkpoint variant is warmed with the existing dense path. Scalar metadata pointers do not specialize on alignment, so a leading decode row does not introduce a new kernel variant.

The checkpoint workspace has `max_num_seqs` rows in the recurrent-cache dtype and uses the existing shared workspace manager. This adds state storage and recurrent checkpoint copy traffic. An unsplit prefill can delay other requests' decode steps.

This updates the existing Triton/FLA GDN PR. #60659 targets AITER FlyDSL with a different prefill execution path; it does not provide this FLA kernel implementation. The buffer/exporter design is credited to the linked mentor fork. Shared scheduler/cache-manager code is unchanged.
