## 正文(PR 描述)

## Purpose

Addresses the engine-containment part of
[#55546](https://github.com/vllm-project/vllm/issues/55546) and is related to
[#55547](https://github.com/vllm-project/vllm/issues/55547). It does not close
#55546 because frontend multimodal processor-cache (P0) fingerprint/content
validation remains follow-up work.

Keep the encoder embedding count with each V1 multimodal encoder-cache entry and
reject a cache hit when the incoming request expects a different count. Complete
only the mismatched request through the scheduler's existing request-error path,
leaving EngineCore available to later requests.

Client-provided multimodal UUIDs must uniquely identify their data, but accidental
reuse can pair a cached encoder output with a request that expects a different
number of embeddings. The existing
[Multimodal Media UUID Security](https://github.com/vllm-project/vllm/blob/main/docs/usage/security.md#multimodal-media-uuid-security)
documentation already assigns UUID uniqueness to the client and documents the
integrity and confidentiality consequences of reuse. This PR leaves that
contract and those risks unchanged while closing the availability gap caused by
different embedding counts.

Related work: [#57833](https://github.com/vllm-project/vllm/pull/57833) makes
`MultiModalReceiverCache` prefer a full payload resent by P0, preventing one
stale processor-payload substitution path. The harmful mismatch in both PRs
requires a client-provided multimodal UUID to be reused for different content;
without a UUID, the cache identity is derived from the media content. #57833
does not validate an encoder-cache entry already retained under that identifier:
if an earlier request completed and left such an entry, scheduling can still
skip encoding the preserved payload and reuse the old encoder output. This PR
checks the embedding count at that admission point; same-count,
different-content reuse remains outside its scope.

If the cached tensor is shorter, the mismatch currently reaches embedding merge,
EngineCore exits, and every subsequent request on that engine fails. If the cached
tensor is longer, slicing can succeed and silently serve embeddings from different
content. Checking counts at cache admission prevents both availability and silent
correctness failures; catching only the merge exception would not cover the latter.
This intentionally changes the longer-cache case from apparent success with
embeddings from different content to an explicit request error.

The old release path also re-derived cache size from the request being released.
With one identifier and different request sizes, that could corrupt freeable
capacity accounting and lead to later allocation assertions.

This PR keeps the existing UUID contract and cache keys. It rejects the request
rather than evicting or re-encoding under a contested identifier. Once admission
is validated, the stale entry cannot make EngineCore unavailable; evicting it on
a client-triggered mismatch would also let that client flush a shared entry that
other requests may still be using.

The request finishes through `FINISHED_ERROR`, which currently represents a
retryable request-level internal error and maps to HTTP 500, even though this
input will fail again until its UUID is corrected. The scheduler has no separate
client-error finish reason, and client-provided grammar compilation failures
already use the same `grammar_compile_error_reqs` drain. This PR reuses that
existing request-scoped containment path; it does not introduce the 500 mapping.

No flag is added because the change converts an engine-fatal condition into a
request-scoped error while preserving behavior for identifiers whose embedding
counts satisfy the existing contract.

For EC connectors, an external load calls `allocate()`, which records the
requesting request's expected count locally. That value is not derived from the
tensor returned by the remote cache, and the arriving tensor's row count is not
compared with it. A first remote hit is therefore outside this validation;
later reuse of the locally recorded entry is checked.

A mismatch schedules zero tokens, but it does not spin: both engine loops still
reach `update_from_output`, which drains and removes the request within one
scheduler step.

- Five named adjacent scheduler tests: 5 passed.
- Ruff check, Ruff format check, and `git diff --check`: passed.

The baseline and fixed GPU arms used the same source baseline, SmolVLM model,
Python environment, and compiled artifacts. The HF processor produced 320 image
tokens for the cached input and 1088 for the later input under the same
identifier.

- Baseline: the mismatch reached V2 worker embedding merge; the mismatched request
  and a later healthy request both reported `EngineDeadError`.
- Final fixed revision: the mismatched request completed with
  `finish_reason="error"`, the healthy request completed, and the process status
  was 0.

The fixed `WARNING` identified `collision-id`, reported that its entry held 320
embeddings while the request expected 1088, and explained that a client-provided
multimodal UUID may have been reused for different content. It contained no
`Attempted to assign`, `EngineDeadError`, or `EngineCore failed` line.

The frontend multimodal processor cache (P0, configured by
`mm_processor_cache_gb`) was disabled to construct cache-lifetime drift
deterministically. A P0 hit reuses the old processed item, while production can
retain an encoder entry after the corresponding P0 entry has been evicted.

Model evals are not applicable. The check only runs while admitting an
identifier-based encoder-cache hit and cannot alter outputs for requests whose
identifier and embedding count satisfy the existing contract.

## Changes

- Store `identifier -> num_encoder_embeds` metadata in `EncoderCacheManager`.
- Preserve it while an unreferenced cache entry remains reusable; remove it on
  eviction and reset.
- Use the stored entry count when updating freeable capacity.
- Compare cached and requested counts before cache-hit admission mutates reference
  state.
- Compare counts when one request repeats an identifier in the same scheduling
  call without double-counting the encoder budget.
- Complete mismatched requests as `FINISHED_ERROR` through the scheduler's existing
  request-error drain.
- Warn with the identifier, cached and requested counts, and likely UUID-reuse
  cause.
- Add coverage for lifecycle accounting, compatible layouts, dangling-reference
  prevention, same-request duplicate identifiers, and scheduler liveness afterward.

The check is entirely in the scheduler and `EncoderCacheManager`, so it applies to
both model runners. The GPU reproduction used the V2 Model Runner.

The short image must run first so its 320-row encoder output is reusable when the
long image requests 1088 rows. The frontend multimodal processor cache is disabled

```python
#!/usr/bin/env python3
"""Validate request-level handling of mismatched encoder-cache lengths."""

from __future__ import annotations

import argparse
import json
import sys
import traceback
from typing import Any

from PIL import Image
from transformers import AutoProcessor
from vllm import LLM, SamplingParams


PROMPT = "<image>\nDescribe the image briefly."


def make_image(width: int, height: int, color: tuple[int, int, int]) -> Image.Image:
    return Image.new("RGB", (width, height), color=color)


def make_request(image: Image.Image, identifier: str) -> dict[str, Any]:
    prefix = f"Image dimensions {image.width} by {image.height}. " * 4
    return {
        "prompt": prefix + PROMPT,
        "multi_modal_data": {"image": image},
        "multi_modal_uuids": {"image": [identifier]},
    }


def count_image_tokens(processor: Any, image: Image.Image) -> int:
    processed = processor(text=make_request(image, "unused")["prompt"], images=[image])
    token_ids = processed["input_ids"]
    if hasattr(token_ids, "tolist"):
        token_ids = token_ids.tolist()
    if token_ids and isinstance(token_ids[0], list):
        token_ids = token_ids[0]
    return token_ids.count(processor.image_token_id)


def generate_once(llm: LLM, image: Image.Image, identifier: str) -> dict[str, Any]:
    try:
        outputs = llm.generate(
            make_request(image, identifier),
            sampling_params=SamplingParams(max_tokens=1, temperature=0),
        )
        output = outputs[0].outputs[0]
        return {
            "returned": True,
            "finished": outputs[0].finished,
            "finish_reason": output.finish_reason,
        }
    except BaseException as exc:
        traceback.print_exc()
        return {
            "returned": False,
            "exception_type": type(exc).__name__,
            "exception": str(exc)[:500],
        }


def main() -> int:
    parser = argparse.ArgumentParser()
    parser.add_argument("--model", required=True)
    parser.add_argument("--output", required=True)
    args = parser.parse_args()

    short_image = make_image(1024, 128, (20, 20, 200))
    long_image = make_image(224, 224, (200, 20, 20))
    healthy_image = make_image(672, 224, (20, 200, 20))

    processor = AutoProcessor.from_pretrained(args.model, local_files_only=True)
    short_tokens = count_image_tokens(processor, short_image)
    long_tokens = count_image_tokens(processor, long_image)

    result: dict[str, Any] = {
        "model": args.model,
        "processor_cache_disabled": True,
        "prefix_cache_enabled": True,
        "token_counts": {"short": short_tokens, "long": long_tokens},
        "token_count_guard": short_tokens < long_tokens,
    }

    if short_tokens >= long_tokens:
        result["guard_error"] = "short image must produce fewer image tokens"
        with open(args.output, "w", encoding="utf-8", newline="\n") as handle:
            json.dump(result, handle, indent=2, sort_keys=True)
            handle.write("\n")
        print("SUMMARY_JSON=" + json.dumps(result, sort_keys=True))
        return 2

    llm = LLM(
        model=args.model,
        enforce_eager=True,
        enable_prefix_caching=True,
        mm_processor_cache_gb=0,
        max_model_len=2048,
        max_num_seqs=1,
        limit_mm_per_prompt={"image": 1},
    )

    result["short_seed"] = generate_once(llm, short_image, "collision-id")
    result["long_reuse"] = generate_once(llm, long_image, "collision-id")
    result["healthy_after"] = generate_once(llm, healthy_image, "healthy-id")

    with open(args.output, "w", encoding="utf-8", newline="\n") as handle:
        json.dump(result, handle, indent=2, sort_keys=True)
        handle.write("\n")
    print("SUMMARY_JSON=" + json.dumps(result, sort_keys=True))

    return 0 if all(
        step.get("returned", False)
        for step in (
            result["short_seed"],
            result["long_reuse"],
            result["healthy_after"],
        )
    ) else 1


if __name__ == "__main__":
    sys.exit(main())
```
