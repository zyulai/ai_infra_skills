## Overview

Continues #48244 by @njhill (co-author). In steps where no scheduled request can use the
drafts proposed after the step, the speculator now proposes with K=0 instead of
drafting. Such requests are non-final prefill chunks and requests sure to reach
`max_tokens`. This covers every request on a P/D prefill instance, which runs with
`max_tokens=1`.

Related: #39266 (draft) skips EAGLE drafting on MRV2 for P/D prefill instances and
non-final chunks; this PR decides in the scheduler and also covers requests about to
finish, DFlash and DP. #53426 makes the K=0 draft sync forward optional; this PR keeps
that forward.

## Claims

- On Model Runner V2, when no scheduled request on any DP rank can use the drafts, the
  speculator runs with `num_speculative_tokens=0`:
  - EAGLE/EAGLE3/MTP still run the draft prefill pass, which keeps the drafter's KV cache
    in sync, but skip draft sampling and the draft decode steps.
  - DFlash stores the context K/V and skips the query pass. DSpark, DFlash2 and
    LiLiCorr share this code.
- The drafter's prefill pass still runs, so the gain is modest. Prefill-only throughput
  (Qwen3-8B, 64 x 16,384-token prompts, 1 output token, one GB300 GPU) improves by
  **+1.9% with EAGLE3** and **+7.3% with DFlash** at `max_num_batched_tokens=512`, and by
  +1.4% and +2.7% at 2048. On a 1P1D prefill instance every step proposes with K=0,
  and prefill throughput improves by +2.1% (EAGLE3) and +3.4% (DFlash) at 512, and by
  +0.6% and +1.9% at 2048.
- Outputs and acceptance do not change. With batch-invariant kernels, outputs and every
  spec-decode counter are identical to `main`.

## Details

- **Scheduler.** It sets `SchedulerOutput.skip_drafts` when no scheduled request can use
  the step's drafts, on the V2 runner and for drafters that reserve lookahead slots.
  `_drafts_unused` counts only the output tokens a request is sure to have, assuming
  every draft is rejected, so it never skips drafts a later step could verify.
- **DP.** The flag is ANDed across ranks in the batch-descriptor all-reduce that already
  runs, giving `DPSyncState.skip_drafts`. The runner then proposes with K=0. A rank
  running a dummy batch votes no, so an idle DP rank disables the skip for that step.
- **Changes from #48244:**
  - The per-request lookahead-slot skip is dropped. For a non-final chunk, the lookahead
    slots are the next chunk's first positions, which are allocated one step later
    anyway. For a finishing request it saves at most about one block for one step.
    Keeping it safely means masking every draft KV write, including inside captured
    FULL draft-decode graphs; the fused decode path is the default on FlashAttention,
    FlashInfer and Triton, and its captured graphs compute their own slot mappings.
  - Skipping reuses the existing `num_speculative_tokens == 0` path, which already skips
    the AR draft decode steps, instead of a separate flag in each speculator.
    `skip_sample` and the DFlash early return also apply to K=0 from dynamic speculative
    decoding.
  - The scheduler reports one flag instead of a set of request ids.
- **Not covered.** Multi-module MTP and the draft-model speculator ignore K, so they
  still draft in these steps and the drafts go unused, as before. N-gram reserves no
  lookahead slots, so the flag is never set for it. MTP, DSpark, DFlash2 and LiLiCorr
  share the changed code but were not run; all validation used Qwen3-8B. MRV1 is
  unchanged.
