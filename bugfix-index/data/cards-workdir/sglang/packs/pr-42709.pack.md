## 正文(PR 描述)

## Motivation

With compact ragged verify (`SGLANG_RAGGED_VERIFY_MODE=compact`), `DecodeCudaGraphRunner` captures a token tier more than once when there are several attention graph variants (for example the DSv4.1 candidate graphs `candidate_unfiltered` / `candidate_filtered`) or several PD-mux streams. Each capture calls `_capture_ragged_verify_layout`, which allocated a new `RaggedVerifyLayout` and replaced `_captured_ragged_layouts[num_tokens]`. At replay, `_stage_ragged_verify_layout` copies the live `verify_lens` / `qo_indptr` only into that registered layout, which belongs to the last capture. Graphs from the earlier captures still read the layout they were captured with. That layout holds synthetic capture offsets, and replay no longer refreshes it.

A graph that reads an earlier capture's layout tensors directly computes with the wrong offsets whenever the live layout differs from the capture-time one. On current main, PD-mux with the TRT-LLM MLA backend is exposed: its ragged verify path pads and unpads queries with the captured `verify_lens` / `qo_indptr` inside the graph. For DSv4.1 target verify on current main the defect is latent, because its backend copies the live layout into its own buffers outside the graph. The ragged Engram hashing and `token_req_indices` in #40567 read `qo_indptr` inside the DSv4.1 verify graph; with them, the `candidate_unfiltered` graphs map tokens to the wrong requests.

I measured an A/B on DeepSeek-V4.1-Flash (TP4, 4x RTX PRO 6000 Blackwell, SM120, DSpark gamma 5, compact verify, #40567 applied) with an earlier revision of this fix, which copied the live layout into each capture instead of sharing one layout per tier. I compared the log-prob of each generated token with a plain prefill of the same text:

- Without the fix, per-token differences reached 14.4 nats. At temperature 1, 9 of 32 streams looped to the length cap.
- With the fix, the maximum difference was 0.79-0.86 nats, and none of the 32 streams looped or hit the cap.

Eager verify was correct in both builds.

## Modifications

`_capture_ragged_verify_layout` creates the layout once per token tier and returns the same object for later captures of that tier. Every graph of the tier now captures the tensors that replay refreshes.

## Accuracy Tests

- `TestRaggedVerifyLayoutPerTier` (CPU, `test/registered/unit/model_executor/runner/test_decode_cuda_graph_runner.py`) calls the capture-layout helper twice for tier 24 with two variant labels, stages a live layout, and checks both returned layouts' `qo_indptr_device` / `verify_lens` against the live padded layout. On main the first layout keeps its synthetic offsets (7 of 9 `qo_indptr` entries differ).
- The end-to-end A/B in Motivation (earlier revision of the fix).

## Speed Tests and Profiling

Not benchmarked. The replay staging code is unchanged; capture reuses one registered layout per token tier across attention variants and PD-mux streams.
