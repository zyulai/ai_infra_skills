## 正文(PR 描述)

## Summary

Fix out-of-memory (OOM) errors during MoE kernel tuning for models with many experts (e.g., 128 experts).

## Problem

When running `benchmark_moe.py --tune` on large MoE models, memory accumulates because Triton JIT compiles and caches kernels for each configuration. With 1920 configurations per batch_size, this can cause memory to grow from ~40GB to 100GB+, triggering Ray's OOM killer.

## Solution

Add periodic Triton JIT cache clearing during tuning:
- New `clear_triton_cache()` function that clears Python GC, CUDA memory, and Triton JIT cache
- Call it every 50 configurations (configurable via `VLLM_MOE_TUNE_CACHE_CLEAR_INTERVAL` env var)
- Final cleanup after each batch_size tuning completes

## Testing

Tested on GPT-OSS-120B (128 experts, topk=4) with batch-size 1-64. Previously OOM'd at batch_size=2, now completes successfully.
