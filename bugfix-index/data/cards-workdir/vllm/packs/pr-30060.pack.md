## 正文(PR 描述)

## Purpose

#30008 introduced a silent error when generating nightly wheel indices. `$PYTHON pip install regex && .buildkite/scripts/generate-nightly-index.py --version "$SUBPATH" --current-objects "$obj_json" --output-dir "$INDICES_OUTPUT_DIR" $alias_arg` is wrong because: (1) it should be `$PYTHON -m pip` (2) the second half is not run with the same python (3) former half failure in `&&` shortcut will not be caught by bash.

So currently the `generate-nightly-index.py` is not run at all, thus no indices are generated. Wheels are uploaded nonetheless. The logs look like:

```text
[2025-12-04T11:26:21Z] + docker run --rm -v /var/lib/buildkite-agent/builds/bk-arm64-cpu-queue-postmerge-i-04192f6325ee0943d-1/vllm/release:/app -w /app python:3-slim python3 pip install regex
[2025-12-04T11:26:21Z] python3: can't open file '/app/pip': [Errno 2] No such file or directory
[2025-12-04T11:26:22Z] + echo 'Uploading indices to s3://vllm-wheels/1b7c7f5159484063af28cb47809d79e83d3301ec/'
[2025-12-04T11:26:22Z] Uploading indices to s3://vllm-wheels/1b7c7f5159484063af28cb47809d79e83d3301ec/
[2025-12-04T11:26:22Z] + aws s3 cp --recursive indices/ s3://vllm-wheels/1b7c7f5159484063af28cb47809d79e83d3301ec/
```

This PR fixes this issue by monkey-patching `regex` back to `re` in that script to both (1) make pre-commit linter happy and (2) get rid of any external dependencies. We are using very simple regexes and do not need the performance brought by `regex` here.

I also added comments in the generated HTML index to clearly specify the generation time and commit.
