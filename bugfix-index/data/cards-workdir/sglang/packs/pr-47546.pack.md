## 正文(PR 描述)

## Motivation

If a request is aborted while the tokenizer manager is still preparing it (for example while it fetches an image or publishes multimodal features), the `AbortReq` reaches the scheduler before the request itself. The scheduler drops an abort for a rid it has not received and keeps no record of it, and `abort_request` never resends one because `state.abort_sent` is already set. The request is then dispatched anyway and runs to completion while its caller waits. A plain server shows it with a slow image URL and a client disconnect: the request runs to `max_new_tokens`. In PD disaggregation a decode request in this state holds its KV until the transfer timeout.

The ordering:
1. The rid is registered and preprocessing is in progress.
2. `abort_request` sets `state.abort_sent` and sends `AbortReq`. The scheduler has no request with that rid yet, so it drops the abort.
3. Preprocessing finishes and `_send_one_request` dispatches the request.
4. Every later `abort_request` call returns early at `if state.abort_sent`, including the disconnect watcher's.

## Modifications

- `_send_one_request` and `_send_batch_request` check `abort_sent` after their last `await` and skip dispatch for such requests. Everything after the check is synchronous, so no abort can land between the check and the dispatch. The prepared transport features of a skipped request are released the same way a failed dispatch releases them: CUDA VMM items through `cancel_for_dispatch`, and CUDA IPC feature proxies (`feature` and `precomputed_embeddings`) through the pool's `cancel_proxy`, since no scheduler would ever acknowledge them. A batch still dispatches its other requests. The batch path is factored into `_drop_aborted_before_dispatch`.
- `_wait_one_response` finishes a skipped request through `_handle_abort_req`. That produces the same output the scheduler sends when it pops an aborted request from its waiting queue (finish reason `abort`, "Abort in waiting queue") and removes the rid from `rid_to_state`. It runs in the waiter rather than at the send site because the waiter looks its state up by rid and finishing the request removes that entry.
- `abort_request(abort_all=True)` marks every undispatched request `abort_sent`, so an abort-all (`/abort_request`, weight updates with `abort_all_requests`, pause with abort) also keeps requests still preprocessing from running. Requests held at `generate_request`'s pause gate are left alone (new `ReqState.waiting_at_pause_gate`): a pause holds them and they run after `continue_generation`.

Not covered: multi-tokenizer mode (`tokenizer_worker_num > 1`). If `/abort_request` lands on a worker that does not own the rid, that worker forwards it to the scheduler without touching the owning worker's state; covering that needs a record on the scheduler side.

## Tests

New tests in `test/registered/unit/managers/test_tokenizer_manager_rid_cleanup.py::TestAbortBeforeDispatch`; each fails without the fix (the waiter never finishes, `TimeoutError`):
- `test_abort_during_preprocessing_is_not_dispatched` aborts a request through `generate_request` while tokenization (subtest `tokenize`) or feature publication (subtest `publish`) is blocked, then lets it finish. Only the `AbortReq` reaches the scheduler, the caller gets an `abort` finish reason, the prepared features and CUDA IPC proxies are cancelled, and the rid is freed.
- `test_abort_all_skips_preprocessing_requests_but_not_paused_ones`: an abort-all finishes the request that was preprocessing and leaves the one held at the pause gate, which is dispatched after the pause is lifted.
- `test_batch_dispatches_only_requests_not_aborted` aborts one request of a batch during the batch's feature publication. The other request is dispatched alone, only the aborted request's multimodal items and proxies are cancelled, and its waiter gets an `abort` finish reason.

`test_request_class_override_points.py`: the stub request state gains an `abort_sent` field, which the dispatch path now reads.

Run locally on a CPU-only environment: `test_tokenizer_manager_rid_cleanup.py` and `test_request_class_override_points.py`, 55 passed; `test_multimodal_abort_cleanup.py`, `test_gpu_feature_transport.py` and `test_scheduler_pause_generation.py` also pass.
