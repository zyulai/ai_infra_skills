## Motivation

DSA index-cache logic had no single owner across two remaining concerns: per-batch MTP top-k reuse state and the per-layer index-K storage buffer. The layer-skip policy is already owned by `dsa_layer_skips_topk` and is intentionally out of scope here.

Raw `ForwardBatch` / `spec_info` state writes made the MTP reuse lifecycle fragile, while index-K allocation, reads, writes, moves, transfer metadata, and offload were interleaved with latent-KV pool logic.

## What this does

- Adds `IndexTopKShareState`, an adapter over `reuse_dsa_topk_indices` and `spec_info.dsa_topk_indices`. Its `mtp_iteration` context manager preserves the draft-extend seed when requested and always clears reuse state on exit, including exceptions.
- Adds `IndexKeyCache`, which owns the DSA index-K buffer and its read, store, move, transfer-metadata, and CPU offload/load operations. `DSATokenToKVPool` delegates through `_create_index_key_cache` while retaining `index_k_with_scale_buffer` as a compatibility property.
- Adds `LayerSplitIndexKeyCache` for the upstream DSA layer-split pool. It preserves owned-only allocation, owner-broadcast reads, remote-buffer invalidation, fused-read latent-KV prefetch ordering, move behavior, PD state-buffer metadata, and HiCache CPU copy/load.
- Rewires the NextN decoder and EAGLE V2 draft loop through the state adapter and adds focused lifecycle tests.

## Behavior and compatibility

- The index buffer layout and `index_buf_accessor` codec are unchanged. Accessor calls still receive the pool object, so page size, quantization layout, and transfer counters retain their existing behavior.
- `IndexTopKShareState` keeps the carry on `spec_info`, which survives per-step `ForwardBatch` copies, and preserves the draft-extend seed for step 0.
- Layer-split ranks allocate full index buffers only for owned layers and use the existing owner communicator for remote reads. Non-layer-split DSA pools retain one full buffer per layer.
- DSV4 nested and NPU pools keep their existing implementations.

- Changed-file `pre-commit`, `py_compile`, and conflict-marker checks pass on the current upstream tip.
- Focused state, shard, pool, HiCache/offload, and DSA EAGLE CUDA-graph coverage passes: 53 passed and 1 skipped across the exercised test groups.
- Two-rank `test_dsa_layer_split_broadcast.py` passes on GB300, covering owned-only index allocation and owner-broadcast reads through the facade.
- Existing real-DSA validation covers plain decode, HiCache offload/load, and PD-disaggregation index-buffer transfer.
- Fixed-seed EAGLE3 baseline versus candidate evaluation is exact for 40/40 GSM8K samples: generated text, `finish_reason`, parsed answer, score, stop rate, and error rate all match.
- After the final upstream merge, the official Llama checkpoint rerun again matches the pre-merge candidate for 40/40 outputs and reports 97.5% stop rate with 0% errors.
