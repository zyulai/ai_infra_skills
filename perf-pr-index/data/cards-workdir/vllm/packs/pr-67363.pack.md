## Overview

On ROCm, `RocmMxfp4IndexerMetadataBuilder` (the DeepSeek-V4/V4.1 MXFP4 sparse indexer on gfx950) builds its decode metadata every step with a chain of small eager torch ops before the graph replay. This PR builds it with one Triton launch per indexer KV group, `RocmMxfp4DecodeRowsKernel`, in the ROCm-only ops module. The shared `DeepseekV32IndexerMetadataBuilder` gets a documented `_build_decode_rows()` hook (+29/-2) that returns None by default. `build()` calls it on decode steps that use neither varlen decode nor DCP, and keeps its current path when it returns None, so CUDA and the other builders are unchanged. Varlen decode and DCP skip the hook and always take the default path. Readers get the same integers as on main. Only never-read padding rows differ: they are zeroed.
