## Motivation
Prepare the AMD CI to run PR tests on the new `linux-mi300-*gpu-sglang` runner pool while keeping scheduled runs on `linux-mi325-*gpu-sglang`. This involves three coupled changes:
1. **In-network image mirror** so PR jobs don't hammer Docker Hub
2. **Runner pool routing** that picks MI300x for PRs, MI325x for schedules, user-selectable for `workflow_dispatch`
3. **MI300x-specific test budget tuning** — perf thresholds, est_time, step timeouts, and a couple of skips for known kernel-precision issues

<!-- Describe the purpose and goals of this pull request. -->

## Modifications
### 1. In-network Docker registry (avoid Docker Hub rate limits)

- `release-docker-amd-nightly.yml` / `release-docker-amd-rocm720-nightly.yml`: after publishing the nightly `rocm/sgl-dev` image, an extra `push_local_registry` job re-tags it with `172.29.8.23:5000/` prefix and pushes to the in-network registry.
- `scripts/ci/amd/amd_ci_start_container.sh` and `amd_ci_start_container_disagg.sh`:
  - Lookup order is now (a) local docker cache, (b) Docker Hub manifest probe.
  - Pull step tries the LAN mirror first via `docker pull "${LOCAL_DOCKER_REGISTRY}/${IMAGE}"` (which goes through the host docker daemon and inherits its `insecure-registries` config), and only falls back to public Docker Hub with a 6-attempt exponential-backoff retry helper if the LAN pull fails.
  - On fallback, the captured stderr is surfaced with a `[local-pull]` prefix so the real reason (TLS handshake, 404, connection refused, etc.) is visible in the job log.
  - When `DOCKERHUB_AMD_USERNAME` / `DOCKERHUB_AMD_TOKEN` are present, do `docker login` (also wrapped in `retry_with_backoff`) to lift anonymous pull rate limits on the public-registry fallback path.
- `pr-test-amd.yml`, `pr-test-amd-rocm720.yml`, `nightly-test-amd.yml`, `nightly-test-amd-rocm720.yml`: workflow-level `env:` block injects `DOCKERHUB_AMD_USERNAME` / `DOCKERHUB_AMD_TOKEN` from repo-level secrets to every job's environment so the script's login block actually has credentials to use.

### 2. Runner pool routing (PR vs schedule vs dispatch)

- `pr-test-amd.yml` no longer hard-codes `linux-mi325-*-sglang`. Each GPU-bound job now uses:
  ```yaml
  runs-on: ${{ format('linux-{0}-Ngpu-sglang',
               inputs.runner_arch ||
               (github.event_name == 'pull_request' && 'mi300' || 'mi325')) }}
  ```
  - `pull_request` → MI300x (lighter pool, faster PR feedback)
  - `schedule` → MI325x (full-coverage nightlies)
  - `workflow_dispatch` → user picks via new `runner_arch` choice input (defaults to `mi300`)
  - `workflow_call` → inherits caller's `event_name`, same rules
- Job names render the actual runner arch / GPU count for at-a-glance triage in the Actions UI.

### 3. MI300x-specific test budget tuning

MI300x has lower HBM bandwidth than MI325x (HBM3 vs HBM3e), so memory-bound paths run noticeably slower. None of the changes weaken the CUDA / non-AMD path; existing strict bounds are preserved in the `else` branch.

| Test | Before | After (AMD branch) |
|---|---|---|
| `test_online_lora_latency` | TTFT < 58 ms | TTFT < 100 ms |
| `test_online_lora_latency_with_concurrent_adapter_updates` | TTFT < 80 ms | TTFT < 130 ms |
| `test_embeddings_api_latency_throughput` | avg<20, p95<25, tput>60 | avg<35, p95<40, tput>30 |
| `test_score_api_batch_scaling` | bs=10:(45,50), 25:(50,60), 50:(60,65) | (60,65), (70,80), (80,90) |
| `test_torch_compile_moe::test_throughput` | non-CUDA: ≥ 270 tok/s | AMD: ≥ 240 tok/s |
| `test_multi_tokenizer.py` median TTFT | < 86 ms | < 130 ms |
| `test_deepseek_v32_basic.py` `est_time` | 1800 s | 3600 s (observed 3283 s) |
| `pr-test-amd.yml` stage-c step `timeout-minutes` | 90 | 120 |

Two known precision/non-determinism cases that surfaced on MI300x (and are not bound regressions, but kernel-level numerical issues) are skipped on AMD only with a comment:

- `test_pytorch_sampling_backend.py::test_greedy` — greedy decode is not bit-exact across runs on MI300x; `assertEqual` between regenerated texts is flaky. Skipped via `@unittest.skipIf(is_in_amd_ci(), ...)`.
- `sgl-kernel/tests/test_moe_topk_sigmoid.py::test_topk_sigmoid[2048-32-4]` — kernel diverges from `torch.topk` by a different (but equally valid) tie-breaking when several sigmoid scores are within fp32 ULP. Skipped only for this single param when `torch.version.hip is not None`; the other 773 params still run strict.

Both skips also reproduce on MI325x baseline runs and have been called out previously as known issues; they are tracked separately and not regressions of this PR.

### 4. Misc

- `pr-test-amd.yml`: docker cache temporarily disabled (one-line conditional flip) until the cache pipeline is healthy on the new pool.
