## 正文(PR 描述)

## Purpose
This PR cuts down on some ROCm-specific divergences that have now outlived their use. This serves as a cleaner base for the ModelRunner V2 default enablement on ROCm (https://github.com/vllm-project/vllm/pull/56360).

1. Reverts https://github.com/vllm-project/vllm/pull/48526, which performed graph capture profiling on the current stream rather than a new side stream on other platforms after a performance regression was observed. The reason given then was that a side-stream "shifts the KV/activation buffers' physical placement and slows every bandwidth-bound decode kernel ~20%"; this is not correct.
The true reason is due to a latent runtime defect involving long cross-stream waits which was subsequently fixed in https://github.com/vllm-project/vllm/pull/53712 and https://github.com/vllm-project/vllm/pull/55099. In particular, the revert is now measured to be performance neutral rather than incurring a 20% slowdown.

2. Reverts #55095's DS V4 fallback on ROCm to `CudaGraphMode.NONE` if MRV2 is enabled. The justification given was #52644, but it no longer applied on `main`, so DS V4 was suffering an unnecessary performance degradation on ROCm with MRV2 enabled.

3. Gate `compile_or_warm_up_model`'s `torch.compile` specialization warmups not only on whether the compilation mode is `VLLM_COMPILE` but also on whether there's even a torch.compile'd submodule.

## Test Plan
Full `gsm8k` was run on DS V4 before/after these changes (2 in particular), on both ModelRunner V1 and V2, and accuracies between 0.954-0.972 were observed.
Performance was measured on TP8, concurrencies 1, 8, 32, 128, 256, 8K/1K, on DS V4 and Qwen-3.5-35B after these changes, and found to be the same (within noise).

Main and AMD CI will also be run on this PR. 

## Test Result
There are no new regressions in CI.
