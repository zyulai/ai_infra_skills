## 正文(PR 描述)

## Purpose

`ThrottledDropPolicy` calculates what fraction of store attempts should be dropped based on pressure. This PR fixes how it applies that fraction.

For a calculated drop rate of 75%, the expected result over 20 store attempts is 15 drops and 5 allowed stores.

- Before: 10 dropped, 10 allowed. Only 50% are dropped.
- After: 15 dropped, 5 allowed. The calculated 75% rate is honored.

The old implementation rounds the rate into a "drop every N attempts" interval, which cannot represent rates such as 75%. The replacement carries fractional drops between decisions, keeping the cumulative drop count within one store of the calculated target.

This corrects application of the existing rate; it does not change how pressure determines that rate. Pressure detection and cooldown behavior are unchanged. These decisions control optional writes to secondary cache tiers, not inference-request admission.

Related to #50045. Duplicate-work checks found no open PR implementing this arithmetic correction. #51576 adds admission-policy infrastructure without changing this calculation; #51240 tracks the broader admission/backpressure work.

AI assistance (OpenAI Codex) was used to implement and test this change.
