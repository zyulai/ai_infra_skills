## 正文(PRD / 提案全文)

### Motivation.

With AFD, large-scale MoE inference on vLLM runs across two execution sides: an Attention side that batches requests, manages KV cache, and performs routing, and an FFN (Experts) side that executes expert MLPs. In proposal #22799, we introduce AFD as a single instance spanning DP-Attention and EP-FFN. 

To further improve the online serving performance and reliability, online elasticity of AFD becomes important by keeping QoS and throughput when traffic spikes and nodes fail. Prior work (Elastic EP #20323) established online elasticity for DeepEP; coordinating AFD is broader in scope. Elastic AFD needs a new architecture that jointly coordinates Attention and FFN across control and data planes and reframes load balancing for AFD pipelines.

There are two goals in this RFC: 1) We need low MTTR within one elastic AFD instance: apply live edits to Attention/FFN group membership and placement, resize DP ranks, and adjust expert placement while the service stays up. 2) We also need high throughput before and after scale in/out: tune per-node concurrency on the Attention and FFN paths by changing pipeline allocation, micro-batch distribution, threads, streams and SM utilization, etc.

This RFC proposes a unified elastic AFD implementation based on Ray with clear control and data planes, plus an updated AFDConnector for elastic communication within the instance.

### Proposed Change.

**Background**
AFD work (e.g., AFD PR #25162 and related AFD RFC #22799) AFD defines Attention–FFN disaggregation on Step-3 and DeepSeek v3. This RFC extends AFD to online elasticity across A/F domains.

**Main components**
1) Ray-based basic elasticity.
**Scope:** within one AFD instance, edit DP-Attention and EP-FFN membership and placement online (scale in/out and replacement).
**Changes:** use Ray for control and execution orchestration; apply minimal in-place changes to membership and placement. Output the updated actor set and placement. Perform switches at micro-batch or sequence boundaries. 
2) Unified interface for elastic communication domains.
**Scope:** provide a single abstraction to update the communication domain when membership or placement changes.
**Changes:** support StepMesh and Global Communicator as pluggable implementations, hiding mode differences from upper layers. Update the AFDConnector in the communication layer to carry and update required metadata (members, endpoints, topology) within the same AFD instance.


**Milestones**
1) Milestones1 — Baseline (Ray + Elastic Comm)
Deliver Ray-based online membership and placement edits for DP ranks and experts. Provide the unified elastic communication interface with StepMesh and Global Communicator. 
2) Milestones2 — vLLM fault-tolerance adaptation #27866 + elastic pipeline load balancing
Adapt to vLLM fault-tolerance interfaces. Add elastic pipeline load balancing based on Elastic NBO, adjusting workload allocation between Attention and FFN.
3) Milestones3 — Asynchronous graph rebuild & capture
Introduce asynchronous compute-graph rebuild and capture that can proceed alongside serving, with reuse of existing artifacts where possible.
