## Summary

Recover a pull peer whose **local NIXL metadata is missing while Prefill is still alive with the same engine ID**. Without recovery, vLLM's cached `_remote_agents` entry and prepared dlists can keep subsequent requests on the stale path.

A receive failure schedules a descriptor-free `check_remote_metadata(agent)` check. This queries **local metadata existence, not peer health**. Only confirmed absence makes the peer eligible for recovery; a transfer error or probe exception alone does not.

## Implementation

- Track failed and locally invalid peers in `NixlBaseConnectorWorker`. One `_cleanup_remote_engines()` pass handles both replacement and invalidation, reusing `_cleanup_remote_engine()` to release resources.
- Defer probes and cleanup while background handshakes are pending. For invalid peers, reject new reads and wait for all existing receive handles to settle before cleanup. Replacement cleanup retains its existing queued-request guard.
- Clear recovery state in the shared per-engine cleanup, including TTL eviction and shutdown. A peer that is both replaced and invalidated is cleaned once; the replacement's address mapping is preserved.
- Route new and handshake-ready requests through the pull worker's existing read entry point. After cleanup, a fresh request re-handshakes the unchanged engine ID and uses newly prepared descriptors. Failed requests are **not replayed with old remote block IDs**.

The production changes are in `nixl/base_worker.py` and `nixl/pull_worker.py`. Recovery remains **pull-only**, with an explicit push-mode TODO. There is no new router API, configuration, or metadata probe on successful transfers.

Following Yannik's review, tests reuse `TestPeerReplacement` and `FakeNixlWrapper` instead of a separate hand-built recovery fixture. The existing receive/HMA fixtures and push test stub initialize the new fields. Nick Hill's read/handshake simplification is retained with authorship preserved.

## Related Work and Scope

Related to #49238. This is a follow-up to merged #50047, not another replacement detector:

| Change | Trigger |
| --- | --- |
| #50047 | A new engine ID is confirmed at the same address. |
| This PR | The engine ID is unchanged, but NIXL has lost the decoder's local peer metadata. |

Both now use one base-worker cleanup pass, rather than separate replacement and recovery passes. The scope split was discussed in [#50047](https://github.com/vllm-project/vllm/pull/50047#issuecomment-5629552908).

#52232 addresses HMA failure propagation and is **not included here**. Recovering future requests does not by itself guarantee that the failed HMA request returns an error instead of invalid output. TTL policy and the native UCX race discussed in NIXL #1987 are also outside this patch's scope.

Stuck reads or handshakes defer recovery; this patch does not forcibly release active resources. Native cleanup exceptions propagate rather than being swallowed. Recovery is not a claim that every UCX failure is recoverable.
