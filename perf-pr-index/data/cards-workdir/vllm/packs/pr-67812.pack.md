## Overview

Fixes #65385. `chunk_scaled_dot_kkt_fwd_kernel` now applies `beta` after the K loop, as upstream FLA does, instead of scaling `k` inside it.

## Claims

- On Hopper, the autotune configs with `BK < K` and `num_warps >= 4` gave different results from run to run. With this change, all 27 configs give the same result on every run at K=128 and K=256.
- Every config is now within 2.8e-7 of a float32 reference, where main’s deterministic configs were 1.7e-3 off.
- The autotuned kernel is 4–6% faster on an H100.

## Validation

H100 80GB HBM3, torch 2.14.0+cu132, Triton 3.8.0, main `919d45fc3`.

## Details

- Root cause: `k` feeds the wgmma through shared memory and also has a register user (`k * beta`). In that case Triton’s pipeliner gives its buffer one slot too few, so the next iteration’s load overwrites it while the async wgmma still reads it (triton-lang/triton#12738 fixes this in Triton). Scaling after the loop leaves `k` with no other user.
- RDNA: the dot now always takes `k`’s dtype, so the RDNA cast branch is no longer needed and is removed.
- Not a duplicate: #65927 prunes configs with `BK < 128`. At K=256 that leaves the six `BK=128`, `num_warps >= 4` configs, which all race here. pkusp suggested this approach in #65385.
- Who is affected: on Hopper, Qwen3-Next and Qwen3.5 use FlashInfer GDN prefill by default. This kernel runs with `--gdn-prefill-backend triton`, and for OLMo Hybrid, which calls the vendored `chunk_gated_delta_rule` directly.
- CI: `tests/kernels/fla` runs on B200 and MI355, where this race doesn’t occur. The new test still checks every config against the reference there. The Hopper results above come from an H100.
