## PR body
```markdown
## Summary

Replace the per-request split FlashKDA execution in #52789 with one packed FlashKDA call that exports an intermediate recurrent-state checkpoint for every sequence.

This keeps #52789's checkpoint block allocation, lifecycle, and cache-store logic. It changes how FlashKDA produces the output, final state, and checkpoint state, and ensures checkpoint offsets passed to FlashKDA satisfy its 16-token chunk alignment.

This PR is stacked directly on #52789 and depends on the now-merged [FlashKDA#7](https://github.com/vllm-project/FlashKDA/pull/7). The FlashKDA pin is updated to its merge commit, `ee0be888cd0e972f9409bf53756f8c38c6652173`.

This does not duplicate #52971: that PR contains the broader standalone checkpoint implementation, including partial-prefix and speculative-decoding integration. This PR is a focused follow-up whose diff is relative to #52789.

## Implementation

#52789 currently splits each request at its checkpoint and invokes FlashKDA separately for both parts:

```python
for sequence in packed_batch:
    flashkda(sequence[:checkpoint])
    flashkda(sequence[checkpoint:])
```

For a batch of 64 requests with non-empty tails, this makes 128 sequential FlashKDA API calls.

FlashKDA#7 added `checkpoint_state` and `checkpoint_offsets` to the forward API, so the same operation is now expressed as one packed call:

```python
flashkda(
    packed_batch,
    cu_seqlens=cu_seqlens,
    checkpoint_state=checkpoint_state,
    checkpoint_offsets=checkpoint_offsets,
)
```

The kernel writes the intermediate and final recurrent states while processing the packed batch. The existing #52789 Triton store kernel then writes the recurrent checkpoint and causal-conv checkpoint into the request-owned cache block as before.

FlashKDA checkpoint offsets must be divisible by its 16-token chunk size. Metadata includes this requirement in the checkpoint validity predicate and omits unsupported offsets instead of passing them to FlashKDA. The cache manager only allocates an internal checkpoint block when the current request start is Mamba-block aligned; otherwise the checkpoint slot remains a real null block and cannot receive a cache hash. Scheduler alignment improvements are intentionally left to a follow-up.

## Microbenchmark

NVIDIA GB300, CUDA 13.0, BF16, head dimension 128, 12 heads, 64 sequences. Timings use CUDA events, ten warmup rounds, nine trials, and report the median.

| Shape | Implementation | FlashKDA calls | Median latency |
| --- | --- | ---: | ---: |
| 64 × 512 tokens, checkpoint 384, tail 128 | #52789 split loop | 128 | 8.4425 ms |
| 64 × 512 tokens, checkpoint 384, tail 128 | Packed single launch | 1 | **0.3733 ms** |
| 64 × 512 tokens, no checkpoint | Packed baseline | 1 | 0.3587 ms |
| 64 × 2,048 tokens, checkpoint 1,536, tail 512 | #52789 split loop | 128 | 10.1720 ms |
| 64 × 2,048 tokens, checkpoint 1,536, tail 512 | Packed single launch | 1 | **1.3040 ms** |
| 64 × 2,048 tokens, no checkpoint | Packed baseline | 1 | 1.2763 ms |

Results:

- 32,768 total tokens: single launch is 22.62x faster than the split loop, reducing kernel latency by 95.58%. Checkpoint export adds 4.08% over a packed call without checkpoint export.
- 131,072 total tokens: single launch is 7.80x faster than the split loop, reducing kernel latency by 87.18%. Checkpoint export adds 2.17%.
- Output, final-state, and checkpoint-state maximum absolute differences between the split and packed implementations are all `0.0` for both shapes.

The benchmark mirrors #52789 by running two sequential FlashKDA calls per request for the baseline and compares it with one call over the same packed Q/K/V/G/beta tensors, initial states, and sequence boundaries.

## End-to-end benchmark

Kimi K3, TP8 on two GB300 nodes, 32 concurrent requests, 15,360-token shared prefix plus 2,048-token distinct suffix per request, three repeats per variant. Both variants used the same FlashKDA#7 binary.

| Variant | Median P50 TTFT | Median request throughput | Median input throughput |
| --- | ---: | ---: | ---: |
| #52789 | 2,121.29 ms | 10.239 req/s | 178,246 tok/s |
| Packed single launch | **1,893.82 ms** | **11.229 req/s** | **195,466 tok/s** |

The packed path reduced median P50 TTFT by 10.72% and increased request throughput by 9.66%. All six runs completed 32/32 requests and reported the expected 491,520-token prefix-cache hit delta. Slurm job 8758 completed with exit code 0. The benchmark used single-launch revision `dcfea8ea83`; the later alignment guard only affects multimodal encoder-capped chunks and does not change this text workload's aligned path.
