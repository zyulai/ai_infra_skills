## Overview

Allows decode-only full CUDA graphs (`FULL_DECODE_ONLY` / `FULL_AND_PIECEWISE`) under MRV2 PCP with DCP=1 for sparse-MLA models on the DeepSeek-V3.2 attention path (DeepSeek-V3.2 and GLM-5.2/5.3: `deepseek_v32`, `glm_moe_dsa`). In that mode, decode requests are round-robin sharded across PCP ranks. These models previously had to run with `cudagraph_mode=NONE`, but the pure-decode full-graph path from #53867 already handles them. Other `index_topk` models (DSv4/V4.1, MiniMax-M3, ...) still require `NONE`, because they need model-specific work (see #61555 for DSv4.1).

## Claims

- GLM-5.3 with TP1 × PCP4 + EP captures and replays decode-only full CUDA graphs.
- On GSM8K, that is 2.6× faster than eager, with matching accuracy (0.9083 vs 0.9075).

## Validation

Tested with GLM-5.3-NVFP4 on 4×B300: `-tp 1 -pcp 4 --enable-expert-parallel --kv-cache-dtype fp8`, `VLLM_USE_V2_MODEL_RUNNER=1`, `tests/evals/gsm8k/gsm8k_eval.py --num-questions 1319 --max-concurrency 64`:

| cudagraph_mode | GSM8K accuracy | Wall time | Output tok/s |
|---|---|---|---|
| NONE | 0.9075 | 379.5 s | 330 |
| FULL_AND_PIECEWISE | 0.9083 | 145.9 s | 859 |

Every rank captured 11 FULL and 19 PIECEWISE graphs.

`pytest tests/v1/worker/test_gpu_pcp_manager.py`: passes.

## Details

- Pure FULL mode is still rejected, so prefills under PCP keep running piecewise.
- DeepSeek-V3.2 shares GLM-5.3's attention/indexer code but was not run end-to-end.
- Not validated yet with MTP.
