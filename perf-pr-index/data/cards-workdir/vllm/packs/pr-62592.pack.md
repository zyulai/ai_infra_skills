## PR body
```markdown
## Overview

Add a platform-selected backend so hardware plugins can reuse HiSparse's runtime and connector. CUDA uses the same cache operations and kernels.

Related: #60072. Ascend integration: vllm-project/vllm-ascend#19109.

## Claims

- Add `HiSparseBackend` for cache operations, host registration, IPC handles, resident-row payload handling, capture queries, DMA and statistics dtype.
- Let each platform select its HiSparse backend through a `@classmethod` hook. The base platform returns `None`; CUDA overrides the method in `platforms/cuda.py`.
- Validate cache formats before allocation and prepare device views inside the existing initialization rollback scope.
- Use `torch.Stream`, `torch.Event` and `torch.accelerator` directly for common device operations. Only IPC events need backend-specific creation/import/export. FP8 prefill keeps its existing custom-op call.

Speculative group prefetch is excluded. Follower staging keeps the original `decode_batch` condition. No CUDA performance improvement is claimed.

## Details

A plugin overrides `Platform.get_hisparse_backend_cls()` with its backend's qualified class name. Lookup is lazy and cached by class name. HiSparse uses generic torch streams, events, current-stream queries and synchronization. The constructor validates backend availability once. Generic resident gathering has a base implementation; plugins may override packed-payload handling.

The linked Ascend draft must align its resolver workspace ownership and tests with this interface before the pair can merge. Its currently published head still accesses the removed `backend_state` field. Speculative group prefetch is separate work in #63801. Installed PTA 2.10.0.post7 headers provide generic stream/event/device-guard operations, but this source inspection does not establish NPU graph replay or final-pair correctness. Final-head Ascend integration and device validation remain required.

The scheduler, HMA allocation, residency policy, KV formats and attention math keep their existing ownership. The device-view hook runs once after allocation and before binding; per-step metadata and transfers stay outside it. Existing PP/CP/graph restrictions remain. DMA submission retains upstream error handling; this PR adds no exception-drain/quarantine branch or unused backend state.

The open HiSparse PRs checked for overlap, including #57602 and #60358, address ROCm execution/registration and other fixes. This PR provides the platform interface without their kernels or unrelated lifecycle changes.

AI assistance was used for implementation and preparation. Final human review and hardware/model validation remain required before merge.
