## Overview

Fuse native BF16 ReLU2 with NVFP4 quantization for Nemotron shared experts on SM10x. Removes one launch and the BF16 intermediate; reuses the consumer from [#59612](https://github.com/vllm-project/vllm/pull/59612), with no GEMM changes.

## Claims

- **24–31% lower activation/quantization latency at 2K–4K tokens; 13–20% lower including the down-projection GEMM.**
- Bit-exact packed values and live scales, with existing activation/LoRA fallbacks preserved.

## Validation

**Revision `462744b0`, GB200, Nemotron shared-expert dimensions** (K=5376, N=4096). Ordinary native compiler settings, warm CUDA graphs; eight paired samples per shape:

| Tokens | ReLU2 + quantization (µs) | Including down GEMM (µs) | Component speedup |
|---:|---:|---:|---:|
| 1 | 2.56 → 1.54 | 6.53 → 6.28 | 1.04× |
| 128 | 3.33 → 2.31 | 8.16 → 7.77 | 1.05× |
| 2,048 | 17.17 → 12.98 | 35.94 → 31.24 | **1.15×** |
| 4,096 | 35.60 → 24.46 | 74.63 → 59.85 | **1.25×** |

All pairs improve; paired component speedups are 1.147–1.151× at 2K and 1.246–1.258× at 4K. Nsight confirms **3 → 2 kernels** with identical GEMM kernel and grid.

**Correctness:** 325 GPU checks and pre-commit/mypy pass. Full-model oracle: 707,680 fused calls, zero value/scale/padding errors, no post-startup compilation. GSM8K: 90.75% in the current instrumented run; prior controlled A/B: 91.66% in all four runs, identical tokens (not a new-stack paired comparison).

**Revision `60a2df16` (warmup removed), B300:** bitwise identical to `462744b0`, 0–13% lower kernel latency. GSM8K (1319 questions, 5-shot, TP1, CUDA graphs) on Nemotron-3-Super-120B-A12B-NVFP4: 93.6% vs 93.7% on main.

**Serving:** prior-stack C50, 2K-input/1K-output median throughput is 2,359 → 2,375 output tokens/s (+0.66%, six trials/arm), with overlapping ranges—not a robust serving-speedup claim.

**Prefill-heavy serving (same revision):** AGG TP1, C50, 8K-input/128-output; fresh-cache B–C–C–B, six 100-request trials per implementation/budget. Both full retries completed: 24/24 trials, 2,400/2,400 requests passed.

| Token budget | Baseline output tokens/s, median [range] | Fused output tokens/s, median [range] | Median change |
|---:|---:|---:|---:|
| 2,048 | 202.87 [198.90–204.09] | 204.56 [201.90–208.36] | +0.83% |

## Details

Reuses QuantizedActivation; opaque dispatch preserves dynamic rows under guard-free Dynamo. The kernel has a single Triton specialization per K (no M-dependent constexprs), so the profile run compiles it and no startup warmup registration is needed. Output is bitwise identical to `scaled_fp4_quant`, so it feeds any `kNvfp4Dynamic` consumer (FlashInfer CuTe-DSL and CUTLASS verified bit-exact). No scheduler, runner, communication or dependency changes.

Distinct from routed-MoE [#56740](https://github.com/vllm-project/vllm/pull/56740), GELU [#59467](https://github.com/vllm-project/vllm/pull/59467) and normalization [#61073](https://github.com/vllm-project/vllm/pull/61073). No DISAGG, TP>1 or default-stack serving claim.

+def _relu_squared_nvfp4_max_rows(k: int) -> int:
+    # Keep groups and padded scale size <= 2^30 so every pid * 128 group and
+    # pid * 512 padding offset stays within signed int32.
+    groups_per_row = k // 16
+    scale_cols = round_up(groups_per_row, 4)
+    return min((1 << 30) // groups_per_row, (1 << 30) // scale_cols // 128 * 128)
+

+@triton.jit
+def _rcp_ftz(x):
+    return tl.inline_asm_elementwise(
+        "rcp.approx.ftz.f32 $0, $1;",
+        constraints="=f,f",
+        args=[x],
+        dtype=tl.float32,
+        is_pure=True,
+        pack=1,
+    )
+
+
+@triton.jit
+def _max_ignore_nan(a, b):
+    return tl.maximum(a, b, propagate_nan=tl.PropagateNan.NONE)
+

+@triton.jit
+def _e4m3_satfinite(x):
+    packed = tl.inline_asm_elementwise(
+        "{ .reg .b16 v; cvt.rn.satfinite.e4m3x2.f32 v, 0f00000000, $1; "
+        "cvt.u32.u16 $0, v; }",
+        constraints="=r,f",
+        args=[x],
+        dtype=tl.int32,
+        is_pure=True,
+        pack=1,
+    )
+    return packed.to(tl.uint8).to(tl.float8e4nv, bitcast=True)

+@triton.jit(do_not_specialize=["M", "NUM_GROUPS", "PADDED_SCALE_SIZE"])
+def _relu_squared_nvfp4_quant_kernel(
+    x_ptr,
+    global_scale_ptr,
+    output_ptr,
+    scale_ptr,
+    M,
+    K: tl.constexpr,
+    NUM_GROUPS,
+    PADDED_SCALE_COLS: tl.constexpr,
+    PADDED_SCALE_SIZE,
+    GROUPS_PER_CTA: tl.constexpr,
+):
+    pid = tl.program_id(0)
+    groups = pid * GROUPS_PER_CTA + tl.arange(0, GROUPS_PER_CTA)
+    row = groups // (K // 16)
+    col = groups % (K // 16)
+    if pid * GROUPS_PER_CTA < NUM_GROUPS:
+        pair = tl.arange(0, 8)
+        index = row[:, None].to(tl.int64) * K + col[:, None] * 16 + pair[None, :] * 2
+        valid = groups[:, None] < NUM_GROUPS
+        values = tl.load(
+            x_ptr
+            + row[:, None].to(tl.int64) * K
+            + col[:, None] * 16
+            + tl.arange(0, 16)[None, :],
+            valid,
+            other=0,
+        )
+        lo, hi = tl.split(tl.reshape(values, (GROUPS_PER_CTA, 8, 2)))
+        lo, hi = lo.to(tl.float32), hi.to(tl.float32)
+        # ReLU propagates NaN; tl.maximum otherwise defaults to maxnum semantics.
+        lo = tl.maximum(lo, 0.0, propagate_nan=tl.PropagateNan.ALL)
+        hi = tl.maximum(hi, 0.0, propagate_nan=tl.PropagateNan.ALL)
+        # Preserve the materialized BF16 ReLU2 boundary before computing amax.
+        lo = (lo * lo).to(tl.bfloat16).to(tl.float32)
+        hi = (hi * hi).to(tl.bfloat16).to(tl.float32)
+        # Match __hmax2 / __hmax in the CUDA quantizer: ignore individual NaNs.
+        amax = tl.reduce(_max_ignore_nan(lo, hi), 1, _max_ignore_nan)
+        global_scale = tl.load(global_scale_ptr)
+        scale = _e4m3_satfinite(global_scale * (amax * _rcp_ftz(6.0)))
+        scale_f32 = scale.to(tl.float32)
+        inverse = tl.where(
+            scale_f32 != 0.0,
+            _rcp_ftz(scale_f32 * _rcp_ftz(global_scale)),
+            0.0,
+        )
+        lo = lo * inverse[:, None]
+        hi = hi * inverse[:, None]
+        packed = tl.inline_asm_elementwise(
+            "{ .reg .b8 v; cvt.rn.satfinite.e2m1x2.f32 v, $2, $1; cvt.u32.u8 $0, v; }",
+            constraints="=r,f,f",
+            args=[lo, hi],
+            dtype=tl.int32,
+            is_pure=True,
+            pack=1,
+        ).to(tl.uint8)
+        tl.store(output_ptr + index // 2, packed, valid)
+        scale_index = (
+            ((row.to(tl.int64) // 128) * (PADDED_SCALE_COLS // 4) + col // 4) * 512
+            + (row % 32) * 16
+            + ((row % 128) // 32) * 4
+            + col % 4
+        )
+        tl.store(scale_ptr + scale_index, scale, groups < NUM_GROUPS)
+
+    # Initialize only padding; these stores never overlap the live scale stores.
+    if pid < PADDED_SCALE_SIZE // 512:
+        offsets = pid * 512 + tl.arange(0, 512)
+        padded_row = (
+            (pid // (PADDED_SCALE_COLS // 4)) * 128
+            + (offsets % 16 // 4) * 32
+            + offsets % 512 // 16
+        )
+        padded_col = (pid % (PADDED_SCALE_COLS // 4)) * 4 + offsets % 4
+        is_padding = (padded_row >= M) | (padded_col >= K // 16)
+        tl.store(scale_ptr + offsets, 0.0, is_padding)
+

+def _relu_squared_nvfp4_quant_fake(
+    x: torch.Tensor, global_scale: torch.Tensor
+) -> tuple[torch.Tensor, torch.Tensor]:
+    m, k = x.shape
+    output = torch.empty((m, k // 2), dtype=torch.uint8, device=x.device)
+    block_scale = torch.empty(
+        (round_up(m, 128), round_up(k // 16, 4)),
+        dtype=torch.float8_e4m3fn,
+        device=x.device,
+    )
+    return output, block_scale

+def _relu_squared_nvfp4_quant(
+    x: torch.Tensor, global_scale: torch.Tensor
+) -> tuple[torch.Tensor, torch.Tensor]:
+    m, k = x.shape
+    # vLLM can reuse compiled graphs without checking Dynamo's shape guards.
+    assert m <= _relu_squared_nvfp4_max_rows(k), "NVFP4 row limit exceeded"
+    output, block_scale = _relu_squared_nvfp4_quant_fake(x, global_scale)

+    scale_cols, scale_size = block_scale.shape[1], block_scale.numel()
+    groups = m * (k // 16)
+    # Each CTA zeroes at most one 128x4 scale tile, so no constexpr depends on M.
+    grid = (max(triton.cdiv(groups, 128), scale_size // 512),)
+    _relu_squared_nvfp4_quant_kernel[grid](
+        x,
+        global_scale,
+        output,
+        block_scale,
+        M=m,
+        K=k,
+        NUM_GROUPS=groups,
+        PADDED_SCALE_COLS=scale_cols,
+        PADDED_SCALE_SIZE=scale_size,
+        GROUPS_PER_CTA=128,
+        num_warps=4,
+        enable_fp_fusion=False,
+    )
+    return output, block_scale
