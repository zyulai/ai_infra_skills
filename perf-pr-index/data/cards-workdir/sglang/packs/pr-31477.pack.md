## PR body
```markdown
## Motivation

GLM-5.2 MTP reuses DSA IndexShare top-k seeds across draft-decode steps to avoid redundant indexer work. The seed-transfer path added in [PR #30839](https://github.com/sgl-project/sglang/pull/30839) preserves allocator independence by transporting request-relative positions. Because the existing fused TopK consumes allocator-local physical KV slots, this path currently falls back to an unfused page-table transform during draft decode.

This PR optimizes GLM-5.2 MTP IndexShare specifically under PD disaggregation. It converts the transferred seed once at the Decode consumer and then uses the existing fused TopK. The wire representation remains unchanged, while the Decode-local remap is required because the Prefill and Decode allocators are independent.

## Modifications

- Keep GLM-5.2 MTP IndexShare seeds in request-relative position space during transfer.
- For the supported Decode consumer path (`SGLANG_DSA_FUSE_TOPK=1`, non-HiSparse, and `dcp_size == 1`), remap the seed once through the local `req_to_token` table before it enters the EAGLE draft loop.
- Fail invalid seed rows closed instead of consuming stale, out-of-range, or unallocated slots.
- Enable the existing fused DSA TopK after the local remap.
- Add one focused CPU unit test covering fused-path selection and position-to-local-slot remapping.

- MTP acceptance: `66% -> 66%`

- No request errors, OOMs, worker restarts, or long-context CUDA Graph fallback
- Targeted CPU suite: `19 passed, 17 warnings, 2 subtests passed`

- 4 nodes, 32 x H20-96G
- Prefill: 2 nodes, TP16, EAGLE/MTP
- Decode: 2 nodes, TP16, EAGLE/MTP, Full CUDA Graph
- HiSparse disabled

- 131072 input tokens + 1536 output tokens
- Concurrency 1, temperature 0, fixed seed
- One excluded warmup followed by three independent cache-miss runs per arm

TTFT and PD transfer time were unchanged within noise, as expected for a Decode-local optimization. Target verify, draft extend, and draft decode remained on Full CUDA Graph in all measured runs.

Raw profiler durations are intentionally not used for an A/B latency claim because capture perturbation differs between the two CUDA Graph paths; the profiler-off repeated `128K + 1.5K` A/B above remains the performance evidence.
