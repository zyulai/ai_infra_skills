## 正文(PR 描述)

## Motivation

#8472 

We have been encountering various unexpected behavior while tuning `mem-fraction-static` for GLM4.5. For example:
1. None of the GLM4.5 model can run without explicitly specifying `mem-fraction-static` when MTP is enabled.
2. The full weight (300B) model can start successfully with 0.8, but the lighter weight Air version (100B) instead will run into OOM unless we adjust `mem-fraction-static` to 0.5 or below.

Upon investigation, I noticed that when we create KV cache for the draft model, currently we for ALL model layers while we only needed the last MTP layer. 

## Modifications

Use `num_nextn_predict_layers` to determine draft model kv cache size.

## Result

After the change, all the 4 GLM 4.5 models can be started without `--mem-frac-static` override with comparable GSM scores:

* zai-org/GLM-4.5
 ```
python3 -m sglang.launch_server \
  --model zai-org/GLM-4.5 \
  --tp 8 \
  --speculative-algorithm EAGLE \
  --speculative-num-steps 3 \
  --speculative-eagle-topk 1 \
  --speculative-num-draft-tokens 4
```
* zai-org/GLM-4.5-Air
```
python3 -m sglang.launch_server \
  --model zai-org/GLM-4.5-Air\
```
