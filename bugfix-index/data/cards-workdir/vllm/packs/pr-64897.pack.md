## 正文(PR 描述)

## Purpose

XPU on main is broken. This PR fixes `greedy_argmax`'s torch fallback to treat NaNs as `-inf`, matching its documented contract and Triton path. This issue was introduced by #57770.

**Notes for Reviewers**

- The fix only touches the torch fallback, which runs on XPU, for fp16, and for small vocabularies. The Triton path that bf16/fp32 models use on CUDA and ROCm is unchanged, so typical deployments see no difference.
- The trade-off is one extra copy of the logits on the fallback path. That's a small cost next to the weights the draft step already reads, and it's the price of getting the same token for the same logits everywhere.
- Turning on the Triton kernel for XPU would avoid that copy, but it needs XPU performance numbers and sign-off from the XPU owners. CPU and non-contiguous inputs would still need this fallback anyway. I kept this PR to the minimal fix so XPU CI is unblocked, and we can address the Triton change in a follow up PR.
- Why not just fix the test? The docstring already promises NaN is treated as -inf, and the Triton path does exactly that. Changing the test instead would let the drafted token depend on the platform and dtype.

## Reproducer

Add `1000` to the existing test's vocab parameters, then run the same command before and after the fallback fix:

```bash
  python -m pytest -v \
  tests/v1/worker/test_gpu_gumbel_sample.py -k test_greedy_argmax_matches_torch
```

<details>
<summary>Implementation and environment</summary>

The fallback uses `masked_fill(isnan, -inf).argmax(-1)`, preserving infinities and first-index ties without modifying inputs. It adds a mask and logits copy only on the fallback. The Triton kernels and gating are unchanged, so eligible BF16/FP32 CUDA/ROCm inputs keep the existing execution path.
</details>
