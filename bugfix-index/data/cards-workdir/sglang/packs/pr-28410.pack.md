# PR #28410: [Bugfix] Fix MTP acceptance regression on plan stream by moving int64 cast before plan stream context

## 正文(PR 描述)

## Motivation
Closes https://github.com/sgl-project/sglang/issues/28405, https://github.com/sgl-project/sglang/issues/28406.
PR #28043 fixed a DeepSeek-V4 DP dtype mismatch hang by normalizing predict to torch.int64 inside prepare_for_draft_extend . However, when the overlap plan stream is enabled, this cast executes on the plan stream while predict is produced on the main stream, creating a cross-stream data race that silently corrupts draft token ids and drops MTP acceptance to nearly zero.

## Modifications
- eagle_worker_v2.py : Move the predict.to(torch.int64) cast from inside prepare_for_draft_extend to _draft_extend_for_decode , before entering the plan stream context. The cast now runs on the main stream with correct synchronization.
- base_spec_worker.py : Update the comment in prepare_for_draft_extend to explain why dtype normalization must NOT be done inside this function, and that the caller should cast before entering the plan stream.

## Accuracy Tests
No impact on model output — the int64 cast preserves all token id values. The fix only changes where the cast executes (main stream vs. plan stream).

## Speed Tests and Profiling
No impact on inference speed. The int64 cast is a lightweight element-wise operation on a small token-id tensor, not on hidden states, logits, or KV cache. The cast already existed in PR #28043; this PR only moves its execution point without adding extra overhead.
