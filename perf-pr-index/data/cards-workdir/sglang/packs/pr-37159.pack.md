## Motivation

GLM-4.5-FP8 uses per-channel FP8 Triton MoE with the per-rank TP8 geometry
`E=161,H=5120,I=192,topk=9`. SGLang had no Triton 3.7.1 GB300 config for this
exact lane and therefore used the generic heuristic.

The missing tuned baseline was identified while validating
[KDA-Pilot PR #197](https://github.com/BBuf/KDA-Pilot/pull/197). A larger custom
kernel was also evaluated, but the tuned generic kernel was faster, so this PR
only adds the smaller configuration change. Validation uses current SGLang main
at `5ab97c4f441462f3d2adb1ffa954cc92518beece`.

## Modifications

- Add a sparse Triton configuration map for `E=161,N=192`, NVIDIA GB300,
  `fp8_w8a8`, `per_channel_quant=True`, and Triton 3.7.1.
- Cover decode/small batch through 16K-token prefill. The existing optional
  down-projection fallback reuses the same tuned map.
- Add a CPU test that pins the expected token grid and verifies the config is
  packaged.

The filename's device, Triton, dtype, and scale-mode selectors keep all other
hardware, Triton versions, quantization modes, and MoE shapes on their existing
fallbacks.

## Accuracy Tests

Hardware: 2 nodes, 4x NVIDIA GB300 (SM103) per node, TP8 over the same NVLink
domain. Software: CUDA 13.0, PyTorch 2.13.0+cu130, Triton 3.7.1.

```bash
PYTHONPATH=python python3 -m pytest -q \
  test/registered/unit/layers/moe/test_fused_moe_triton_config.py
```

Result: `4 passed`.

An exact-production-shape comparison of the default and tuned schedules used
`[161,384]` / `[161,5120]` per-channel scale tensors. For M=1/16/256/2048,
the largest observed absolute difference was `2.4e-7` and the largest mean
relative difference was `1.67e-8`. The real TP8 server loaded the exact config
on all ranks and completed all 74 prefill and 52 decode CUDA Graph captures.

## Speed Tests and Profiling

### Full FP8 fused-experts call under CUDA Graph

This includes up GEMM, SiLU-and-mul, down GEMM, routed weighting, and combine.

| Tokens | Default (us) | Tuned (us) | Speedup |
|---:|---:|---:|---:|
| 1 | 32.788 | 30.730 | 1.067x |
| 16 | 121.018 | 84.050 | 1.440x |
| 256 | 236.390 | 136.889 | 1.727x |
| 512 | 244.532 | 160.625 | 1.522x |

The sweep used the production `E=161,H=5120,I=192,topk=9` geometry and real
`[E,N]` per-channel scale layout.

### GLM-4.5-FP8 serving

Two-node TP8, concurrency 16. Each number is the median of three trials with
seeds 1001/1002/1003. `--random-range-ratio 1.0` fixes every request at the
stated lengths, and each trial flushes the cache.

| Workload | Baseline output tok/s | This PR output tok/s | Change | Mean TPOT change |
|---|---:|---:|---:|---:|
| 1 input / 256 output, 256 prompts | 1016.42 | 1238.80 | **+21.88%** | **-19.16%** |
| 1024 input / 256 output, 128 prompts | 926.13 | 1125.10 | **+21.48%** | **-19.52%** |

Per-trial output throughput was 1024.44/1010.58/1016.42 vs
1238.80/1234.85/1241.27 tok/s for decode, and 926.15/922.44/926.13 vs
1125.10/1124.37/1129.06 tok/s for mixed.

Server (run on both nodes with the corresponding rank):

```bash
python3 -m sglang.launch_server \
  --model-path /scratch/models/GLM-4.5-FP8 --trust-remote-code \
  --quantization compressed-tensors --tp-size 8 --nnodes 2 \
  --node-rank ${RANK} --dist-init-addr ${RANK0_IP}:29501 \
  --moe-runner-backend triton --attention-backend trtllm_mha \
  --mem-fraction-static 0.902 --chunked-prefill-size 16384 \
  --max-prefill-tokens 16384 --page-size 64 \
  --disable-chunked-prefix-cache --enable-tf32-matmul \
  --reasoning-parser glm45 --tool-call-parser glm --port 30000
```

Benchmark (decode; mixed changes input length to 1024 and prompts to 128):

```bash
python3 -m sglang.bench_serving --backend sglang \
  --base-url http://127.0.0.1:30000 \
  --model /scratch/models/GLM-4.5-FP8 --dataset-name random \
  --random-input-len 1 --random-output-len 256 \
  --random-range-ratio 1.0 --num-prompts 256 --max-concurrency 16 \
  --seed 1001 --warmup-requests 16 --flush-cache --disable-tqdm
```
