## Purpose

Use **local argmax + gather reduction** instead of **all-gathering full-vocabulary logits** to reduce TP communication overhead in speculative decoding modes such as **DFlash** and **PARD**.

Enabling `use_local_argmax_reduction` improves performance in all tested scenarios.

In terms of **Total token throughput (tok/s)**, the gains are:

* **+9.38%** for Qwen3-8B + Qwen3-8B-DFlash + tp2 at 1 concurrency
* **+10.21%** for Qwen3-8B + Qwen3-8B-DFlash + tp2 at 32 concurrency
* **+11.54%** for Qwen3-8B + Qwen3-0.6B-PARD + tp2 at 32 concurrency
* **+30.63%** for Qwen3-8B + Qwen3-8B-DFlash + tp4 at 32 concurrency

## Current Issue

Speculative decoding methods such as **DFlash** and **PARD** often require the draft model and target model to have the same vocabulary size. Under the current implementation, this requires **all-gathering the full logits tensor across TP ranks**, which incurs **O(batch_size × vocab_size)** communication cost per step. For example, **PARD-Qwen3-0.6B** uses a vocabulary size of **40960**.

We can reuse the approach introduced in [https://github.com/vllm-project/vllm/pull/34049](https://github.com/vllm-project/vllm/pull/34049) to reduce this communication overhead.

This PR adds a `use_local_argmax_reduction` option to `speculative_config` that:

* Computes the local argmax on each TP rank's vocab shard
* Gathers only `(max_value, global_index)` pairs — **O(batch_size × 2 × tp_size)** instead of **O(batch_size × vocab_size)**
* Reduces across ranks to find the global argmax

## Changes

Add `get_top_tokens()` to the corresponding model files.

+class LocalArgmaxMixin:
+    """Mixin for draft model heads in speculative decoding.
+
+    Provides a D2T-aware ``get_top_tokens`` that preserves the
+    local-argmax communication reduction even when the draft vocabulary
+    is smaller than the target vocabulary.
+
+    When ``draft_id_to_target_id`` is present (shape ``(draft_vocab_size,)``,
+    containing per-token offset to target vocab id), the draft argmax index
+    ``k`` is mapped to the target vocab id via::
+
+        target_id = k + draft_id_to_target_id[k]
+
+    This is mathematically equivalent to computing the full-vocab scatter
+    logits and taking the global argmax, but requires only
+    O(batch * 2 * tp_size) communication instead of O(batch * vocab_size).
+
+    Requires the subclass to expose:
