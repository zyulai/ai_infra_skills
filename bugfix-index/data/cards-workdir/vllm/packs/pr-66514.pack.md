## 正文(PR 描述)

## Purpose

Fix the DeepSeek-V3 NIXL cells (1P1D TP8, 1P1D EP8, 2P2D EP16; pull and push) on the CI image's stock UCX. Follow-up to #62007.

## Changes

- `cluster.sh`:
  - Set `UCX_ROCM_COPY_DMABUF=no`. UCX 1.23 turns on DMABUF registration for ROCm memory; with it TP8 runs out of memory and EP8/EP16 fail with HIP error 209.
  - Drop `tcp` and `lo` so KV cannot fall back to TCP, and list all ionic NICs in `UCX_NET_DEVICES`.
- `vllm_disagg.sh`: set `VLLM_NIXL_SIDE_CHANNEL_HOST` to the node's IP. It defaults to localhost, so decode handshakes with itself and every load silently recomputes.
- `pipeline-disagg.yaml`: run the EP8 and 2P2D EP16 cells at accuracy concurrency 32. At 1 the EP16 eval runs past the 105-minute limit. TP8 keeps the default of 1.

- `models.yaml`: fit Kimi-K3 2P2D EP16 in memory. At 0.75 the prefill KV cache goes negative, and without a sequence cap prefill fails its startup check (`num_cache_lines >= batch`). Prefill now runs at 0.82 with `--max-num-seqs 128 --max-num-batched-tokens 8192`; decode runs at 0.80 with `--max-num-seqs 128 --max-num-batched-tokens 512`. gsm8k 0.9636 (1319 questions).

```bash
export UCX_TLS=rc_verbs,ud_verbs,self,rocm
export UCX_NET_DEVICES=ionic_0:1,ionic_1:1,ionic_2:1,ionic_3:1,ionic_4:1,ionic_5:1,ionic_6:1,ionic_7:1
export UCX_IB_GID_INDEX=1
export UCX_UD_VERBS_ETH_DGID_CHECK=n
export UCX_IB_GPU_DIRECT_RDMA=yes
export UCX_RMA_PPLN_ENABLE=y
export UCX_PROTO_EMULATION_ENABLE=n
export UCX_KEEPALIVE_INTERVAL=inf
export UCX_UD_VERBS_RX_QUEUE_LEN=1024
export UCX_RCACHE_MAX_UNRELEASED=1024
export UCX_ROCM_COPY_DMABUF=no
export VLLM_NIXL_SIDE_CHANNEL_HOST=$NODE_IP
```

KV config (`kv_consumer` on decode; push uses `"kv_connector":"NixlPushConnector"`):

```bash
KV='{"kv_connector":"NixlConnector","kv_role":"kv_producer","kv_load_failure_policy":"recompute","kv_connector_extra_config":{"backends":["UCX"],"kv_lease_duration":180}}'
```

TP8, prefill (port 8100) and decode (port 8200, `kv_consumer`):

```bash
vllm serve DeepSeek-V3 --host $NODE_IP --port 8100 --tensor-parallel-size 8 \
  --trust-remote-code --kv-cache-dtype fp8 --max-model-len 32768 \
  --gpu-memory-utilization 0.85 --kv-transfer-config "$KV"
```

EP8/DP8, prefill:

```bash
vllm serve DeepSeek-V3 --port 20005 -tp 1 --data-parallel-size 8 --data-parallel-size-local 8 \
  --data-parallel-address $PREFILL_IP --data-parallel-rpc-port 13345 \
  --enable-expert-parallel --all2all-backend mori_high_throughput --enforce-eager \
  --no-enable-prefix-caching --api-server-count 8 --trust-remote-code \
  --kv-cache-dtype fp8 --max-model-len 32768 --gpu-memory-utilization 0.85 \
  --kv-transfer-config "$KV"
```

EP8/DP8, decode: the same with `--data-parallel-address $DECODE_IP`, `--all2all-backend mori_low_latency`, no `--enforce-eager`, `--gpu-memory-utilization 0.75` and `kv_consumer`.

EP16/DP16 side (2 nodes), master:

```bash
vllm serve DeepSeek-V3 --port 20005 -tp 1 --data-parallel-size 16 --data-parallel-size-local 8 \
  --data-parallel-address $MASTER_IP --data-parallel-rpc-port 13345 \
  --enable-expert-parallel --all2all-backend mori_high_throughput --enforce-eager \
  --no-enable-prefix-caching --api-server-count 8 --trust-remote-code \
  --kv-cache-dtype fp8 --gpu-memory-utilization 0.75 --kv-transfer-config "$KV"
```

The second node runs the same command with `--headless --data-parallel-start-rank 8` and the same `--kv-transfer-config`. A decode EP16 side uses `--all2all-backend mori_low_latency`, no `--enforce-eager` and `kv_consumer`.

Router (`--intra-node-data-parallel-size 1` for TP8, `8` for EP):

```bash
vllm-router --vllm-pd-disaggregation --kv-connector nixl \
  --prefill http://$PREFILL_IP:8100 --decode http://$DECODE_IP:8200 \
  --worker-startup-timeout-secs 1800 --port 30000 --host 0.0.0.0 \
  --intra-node-data-parallel-size 8 --policy round_robin \
  --prefill-policy round_robin --decode-policy round_robin
```

Accuracy (`num_concurrent=32` for EP8 and EP16, 1 for TP8):

```bash
lm_eval --model local-completions --tasks gsm8k \
  --model_args model=DeepSeek-V3,base_url=http://127.0.0.1:30000/v1/completions,num_concurrent=1,tokenized_requests=False,trust_remote_code=True
```

## Results

GSM8K 5-shot exact_match on the image's UCX 1.23.0. With this PR every run had no failed transfers.

| Cell | GSM8K without this PR | GSM8K with this PR |
|---|---|---|
| 1P1D TP8 pull | no score: out of memory at startup | 0.9431 |
| 1P1D TP8 push | no score: out of memory at startup | 0.9454 |
| 1P1D EP8 pull | no score: HIP error 209 at startup | 0.9469 |
| 1P1D EP8 push | no score: HIP error 209 at startup | 0.9462 |
| EP16 pull (3 nodes) | no score: HIP error 209 at startup | 0.9409 |
| EP16 push (3 nodes) | not run | 0.9424 |

KV moved over RDMA only, evenly across all 8 NICs. TP8 transfer time drops from 31-38 ms to 7 ms per 137 MB; EP8 stays at 93-102 ms per 144 MB.
