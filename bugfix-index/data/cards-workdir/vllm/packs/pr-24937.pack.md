## 正文(PR 描述)

<!-- markdownlint-disable -->

## Purpose
Fix wrong token length when using random dataset.

Because sometime `seq != tokenizer.decode(tokenizer.encode(seq))`, we need to iterate and fix the length until it match.

## Test Plan

`vllm bench serve --backend vllm --host 0.0.0.0 --port 8000 --model /home/model/gpt-oss-120b --num-prompts 640 --trust-remote-code --ignore-eos --max-concurrency 128 --random-input-len 8192 --random-output-len 1024 --random-range-ratio 0 --no-stream --dataset-name random `

## Test Result
before the change, when print length, we can see cases like:
```
len(token_sequence), target_token_len: 8179, 8192
len(token_sequence), target_token_len: 8185, 8192
```

after the change, all is 8192

+
+    This function decodes an initial token sequence to text and re-encodes it
+    , iteratively adjusting the token sequence length to match a target. 
+    This is necessary because some tokenizers do not guarantee a 1:1 mapping 
+    between consecutive tokens and the decoded-then-encoded sequence length.
+    For example, for GPT2Tokenizer:
+    [6880, 6881] -> ['Ġcalls', 'here'] ->
+    [1650, 939, 486] -> ['Ġcall', 'sh', 'ere']
+
+    Returns a tuple of the final prompt string and the adjusted token sequence.
+    """
+    remain_num_try = max_retry
+    token_mismatch = 0
+    while True:
+        prompt = tokenizer.decode(token_sequence)
+        token_sequence = tokenizer.encode(
+            prompt, add_special_tokens=add_special_tokens
+        )
+        if remain_num_try <= 0:
