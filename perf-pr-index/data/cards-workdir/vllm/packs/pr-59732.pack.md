## Overview

On ROCm, the Qwen4Exp QSA layer's main-attention QK-norm, RoPE, gate split and K/V cache write now run inside the fused QSA prepare launch, as #57097 did for NVIDIA.

## Claims

- MI355X TP2 `amd/Qwen3.8-Flash-Next-Quark-MXFP4`: +0.9% to +2.9% output throughput, faster in all 8 measured cells (4 points × 2 repeats).
- Accuracy neutral: GSM8K 0.9638 → 0.9605 over 6 pairs, a −0.33 point paired difference within run-to-run noise (paired t = −1.8, 5 df).
- Kernel numerics no worse than the unfused AMD chain against an fp64 reference; the gate is bit-identical.

## Details

- **Kernel.** `amd/ops/qsa_pre_indexer.py` becomes `amd/ops/qsa_prepare.py`, matching NVIDIA's naming, and takes #57097's main-attention programs unchanged. Its only other difference from NVIDIA's kernel is still #57947's two-masked-load state select.
- **Gate out of the op.** The AMD layer applies the output gate after its opaque QSA op, so the gate has to come out of it. A new `qwen4_exp_qsa_prepare_with_output` custom op takes the packed `qkv` and mutates `output` and `gate`; the wrapper's optional `main_gate_out` writes the gate straight into that buffer.
- **Padding rows.** `* sigmoid(gate)` stays in the compiled graph, where Inductor fuses it as before. NVIDIA's attention kernel gates real tokens only; AMD's graph gates every row, so the op zeroes the gate's cudagraph-padding rows, keeping them at the zero output `forward_qsa` writes. With no padding the fill launches nothing.
- **Eligibility.** On when the layer has an output gate, the indexer passes `supports_fused_pre_indexer`, and the main head dim is a power of two. The main RoPE reads the indexer's cos/sin table, which is the layer's own `rotary_emb`. Otherwise both prepares take the unfused chain, as on NVIDIA.
- **No CPU/GPU sync** on the hot path: eligibility is decided at init; the gate padding size is the static difference between the padded and real token counts.
