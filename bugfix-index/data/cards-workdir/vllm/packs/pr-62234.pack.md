## 正文(PR 描述)

### Overview

Three GLM-family MTP (Multi-Token Prediction) models — `glm4_moe_mtp.py` (GLM-4.5 / GLM-4.5-Air / GLM-4.6), `glm4_moe_lite_mtp.py` (GLM-4.7-Flash), and `glm_ocr_mtp.py` (GLM-OCR) — return the **pre-final-norm** hidden from the MTP layer, so the speculator recycles a hidden that is one RMSNorm short into the next draft step's `hnorm`. The established GLM/DeepSeek-NextN contract (already merged in vLLM by #47448 and also SGLang's `glm4_moe_nextn`/`deepseek_nextn` `vllm/models/glm5next/common/mtp.py`) recycles the **post-final-norm** hidden. This PR extends that contract to the three models it missed, and registers them in `SpecDecodeBaseProposer.model_returns_tuple()` so Model Runner V1 unpacks the new tuple return. Draft-only change; verified output is unaffected.

**Relation to #62986:** #62986 (opened after this PR) fixes the same recycle for `Glm4MoeMTP` only, DeepSeek-style; its description offers to close in favour of this PR once the V1 registration is included, which it now is (`6ecfab6`). #62987 (enabling `torch.compile` for `Glm4MoeMTP`) is independent.

### Claims

- **Correctness/contract alignment:** each MTP layer now applies the final norm once (fused `shared_head.norm(hidden, residual)`) and returns the post-final-norm hidden for both tuple positions, with `compute_logits` consuming it directly — identical to #47448 and `glm5next`.
- **Both model runners:** Model Runner V2 unpacks tuple returns generically; Model Runner V1 (`SpecDecodeBaseProposer`) only unpacks registered architectures, so `Glm4MoeMTPModel`, `Glm4MoeLiteMTPModel` and `GlmOcrMTPModel` are added to `model_returns_tuple()`. Without that, V1 crashes on the first draft step (below).
- **Lossless:** speculative decoding verifies every drafted token, so the target-visible output is unchanged; only the drafter's recycled state changes (affects draft steps ≥1, i.e. `num_speculative_tokens ≥ 2`).
- **No performance regression, and no performance claim.** On a real checkpoint (GLM-4.5-Air) a controlled, paired acceptance measurement shows **no statistically significant change** in draft acceptance (details below).

### Details

Root cause: the MTP layer forward ended with `hidden_states = residual + hidden_states; return hidden_states` (pre-final-norm), and `compute_logits` applied `shared_head` to it. The speculators store the model's returned hidden as the next step's `previous_hidden_states` (fed into `hnorm`), so the recycled state was missing the final `shared_head` RMSNorm that DeepSeek/`glm5next` apply; the logits path was always correctly single-normed. Fix (per file):

```python
hidden_states, _ = self.shared_head.norm(hidden_states, residual=residual)
return hidden_states, hidden_states
```

plus `compute_logits`: `shared_head.head, hidden_states` (drop the second norm), and the three architectures added to `model_returns_tuple()`. Affects the single-module AR path (`num_nextn_predict_layers=1`, k≥2 — the common GLM-4.5/4.6 case) and the multi-module path; k=1 is unaffected.

The two tuple elements are intentionally the same post-norm tensor, as in #47448 and `glm5next`, which go through the same recycle sites: the MRV2 AR step-0 setup stores `last_hidden_states[idx]`, MRV2 steps ≥1 and the multi-module path recycle the second element, and V1 unpacks the tuple once the architecture is registered.
