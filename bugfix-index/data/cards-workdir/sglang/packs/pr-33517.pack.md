## 正文(PR 描述)

## Motivation

`--enable-unified-memory` + `--attention-backend triton` + `--enable-deterministic-inference` together produce `NaN` logits. Any two of the three are fine, which is why no existing test caught it. Found while adding a PD-disaggregation test in #33362; this is a pre-existing defect on `main`, unrelated to PD, and #33362 works around it by not setting those flags together.

The failure is nastier than a crash: it only *aborts* when `SGLANG_ENABLE_ASYNC_ASSERT` is armed (which CI does):

```
_assert_async_cuda_kernel: Assertion `NaN detected! sampler: next_token_logits` failed.
```

Without that flag the run completes and returns finite top-k logprobs, so the corruption is silent locally.

## Root cause

`--enable-deterministic-inference` routes Triton extend through `TritonAttnBackend._forward_extend_unified`, a 1-stage kernel that reads **both** the prefix and the extend half of the KV out of the pool — unlike the default 2-stage path, which takes the extend half from its `k`/`v` arguments and only reads the prefix from the pool.

That kernel was given `forward_batch.out_cache_loc` untranslated. On the unified memory pool `out_cache_loc` holds **virtual** ids, and the prefix `kv_indices` are already translated in `init_forward_metadata`. So the prefix was read at physical ids while the just-written extend tokens were read at virtual ones; the mismatched reads produce garbage that becomes NaN by the LM head.

This also explains the three-way condition exactly:
- **without deterministic** — the 2-stage kernel never reads the extend half from the pool;
- **without unified memory** — `out_cache_loc` is already physical, so no translation is needed;
- **without Triton** — another backend doesn't use this kernel.

## Modifications

Use the translation already computed once per forward for the KV write (`forward_metadata.out_cache_loc_full_physical`) as the extend read indices. This matches the idiom a few lines above in the same function's `k is None` branch (SWA translate first, else the unified translate), which is where the pattern was established — line 1600 was simply missed.

- SWA layers keep taking the raw virtual loc: `translate_loc_from_full_to_swa` consumes virtual ids by contract.
- Reuses the per-forward translation rather than re-translating, because `_forward_extend_unified` runs once per layer.
- **No effect on static pools**: `out_cache_loc_full_physical` is `None` unless the allocator exposes a virtual→physical translate, and `translate_kv_loc` / `translate_kv_loc_dense` are defined only in `multi_ended_allocator.py` (the unified allocators).

Incidentally this also repairs unified **SWA** pools under deterministic Triton extend, whose full-attention layers hit the same path (not covered by the test below; the test uses the MLA hybrid-Mamba pool).

## Validation

On `yujiepan/kimi-linear-tiny-random`, 257-token prompt, `SGLANG_ENABLE_ASYNC_ASSERT=1`:

| config | before | after |
|---|---|---|
| unified + triton + deterministic | **NaN abort** | `[-11.908, -11.918, -11.880, -11.880]` |
| static + triton + deterministic (reference) | same values | same values |

The fixed unified run is bit-identical to the static pool, which is the real confirmation — not merely "no longer NaN".

New regression test `test/registered/attention/test_unified_memory_deterministic.py` asserts unified-vs-static parity under the three flags. Verified it **fails on the unfixed code** (1 NaN assert) and **passes on the fix**. Triton is pinned there on purpose: the defect lives in the Triton deterministic kernel, so a resolved default backend would not exercise it.
