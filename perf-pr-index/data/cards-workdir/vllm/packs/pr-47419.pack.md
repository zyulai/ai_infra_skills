## Summary

DSpark speculative decoding for **DeepSeek-V4-Pro (1.6T)** was previously **NVIDIA-only** in vLLM:
`vllm/models/deepseek_v4/__init__.py` sets `DSparkDeepseekV4ForCausalLM = None` on ROCm, so
`--speculative-config '{"method":"dspark",...}'` fails at model-load time on AMD GPUs.

This PR enables DSpark on ROCm by porting the draft model to the AMD subpackage and wiring the two
pieces the draft depends on that were missing on the AMD path (the EAGLE3 aux-hidden-state interface
on the target model, and the non-causal sliding-window-attention ragged-buffer sizing). The base
DeepSeek-V4 model, the ROCm sparse-MLA / sparse-SWA backends, and the MHC
`aiter`/`triton` kernels already existed on ROCm — DSpark reuses all of them, so this is a wiring
port, not new kernel work.

Model: [`deepseek-ai/DeepSeek-V4-Pro-DSpark`](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro-DSpark)

## Changes

### Why the sparse-SWA ragged-buffer change is required

`DeepseekV4ROCMAiterSparseSWAMetadataBuilder` allocated its persistent ragged index buffer for the
**causal** window width only (`max_tokens * window_size`) and passed `window_size` as the
max-entries-per-row to `_copy_ragged_to_graph_buffers`. DSpark's **non-causal** draft widens each
token's SWA index list to `noncausal_index_width = cdiv(window_size + num_speculative_tokens, 128) * 128`,
so the actual `nnz` overflows the buffer and crashes with e.g. `RuntimeError: The size of tensor a
(896) must match the size of tensor b (1792) at non-singleton dimension 0`.

The non-causal path was never exercised on ROCm before (its only user, DSpark, was stubbed), which is
why this was latent. The fix is backward-compatible: for the non-DSpark/causal path
`noncausal_index_width == 0`, so `max(window_size, noncausal_index_width) == window_size` and
`base.decode_swa_indices.shape[-1] == window_size` — i.e. a no-op for the existing base path, and
correct for DSpark.

## Results (8× AMD MI350X, gfx950)

- Image: `vllm/vllm-openai-rocm:nightly-09663abde0f50944a8d5ea30120666024b503faa` (vLLM `0.23.1rc1.dev714+g09663abde`)
- Recipe: InferenceX `dsv4-fp4-mi355x-vllm` (TP=8, `--moe-backend aiter`, FP8 KV cache, full CUDA graph `mode:3 FULL_AND_PIECEWISE`)
- Workload: `ISL/OSL = 1024/1024`, `--ignore-eos` (fixed 1024 output tokens/request), greedy
- The DeepSeek-V4-Pro checkpoint is mixed precision: FP4 (MXFP4) MoE experts + FP8 block-scaled dense/attention + FP8 (`fp8_ds_mla`) KV cache.

## Reproduction

All commands run inside the ROCm container. Environment: `VLLM_ROCM_USE_AITER=1`.

### 1. Serve

**STP baseline (no speculative decoding):**

```bash
VLLM_ROCM_USE_AITER=1 vllm serve deepseek-ai/DeepSeek-V4-Pro-DSpark --port 8000 \
    --tensor-parallel-size 8 --data-parallel-size 1 \
    --async-scheduling --no-enable-prefix-caching \
    --distributed-executor-backend mp \
    --gpu-memory-utilization 0.8 --kv-cache-dtype fp8 \
    --trust-remote-code --moe-backend aiter \
    --tokenizer-mode deepseek_v4 --reasoning-parser deepseek_v4 \
    --compilation-config '{"mode":3,"cudagraph_mode":"FULL_AND_PIECEWISE"}'
```

**DSpark** — add (`num_speculative_tokens=6` was the best-performing value in testing):

```bash
    --speculative-config '{"method":"dspark","num_speculative_tokens":6,"draft_sample_method":"greedy"}'
```

### 2. Benchmark (InferenceX `benchmark_serving.py`)

```bash
# from InferenceX/utils/bench_serving/
python3 benchmark_serving.py \
    --model deepseek-ai/DeepSeek-V4-Pro-DSpark --backend vllm \
    --base-url http://0.0.0.0:8000 \
    --dataset-name random \

    --num-warmups 16 \
    --percentile-metrics 'ttft,tpot,itl,e2el' \
    --save-result --trust-remote-code
```

- `num-prompts = 10 × max-concurrency`, `num-warmups = 2 × max-concurrency` (InferenceX convention).
- **For the DSpark runs, add `--use-chat-template --dsv4`.** Spec-decode acceptance
  degrades on raw random tokens; the DeepSeek-V4 chat encoding is required for meaningful acceptance
  numbers (matches the InferenceX spec-decoding recipes).
- Output-throughput-per-GPU = `output_throughput / tensor_parallel_size`.

### 3. Acceptance metrics

```bash
curl -s http://0.0.0.0:8000/metrics | grep -E 'spec_decode_num_(drafts_total|draft_tokens_total|accepted_tokens_total|accepted_tokens_per_pos_total)'
```

- Mean acceptance length = `1 + accepted_tokens_total / drafts_total`
- Per-position acceptance rate = `accepted_tokens_per_pos_total[i] / drafts_total`

## Note: known limitation

Greedy DSpark occasionally produces intermittent, prompt/run-dependent garbled output (not tied to a
specific `num_speculative_tokens`). Root-causing this is left as a follow-up.

## Caveats

- Validated on **MI350X**; the InferenceX reference recipe targets **MI355X** (same gfx950 family,
  higher clocks/TDP), so absolute throughput may differ. STP vs DSpark were all measured on
  the same hardware and image, so the relative speedups are directly comparable.
- Measured with the pinned nightly image above; the InferenceX recipe pins `vllm/vllm-openai-rocm:v0.22.0`.

+"""DSpark draft model for DeepSeek-V4 on ROCm/AMD (gfx950).
+
+ROCm port of ``nvidia/dspark.py``. Follows the same nvidia->amd recipe used for
+``amd/mtp.py``:
+
+  * import ``DeepseekV4DecoderLayer`` from the AMD ``.model`` (aiter/triton
+    attention + MHC CustomOp path) instead of the nvidia one;
+  * route the MHC head through the ``HCHeadOp`` CustomOp dispatcher (aiter /
+    tilelang / triton / torch) instead of calling the tilelang kernels directly,
+    and gate the trailing ``mhc_post`` on ``use_fused_mhc`` (False on the aiter
+    path, where the decoder layer already applies hc_post in-layer);
+  * drop the mega-MoE weight path (``make_deepseek_v4_expert_params_mapping`` /
+    ``use_mega_moe`` / ``finalize_mega_moe_weights`` do not exist in amd/model.py).
+
+Everything else — the semi-autoregressive drafting hooks, the Markov head, the
+sliding-window context-KV insert, and the checkpoint ``mtp.*`` weight remap — is
+pure torch / Triton and shared with the nvidia implementation unchanged.

+        Mirrors the reference DSparkAttention: each layer derives its context KV
+        from the SAME projected target hidden ``main_x``, via that layer's own

+        layer's context slots.
+
+        ``context_slot_mappings`` is a per-layer list (each entry is the context
+        slot mapping for that layer's kv-cache group, since the hybrid manager may
+        place draft layers in different groups). ``None`` (or a ``None`` entry)

+        for i, layer in enumerate(self.layers):

+            _insert_context_kv(attn, kv, context_positions, slot_mapping)

+    def forward(
+        self,
+        input_ids: torch.Tensor,
+        positions: torch.Tensor,
+        inputs_embeds: torch.Tensor | None = None,
+    ) -> torch.Tensor:
+        if inputs_embeds is None:
+            inputs_embeds = self.embed_input_ids(input_ids)
+        # Expand to hc_mult copies for hyper-connections ([T, H] -> [T, hc, H]).
+        hidden_states = inputs_embeds.unsqueeze(-2).repeat(1, self.hc_mult, 1)
+
+        residual = post_mix = res_mix = None
+        for layer in self.layers:
+            hidden_states, residual, post_mix, res_mix = layer(
+                hidden_states,
+                positions,
+                input_ids,
+                post_mix,
+                res_mix,
+                residual,
+            )
+        # On the fused-MHC path the trailing hc_post must be applied here; on the
+        # aiter unfused path (ROCm default) the decoder layer already applied
+        # hc_post in-layer and returned None mixes, so this is skipped. Mirrors
+        # amd/mtp.py.
+        last_layer = self.layers[-1]
+        if last_layer.use_fused_mhc:
+            hidden_states = last_layer.hc_post(
+                hidden_states, residual, post_mix, res_mix
+            )
+        # hc_head reduces the hc copies; return the PRE-norm head hidden.
+        hidden_states = self.hc_head_op(
+            hidden_states,
+            self.hc_head_fn,
+            self.hc_head_scale,
+            self.hc_head_base,
+            self.rms_norm_eps,
+            self.hc_eps,
+        )
+        return hidden_states

+def _insert_context_kv(
+    attn: nn.Module,
+    kv: torch.Tensor,
+    positions: torch.Tensor,
+    slot_mapping: torch.Tensor,
+) -> None:
+    """RoPE + quant + paged-cache insert of (already kv_norm'd) context KV.
+
+    Reuses the DSV4 fused insert ops (which also process a query; we pass a dummy
+    query and discard it, since context tokens have no query). Mirrors
+    ``DeepseekV4Attention._fused_qnorm_rope_kv_insert``.
+    """
+    swa_cache = attn.swa_cache_layer.kv_cache
+    block_size = attn.swa_cache_layer.block_size
+    cos_sin_cache = attn.rotary_emb.cos_sin_cache
+    cache_dtype = swa_cache.dtype
+    n_ctx = kv.shape[0]
+    dummy_q = torch.zeros(
+        (n_ctx, attn.n_local_heads, attn.head_dim),
+        dtype=kv.dtype,
+        device=kv.device,
+    )
+    if cache_dtype == torch.uint8:
+        # fp8_ds_mla UE8M0 paged layout (the gfx950 aiter SWA cache path).
+        swa_2d = swa_cache.view(swa_cache.shape[0], -1)
+        torch.ops._C.fused_deepseek_v4_qnorm_rope_kv_rope_quant_insert(
+            dummy_q,
+            kv,
+            swa_2d,
+            slot_mapping,
+            positions,
+            cos_sin_cache,
+            attn.padded_heads,
+            attn.eps,
+            block_size,
+        )
+    elif cache_dtype == torch.bfloat16:
+        swa_3d = swa_cache.view(-1, block_size, attn.head_dim)
+        torch.ops._C.fused_deepseek_v4_qnorm_rope_kv_rope_full_cache_bf16_insert(
+            dummy_q,
+            kv,
+            swa_3d,
+            slot_mapping,
+            positions,
+            cos_sin_cache,
+            attn.eps,
