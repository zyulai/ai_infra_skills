## 正文(PRD / 提案全文)

### Motivation.

**I (@algebra-MCX) propose to microbatch the MTP/EAGLE drafter forward under DBO in Model Runner V2, and will lead the design, implementation and validation, subject to maintainer feedback.**

DeepSeek-class deployments usually run DP+EP with MTP speculative decoding. With [#61464](https://github.com/vllm-project/vllm/pull/61464) merged, `--enable-dbo` and speculative decoding can be combined in MRV2, but only the target forward is microbatched. The drafter runs afterwards on the whole batch. For DeepSeek MTP the draft layer is itself an MoE layer, so its dispatch/combine is fully exposed every draft step, with no peer microbatch to overlap with.

### Proposed Change.

**First slice:** CUDA, DP+EP (DeepEP LL or NIXL EP), DeepSeek MTP with one speculative step, uniform decode, eager mode. FULL graphs for the drafter come in a follow-up.

1. **Reuse the target's split.** The drafter consumes the same requests in the same order, so reuse the target step's `UBatchSlices` (request boundaries and token ranges after rejection), rather than computing a new split. Both microbatches stay in the same DP-agreed microbatch count as the target step, so no new DP collective is needed.
2. **Run the draft forward through `UBatchRunner`.** Slice draft inputs (input ids, positions, hidden states from the target) per microbatch, run them in the existing ubatch threads/streams, and merge the outputs before draft sampling. Sampling and draft-token bookkeeping stay full-batch, with single ownership.
3. **Per-microbatch attention metadata.** Build draft metadata per microbatch from the existing slices. This also removes the full-batch rebuild described above in the microbatched path.
4. **Fallback.** If the target step was not microbatched, or a later draft step cannot be split consistently across DP ranks, run the drafter whole, as today.

Out of scope: multi-step tree drafting, EAGLE3 auxiliary hidden-state layouts beyond the existing merge support, and drafter CUDA graphs.

#### Completion criteria

- [ ] DBO off, or spec decode off: code path and outputs unchanged.
- [ ] Unit tests: slice reuse after rejection, per-microbatch draft inputs, merge order, fallback decision consistent across DP ranks.
- [ ] 2×H200 DP2/EP2 and 8-GPU DP/EP with DeepSeek MTP: identical draft tokens and acceptance rate with drafter microbatching on/off; identical final outputs/logprobs with greedy decoding.
- [ ] Trace showing the draft MoE dispatch/combine overlapping the peer microbatch.
- [ ] `vllm bench serve` throughput/TPOT, DBO + MTP with drafter microbatching on/off, plus the share of step time spent in the drafter.
