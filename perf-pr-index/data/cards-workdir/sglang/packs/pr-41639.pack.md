## Motivation

GLM-5.2/5.3 decode on MI355X spends a material part of each step in the MoE layer. The existing runner boundary receives already-materialized top-k IDs and weights, so a model-specific kernel cannot optimize across router projection, top-k, route sorting, expert scheduling, activation quantization, routed experts, and the shared expert.

This PR adds an **explicit, strict, whole-layer Triton Gluon MoE backend** for the audited GLM Quark MXFP4 contract. Its main optimization is not a standalone faster top-k operation: the selected routes directly become the expert schedule, removing the generic `topk_ids -> moe_sorting -> expert GEMM` handoff.

The backend is opt-in and fail-closed. `auto` never selects it, unsupported contracts raise before execution, and a requested Gluon path never silently falls back to AITER or another MoE runner.

## Modifications

### 1. What this adds

- `gluon` as a `MoeRunnerBackend` choice.
- A reusable whole-layer `GluonMoeBackend` interface with model-specific binding, eager weight preparation, execution, and output ABI validation.
- A GLM-5.2/5.3 implementation for serialized Quark W4A4 MXFP4 target experts and the audited BF16 NextN expert layout on gfx950.
- Shape-family kernels for decode, speculative verification, and prefill, including continuous TP4/EP1 and TP8/EP1 coverage through a 32K prefill chunk.
- TP/EP-aware shared-expert handling and reuse of SGLang's existing post-expert collective/finalization path.

Enable the target and speculative paths explicitly:

```bash
--moe-runner-backend gluon \
--speculative-moe-runner-backend gluon
```

### 2. Kernel design

The optimized layer owns this model-specific sequence:

```mermaid
flowchart LR
    subgraph A["Current SGLang + AITER boundary"]
        A0["BF16 hidden states"] --> A1["router GEMM"]
        A1 --> A2["M x 256 logits"]
        A2 --> A3["biased sigmoid top-8"]
        A3 --> A4["dense IDs + weights"]
        A4 --> A5["generic moe_sorting<br/>count, bucket, pad, publish metadata"]
        A5 --> A6["quantize + GEMM1 + activation + GEMM2"]
        A6 --> A7["shared expert + add"]
    end

    subgraph G["GLM Triton Gluon whole-layer path"]
        G0["BF16 hidden states"] --> G1["router projection + input quant work<br/>co-scheduled in one launch grid"]
        G1 --> G2["fixed 256-expert sigmoid top-8"]
        G2 --> G3{"active-token family"}
        G3 -->|"tiny M"| G4["selection/expert CTAs share a launch;<br/>expert CTAs recompute the needed route rank"]
        G3 -->|"medium M"| G5["selection directly emits expert tickets,<br/>sorted routes, and job descriptors"]
        G3 -->|"large M"| G6["chunk histogram + prefix/scatter<br/>and bucketed grouped projections"]
        G4 --> G7["MXFP4 experts + shared expert"]
        G5 --> G7
        G6 --> G7
    end
```

Important details:

- **Tiny M:** the router uses split-K CDNA4 MFMA work to expose enough CTAs on MI355X. Selection is compile-time specialized for 256 experts/top-8. The up-projection launch consumes the selected route directly instead of waiting for a generic sort.
- **Medium M:** top-k appends routes directly to expert buckets and publishes the descriptors consumed by the expert projection.
- **Large M:** chunked counting, prefix/scatter, and bucketed projections cover prefill shapes. The 32K family splits large routed-partial/code buffers so every gfx950 buffer address remains below the 4-GiB window.
- **Quantization:** router projection and activation quantization are independent CTAs in the same launch grid; this removes a host launch and lets both work classes occupy the device together. They are not incorrectly described as a single CTA reading the input once.
- **Shared expert:** TP/EP1 target execution consumes SGLang's normal appended shared-expert representation (257 experts). EP and NextN keep the native shared expert and add it before SGLang's existing collective.

The isolated measurements below show that standalone top-k is approximately tied with AITER. The useful difference is the producer/consumer boundary:

```text
AITER: router -> top-k metadata -> generic MoE sort -> expert work
Gluon: router/quant -> top-k becomes the expert schedule -> expert work
```

### 3. SGLang integration, isolation, and support matrix

The integration sits above `MoeRunnerCore`, because that interface starts after routing has already been computed. The runtime flow is:

```text
explicit Gluon selection
  -> validate quant/model/runtime contract
  -> bind GLM backend
  -> prepare packed weights after checkpoint load and before CUDA graph capture
  -> dispatch by TP/EP, target/NextN, and active M
  -> validate rank-local output tensor ABI
  -> existing SGLang _finalize_normal_output / post_experts_all_reduce
```

Isolation from other paths:

- `auto` never selects Gluon; AITER, Triton, FlashInfer, MegaMoE, DeepEP, CPU, and other models retain their existing behavior.
- GLM modules and Gluon kernels are imported lazily only after explicit selection.
- Binding validates `model_type`, hidden/intermediate dimensions, 256 routed experts, sigmoid normalized top-8, quant ABI, gfx950, TP/EP-local shapes, shared-expert state, stream mode, A2A, EPLB, MoE DP, and routed scaling.
- Quark layout preparation is owned by the selected backend; Gluon does not construct a dummy AITER runner.
- Unsupported M/topology/model/quant combinations raise an actionable error. There is no native/AITER fallback from the Gluon backend.

Current model scope:

- GLM-5.2/5.3 `glm_moe_dsa` target with serialized Quark W4A4 MXFP4 experts.
- GLM NextN/EAGLE draft with the exact audited BF16 expert ABI.

This is intentionally not a generic Gluon MoE claim. Future fixed-topology MoEs can reuse the backend boundary, but each model still needs its own strict validator, weight-layout adapter, routing semantics, kernel family, correctness comparison, and performance evidence. The most direct next extension is another GLM-family Quark MXFP4 shape; unrelated models should not be enabled by relaxing the current checks.

+@gluon.jit
+def _add(a, b):

+@gluon.jit
+def _encode_groups(x, shared):
+    peak = gl.max(gl.abs(x), 1)
+    divided = gl.div_rn(peak, 6.0)
+    bits = divided.to(gl.uint32, bitcast=True)
+    exponent = (bits >> 23 & 255).to(gl.int32) - 127 + (bits & 8388607 != 0)
+    peak_bits = peak.to(gl.uint32, bitcast=True)
+    floor_exp = (peak_bits >> 23 & 255).to(gl.int32) - 127
+    threshold = gl.exp2(floor_exp.to(gl.float32)) * 1.75
+    even_exp = floor_exp - 2 + (peak >= threshold).to(gl.int32)
+    exponent = gl.where(shared, even_exp, exponent)
+    exponent = gl.maximum(-127, gl.minimum(127, exponent))
+    scale = gl.exp2(exponent.to(gl.float32))
+    inverse_scale = gl.div_rn(1.0, scale)
+    a = gl.abs(x * inverse_scale[:, None])
+    low, high = gl.split(a.reshape((x.shape[0], 16, 2)))
+    packed = gl.inline_asm_elementwise('v_cvt_scalef32_pk_fp4_f32 $0, $1, $2, $3;', constraints='=v,v,v,v', args=[low, high, gl.full(low.shape, 1.0, gl.float32, low.type.layout)], dtype=gl.uint32, is_pure=True, pack=1)

+    low_sign, high_sign = gl.split(signs.reshape((x.shape[0], 16, 2)))
+    return (packed.to(gl.uint8) & 119 | low_sign | high_sign << 4, (exponent + 127).to(gl.uint8))

+@gluon.jit
+def _select_routes(L, Bias, Ids, Counts, expert_start, SHARDS: gl.constexpr, TICKET_STRIDE: gl.constexpr, LOCAL_EXPERTS: gl.constexpr, SCALE: gl.constexpr):
+    layout: gl.constexpr = gl.BlockedLayout([1], [64], [1], [0])
+    m = gl.program_id(0)
+    e = gl.arange(0, 256, layout)
+    prob = 1.0 / (1.0 + gl.exp(-gl.load(L + m * 256 + e).to(gl.float32)))
+    score = prob + gl.load(Bias + e).to(gl.float32)
+    available = gl.full((256,), True, gl.int1, layout)
+    selected_prob = gl.full((256,), 0.0, gl.float32, layout)
+    selected_id = gl.full((256,), 0, gl.int32, layout)
+    total = 0.0
+    for j in gl.static_range(8):
+        maximum = gl.max(score, 0)
+        priority = gl.where(available, e + gl.where(score == maximum, 0, 256), 512)
+        idx = gl.min(priority, 0) % 256
+        p = gl.sum(gl.gather(prob, gl.full((1,), idx, gl.int32, layout), 0), 0)
+        total += p
+        selected_prob = gl.where(e == j, p, selected_prob)
+        selected_id = gl.where(e == j, idx, selected_id)
+        available &= e != idx
+        score = gl.where(e == idx, -float('inf'), score)
+    owned = (selected_id >= expert_start) & (selected_id < expert_start + LOCAL_EXPERTS)
+    ticket = gl.atomic_add(Counts + m // 64 % SHARDS * 256 + selected_id, 1, (e < 8) & owned, sem='relaxed')
+    weight = gl.where(owned, selected_prob / total * SCALE, 0.0)
+    record = (selected_id * TICKET_STRIDE + ticket).to(gl.uint64)
+    record |= weight.to(gl.uint32, bitcast=True).to(gl.uint64) << 32
+    gl.store(Ids + m * 8 + e, record, e < 8)

+@gluon.jit
+def _write_height_descriptors(UpInfo, e, experts, counts, offset, count, M: gl.constexpr, BM: gl.constexpr):
+    layout: gl.constexpr = gl.BlockedLayout([1], [64], [1], [0])
+    b = gl.arange(0, _artifact_next_power_of_2(triton.cdiv(M, BM)), layout)
+    live = gl.minimum(BM, count - b * BM)
+    remainder = counts % BM
+    destination = gl.full(b.shape, 0, gl.int32, layout)
+    for level in gl.static_range(3 + (BM == 128)):
+        height = gl.constexpr(BM >> level)
+        lower = gl.constexpr(0 if height == 16 else height // 2)
+        same = ((remainder > lower) & (remainder <= height)).to(gl.int32)
+        if height == BM:
+            same += counts // BM
+            before = gl.sum(gl.where(experts < e, same, 0), 0)
+            local = b
+        else:
+            higher = counts // BM + (remainder > height).to(gl.int32)
+            shared_higher = gl.constexpr(M // BM + (M % BM > height))
+            before = gl.sum(higher, 0) + shared_higher + gl.sum(gl.where(experts < e, same, 0), 0)
+            local = gl.full(b.shape, 0, gl.int32, layout)
+        destination = gl.where((live > lower) & (live <= height), before + local, destination)
+    descriptor = e | live << 9 | offset + b << 17
+    gl.store(UpInfo + destination, descriptor, b < gl.cdiv(count, BM))

+@gluon.jit
+def _sum_shard_counts(Counts, SHARDS: gl.constexpr, before=0, WITH_PREFIX: gl.constexpr=False):
+    layout: gl.constexpr = gl.BlockedLayout([1, 1], [1, 64], [1, 1], [1, 0])
+    shard = gl.arange(0, SHARDS, gl.SliceLayout(1, layout))
+    expert = gl.arange(0, 256, gl.SliceLayout(0, layout))
+    partial = gl.load(Counts + shard[:, None] * 256 + expert[None, :])
+    native: gl.constexpr = gl.BlockedLayout([1], [64], [1], [0])
+    totals = gl.convert_layout(gl.sum(partial, 0), native)
+    if WITH_PREFIX:
+        prefix = gl.sum(gl.where(shard[:, None] < before, partial, 0), 0)
+        return (totals, gl.convert_layout(prefix, native))
+    else:
+        return totals

+@gluon.jit
+def _write_down_tiles(Jobs, e, experts, counts, offset, count, arena_start, M: gl.constexpr, BM: gl.constexpr, WIDE: gl.constexpr=32):

+    layout: gl.constexpr = gl.BlockedLayout([1], [64], [1], [0])

+    sizes = counts // BM * 2 + gl.where(remainder > WIDE, 2, (remainder > 0).to(gl.int32))

+    dense_start = gl.sum(gl.where(experts < e, counts, 0), 0)
+    descriptor = (e | live << 9 | offset + b << 17).to(gl.uint64)
+    descriptor |= (dense_start + b * BM).to(gl.uint64) << 32
+    descriptor |= (arena_start + b * BM).to(gl.uint64) << 48
+    gl.store(Jobs + start + b * 2, descriptor, b < gl.cdiv(count, BM))
+    gl.store(Jobs + start + b * 2 + 1, descriptor | 1 << 29, (b < gl.cdiv(count, BM)) & (live > WIDE))

+@gluon.jit
+def _prepare_tickets(Codes, Counts, Sorted, UpInfo, Jobs, M: gl.constexpr, CHUNKS: gl.constexpr, BM: gl.constexpr, ROUTED_BLOCKS: gl.constexpr, SCHEDULED: gl.constexpr, DOWN_SCHEDULED: gl.constexpr, WIDE: gl.constexpr=32, SHARDS: gl.constexpr=8, TICKET_STRIDE: gl.constexpr=1024, SKIP_SHARED_DOWN: gl.constexpr=False):
+    pid = gl.program_id(0)
+    if pid < CHUNKS:
+        chunk = pid
+        layout: gl.constexpr = gl.BlockedLayout([1], [64], [1], [0])
+        lane = gl.arange(0, 256, layout)
+        route = chunk * 256 + lane
+        ticket_record = gl.load(Codes + route, route < M * 8, 0).to(gl.uint64)
+        code = ticket_record.to(gl.int32)
+        expert, ticket = (code // TICKET_STRIDE, code % TICKET_STRIDE)
+        counts, prefix_counts = _sum_shard_counts(Counts, SHARDS, chunk // 2 % SHARDS, True)
+        tiles = gl.cdiv(counts, BM)
+        dense_offsets = gl.associative_scan(counts, 0, _add) - counts
+        dense = gl.gather(dense_offsets, expert, 0)
+        offsets = (gl.associative_scan(tiles, 0, _add) - tiles) * BM
+        offset = gl.gather(offsets, expert, 0)
+        prefix = gl.gather(prefix_counts, expert, 0)
+        active = (route < M * 8) & ((ticket_record >> 32).to(gl.uint32) != 0)
+        gl.store(Sorted + offset + prefix + ticket, route, active)
+        record = (dense + prefix + ticket).to(gl.uint64)
+        record |= ticket_record & 18446744069414584320
+        gl.store(Codes + route, gl.where(active, record, 0), route < M * 8)
+    else:
+        e = pid - CHUNKS
+        layout: gl.constexpr = gl.BlockedLayout([1], [64], [1], [0])
+        experts = gl.arange(0, 256, layout)
+        counts = _sum_shard_counts(Counts, SHARDS)
+        tiles = gl.cdiv(counts, BM)
+        if e == 257:
+            active = gl.sum(tiles, 0)
+            hole = gl.arange(0, _artifact_next_power_of_2(SCHEDULED), layout)
+            gl.store(UpInfo + hole, 0, (hole >= active + triton.cdiv(M, BM)) & (hole < SCHEDULED))
+            remainder = counts % BM
+            sizes = counts // BM * 2 + gl.where(remainder > WIDE, 2, (remainder > 0).to(gl.int32))
+            shared_tiles: gl.constexpr = M // BM * 2 + (2 if M % BM > WIDE else 1 if M % BM > 0 else 0)
+            active_tiles = gl.sum(sizes, 0)
+            if not SKIP_SHARED_DOWN:
+                active_tiles += shared_tiles
+            holes = gl.arange(0, _artifact_next_power_of_2(DOWN_SCHEDULED), layout)
+            gl.store(Jobs + holes, 0, (holes >= active_tiles) & (holes < DOWN_SCHEDULED))
+        else:
+            if e < 256:
+                offset = gl.sum(gl.where(experts < e, tiles, 0), 0)
+                count = gl.sum(gl.where(experts == e, counts, 0), 0)
+            else:
+                offset = ROUTED_BLOCKS
+                count = M
+            _write_height_descriptors(UpInfo, e, experts, counts, offset, count, M, BM)
+            remainder = counts % BM
+            tail = gl.where(remainder > 64, 128, gl.where(remainder > 32, 64, gl.where(remainder > 16, 32, gl.where(remainder > 0, 16, 0))))
+            arena_sizes = counts // BM * BM + tail
+            arena_start = gl.sum(gl.where(experts < e, arena_sizes, 0), 0)
+            if (not SKIP_SHARED_DOWN) | (e < 256):
+                _write_down_tiles(Jobs, e, experts, counts, offset, count, arena_start, M, BM, WIDE)
+            b = gl.arange(0, _artifact_next_power_of_2(triton.cdiv(M, BM)), layout)
+            gl.store(Sorted + ROUTED_BLOCKS * BM + offset + b, arena_start + b * BM, b < gl.cdiv(count, BM))
