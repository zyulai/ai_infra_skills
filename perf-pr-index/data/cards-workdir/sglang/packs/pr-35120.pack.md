## Motivation

@humansand

Add an opt-in W4A16 compute mode for FlashInfer CuTe DSL NVFP4 MoE and dense linear layers: weights remain NVFP4 while activations and outputs stay BF16. Registered tests cover online-quantized Nemotron MoE accuracy, serialized ModelOpt Qwen3 dense+MoE disk-reload invariance, and the existing dense W4A4 numerical path.

Dependency:

- This PR requires the final [FlashInfer v0.6.18](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.6.18) release (`69ff11fc4954396d98326656dc85debd2223f637`), which contains the CuTe DSL NVFP4 MoE W4A16, SiTU, workspace-lifetime, and SM100/SM103 dense W4A16 APIs used here.
- SGLang `main` pins FlashInfer 0.6.18 through merged [#36954](https://github.com/sgl-project/sglang/pull/36954). This integration intentionally has no compatibility fallback for earlier FlashInfer APIs.

## Modifications

- Add `SGLANG_FLASHINFER_CUTEDSL_NVFP4_W4A16` (default `false`).
- Refresh the existing CuTe DSL prefill-dispatch unit fixture after the main merge by declaring its intended `quant_mode="w4a4"`; this follow-up changes no runtime code.
- Select `CuteDslMoEWrapper(quant_mode="w4a16")`, pass raw BF16 activations, and omit GEMM1/GEMM2 activation scales.
- Reuse the existing packed NVFP4 weights and CuTe MMA-layout block scales, but construct weight-only decode alphas for both online-quantized and serialized ModelOpt weights.
- Keep serialized ModelOpt NVFP4 dense layers in the existing `ModelOptFp4LinearMethod`. When the environment variable and `--fp4-gemm-backend flashinfer_cutedsl` are both selected, its registered `fp4_gemm` compiler boundary dispatches to FlashInfer `mm_bf16_fp4`; otherwise the existing W4A4 `mm_fp4` route is unchanged.
- Prepare dense W4A16 weights through `prepare_bf16_fp4_weights`, preserve loader-owned source scales for disk reload, and keep stable prepared scale/alpha bindings for decode CUDA graphs. Reuse the existing NVFP4_AWQ pre-scale operation before BF16 GEMM.
- Recognize prepared W4A16 state in the generic quantized LM-head guard, and keep DeepSeek's W4A4-only GEMM+SwiGLU fusion disabled for W4A16.
- Support the standard CuTe DSL v2 paths with no A2A or FlashInfer A2A on SM100-family GPUs (SM100/SM103). Keep FlashInfer A2A dispatch in BF16 by suppressing automatic NVFP4 dispatch and rejecting an explicit NVFP4-dispatch configuration; the existing DeepEP masked path remains W4A4-only. The registered reload test covers no A2A, while the online accuracy test covers FlashInfer A2A, and the serving benchmark compares no A2A with FlashInfer A2A.
- Preserve the configured finalize mode for ReLU2. For W4A16, honor `SGLANG_FLASHINFER_MOE_FUSED_FINALIZE`; registered tests cover both fused and two-stage finalization.
- Register nightly `4-gpu-b200` end-to-end coverage for `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-FP8` with online NVFP4 expert-weight quantization.
- Add a separate registered TP4/DP4/EP4 case with DP attention and no A2A for serialized `nvidia/Qwen3-30B-A3B-NVFP4`: dense and MoE layers use W4A16, and two same-checkpoint disk reloads across weight/CUDA-graph release and resume must preserve deterministic decode text and token IDs exactly, with token logprobs within `1e-4`. This remains alongside the existing per-token NVFP4 CuTe DSL case.
