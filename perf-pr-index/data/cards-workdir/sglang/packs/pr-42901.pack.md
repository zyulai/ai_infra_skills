## PR body
```markdown
## Motivation

- DeepSeek-V4.1 has an option called decoder bounded replay (`--enable-decoder-swa-bounded-replay`). When it is on, the last layers of the model only process the last 128 prompt tokens of each request during prefill.
- Today this starts at layer 21. Layer 20 still processes every prompt token.
- Layer 20 does two things. It writes the compressed KV cache that decoding reads later, and that needs every token. It also runs its own indexer, attention and MoE to produce its output, and layer 21 only reads the last 128 tokens of that output.
- So the indexer, attention and MoE work of layer 20 on all the earlier tokens is thrown away. The indexer of layer 20 scans the whole context, so this wasted work grows with the prompt length.

## Modifications

- When decoder bounded replay is on, layer 20 now writes its compressed KV cache for every token first, and then runs the rest of the layer on the last 128 tokens only.
- The compressed KV cache that layer 20 writes is the same as before.
- Layer 20 now writes its indexer results directly for the last 128 tokens. The code that copied those rows out of the full-size buffers is no longer needed, so this PR removes it.
- No flag is added. Nothing changes when decoder bounded replay is off.
- ROCm keeps the old behavior, because its fused layer path runs all of layer 20 in one call.
- This also works with the prefill CUDA graph that #43736 added for decoder bounded replay. Inside the graph, the step that prepares the layer 20 inputs now computes only the part the caller asked for. Before, it always computed the indexer inputs too, and the new full-prompt KV write does not have them.

One behavior change to review:

- For the last 128 tokens, layer 20 now uses the same shortened sliding window as layers 21 to 39. Before this PR, layer 20 saw the full window.
- This matches how the DeepSeek-V4.1 report describes decoder replay: "feed their encoder outputs through the decoder layers under the same SWA truncation".
