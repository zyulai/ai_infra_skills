## Motivation

Optional speculative-decoding providers need one narrow, model-neutral boundary. Provider discovery should happen once, graph-facing call sites should invoke an always-present strategy, and provider absence or decline must preserve SGLang's stock RNG, collective, verification, and state-lifetime behavior.

This PR contains only provider contracts, binding, and stock-or-provider facades. It is based directly on `main` and does not depend on the companion runtime-optimization PR. The two PRs can build, test, and land independently.

**Switch inventory:** this standalone binding tree retains the **27** master-following Boolean child switches already in its `main` base and declares no new child switch. It adds only `SGLANG_NVIDIA_MEGAKERNEL_SLOTS`, an independent tuple selector rather than a child of `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION`. When composed with #47200, `SGLANG_TRTL3_EP_DEFER_FINALIZE` from R7 is the 28th master-following child, so the combined stack has **28**.

## Modifications

### B1a — Define speculative provider contracts

- **What:** Add frozen, structured `VocabShardView`, `ShardedLogitsView`, verification/sampling/watermark views, `PostVerifyIO`, `PostVerifyOutput`, `PostVerifyStrategy`, `SpeculativeRuntimeHooks`, and `HooksFactory` contracts. The optional factory is published by `BuiltMegakernel`. Contract tests freeze field names, exact types, key encoding, shapes, splits, logits write-back semantics, and strategy forwarding.
- **Why:** Give providers a stable ABI while keeping the replaceable seam limited to rank-local `local_keys` production. SGLang continues to own reduction, collectives, gather/write-back, acceptance, forced acceptance, sampling policy, and state updates.
- **Switch:** None. This commit declares types and an optional protocol member only.
- **Fallback:** It changes no call site or runtime behavior. Older providers remain valid because the factory is optional and discovered with `getattr`.

### B1b — Bind speculative provider factories

- **What:** Add `bind_speculative_runtime_hooks`, `default_local_keys`, `default_post_verify`, environment registration, and focused binder/default tests. The provider factory receives SGLang's complete stock defaults and may replace only local-key construction; it cannot replace the verifier runner.
- **Why:** Resolve optional capability once at the NVIDIA binding boundary instead of branching on provider presence in every round or captured path.
- **Switch:** `SGLANG_ENABLE_NV_MEGA_RUNTIME_OPTIMIZATION`. An explicit off value takes precedence and returns the caller's stock bundle by identity without inspecting a provider. `SGLANG_NVIDIA_MEGAKERNEL_SLOTS` selects plugin entries independently and is not a master-following Boolean child.
- **Fallback:** A missing built provider or factory returns stock defaults. Unsupported local-key requests return `None` before provider RNG is consumed and use the gathered stock verifier. The default local-key implementation remains deterministic for greedy requests, including requests that carry seeds, and declines non-greedy temperature sampling. Provider availability must agree across ranks.

### B1c — Bind an always-present DSpark draft strategy

- **What:** Resolve a stock or specialized DSpark proposal strategy once and call the same facade for every batch. Cross-rank agreement determines the batch sizes served by a provider.
- **Why:** Remove provider-presence branches from the sampler while keeping graph-facing dispatch stable.
- **Switch:** No new switch. Existing `--enable-nvidia-megakernel` construction determines whether a provider can be offered.
- **Fallback:** No provider, no factory, or an unsupported batch size invokes the unchanged stock Markov block. The greedy stock path avoids unnecessary step-logit allocation.

### B1d — Route EAGLE draft entries through a stock facade

- **What:** Add `EagleDraftRuntime` and route draft-loop, draft-extend, round-start, token-extension, and proposal selection through an unconditional facade in workers and graph runners.
- **Why:** Centralize optional entry selection before graph capture and remove repeated provider-presence checks from EAGLE call sites.
- **Switch:** No new switch. Existing `--enable-nvidia-megakernel` construction controls whether specialized entries are available.
- **Fallback:** With the flag off, no offered entry, or an unserved captured batch, the facade calls the original SGLang callbacks and preserves `main` clone semantics. An offered-but-incompatible setup is rejected during binding, and rank disagreement raises on every rank instead of permitting divergent execution.

### Notes for reviewers

- **`speculative_runtime_hooks` is read as a declared member** (commit `faca41e854`, +8/−11 production, +1 test). SGLang already rejects any plugin whose `MEGAKERNEL_API_VERSION` differs, so the plugin and SGLang move together; like `draft_sampler` and `graph_variants`, every built object must define the member (`None` when it offers no factory). The matching plugin change declares it on all built classes (sgl-project/sgl-nvidia-mega#33, `72f0cd25`); that plugin commit should land together with or before this PR. Per-commit CPU tests: no new failures.
- **`id(runner)` in `EagleMegakernel`.** The draft and draft-extend graph caches key on `id(runner)`, as on `main`. The key is used only inside SGLang to find the graphs a runner captured; the runner object itself is never passed to the plugin. Providers receive only the buffers and batch sizes documented in `spec.py`.
- **`SGLANG_NVIDIA_MEGAKERNEL_SLOTS` is not a child of the runtime master switch.** SGLang only registers and documents the variable; the plugin reads it to choose which of its kernels to build under `--enable-nvidia-megakernel`. That choice is independent of SGLang's runtime optimizations: a deployment can run plugin kernels with the master switch off, and turning the master switch off should not silently change the kernel selection. Making it a Boolean child would also not fit its type, since it is a tuple of slot names whose empty value already means "stock paths".
