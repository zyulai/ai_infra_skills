## Overview

`silu_and_mul_per_block_quant` launches one 128-thread block per (token, group). Each thread issues one 2-byte load, and the group max is a shared-memory tree reduction. At prefill sizes the kernel runs at ~0.9 TB/s on H200. It is therefore 1.3-2.2x *slower* than the unfused `silu_and_mul` + `per_token_group_quant_fp8` pair it replaces.

This PR adds a vectorized variant (16B loads, warp-shuffle reduction, 8B stores) for large inputs. The existing kernel stays for small inputs, where it has lower latency. Both produce bitwise-identical results.

## Claims

- At >= 16k rows the fused kernel is 2.0-2.45x faster than before, and now 8-53% faster than the unfused pair. At <= 64 rows (decode) it is unchanged. See the table below.
- Paths that use the fused kernel today get faster prefill:
  - the Triton FP8 MoE with `VLLM_USE_DEEP_GEMM_E8M0=0`;
  - the `SiluMul+BlockQuant` compile fusion, where it matches.
- Prerequisite for #65794, which enables the fused path by default (superseding #64906 and #43399). With the old kernel, that change costs -3.8% prefill on Qwen3-30B-A3B-FP8.

## Details

**Mapping:** each group is handled by `group_size / 8` lanes (16 for group 128), each owning 8 contiguous elements of gate and up. The max is reduced with `__shfl_xor_sync` over those lanes, and lane 0 writes the scale.

**Dispatch:** the vectorized kernel is used for 16-bit inputs with 16B-aligned input and 8B-aligned output, when `num_tokens * num_groups >= 3072`. The threshold is measured: at <= 2048 groups the one-block-per-group kernel is ~0.4-0.9 µs faster, and above ~3072 groups the vectorized one wins. Misaligned views fall back to the existing kernel.

**Arithmetic:** identical to the existing kernel (`gate * (1 / (1 + exp(-gate))) * up`, `max(amax / qmax, min_scale)`, `x / scale`). The file is not built with `--use_fast_math`.

**Overlaps:**
- #62386 edits the same file (TMA-aligned scale stride). The changes are orthogonal, but whichever lands second needs a rebase.
- #43399 (UE8M0 option) also touches this kernel; the vectorized variant takes the same template flags if both land.

**Duplicate check:** no open PR changes this kernel's performance.
