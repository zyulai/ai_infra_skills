## PR body
```markdown
## Motivation

KDA MTP verify on the FlashInfer path (`recurrent_kda`, SM100) is two-phase today: the verify kernel writes every draft token's post-state into the speculative `intermediate_ssm` scratch, then `commit_mamba_states_after_verify` scatters the accepted checkpoint back into the persistent pool (`temporal`) across **all** KDA layers, and the next verify re-reads the committed state as its seed. The scatter is a full recurrent-state write per request per round — `num_kda_layers × HV × V × K × 4B` (≈4 MB per layer per request at HV=16, K=V=128 fp32) — plus one kernel launch and its host dispatch, all sitting in the bs=1 MTP inter-phase seam.

FlashInfer's `recurrent_kda` already ships the missing half: a `num_accepted_tokens` parameter ("fused speculative decode") that makes the kernel seed itself from `ssm_state_indices[n, nat - 1]` — the checkpoint after the last accepted token of the previous round — instead of slot 0. sglang never passes it. With it, the SSM commit scatter can be skipped entirely: the accepted state is consumed where it already lives.

## Modifications

One commit, gated by `SGLANG_OPT_KDA_FUSED_ACCEPT_STATE` (env, default off — zero change to any default path):

- **Slot-indexed scratch rows.** In fused mode the verify's `[N, T]` state indices are built from the requests' mamba slots (stable for the request lifetime) instead of batch positions, so last round's checkpoints stay addressable across batch membership changes. Padded CUDA-graph rows carry slot `-1`; every derived index stays negative, which `recurrent_kda` natively treats as inactive — no extra padding plumbing.
- **Seeding moves out of the per-verify path.** The per-round committed-pool → scratch slot-0 copy is gone. Fresh requests are staged once at extend time (committed state → `scratch[slot, 0]`, accept length 1); continuing requests seed in-kernel from `slot[nat - 1]`, with `nat` gathered from a persistent per-slot `accept_lens_pool` — all device-side ops, CUDA-graph capture safe.
- **Commit shrinks to conv + bookkeeping.** `commit_mamba_states_after_verify` keeps only the conv-window rollback (FlashInfer does not own the conv path) plus a tiny scatter recording this round's accept lengths for the next verify's seed selection. The all-layer SSM state scatter disappears.
- **Fail-loud startup gates.** The env requires the FlashInfer KDA decode backend, `--disable-radix-cache` (the committed SSM pool goes stale between verifies; nothing may read it mid-stream), and is mutually exclusive with `--enable-linear-replayssm-spec` (both mechanisms own the verify-round SSM state commitment).

Bit-exactness by construction: the in-kernel seed value is byte-identical to what the scatter used to commit and the next round re-read (same tensor dtype, pure copy round-trip), so outputs cannot change.

Relationship to Kimi-K3: the K3 DSpark verify kernel follows the same read-only-persistent-state contract and still commits via the scatter; extending fused-accept to that path (separate seed-index tensor in the kernel) is planned follow-up and does not affect this PR.

## Accuracy Tests

- **Unit tests** `test/registered/attention/unittests/hybrid_linear/test_kda_fused_accept_indices.py` (6 cases). `TestBuildFusedAcceptIndices` pins the padding-negativity invariant of the slot-index arithmetic (a padded slot must yield only negative indices for every step — an arithmetic reorder would silently activate padded rows) and the `accept_lens_pool` gather semantics. `TestFusedAcceptPerForwardCache` guards the per-forward build: what the layers share must equal what each would have built, a different batch must produce different rows, and a fresh `ForwardMetadata` must arrive uncached — a cache outliving its forward would seed the next batch from the *previous* batch's mamba slots, which is a silent wrong-state bug with no shape or index error to catch it.
- **GPU parity, SM100** (B200, FlashInfer 0.6.14, real `recurrent_kda`). Two-round legacy-vs-fused (legacy seed-copy + manual commit vs fused staging + `nat` seeding, with deliberately offset slots so slot-indexed rows differ from batch positions): `torch.equal` — not `allclose` — on both rounds' outputs, on the final accepted states, and on the committed pool being untouched by fused. **PASS at B=1/8/32 and T=4/6.** The hoist has its own case: 20 layers sharing one index build vs 20 layers each building their own, bit-identical at B=1 and B=8, so an aliased or stale shared tensor surfaces as a value difference rather than an error.

## Speed Tests and Profiling

A/B of the changed path on SM100 (B200, FlashInfer 0.6.14), Kimi-Linear-48B shapes: 20 KDA layers, HV=32, K=V=128, draft window T=4, bf16 state. The 20 per-layer verify calls are captured in a CUDA graph and timed by replay — the mode the real verify path runs in — while the post-verify commit is timed eagerly because it runs after the forward. Min of 5 x 100 iterations.

|---|---|---|---|
| 1 | 393.4 us | 218.5 us | **175.0 us (44.5%)** |

The SSM commit scatter this replaces measures 18.3 / 30.9 / 110.8 us at B=1/4/16, against a flat ~5 us accept-length write.

+``step < scratch_steps`` — an arithmetic reorder (e.g. adding the step before
+the multiply) would silently activate padded rows and corrupt neighbor state.
+The nat gather must clamp padded slots in-bounds (their value is never
+consumed) and keep real slots' accept lengths intact.
+
+CPU tensors only — the invariants are pure index arithmetic.
+"""
+
+import unittest

+import torch

+from sglang.srt.layers.attention.linear.kernels.kda_flashinfer import (
+    build_fused_accept_indices,

+class TestBuildFusedAcceptIndices(CustomTestCase):
+    def test_real_slots_address_their_scratch_rows(self):
+        for scratch_steps, draft_token_num in ((4, 4), (8, 4), (33, 33)):
+            slots = torch.tensor([0, 3, 7], dtype=torch.int32)
+            pool = torch.arange(10, dtype=torch.int32) + 1  # accept len = slot + 1
+            indices, nat = build_fused_accept_indices(
+                slots=slots,
+                scratch_steps=scratch_steps,
+                draft_token_num=draft_token_num,
+                accept_lens_pool=pool,
+            )
+            self.assertEqual(indices.shape, (3, draft_token_num))
+            self.assertEqual(indices.dtype, torch.int32)
+            step = torch.arange(draft_token_num, dtype=torch.int32)
+            expected = slots[:, None] * scratch_steps + step[None, :]
+            self.assertTrue(torch.equal(indices, expected))
+            self.assertEqual(nat.dtype, torch.int32)
+            self.assertTrue(torch.equal(nat, slots + 1))
+
+    def test_padded_slot_rows_stay_fully_negative(self):
+        # T == scratch_steps is the tight case: the largest step must still
+        # land below zero for slot -1.
+        for scratch_steps, draft_token_num in ((4, 4), (8, 8), (8, 4), (33, 33)):
+            slots = torch.tensor([2, -1, 5, -1], dtype=torch.int32)
+            pool = torch.full((8,), 3, dtype=torch.int32)
+            indices, nat = build_fused_accept_indices(
+                slots=slots,
+                scratch_steps=scratch_steps,
+                draft_token_num=draft_token_num,
+                accept_lens_pool=pool,
+            )
+            padded_rows = indices[slots < 0]
+            self.assertTrue(

+                f"padded row leaked a non-negative index "
+                f"({scratch_steps=}, {draft_token_num=}): {padded_rows.tolist()}",
+            )
+            real_rows = indices[slots >= 0]
+            self.assertTrue((real_rows >= 0).all())
+            # nat gather clamps padded slots in-bounds (value unused).
+            self.assertEqual(nat.shape[0], 4)

+        pool = torch.tensor([9, 2, 9, 9, 5, 9], dtype=torch.int32)
+        _, nat = build_fused_accept_indices(
+            slots=slots,
+            scratch_steps=4,
+            draft_token_num=4,

+        self.assertEqual(nat[0].item(), 2)
+        self.assertEqual(nat[1].item(), 5)
+        # Padded row clamps to pool row 0; the value is never consumed but the
+        # gather itself must stay in-bounds.
+        self.assertEqual(nat[2].item(), 9)

+class TestFusedAcceptPerForwardCache(CustomTestCase):
+    """The verify indices are built once per forward and shared by every KDA
+    layer. That sharing is only sound while the cache dies with the forward: a
+    cache that outlived it would seed the next batch from the previous batch's
+    mamba slots, which is a silent wrong-state bug (no shape or index error).
+    """
+
+    @staticmethod
+    def _build(slots, pool_values, draft_token_num=4, scratch_steps=4):
+        device = "cuda" if torch.cuda.is_available() else "cpu"
+        return build_fused_accept_indices(
+            slots=torch.tensor(slots, dtype=torch.int32, device=device),
+            scratch_steps=scratch_steps,
+            draft_token_num=draft_token_num,
+            accept_lens_pool=torch.tensor(
+                pool_values, dtype=torch.int32, device=device
+            ),
+        )
+
+    def test_shared_build_matches_a_per_layer_build(self):
+        """What every layer reuses must equal what it would have built itself."""
+        pool = [1] * 8
+        pool[3], pool[5] = 2, 4
+        first_idx, first_nat = self._build([3, 5], pool)
+        second_idx, second_nat = self._build([3, 5], pool)
+        self.assertTrue(torch.equal(first_idx, second_idx))
+        self.assertTrue(torch.equal(first_nat, second_nat))
+
+    def test_a_different_batch_builds_different_rows(self):
+        """Guards the staleness mode: reusing a previous forward's tensor would
+        address the previous forward's slots, and the values must differ so the
+        cache-reset is observable rather than accidentally correct."""
+        pool = [1] * 8
+        pool[3], pool[5], pool[6] = 2, 4, 3
+        idx_a, nat_a = self._build([3, 5], pool)
+        idx_b, nat_b = self._build([6, 5], pool)
+        self.assertFalse(torch.equal(idx_a, idx_b))
+        self.assertFalse(torch.equal(nat_a, nat_b))
+
+    def test_metadata_starts_uncached(self):
+        """A forward's metadata must arrive with no indices carried over: the
+        backend keys 'build once' on these being None."""

+
+        metadata = ForwardMetadata(
+            query_start_loc=torch.zeros(2, dtype=torch.int32),
+            mamba_cache_indices=torch.zeros(1, dtype=torch.int32),

+        self.assertIsNone(metadata.fused_accept_state_indices)
+        self.assertIsNone(metadata.fused_accept_num_accepted)
