## Motivation
This is similar to Issue#15680 
We observed severe model output corruption (as shown in the attached screenshot) when running inference with EPLB enabled.
<img width="1452" height="224" alt="image" src="https://github.com/user-attachments/assets/7f1dde4e-4ebc-4dd2-974a-c01932a693ef" />
`CUDA_VISIBLE_DEVICES=0,1,2,3 python -m sglang.launch_server \
  --model-path /root/.cache/modelscope/hub/models/moonshotai/Moonlight-16B-A3B-Instruct \
  --trust-remote-code \
  --tp 4 --ep 4 --dp 1 \
  --moe-a2a-backend none \
  --enable-eplb --eplb-rebalance-num-iterations 10 \
  --expert-distribution-recorder-buffer-size 10`
(this screenshot running in H800 * 4)
By manually controlling the trigger timing of the load rebalancing, we confirmed that the output degradation occurs specifically after the rebalancing phase. Further investigation via logging revealed the root cause: both forward_normal in deepseek_v2.py and dual_forward_normal (used for CUDA Graph) were missing the necessary logical-to-physical mapping for expert_id.

This PR implements the correct expert ID mapping in these forward paths to resolve the issue.
