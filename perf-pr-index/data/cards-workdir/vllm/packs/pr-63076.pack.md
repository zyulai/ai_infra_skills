## Overview

AITER `biased_grouped_topk` runs an LDS group scan even when the grouping cannot eliminate any expert — that is, when `topk_group >= num_expert_group`, so every group is selected. This adds a register-resident Triton sigmoid+bias top-k and substitutes it at `rocm_aiter_ops.biased_grouped_topk`, the single call site both ROCm routers reach.

Previously this PR specialised `rocm_aiter_grouped_topk` only. Moving it to the wrapper came out of review (thanks @simondanielsson) and covers both paths without touching routing metadata:

| caller | group arguments it passes |
|---|---|
| `GroupedTopKRouter` | the model's own `1/1` for a degenerate router |
| `FusedTopKBiasRouter` | a count synthesised to fit an AITER kernel — measured `2/2` for a 64-expert router — with `topk_group == num_expert_group` |

`vllm/model_executor/layers/fused_moe/experts/rocm_aiter_moe.py` is no longer modified; the diff is three files, additions only.

## Claims

- 1.67×–2.15× on the routing op on gfx942, and 1.16×–1.57× per shape on gfx950, under CUDA graph replay, across the configurations listed below.
- The gate stops at 512 experts and top-8. On gfx950 the kernel loses at top-16 (896-expert top-16 down to 0.62×), so those routers keep AITER — see *Scope and bounds*.
- Equivalent to the call it replaces whenever no group is eliminated, including `num_expert_group == topk_group > 1`, which is the shape `FusedTopKBiasRouter` produces.
- Eager execution is **not** faster, so it is excluded by the substitution rather than claimed as a win.
- Selected expert ids match AITER on 3323 of 3328 routing calls in a live Moonlight-16B-A3B forward and on 1248 of 1248 in Kimi-VL-A3B.
- **Scope: single-token batches only (`_MAX_TOKENS = 1`), as suggested in review**, i.e. one request decoding without speculation, which is where the end-to-end gain is. Larger batches keep AITER.
- End to end on MI355X with current `main`, five models with 64 to 384 experts, 1k to 32k context: **single-request decode is 0.4% to 4.2% faster on every model**, and higher concurrency is within noise; nothing regresses beyond the same-arm drift. GSM8K is unchanged on GLM-5.3-Flash and Kimi-K2.6. Earlier gfx942 runs were within noise.
- No new env var, and no change to router selection or to the advertised routing method.

## Dispatch scope: why this is restricted to CUDA graph steps

The kernel's advantage is device time. Timed from a plain Python loop it is *slower* — it is a Triton launch from Python against a single C++ dispatch, and that overhead is not amortised.

Because the gate is a token-count bound rather than an execution-phase check, eager steps can reach it, so this was measured end to end with `--enforce-eager`, interleaved B-A-B-A on Moonlight:

| in / out | concurrency | AITER tok/s | ungated PR tok/s | Δ | same-arm drift |
|---|---:|---:|---:|---:|---|
| 64 / 256 | 8 | 488.7 | 471.8 | **−3.5%** | 0.6% / 1.2% |
| 64 / 256 | 32 | 1910.4 | 1876.9 | **−1.8%** | 0.8% / 0.1% |
| 1024 / 1024 | 8 | 780.8 | 758.1 | **−2.9%** | 0.8% / 0.2% |
| 1024 / 1024 | 32 | 3008.8 | 2915.3 | **−3.1%** | 0.0% / 0.9% |

Consistent sign and a magnitude several times the drift, so this is a real regression, not noise. The dispatch therefore substitutes only while a CUDA graph is being captured, tested with `torch.cuda.is_current_stream_capturing()` as `custom_all_reduce.py` and `sparse_attn_indexer.py` already do, and eager steps keep AITER. An earlier revision tested `get_forward_context().cudagraph_runtime_mode` instead; that misses every FULL graph under the V2 model runner, which captures them with the forward context set to `NONE` (`vllm/v1/worker/gpu/cudagraph_utils.py`), so on current main it substituted only inside PIECEWISE graphs. Re-running the same eager A/B with the check in place:

|---|---:|---:|---:|---:|---|
| 64 / 256 | 8 | 490.2 | 492.5 | +0.5% | 0.7% / 0.1% |
| 64 / 256 | 32 | 1934.9 | 1933.3 | −0.1% | 1.2% / 0.0% |
| 1024 / 1024 | 8 | 787.1 | 786.8 | −0.0% | 0.1% / 1.0% |
| 1024 / 1024 | 32 | 3018.7 | 3009.5 | −0.3% | 1.9% / 0.8% |

Instrumentation observed no Triton dispatches with `enforce_eager=True`. With graphs enabled, on current main and MI355X, a server records these substitution decisions while it captures its graphs:

| model | cudagraph mode | substituted with the forward-context check | substituted with the stream-capture check |
|---|---|---:|---:|

The slow launches are the tie fallback: when a row has two experts with exactly equal biased scores among its top-k, the fast path picks more than k and that row redoes the selection, and the launch waits for its slowest row. bf16 logits make exact ties common enough at top-16 to matter (0.8% of rows at 896 experts, so about one 32-row launch in five), which is where the 0.6× launches come from. Rows above 512 experts or top-8 therefore stay on AITER.

**The 8k/1k and 64k/1k points are now measured.** The earlier report that they could not be served was wrong, and the reason is worth stating because it is a bug in the benchmark harness rather than in serving.

`vllm bench serve --dataset-name random` samples token ids from `tokenizer.vocab_size`. For this checkpoint that is **163842**, while the model's embedding has `config.vocab_size` = **163840** rows, so ids 163840 and 163841 index past the table and the embedding gather faults. The dataset emits a *contiguous run* of ids, so a 65536-token prompt covers 40% of the vocabulary and nearly always includes one of the two; an 8192-token prompt covers 5%, which is why 8k completed under some seeds and not others. On stock vLLM, with no part of this PR installed, the identical 8192 configuration completes 3/3 with `--seed 7` and faults 3/3 with `--seed 1234`:

| seed | completed | `Memory access fault` |
|---|---|---|
| 7 | 8, 8, 8 | 0 |
| 1234 | 0, 0, 0 | 1 |

That also explains the fault seen earlier on a different machine with Kimi-VL, where the kernel named in the HSA exception was `at::native::vectorized_gather_kernel` — the embedding gather.

Replacing the synthesised prompts with real text (a custom dataset whose maximum token id is 138177, verified below the embedding size) removes the fault entirely: 8 of 8 runs complete at 64k with zero faults.

### Bias dtype

`rocm_aiter_ops.biased_grouped_topk` casts `correction_bias` to the gating dtype before dispatching, because AITER raises on a mismatch. A bf16 gating output next to an fp32 correction bias is a common router layout, so without the same cast the new path would score experts at a precision the replaced path never uses, and could select different experts. `sigmoid_bias_flat_topk` therefore makes the same cast at its own entry; Removing the cast fails 4 of the 6 cases in `test_flat_topk_casts_bias_like_aiter`; the other two shapes happen not to be sensitive to the bias precision.

+"""Register-resident sigmoid + bias top-k for degenerate grouped routing.
+
+Several DeepSeek-V3-architecture checkpoints route with ``use_grouped_topk=True``
+but ``num_expert_group=1`` and ``topk_group=1``, so the group stage selects
+nothing: Moonlight-16B-A3B (64 experts, top-6) and Kimi-K2 (384 experts, top-8),
+both ``scoring_func="sigmoid"`` with a ``noaux_tc`` correction bias.  On ROCm this
+lands in ``aiter.biased_grouped_topk_hip`` (``grouped_topk_kernel<...,
+NUM_GRP=1>``), which keeps the biased scores in LDS and runs one serial round
+per selected expert of ``LDS scan -> shuffle argmax -> LDS invalidate -> LDS
+read of the pre-bias sigmoid``.
+
+With a single group the group-selection stage is the identity, so the op is
+exactly "sigmoid(logits) + bias -> top-k -> weights = sigmoid at the chosen
+experts (optionally renormalised, times routed_scaling_factor)".  This kernel
+does that with all scores held in registers: each score is packed with its
+expert index into a unique, order-preserving int64 key, so every round is a
+single ``tl.max`` plus an equality invalidate (no argmax pair reduction, no
+LDS round trips, ties broken towards the lower expert id).
+"""

+from vllm.triton_utils import tl, triton

+# Shape bounds, not model bounds: no checkpoint is assumed. _MAX_TOKENS limits
+# this to single-token batches, i.e. one request decoding without speculation.
+# That is where it shows end to end (+0.4% to +4.2% output throughput across
+# five models on MI355X); at larger batches the router is a smaller share of
+# the step and the gain is within noise, so those keep AITER.
+# _MAX_EXPERTS and _MAX_TOPK are where this kernel stops beating AITER on
+# MI355X (gfx950), measured under CUDA graph replay with bf16 router logits:
+# up to 512 experts and top-8 it averages 1.16-1.57x per shape, and no launch
+# falls below 0.92x even with a forced score tie. At top-16 one row with an
+# exactly tied score sends the launch through the fallback path at 0.62-0.78x
+# (512, 896 and 1024 experts), and from 896 experts tie-free launches gain at
+# most 1.09x, so those routers keep AITER.
+_MAX_TOKENS = 1
+_MAX_EXPERTS = 512
+_MAX_TOPK = 8

+# round trip / barrier), which is what bounds latency at decode batch sizes.
+_NUM_WARPS = 1

+@triton.jit
+def _sigmoid_bias_flat_topk_kernel(
+    logits_ptr,
+    bias_ptr,
+    topk_weights_ptr,
+    topk_ids_ptr,
+    stride_lm,
+    stride_wm,
+    stride_im,
+    routed_scaling_factor,
+    E: tl.constexpr,
+    BLOCK_E: tl.constexpr,
+    TOPK: tl.constexpr,
+    BLOCK_K: tl.constexpr,
+    RENORM: tl.constexpr,
+):
+    pid = tl.program_id(0)
+    offs = tl.arange(0, BLOCK_E)
+    emask = offs < E
+    row = logits_ptr + pid.to(tl.int64) * stride_lm
+
+    x = tl.load(row + offs, mask=emask, other=0.0).to(tl.float32)
+    b = tl.load(bias_ptr + offs, mask=emask, other=0.0).to(tl.float32)
+    # Same formula as the AITER kernel: 1 / (1 + 2^(-x * log2(e))).
+    s = 1.0 / (1.0 + tl.exp2(x * -1.4426950408889634))
+    # NaN logits (e.g. padded CUDA-graph rows) must not win selection: like
+    # AITER's '>'-based scan, treat them as score 0.
+    s = tl.where(s == s, s, 0.0)
+    sc = s + b
+
+    w_row = topk_weights_ptr + pid.to(tl.int64) * stride_wm
+    i_row = topk_ids_ptr + pid.to(tl.int64) * stride_im
+
+    # Fast path: TOPK rounds of fp32 max (DPP-fused v_max) that also record the
+    # round in which each expert was taken. With no exact score ties exactly
+    # TOPK experts are taken, round k == output slot k (descending, as AITER),
+    # and the weights come straight from registers.
+    v = tl.where(emask, sc, float("-inf"))
+    rnd = tl.full([BLOCK_E], -1, tl.int32)
+    for k in tl.static_range(TOPK):
+        m = tl.max(v, axis=0)
+        hit = v == m
+        rnd = tl.where(hit, k, rnd)
+        v = tl.where(hit, float("-inf"), v)
+    picked = rnd >= 0
+    n_picked = tl.sum(picked.to(tl.int32), axis=0)
+
+    if n_picked == TOPK:
+        if RENORM:
+            wsum = tl.sum(tl.where(picked, s, 0.0), axis=0)
+            scale = routed_scaling_factor / tl.maximum(wsum, 1e-20)
+        else:
+            scale = routed_scaling_factor
+        tl.store(w_row + rnd, s * scale, mask=picked)
+        tl.store(i_row + rnd, offs, mask=picked)
+    else:
+        # Exact ties: pack (order-preserving score, E-1-idx) into a unique
+        # int64 key so equal scores resolve to the lower expert id.
+        bits = sc.to(tl.int32, bitcast=True)
+        okey = bits ^ ((bits >> 31) & 0x7FFFFFFF)
+        key = (okey.to(tl.int64) << 32) | (BLOCK_E - 1 - offs).to(tl.int64)
+        sentinel = tl.full([BLOCK_E], -2147483648, tl.int32).to(tl.int64) << 32
+        key = tl.where(emask, key, sentinel)
+
+        kk = tl.arange(0, BLOCK_K)
+        sel = tl.zeros([BLOCK_K], dtype=tl.int64)
+        for k in tl.static_range(TOPK):
+            mk = tl.max(key, axis=0)
+            sel = tl.where(kk == k, mk, sel)
+            key = tl.where(key == mk, sentinel, key)
+
+        kmask = kk < TOPK
+        ids = (BLOCK_E - 1) - (sel & (BLOCK_E - 1)).to(tl.int32)
+        ids = tl.where(kmask, ids, 0)
+        # Pre-bias sigmoid of the chosen experts, re-derived from the logits
+        # with the identical formula (bit-exact with the selection value).
+        xs = tl.load(row + ids, mask=kmask, other=0.0).to(tl.float32)
+        w = 1.0 / (1.0 + tl.exp2(xs * -1.4426950408889634))
+        w = tl.where(kmask & (w == w), w, 0.0)
+        if RENORM:
+            w = w * (routed_scaling_factor / tl.maximum(tl.sum(w, axis=0), 1e-20))
+        else:
+            w = w * routed_scaling_factor
+        tl.store(w_row + kk, w, mask=kmask)
+        tl.store(i_row + kk, ids, mask=kmask)

+def can_use_sigmoid_bias_flat_topk(
+    gating_output: torch.Tensor,
+    correction_bias: torch.Tensor | None,
+    topk_weights: torch.Tensor,
+    topk_ids: torch.Tensor,
+    num_expert_group: int,
+    topk_group: int,
+) -> bool:
+    if correction_bias is None:
+        return False
+    # The grouping stage only eliminates experts when some group is left out.
+    # With topk_group >= num_expert_group every group is selected, so the
+    # masked top-k degenerates to a plain top-k over all experts. That covers
+    # a router declaring a single group and one whose group count was
+    # synthesised to fit an AITER kernel.
+    if topk_group < num_expert_group:

+    topk = topk_ids.shape[-1]

+        and num_experts <= _MAX_EXPERTS
+        and topk <= min(_MAX_TOPK, num_experts)
+        and correction_bias.numel() == num_experts
+        and correction_bias.is_contiguous()
+        and gating_output.dtype in (torch.float32, torch.bfloat16, torch.float16)
+        and topk_ids.dtype == torch.int32
+        and topk_weights.dtype == torch.float32
+        and topk_ids.stride(-1) == 1
+        and topk_weights.stride(-1) == 1
+    )
+
+
+def sigmoid_bias_flat_topk(
+    gating_output: torch.Tensor,
+    correction_bias: torch.Tensor,
+    topk_weights: torch.Tensor,
+    topk_ids: torch.Tensor,
+    need_renorm: bool,
+    routed_scaling_factor: float = 1.0,
+) -> None:
+    """In-place equivalent of aiter.biased_grouped_topk when no group is
+    eliminated, i.e. topk_group >= num_expert_group."""
+    # AITER rejects a bias whose dtype differs from the gating dtype, so
+    # rocm_aiter_ops.biased_grouped_topk casts it before dispatching. Routers
+    # commonly hold a bf16 gating output next to an fp32 correction bias, so
+    # without the same cast here the two paths would score experts at
+    # different precision and this function would not be the equivalent its
+    # docstring claims: selected expert ids can differ.
+    if correction_bias.dtype != gating_output.dtype:
+        correction_bias = correction_bias.to(gating_output.dtype)
+    num_tokens, num_experts = gating_output.shape
+    if num_tokens == 0:
+        return
+    topk = topk_ids.shape[-1]
+    _sigmoid_bias_flat_topk_kernel[(num_tokens,)](
+        gating_output,
+        correction_bias,
+        topk_weights,
+        topk_ids,
+        gating_output.stride(0),
+        topk_weights.stride(0),
+        topk_ids.stride(0),
+        float(routed_scaling_factor),
+        E=num_experts,
+        BLOCK_E=triton.next_power_of_2(num_experts),
+        TOPK=topk,
+        BLOCK_K=triton.next_power_of_2(topk),
+        RENORM=bool(need_renorm),
+        num_warps=_NUM_WARPS,
+    )
