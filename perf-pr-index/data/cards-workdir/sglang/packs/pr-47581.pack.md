﻿## Motivation



DSpark verify-length scheduling and greedy verification can spend significant time in generic operations on Ascend NPUs. Route the supported paths through the NPU-specific scheduler and row-wise argmax implementations.



Depends on https://github.com/sgl-project/sgl-kernel-npu/pull/913 for `schedule_verify_lens_topk_triton`; the NPU kernel package must also provide `row_argmax`.



## Modifications



- Dispatch verify-length top-k scheduling to the sgl-kernel-npu Triton operator on NPU.

- Use the NPU row argmax operator under the existing fused argmax eligibility conditions.

- Extend NPU dispatch tests for correctness, special values, fallback inputs, and scheduler edge cases.



## Accuracy Tests



On Ascend910_9362 with PyTorch 2.10.0, torch-npu 2.10.0.post6, and Triton-Ascend 3.2.0, the focused sgl-kernel-npu operator tests and SGLang NPU dispatch tests passed **15/15**, using SGLang `58d10d27dc` and sgl-kernel-npu `e0893fb` source with the container's installed shared library. Coverage includes FP16/BF16/FP32 confidence, ties, budget and threshold changes, noncontiguous and offset inputs, and NPU Graph replay. Row argmax verification includes NaN and infinity cases.



Pending follow-up: model-level output accuracy validation.



## Speed Tests and Profiling



Operator microbenchmarks on Ascend910_9362 (FP32) show the following. These are not end-to-end serving measurements.



For the scheduler, an in-process comparison of the original NPU Triton implementation with the launcher-cached implementation from kernel PR-913 used `gamma=6`, `budget=3 × B`, 10 warmup calls, and the median of 10 groups of 20 calls measured with NPU events:



| Batch size | Original NPU Triton (μs) | Cached NPU Triton (μs) | Speedup |
|:---:|---:|---:|---:|
| 8 | 226.0 | 135.1 | 1.67× |
| 32 | 254.0 | 139.5 | 1.82× |
| 128 | 265.3 | 138.0 | 1.92× |



A separate earlier run measured the Torch NPU scheduler at 645.7, 628.3, and 781.4 μs for B=8, 32, and 128 respectively; its integer sorts ran on AiCPU. These numbers are from a different run and are indicative rather than a controlled speedup comparison.



For row argmax with vocab 129280, a repeated NPU Graph microbenchmark measured Torch at 18.3 μs versus NPU Triton at 12.9 μs for 7 rows, and 54.8 μs versus 36.9 μs for 112 rows. Graph replay reduces host submission overhead and does not represent end-to-end serving latency.
