## Overview

**Split 3/5 of Kimi K3.1 (#65685): serve K3.1 at TP8.** This PR adds the KV cache and attention changes that the K3.1 model (split 1/5, #66030, merged) needs to serve. Splits 1/5 and 2/5 are merged, so the diff against `main` is only this split.

Not a duplicate: it is one part of #65685, split for review. The remaining splits (#65685 for ROCm, P/D and indexer top-k; #66027 for DCP) are stacked on it and do not repeat its changes.

## Claims

- **Packed hybrid KV cache rows** (BLHNC):
  - A model can size the block row that holds every layer's page itself (`get_packed_hybrid_block_size`), so no page is padded.
  - The DS-MLA blob sizes (`DS_MLA_STATE_CONTENT_BYTES`) anchor the mamba page alignment, and the size of the packed-cache MLA draft page.
  - Hybrid targets keep a layer-compact layout under DCP.
- **Kernel-block slot mapping**:
  - A packed token cache may split into kernel blocks when the runner maps its slot mappings (`AttentionGroup.map_to_kernel_slot_mapping`).
  - Speculators opt in (`maps_slot_mapping`; DFlash and DSpark do). Their draft layers form their own attention groups in the target runner, so a DFlash draft gets one more metadata builder there.
  - Backends that write even an uncompressed cache from the block table say so (`AttentionBackend.writes_kv_cache_from_block_table`).
- **Sparse MLA**:
  - A DSA layer on a dense backend raises instead of silently running full attention.
  - The fp8 query is concatenated in place before quantization (about 1 ms per layer of a 32k-token prefill).
  - A ShardQ caller (Kimi K3.1) may pass the indexer query and weights of only the rank's rows. Before, the indexer indexed them again by the gathered-row ids, which read out of bounds (a device-side assert in the first mixed prefill/decode step at TP8).
- **Kimi K3.1 model config** (`KimiK31ForConditionalGeneration` in `MODELS_CONFIG_MAP`): with DSA, the kv-cache dtype defaults to per-tensor fp8 for FlashInfer sparse MLA (the SM10x default) and `fp8_ds_mla` otherwise, and dense drafts get a dense MLA backend (`tests/models/kimi_k3/test_dense_draft.py`).
- **FLASHINFER_MLA_SPARSE** (moved here from split 1/5, so that split does not touch `vllm/v1/attention`):
  - prims_ts, FlashInfer's task-scheduled sparse MLA decode (`kernel_config.flashinfer_sparse_mla_kernel`), for nvfp4_ds_mla and a per-tensor fp8 cache under DCP. It runs only when FlashInfer's prims_ts takes the plan arguments vLLM passes (newer than 0.7.3); on 0.7.3, `auto` keeps trtllm-gen and the prims_ts tests skip.
  - Trtllm-gen query head padding (no head count between 64 and 128) and shared multi-CTA KV counters.
  - The Kimi K3.1 specialized decode uses these again; its tests that need them come with this PR.
- **Specialized decode fix**: the wide MoE grid is sized by the SM count (from #65685).
- FA4 MLA prefill passes `head_size_v`.
