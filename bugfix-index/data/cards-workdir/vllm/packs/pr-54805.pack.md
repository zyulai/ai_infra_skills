## 正文(PR 描述)

## Purpose
The gluon decode kernel requires a uniform query length across the batch, but the scheduler emits ragged decode batches whenever a speculative draft is truncated or the token budget clips a request. MiniMax-M3 with EAGLE3 and shuffle KV cache layout aborts on the first ragged step. The AITER-side change that gives the gluon kernel per-row query lengths
kernel changes work in progress, so reverting pa gluon changes in rocm_aiter_fa.py. A follow-up PR will restore the gluon decode path once that AITER PR lands.

 pa gluon backend in AITER FA added in this PR - https://github.com/vllm-project/vllm/pull/52849/
 
 We are only reverting the pa gluon attn backend and keeping the shuffle layout fix.
