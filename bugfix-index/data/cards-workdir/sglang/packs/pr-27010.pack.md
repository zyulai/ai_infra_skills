## 正文(PR 描述)

## Motivation

When deploying HiCache and PP, multiple PP ranks go diverge and eventually cause sglang crash.  The detailed reason was discussed in issue #22607.

## Modifications

This patch introduces two kinds of synchronization mechanisms to fix the issue.  I will illustrate this idea with an example of pp_size=2 and tp_size=1.

1. **pp_sync** across scheduler threads.  pp_sync is a new name introduced by this patch.  PP0's scheduler thread determine the number of completion events in its local queues (ack_load_queue, ack_prefetch_queue, etc). Then, PP1 must consume the **exact** same number of events from its queues.  This prevents divergence.

2. **all_reduce** across prefetch threads.  Consider a case that PP0 and PP1 have different lengths on their L3 storage for a given sequence. They have to reach an agreement on the length, by perform all_reduce(MIN).  This behavior is consistent with TP.

This patch also changes how `check_prefetch_progress` works.  Before this patch, it simply does all_reduce(MIN) to determine the final tokens prefetchted.  However, this would not work on PP, as we cannot do that in the scheduler thread.  This patch adds a new background thread `prefetch_sync_thread`, which does the all_reduce work instead.

- Group A: The baseline, commit 5747ed3b, without this PR, TP=8, L3 enabled.  Resolved 356/500.
