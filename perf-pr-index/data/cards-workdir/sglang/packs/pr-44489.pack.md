## Motivation

This PR lets deterministic inference on MI350X/MI355X (gfx950) use AITER for decode attention: `--decode-attention-backend aiter`, with prefill attention still on a deterministic backend such as Triton. Decode attention is a large part of the cost of deterministic mode on these GPUs, and with AITER decode, deterministic throughput is 1.27-1.91x higher for Qwen3-8B, 1.53-1.61x for Qwen3-30B-A3B and 1.09-1.13x for Qwen3.8-27B, with every determinism check still passing and unchanged GSM8K.

AITER's paged decode attention (`paged_attention_ragged`) splits each request's KV cache into fixed 256-token partitions and reduces them per request. The split depends only on the request's own context length, never on the batch, so a request gets the same result whatever it is batched with.

This builds on #44438, which makes deterministic mode check `--prefill-attention-backend` and `--decode-attention-backend`. Decode has to be set explicitly: `--attention-backend aiter --prefill-attention-backend triton` stays refused, because `--attention-backend` itself must be a deterministic backend.

### Refused in deterministic mode, and why

| Configuration | Why |
| --- | --- |
| AITER as `--attention-backend` or `--prefill-attention-backend` | AITER prefill attention is not batch-invariant (in our tests its results changed with the batch from about 480 tokens, and with mixed batches) |
| AITER decode for MLA models | MLA decode sizes its KV splits by the batch size |
| AITER decode on other GPUs than gfx950 | not tested |
| AITER decode with speculative decoding | target verify (`--speculative-attention-mode decode`) and some draft workers would run AITER's verify and extend kernels, which are not verified |
| AITER decode with sliding-window models, `SGLANG_USE_AITER_UNIFIED_ATTN` or the vectorized 5D KV-cache layout | these run AITER's unified-attention or 5D-pool decode kernels instead of `paged_attention_ragged`; not verified. Refused when the AITER backend starts |
| `--enable-mixed-chunk` (any backend) | a mixed batch runs its decode tokens through the prefill kernels; handled separately in #44701, which switches it off in deterministic mode |

## Modifications

- `arg_groups/overrides.py` (`_deterministic_attention_backend`): the allowed backends are built per phase first; `aiter` is added for decode on gfx950, for non-MLA models and without speculative decoding. Both phases are then checked in one loop. When AITER decode is refused, the error says why. The per-phase fields are read directly.
- `layers/attention/aiter_backend.py`: in deterministic mode, the AITER backend refuses to start when decode would not run `paged_attention_ragged` (unified attention or the vectorized 5D KV-cache layout), so an accepted configuration always runs the kernel that was verified.
- `test_model_overrides.py`: a table test (gfx950 or not, MLA or not, AITER prefill or not, speculative decoding or not) for which configurations are accepted. #44438's refusal test pins `is_gfx95_supported` to `False` and sets both per-phase fields, so it does not depend on the machine it runs on.
- Unchanged: deterministic mode off; every configuration that does not set `--decode-attention-backend aiter`; the radix cache (it follows `--attention-backend`, which stays a deterministic backend).

## Accuracy Tests

Environment: 8x MI350X, `rocm/sgl-dev:v0.5.21-rocm724-mi35x-20261013` (SGLang `27b68303d0`, AITER `e7d2453f2`), `SGLANG_USE_AITER=1` (the image default); `aiter_backend.py` is identical to upstream main. Deterministic mode on MI350X also needs the open fixes #43788 (AITER GEMM and MoE bypass; not merged yet) and #34543 (all-reduce for oversized inputs), which were applied in all runs, together with our other open PRs. These runs used the image without #44438, where `--decode-attention-backend aiter` was not checked yet; the server arguments are the ones this PR accepts:

```bash
python3 -m sglang.launch_server --model-path Qwen/Qwen3-8B --tp $TP \
  --attention-backend triton --prefill-attention-backend triton --decode-attention-backend aiter \
  --enable-deterministic-inference
# Qwen3.8-27B additionally: --linear-attn-prefill-backend triton --linear-attn-decode-backend triton
```
