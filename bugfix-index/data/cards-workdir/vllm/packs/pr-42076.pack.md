## 正文(PR 描述)

## Purpose

Fix precision loss in `chunk_scaled_dot_kkt_fwd_kernel` on Hopper-architecture GPUs (e.g. H20, sm_90) that causes GDN-based models to produce **garbage output (e.g. lm_eval gsm8k score = 0 !!!)**.

### Root Cause

[PR #37813](https://github.com/vllm-project/vllm/pull/37813) optimized the GDN conv path, but it also introduced an overlooked side-effect: the `g` tensor passed to `chunk_scaled_dot_kkt_fwd_kernel` changed from float32 to bf16. Combined with a suboptimal operand layout in the existing `tl.dot` call on line 86, this triggered a precision bug specific to Hopper (sm_90) GPUs.

The problematic line:

```python
b_A += tl.dot(b_kb.to(b_k.dtype), tl.trans(b_k))
```

`b_kb` is already bf16 (result of `b_k * b_beta[:, None]`, both bf16). `b_k.dtype` is also bf16. So `.to(b_k.dtype)` is an identity cast in terms of data type — but in Triton's IR it inserts a `convert_layout` operation that changes the tensor's distributed register layout.

On **Hopper (H20, sm_90)**, Triton lowers `tl.dot` to the WGMMA (Warpgroup MMA) instruction family. WGMMA is highly sensitive to operand layout — when operand A's register layout is perturbed by the spurious `.to()` call, the hardware performs additional rearrangement that loses precision in the dot product accumulator. The error propagates through `exp(b_g_diff)` and ultimately produces NaN in the output, causing downstream GDN layers to generate garbage tokens.

On **Ada (4060ti, sm_89)** and earlier architectures, Triton uses HMMA/WMMA instructions which are tolerant of layout variations — the compiler optimizes away the redundant layout conversion and both patterns produce identical PTX. This is why the issue was not caught during development.

With float32 `g`, the higher-precision `exp(b_g_diff)` multiplication masks the dot product error. With bf16 `g` (introduced by #37813), the lower-precision downstream computation amplifies the error past the NaN threshold.

### Fix

Move `.to()` from the non-transposed operand (A matrix) to the transposed operand (B matrix):

```python
# Before (buggy):
b_A += tl.dot(b_kb.to(b_k.dtype), tl.trans(b_k))

# After (fixed):
b_A += tl.dot(b_kb, tl.trans(b_k).to(b_kb.dtype))
```

This lets Triton combine the transpose + type conversion into a single layout transform that produces the register layout WGMMA expects natively, avoiding the intermediate precision loss. This pattern is already used consistently in other FLA kernels (e.g. `chunk_delta_h.py`).
