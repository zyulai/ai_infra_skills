## Motivation

`fp8_fa_sm120` computes QK and PV with the plain FP8 `mma.sync` (E4M3 x E4M3, FP32
accumulate). On GeForce SM120 this instruction runs at half rate. I measured the raw MMA
peak on an RTX 5080 with back-to-back chains and no memory traffic:

| instruction | SASS | TFLOP/s |
|---|---|---:|
| plain FP8, FP32 accumulate | `QMMA.16832.F32.E4M3.E4M3` | 246 |
| block-scaled FP8, FP32 accumulate | `QMMA.SF.16832.F32.E4M3.E4M3.E8` | 488 |

The block-scaled encoding (`kind::mxf8f6f4.block_scale`) multiplies each operand by a
UE8M0 scale, one byte per 32 k elements. With every scale byte set to 0x7F (2^0) the math
is the same product. On random finite E4M3 inputs, 0 of 704 M accumulator registers differ
between the two instructions.

So the kernel was limited by the instruction encoding, not by its design.

## Modifications

- `kernels/ops/attention/fp8_fa_sm120/kernel.py`
  - The MMA atom is `warp.MmaMXF8Op` when the compile target has it (sm_120a/f,
    sm_121a/f), `warp.MmaFP8Op` otherwise.
  - Four scale fragments (for Q, K, P, V) hold the constant byte 0x7F. They live in
    registers: no shared memory, no extra loads.
  - The two `cute.gemm` calls pass `[operand, scale]` pairs.
- `kernels/ops/attention/fp8_fa_sm120/plan.py`: the public `fp8_attention()` signature is
  unchanged. An internal compile-time parameter selects the encoding. It is not a user
  option, because the output is bit-equal and there is no speed against accuracy choice.
- One unit test runs both encodings on the same inputs and requires equal bits.

Operand layouts, shared memory, the softmax, the P pack and the prep do not change.
Register count goes from 244 to 250, no stack.

## Accuracy Tests

The output is bit-identical to `main`. Same inputs (seed 42), SHA-256 over the O and LSE
bytes, `main` against this branch:

| H | S | equal |
|---:|---:|---|
| 8 | 1052 (key mask path) | yes |
| 56 | 20440 | yes |
| 56 | 30272 | yes |

Unit tests: 10/10, including the new bit-equality test.

## Speed Tests and Profiling

RTX 5080, H=56, D=128, median of 5 runs, same process and inputs.

| S | prep (ms) | kernel `main` (ms) | kernel this PR (ms) | full call `main` (ms) | full call this PR (ms) |
|---:|---:|---:|---:|---:|---:|
| 20440 | 2.60 | 56.34 | 37.66 | 58.91 | 40.27 |
| 30272 | 3.84 | 123.60 | 83.28 | 127.26 | 86.29 |

The full call is 1.47x faster at both lengths. Against cuDNN SDPA BF16 on the same card
(226 ms at S=30272) the backend is now 2.6x faster, was 1.8x.
