## Overview

Removes QuTLASS and the deprecated `fp_quant` method, and runs compressed-tensors NVFP4 checkpoints with a Hadamard input transform (QuIP) on Humming. Supersedes #61671, and makes #51112 moot.

## Claims

- QuIP NVFP4 checkpoints load and generate again. At `main` they crash at startup on SM100+.
- The checkpoint's declared FP4 activation is honored, with no fallback to A16 on this path.
- Input transforms always receive unquantized activations, which also fixes the generic transform path.
- The `_qutlass_C` build dependency, the `fp_quant` method, and about 1,800 lines of code are gone.

**Breaking:** `fp_quant` checkpoints no longer load. They already failed to load on `main`, and the method has been deprecated since #31688.

## Validation

B300 (SM103), humming-kernels 0.1.18. FP-Quant numbers below are from a scratch prototype, since that path is removed here; the QuIP row was re-run on this branch.

**Tests**

| Command | Result |
|---|---|
| `pytest tests/models/quantization/test_nvfp4.py -k 'quip or hadamard_fp4_routing'` | 8 passed |
| `pytest tests/quantization/test_compressed_tensors.py -k transforms_perplexity` | 3 passed |
| QuIP generation with `VLLM_GPU_SYNC_CHECK=error` | clean |
| `pre-commit` on changed files | passed |

Reproducer on `main`: `LLM(model="nm-testing/Llama-3.2-1B-Instruct-quipv16-nvfp4")` fails during startup with `'QuantizedActivation' object has no attribute 'shape'`.

**GSM8K** (600 questions, 5-shot, greedy, %)

| Checkpoint | QuTLASS* | Humming A4 | Humming A16 + Hadamard |
|---|---|---|---|
| Llama-3.2-1B QuIP NVFP4 (float: 32.3) | 18.8 | 17.3–20.5 (this branch) | 22.8 |
| Qwen3-1.7B FP-Quant RTN NVFP4 (float: 66.8) | 23.5 | 21.3 | 45.2 |
| Qwen3-1.7B FP-Quant QAT NVFP4 | 55.0 | 52.0 | 62.0 |
| Qwen3-1.7B FP-Quant RTN MXFP4 | 16.3 | 15.3 | 26.7 |

\* `main` cannot run these, so the baseline needed small harness patches for the two root causes below. FP-Quant rows ran in eager mode.

A4 vs QuTLASS is a statistical tie (paired p = 0.13–0.93), though lower in every prototype row. Run-to-run noise is large: two passes in one process scored 17.3 and 20.5, with 196/600 identical outputs.

**GEMM GPU time** (µs, graph replay, real `down_proj` weights, N=2048, K=6144, warm L2, not hand-tuned)

| M | QuTLASS + cutlass | QuTLASS + FlashInfer | Humming A4 | Humming A16 |
|---|---|---|---|---|
| 1 | 17.9 | 7.7 | 9.7 | 9.8 |
| 1024 | 36.8 | 24.1 | 15.9 | 41.4 |
| 8192 | 164.9 | 146.4 | 75.8 | 240.6 |

NVFP4 shown. Graph replay was used because CUPTI failed in this environment (`cupti-python` 13.3.1).

## Details

**Root causes on `main`**
- `fp_quant`: checkpoints contain `backward_hadamard_matrix`, which `FPQuantLinearMethod` never registers, so loading fails.
- QuIP: since #44260 NVFP4 layers expose `input_quant_key`, so producers pass a `QuantizedActivation`, which the transform methods cannot handle. Per #61671, SM12x also fails because QuTLASS wheels contain only `sm_100` code.
- Neither was caught because the job holding the QuIP perplexity test is commented out. The new tests are in `test_nvfp4.py`, whose Blackwell job does run.

**Routing:** Humming is used for W4A4, SM100+, a `hadamard` input transform with `head_dim` in 16–128, no output transform, and backend `auto` or `humming`. Everything else uses the generic transform path. Humming's block size 16–256 output matched the dense Sylvester matrix to bf16 rounding.

**What is lost**
- QuEST for MXFP4. None of the 36 public `fp_quant` models use it.
- Bit-exact output against QuTLASS, since scale rounding differs.
- Fused handling of non-Sylvester dense transforms. They use the generic path, which is slower and was not tested here.
- About 2 µs at M=1–16 versus the CT FlashInfer path.

**Not validated:** SM120, and TP>1 (`HadamardTransform` still raises `NotImplementedError`). `Humming float4e2m1 activation is slow on SM103` still logs, though A4 was the fastest option at M ≥ 1024. Plain NVFP4 on `--linear-backend humming` still falls back to A16 on SM10x and is unchanged here.

Not a duplicate: open PRs #61671 and #51112 fix QuTLASS rather than remove it.

+## Hadamard Input Transforms (QuIP)
+
+Compressed-tensors NVFP4 checkpoints with a QuIP-style Hadamard input transform (`transform_config` with `type: hadamard` and `head_dim` of 16, 32, 64, or 128) run on the Humming backend by default on compute capability 10.0 and newer. The Hadamard is fused with input quantization, and the activation dtype declared by the checkpoint is used, with no fallback to 16-bit activations.
+
+Other transforms, older GPUs, and an explicit `--linear-backend` other than `auto` or `humming` use the generic transform path, which applies the transform separately before the selected kernel.
+
+!!! note
+    The `fp_quant` quantization method and the QuTLASS backend have been removed. Use a compressed-tensors checkpoint instead.
+
