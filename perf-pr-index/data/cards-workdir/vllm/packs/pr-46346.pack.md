## Purpose

This a a follow-up of #43273. In this PR, I only focused on optimizing the matrix inverse pipeline inside the KKT kernel. A quick recap on the KKT kernel timeline
<img width="3684" height="648" alt="kkt_old" src="https://github.com/user-attachments/assets/8197c715-a2fc-46a0-98e0-7fe61888fd15" />

This is a bit more detailed than the timeline shown previously in #43273, because the extra steps shown above (`Prepare gate/beta` and `Store Ab/Abg to tmem`) turn out to be the bottleneck! I asked Codex to add some instrumenting code so we can get an actual kernel timeline

<img width="1455" height="417" alt="image" src="https://github.com/user-attachments/assets/4a3a410f-186f-49e7-937c-e2788c2d3a42" />

tcgen05 is so fast that `W MMA + U MMA + next KKT MMA` < `INV warps load and prepare beta/gate`! Furthermore, Ab/Abg preparation looks surprisingly slow, taking around 20-25% the time of inverse logic, which was supposed to be the most expensive. As it turns out again, doing multiplication can be a bottleneck on Blackwell.

So how do we overcome it?

### Slow beta/gate preparation

Move beta/gate preparations to extra warps! These prep warps can overlap with existing INV warps, and go 1 stage ahead of the INV warps -> when INV warps need beta/gate, those values are already ready in smem buffer -> no waiting

### Slow Ab/Abg prepration after `inverse(I+A)`

Currently, we have a clear boundary between doing `inv(I+A)`, and then compute `Ab = inv(I+A) * beta` / `Abg = inv(I+A) * beta * gate`.

```
# current
1. compute inverse for diagonal 16x16 tiles (Newton-Schulz)
2. compute inverse for off-diagonal tiles (block forward-substitution)
3. compute Ab/Abg, and store to tmem
```

This cleanly separates the logic, but not optimal: there is an extra smem roundtrip, and we also unnecessarily store the zeros upper-triangular tiles. Instead, we can fuse Ab/Abg prep with the inverse steps.

```
# new
1. compute inverse for diagonal 16x16 tiles (Newton-Schulz)
1b. while the result is still in registers, compute Ab/Abg and store to tmem
2. compute inverse for off-diagonal tiles (block forward-substitution)
2b. while the result is still in registers, compute Ab/Abg and store to tmem
```

We save the unnecessary Ab/Abg computation for the upper triangular tiles. Before, we have 4x4 16x16 tiles. Now, we only need to compute and store (1+2+3+4) 16x16 Ab/Abg tiles.

The new kernel timeline

<img width="1455" height="473" alt="image" src="https://github.com/user-attachments/assets/412ebeb8-1108-4c2b-b226-baf495043be5" />

tcgen05 is still mostly idle. We can do pingpong schedule like FlashAttention in the future.

### Other cleanup

I also take this opportunity to make small tweaks in the kernels that don't really bring significant changes
- Move `elect_sync()` inside the tcgen05 helper functions. From my experience, this gives better codegen, as CuteDSL may generate weird predicated address calculations
- Remove swizzled layout for `sA` and `sAi`
- Use `TmaInfo` object returnted by `make_tiled_tma_atom` directly, no need to `(atom, tma_tensor, s_layout)` tuples.
- Apply `f32x2` math as appropriate using `cutlass.range(vectorize=True)`
- Remove adhoc BF16 bit manipulation in favour of built-in PTX like `neg.bf16x2` and `sub.bf16x2`
