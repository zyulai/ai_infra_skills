## Summary

On the DeepSeek-V4 unified-KV path, the fused qk-norm-rope kernel is wired to
decode only. MTP **target-verify** falls back to running the same work as two
separate launches per layer — `sglang::fused_q_norm_rope` for q and
`sglang::fused_norm_rope` for kv — which is 122 launches per verify step across
the 61 target layers.

This PR routes target-verify through the same fused kernel, **with the cache
store left off**.

The store half deliberately does not move. Decode is a 1-source consumer: the
ring holds everything, so writing it before attention is required. Target-verify
is **2-source** — attention reads history from the ring and takes the current
chunk as `k`/`v` so the draft tokens stay causally masked against one another.
Writing the current chunk into the ring ahead of attention makes those tokens
indistinguishable from history, and every draft position then attends to all of
them regardless of order. Fusing the store as well drops GSM8K from 0.950 to
0.027 while looking like a ~7% throughput win, because it skips exactly the work
correctness depends on. Only the norm+RoPE half is sound, and that is what this
PR fuses.

## Modifications

- **`python/sglang/srt/models/deepseek_v4.py`** (`MQALayer._forward_prepare`)
  - `do_fused_store` now also admits `is_target_verify()` when the new gate is
    on. The kernel is token-indexed (`q`, `kv` and `positions` are all length M),
    so a verify batch carrying several draft tokens per request is a shape it
    already handles.
  - On that path the kernel is called with `swa_cache`/`swa_loc` left as `None`,
    so it performs q-norm+RoPE and kv-norm+RoPE and stores nothing.
    `get_unified_swa_loc` is not called at all — it exists solely to address a
    store this path no longer performs.
  - `kv` is returned instead of being set to `None`, so the caller's existing
    contract drives the rest unchanged: `attn_k = kv` gives attention the real
    current-chunk source, and `save_kv_cache = kv is not None` makes the backend
    write the ring after attention, exactly as the unfused path did.
  - `kv` is materialised with `.contiguous()` first: it is a strided slice of
    `qkv_a`, and the ring store requires a contiguous buffer. The unfused path
    pays the identical copy inside `_compute_kv_bf16`, so this is parity, not
    added overhead.
- **`python/sglang/srt/environ.py`** — new `SGLANG_OPT_FUSED_QK_NORM_ROPE_VERIFY`
  (default on). Set to 0 to fall back to the unfused chain on the verify path.

Decode, prefill and the non-unified paths are untouched.

`DeepseekV4DecoderLayer` frames (TP8, 8k/1k, conc 16, rank 0). `fused_q_norm_rope`
and `fused_norm_rope` both go to zero and one `_fused_qk_norm_rope_store_kernel`
replaces them; no other kernel is added.

## Performance

Same model and hardware. 8k input / 1k output, TP8, steady state (10 waves
through a `--max-concurrency` gate). Each cell is the mean of 2 repeats run in
`off, on, on, off` order per concurrency, so a monotonic drift over the block
shifts both arms equally instead of being credited to the patch. Repeated
all-gates-off runs on this node put the noise floor at 0.25% (1σ).

| concurrency | output tok/s (base → patched) | uplift | mean TPOT ms | accept len |
|---|---|---|---|---|
| 4  | 332.43 → 341.07 | **+2.60%** | 11.37 → 11.06 | 2.499 → 2.498 |
| 8  | 543.73 → 555.57 | **+2.18%** | 13.75 → 13.46 | 2.499 → 2.469 |
| 16 | 839.00 → 857.32 | **+2.18%** | 17.98 → 17.57 | 2.499 → 2.507 |
| 32 | 1167.14 → 1186.66 | **+1.67%** | 25.79 → 25.34 | 2.482 → 2.508 |

Acceptance length is flat across arms, so the uplift is kernel time and not a
shift in speculation behaviour.

    --host 127.0.0.1 --port 31710 --model deepseek-ai/DeepSeek-V4-Pro \

`bench_serving` ignores EOS by default here (it only offers
`--disable-ignore-eos`), so every request runs to exactly 1024 output tokens and
neither arm can win by generating less.
