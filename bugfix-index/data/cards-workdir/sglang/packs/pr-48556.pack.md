## 正文(PR 描述)

## Motivation

Weight-only quantized MoE models (W4A16 / W8A16) that run on the Triton MoE path can crash with `CUDA error: an illegal memory access` in `fused_moe_kernel_gptq_awq`. An AutoRound W4A16 checkpoint of Qwen3.8-Flash-Next at TP 4 hits it on its first decode step, every time. The cause is a weight load without its K mask; this PR adds the mask.

**Cause.** When K is not a multiple of `BLOCK_SIZE_K`, `fused_moe_kernel_gptq_awq` builds `k_mask` and applies it to the activation, scale and zero-point loads, but not to the weight load:

```python
b = tl.load(b_ptrs)
```

So the last K tile reads past the end of every weight row. On the last row of the last expert, it reads past the end of the weight tensor. The extra values are multiplied by a scale that is masked to zero, so the results are correct whenever the read does not fault. `fused_moe_kernel` already masks the same load.

**Who runs this kernel.**

- `--quantization moe_wna16`, for GPTQ and AWQ checkpoints.
- AWQ and AutoRound MoE layers that Marlin cannot take, for example without Marlin support on the platform, or with a per-rank intermediate size that is not a multiple of max(64, group size). So the irregular shapes, the ones most likely to leave a partial K tile, are the ones that fall back here.
- Compressed-tensors W4A16 MoE through `CompressedTensorsWNA16TritonMoE`: always on ROCm, by default on SM100/SM103 for symmetric INT4 with group 32 or 128, and elsewhere with `--moe-runner-backend triton`.

**When it reads out of bounds.** Whenever the per-rank K is not a multiple of the `BLOCK_SIZE_K` in use. At decode batch sizes (M ≤ E, no more tokens than experts), the default config uses `BLOCK_SIZE_K` 64, so the down projection overruns when the per-rank intermediate size is not a multiple of 64. Common cases:

| model | `moe_intermediate_size` | TP | per-rank K |
|---|---|---|---|
| GLM-4.5-Air, DeepSeek-V2-Lite, Qwen1.5-MoE-A2.7B | 1408 | 4 | 352 |
| Qwen3-30B-A3B | 768 | 8 | 96 |
| Qwen3.8-Flash-Next | 640 | 4 | 160 |

Tuned configs with `BLOCK_SIZE_K` 128 or 256 leave a partial tile for more shapes.

**When it crashes.** Whether the read faults depends on what follows the weight tensor in memory. I have tested only Qwen3.8-Flash-Next (512 experts) at TP 4, and there it always faults:

- `moe_wna16` lowers the group size from 128 to 32 to fit the per-rank K of 160, and the last tile covers 128–191.
- Each rank's down-projection weight is `[512, 2560, 80]` uint8, exactly 100 MiB, and the overrun leaves the allocation.

On v0.5.22, every such server I started died on its first decode. With this one line masked, they serve normally.

## Modifications

- Load the weights with the existing `k_mask` / `k_other`, as the scale and zero-point loads already do. When K is a multiple of `BLOCK_SIZE_K`, `k_mask` is `None` and the load is unchanged.
- New `test/registered/kernels/ops/moe/test_fused_moe_gptq_awq_k_tail.py`, driving `invoke_fused_moe_kernel` with explicit configs:
  - `test_partial_k_tile`: int4 and int8, with and without zero points, K = 96 and 160 with `BLOCK_SIZE_K` 64, compared against dequantize-then-matmul. The existing wna16 test (`test/manual/test_triton_moe_wna16.py`) only uses K = 128 and 1024, so a partial K tile had no coverage.
  - `test_weight_tail_at_allocation_end`: the Flash-Next down-projection shape above (E 512, N 2560, K 160, group 32, `BLOCK_SIZE_K` 64), with the weights allocated last so that the overrun leaves the allocation. Without the fix it crashes on L40S (below).

## Accuracy Tests

1x L40S (SM89), torch 2.14.1, Triton 3.8.0. The kernel function and its launch path are identical between current main and the tree I tested. I ran the new test with and without the change:

| | without the fix | with the fix |
|---|---|---|
| `test_partial_k_tile` | passes | passes |
| `test_weight_tail_at_allocation_end` | `CUDA error: an illegal memory access` (4 of 4 runs) | passes (2 of 2) |
| `test_partial_k_tile` under `PYTORCH_NO_CUDA_MEMORY_CACHING=1 compute-sanitizer --tool memcheck` | 6 errors: `Invalid __global__ read of size 1 bytes` at the weight load in `fused_moe_kernel_gptq_awq` | 0 errors |

`test_partial_k_tile` passes without the fix because the scale mask zeroes the extra values; only the sanitizer, or a read that leaves the allocation, exposes it.

The results do not change: with the fix, the masked slots load 0 and are still multiplied by a scale of 0.

## Speed Tests and Profiling

When K is a multiple of `BLOCK_SIZE_K` (`even_Ks`), the generated code is unchanged. Otherwise, it adds one predicate to the weight load, which the scale and zero-point loads in the same loop already carry. Not benchmarked.

+def _align(topk_ids, num_experts, block_m):
+    """Sort routes by expert and pad each expert to whole BLOCK_SIZE_M tiles."""
+    flat = topk_ids.flatten()
+    sorted_ids, expert_ids = [], []
+    for expert in range(num_experts):
+        routes = (flat == expert).nonzero().flatten().tolist()
+        routes += [flat.numel()] * (-len(routes) % block_m)
+        sorted_ids += routes
+        expert_ids += [expert] * (len(routes) // block_m)
+    return (
+        torch.tensor(sorted_ids, device="cuda", dtype=torch.int32),
+        torch.tensor(expert_ids, device="cuda", dtype=torch.int32),
+        torch.tensor([len(sorted_ids)], device="cuda", dtype=torch.int32),
+    )
+
+
+def _run(a, qweight, scale, qzeros, topk_ids, config, bits, group_size):
+    m, top_k = topk_ids.shape
+    sorted_ids, expert_ids, num_post_padded = _align(
+        topk_ids=topk_ids,
+        num_experts=qweight.shape[0],
+        block_m=config["BLOCK_SIZE_M"],
+    )
+    output = torch.empty(
+        m, top_k, qweight.shape[1], device="cuda", dtype=torch.bfloat16
+    )
+    invoke_fused_moe_kernel(
+        A=a,
+        B=qweight,
+        bias=None,
+        C=output,
+        A_scale=None,
+        B_scale=scale,
+        B_zp=qzeros,
+        topk_weights=torch.ones(m, top_k, device="cuda"),
+        topk_ids=topk_ids,
+        sorted_token_ids=sorted_ids,
+        expert_ids=expert_ids,
+        num_tokens_post_padded=num_post_padded,
+        mul_routed_weight=False,
+        top_k=top_k,
+        config=config,
+        compute_type=tl.bfloat16,
+        use_fp8_w8a8=False,
+        use_int8_w8a8=False,
+        use_int8_w8a16=bits == 8,
+        use_int4_w4a16=bits == 4,
+        per_channel_quant=False,
+        block_shape=[0, group_size],
+    )
+    torch.cuda.synchronize()
+    return output

+def _reference(a, q, zp, scale, group_size):
+    """a: [m, k]; q, zp, scale: per route, [m, top_k, n, ...] unpacked."""
+    weight = (q.float() - zp.float().repeat_interleave(group_size, -1)) * (
+        scale.float().repeat_interleave(group_size, -1)
+    )
+    # The kernel rounds the dequantized weight to bf16 before the dot.
+    weight = weight.to(torch.bfloat16).double()
+    return torch.einsum("mk,mtnk->mtn", a.double(), weight)
