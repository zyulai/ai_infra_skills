## Description

This PR fixes an Out of Memory (OOM) issue that occurs inconsistently when deploying multiple vLLM replicas with ray distributed backend (not sure if the ray backend is part of the cause). The problem manifests as some replicas failing with insufficient KV cache memory while others work fine, despite identical configurations.

### Root Cause

This is a viable hypothesis. The issue seem to stem from a race condition in the `init_device()` method of the GPU worker:

1. **Threading Issue**: When using Ray Compiled DAG, model execution happens on background threads, but memory snapshots were taken on the main thread
2. **NCCL Initialization Timing**: NCCL buffers (~4.5 GiB for tensor parallelism) were allocated after the memory snapshot in some cases, leading to inconsistent memory measurements. The NCCL buffer allocation shows up as non-torch memory increase during forward pass. 
3. **Inconsistent Behavior**: Replicas would sometimes see 78.59 GiB free memory (before NCCL init) and sometimes 74.07 GiB (after NCCL init), causing the KV cache calculation to fail

### Solution

The fix reorders the initialization sequence to ensure NCCL is fully initialized before taking memory snapshots:

1. **Move NCCL Initialization First**: `init_worker_distributed_environment()` now runs before memory measurement
2. **Force NCCL Initialization**: Added a dummy `all_reduce` operation for tensor parallelism to ensure NCCL buffers are allocated on the correct thread (Note this is already done as part of [pynccl communicator](https://github.com/vllm-project/vllm/blob/main/vllm/distributed/device_communicators/pynccl.py#L104-L107) init)
3. **Consistent Memory Accounting**: Memory snapshots now always include NCCL overhead, providing accurate KV cache calculations

### Code Changes

```python
# Before: Memory snapshot taken before NCCL init
self.init_snapshot = MemorySnapshot()
init_worker_distributed_environment(...)

# After: NCCL init first, then memory snapshot
init_worker_distributed_environment(...)
self.init_snapshot = MemorySnapshot()
```
