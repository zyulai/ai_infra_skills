## PR body
```markdown
Stacks on #43620.

- `MarkovSampleStep` adds a step's bias to the base logits, rounds the sum to the head's step dtype, and picks one token per row: the argmax at temperature 0, a Gumbel-max sample otherwise. Triton and torch implementations.
- The noise is Philox4x32-10 computed in the kernel, keyed by the server seed and countered by (global token id, row, step, a per-block offset). It needs no noise tensor, does not touch the torch generator, and every TP rank draws the same values from the same inputs.
- TP-sharded vocab: without kept logits each rank reduces its shard to one (value, index) pair per block and only those pairs are all-gathered; with kept logits the step logits are gathered once and every rank picks from the full vocab. Either way a step takes one collective.
- A greedy-only variant (no temperature read, no noise code) compiles when no row samples.
- Replaces `sharded_greedy.py`; the DeepSeek-V4.1 greedy graph tail now calls the op.
- Tests: Triton against the torch reference, the greedy-only variant against the mixed one, NaN and inf, ties across blocks, strided rows, the tempered-softmax distribution, noise keying, and sharded against full vocab in both gather modes.

No behavior change: greedy picks are the same argmax with the same lowest-index tie rule.

## Verification

- `test/registered/kernels/ops/speculative/test_dspark_markov_sample.py`: 9 passed on GB300 (torch 2.14.1, Triton 3.8.0).
- Per launch, against the kernels it replaces: the greedy-only variant is no slower than the old sharded greedy step, and sampling rows run 2.0-2.3x faster than the old sampling path. 1024-wide blocks cut a one-row sampled step over a 129280-token vocab from 5.6 to 2.4 us.
```

```diff
+@triton.jit

+    T,
+    OFFSET,
+    P,
+    row,
+    part,
+    i,
+    valid,
+    PARTS,
+    KEY,
+    STEP,

+def _mul32(a: torch.Tensor, b: int) -> tuple[torch.Tensor, torch.Tensor]:
+    # (high, low) 32-bit words of a * b; b splits in halves so int64 never overflows.
+    product_lo = a * (b & 0xFFFF)
+    product_hi = a * (b >> 16)
+    high = (product_hi + (product_lo >> 16)) >> 16
+    low = (((product_hi & 0xFFFF) << 16) + product_lo) & 0xFFFFFFFF
+    return high, low

+def _philox(key: int, c0, c1, c2, c3) -> tuple[torch.Tensor, ...]:
+    """Philox4x32-10, the same function as ``tl.philox``."""
+    k0, k1 = key & 0xFFFFFFFF, (key >> 32) & 0xFFFFFFFF
+    for _ in range(_PHILOX_ROUNDS):
+        hi_b, lo_b = _mul32(c2, 0xCD9E8D57)
+        hi_a, lo_a = _mul32(c0, 0xD2511F53)
+        c0, c1, c2, c3 = hi_b ^ c1 ^ k0, lo_b, hi_a ^ c3 ^ k1, lo_a
+        k0 = (k0 + 0x9E3779B9) & 0xFFFFFFFF
+        k1 = (k1 + 0xBB67AE85) & 0xFFFFFFFF
+    return c0, c1, c2, c3
```
