## 正文(PR 描述)

## Motivation

Fixes #46517.

A `/v1/chat/completions` stream that loses its client can keep decoding. With uvicorn, main already handles the common case: the disconnect cancels the response task, the cancellation reaches `generate_request`, and its cleanup aborts the request (see the GPU run below). Two paths still leak:

- When a send fails, Starlette leaves the body iterator suspended, and on ASGI spec >= 2.4 it also skips the background abort task. Nothing closes `generate_request`, so the request runs to `max_tokens`.
- `_stream_one_response` only checked `is_disconnected()` for non-streaming requests, so a stream kept writing chunks to a dead socket.

## Modifications

- `serving_chat.py`: `_generate_chat_stream` closes its inner `generate_request` generator in a `finally`, `prepend_first_chunk` closes the outer one, and a small `StreamingResponse` subclass closes the body iterator however streaming ends. Closing runs `generate_request`'s existing cleanup (`_release_req_states_on_failure`), which aborts only while the rid still maps to this request's state.
- `tokenizer_manager.py`: run the per-output disconnect check for streaming requests too.

An earlier revision sent forced `AbortReq`s after the request state was gone. The scheduler matches abort rids by prefix, so that could stop an unrelated request (`job` vs `job-1`). Those paths and the `force` flag are removed, and `serving_base.py` is back to main.

## Tests

In `test/registered/unit/managers/test_tokenizer_manager_rid_cleanup.py`:

- `TestChatStreamDisconnect` runs the real `generate_request` through the real `StreamingResponse` ASGI call:
  - a send failure on spec 2.4 aborts the request, and its state is released once the scheduler acks;
  - `http.disconnect` on spec 2.3 aborts the request;
  - closing an already-finished `job` stream sends no abort and leaves `job-1` running.
- An unfinished output for an rid without state sends no abort.
- A disconnected stream aborts before the next chunk is sent.

The send-failure and per-chunk tests fail on main. The `job`/`job-1` test fails if an abort on `GeneratorExit` is added back.

```python
"""Client-disconnect repro for sgl-project/sglang#46517 against a live server.

Sends a long /v1/chat/completions request, drops the TCP connection after
DISCONNECT_AFTER seconds, then samples sglang:num_running_reqs from /metrics.
"""

import json
import re
import socket
import sys
import time
import urllib.request

HOST, PORT = "127.0.0.1", 30000
DISCONNECT_AFTER = 4.0
OBSERVE_SECONDS = 30
MAX_TOKENS = 16000


def running_reqs() -> float:
    body = urllib.request.urlopen(f"http://{HOST}:{PORT}/metrics", timeout=5).read()
    vals = re.findall(rb"^sglang:num_running_reqs\{[^}]*\} ([0-9.e+]+)$", body, re.M)
    return sum(float(v) for v in vals)


def run(mode: str, model: str) -> dict:
    payload = json.dumps(
        {
            "model": model,
            "messages": [{"role": "user", "content": "Write a very long story."}],
            "max_tokens": MAX_TOKENS,
            "ignore_eos": True,
            "stream": mode == "stream",
        }
    ).encode()
    req = (
        f"POST /v1/chat/completions HTTP/1.1\r\nHost: {HOST}\r\n"
        f"Content-Type: application/json\r\nContent-Length: {len(payload)}\r\n"
        "Connection: close\r\n\r\n"
    ).encode() + payload
    sock = socket.create_connection((HOST, PORT))
    sock.sendall(req)
    sock.settimeout(0.5)
    received = 0
    start = time.monotonic()
    while time.monotonic() - start < DISCONNECT_AFTER:
        try:
            chunk = sock.recv(65536)
            if not chunk:
                break
            received += len(chunk)
        except socket.timeout:
            pass
    running_at_disconnect = running_reqs()
    # RST instead of FIN so the server sees the drop as a real client loss.
    sock.setsockopt(socket.SOL_SOCKET, socket.SO_LINGER, b"\x01\x00\x00\x00\x00\x00\x00\x00")
    sock.close()
    t_drop = time.monotonic()

    samples = []
    stopped_after = None
    while time.monotonic() - t_drop < OBSERVE_SECONDS:
        time.sleep(1)
        n = running_reqs()
        elapsed = round(time.monotonic() - t_drop, 1)
        samples.append((elapsed, n))
        if n == 0 and stopped_after is None:
            stopped_after = elapsed
    return {
        "mode": mode,
        "bytes_before_drop": received,
        "running_at_disconnect": running_at_disconnect,
        "stopped_after_s": stopped_after,
        "running_at_end": samples[-1][1],
        "samples": samples,
    }


if __name__ == "__main__":
    label, model = sys.argv[1], sys.argv[2]
    for mode in ("stream", "non-stream"):
        result = run(mode, model)
        print(f"[repro] {label} {json.dumps(result)}", flush=True)
        # Let any still-running request drain before the next case.
        deadline = time.monotonic() + 180
        while running_reqs() > 0 and time.monotonic() < deadline:
            time.sleep(2)
```
