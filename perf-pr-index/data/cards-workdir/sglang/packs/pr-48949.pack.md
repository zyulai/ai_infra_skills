## Motivation

`speculative_sampling_classic_kernel` runs one program per request, and that program scans the whole vocabulary twice: once to sum the residual distribution and once to walk its CDF. A launch therefore costs about as much at one request as at many, and at small batch the device is nearly idle while a few programs each read hundreds of thousands of entries. With a 202,048-entry vocabulary this final-token pass takes 72-113 us per verify step at batch 1-16 on GB300.

## Modifications

- A split path runs the same arithmetic on a (requests x vocabulary tiles) grid. `_split_sum_kernel` repeats the chain walk and reduces one tile; `_split_cdf_kernel` adds the tile sums in tile order to recover the normalizer and the running sum in front of its own tile, then applies the stock tile step. The stock loop takes the first tile with a match and its first matching index, the smallest matching index of the row, so keeping the minimum across tiles with an atomic reproduces the stock token.
- The stock kernel is unchanged. The launcher takes the split path only on CUDA and ROCm devices, when `block_verification` is off, the vocabulary spans more than one tile, and the batch is smaller than the multiprocessor count.
- The arrival counter each row uses to elect a finishing program is reset by that program, so the scratch is reusable in stream order and the launch is safe to capture. The scratch is made once per (device, stream, tile count) with one row per multiprocessor, the gate's bound on the batch, and is never replaced, so a captured graph keeps valid pointers; a capture on a stream with no scratch yet keeps the stock kernel.
- Tests: `test_reject_sampling_split.py` checks every output buffer bit for bit against the stock path across batch, chain depth and vocabulary size, including a 129,280-entry vocabulary, that the scratch made at batch 1 serves the largest batch the gate splits without being replaced, and that a non-CUDA device keeps the stock kernel.

## Accuracy Tests

The split path reproduces the stock outputs exactly: `test_reject_sampling_split.py` passes on GB300 (51 passed with the review fixes; the launcher's other test, `test_block_verification.py`, 25 passed; a CUDA graph captured at batch 1 and replayed after eager calls at the largest split batch matches the stock kernel on every replay), and the benchmark below checks `predicts`, `accept_index` and `accept_token_num` for equality on 7 input variants per configuration (random acceptance, a drafter that proposes the target's top token 70 % of the time, every draft accepted, the first draft rejected, a draft row equal to the target row (zero residual, last-index fallback), final coin 0 and final coin just below 1): identical in all 16 configurations.

End to end on GB300 x4 (`lmsysorg/sglang:nightly-dev-cu13-20261106-858073e4` with this PR's file on top, `meta-models/Muse-Spark-Open-816B-A42B-NVFP4` TP4 / EP4, DFLASH with 8 draft tokens, real acceptance, sampled verification at temperature 1.0): gsm8k through sgl-eval, 1319 questions, top-p 1.0, max 16384 tokens, seed 42. +def _split_scratch(device, num_tiles):
+    """Tile sums, sampled token and arrival counters, one set per (device, stream, tile
+    count), made once and never replaced, so pointers captured in a CUDA graph stay
+    valid. Returns ``None`` while capturing until an eager launch has made the set,
+    because a zero fill recorded under capture runs only when the graph replays."""

+    key = (device.index, stream, num_tiles)
+    scratch = _SPLIT_SCRATCH.get(key)
+    if scratch is None and not torch.cuda.is_current_stream_capturing():
+        # One row per multiprocessor; the gate splits only smaller batches.
+        rows = torch.cuda.get_device_properties(device).multi_processor_count
+        scratch = _SPLIT_SCRATCH.setdefault(
+            key,
+            (
+                torch.empty((rows, num_tiles), dtype=torch.float32, device=device),
+                torch.empty((rows,), dtype=torch.int32, device=device),
+                # Left at zero; _split_cdf_kernel resets each counter it completes.
+                torch.zeros((rows,), dtype=torch.int32, device=device),
+            ),
+        )
+    return scratch

+def _should_split_final_sampling(batch_size, num_tiles, device):
+    """Split only when the stock grid leaves the device idle. One program per request
+    means ``batch_size`` programs; below one per multiprocessor the final-token pass is
+    latency-bound on a few programs each scanning the whole vocabulary, and splitting it
+    into ``batch_size * num_tiles`` programs is strictly more parallelism for the same
+    arithmetic. At or above that point the stock grid already fills the device and the
+    split only adds a second launch and the tile-sum round trip."""
+    # ROCm devices have type "cuda" too; torch.cuda raises on XPU and CPU devices.
+    if num_tiles < 2 or device.type != "cuda":
+        return False
+    # _split_scratch is sized to this bound; a larger bound must grow it too.
+    return batch_size < torch.cuda.get_device_properties(device).multi_processor_count

+    g = torch.Generator(device=DEVICE).manual_seed(seed)
+    target = torch.rand((batch, slots, vocab), device=DEVICE, generator=g)
+    target /= target.sum(-1, keepdim=True)
+    draft = torch.rand((batch, slots - 1, vocab), device=DEVICE, generator=g)

+    # makes the two paths disagree if the split chain walk drifts from the stock one.
+    coins = torch.rand((batch, slots), device=DEVICE, generator=g)

+    )
