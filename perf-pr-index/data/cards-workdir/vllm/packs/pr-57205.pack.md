## PR body
```markdown
Addresses #57200.

Adds a typed `LoggingConfig` to `VllmConfig` with three initial fields:

- `configure_logging`
- `log_level`
- `pylogging_config_file`

The complete object can be supplied as `--logging-config` JSON or with dotted arguments such as `--logging-config.log_level DEBUG`. `--log-level` is a convenience override for `log_level`, while the pre-existing `--log-config-file` is retained as a legacy override for `pylogging_config_file`.

The same model is available through serve YAML and Python configuration. `VLLM_CONFIGURE_LOGGING`, `VLLM_LOGGING_LEVEL`, and `VLLM_LOGGING_CONFIG_PATH` remain as compatibility defaults. Explicit CLI and YAML configuration takes precedence, and the convenience/legacy CLI arguments override their matching `--logging-config` fields.

The resolved configuration is applied after argument parsing and propagated through `VllmConfig` to Uvicorn and API, engine, coordinator, and worker processes. This fixes the asymmetry where a CLI-supplied `--log-config-file` configured Uvicorn but arrived too late for vLLM's already-initialized root logger. Code that previously inspected `VLLM_LOGGING_LEVEL` directly now uses the effective logger level.

The existing default text output and custom Python `dictConfig` behavior are preserved. Tests cover JSON and dotted CLI forms, CLI/YAML/environment precedence, post-import reconfiguration, custom configuration files, and spawned-process propagation.

Co-authored-by: AI Assistant <noreply@openai.com>

```
