  ## Purpose

 Fixes RFC [#56816 ](https://github.com/vllm-project/vllm/issues/56816)

  Add a watchdog mechanism to vLLM V1 to automatically capture all-thread stack
  traces when the engine or worker process stops making progress, making it easier
  to diagnose hangs and deadlocks.

  - **New `vllm/utils/watch_dog.py`**: introduces the `WatchDog` class. A background
    daemon thread monitors a heartbeat (`feed()`); if the heartbeat is not refreshed
    within a timeout (default 300s, checked every 10s), it dumps the stack traces of
    all threads via `faulthandler` into a per-process log file
    (`VLLM_STACK_DUMP_for_<name>_<pid>.log`). Repeated timeouts without an intervening
    feed are logged only once. Provides `feed()` / `dump_stack()` / `start()` /
    `stop()` and a process-wide singleton `get_watch_dog()`.
  - **EngineCoreProc**: creates and starts a watchdog named `engine` after startup and
    feeds it while processing the input queue and before each engine step. The input
    queue `get()` now uses `timeout=5` so the loop stays responsive while preserving
    the original blocking semantics. The shutdown signal handler dumps all thread
    stacks for diagnosis.
  - **WorkerProc** (multiproc executor): likewise creates and starts a watchdog named
    `worker` and feeds it before executing every worker method; its signal handler
    dumps all thread stacks.

+        self.active = False
+        try:
+            yield
+        finally:
+            self.active = True

+        with self.lock:

+                self.dump_stack(reason)
+            else:

+                f.write("\n" + "=" * 64 + "\n")

+            )

+            if not self.thread.is_alive():
