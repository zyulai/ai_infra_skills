## Details

### Motivation

[#60683](https://github.com/vllm-project/vllm/pull/60683) currently requires speculative decoding and only routes spec-verification steps through the Kimi-K3 MonoKernel. Ordinary autoregressive decode is refused at configuration time even though its one-token decode shape can use the existing `qlen=1` K1 specialization and K2 kernels.

This change removes only that restriction and adapts regular-decode metadata to the existing kernel interface.

### Design

For regular decode:

- `non_spec_state_indices_tensor` supplies one KDA state slot per active row.
- State indices are exposed to K1 as `[requests, 1]`.
- A device-resident tensor of ones supplies graph-stable accepted-token counts.
- Eligibility requires:
  - no prefill rows;
  - no speculative rows;
  - one regular-decode row per active request;
  - valid one-dimensional state indices;
  - launch width no greater than 16.

When speculative decoding is configured, the existing spec-verification path remains unchanged.

### Limitations

The existing [#60683](https://github.com/vllm-project/vllm/pull/60683) constraints remain:

- MI355X/gfx950.
- TP8.
- FULL CUDA graphs for decode.
- Pure decode steps only.
- Maximum specialized-decode width of 16 rows.

Other steps continue using standard vLLM execution, including uniform decode steps wider than `min(max_num_seqs, 16)`.

### Performance
`vllm bench serve`, 64K shared cached prefix + 16K unique input, forced 1K output with ignore-EOS, 16 warm-ups, and `10 × concurrency` measured prompts. Off and on use the same image and server settings; only `--additional-config '{"decode_backend":"latency_specialized"}'` differs.
