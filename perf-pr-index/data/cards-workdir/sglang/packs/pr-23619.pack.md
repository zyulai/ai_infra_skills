## PR body
```markdown
## Summary

- Route Qwen3-Next decoder MLP outputs through `LayerCommunicator.should_fuse_mlp_allreduce_with_next_layer`, matching the existing MoE all-reduce fusion pattern used by related Qwen MoE model code.
- Mark fused-path MoE outputs with `_sglang_needs_allreduce_fusion` so the next layer can use all-reduce + RMSNorm fusion when supported.
- Keep the PR code change scoped to `python/sglang/srt/models/qwen3_next.py`; the earlier unit test addition was removed from this PR.

## SGLang Base vs Optimized Validation

Comparison is SGLang-only: base/main commit `b3e6cf60aaed73dcca07626c06beb8e5e477ed65` vs optimized commit `aa675c1b9a55881790a06cfa69bf178d70cfdb1a`.

Environment:

- Model: `Qwen/Qwen3-Next-80B-A3B-Instruct`
- Hardware: single-node H100 TP4
- Physical GPU ids: `0,2,3,4`
- `CUDA_VISIBLE_DEVICES=0,2,3,4`; framework-visible mapping `0->physical0, 1->physical2, 2->physical3, 3->physical4`
- Note: GPU `4,5,6,7` were requested, but physical GPU `6,7` were already occupied by unrelated `/data/sglang-omni` processes, so this isolated run used currently free H100s.
- Shared server flags: `--tp-size 4 --mem-fraction-static 0.82 --schedule-policy lpm --prefill-attention-backend fa3 --decode-attention-backend fa3 --chunked-prefill-size 8192 --max-running-requests 128 --context-length 12288 --cuda-graph-max-bs 32 --trust-remote-code`
- Artifact root: `/data/bbuf/validate/pr23619_qwen3_next_allreduce_fusion_20260424_sglang_base_vs_patch`

### Serving Benchmark

Both scenarios use the cookbook random workload with 80 prompts, request rate 12, max concurrency 16, temperature 0.0.

| Scenario | Metric | Base/main | Optimized | Delta |
|---|---:|---:|---:|---:|
| chat 1000->1000 | Request throughput | 2.61 req/s | 2.73 req/s | +4.6% |
| chat 1000->1000 | Output throughput | 1332.73 tok/s | 1392.62 tok/s | +4.5% |
| chat 1000->1000 | Mean TTFT | 88.08 ms | 88.89 ms | +0.9% |
| chat 1000->1000 | Mean TPOT | 10.48 ms | 9.98 ms | -4.8% |
| summarization 8000->1000 | Request throughput | 2.72 req/s | 2.75 req/s | +1.1% |
| summarization 8000->1000 | Output throughput | 1419.07 tok/s | 1433.68 tok/s | +1.0% |
| summarization 8000->1000 | Mean TTFT | 97.42 ms | 110.06 ms | +13.0% |
| summarization 8000->1000 | Mean TPOT | 10.05 ms | 9.90 ms | -1.5% |

The consistent gain is throughput and mean TPOT. Mean TTFT is nearly unchanged for the chat workload and higher for the summarization workload in this single run.

From the earlier real-model SGLang profiler on the same Qwen3-Next TP4 setup, the patch reduced the prefill NCCL all-reduce hotspot:

| Stage | Kernel | Before | After |
|---|---|---:|---:|
| prefill/extend | `ncclDevKernel_AllReduce_Sum_bf16_RING_LL` | 303.8 ms / 34.3% | 177.5 ms / 26.2% |

Remaining known hotspots after this patch are MoE kernels and BF16 GEMM paths; this PR intentionally keeps the change focused on enabling the missed Qwen3-Next MoE all-reduce fusion path.
```
