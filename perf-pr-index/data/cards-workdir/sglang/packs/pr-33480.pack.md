## Motivation
DeepSeek V4 prefill context parallelism (CP) distributes long-context prefill across attention CP ranks, but introduces several per-layer CP collectives around attention and MoE. Previously, the DeepSeek V4 two-batch-overlap (TBO) path only supported non-CP DP/EP workflows:
- `--enable-prefill-cp` with `--enable-two-batch-overlap` was rejected when DP attention was disabled.
- CP batches were explicitly excluded by the runtime TBO gate.
- Existing TBO operations only handled DP/EP communication and could not schedule CP all-gather/reduce-scatter operations.
This PR enables TBO for the AMD/ROCm DeepSeek V4 DSA prefill CP path. Each eligible prefill batch is split into two sub-batches so that one sub-batch's CP MoE communication can overlap with the other sub-batch's attention and expert computation. Attention-side KV and `kv_score` all-gathers are also launched early and hidden behind projection, indexer, and compressor computation.
The goal is to reduce TTFT and improve long-context prefill throughput while preserving CP-only accuracy and leaving existing CUDA and non-CP behavior unchanged.

## Modifications

- Add a HIP-only CP-aware TBO forward path for DeepSeek V4:
  - Split each prefill batch into two independently managed sub-batches.
  - Rebuild CP metadata and round-robin split `hidden_states`, `positions`, and `input_ids` for each sub-batch.
  - Restore each sub-batch from CP layout and merge the outputs after overlapped execution.
- Add a CP-specific TBO operation schedule:
  - Overlap one sub-batch's MoE all-gather with the other sub-batch's attention computation.
  - Overlap one sub-batch's reduce-scatter with the other sub-batch's MoE computation.
  - Use persistent buffers and stream events to safely manage asynchronous communication.
- Add a duplicate `attn_cp_overlap` communicator over the same CP ranks. This allows collectives on the communication stream to execute concurrently with attention collectives on the compute stream without driving the same RCCL communicator from multiple streams, which can deadlock.
- Add split-phase CP all-gather helpers:
  - Launch KV and `kv_score` all-gathers as soon as their inputs become available.
  - Delay synchronization until immediately before the gathered tensors are consumed.
  - Keep communication inputs alive until completion to prevent allocator reuse.
- Update validation and fallback logic:
  - Enable CP+TBO only for HIP, DSA prefill CP with round-robin split, CP-v1, non-EP TP-MoE, single-stage PP, and valid sub-batches.
  - Fall back to the original eager path for unsupported or undersized batches.
  - Align TBO padding with both TP and CP requirements.
  - Preserve the existing behavior on NVIDIA/CUDA and non-CP paths.
- Add an AMD 8-GPU DeepSeek V4 Pro FP4 nightly test covering CP+TBO startup, high-concurrency GSM8K accuracy, per-sub-batch CP metadata, and concurrent-communicator stability.

base | baseline)
    ARGS=()
    ;;

    ARGS=(--enable-prefill-cp --cp-strategy interleave)
    ;;

    ARGS=(--enable-prefill-cp --cp-strategy interleave --enable-two-batch-overlap)
