## Purpose

Capture the rest of the DFlash/DSpark context preparation in the draft's FULL CUDA graph, ahead of the query forward: combine the target's auxiliary hidden states, publish the LiLiCorr context anchor, then precompute the context K/V. #57632 captured only the last step; the first two still ran eagerly before every replay.

- The target's auxiliary states are staged into a fixed-address buffer before replay. The buffer is allocated at capture, only when the draft captures FULL graphs, so memory profiling accounts for it and an eager fallback does not hold it.
- LiLiCorr owns a fixed-address copy of the rejection counts its anchor reads; DFlash, DFlash2 and DSpark skip that copy.
- Context rows beyond the graph's capacity, and non-FULL paths, still run eagerly.
- The eager warmup before capture is preserved, including the Kimi-K3 cache-pointer refresh from #58814.

Applies to the shared DFlash, DFlash2, DSpark and LiLiCorr path. Open-PR searches for `dflash graph context`, `combine_hidden_states` and `57632 in:body` found no PR capturing this prologue; #50658 instead moves Kimi-K3 auxiliary projection before the SP all-gather.

## Test Plan

- E2E decode ITL: TP4 + DSpark serving benchmark, base vs PR vs base again on one node.

- Unit tests, including a new CUDA graph test of the captured context step.
