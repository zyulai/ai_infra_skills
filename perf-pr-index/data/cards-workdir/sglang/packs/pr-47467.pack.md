## Motivation

Qwen-Image-2.1 T2I encodes the prompt with the Qwen3-VL text model: ~2600 small kernels and 40 ms of host time for ~10 ms of GPU work on B300, all of it before the first denoising step. Under `--async-output-save` the next request could not even start encoding early: the processor outputs were uploaded with a pageable copy, which first waits for the previous request's queued denoise and decode.

## Modifications

- `TextEncoderGraphs` (Qwen-Image-2.1 encoding stage): the text-only encoder forward is captured per prompt length on its second request and replayed afterwards. A replay runs the same kernels, so the output is bit-identical. Image-conditioned prompts, tensor parallel encoders and non-resident weights stay eager; a change of any parameter or buffer address (offload, reload, replacement) drops the graphs; at most 8 lengths are kept; a capture failure falls back to eager for good.
- `upload_without_sync`: processor and tokenizer outputs go to the GPU from pinned memory (the Qwen-Image-2.1 stage and the generic `TextEncodingStage`, which already asked for `non_blocking=True` on pageable memory).
- Test: replay matches eager bit for bit, image inputs stay eager, replaced weights drop the graph.

## Accuracy

Bit-identical: decoded PNG pixels of every T2I and edit request match main (md5 of the RGBA array).

+        weights = tuple(t.data_ptr() for t in tensors)

+def upload_without_sync(batch, device):
+    """Move a batch of host tensors to `device` without waiting for the GPU work already queued.
+
+    A pageable host-to-device copy synchronizes its stream first; a pinned one does not.
+    """
+    if torch.device(device).type != "cuda" or not torch.cuda.is_available():
+        return batch.to(device)
+    pinned = type(batch)(
+        {
+            k: v.pin_memory() if torch.is_tensor(v) and v.device.type == "cpu" else v
+            for k, v in batch.items()
+        }
+    )
+    return pinned.to(device, non_blocking=True)
