## Disclosure

AI assistance was used. The changes were reviewed and tested manually.

## Purpose

Allow online quantization on the unquantized `linear` or `moe` (or fine-grained `targets`) portions of a partially pre-quantized checkpoint **from ANY `quant_method` (Quark, ModelOpt, compressed-tensors, etc.)**. 

The original `quant_method` remains responsible for its pre-quantized layers, the composed config applies the requested online method only when the checkpoint returns an unquantized method.

Example use cases:
- Supersedes https://github.com/vllm-project/vllm/pull/49313 that attempts to do the same for `amd/GLM-5.2-MXFP4` that quantizes only the MOE layers.
- Supersedes https://github.com/vllm-project/vllm/pull/48983 that attempts to do the same with modelopt checkpoint
- Take e.g. [`nvidia/Qwen3.5-122B-A10B-NVFP4`](https://huggingface.co/nvidia/Qwen3.5-122B-A10B-NVFP4) (modelopt checkpoint) or [`amd/Qwen3.5-397B-A17B-MXFP4`](https://huggingface.co/amd/Qwen3.5-397B-A17B-MXFP4) (quark checkpoint) that apply non-shared MOE expert only quantization, and quantize additional layers as needed (for evaluation or optimization purposes
- Relax the need to release several models with different preset pre-quantized layers / different ignore lists).
- Eventually, support `shared_experts` online quantization +fusion (not in this PR, see draft https://github.com/fxmarty-amd/vllm/pull/6)

This PR will work nicely with https://github.com/vllm-project/vllm/pull/51285 once it is merged.

Implementation details:

- Online quantization is stored as `QuantizationConfig.online_quant_config`. `QuantizationConfig.get_effective_quant_method` **resolves the global quant method, including both the base checkpoint quant method and the online quant method**. The original `QuantizationConfig` subclass instantiation is preserved (e.g. `Fp8Config`), so **model developers do not need to be aware of this online quantization composition** (see examples below).
- Selected layers for `online` that are already pre-quantized fail clearly instead of being silently replaced.
- Activation-only overrides remain owned by the original checkpoint quantizer
- `quantization_config.ignore` excludes applies only to `online`, as done currently on `main`.

Preserving the original checkpoint config type is required for existing model-specific behavior:

- Quark Qwen3Next shared-expert fusion reads Quark exclusion metadata and controls fusion: https://github.com/vllm-project/vllm/blob/4f76c8ad9d8ec06e91ac9c84895e07a1913d7726/vllm/model_executor/models/qwen3_next.py#L81-L98 https://github.com/vllm-project/vllm/blob/4f76c8ad9d8ec06e91ac9c84895e07a1913d7726/vllm/model_executor/models/qwen3_next.py#L154-L162
- Kimi K2.5 checks for `CompressedTensorsConfig` before quantizing its multimodal projector: https://github.com/vllm-project/vllm/blob/4f76c8ad9d8ec06e91ac9c84895e07a1913d7726/vllm/model_executor/models/kimi_k25.py#L393-L396
- GLM4.1V selects a compressed-tensors-specific QKV prefix: https://github.com/vllm-project/vllm/blob/4f76c8ad9d8ec06e91ac9c84895e07a1913d7726/vllm/model_executor/models/glm4_1v.py#L303-L308
- Qianfan OCR applies `Fp8Config` visual-layer safety exclusions: https://github.com/vllm-project/vllm/blob/4f76c8ad9d8ec06e91ac9c84895e07a1913d7726/vllm/model_executor/models/qianfan_ocr.py#L69-L92

Behavior change from `main`: `--quantization-config` can now be used with a checkpoint `quant_method` for online weight composition. A request that selects an already pre-quantized layer now fails clearly instead of replacing the checkpoint method.

+### Online quantization on unquantized layers from partially-quantized checkpoints
+
+Online quantization can be used on already quantized checkpoints independently of their original `quant_method` (`modelopt`, `compressed-tensors`, `quark`, etc.), for layers that are left unquantized in the original checkpoint.
