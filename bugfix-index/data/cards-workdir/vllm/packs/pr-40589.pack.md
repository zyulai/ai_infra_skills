## 正文(PR 描述)

## Purpose
Add a drafter.dummy_run() when proposed_daft_token_ids is skipped to maintain consistency with the behavior of dummy_run executed by other DP.

I runned the DeepSeek-R1 bench test with dp 4 tp 2 mtp 3, and set the max-model-len as 4100 to meet the limit greater than input-len+output-len.  But found a hang issue caused by one dp's proposed_daft_token_ids skipped for max_seq_len(4098) + num_spec_token(3) > max_model_len(4100), while other dp still running drafter.dummy_run().

## Test Plan
`vllm serve /models/DeepSeek-R1 --trust-remote-code --distributed-executor-backend mp --max-model-len 4100  --gpu-memory-utilization 0.92 -dp 4 -tp 2  --no-enable-prefix-caching --max-num-seqs 128 --max-num-batched-tokens 2048 --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
`
`vllm bench serve /models/DeepSeek-R1 --dataset-name random --num-prompts 32 --max-concurrency 32 --random-input-len 3072 --random-output-len 1024 --ignore-eos`

## Test Result
The original implementation would hang, but now it can pass
