- Also noticed that we didn't use vectorization for per_token cuda kernel, after adopt that technique, it's 20%-25% faster than previous implementation.
- Instead of using flashinfer vec's cast_load, we need to manually load each element to prevent `misanligned address` error when `hidden_dim % 8 != 0` 


### Learning:

#### 1. We cannot do `flashinfer:vec_t.cast_load` when `hidden_dim % 8 != 0`
![image](https://github.com/user-attachments/assets/a6bd4101-8df1-436e-a7ff-ea20deecb31d)
We need to handle flashinfer:vec carefully like this otherwise it will hitting error like `misaligned address`

#### 2. Why `per_tensor` and `per_token_group` quant kernel can do `flashinfer:vec_t.cast_load` when `hidden_dim % 8 != 0`?
- per tensor: `input_vec.cast_load(input + i * vec_size);`
- per token group: 
    ```cpp
    const T* group_input = input + block_group_offset;
    block_group_offset = (block_group_id + local_group_id) * group_size;
    ```
- per token: `token_input = input + token_idx * hidden_dim;`

Hence, we can see `per_tensor` and `per_token_group` are loading 8 elements each and deal with the rest of remaining elements.
However, in `per_token` (if hid_dim = 11), we are loading the first 8 element using cast_load and load 3 remaining in first thread.
The second thread (tho it will run concurrently but let's assume it's sequentially to make it intuitive), will read from the element 12 - 17 (12,13,14,15,16,17,18,19) and load rest of three element (20,21,22)

However, cast_load will require the address to be aligned with 8 element (or 4 if we load float32). Hence we will hitting misaligned address issue)

Thanks for @zcnrex for debugging on this and deliver the insightful learning! 

#### 3. Since hidden_dim will be multiple of 8 in all of observed models, we will just add a check and do cast_load directly without handling remaining elements
