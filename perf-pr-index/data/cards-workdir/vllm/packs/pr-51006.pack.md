## Overview

Make `FusedMoERouter` a `PluggableLayer`, using the same OOT class registration already supported by `MoERunner` and `RoutedExperts`. Unregistered model-specific classes retain their implementations.

Related: #51005. This updates the existing PR; EPLB lifecycle work remains separate in #49700.

## Claims

- Reuse construction-time `PluggableLayer` dispatch instead of adding Platform hooks or another registry.
- Preserve explicit router instances, model-specific constructors and weight loaders, expert substitution, and optional EPLB state.
- Document concrete-class registration, the replacement subclass contract, and shared correction-bias parameter ownership.

## Details

The factories instantiate their selected classes normally; `PluggableLayer` resolves registrations by concrete class name. Register each supported model-specific class separately and derive its replacement from that class, preserving its constructor and execution contract.

As a PyTorch module, a router can expose aliases of shared correction-bias parameters in `state_dict()`. The model comparison added such aliases while preserving the canonical loading names and parameter identity. The plugin guide explains how to retain the model's gate-owned checkpoint path.
