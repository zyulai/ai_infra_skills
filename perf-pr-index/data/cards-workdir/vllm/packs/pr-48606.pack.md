## Summary

Adds a **native Quark** loading path for `real_quantized` INT4/UINT4 checkpoints (`export.pack_method` = `order` / `reorder`).

- `QuarkW4A16Int4` for dense layers and `QuarkW4A16Int4MoEMethod` for routed experts
- Quark pack order canonicalization to the layout used by existing `awq_*` ops (**compute kernel layout only**)
- Both symmetric INT4 and asymmetric UINT4 MoE experts use the shared WNA16 oracle backend (`TritonWNA16Experts`)

**Mixed FP16 modules:** MoE router (`mlp.gate`) and other FP16 layers must appear in `quantization_config.exclude`. vLLM does not infer this from tensor dtypes; Quark export should persist all `exclude_layers_name` patterns (see Quark issue for `*mlp.gate` not written to config).

**Why not a duplicate PR:** No existing PR adds native Quark `real_quantized` W4A16 INT4/UINT4 support with MoE + Qwen3.5 loading.

**AI assistance:** Used for implementation and tests.

## GSM8K Evaluation (Qwen3.6-35B-A3B, 5-shot)

Evaluated on [Qwen3.6-35B-A3B](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) quantized checkpoints using this PR's Quark W4A16 loading path. All three runs use identical lm-evaluation-harness settings; a `<think>\n\n</think>\n\n` prefix is injected at the answer position to suppress the thinking preamble uniformly across models.

|-------|----------------------:|-------------------:|
| [Qwen3.6-35B-A3B BF16](https://huggingface.co/Qwen/Qwen3.6-35B-A3B) (baseline) | 0.9158 ± 0.0076 | 0.9090 ± 0.0079 |
