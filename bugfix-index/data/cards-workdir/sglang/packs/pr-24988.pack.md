## 正文(PR 描述)

## Motivation

In `DenoisingStage`, `target_dtype` was hardcoded to `torch.bfloat16`, ignoring the user-configured `pipeline_config.dit_precision` setting. This is inconsistent with other stages (e.g., `helios_denoising`, `mova`) that correctly use `PRECISION_TO_TYPE[server_args.pipeline_config.dit_precision]` to determine the target dtype.

This bug means that even if a user explicitly sets `dit_precision` to `fp16` or `fp32`, the denoising stage would still forcefully cast tensors to `bfloat16`, causing precision loss and potentially degrading generation quality — especially for models that are trained or fine-tuned in `fp16` or `fp32`.

## Modifications

- Changed `target_dtype` in `DenoisingStage` from hardcoded `torch.bfloat16` to `PRECISION_TO_TYPE[server_args.pipeline_config.dit_precision]`, making it consistent with other stages (e.g., `helios_denoising`, `mova`).

## Accuracy Tests

- **Fix**: Previously, when `dit_precision` was set to `fp16` or `fp32`, the denoising stage would still run in `bfloat16`, introducing unintended precision loss (e.g., `fp32` → `bfloat16` truncation). After this fix, the stage correctly respects the configured precision, preserving numerical accuracy for models that require higher or different precision.
- When `dit_precision` is set to `bfloat16` (the common default), behavior is identical to before.

## Speed Tests and Profiling

- No performance impact. This is a one-line config lookup replacing a hardcoded constant.
