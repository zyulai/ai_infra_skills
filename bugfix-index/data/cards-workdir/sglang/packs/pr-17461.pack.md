### Problem

The `test_triton_attention_kernels.py::test_extend_attention` test fails sporadically with an `AssertionError` at the second iteration's `torch.allclose()` check, even though the actual numerical differences between `o_extend` and `o_redundant` are within acceptable bounds for bfloat16 precision.

### Root Cause

The assertion used `torch.allclose(o_extend, o_redundant, rtol=1e-2)` with the default `atol=1e-8`. The `torch.allclose` function checks: `|a - b| <= atol + rtol * |b|`.

When tensor values are close to zero, the tolerance becomes approximately `atol` (since `rtol * |b|` ≈ 0). The default `atol=1e-8` is far below bfloat16's precision:

- **bfloat16 epsilon:** ~0.0078 (7.8e-3)
- **Observed max absolute diff:** ~0.001 (1e-3)
- **Default atol:** 1e-8

The observed difference of 0.001 is well within expected bfloat16 rounding error, but the assertion failed because values near zero had a tolerance of only 1e-8.

### Solution

Added `atol=1e-3` to both `torch.allclose()` assertions to properly accommodate bfloat16's limited precision while still catching meaningful numerical differences.

```
...
===== Pass Rate: 10/10 (100%) =====
```
