## PR body
```markdown
## Summary

- Keep the EAGLE chunked-prefill tail-token update asynchronous on the device.
- Compute the sparse-prefill SWA allocation length from existing CPU sequence lengths.

## Why

The scalar tail-token assignment and `swa_offsets[-1].item()` both serialize the CUDA stream during chunked prefill. The latter otherwise becomes the next blocking point after removing the former.

## Performance

Same c384 AgentX workload, 8 prefill + 8 decode GPUs, and 1,800-second profiling window:

| Metric | Baseline | This PR | Change |
| --- | ---: | ---: | ---: |
| Prefill throughput | 66.9K tok/s | 75.3K tok/s | +12.6% |
| TTFT p50 | 19.49s | 13.34s | -31.6% |
| Total throughput | 1.312M tok/s | 1.482M tok/s | +12.9% |

Prefill throughput is the actual new-token rate across the eight prefill ranks during the formal window. TTFT and total throughput are from the profiled AIPerf requests. Both runs completed with zero profiled request errors.

## Validation

Nsight identified both synchronization points. No new test file is added.
```
