## 正文(PR 描述)

## Purpose

Fixes the chain of three bugs reported in #39809 that crash NemotronH (and other hybrid Mamba2) models when prefix caching `all` mode is combined with speculative decoding.

This PR also reverts the temporary workaround merged in #40454.

### Evaluation

Verified end-to-end with `tests/evals/gsm8k/gsm8k_eval.py` against NVIDIA Nemotron 3 Super using a shared few-shot prefix to exercise the cache. The full `(PC-off, PC-align, PC-all) × (CUDA graphs, --enforce-eager)` matrix all land at ~92% accuracy, confirming `PC all + SpecDec` is correctness-equivalent to the existing baselines. The logs also show a prefix cache hit rate of around 75%, for both `align` and `all` modes.

### Solution overview

The three issues share a root cause: in `mamba_cache_mode='all'` + spec decode the kernel reads/writes `1 + num_speculative_blocks` consecutive state slots per request, but the surrounding bookkeeping treated the block table and per-request indices as if no speculative slots were reserved. Concretely:

1. `state_indices_tensor_d` is now sized to `cdiv(max_model_len, block_size) + num_speculative_blocks` so each request's block table addresses every slot the kernel actually touches. `MambaSpec.max_memory_usage_bytes` and the `mamba_get_block_table_tensor` docstring updated to match.
2. The persistent `block_idx_last_*` buffers used during CUDA graph capture are now padded to `num_reqs` (matching how the kernel indexes them) instead of `num_decode_tokens`.
3. When fewer drafts are accepted than scheduled, the next step's read anchor must point to the slot the previous step actually wrote — `(num_computed - 1) // block_size` no longer matches because `num_computed` reflects only accepted tokens. Tracked per request in `mamba_state_idx` and plumbed to the kernel as `block_idx_last_scheduled_token_prev_step`.

## Test Plan

Two new regression tests added `tests/v1/attention/test_mamba_update_block_table.py`:
- test_state_indices_tensor_d_includes_num_speculative_blocks
- test_block_idx_cudagraph_capture_padded_by_num_reqs

Both fail on main without this PR and pass with it.

End-to-end reproducer from #39809 on a 4×GB200 host:

```bash
vllm serve nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-NVFP4 \
--enable-prefix-caching --mamba-cache-mode all \
--trust-remote-code \
--tensor-parallel-size 4 \
--speculative-config '{"method":"mtp","num_speculative_tokens":1}'
```

Sent the same long prompt twice and observed vllm:prefix_cache_hits_total.

## Test Result

Unit tests: 2 passed, 0 failed.

```

tests/v1/attention/test_mamba_update_block_table.py::test_block_idx_cudagraph_capture_padded_by_num_reqs PASSED
```

- test_state_indices_tensor_d_includes_num_speculative_blocks fails with
