## 正文(PR 描述)

## Motivation

After CRIU restore, the process CPU clock can be below the scheduler's saved accounting baseline. The resulting negative delta causes the Prometheus counter to raise `ValueError`, terminating the restored scheduler when metrics are enabled.

Without a time namespace, restoring on a host with less uptime also moves the monotonic clock backwards. Scheduler time accounting then stalls until the clock catches up, and stage metrics accumulate negative wall time that crashes the same way when drained.

## Modifications

- Count the restored CPU clock reading as CPU time since restore instead of a negative delta, so the counter never decrements.
- Flush buffered idle and stage totals before rebasing scheduler time accounting when the monotonic clock moves below the last sample.
- Preserve the active stage and reset the forward-occupancy window.
- Drop backwards spans in `SchedulerStageMetricsRecorder` so drained totals stay non-negative.

Add regressions for repeated CPU clock resets during idle and active scheduling, monotonic clock resets, and preservation of buffered totals and an active stage across a reset between reporting ticks.
