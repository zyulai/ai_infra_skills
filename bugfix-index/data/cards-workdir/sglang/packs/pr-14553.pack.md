## 正文(PR 描述)

Fix B200 CI failure that caused #14093 to be reverted in #14550.

Original issue discovered in CI run:
https://github.com/sgl-project/sglang/actions/runs/19985523381/job/57335123826?pr=14493

Root cause:
- layer.k_scale/v_scale are torch.nn.Parameter (0-D tensors)
- Triton interprets tensor arguments as pointers
- Expression '1.0 / k_scale' in kernel caused IncompatibleTypeError

Solution:
- Convert tensor scales to Python float in wrapper before kernel launch
- Handles None, Tensor, and scalar cases explicitly
- Preserves per-tensor scaling semantics

Testing:
- Added regression test test_fp8_kv_kernel_accepts_tensor_scales
- Verified on local environment with ATTN_BACKEND=trtllm_mha
- All 11 kernel tests pass, including new regression test
- test_llama31_fp4.py::TestLlama31FP4B200::test_gsm8k passes

## Motivation

Fix the Triton `pointer<fp32>` vs `float32` type error on B200 when using the fused FP8 KV cache path for TRTLLM MHA, which breaks Llama-3.1-FP4 CI.

## Modifications

- Normalize `layer.k_scale` / `layer.v_scale` into Python float scalars in `fused_fp8_set_kv_buffer` so Triton does not treat them as `pointer<fp32>`.
- Add a regression test `test_fp8_kv_kernel_accepts_tensor_scales` to cover the 0-D tensor scale case.

## Accuracy Tests

- `pytest test/manual/test_trtllm_fp8_kv_kernel.py -vv`
- `ATTN_BACKEND=trtllm_mha pytest test/srt/test_llama31_fp4.py::TestLlama31FP4B200::test_gsm8k -vv`

Both pass on a B200 box.
