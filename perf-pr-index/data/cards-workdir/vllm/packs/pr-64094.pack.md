## PR body
```markdown
## Overview

Re-enable DeepSeek-V4.1 prefix-cache sliding-window bounded replay on gfx950. Decoder replay is a separate path and is already enabled by #59039 when `cache_config.swa_bounded_replay` is on. This PR only restores the prefix-cache path from #57906.

The AITER sparse MLA path consumes slot IDs that `_compute_swa_indices_and_lens_kernel` has already clamped to `replay_start`. The ROCm force-off in `attention.py` stays in place for every ROCm GPU other than gfx950, including gfx942. On gfx950 the sliding-window cache follows `cache_config.swa_bounded_replay`.

## Claims

- On gfx950, prefix-cache SWA replay is no longer forced off. The flag still defaults on, and `--no-swa-bounded-replay` still disables it. Other ROCm GPUs stay on the existing force-off path.
- On our best MI355X config, end-to-end throughput is 13.5% higher at concurrency 128 and 12% higher at concurrency 256.
- GSM8K and RULER NIAH are unchanged between stock and replay.

## Validation

GSM8K, 1,319 questions, 5-shot, temperature 0, all questions in flight:

| Arm | Accuracy |
|---|---:|
| Stock, replay off | 0.904
| Replay on | 0.902

RULER `niah_single_1` (single needle, word key, number value, repeated haystack), 131,072 tokens, 5 samples, temperature 0:

| Arm | Score |
|---|---:|
| Stock, replay off | 1.0 |
| Replay on | 1.0 |

Prefix-cache sweep across the prefill-chunk boundary. Each point primes eight DP replicas with a shared prefix plus 128 new tokens, then repeats the query. `vllm:prefix_cache_hits_total` is the hit signal. Every second-wave request completed on both arms, with no GPU fault.

| Prefix tokens | Stock hit tokens | Replay hit tokens |
|---:|---:|---:|
| 1,920 | 15,360 | 15,360 |
| 2,048 | 16,256 | 16,384 |
| 2,176 | 17,280 | 17,408 |
| 4,096 | 32,640 | 32,768 |

A separate single-request check on an otherwise stock nightly (`00b6c4c`, chunk 2048, DEP8, one request, token-id prompts) shows the config-flag A/B. Warmed requests:

| Shape | Stock | Replay |
|---|---:|---:|
| 8k TTFT | 492 ms | 316 ms |
| 32k TTFT | 1.84 s | 1.23 s |

Decode does not change. A decode step is already one new token inside the window.

CI does not have this MI355X checkpoint, so Buildkite does not cover this path.

## Details

DeepSeek-V4.1-Flash has 40 layers. KV is written at layers 2, 8, 14, and 20. The sliding window is 128 tokens. After layer 20 has written KV for a token, layers 21–39 only need the last 128 tokens. That trim is decoder replay (#59039). It is built from `cache_config.swa_bounded_replay` and is already active on ROCm when the flag is left on.

This change is the prefix-cache half. On a prefix-cache hit, the SWA cache replays from `replay_start` instead of storing the full sliding window. gfx950 can take that path because AITER sparse MLA uses the already-clamped slot list. The old force-off assumed an extra clamp inside the FlashInfer and FlashMLA prefill kernels, which this path does not use. gfx942 cannot take AITER sparse MLA, so it stays forced off.

To enable it on a gfx950 recipe that sets `VLLM_NO_SWA_BOUNDED_REPLAY=1`, remove that setting. Keep model runner V2 and breakable CUDA graphs. A 4096-token prefill chunk is above the 768-token replay trim threshold, so it uses the trimmed graph.


## ROCm consumers

CDNA4 keeps prefix-cache SWA replay. Both ROCm consumers clamp to replay_start:

- Opt-in AITER sparse MLA reads slot ids from _compute_swa_indices_and_lens_kernel, which clamps start_pos.
- The default Triton gather path clamps the prefill gather length in ComputePrefillMetadataKernel and clamps swa_start again in combine_topk_swa_indices.

Every other ROCm GPU, including CDNA3, stays forced off. get_cdna_version() != 4 is the gate.
Limitations:

- Measured on gfx950 with the AITER Triton sparse MLA path.
- The flag defaults on, so gfx950 behavior changes for every DeepSeek-V4.1 server that does not pass `--no-swa-bounded-replay`.
```
