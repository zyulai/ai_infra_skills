## 正文(PR 描述)

## Context

Prior to this PR, turning on `ec_both` on aggregated node will crash the program

- vLLM won't allocate KV cache because it thought itself only does encode (which is wrong)
- engine.py won't update `model_executed` so that forward pass won't work either

------

details --

- When https://github.com/vllm-project/vllm/issues/25233 introduced disagg encoder, it has assumptions that `is_producer` refers to workers that are only encoding, but not prefilling
- With https://github.com/vllm-project/vllm/pull/34182, an aggregated node with `ec_both` can be both producer and consumer, while outputting tokens
    - These P/PD workers need KV cache by nature
    - The assumption of "`is_producer` -> encode only" doesn't hold any more

## What Changed

- Replace `is_producer` / `not is_ec_producer` checks with `not is_consumer` / `is_ec_consumer` across `gpu_model_runner.py`, `engine/core.py`, and `ray_executor.py`
- Call `ec_connector.update_state_after_alloc()` in the scheduler after encoder cache allocation to keep connector state in sync
- Add `ec_both_encoder` example launch script demonstrating single-node `ec_both` usage
