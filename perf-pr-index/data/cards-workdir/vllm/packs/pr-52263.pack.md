## PR body
```markdown
## Purpose

#47972 added per-block (128x128) FP8 for Quark **linear** layers, but
`QuarkW8A8Fp8MoEMethod` still rejects the qscheme, so a Quark checkpoint whose routed
experts are quantized per-block loads every linear layer and then fails:

```
ValueError: For FP8 Fused MoE layers, only per-tensor and per-channel scales for
weights and activations are supported. Found per_block, per_group
```

## Changes

`QuarkW8A8Fp8MoEMethod` now accepts `per_block`, following the `BLOCK` strategy of
`CompressedTensorsW8A8Fp8MoEMethod`. The per-tensor and per-channel paths are untouched;
only the scale layout differs.

- `create_weights` allocates the weight scales on the 128x128 block grid and tags them
  with `FusedMoeWeightScaleSupported.BLOCK`, so `RoutedExperts.weight_loader` shards them
  by block rather than by row.
- The scales are registered as `w13_weight_scale` / `w2_weight_scale`, the names Quark
  exports, so loading them needs no model-specific checkpoint mapping.
- `__init__` reads `block_size` from the weight config and requires dynamic activation
  quantization, rejecting a static input scale.
- `block_shape` is threaded through `_setup_kernel` and `get_fused_moe_quant_config` into
  `make_fp8_moe_quant_config`, which picks the block-scaled backend.

The fused-MoE block-alignment check was byte-identical in the FP8, compressed-tensors and
Quark implementations, so it now lives next to its linear counterpart in `fp8_utils` as
`validate_fp8_block_shape_moe`.

## Test Plan

```bash
pytest tests/quantization/test_quark.py -k per_block
```

## Test Result

The unit tests above report `8 passed, 35 deselected`, covering the four new MoE tests and
the per-block linear tests from #47972.

End to end on 1x MI355X (gfx950), serving `Qwen3.5-35B-A3B` re-quantized with AMD Quark
into an NVFP4 backbone with a per-block FP8 MTP layer, at TP=1 with
`num_speculative_tokens=1`:

- The drafter's `mlp.experts.routed_experts` binds `QuarkW8A8Fp8MoEMethod` and loads
  without any model-specific weight mapping, on the TRITON FP8 MoE backend.
- Its scales are sharded on the block grid, giving `w13_weight_scale (256, 8, 16)` and
  `w2_weight_scale (256, 16, 4)` for `weight_block_size=[128, 128]`.
- `Avg Draft acceptance rate` averages 94.2%, which a scale or layout mismatch would drive
  towards 0.

Accuracy on that same run, `lm_eval` GSM8K 5-shot over the full 1319 questions with the
drafter enabled and thinking disabled in the chat template:

| Filter | exact_match |
| --- | --- |
| flexible-extract | 0.9613 ± 0.0053 |
| strict-match | 0.9613 ± 0.0053 |

```
