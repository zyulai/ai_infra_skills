## Overview

In short: in batch-invariant (BI) mode (`VLLM_BATCH_INVARIANT=1`), every bf16 linear layer and the lm_head run the Triton kernel `matmul_kernel_persistent` instead of cuBLAS. Its tile comes from a per-GPU table, and the Hopper table only has the five Qwen3-1.7B shapes (measured on an H20), so Llama-3.1-8B and Qwen3-8B run the default 128x128x64 tile on H100. This PR adds H100-measured entries for their 8 TP=1 shapes to the `"hopper"` family.

With BI on, on an H100 SXM:
- `vllm bench latency` is 1.85-2.79x faster than main.
- The BI tax (latency with BI on / latency with BI off) drops from 2.13-2.99x on main to 1.03-1.20x with this PR.
- GSM8K stays within 0.5 standard error (SE) of main.

Related: tracker [#27433](https://github.com/vllm-project/vllm/issues/27433), same kind of table as [#53247](https://github.com/vllm-project/vllm/pull/53247), [#57456](https://github.com/vllm-project/vllm/pull/57456), [#58495](https://github.com/vllm-project/vllm/pull/58495).

## Key results

- 8 new `(N, K)` entries in `_BATCH_INVARIANT_MATMUL_TUNED_CONFIGS["hopper"]`: gate_up/down/lm_head of Llama-3.1-8B and Qwen3-8B plus their shared qkv/o. Existing entries and other families are not touched.
- One `BLOCK_K` per shape, so a row's K-reduction order does not depend on M. Checked bit for bit through the real `matmul_persistent` dispatch: 2028/2028 cases identical.
- Kernel (H100 SXM, cold L2): geomean 2.03x vs main over 80 (shape, M) cases, 2.89x at M <= 64; the slowest case is 1.00x (Qwen3 gate_up at M=2048, 827 vs 828 us). At M <= 64 the kernel is now 0.90-1.12x of cuBLAS time (main: 1.48-4.09x).
- E2E latency with the flag on (fresh process per run, 2 interleaved rounds):

## Validation

**Setup.**
- GPU: 1x H100 80GB HBM3 SXM, 132 SMs, power limit 700 W of 700 W.
- Software: driver 595.91.07, CUDA 13.0, torch 2.14.0+cu130, triton 3.8.0.
- main = 307c5844ad. PR = main + this commit, applied on the box with `git am` (same diff).
- main and PR are the same checkout, switched with `git checkout`. Every run is a fresh process.
- Llama-3.1-8B-Instruct checkpoint: `unsloth/Llama-3.1-8B-Instruct`, an ungated copy. It has the same architecture and layer shapes as `meta-llama/Llama-3.1-8B-Instruct`; its config.json adds `pad_token_id`. I did not compare the weights against the gated repo.
- [#61118](https://github.com/vllm-project/vllm/pull/61118) merged after this base. It enables Inductor's `batch_invariant` flag. It can only change the torch.compile arms (main, and PR + torch.compile under Details). It does not change this PR's default breakable-graph mode, because that mode does not run Inductor.

**Bitwise.**
- Path: `matmul_persistent` on the PR tree, all 13 hopper shapes.
- Check: a probe row at rows 0, M/2 and M-1 must equal the same row computed at M=1.
- M values (39): 1-17, every bucket edge ±1, 100, 1000, 3000 and 4096.
- 2 seeds. Weight as `w.t()` (the linear layout) and as a contiguous `(K, N)` tensor.
- Result: 2028/2028 identical, 0 mismatched.
