## Overview

On Model Runner V2, GPU memory keeps growing after startup while load ramps up. The sampler makes an fp32 copy of the `[num_reqs, vocab]` logits on every step. `capture_model()` ends with `empty_cache()`, so serving starts with no cached block of that size, and each new largest batch reserves a slightly bigger block while the smaller ones stay cached.

V1 already avoids this: `compile_or_warm_up_model` runs the sampler once at the largest batch *after* `capture_model()` ("on purpose to prevent memory buffers from being cleared by `torch.accelerator.empty_cache`"). This PR adds the same step for MRV2.

**Depends on #57926.** That PR makes `_dummy_sampler_run` take the fp32 path and counts it in `profile_run`. Without it, the dummy run skips the copy and this warm-up keeps nothing.

## Claims

- Memory no longer grows step by step under load (Qwen3-4B: +1.77 GB in 18 steps to +0.11 GB in 1 step; Gemma-4-31B TP4: +0.24 to +0.003 GB per GPU).
- No KV cache cost on top of #57926.
- No throughput change.
