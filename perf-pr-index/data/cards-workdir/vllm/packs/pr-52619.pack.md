## Purpose

Before this change, `RDNAHybridW4A16LinearKernel` routed a decode GEMM to the HIP `wvSplitK_int4_g` kernel only when the activation row count was at most five (`M <= 5`) and the total activation size satisfied `K * M <= 32768`.

The existing C++ operator supports up to five activation rows (`N_in <= 5`) and accepts `K_in * N_in` up to `int(max_lds_len * 1.2)`. With `max_lds_len = 32768`, the effective upper limit is `39321` elements.

Python `M` maps to C++ `N_in`. For inputs above the regular LDS capacity, the medium kernel keeps the activation prefix in LDS and reads the remaining elements from global memory.

Consequently, supported shapes with `K * M` between `32768` and `39321` (exclusive of the lower bound and inclusive of the upper bound) fell back to Triton instead of using the existing HIP kernel.

This PR aligns the Python dispatch limit with the C++ operator contract. It also adds dispatch-boundary tests and numerical correctness coverage for the newly enabled range. No C++ kernel is changed.
