## Overview

Independent of #67194. Both PRs edit the same lines of `Glm5NextVisionTransformer.forward`, so whichever merges second needs a rebase. The numbers below were measured while this PR was stacked on #67194, so every arm that includes this change also includes #67194.

Two changes to the GLM-5.3 (`Glm5NextForConditionalGeneration`) vision blocks:

- q/k RMSNorm and 2D RoPE run as one in-place `ops.fused_qk_norm_rope` call on the qkv projection output. This replaces two reshape copies, the Triton q/k RMSNorm, a `torch.cat` and the rotary kernel.
- Each residual add runs inside the next fused add-RMSNorm (`norm1`, then `post_layernorm`) instead of as a separate kernel.

## Claims

- Vision tower wall time −12% to −41% on top of #67194 (1x B200; the largest gains are on 1-image requests of 256-1,024 tokens).
- End to end (#67194 + this PR vs main, glm-5.3-bf16 DEP8): output throughput +4.3% / +2.3% and mean TTFT −10% / −13% for 1024x1024 / 512x512 image requests.

## Details

**Why the q/k path was slow.** The Triton `fused_q_kv_rmsnorm` was written for MLA rows of 512-1,536 elements. With the vision tower's 64-element heads it launches one program per head row, 2 x 16 x tokens programs (131K at 4,096 patches). It was the largest non-attention cost: 3.3 ms of the 10.4 ms GPU time for a 1,024-token image, more than all attention (2.5 ms) or all GEMMs (2.6 ms).

**Fused q/k norm + RoPE.**

- `ops.fused_qk_norm_rope` already ships for CUDA and ROCm (head dim 64, NeoX style).
- The 2D RoPE goes in as a per-token `cos|sin` table built once per forward from the existing `rotary_pos_emb_cos/sin` metadata, indexed by `arange` positions. The encoder CUDA-graph buffers are unchanged.
- q/k stay views into qkv, like v already is. Only FlashInfer gets contiguous copies, because its `cu_seqlens` layout needs them.
- `ApplyRotaryEmb` and `fused_q_kv_rmsnorm` are no longer used in this file.

**Numerics.** The kernel keeps the normalized q/k in fp32 into the RoPE and rounds once; before, they were rounded to bf16 in between. Per-block errors match main through block 12. The tower itself is bf16-sensitive in blocks 13-18: a pure-bf16 PyTorch run of the same reference is 27-31% off fp32 there.

**Residual in RMSNorm.** The blocks pass `(hidden, residual)`. `norm1` of the next block, and `post_layernorm` after the last one, take the residual and do the add. The first block starts with `residual = None`.

**Large images.** On large images FA4 gets 5-8% slower although nothing about it changed. With the short memory-bound kernels gone, the GPU sits at its 1,000 W power cap, and the SM clock drops from 1,938 to 1,812 MHz (sampled at 200 ms over 400 iterations of the 7,920-token input). The total still drops 12%.

**Encoder CUDA graph.** `cudagraph_mm_encoder` did not help on top of the fused q/k change (measured before the residual change). One run each gave TTFT 1,418 / 619 ms with the graph against 1,340 / 584 ms eager, within the run-to-run spread.
