## Summary

- Port the SM100 (Blackwell) CuTeDSL chunkwise GDN prefill kernel from vLLM PR [#43273](https://github.com/vllm-project/vllm/pull/43273) into SGLang as a new option for `--linear-attn-prefill-backend cutedsl`.
- Three CuTeDSL kernels (`kkt_inv_uw`, `h`, `o`) plus shared Blackwell helpers (`cute_utils/`: tcgen05 / tmem / TMA bulk-swizzle / PTX BF16 wrappers).
- 1.7x geomean kernel speedup over Triton FLA baseline on Qwen3-Next prefill shapes (B200, bfloat16).
- +12.7% total throughput and -17% mean TTFT on Qwen3.6-27B TP=1 end-to-end (input=4096, output=256, 64 concurrent prompts).
- SM90 path is unchanged: when the user picks `cutedsl` on Hopper, the dispatcher transparently falls back to Triton for prefill (decode keeps the existing CuTeDSL fused recurrent kernel).

## Motivation

vLLM PR [#43273](https://github.com/vllm-project/vllm/pull/43273) introduces a Blackwell-specific CuTeDSL GDN prefill kernel that beats both Triton FLA and FlashInfer's GDN Blackwell path in the multi-request / mixed-length / lower-head-count workloads that production serving actually sees. SGLang's existing `gdn_cutedsl.py` only wired the decode path; prefill on Blackwell was stuck on Triton. This PR closes that gap by porting the upstream kernel byte-for-byte under `python/sglang/srt/layers/attention/linear/kernels/gdn_blackwell/`, with the integration cost limited to a new `extend()` method on `CuteDSLGDNKernel` and an additional dispatch branch in `GDNKernelDispatcher`.

The kernels follow the design of FLA:

kkt_inv_uw_kernel: fusion of FLA's chunk_scaled_dot_kkt_fwd(), solve_tril(), and recompute_w_u_fwd()
h_kernel: FLA's chunk_gated_delta_rule_fwd_h()
o_kernel: FLA's chunk_fwd_o()
This kernel also provides native support for BF16 state (no extra BF16->FP32 casting)

Kernel timeline (just to illustrate the pipeline, not drawn correct to relative latencies)

## Modifications

- `python/sglang/srt/layers/attention/cute_utils/` — shared Blackwell helpers (3 files: tcgen05 / tmem / TMA-bulk-swizzle wrappers and PTX BF16 SIMD ops). Sourced from `vllm/cute_utils/` (Apache-2.0).
- `python/sglang/srt/layers/attention/linear/kernels/gdn_blackwell/` — 4 files: `kernel_kkt_inv_uw.py`, `kernel_h.py`, `kernel_o.py`, and the top-level `chunk_gated_delta_rule_cutedsl` + `prepare_metadata_cutedsl` entry. Sourced from `vllm/model_executor/layers/mamba/ops/gdn_chunk_cutedsl/`.
- `python/sglang/srt/layers/attention/linear/kernels/gdn_cutedsl.py` — `CuteDSLGDNKernel.extend()` added; `decode()` unchanged. Adapts to the existing SGLang contract: l2norm Q/K outside the kernel, gather initial state from the pool, build `chunk_indices` / `chunk_offsets` via `prepare_metadata_cutedsl`, scatter final state back. Lazy import keeps SM90 boxes able to construct the kernel for decode only.
- `python/sglang/srt/layers/attention/linear/gdn_backend.py` — `GDNKernelDispatcher` learns to route prefill through the CuTeDSL kernel when `prefill_backend=cutedsl` and `cutedsl_kernel.supports_prefill` is True (SM>=10); else it logs a one-line warning and falls back to Triton.
- `test/registered/attention/test_gdn_prefill_cutedsl.py` — correctness test (6 cases: `num_seqs in {1,5,257}` x `state_dtype in {bf16, fp32}`) against `fused_recurrent_gated_delta_rule` as ground truth. Registered for CI via `register_cuda_ci(est_time=60, stage="base-b", runner_config="4-gpu-b200")` and module-level `pytest.skip` on SM<10.
- `benchmark/bench_linear_attention/bench_gdn_prefill_cutedsl.py` — Triton-vs-CuteDSL correctness sweep (19 shapes) plus `do_bench_cudagraph` perf table.

## How to use

```
python -m sglang.launch_server \
    --model Qwen/Qwen3.6-27B \
    --trust-remote-code \
    --tp 1 \
    --linear-attn-prefill-backend cutedsl \
    --host 127.0.0.1 --port 30000
```

The flag is also accepted on SM90 (Hopper); the dispatcher transparently falls back to Triton for prefill and prints one info-level line. This means users can pick `cutedsl` uniformly across hardware without per-host configuration.

## Requirements

- CUDA runtime >= 13.
- `nvidia-cutlass-dsl[cu13]==4.5.0` — **the `[cu13]` extra matters**. The base `nvidia-cutlass-dsl==4.5.0` wheel does not pull in the matching `cuda-bindings 13.2.0` / `cuda-pathfinder` / `numpy 2.4.x` set, and the kernel fails to compile inside `cute.copy` (asserts in `_ods_common._get_value`) without them. Consider updating `requirements/cuda.txt` accordingly.
- `quack-kernels>=0.3.3`.

## Limitations and future work

- The ported kernel hard-codes `BT=64` and `K_dim=V_dim=128`. The wrapper asserts `head_k_dim==128` at first call; a clearer error path may be added later.
- KDA (Kimi Delta Attention, used by Kimi-Linear) cannot reuse this kernel: GDN's forget gate is per-head scalar `[T, Hv]`, while KDA's is per-K-dim `[T, H, K]`. The kernel's `Gamma[i,j] = exp(g_cu[i] - g_cu[j])` is structurally per-head. A KDA-specific Blackwell kernel would need to add a K dim to `Gamma` and to the H/state-evolution and output kernels; this is left as follow-up.
- Two reviewer flags from the upstream Gemini bot on the source PR are not yet addressed there (TMEM hardcoded base addresses; an H-kernel TMEM dealloc race). These carry over to this port; we should re-sync once upstream lands fixes.
- Decode path is unchanged. Existing `cutedsl_fused_sigmoid_gating_delta_rule_update` continues to serve decode on SM90+ via the unmodified `CuteDSLGDNKernel.decode()`.

+def make_k_contiguous(t: torch.Tensor) -> torch.Tensor:
+    """K-last view of a logical [..., K, V] tensor (physically [..., V, K])."""
+    return t.transpose(-2, -1).contiguous().transpose(-2, -1)

+def gdn_flops(total_seq_len, num_heads, head_size_k, head_size_v):
+    """Per-token-per-head: k@v^T outer (2*K*V) + q@state output (2*K*V)."""
+    return 4 * total_seq_len * num_heads * head_size_k * head_size_v

+def gdn_bytes(
+    total_seq_len, num_q_heads, num_v_heads, head_size_k, head_size_v, num_seqs, dtype
+):

+    elem = dtype.itemsize
+    q_b = total_seq_len * num_q_heads * head_size_k * elem
+    k_b = total_seq_len * num_v_heads * head_size_k * elem
+    v_b = total_seq_len * num_v_heads * head_size_v * elem
+    o_b = total_seq_len * num_o_heads * head_size_v * elem
+    state_b = 2 * num_seqs * num_o_heads * head_size_k * head_size_v * 4  # fp32 r/w
+    g_b = total_seq_len * num_o_heads * 4
+    beta_b = total_seq_len * num_o_heads * 4
+    return q_b + k_b + v_b + o_b + state_b + g_b + beta_b
