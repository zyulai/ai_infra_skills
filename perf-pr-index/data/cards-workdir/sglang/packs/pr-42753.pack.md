## Motivation

On the unified memory pool a KV slot has a virtual id (what the scheduler
allocates and `req_to_token` stores) and a physical id (what kernels index).
The conversion between them was done wherever an id was needed: every
`ForwardBatch` translated its own write window, every attention backend built
its own translated page table (some per forward, some per layer group, some
per captured mode), the multi-step draft kernel translated every id it
gathered, and the speculative KV writers translated the ids they were handed.
Within one speculative iteration the same window was translated three to four
times (draft, verify, draft extend, target-hidden KV writes), and a captured
graph translated its write ids a second time into a private buffer.

Besides the wasted launches, every one of those sites had to agree on which
ids were already physical, and a site that translated twice, or not at all,
silently read or wrote the wrong slot.

**This PR translates an iteration's write window once per sub-pool, in one
place, and gives every read exactly one translation, in one place too: the
translator's read primitives. A read table exists only once a reader that reads
the table form asks for it -- built into that reader's own capture-stable table
when it has one -- and every later reader takes it; every reader before it
translates in its own gather. No table is built that no reader asked for.**

## Modifications

**`KVLocPlan`** (`mem_cache/kv_loc_plan.py`, new) names one iteration's ids,
in every sub-pool of the pool. A sub-pool is an **`IdSpace`**: how it maps the
iteration's virtual token ids (`write`) and the page table its reads go through
(`read_v2p`). A runner's translator holds one per sub-pool its pool has
(`space(IdSpaceKind.FULL / SLIDING_WINDOW)`), keyed so that runners sharing a
sub-pool (a fused draft and its target) share the plan's results; adding a
sub-pool means registering a space, not adding fields. The window itself
stays in allocator-global ids: an NPU DCP target, which writes rank-local
slots, has its own full space mapping the window to them, while the
replicated draft binds the same window global. The plan holds:

- its write window, translated once into the full sub-pool
  (`write_physical`); the virtual window it was built from is never mutated
  (radix tree, accept path and lazy compaction still read it);
- `write_ids(reader, kind=, cols=)`: the window in any sub-pool's ids, derived
  on first use and kept for the iteration -- physical for the target and a
  fused draft, virtual for a static or private draft pool's full sub-pool;
  `cols` selects the part a forward writes (a draft step's columns, a flat
  index for a ragged verify's packed rows, or a run of the window's tokens
  for one half of a two-batch-overlap split, `TokenSpan`, read as a view);
- `read_table(kind=, rows=)`: a sub-pool's page table over
  `[0, seq_lens + read_extent)`, built when a reader that reads the table form
  (a page-table kernel, or a captured graph's table: `copy_page_table`) first
  asks for it, and then shared by every later reader of the iteration; built
  straight into a captured reader's own buffer -- no table of the plan's own,
  no copy; without host lengths (fa3's speculative overlap steps) the build
  stops at that buffer's width. A captured graph's padded lanes are appended by copy, reading the
  sink, and a reader that asks for its batch's rows gets exactly those, a view
  of a wider table a captured reader built. Until a table exists no reader
  waits for one: a CSR stream is gathered and translated straight into the
  reader's buffer, and the multi-step draft kernel gets the virtual rows with
  the sub-pool's page table (`KVIndexTable.v2p`), applied in its own gather.
  Whether to share is local -- does the plan hold a table yet -- so nothing
  predicts which runners will read one;
- `bind(batch, reader, cols)`: the one way a forward gets its write ids. A
  forward carries only the plan and its columns (`ForwardBatch.kv_loc_cols`);
  a backend that writes another sub-pool asks its translator at metadata time
  (`KVIndexTranslator.write_ids(batch, kind)`), padded to the batch's
  `out_cache_loc` with the sink, so padded batches, replay views and the
  halves of a two-batch-overlap split need nothing of their own.

`KVIndexTranslator` keeps what a plan needs: `plan` / `own_plan`, the plan's
table builder (`build_iteration_table`), the readers
(`read_source` for gather kernels, `pack_read_stream` for CSR streams,
`copy_page_table` for captured tables, `read_table`, each by `IdSpaceKind`),
`write_ids` for a backend's sub-pool, the dispositions, and
DCP's read production (`translate_dcp_read_ids`, the one translation that
stays outside a plan: which ids a rank reads is only known where the DCP index
kernels select them). A reader takes a plan's table only when it reads
through it -- same v2p table, same `req_to_token` rows (`is_read_by`).

The commits are layered:

1. **One plan per forward.** `ForwardBatch.init_new` builds a plan and binds
   it; replay views carry it.
2. **Writes.** A captured forward writes through the graph runner's own
   `out_cache_loc` slot, which already holds the batch's physical ids; triton
   and the trtllm_mla family drop the private capture buffers that translated
   them again. Batches a runner builds itself (captures, warmup runs) bind
   their own buffer as it is (`bind_runner_slots`). A forward
   whose lengths do not count the window it writes -- a verify, a speculative
   draft decode, a draft extend -- plans its reads that far
   (`window_read_extent`).
3. **Reads, per backend.** triton, the multi-step draft kernel, fa3, the
   trtllm_mla family, flashmla, trtllm_mha, flashinfer, flashinfer_mla, aiter,
   the speculative inputs' `generate_attn_arg_prefill` and DeepSeek's one-shot
   and chunked-prefix MHA indices read the plan's table instead of
   translating. The plan is passed explicitly through the index updaters (no
   hidden backend state).
4. **One plan per speculative iteration.** EAGLE (single- and multi-layer)
   plans the verify window when the draft gathers it -- in the same launch --
   and the draft decode, verify and draft extend share it. DSPARK and DFLASH
   plan their window where it is allocated; the draft block, the verify
   (including DSPARK's ragged verify, by index) and the target-hidden KV
   writers share it, and a compact DFLASH draft reads its own rows over the
   shared write ids (`reads_from`). At prefill, the target forward hands back
   its plan (`return_kv_loc_plan`), and the draft writes into the same slots
   take their ids from it.
5. **Removal.** The per-forward translate API goes (`index_table_for_batch`,
   `widened_index_table`, `build_index_table`, `fill_read_table`,
   `fill_packed_read_stream`, `translate_full_attn_ids`, `full_flat_v2p`,
   `sliding_window_write_loc_for`); `rebind_write_loc` becomes
   `bind_own_plan`. A padded (DP-attention) batch pads its eager page table
   along with its write ids. DiffusionGemma's FA4 prefill graphs build their
   streams from the batch's plan and take their sliding-window write ids from
   `write_ids`; their private capture buffer of translated write ids goes, as
   triton's did.
6. **Sub-pools as id spaces.** Every sub-pool, the sliding-window one
   included, goes through `IdSpace` (as above): a batch carries no ids of its
   own per sub-pool, a table no per-sub-pool twin, a reader no per-sub-pool
   flag. trtllm_mha's ragged-verify refill takes its sliding-window ids from
   the plan as well, instead of mapping `out_cache_loc`, which on the unified
   pool is already physical.
7. **Tests and comments of the stack.** The stack's tests that duplicate
   another test, pin a development-time detail, or only catch a failure that
   already stops the boot are dropped (about 60); the ones kept check the ids,
   rows, columns and bytes a kernel or captured graph gets. The fused-draft
   bind gate and the speculative aux-state resolver tests run weekly. The
   stack's comments and docstrings are cut to contracts and invariants.

A static pool does no translation work and runs no kernel for it: its plan
is a few host objects over the batch's own write ids, and every read is the
`req_to_token` passthrough, as before.

## Notes for reviewers

- **Not validated end to end here:** NPU (its DCP write ids are covered by
  a unit test), fa3 with DFLASH or DSPARK (its draft and verify metadata
  paths are covered by unit tests), multi-layer EAGLE
  (no such model on the test machine), cutedsl_mla / tokenspeed_mla /
  flashmla, `--dcp-size > 1`, and two-batch overlap (the unified pool refuses
  it; a split batch's columns on a static sliding-window pool are covered by
  unit tests).
- **One translation stays outside a plan by design:** DCP's read production
  (`translate_dcp_read_ids`): which ids a rank reads is only known where the
  DCP index kernels select them.
- trtllm_mla's eager block table past a row's live pages now reads the sink
  (0) within the plan's width instead of -1; the kernels bound their reads by
  `seq_lens`, and a draft extend's padded queries (whose outputs are dropped)
