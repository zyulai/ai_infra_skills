## 正文(PR 描述)

## Motivation

On the AITER backend, the SHUFFLE 5D KV layout (`SGLANG_AITER_KV_CACHE_LAYOUT=vectorized_5d`) silently produces garbage output for every model without sliding-window attention: decode reads the wrong KV pages and nothing reports an error. GSM8K on Qwen3-14B-FP8 drops from 0.885 to 0.000 on MI325X. This has been the case since the layout was added in #27063. Setting `SGLANG_USE_AITER_UNIFIED_ATTN=1` works around it today.

Root cause: `forward_decode_vectorized_5d` passes `forward_metadata.kv_indices` to `pa_decode_gluon` as its `block_tables`, a 2-D `(bs, max_num_blocks_per_seq)` table of page ids, and its docstring says the same ("Full-attn → `kv_indices` page table"). But the decode metadata only builds that table on the unified-attention branch:

```python
if not self.use_triton_unified_attention:
    # flat per-token kv_indices, addressed through kv_indptr
    create_flashinfer_kv_indices_triton[(bs,)](...)
else:
    # 2-D page table
    ...
```

`use_triton_unified_attention` is forced on for sliding-window models, which is why gpt-oss (the model the 5D path was added for in #27063) is unaffected. Every other model leaves it off by default, so `pa_decode_gluon` reads token ids as page ids with a row stride of 1. The eager path, the CUDA-graph page-table buffer and CUDA-graph capture/replay all make the same choice.

## Modifications

The decode metadata format and the decode kernel are separate choices, so this PR names the former explicitly:

```python
self.decode_uses_page_table = (
    self.use_triton_unified_attention or self.kv_cache_is_vectorized_5d
)
```

and uses it at the five sites that decide between the flat indices and the page table: the eager decode path (plain and speculative), the CUDA-graph page-table buffer allocation, and both checks in `_apply_cuda_graph_metadata` (shared by capture and replay).

`use_triton_unified_attention` itself is unchanged. The 5D layout already has dedicated KV-write, extend and decode branches, so the only things the flag still controls for it are the metadata format and the target-verify kernel choice (`_use_unified_verify`). Forcing the flag on would also switch the verify kernel, which is outside this fix. The NHD layout is unaffected: `decode_uses_page_table` equals `use_triton_unified_attention` there.

Tests: `test/registered/amd/test_aiter_vectorized_5d_decode.py` launches the CI default model (`meta-llama/Llama-3.1-8B-Instruct`, dense, no sliding window) with `SGLANG_USE_AITER=1`, the 5D layout and `--page-size 64`, and runs GSM8K. Registered in `stage-b-test-1-gpu-small-amd-mi35x`.

The branch is rebased onto `main` @ `e45cbce599` without conflicts.

## Accuracy Tests

### MI325X (gfx942)

MI325X (gfx942, 304 CU), ROCm 7.2, torch 2.11.0, Triton 3.7.0, AITER `c16d44b93`. This image ships a `sgl-kernel` that current `main` does not run against, so these runs use the image's sglang (`dc6b5d1f5a`, 2026-09-04), with and without this patch, which applies to it unchanged.

Qwen3-14B-FP8, `SGLANG_USE_AITER=1`, `--attention-backend aiter`, `--mem-fraction-static 0.85`, CUDA graph on, GSM8K 200 questions, 5-shot, greedy, one server at a time:

| Config | GSM8K |
|---|---|
| NHD layout, `--page-size 1` | 0.870 |
| NHD layout, `--page-size 64` | 0.885 |
| 5D layout | **0.000** |
| This PR, 5D layout | 0.890 |
| 5D layout + `SGLANG_USE_AITER_UNIFIED_ATTN=1` | 0.890 |

## Speed Tests and Profiling

No change on the NHD layout. On the 5D layout the fixed path builds the same page table as the unified-attention path.

Long-context serving on MI325X, same setup as the gfx942 accuracy table: `bench_serving --dataset-name random-ids`, 8192 input / 1024 output tokens, `--random-range-ratio 1.0`, 3 × concurrency prompts after a warmup of one concurrency's worth:

| Config | c=64 output tok/s | c=64 mean TPOT (ms) | c=128 output tok/s | c=128 mean TPOT (ms) |
|---|---|---|---|---|
| NHD layout, `--page-size 1` | 351.9 | 133.0 | 389.2 | 190.7 |
| NHD layout, `--page-size 64` | 349.0 | 133.3 | 383.6 | 194.5 |
| This PR, 5D layout | 358.9 | 128.6 | 395.2 | 186.2 |
| 5D layout + `SGLANG_USE_AITER_UNIFIED_ATTN=1` | 358.0 | 128.9 | 392.1 | 187.4 |

At the same page size, the 5D layout lowers mean TPOT by 3.5% (c=64) and 4.3% (c=128) on this dense model. The runs are prefill-heavy (mean TTFT is about 50 s at c=64 and 110 s at c=128 for every config), so these numbers are about the decode side only.
