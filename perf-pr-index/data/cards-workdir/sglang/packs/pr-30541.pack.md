## Motivation

Add a new opt-in MoE runner backend `hpc_ops` wrapping the monolithic FP8 fused-MoE kernels from [HPC-Ops](https://github.com/Tencent/hpc-ops), the production-grade operator library for LLM inference from the Tencent Hunyuan AI Infra team.

This is the second half of the first-phase HPC-Ops <-> SGLang integration discussed with the Hunyuan team (attention backend: #30540).

Enable with:

```bash
python3 -m sglang.launch_server \
  --model Qwen/Qwen3-30B-A3B-Instruct-2507-FP8 \
  --moe-runner-backend hpc_ops
```

> [!NOTE]
> The HPC-Ops kernels run on any sm90+ GPU, but they are currently **tuned primarily for H20**. On other hardware (H100/H200/B200, ...) the speedup may be limited or absent — the H200 numbers below reflect exactly that. Further kernel-side tuning for non-H20 GPUs is planned as follow-up work with the Hunyuan team, and the backend stays strictly opt-in so default paths are unaffected.

## Modifications

- New `python/sglang/srt/layers/moe/moe_runner/hpc_ops.py`: a fused-func runner backend (same shape as flashinfer_trtllm / cutlass) with two paths:
  - **Blockwise FP8** (128x128 weight blocks + dynamic per-token-group-128 activations, e.g. Qwen3-FP8 / Hy3-FP8 checkpoints) → `hpc.fuse_moe_blockwise`.
  - **Per-tensor FP8** with static activation scales → `hpc.fuse_moe` (per-expert dequant alphas `w_scale * a_scale`, inverse a2 scale for the activation requant — same wiring as the flashinfer CUTLASS per-tensor path).
  - Both kernels fuse gather → grouped gate_up GEMM → SiLU-and-mul (+ FP8 requant) → grouped down GEMM → weighted top-k reduce in one call.
- `Fp8MoEMethod`: precompute the HPC-Ops scale layouts once at `process_weights_after_loading` (the kernel wants `[E, N/128, K/128]` fp32 dequant scales with the K dim padded to a multiple of 4) and build `HpcOpsMoeQuantInfo` in `apply`.
- The kernels consume **global** top-k expert ids together with `rank_ep` / `num_expert_total`, so `hpc_ops` is added to `skip_local_expert_mapping` in the standard dispatcher — contiguous-partition EP works without the local-expert remap.
- Enum/choices/registry wiring + a numerical unit test (`test/registered/moe/test_hpc_ops_moe.py`, skipped when HPC-Ops is not installed or on pre-sm90 GPUs).

Constraints checked with clear errors: gated SiLU only, no fused shared experts, no `apply_router_weight_on_input` / `no_combine` / swiglu clamp, hidden dims 128-aligned, bf16 hidden states.

+def pad_hpc_ops_block_scale(scale: torch.Tensor) -> torch.Tensor:
+    """Pad the K dim (last dim) of a [E, N/128, K/128] block scale to %4."""
