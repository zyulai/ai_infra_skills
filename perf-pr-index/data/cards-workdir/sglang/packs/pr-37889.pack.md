## Motivation

**Add a packed-row top-k kernel to the DSA top-k v2 family and route GLM-5.x prefill through it. The prefill top-k kernel drops ~66% per launch; at ISL 70000 / OSL 300 that is +4.9% token throughput per GPU, −3.5% median TPOT and −4.8% median TTFT (geomean over concurrency 4-64); GSM8k 0.937 against 0.935 on the baseline.**

<img width="1692" height="965" alt="image" src="https://github.com/user-attachments/assets/0ccb560a-cf57-410d-8d08-c416ee909f4d" />

PR #36684 and PR #36851 brought the v2 fused top-k to GLM-5.x on ROCm, but only decode ever reached it; prefill stayed on the legacy fused transform, which gathers the wide `page_size=1` table.

The blocker was addressing, not math. The paged v2 entry assumes each row starts at column 0 of its own score row and owns one page-table row. DSA extend breaks both: all requests share one packed score buffer, so a row starts at some column in the middle, and every row of a request reads the same page-table row. Two lookup tables fix that, with no copy of the score buffer and no per-row page table, which at 327K context would be hundreds of MB per forward.

The layout gets its own kernel because prefill row lengths vary within a launch: the level (register-2 / register-4 / streaming) has to be chosen per row at runtime, which the paged kernel, sized once off `max_seq_len`, cannot do. The packed entry also needs no `topk_v2_plan`, no cluster path and no compile-time level.

## Modifications

**`topk_v2.cuh`** -- add `TopKPackedParams` and `topk_packed_kernel<kPDL>` next to `topk_ragged_kernel`, plus the `TopKKernel::transform_packed` host entry. Addressing, against the paged layout:

| | paged entry (decode layout) | `transform_packed` (extend layout) |
| --- | --- | --- |
| score window of row `i` | `scores[i, :seq_lens[i]]` | `scores[i, row_starts[i] : row_starts[i] + seq_lens[i]]` |
| page-table row | `page_tables[i]` | `page_tables[row_to_batch[i]]`, identity when `row_to_batch` is null |

`row_starts` is required, `row_to_batch` optional. Shifting the score pointer keeps the selected index row-local, so the output path is untouched; the page-table row count must match the score row count only when `row_to_batch` is absent.

Vector loads need the read base on a 4-float boundary, so the kernel rounds `row_starts[i]` down and masks the <= 3 columns ahead of the window in place. The level is then picked from the widened length, which keeps a row of exactly 8192 with a 3-column residue out of the register-2 implementation.

Kernel, host entry and wrapper registration are behind `USE_ROCM`: only the ROCm DSA prefill emits this layout, and CUDA gets the same fusion from the ragged path.

**`dsv4/topk.py`** -- register the `topk_transform_packed` wrapper when `is_hip_runtime()`, and add `topk_transform_packed_v2(scores, seq_lens, page_tables, out_page_indices, page_size, *, row_starts, row_to_batch=None)`.

**`dsa/dsa_topk_backend.py`** -- route packed PAGED extend to `_topk_transform_v2_packed`, passing `ks` as `row_starts`. The row -> request map arrives whole-forward as `token_to_batch_idx` or per row-chunk as `batch_idx_list`, and both take this path: since #36960 capped the MQA-logits budget at aiter's 2 GiB `buffer_store` limit, a 70K prefill splits its rows on every forward but a request's first chunk, so routing only the whole-forward shape left 126 of 147 launches in a 70K trace on the legacy kernel (fixed by a6d769e).

Two shapes fall back, checked in the dispatch so they do not trip the helper's asserts: a row stride that is not a multiple of 4, which the vectorized load needs and which an extend stride -- the batch's total KV length -- only satisfies by luck, and a `batch_idx_list` that is not a per-row tensor. The decode condition is left byte-identical, because `dsa_drop_wide_page_table` keys off exactly that condition.

**`test_topk_v2.py`** -- `test_topk_v2_packed_rows` packs several requests into one score buffer, each with its own page-table permutation so a row/request mix-up cannot pass, and checks a row-local `torch.topk` reference; `test_topk_v2_packed_level_boundary` covers rows of exactly 8192 and 16384 with a 1-3 column masked residue, the case that overflows a register implementation if the level is picked from the un-widened length.
