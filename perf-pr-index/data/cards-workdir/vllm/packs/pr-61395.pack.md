## Overview
Follow-up of #57549

Enable EPLB for DeepSeek V4 and V4.1 DSpark drafts when their expert topology differs from the target model.
This PR covers DSpark’s draft model loader.
Related: [#59611](https://github.com/vllm-project/vllm/pull/59611) fixes redundant expert loading in the target model. 
Open #66045 addresses draft expert filtering during weight loading; it is complementary and does not implement heterogeneous EPLB state or load balancing.

## Claims

- Register supported DSpark draft MoE models with the target's EPLB state and reduce their load statistics together, including when their physical expert counts differ.
- When draft R is unset and the routed-count sets match, inherit the resolved target R if it is valid for the draft. If the sets differ, compute the draft minimum.
- Honor an explicit draft R when it is valid for every draft routed count. Reject an invalid explicit value and suggest the minimum valid count when one count works for every draft layer.
- Read `draft_num_redundant_experts` from `--eplb-config`, alongside the target EPLB settings. `draft_enable_eplb` remains in `--speculative-config`.
- Enable EPLB by default for supported V4.1 DSpark drafts when target EPLB is enabled. A DSpark draft with `draft_tensor_parallel_size=1` requires prefill context parallelism or data parallelism greater than 1; otherwise, config validation rejects it. DSpark draft EPLB is incompatible with Elastic EP; set `draft_enable_eplb=false` to disable it.
- Include redundant physical slots in V4.1 DSpark's fused-MoE weight mapping.

## Details

The target and DSpark draft can have different routed and physical expert counts. EPLB state now keeps topology-dependent counts per registered model and handles load-stat reductions when models have different physical expert dimensions.

For supported MoE drafts, draft EPLB is enabled by default whenever target EPLB is enabled. Set `speculative_config.draft_enable_eplb=false` to disable it for the draft while leaving target EPLB enabled. DeepSeek V4 and V4.1 DSpark drafts require the draft EP group to have more than one rank when draft EPLB is enabled; `draft_tensor_parallel_size=1` is rejected when prefill context parallelism and data parallelism are both 1. Draft EPLB for DSpark is rejected with Elastic EP during config validation, with a suggestion to disable draft EPLB.

DSpark’s custom weight loader is a separate call path from the target model’s `get_expert_mapping`. Since DSpark is now registered with EPLB, its redundant physical slots must also receive the replicated expert weights. #59611 addresses the target model’s mapping; end-to-end use with redundant experts requires that fix as well.


The PR example adds `draft_num_redundant_experts` in `--eplb-config`. The value is a draft override and does not change the target's `num_redundant_experts`. It is only consumed when a speculative MoE draft is configured; without one, the draft-specific setting is ignored.

Draft R resolution follows three cases. 
 - With no draft override and matching target/draft routed-count sets, inherit the target R when it is already resolved and valid for the draft. 
 - With no override and different routed-count sets, compute the minimum valid draft R. 
 - For an explicit draft R, use it if it satisfies divisibility for every draft routed count; otherwise, fail config validation and suggest the minimum valid R when one value works for all layers. 
 - If draft layers require different padding values, validation reports that no single R works. 
 - When target R is automatic but still unresolved during draft validation, matching topologies compute the same minimum independently; target R is stored later by the normal `VllmConfig` path.

For target EPLB validation, an unset target R is now resolved locally for the divisibility check without mutating `EPLBConfig`; this lets ngram configurations reach the normal `VllmConfig` path that resolves the target count.
