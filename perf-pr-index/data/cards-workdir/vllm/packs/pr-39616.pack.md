## Summary                                                                                      
                                                                                                  
  Enable AITER MLA attention backend to work with Eagle3 speculative decoding on ROCm.            
                                                                                                  
  AITER MLA is the fastest MLA attention backend on AMD MI300X/MI355X GPUs (using AMD's ASM       
  kernels via the aiter library). However, it currently cannot be used with speculative decoding
  methods like Eagle3 due to a `kernel_block_size` conflict:                                      
                                                                                                
  - **AITER MLA** declares `get_supported_kernel_block_sizes() = [1]`                             
  - **Eagle3 draft model** (flash_attn) requires `block_size = MultipleOf(16)`                    
  - Both share the same KV cache group, so `select_common_block_size()` fails — no block size      satisfies both constraints                                                                      
                                                 
  This means users must choose between AITER MLA (fast decode, no spec-dec) or a slower backend   
  (spec-dec works but lower baseline performance). This PR removes that limitation.               
                                                                                                  
  ## Key Insight                                                                                  
                                                 
  The aiter MLA decode kernel always operates with `page_size=1` internally — the vLLM wrapper    
  flattens `kv_buffer` via `.view(-1, 1, 1, head_size)` before calling the ASM kernel. The kernel
  never sees multi-token pages. So AITER MLA can work with any `kernel_block_size` — we just need 
  to expand block-level indices into per-token flat indices in the metadata builder.            
                                                                                                  
  ## Changes                                                                                      
                                                                                                  
  All changes are in a single file: `vllm/v1/attention/backends/mla/rocm_aiter_mla.py`            
                                                 
  1. **`get_supported_kernel_block_sizes()`**: `[1]` → `[MultipleOf(1)]` — allows any block size,  enabling compatibility with Eagle3's flash_attn (block_size=16)                                 
                        
  2. **Store `kernel_block_size`**: `self.kernel_block_size = kv_cache_spec.block_size` in the     metadata builder for use during index expansion                                                 
                                                 
  3. **`_copy_page_indices_kernel` → `_expand_page_indices_kernel`**: Rewrote the Triton kernel to expand block-level entries into per-token flat indices. When `kernel_block_size=1` (no spec-dec), behavior is mathematically identical to the original — no regression. When            `kernel_block_size=K` (e.g. 16 with Eagle3), block table entry `b` covering K tokens is expanded to flat indices `b*K, b*K+1, ..., b*K+(K-1)`.

  4. **Conditional `get_mla_metadata_v1`**: Only called for `max_qo_len == 1` (single-token decode steps). The result is tracked via `has_persistent_metadata` on the decode metadata object (not builder instance state), and passed through to `forward_mqa` via the metadata dataclass. During Eagle3 verification, `qseqlen = num_speculative_tokens + 1 > 1`, and  `get_mla_metadata_v1` internally calls `get_heuristic_kernel_mla` which crashes for `qseqlen >   1`. When skipped, the kernel falls back to computing metadata internally.   ## Benchmark Results                                                                            
   
  Tested on AMD MI355X (TP=4) with Kimi-K2.5-MXFP4 https://huggingface.co/amd/Kimi-K2.5-MXFP4 (MLA, 64 heads) + Eagle3 draft model https://huggingface.co/lightseekorg/kimi-k2.5-eagle3,          
  ISL=1024/OSL=1024, random dataset, 10 seeds per config:                                       
                                                                                                  
  | Config | Baseline (tok/s/gpu) | Eagle3 spec7 (tok/s/gpu) | Speedup |                          
  |---|---|---|---|                      
  | MML=2248, conc=16 | 206.1 ± 3.7 | 363.7 ± 20.2 | **+76.5%** |                                 
  | MML=4096, conc=16 | 204.2 ± 10.9 | 353.4 ± 27.2 | **+73.0%** |                                
                                                                                                  
  - Baseline performance (no spec-dec) is unchanged — no regression                               
  - Eagle3 spec7 delivers +73-77% throughput improvement with AITER MLA                           
                                                                                                  
  ## Output Quality                                                                               
                                                                                                  
  Verified with 10 diverse prompts (geography, math, coding, translation, etc.) using             
  `/v1/chat/completions` API at temperature=0. Eagle3 spec7 output quality matches baseline across
   all prompts. Spec-dec acceptance rates are in the normal range (35-55% depending on workload). 
                                                                                                
  ## Test Plan                           

  - [x] Baseline (no spec-dec) throughput unchanged — no regression                               
  - [x] Eagle3 spec7 works correctly with AITER MLA backend
  - [x] Output quality: Eagle3 output matches baseline (10 prompts, chat API)                     
  - [x] Normal spec-dec acceptance rates (35-55%)                                                 
  - [x] Throughput: +73-77% speedup with Eagle3 spec7                                             
                                                                                                  
  ## Known Limitation                                                                           
                                                                                                  
  The aiter ASM kernel has a pre-existing issue with non-power-of-2 `max_qo_len` values (e.g.,    
  `num_speculative_tokens=5` → `qseqlen=6`), producing incorrect attention output. This is not 
  introduced by this PR — it exists in the upstream aiter kernel. Only `num_speculative_tokens`   
  values where `spec+1` is a power of 2 (1, 3, 7, 15) work correctly. We are reporting this issue (https://github.com/ROCm/aiter/issues/2720) to the
   AMD aiter kernel team.
