## PR body
```markdown
Fixes #34473.

## Summary

QuickReduce converts BF16 inputs to FP16 before reduction for performance. GPT-OSS reaches magnitudes above FP16's maximum finite value (65,504), so the conversion could produce `inf`; quantized codecs then propagated that value through a 32-element block.

This PR:

- Enables `MODE.FP16_OVFL` on both gfx942 and gfx950 so FP16 overflow clamps instead of becoming non-finite.
- Uses a power-of-two range guard (`S = 16`) for `CodecFP`, scaling in FP32 before narrowing and restoring the scale on output.
- Emits `v_cvt_pk_f16_f32` explicitly for the scaled `CodecFP` conversion. This prevents LLVM from moving the FP16 conversion ahead of the scale.
- Keeps `CodecQ4/Q6/Q8` at `S = 1` on the existing fast FP16 path. Their block scaling already normalizes values, and a larger cast scale moves the reciprocal-scale saturation cliff into real data.
- Adds a four-GPU regression test covering low values, ordinary values, sums above FP16 range, individual inputs above FP16 range, negative overflow, and mixed blocks.

## Scope

This fixes the GPT-OSS non-finite-output failure without routing quantized codecs through native BF16 kernels. Quantized reductions may still clamp finite values when their FP16 accumulator exceeds 65,504; that is pre-existing lossy behavior and is intentionally left unchanged here. The native-BF16 alternative was numerically exact but 22–46% slower.

## Validation

- Built and passed the TP4 range regression on MI350X and MI355X with ROCm 7.2.
- `CodecFP` is bit-exact for all tested cases, including inputs and sums above FP16 range.
- Quantized codecs remain bit-exact for low and ordinary values and produce finite outputs for overflow cases.
- Captured GPT-OSS reductions went from non-finite outputs to zero non-finite outputs.
- PR-base versus final-patch latency on MI350X showed no measurable regression:
  - INT8/INT6/INT4: within 0.4% at 16 MiB and within 0.1% at 90 MiB.
  - FP: 9.6% faster at 16 MiB and 1.1% faster at 90 MiB in this run.
- Repository pre-commit checks pass.
```
