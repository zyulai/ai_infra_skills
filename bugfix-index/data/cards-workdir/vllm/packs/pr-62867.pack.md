## 正文(PR 描述)

## Overview

Fix CPU data-parallel ranks all binding to the same NUMA node, a regression from #45026. Fixes #47328.

## Claims

- With `--data-parallel-size N` on a multi-NUMA CPU host, each `EngineCore_DP*` now binds the cores and memory of its own NUMA node instead of every rank binding the same cores.
- Manual pinning with `CPU_VISIBLE_MEMORY_NODES` without DP is unchanged.
- No change to shared engine code; the fix is CPU-only (26 lines added, 10 removed, excluding tests).

## Validation

Reproducer from the issue, on a 6-NUMA-node host:

```bash
vllm serve facebook/opt-125m --data-parallel-size 2 --max-model-len 256
```

OpenMP binding chosen by each EngineCore at startup (from the `OpenMP thread binding info` log):

| | `EngineCore_DP0` | `EngineCore_DP1` |
|---|---|---|
| main | cores 192-222, reserved 223 | cores 192-222, reserved 223 (same) |
| this PR | cores 192-222 (node 0), reserved 223 | cores 224-254 (node 1), reserved 255 |

With this PR the two workers also bind memory to distinct NUMA nodes (`NUMA binding: Using MEMBIND policy ... nodes (0)` and `(1)`), and a completion request returns a correct response end to end.

Unit tests:

```bash
pytest tests/utils_/test_cpu_resource_utils.py tests/v1/worker/test_cpu_worker_kv_budget.py   # 21 passed
```

`test_omp_manager_binds_each_dp_rank_to_its_assigned_node` builds `OMPProcessManager` on a fake 2-node topology and checks that two DP ranks get disjoint cores. It fails (both ranks pick node 0 cores) if the assigned ids are ignored.

## Details

**Root cause.** #45026 moved the per-DP-rank device list from the device-control env var into `parallel_config.assigned_physical_gpu_ids`. `CoreEngineProcManager` still computes each rank's shard and stores it there, and GPU/XPU consume it. The CPU code still read only `CPU_VISIBLE_MEMORY_NODES`, which nothing sets per rank anymore. `OMPProcessManager`, which runs in the EngineCore process, then saw the full node list and picked `allowed_numa_nodes[local_rank]`, the same node for every DP rank.

**Fix.** `get_visible_memory_node()` takes an optional `assigned_node_ids`. Precedence is assigned ids, then `CPU_VISIBLE_MEMORY_NODES`, then all nodes. `VLLM_CPU_SIM_MULTI_NUMA` still overrides everything. Three call sites pass the ids:

- `OMPProcessManager` reads the config. The in-process `get_assigned_physical_gpu_ids()` global is only set inside worker processes, so it is not available in the EngineCore process where this runs.
- `CPUWorker` reads `vllm_config.parallel_config.assigned_physical_gpu_ids`.
- `CpuPlatform.get_current_memory_usage` runs in the worker and uses the global.

**Limitations.** `--device-ids` also fills `assigned_physical_gpu_ids`, so on CPU it now selects NUMA nodes (composed with `CPU_VISIBLE_MEMORY_NODES`), consistent with GPU. This path is not covered by the validation above.
