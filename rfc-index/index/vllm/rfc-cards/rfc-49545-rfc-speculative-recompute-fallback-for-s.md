## 一句话结论
为远程 KV cache 加载加可选软超时,超时即转本地重算,在不改动快路径的前提下降低尾延迟。

## 提案动机
远程 KV cache 加载通常远快于本地重算,但 Mooncake `get` 偶发变慢时,请求可能等待约 60 秒才返回失败。对这类离群请求,继续等待的代价可能高于本地重算 KV。RFC 提出一个软超时回退机制,不改变正常远程加载路径,专门压低这类长尾。

## 提出的方案
- 为远程 KV 加载引入可选软超时(例如 5 秒):先分配 KV 块 A 并发起远程加载,超时前完成则正常使用 A。
- 超时后把加载移出请求关键路径:A 保留并隔离(不归还块分配器),另分配物理不同的块 B,把请求重映射到 B 并本地重算 KV。
- 原远程加载继续在后台进行,完成后忽略其结果并释放 A;无法分配额外 KV 块时保留现有等待/失败行为。
- 功能初始 opt-in,软超时、最大隔离 HBM 容量或回退请求数上限均可配置。

## 优化点与收益
收益方向是尾延迟:以离群慢加载时的临时 HBM 占用与重复计算为代价,换取更低的长尾延迟。正文未给出量化性能数字(60 秒、5 秒是超时参数,非收益数据)。正确性关键:A 在原传输可能仍访问期间不得归还分配器,逻辑超时不等于传输已完成;RDMA 取消与传输层恢复明确不在范围内。
