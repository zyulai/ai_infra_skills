## Purpose

Fixes a severe NVFP4 decode regression on Blackwell (B300 / GB300) introduced by #42988 ("[Perf] zeros -> empty to remove additional fill", commit `b29cbf0652`).

`create_fp4_scale_tensor` (`vllm/_custom_ops.py`) allocates the **swizzled** scale-factor buffer with shape `(round_up(m, 128), round_up(n // 16, 4) // 4)`, i.e. padded in both the M (to 128) and packed-K (to 4) dimensions. The NVFP4 quant kernel (`cvt_fp16_to_fp4`) writes scale factors through a swizzled tiled layout and does **not** write every padded element that the downstream NVFP4 GEMM subsequently reads. #42988 switched this allocation from `torch.zeros` to `torch.empty`, leaving those padded scale factors uninitialized → corrupted dequantization.

This is a **partial** revert of #42988: it restores `torch.zeros` for **only** the swizzled `int32` scale allocation. Everything else #42988 changed is intentionally kept (`torch.empty` / removed fill), because those buffers are genuinely safe to leave uninitialized:

- within the same function, the non-swizzled `uint8` branch allocates an **exact-size** buffer `(m, n // 16)` (no padding) whose kernel (`cvt_fp16_to_fp4_sf_major`, row-major `sf_out_rowmajor_u8`) fully covers it;
- the packed-FP8 scale, TurboQuant `attn_out`, and GDN `z_out` buffers are all fully overwritten before use.

So only the one padded buffer that the kernel does not fully initialize is restored to zero-init.

## Symptoms (measured)

For `con1 isl1000 osl1000`, TP4, `--quantization modelopt_fp4`:

- throughput collapse: ~87–93% drop in output-token throughput;
- output degeneration: output sequence length collapses far below the requested 1000 tokens;
- inter-token latency rises ~8–15×.

## Root cause

The fix relies on a narrow, directly-proven claim: the quant kernel leaves some consumer-visible elements of the padded swizzled buffer unwritten. This is proven by the fact that zero-initializing the buffer fully restores correct behavior, only possible if those elements were being read uninitialized. With `torch.zeros` they read a defined `0` (the long-standing pre-#42988 behavior).

## Validation

Single line toggled (`empty` ↔ `zeros`) on the swizzled `int32` allocation; `vllm serve` + `aiperf`, TP4, ISL/OSL=1000/1000. `OSL` below is the average output sequence length (requested 1000), derived from throughput; the derivation is approximate and can land slightly above the 1000 cap, so the meaningful signal is regressed (~65–127) vs. healthy (~870–1040), not the exact value.

**Per-hunk isolation, B300, Llama-3.3-70B, con=1** (proves this one line is necessary and sufficient):

| Configuration                                | Output tok/s | ITL (ms) | OSL    |
| -------------------------------------------- | -----------: | -------: | -----: |
| Baseline (#42988 as-is, all `empty`)         |        19.56 |    50.62 |  127.0 |
| Revert **swizzled `int32`** line only        |       135.40 |     7.35 |  873.2 |
| Revert non-swizzled `uint8` line only        |        19.49 |    50.77 |  127.0 |
| Revert fp8-util line only                    |        19.56 |    50.59 |  127.0 |
| Revert all `empty`→`zeros`                   |       162.29 |     6.11 | 1041.4 |

**Before/after, GB300NVL, con=1:**

| Model                | Allocation        | Output tok/s | ITL (ms) | OSL   |
| -------------------- | ----------------- | -----------: | -------: | ----: |
| Llama-3.3-70B (dense)| `empty` (regressed) |        18.39 |    53.99 | 127.0 |
| Llama-3.3-70B (dense)| `zeros` (fixed)     |       143.25 |     6.88 | 997.8 |
| Kimi-K2.5 (1T MoE)   | `empty` (regressed) |        10.16 |    97.61 |  65.8 |
| Kimi-K2.5 (1T MoE)   | `zeros` (fixed)     |       148.28 |     6.58 | 999.6 |

**Concurrency sweep with the fix, GB300NVL**:

| Concurrency | Llama tok/s | Llama OSL | Kimi tok/s | Kimi OSL |
| ----------: | ----------: | --------: | ---------: | -------: |
| 1           |      137.93 |     995.0 |     147.57 |   1000.2 |
| 16          |     2020.14 |    1000.0 |    1047.85 |    999.9 |
| 64          |     7305.73 |     999.7 |    2770.39 |   1000.0 |
| 128         |    11478.84 |     999.8 |    4913.39 |   1000.0 |

Throughput scales monotonically and OSL stays at the full requested length at every concurrency for both models — no degeneration at scale.
