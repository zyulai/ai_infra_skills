## 正文(PR 描述)

## Summary

- Fix off-by-one error in `_check_vocab_boundary_finish` in `schedule_batch.py`: change `token_id > self.vocab_size` to `token_id >= self.vocab_size`
- Valid token IDs are in range `[0, vocab_size)`, so `token_id == vocab_size` is out of bounds and should trigger the finish condition
- This is consistent with the same boundary check in `spec_utils.py` (line 597) which correctly uses `>=`

## Details

The `_check_vocab_boundary_finish` method is responsible for detecting out-of-bounds token IDs (e.g., caused by NaN in logits or sampling errors). The previous check `token_id > self.vocab_size` would miss the case where `token_id == vocab_size`, which is still an invalid token ID since valid IDs range from `0` to `vocab_size - 1`.

This matches the existing correct pattern in `speculative/spec_utils.py`:
```python
if vocab_size and curr_token_id >= vocab_size:
    accepted = False
```

+def _make_req(*, output_ids: list, eos_token_ids: set, stop_token_ids: set) -> Req:
+    # Build a bare Req without running __init__; only the fields touched by
+    # _check_vocab_boundary_finish are populated.
+    req = Req.__new__(Req)
+    req.output_ids = list(output_ids)
+    req.vocab_size = VOCAB_SIZE

+    req.finished_reason = None

+class TestVocabBoundaryFinish(CustomTestCase):
+    def test_token_equal_to_vocab_size_is_out_of_bounds(self):
+        # Valid ids are [0, vocab_size); id == vocab_size must trip the NaN guard.
+        req = _make_req(
