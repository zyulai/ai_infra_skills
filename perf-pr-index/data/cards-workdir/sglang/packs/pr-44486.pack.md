## Motivation

Since #33148, per-tensor FP8 linears (`ModelOptFp8LinearMethod`) run FlashInfer `bmm_fp8` on SM90 and newer. It takes no bias, so every biased Linear pays a separate `output + bias` pass: `BAAI/bge-reranker-v2-m3` in ModelOpt FP8 spent 43 of 197 ms per batch in these adds on an RTX PRO 6000.

## Modifications

- With a bias and at least 8192 rows, `apply_fp8_linear_bmm_flashinfer` adds the bias in the GEMM epilogue through `torch._scaled_mm(..., bias=bias, use_fast_accum=True)`, as `apply_fp8_linear` already does.
- Below 8192 rows nothing changes: there SGLang's autotuned `bmm_fp8` picks a faster kernel than `torch._scaled_mm` (not autotuned), which outweighs the saved add.
- flashinfer-ai/flashinfer#8811 (in review) adds a bias to `bmm_fp8` itself; with it, the threshold can go.
- Unit tests: the epilogue matches the bias-free path plus the bias; a CPU test pins the threshold.

## Accuracy Tests

bge-reranker-v2-m3 (on the epilogue, at 40k+ rows), 60 questions each of Ko-StrategyQA / MIRACL-ko: Recall@10 0.889 / 0.934 on main and this PR alike, mean |logit - FP32| 0.142 / 0.191 vs 0.143 / 0.191. `test_fp8_utils.py`: 10 passed, 1 skipped (needs SM100).

## Speed Tests and Profiling

RTX PRO 6000 (SM120), torch 2.14.1, FlashInfer 0.7.1. GPU time per `rerank` call on 128 pairs (mean of 2 runs):

| bge-reranker-v2-m3 FP8 | main | this PR |
|---|---|---|
| 128 x 320 tokens | 100.2 ms | **77.9 ms** |
| 128 x 640 tokens | 196.6 ms | **150.3 ms** |

GEMM + bias alone vs `bmm_fp8` (tuned at each M) + add, 12 shapes x FP16/BF16: 0.70x at the median and 0.90x at worst from 8192 rows; below 8192 it lost at 4 of 96 points, by up to 7%.
