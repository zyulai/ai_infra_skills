## 正文(PRD / 提案全文)

### Motivation.

Hello!
I recently explored speculative decoding for hybrid models (Qwen 3.5 model series) in vLLM and the recurrent-state memory bottleneck in the current implementation. With `mamba_cache_mode="all"`, a draft of `N` positions needs `N+1` full state snapshots per sequence per layer. On Qwen3.5-397B that is 90 MiB/seq i.e. 360 MiB for a depth-3 chain and ~1.2 GiB for a `[2,2,2]` tree (14 nodes), out of the same budget as the KV cache. To alleviate the recurrent-state memory bottleneck, my current implementation reconstructs the accepted state on commit rather than snapshotting it, using the WY/UT representation of the gated delta rule: one strictly-lower-triangular solve over the verify window gives every draft node's output, and any node's continuation state rebuilds from a small per-node stash. I extended it to support **tree** speculative decoding on GDN-based Qwen hybrids. Here's the [paper](https://arxiv.org/abs/2608.20961) related to the study. It has the memory analysis at both model scales, and the serving sweep.

I see that [ReplaySSM](https://github.com/vllm-project/vllm/issues/47572) does something similar for part of this.
I benchmarked ReplaySSM against my implementation on Qwen3.5-35B, and ReplaySSM is the more performant one for chain speculative decoding in hybrid models. It also is broader in terms of model support. Kudos to the team!

Where the two designs diverge: ReplaySSM and my current implementation solve the same triangular system on the same corrected inputs. The two kernels differ in one predicate: an index comparison where mine loads an explicit ancestor mask, so a commit becomes an ancestor-masked reduction rather than a cursor move. That is what makes a tree reachable.

Here's the [current implementation](https://github.com/vllm-project/vllm/compare/main...sneha5gsm:vllm:treewy-gdn-spec-decode), for reference.

Draft trees are not a throughput win yet: acceptance rises monotonically with width (from 3.23 to 3.44 on Spec-Bench) but throughput falls at every width. The cause is CUDA graph capture: a branching verify step cannot be fully captured today. Tree speculative decoding (width > 1) needs a non-causal ancestor mask on the softmax layers which leads to a fallback to PIECEWISE. 



 

### Proposed Change.

I would like to support tree speculative decoding for hybrid models in vLLM.

Since this relates to the ReplaySSM contribution, I am happy to collaborate with the ReplaySSM team to further support it for tree speculative decoding in hybrid models.
