## PR body
```markdown
## Motivation
The mHC `hc_mix` stats kernel uses BLOCK_K=64 everywhere. On SM120, BLOCK_K=32 is consistently faster.

## Modifications
`_HC_MIX_BLOCK_K = 32 if is_sm120() else 64`. The value is still a per-platform constant, independent of M, so the batch-invariance contract in the comment is preserved. GB10 (SM121) is not covered because it has not been measured.

## Accuracy Tests
- Kernel level: rel diff ≈ 3e-7 vs BLOCK_K=64.
- GSM8K 0.913 vs 0.905 (noise).

## Speed Tests and Profiling
RTX PRO 5000, DeepSeek-V4.1-Flash shapes, latency in us:

| M | BLOCK_K=64 | BLOCK_K=32 | Speedup |
|---|---|---|---|
| 1 | 23.2 | 22.5 | 1.03× |
| 256 | 37.4 | 27.2 | 1.38× |
| 1024 | 125.6 | 88.3 | 1.42× |
| 4096 | 683 | 451 | 1.51× |
| 16384 | 2818 | 1819 | 1.55× |

End to end: single-request 32K prefill 11443 → 11734 tok/s (+2.5%). Decode is unchanged.

### Validation of the combined branches
I validated a clean tree: upstream `a90e9c5d` plus #42371 plus this PR and the three companion SM120 PRs (DeepGEMM metadata, b12x MXFP8, mHC BLOCK_K, RTX PRO 5000 configs). It ran on 8x RTX PRO 5000, DP8 attention + EP8, with `--fp8-gemm-backend flashinfer_cutlass`:

| clean branches | 0.905 | 0.807 | 9.59 | 12020 | 17.4 ms |
