## Motivation

Muse Spark fuses its MoE finalize with the custom all-reduce. Today the fused kernel only implements `1shot_push`, and it runs only where the standalone all-reduce would pick `1shot_push`. Above that size the MoE output falls back to a separate finalize kernel plus a standalone all-reduce launch.

This PR adds a `2shot_push` exchange to the fused kernel. The fused path now follows the standalone all-reduce's choice: fused 1-shot where it picks `1shot_push`, and fused 2-shot where it picks `2shot_push`.

Independent of #46197; the fused 2-shot path runs wherever the all-reduce table picks `2shot_push` (main's table on GB300; on SM107 from #46197). SM107 numbers below are measured on top of #46197, GB300 numbers on main.
## Modifications

<!-- Detail the changes made in this pull request. -->

**Kernel** (`muse_spark_moe_finalize_all_reduce_cutedsl.py`)

- The 2-shot exchange follows the `2shot_push` protocol of `custom_all_reduce.cuh`.
- The output is bitwise equal to the fused 1-shot path.
- It reuses the communicator's push slots and epoch controllers, so there are no new allocations.
- When M exceeds the controller count, a block finalizes two tokens, one row of threads each, with per-row named barriers. This applies to 2-shot and unicast 1-shot; multicast 1-shot measured slower.
- One-row fused blocks reduce four experts per barrier pair (`group_width` 4, as the cluster path already does).
- Refactor: the 1-shot `push_token` / `reduce_token` and the new 2-shot functions share small helpers: copy atoms, `_vec_at`, `_epoch_base`, `_remap_sentinel`, `_poll_arrived` and `_sum_ranks`.

**Dispatch** (`muse_spark_finalize_workspace.py`, `muse_spark_moe_finalize_all_reduce.py`)

- `two_shot_max_tokens = slot_bytes * world / (4H)` (2048 tokens at TP4 with the default 8 MB slot). It is 0 unless `H % (8 * world) == 0`, so every rank owns whole 8-column vectors.
- `uses_two_shot_push(M)` is true exactly where the standalone all-reduce picks `2shot_push`, including under `override_algo`.
- `can_fuse` takes the fused 1-shot or the fused 2-shot path. The separate `override_algo` check is gone, because both predicates already go through the communicator's own override handling.
- No standalone all-reduce thresholds or buffer allocations change.
