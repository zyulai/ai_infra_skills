## Overview

Let XPU use the existing Model Runner V2 path that reuses GDN attention metadata across KV cache groups (#58762). Both the reuse path and the aligned state index precompute it depends on in mamba `align` mode were limited to CUDA; this PR allows XPU in both checks.

## Claims

- On XPU, hybrid GDN models (Qwen3.5 / Qwen3.6 family) build GDN metadata once per KV cache spec per step and re-gather state indices for the other groups via `update_block_table()`, as on CUDA. With 3 GDN KV cache groups, 2 of 3 metadata builds per step are replaced.
- Outputs are unchanged.

## Validation

Intel Arc Pro B70, MTP with `num_speculative_tokens=3`, eager mode, prefix caching on (mamba `align` mode), greedy decoding with `logprobs=1`. GDN metadata calls were counted inside the workers; baseline is unmodified main.

| Qwen3.8-27B-FP8 | TP=2, B1+B8, per worker | 2133 → 711 | 0 → 1422 | tokens identical across 4 processes; B8 logprobs identical; B1 max logprob difference 0.093, baseline-vs-baseline 0.075 |

## Details

`GDNAttentionMetadataBuilder.supports_update_block_table` required `device.type == "cuda"`. In mamba `align` mode, `update_block_table()` reads the indices produced by `MambaSpecDecodeGPUContext.compute_aligned_state_indices()`, which asserted `seq_lens.is_cuda`. Qwen3.5 uses `align` mode by default when prefix caching is enabled, so allowing XPU only in the first check fails at that assert. The precompute is a Triton kernel and runs unchanged on XPU; identical outputs above confirm the indices match the per-group build.

No new test is added: the existing builder tests that cover `update_block_table()` are device-independent and pass, and there is no existing unit test for the precompute numerics; the change only widens two device checks, and the end-to-end comparison above exercises both on XPU.

#58851 moves this sharing into the builder and drops the CUDA check for sharing itself, but keeps the aligned-index precompute CUDA-only. This PR is independent of it; the `compute_aligned_state_indices()` change is still needed for XPU in `align` mode either way.

Limitations: XPU only (no CUDA behavior change), eager mode only; graph mode was not exercised.
