## 正文(PR 描述)

Closes #29330 

## Motivation

#29330: GSM8K accuracy on Nemotron-3-Ultra collapses with long few-shot prefills (8-shot fine, 20-shot broken), on both NVFP4 and BF16. The cause is in shared Mamba metadata, so it affects any hybrid-mamba model served with the radix prefix cache.

`Mamba2Metadata` gates the initial-state restore on the tracking mask:

```python
has_initial_states = context_lens_tensor > 0
mamba_track_mask = getattr(forward_batch, "mamba_track_mask", None)
if mamba_track_mask is not None:
    has_initial_states = has_initial_states & mamba_track_mask[: has_initial_states.shape[0]]
```

`has_initial_states` decides whether a prefill seeds its conv/SSM scan from the state already in its cache slot. `mamba_track_mask` marks the steps that snapshot state into the prefix cache (`extend_range.length >= mamba_cache_chunk_size`). The two are independent. Under `--parallel` with a shared few-shot prefix, most requests are prefix-cache hits that prefill only a short unique suffix, so their track mask is `False`; the AND then zeroes `has_initial_states` and the suffix runs from a blank Mamba state. Longer cached prefixes lose more state, so 8-shot passes and 20-shot fails. The gate was added in #24955; the 0.5.13 release does not have it.

## Modifications

Remove the `mamba_track_mask` gate so the restore depends only on `context_lens > 0`, matching pre-#24955 behavior. The snapshot/tracking path in `mamba.py` still uses `mamba_track_mask` and is unchanged.

## Accuracy Tests

`benchmark/gsm8k/bench_sglang.py --platinum --parallel 128`, greedy.

NVIDIA-Nemotron-3-Ultra-550B-A55B-NVFP4, TP4, 4x B200:

| shots | before | after |
|-------|--------|-------|
| 8     | 0.943  | 0.981 |
| 20    | 0.617  | 0.980 |

NVIDIA-Nemotron-Nano-9B-v2 (BF16, same architecture, 1x H100), used to bisect. The 9B is more robust, so the cliff appears at a higher shot count with the same signature:

| shots | before | after |
|-------|--------|-------|
| 8     | 0.915  | 0.915 |
| 72    | 0.680  | 0.945 |

## Unit Tests

Run on the fixed tree (B200), no regressions:

- `test/registered/layers/mamba/`: 934 passed
- `attention/unittests/{mamba,gdn,hybrid_linear}` + `unit/mem_cache` + `unit/model_executor`: 1501 passed, 717 skipped (hardware-gated)
- `unit/{managers,layers,sampling,server_args,parser}`: 909 passed

The 3 failures in `test_fp4_kv_cache_quant_method.py` are pre-existing on `main` (a `torch.compile` fake-tensor device-propagation issue in the NVFP4 KV-cache quant method) and reproduce with this patch reverted, so they are unrelated to this change.

## Speed Tests and Profiling

No speed impact; the change removes a boolean AND. After the fix (550B, 1209 questions): 8-shot 129 s / 1025 tok/s, 20-shot 146 s / 924 tok/s.
