## 正文(PR 描述)

## Overview

On gfx942, DeepSeek-V4.1-Flash with `--monokernel` and adaptive DSpark verification dies with `Memory access fault` during CUDA graph capture. The profile replays a context over KV blocks no request has written. The draft FFN then sees NaN router scores. `stage_route` ranks with `fx.max`, which keeps the NaN, so the same expert is picked twice and a later gather indexes off the slot table.

A NaN score now ranks last, and the winner ballot ignores lanes past the expert count. Both edits are in this patch. The KV fill is gone.

## Claims

- Without this patch, the serve command faults during the real capture and the server does not start.
- With both router edits and no KV zero, the real capture finishes and the server starts.
- Finite scores pick the same experts. TPOT on the shapes below stays with stock.
- No config or API change.

## Details

`batches_to_profile` is the only caller that passes a nonzero `context_len` into `_dummy_run`. `set_dummy_context` fills block tables with ids nobody has written, and the draft reads them. Two requests replay 10 tokens, the gfx942 monokernel's multi-tile draft FFN, and that launch faults.

`fx.max` keeps a NaN, and the NaN then compares equal to itself, so the draft shape emits the same expert id twice. The route counts winners with a bitmap, the count comes up short, and the gather reads off the slot table. Ranking the NaN as `-inf` after the max, and masking the ballot with `cursor < ept`, removes the duplicate. Kimi-K3 and MiniMax-M3 already drop NaN scores before ranking. The ballot mask is particular to this router, which holds 2 experts per lane and picks 3.

A local ranking check matches that. Unguarded draft NaN rows pick `[[0, 64, 0], [0, 64, 0]]`, bitmap 28 against 30 slots. With both edits the bitmap is 30 and there are no duplicates. Finite draft scores, and the target 384/6 shape, match with and without the guard. That check is the ranking logic, not the GPU kernel.

`stage_route` runs on every monokernel FFN launch, including target-only decode with adaptive verification off. The TPOT rows are that path.

Warmup and `profile_run` leave `context_len` at 0. `set_dcp_capture_context` is the other fabrication, only when `cp_size > 1`, and this PR does not change it.
