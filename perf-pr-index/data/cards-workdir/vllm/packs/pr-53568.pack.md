## PR body
```markdown
## Purpose

Follow-up to #49775 and #45739.

#45739 used a separate `torch.zeros` allocation to initialize padded NVFP4 scales. This PR moves the required initialization into the CUDA quantization kernel, allowing the wrapper to safely use `torch.empty` and avoid the extra zero-fill launch.

It also:

- Preserves a specialized fast path for unpadded output.
- Retains programmatic dependent launch support.
- Adds sentinel-based regression coverage for padded rows and columns.

This does not duplicate #47587, which covers FlashInfer’s TRT-LLM 8x4 layout. This PR targets vLLM’s built-in 128x4 swizzled kernel.

## Test Result

Validated on NVIDIA B300 with CUDA 13.4 (`sm_103a`):

- Full vLLM build passed.
- NVFP4 quantization suite: `62 passed`.
- Compute Sanitizer: `2 passed`, `ERROR SUMMARY: 0 errors`.
- Ruff, mypy, clang-format, typos, SPDX, forbidden-import and CUDA-call hooks passed.

The benchmark results that motivated this change are documented in [the original discussion](https://github.com/vllm-project/vllm/pull/49775#issuecomment-5375613975). For Llama 3.3 70B (`N=8192`, `K=28672`), the built-in 128x4 swizzled kernel shows the following before/after results:

| M | vLLM `main`, before (us) | This PR (us) | Speedup | FlashInfer CuTe-DSL (us) |
|---:|---:|---:|---:|---:|
| 1 | 3.133 | 1.912 | 1.639x | 2.418 |
| 16 | 3.132 | 2.008 | 1.560x | 2.636 |
| 32 | 3.197 | 2.089 | 1.531x | 2.790 |
| 64 | 3.411 | 2.200 | 1.550x | 2.900 |
| 128 | 3.305 | 2.497 | 1.324x | 3.253 |
| 256 | 4.576 | 3.718 | 1.231x | 4.031 |
| 512 | 6.828 | 5.834 | 1.170x | 5.600 |
| 1024 | 10.791 | 9.822 | 1.099x | 9.750 |
| 2048 | 24.675 | 24.857 | 0.993x | 28.773 |
| 4096 | 46.590 | 47.080 | 0.990x | 47.462 |
| 8192 | 90.676 | 91.298 | 0.993x | 93.118 |

The change improves the launch-bound small- and medium-`M` cases by up to 1.64x and is effectively neutral at large `M`, where quantization work dominates the removed initialization overhead.

AI assistance was used to port the existing fix onto current `main`.
```
