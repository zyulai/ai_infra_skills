## PR body

## Summary

Eligible Kimi-K3 AMD AttnRes outputs currently materialize BF16 activations that the next linear immediately quantizes. Fuse that per-token FP8 conversion into AttnRes and pass native `QuantizedActivation` to supported consumers.

```diff
 AttnRes + output RMSNorm
-  store BF16 → per-token FP8 quant → input GEMM
+  store FP8 + scale → input GEMM
```

Enable the path only for `kFp8DynamicTokenSym` and only when all consumers accept the same key. Mixed MoE/router consumers, unsupported linear kernels, and batch-invariant mode retain the original path. Preserve BF16 rounding before quantization and the prefix/block write contract.

This is independent of PD connector work and targets main. Duplicate checks covered #50682, #52968, and #53154: #52968's current diff covers convolution and sigmoid/multiply; #53154 covers MXFP4 output fusions. This PR supplies AttnRes per-token FP8 inputs. The current rowwise Torch FP8 KDA kernel does not expose the required input capability, so this PR does not claim all KDA inputs are fused.

## Evidence

### CI follow-up (2026-10-08)

[Buildkite #93497](https://buildkite.com/vllm/ci/builds/93497) exposed an implicit compiled reference in the FP8 output test when AITER is disabled. Commit `42f0ad593` sets `compile_native=False` for the `QuantFP8` reference, keeping its rounding independent of Inductor fusion. Production code and every numerical tolerance are unchanged. The AttnRes and MLA/KDA direct-return suites pass with AITER disabled (**23 passed**) and enabled (**23 passed**); changed-file pre-commit and Python 3.12 mypy pass. [Buildkite #93546](https://buildkite.com/vllm/ci/builds/93546) retries the failed K3 step on that commit.


- **Before:** AttnRes and per-token quantization launch separately.
  **After:** A single producer emits activation and scale. Existing + new AttnRes cases passed on all eight MI355X GPUs (16 tests/rank in the final run, including the three capability cases), with exact prefix/block writes, scale rtol 1e-6, and rounding differences limited to an adjacent FP8 code in <1e-4 of values. Three direct-return tests also passed.
- In the paired rank-0 prefill trace, the corresponding standalone AITER per-token quant kernel count falls from 4009 to 3078 (931 calls removed), while AttnRes executes the same 3553 calls.
- `pre-commit run` and `pre-commit run mypy-3.12 --hook-stage manual`: passed.
- Eight-rank `benchmarks/kernels/benchmark_kimi_k3_amd_fp8_fusions.py` compares AttnRes + quant + one MLA input GEMM (N2112/K7168), using nine rotated CUDA-graph samples per rank. Median of per-rank medians, four residual blocks:
