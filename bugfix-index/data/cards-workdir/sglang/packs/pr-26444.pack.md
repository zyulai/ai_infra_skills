## Motivation

  Fixes https://github.com/sgl-project/sglang/issues/25487

  On CUDA 13.0, the JIT compilation of `activation.cuh` fails during CUDA graph capture, crashing the server process. The root cause is a C++ template type/value mismatch in the `select_kernel` trailing return type:

  activation.cuh:95:52: error: type/value mismatch at argument 1 in template parameter list
    note: expected a type, got 'ActivationKind::kSiLU'

  CUDA 13's stricter `nvcc` cannot correctly parse `decltype(ActivationKernel::template activation_kernel<ActivationKind::kSiLU, kFilterExpert>)` in a dependent context (trailing return type with an outer template parameter `kFilterExpert`). It
   misinterprets the non-type enum value `ActivationKind::kSiLU` as a type argument. Older CUDA versions (11/12) silently accepted this.

  ## Modifications

  - Introduced an explicit `kernel_fn_t` type alias via `decltype(&act_and_mul_kernel<...>)` on the global function template (avoids the problematic variable template parsing path).
  - Replaced `auto` with `kernel_fn_t` for the `activation_kernel` variable template.
  - Removed the `decltype`-based trailing return type from `select_kernel`, using `kernel_fn_t` directly.
  - Removed unnecessary `ActivationKernel::template` qualification inside the class body.
  - Added `static_cast<uint32_t>()` for `hidden_size` to fix a signed-to-unsigned narrowing conversion warning.

  All changes are compile-time only — no runtime behavior or performance change. Compatible with CUDA 11, 12, 13, and ROCm/HIP.
