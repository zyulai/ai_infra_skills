## PR body
```markdown
## Purpose

Supersedes #44296 (rebased onto main with the original commit and authorship preserved — thanks @Tonoken3); that PR has had failing pre-commit since opening and merge conflicts since July 6 with no author activity, so this revives it to make the merge cheap.

Speculative decoding (ngram, EAGLE-3, any method) on `short_conv` (LFM2 / LFM2.5) targets silently corrupts output at the first rejected token: attention KV rolls back, but the conv sliding window retains rejected-token activations. `mamba2` / GDN already handle this via the spec-aware `causal_conv1d_update` path; `short_conv` was never wired in:

1. `MambaStateShapeCalculator.short_conv_state_shape` sizes the conv state `conv_kernel - 1` (no `num_spec`), so there is no room to roll the window back (mirror: `mamba2_state_shape` adds `num_spec`).
2. `GPUModelRunner._build_attn_group_metadata` never injects `num_accepted_tokens` for `ShortConvAttentionMetadataBuilder`, so the layer never sees the accepted-token counts.

Changes vs #44296: rebased onto current main, fixed the mypy failure that blocked its pre-commit (`assert state_indices_tensor_d is not None`), added a regression test for the spec-widened conv state shape.

## Why this is not duplicating an existing PR

#44296 is this fix (red CI + conflicts + stale for 8 weeks; original commit and authorship preserved here). #50146 bundles a rebase of the same target-side fix with 6 further drafter-side changes across 9 files and depends on other open PRs; this PR is the minimal, independently mergeable target-side correctness fix for released models.

## Test plan

- `pre-commit run` (incl. mypy-3.10): pass.
- New `tests/kernels/mamba/test_short_conv_state_shape.py`: pass.
- E2E (we are the model vendor — Liquid AI serving team; LFM2.5-230M fine-tune + trained EAGLE-3 drafter with ~0.9/step acceptance, ROCm MI325X, v0.26.0 + this patch): without the fix, low-concurrency spec decode diverges after the first rejection (doubled/fused tokens, occasionally flipped outputs; under default cudagraphs it degrades to garbage from ~token 2). With it, `--enforce-eager`, `PIECEWISE`, and default `FULL_AND_PIECEWISE` all produce identical, correct output on fixed-seed content probes.

AI assistance was used to rebase, fix, and validate this change; I reviewed every changed line and am accountable for it.
```
