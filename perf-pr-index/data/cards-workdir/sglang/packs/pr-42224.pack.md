## Motivation

A2 and A3 NPUs do not support FP8 LightningIndexer, so FP16 is the only practical precision for the indexer. This makes the indexer a bottleneck for long-context workloads. This PR adds an int8 quantization option for the NPU LightningIndexer. It stores the indexer key cache as int8 and uses the NPU-native npu_quant_lightning_indexer kernel, delivering a 2× indexer speedup and reducing end-to-end TTFT on Ascend A2/A3.

The feature is opt-in via `--indexer-kv-cache-dtype int8` and is off by default, preserving existing behavior.

## Modifications

- `python/sglang/srt/arg_groups/fields/model.py`

New server argument `--indexer-kv-cache-dtype` (choices: `int8`, default `None`) — quantization recipe for the DSA lightning-indexer KV cache (Ascend NPU only).

- `python/sglang/srt/arg_groups/kv_cache_hook.py`, `python/sglang/srt/arg_groups/pipeline.py`, `python/sglang/srt/arg_groups/resolution_hooks.py`

New resolution-pipeline hook `handle_indexer_kv_cache_compatibility`. When a recipe is explicitly requested it fails fast instead of silently degrading:
- not supported with `--enable-hierarchical-cache` (the INT8 + hierarchical-cache combination is rejected explicitly);
- only for DSA models that actually have a lightning indexer.

- `python/sglang/srt/mem_cache/kv_cache_dtype.py`

`resolve_indexer_quant_mode()` maps the argument to an indexer quant mode (`"int8"` -> `QUANT_MODE_TOKEN_INT8`). The INT8 recipe exists only on top of a non-FP8 main KV cache: an FP8 main KV cache already stores the indexer cache quantized, so `int8` on top of `--kv-cache-dtype fp8_e4m3` is rejected.

- `python/sglang/srt/hardware_backend/npu/memory_pool_npu.py`

`NPUMLATokenToKVPool` accepts `indexer_quant_mode`. When INT8 is enabled (and the main KV cache is not the FP8 packed store), `index_k_store_dtype = torch.int8` and `index_k_scale_dtype = torch.float16` (FP8 mode keeps FP32 scales). The scale buffer is created for both quantized modes with the proper scale dtype, and the index-K setters assert the expected dtypes.

- `python/sglang/srt/layers/attention/dsa/dsa_npu_indexer.py`

`_quantize_npu_indexer_activation` takes the scale dtype from the pool (FP16 for INT8, FP32 for FP8). For an INT8 key cache the indexer weights are cast to FP16 (the INT8 kernel requires FP16 weights) and the op is invoked through `torch.ops.npu.npu_quant_lightning_indexer`, because the `torch_npu.npu_quant_lightning_indexer` binding misbehaves for the INT8 cache when `custom_ops` is imported. 

- `python/sglang/srt/model_executor/pool_configurator.py`

Fixes the memory sizing of the DSA indexer cache for the INT8 recipe: 1 byte per element plus one FP16 scale per token (`index_head_dim + 2` bytes/token instead of the BF16 size, e.g. 130 vs 256 bytes/token for `index_head_dim=128`).

+def resolve_indexer_quant_mode(
+    indexer_kv_cache_dtype: Optional[str],
+    main_kv_cache_dtype: torch.dtype,
+) -> Optional[int]:
+    """Map --indexer-kv-cache-dtype to a quantized-indexer recipe for the
+    NPU DSA indexer cache.
+
+    None leaves the quantized indexer at its default: an FP8 main KV cache
+    keeps the existing FP8 indexer (the DSA FP8 packed store), any other
+    main dtype leaves the quantized indexer disabled (the DSA indexer then
+    runs the legacy bf16 npu_lightning_indexer path). The INT8 recipe only
+    exists on top of a non-FP8 main KV cache; the FP8 main cache already
+    stores the indexer cache quantized.

+        )

+            f"--indexer-kv-cache-dtype={indexer_kv_cache_dtype} requires a "
+            "non-FP8 main KV cache (--kv-cache-dtype auto or bf16), "
+            f"got {main_kv_cache_dtype}."
+        )
+    return quant_mode
