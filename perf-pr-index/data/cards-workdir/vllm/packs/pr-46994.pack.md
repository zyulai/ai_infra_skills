## PR body

## Purpose

MTP speculative decoding does not work under pipeline parallelism on the V2 model runner. #50514
landed the generic PP spec-decode transport; this PR covers the MTP-specific gaps that remain on
the PP>1 path.

**Depends on #55745** — a one-line `record_stream` guard in #50514's `broadcast_drafts`, without
which this path trips a device-side `IndexKernel` assert under async launches. It is the bottom
commit here and can be dropped once #55745 merges.

**1. MTP drafters do not implement `SupportsPP`.** The engine refuses to build the draft at all:
```
NotImplementedError: Pipeline parallelism is not supported for this model.
Supported models implement the `SupportsPP` interface.   [DeepSeekMTPModel]
```
The draft runs only on the last PP stage, so it never consumes PP intermediate tensors, but the
interface still requires the `make_empty_intermediate_tensors` factory. Applied to `DeepSeekMTP`
and `Qwen3_5MTP`. Mirrors #39704 for the V1 runner.

**2. Qwen3.5/3.6 MTP draft head skips its `fc` projection.** It branched on `is_first_rank`, which
is False on the last PP stage where the drafter is built. The head then fell through to the
intermediate-tensor path with nothing to read (~1% acceptance). Now branches on
`intermediate_tensors is None`, which is equivalent for a pipelined module and correct for a
whole-drafter-on-one-rank module. @hackxixi suggested this as the general rule for draft heads.

**3. DeepSeek MTP does not load its own `embed_tokens`.** A checkpoint storing it as one top-level
tied weight has no spec layer to rewrite from. The loader dropped it, and the draft embedded with
uninitialised weights. Under PP the target's copy is a `PPMissingLayer` on the draft's stage, so it
cannot borrow the target's. Per-spec-layer checkpoints are unaffected.

**4. `DeepseekV32MTP` carries neither of the above.** It was forked out of `DeepSeekMTP` after this
branch first added `SupportsPP`, and took neither that nor the `embed_tokens` load.
`speculative.py` routes `deepseek_v32` and `glm_moe_dsa` there, so this is the GLM-5.2 and
DeepSeek-V3.2 path. Missing `SupportsPP` raises the error above; the missing `embed_tokens` load is
silent — the engine serves correct output, because rejected drafts are discarded, and only
acceptance shows it: 32.69% against 93.51% once the weight loads. Both restored on the nvidia and
amd variants.

**5. Stale `topk_indices_buffer` in sparse MLA backends.** `LLMBaseProposer.load_model` repoints
the draft's indexers at the target's buffer, but that runs after the backend impls snapshot it in
`__init__`. Its `named_modules()` walk reaches the indexer but not the impls, which are plain
`AttentionImplBase` objects. The impls then read a buffer nothing writes: garbage DSA attention and
degenerate drafts.

A `SharedTopkIndicesBuffer` mixin now resolves the buffer per read, so `forward_mqa` is unchanged
and every `SparseMLACommonImpl` subclass is covered, including `flashinfer_mla_sparse_sm90`. The
three impls that are not subclasses (`flashinfer_mla_sparse_sm120`, `rocm_aiter_mla_sparse`,
`xpu_mla_sparse`) use the same mixin. An explicit assignment still supersedes the indexer, which is
how skip-topk layers and the proposer's module walk set it. The mixin is in
`sparse_mla_attention.py`, not `v1/attention/backend.py`: every consumer is sparse MLA, and the
four span two bases whose only shared ancestor is `AttentionImplBase`.

`DeepseekV32Model` (nvidia) held the buffer in a local, so the proposer's sharing block never ran
for DSA at all. It is now exposed on the model, as the ROCm variant already does.

**6. Draft MM embedding gather on ranks without an encoder runner.** `ModelState.encoder_runner`
exists only on the first PP rank, so a multimodal-capable MTP drafter died in warmup on the last:
```
AttributeError: 'MambaHybridModelState' object has no attribute 'encoder_runner'
```
Later ranks have no cached embeddings to gather. `Qwen3_5MTP` is the first in-tree draft that is
both `SupportsPP` and `SupportsMultiModal`.

## Not duplicating existing work

- #50514 provides the PP draft-token transport. The earlier revision of this PR carried its own
  version; that is dropped. The only change here to `v1/worker/gpu/pp_utils.py` is #55745's guard.
- #53408, #54635, #55081 (@JasonKeyiL) implement `SupportsPP` on other MTP families; neither
  `deepseek_mtp.py` nor `qwen3_5_mtp.py` is touched by any of them. #55081 overlaps fix 4's
  `SupportsPP` half, which can be dropped if it merges first.
- #54709 (qwen4_exp draft head) is the same bug as fix 2 and takes the same one-liner; left out to
  keep this focused.
