## Overview

On gfx950 (AITER FlyDSL MXFP8 path, #67377), DeepSeek-V4.1's MXFP8 linears quantize their bf16 input in a separate `mxfp8_e4m3_quantize` launch. This PR moves that quant into the producing kernel for three linears:

- **① `fused_wqa_wkv`**: AITER Mega-MHC also writes its attention-seam layer input as MXFP8.
- **② shared expert `gate_up_proj`**: likewise for the FFN-seam layer input.
- **③ shared expert `down_proj`**: a new Triton kernel fuses `silu_and_mul_with_clamp` with the MXFP8 quant.

Outputs are bit-identical to the unfused path.

## Claims

- Removes three standalone MXFP8 quant launches per layer, and the bf16 round trip of the shared expert's activation.
- On 2x MI355X DEP2, the forward step is 0.23-0.38% faster for 8k / 16k-token prefill and 768-token decode steps.
- Bit-identical outputs; GSM8K unchanged.
- ROCm-only change; other backends keep their current path.

## Details

`RocmDotScaledMxfp8LinearKernel` already reads a `QuantizedActivation` with row-major `[M, K / 32]` E8M0 scales, so the producers hand over the quantized copy and the GEMMs are unchanged.

- **① / ②:** `mhc_pre_delayed_mxfp8` runs the Mega-MHC seam with `out_dtype="mxfp8"`. It attaches the `QuantizedActivation` to the bf16 layer input as an attribute (`attach_mxfp8_input`), which `fused_wqa_wkv` and the shared expert's `gate_up_proj` read back. Any reshape, slice or gather drops the attribute, so a consumer only sees the copy of the rows it projects. The bf16 input stays available for the router, compressor, indexer and MegaMoE, and the shared `forward` signatures are unchanged.
- **③:** `silu_and_mul_mxfp8` computes the clamped SiLU-and-mul in fp32, rounds it to bf16 as the unfused path does, and quantizes it with `_mxfp8_quant_triton_kernel`'s arithmetic.

**When it applies:** gfx950 with AITER, the consumer linear on `RocmDotScaledMxfp8LinearKernel` / `AiterFlyDSLMxfp8LinearKernel`, and no sequence parallelism. In addition:

- ① / ② need Mega-MHC; ② also needs MegaMoE with an unfused shared expert.
- Decode steps of at most 128 tokens per rank inside FULL graphs use the mHC overlap path, where ① / ② do not apply.

**Other backends:** only ROCm-only modules change (`vllm/_aiter_ops.py`, `models/deepseek_v4/amd/`, `models/deepseek_v41/amd/`). Shared layers are untouched, so CUDA, XPU and CPU are unaffected. DeepSeek-V4 shares `DeepseekV4MLP`, but its linears are not MXFP8, so it keeps its current path.

**Not a duplicate:** open PRs #66572 / #65837 (q-norm quant before `wq_b`) and #63821 / #66856 (`wo_a` epilogue quant before `wo_b`) fuse different quants.

+"""SiLU-and-mul (optionally clamped) fused with the MXFP8 quant of its output.
+
+On gfx950 the MXFP8 linear after the shared expert's activation quantizes the
+bf16 activation in a separate launch; this writes the e4m3 values and row-major
+`[M, D / 32]` E8M0 scales directly, bit-identical to `SiluAndMul` /
+`SiluAndMulWithClamp` followed by `mxfp8_e4m3_quantize`.
+"""
+
+import torch
+
+from vllm.model_executor.layers.quantization.utils.mxfp8_utils import (
+    MXFP8_BLOCK_SIZE,
+    MXFP8_SCALE_DTYPE,
+    MXFP8_VALUE_DTYPE,

+from vllm.triton_utils import tl, triton

+@triton.jit
+def _silu_and_mul_mxfp8_kernel(
+    x_ptr,
+    q_ptr,
+    s_ptr,
+    M,
+    D: tl.constexpr,
+    LIMIT: tl.constexpr,
+    HAS_LIMIT: tl.constexpr,
+    BLOCK_M: tl.constexpr,
+    BLOCK_N: tl.constexpr,
+    FP8_MAX: tl.constexpr,
+    TINY: tl.constexpr,
+):
+    rows = tl.program_id(0) * BLOCK_M + tl.arange(0, BLOCK_M)
+    cols = tl.program_id(1) * BLOCK_N + tl.arange(0, BLOCK_N)
+    mask = rows[:, None] < M
+    rows64 = rows[:, None].to(tl.int64)
+    gate = tl.load(x_ptr + rows64 * 2 * D + cols[None, :], mask=mask, other=0.0)
+    up = tl.load(x_ptr + rows64 * 2 * D + D + cols[None, :], mask=mask, other=0.0)
+    gate = gate.to(tl.float32)
+    up = up.to(tl.float32)
+    if HAS_LIMIT:
+        gate = tl.minimum(gate, LIMIT)
+        up = tl.minimum(tl.maximum(up, -LIMIT), LIMIT)
+    # Round to the activation's bf16 first, as the unfused path materializes it.
+    y = (gate / (1.0 + tl.exp(-gate)) * up).to(x_ptr.dtype.element_ty)
+    y = tl.reshape(y.to(tl.float32), (BLOCK_M, BLOCK_N // 32, 32))
+    # Same arithmetic as _mxfp8_quant_triton_kernel (mxfp8_e4m3_quantize).
+    amax = tl.maximum(tl.max(tl.abs(y), axis=2), TINY)
+    sb = tl.ceil(tl.log2(amax / FP8_MAX)) + 127.0
+    sb = tl.minimum(tl.maximum(sb, 0.0), 254.0)
+    q = tl.reshape(y * tl.exp2(127.0 - sb)[:, :, None], (BLOCK_M, BLOCK_N))
+    tl.store(

+    )
+    groups = tl.program_id(1) * (BLOCK_N // 32) + tl.arange(0, BLOCK_N // 32)
+    tl.store(s_ptr + rows64 * (D // 32) + groups[None, :], sb.to(tl.uint8), mask=mask)

+    else:
+        block_m, block_n, warps = 32, 256, 8

+        TINY=float(torch.finfo(torch.float32).tiny),
+        num_warps=warps,
+    )
+    return values, scales
