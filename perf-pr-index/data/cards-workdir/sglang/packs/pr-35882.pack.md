## PR body
```markdown
A copy whose source is a checkpoint mapping is synchronous however it is requested — the driver stages unpinned memory through its own buffer — and the prefetch hooks run on the compute thread, so every mapped layer stalled the denoise step for its whole transfer. This adds a courier: a worker thread that stages a mapped layer's bytes into one of two pinned slots (a plain memcpy when the page cache holds them) and issues the device copy on its own stream, where it is genuinely asynchronous. Parameters are still rebound on the compute thread at collect time, so module state is never touched concurrently; blocking callers and any courier failure keep the direct synchronous path.

Measured on MiniMax-H3 fl2va, one RTX 4090, 12 GiB allocator cap, 32 GiB host envelope, 864×480 / 124 frames / 20 NFE, interleaved same-window A/B: baseline 538.8 s of denoise (median 25.0 s/step) against 369.1 s (median 18.0) with the courier — 31% faster, and the effect grows with host memory-bandwidth contention, because that contention is exactly what the compute thread stops paying for. Output equivalence was checked at the video level: SSIM against a baseline run equals the baseline's own run-to-run SSIM (0.9941 = 0.9941), and the audio stream is bit-identical.

Stacked with per-layer pinning (#35867) and the VAE staying on its mapping (#35862), the same budget runs the lossless bf16 denoise at a **median of 11.0–12.0 s/step across two interleaved rounds — ahead of ComfyUI's 13.0** measured under the same 32 GiB psutil convention on the same GPU in the same bandwidth window.

Tests cover the ship/collect handshake, release_all draining an in-flight layer, and the fallback when the courier dies mid-flight; the first two fail with the courier disabled.

Merge note: this PR and #35867 touch the same file; whichever lands second rebases (the resolution is mechanical — both sides add independent methods).
```
