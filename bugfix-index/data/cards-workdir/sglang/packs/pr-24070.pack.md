## 正文(PR 描述)

Fix a bug where `rid_to_state` entries are not cleaned up when queued requests are aborted, causing `Duplicate request ID detected` errors on resubmission.

## Motivation
When aborting all requests (e.g., during weight updates or pause/resume), queued requests that were waiting in the scheduler are aborted and an `AbortReq` is sent back to the `TokenizerManager` via `_handle_abort_req`. However, this handler never called `del self.rid_to_state[rid]`, leaving stale entries behind.

The root cause is that **running** and **queued** requests follow completely different abort paths, and the queued path was missing cleanup:

  **Running request abort** — goes through the normal forward → output pipeline:
```text
  scheduler: req.to_finish = FINISH_ABORT()
    → next forward pass finishes normally
    → stream_output() sends BatchStrOutput
    → detokenizer forwards to tokenizer_manager
    → _handle_batch_output()
      → del self.rid_to_state[rid]   ✅ cleaned up
```

  **Queued request abort** — never enters forward, scheduler sends `AbortReq` directly:
```text
  scheduler: waiting_queue.pop(i)
    → sends AbortReq back to tokenizer_manager
    → _handle_abort_req()
      → state.finished = True
      → state.event.set()
      → ❌ missing del self.rid_to_state[rid]
```

Because the two abort paths produce different message types (`BatchStrOutput` vs `AbortReq`), they are dispatched to different handlers. `_handle_batch_output` has the cleanup, but `_handle_abort_req` does not. When the same request ID is resubmitted, a `ValueError` raises:
  `raise ValueError(f"Duplicate request ID detected: {rid}")`

This pattern of aborting all requests is especially common in **Reinforcement Learning training workflows**, where weight updates or rollout synchronization frequently trigger global request drains and resubmissions. In such cases, queued rollout requests that haven't started decoding yet are particularly susceptible to this leak, causing the next training step to fail with duplicate RID errors.


<!-- Describe the purpose and goals of this pull request. -->

## Modifications
Add `del self.rid_to_state[recv_obj.rid]` in `_handle_abort_req` before signaling the event, consistent with how
`_handle_batch_output` handles finished requests.
