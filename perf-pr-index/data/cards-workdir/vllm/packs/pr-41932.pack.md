## Purpose

Fixes CPU speculative decoding crashes by adding missing parameters to CPU Triton fallback kernel signatures. 

**Problem**: CPU speculative decoding fails immediately with `TypeError: _rejection_greedy_sample_kernel_impl() got an unexpected keyword argument 'SYNTHETIC_MODE'`

**Root cause**: The rejection sampler (`vllm/v1/sample/rejection_sampler.py`) passes `uniform_probs`, `synthetic_conditional_rates`, and `SYNTHETIC_MODE` parameters to support synthetic mode, but the CPU fallback kernels (`vllm/utils/cpu_triton_utils.py`) did not accept them.

**Solution**: Add these parameters to CPU kernel signatures:
- `_rejection_greedy_sample_kernel_impl`: Added `uniform_probs`, `synthetic_conditional_rates`, `SYNTHETIC_MODE`
- `_rejection_random_sample_kernel_impl`: Added `synthetic_conditional_rates`, `SYNTHETIC_MODE`

The parameters are accepted but not used (C++ kernels don't implement synthetic mode yet), maintaining compatibility with the calling convention.

**Impact**:
- **Enables CPU speculative decoding** in vLLM v1 (previously completely broken)
- **No GPU impact** (GPU kernels already handle these parameters)
- **Backward compatible** (all parameters have default values)
- **Future-proof** for synthetic mode implementation in C++ CPU kernels

**Related**: Builds on CPU spec decode support from #32662

## Test Plan

Tested on **Intel Xeon Platinum 8580** (Emerald Rapids, 120 cores, 240 threads):

```bash
  --model facebook/opt-1.3b \
  --max-model-len 512 \
  --port 8000

# Spec decode  
VLLM_USE_V1=1 VLLM_TARGET_DEVICE=cpu \
python -m vllm.entrypoints.openai.api_server \
  --model facebook/opt-1.3b \
  --speculative_config '{"method":"draft_model","model":"facebook/opt-125m","num_speculative_tokens":5}' \
  --max-model-len 512 \
  --port 8001

# Run 10 inference requests @ 50 tokens each
```
