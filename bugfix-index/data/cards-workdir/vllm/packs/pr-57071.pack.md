## 正文(PR 描述)

## Purpose

`DeepSeek-V4.1-Flash-MXFP4` does not load today. It is a **mixed-precision** AMD-Quark export — MXFP4 experts, but 226 per-layer attention specs in MXFP8:

| | scheme |
|---|---|
| `global_quant_config` | `fp4` / `per_group` / `group_size=32` / `e8m0` |
| `layer_quant_config` (226 entries) | `fp8_e4m3` / `per_block` / `block_size=[32,32]` / `float8_e8m0fnu` |

Four independent bugs block it. Each one assumes DeepSeek **V4**'s `128x128` block geometry, or the DeepSeek-native scale naming.

| # | Symptom | Fix |
|---|---|---|
| 1 | All 226 per-layer specs silently discarded | Decline mixed-precision Quark exports, let `QuarkConfig` take them |
| 2 | `NotImplementedError: No quark compatible scheme was found.` | New `QuarkW8A8Mxfp8` scheme |
| 3 | Attention shards silently fall back to global MXFP4 | Expose the VL wrapper's mappings as class attributes |
| 4 | Engram scale tensor never routed | Add a `weight_scale$` mapper rule |

### 1. The V4.1 config claims the checkpoint, then throws the specs away

`DeepseekV4FP8Config.override_quantization_method` accepts any Quark export whose *global* scheme is MXFP4 — this one qualifies. But `from_config` then rewrites the config into a single global FP8 scheme with `weight_block_size = [128, 128]`, discarding all 226 per-layer specs. `get_quant_method` then gates its MXFP8 path on `weight_block_size == [32, 32]`,
which that rewrite has just made unreachable.

**Fix:** a Quark export carrying `layer_quant_config` is mixed precision by definition, so decline it and let `QuarkConfig` handle it.

### 2. QuarkConfig has no scheme for 32×32 per-block FP8

`_is_fp8_w8a8` only accepts per-block FP8 at `[128, 128]` (V4 geometry), and the OCP-MX matchers only accept 1-D `per_group` weights. A 32×32 per-block e8m0 weight matches neither, so dispatch raises.

**Fix:** extend `QuarkOCP_MX` to handle MXFP8 as a first-class OCP-MX dtype. `mxfp8_e4m3` is added to `_WEIGHT_QUANT_KEY_MAP` / `_ACTIVATION_QUANT_KEY_MAP`, a normalizer (`ocp_mx_weight_dtype_and_rows()`) accepts both config dialects, and `QuarkOCP_MX` gains an unpacked MXFP8 branch with 3-way `packed_factor` (`1` for mxfp8, `2` for mxfp4, `8/6` for mxfp6).

The only difference from canonical 1-D MXFP8 is scale layout. MXFP8 carries one e8m0 value per weight *row* per 32-element group; Quark's `block_size=[R, 32]` carries one per *R* rows. The loader expands each scale row:

```python
loaded_weight.view(torch.uint8).repeat_interleave(rows, dim=0)
```

At `R == 1` the two layouts coincide and expansion is a no-op. The kernel is the shared `init_mxfp8_linear_kernel()` — the same one compressed-tensors and INC MXFP8 schemes use. Existing 128×128 per-block FP8 keeps
`QuarkW8A8Fp8PerBlock`, asserted in the new tests.

This also fixes a latent dispatch inconsistency: `get_quant_method()` and `get_quant_method_target()` now agree on MXFP8 layers, since both walk the same `QuarkOCP_MX` matcher chain.

Both MXFP8 config dialects are accepted:

| | Shape A (canonical MX) | Shape B (DeepSeek-V4.1) |
|---|---|---|
| `dtype` | `fp8_e4m3` | `fp8_e4m3` |
| shape | `qscheme=per_group`, `group_size=32` | `qscheme=per_block`, `block_size=[32,32]` |
| scale | `scale_format="e8m0"` | `scale_type="float8_e8m0fnu"` |
| `scale_block_rows` (R) | 1 | 32 |

### 3. The VL wrapper hides its module mappings from the quant config

`configure_quant_config` reads `hf_to_vllm_mapper` and `packed_modules_mapping` off the **class**, before `__init__` runs.
`DeepseekV41ForCausalLM` (vision variant) defined neither at class level, only as instance attributes. So per-layer keys naming `layers.N.attn.wq_a` never matched the runtime `language_model.model.layers.N.attn.wq_a`, and every
attention shard silently fell back to the global MXFP4 spec.

**Fix:** expose both as class attributes, with the prefix rules shared via one module-level constant so they cannot drift.

### 4. The engram scale name

Quark spells it `engram.embed.weight_scale`. The mapper's rules match `\.scale$` — a literal `.scale` suffix — so the rule never fires.

**Fix:** add an explicit `weight_scale$` rule alongside the existing one.

## Scope

ROCm/AMD path only (`vllm/models/deepseek_v41/amd/`). The `nvidia/` twins have the same shape for items 3 and 4, but this PR deliberately leaves them alone — only the AMD path has been validated on hardware.

## Test Plan

**Quark dispatch tests (`test_quark.py`):**

- `test_quant_method_dispatch_mxfp8_2d_block` — a 32×32 per-block e8m0 linear dispatches to `QuarkOCP_MX` with `scale_block_rows == 32`; experts still fall through to the global MXFP4 spec; 128×128 per-block FP8 still gets
  `QuarkW8A8Fp8PerBlock`.
- `test_quant_method_dispatch_mxfp8_canonical` — canonical 1-D per-group MXFP8 (Shape A) dispatches to `QuarkOCP_MX` with `scale_block_rows == 1`; `get_quant_method` / `get_quant_method_target` agree.
- `test_quant_method_dispatch_mxfp8_moe_raises` — MXFP8 experts raise `NotImplementedError`.
- `test_quark_override_delegates_to_quark_config` — all `quant_method=="quark"` configs (MXFP4, MXFP8, mixed, etc.) return `None` from  `DeepseekV4FP8Config.override_quantization_method`, confirming delegation to `QuarkConfig`. Parametrized over V4 and V4.1 model types (10 cases).

**FP8 / DeepSeek-V4.1 tests (`test_fp8.py`):**

- `test_deepseek_v41_declines_mixed_precision_quark_config`
- `test_deepseek_v41_vl_exposes_quant_mappings_on_class`
- `test_deepseek_v41_engram_scale_accepts_quark_name`

## Test Result

**0 new code failures.** 

### End-to-end

`DeepSeek-V4.1-Flash-MXFP4` (48 shards, 475 GB) on 4x MI355X at TP=4: all shards load in 74.5 s, MXFP8 attention resolves to `QuarkOCP_MX` via the `RocmDotScaledMxfp8LinearKernel`, and the model is coherent.

GSM8K accuracy (1319 problems, greedy, seed=42, 8-shot)
| Config | flexible-extract | strict-match |
| --- | ---: | ---: |
| MXFP4 | 92.34% ± 0.73 | 92.42% ± 0.73 |
| Base FP8 | 92.87% ± 0.71 | 92.95% ± 0.71 |

Hardware: 4x MI355X (gfx950/CDNA4), TP=4.

+def ocp_mx_weight_dtype_and_rows(
+    weight_quant: dict[str, Any] | None,
+) -> tuple[str, int] | None:
+    """Normalize a Quark weight quant config to ``(mx_dtype, scale_block_rows)``.
+
+    Quark spells OCP MX weights two ways. The canonical one is 1-D per-group:
+    ``qscheme="per_group"``, ``group_size=32``, ``scale_format="e8m0"``. MXFP8
+    checkpoints may instead use a 2-D per-block spelling
+    (``qscheme="per_block"``, ``block_size=[R, 32]``,
+    ``scale_type="float8_e8m0fnu"``), which carries one scale per ``R`` weight
+    rows rather than one per row. ``scale_block_rows`` is that ``R``; it is 1
+    for the canonical spelling, where the two layouts coincide.
+
+    Returns ``None`` when the config is not an OCP MX weight quantization.
+    """
+    if not isinstance(weight_quant, dict):
+        return None
+
+    dtype = weight_quant.get("dtype")
+    if not isinstance(dtype, str):
+        return None
+    mx_dtype = dtype.replace("fp", "mxfp")
+    if mx_dtype not in _WEIGHT_QUANT_KEY_MAP:
+        return None
+
+    qscheme = weight_quant.get("qscheme")
+    if qscheme == "per_group":
+        if weight_quant.get("group_size") != OCP_MX_BLOCK_SIZE:
+            return None
+        if weight_quant.get("scale_format") != "e8m0":
+            return None
+        return mx_dtype, 1
+
+    if qscheme == "per_block":
+        # Only the unpacked dtypes are accepted here: expanding a 2-D scale
+        # over a sub-byte packed weight has no checkpoint to validate against.
+        if mx_dtype not in OCP_MX_UNPACKED_DTYPES:
+            return None
+        block_size = list(weight_quant.get("block_size") or [])
+        if len(block_size) != 2 or block_size[1] != OCP_MX_BLOCK_SIZE:
+            return None
+        if weight_quant.get("scale_type") != "float8_e8m0fnu":
+            return None
+        if weight_quant.get("symmetric") is not True or weight_quant.get("is_dynamic"):
+            return None
+        return mx_dtype, block_size[0]
+
+    return None
