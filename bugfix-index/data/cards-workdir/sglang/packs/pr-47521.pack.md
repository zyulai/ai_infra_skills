## 正文(PR 描述)

- **Abort a retracted request when the recompute cannot rebuild its KV.** `release_req` now returns whether the request can be resumed, and is the single decision point for every retract:
  - **PD decode rebootstrap** (`pause_generation(mode="retract")`, and the DeepSeek-V4 retract through `backup_kv_cache`): `Req.build_rebootstrap_payload` carries token ids only, so multimodal, `input_embeds` and `positional_embed_overrides` requests were recomputed with wrong KV and produced wrong output without an error. They are now aborted (`Req.resumable_by_rebootstrap`). `backup_kv_cache` already did this for multimodal requests under DeepSeek-V4; it now uses the same property.
  - **Local re-prefill** (non-disaggregated retract): multimodal inputs and embed overrides are applied again by `prepare_for_extend`, so those requests are fine. `input_embeds` cover only the prompt, so `reset_for_retract` restarts their generation. That restart is invisible until output has been sent downstream; once it has (a streamed token, or a non-stream request past the `SGLANG_FORCE_STREAM_INTERVAL` flush), the restarted tokens were spliced after the stale `send_token_offset`. Such a request is now aborted instead (`Req.resumable_by_reprefill`); one that has sent nothing still restarts.
  - `retract_all` returns the requests that cannot be resumed, and `pause_generation` aborts them with a 503. `retract_decode` already aborts when `release_req` returns False.
  - Every PD rebootstrap now has at least one output id, so the transfer commit's `resumes_output` is `decode_req.is_rebootstrap` with an assert.
- **One PD fill-length formula.** `len(origin_input_ids) + max(len(output_ids) - 1, 0)` was written in `DecodePreallocQueue._pre_alloc_fill_len` and again for the prebuilt `seq_len`; both use `pre_alloc_fill_len` in `disaggregation/utils.py` now. No behavior change.
- **`/detokenize` rejects out-of-vocabulary ids with 400.** A negative id or one above u32 returned 500, and an id at or above the vocab size was silently dropped with a 200. Ids outside `[0, model vocab_size)` now get a 400, as `_validate_token_ids_logprob` reports invalid ids.

Behavior changes: the aborts above replace silently wrong output (PD decode) or a garbled restarted generation (local `input_embeds` retract after output was sent), and `/detokenize` returns 400 where it returned 500 or dropped ids. Priority preemption still re-prefills a preempted `input_embeds` request from the prompt; that path is unchanged here.
