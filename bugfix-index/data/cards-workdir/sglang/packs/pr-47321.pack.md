## 正文(PR 描述)

Based on #46961, now merged: the frontend abort output repeats the request's `cached_tokens_details`, which that change introduced. This branch sits directly on `main`.

## Motivation

Python's `POST /abort_request` does not fail the request it names. `TokenizerManager.abort_request` forwards an `AbortReq` to the scheduler and leaves the request's response state in place, so the scheduler's next step ends the request with its terminal output: the partial generation produced so far, the request's token counts, and `finish_reason` `{"type": "abort", "message": "Aborted"}`. A streaming client sees a final chunk whose `finish_reason` is `abort`, then `[DONE]`; a unary `/generate` gets a 200 with the partial text.

The Rust frontend's `/abort_request` (#45888) reused the gRPC `Abort` path, which cancels the request at once and ends the client's call with a cancelled error. Clients that abort through the HTTP route therefore got an error body and no partial output where Python's server gives them a completed-with-abort response.

## Modifications

- `handlers/generate.rs`: `CoreHandle::abort` takes an `AbortEnding`. `CancelledError` keeps the gRPC `Abort` behaviour. `AbortFinishReason` is what `/abort_request` uses: a request Intake has not claimed yet is cancelled before it starts and its call finishes on a frontend abort output; an accepted request is handed to the scheduler as an `AbortSource::Request` and its call keeps waiting for the scheduler's terminal output. The cancellation a `Generation` observes is now a `Cancellation` (`Error`, `Unstarted`, `Scheduler`) rather than a unit, and is remembered once observed so preparation, submission and the response stream can all read it.
- `handlers/handle.rs`: a `RuntimeCall` records the counts and cache split of the request's latest output. When a scheduler-handed abort gets no answer, because Intake closed the sink or the scheduler stayed silent for 30 s, the call ends on a frontend abort output that repeats those counts, is marked `abort_output`, and (on the deadline) tells the runtime to drop the request as a dropped call would.
- `tokenizer_manager/to_scheduler.rs`, `wiring.rs`: `AbortSource::Request` keeps the detokenizer entry so the scheduler's terminal output still reaches the client, and queues the `AbortReq` behind the request on the request ring, so the reserved control lane cannot overtake a request the scheduler has not yet seen. On a full ring it falls back to the existing abort path. `RequestAdmission` gains `cancel_if_pending` and `is_accepted` for the two endings.
- `http/info.rs`: `/abort_request` aborts with `AbortFinishReason`. `grpc/service.rs`: the `Abort` RPC keeps `CancelledError`.
- `Cargo.toml`: tokio `test-util` as a dev-dependency, for the paused-time deadline test.
- Tests: `abort_request_ends_requests_on_the_schedulers_abort` (native stream, unary `/generate`, and `/v1/completions` stream each end on the scheduler's abort output), `scheduler_abort_without_an_answer_ends_on_a_frontend_abort_output`, `unstarted_abort_request_records_no_finished_request`, `explicit_abort_ends_the_call_before_its_sink_closes`, `request_abort_keeps_the_sink_and_queues_behind_the_request`, and both endings in `explicit_abort_wakes_a_submission_blocked_on_admission`.

+
+In Python mode the tokenizer manager drains on SIGTERM

+still admitted, every admitted request finishes, then a ``ShutdownReq`` stops

+//!
+//! Once a drain begins, every health endpoint answers 503 while requests keep
+//! being admitted, as in Python. The listeners close when no client request
+//! is left in flight — or at once, skipping the wait, when the last health
+//! probe had failed or the drain was forced (Python's `UnHealthy` and
+//! `SGL_FORCE_SHUTDOWN` exits). There is no deadline: like Python, the
+//! orchestrator's kill is the only bound on a drain.
+

+use std::sync::atomic::{AtomicBool, AtomicUsize, Ordering};
+
+use tokio::sync::Notify;

+#[derive(Default)]
+pub(crate) struct DrainState {
+    draining: AtomicBool,
+    /// Skip the wait for in-flight requests (`SGL_FORCE_SHUTDOWN`).
+    forced: AtomicBool,
+    /// The last deep health probe stalled; a later healthy one clears it, as
+    /// Python moves `server_status` between `UnHealthy` and `Up`.
+    unhealthy: AtomicBool,
+    /// Client generation calls alive (see [`InFlight`]).
+    in_flight: AtomicUsize,

+    /// waiter (each listener's shutdown, the close deadline) agrees it ended
+    /// even if a request on a still-open connection is admitted afterwards.
+    drained: AtomicBool,
+    changed: Notify,
+}

+/// How a drain ended.
+#[derive(Clone, Copy, Debug, Eq, PartialEq)]
+pub(crate) enum DrainEnd {
+    /// Every client request finished.
+    Drained,
+    /// The wait was skipped: the drain was forced or the engine unhealthy.
+    Forced,

+impl DrainState {
+    /// Count one client request until the guard drops.
+    pub(crate) fn track(self: &Arc<Self>) -> InFlight {
+        self.in_flight.fetch_add(1, Ordering::SeqCst);
+        InFlight(self.clone())
+    }
+
+    /// Start draining (idempotent); `force` skips the wait for in-flight
+    /// requests.
+    pub(crate) fn begin(&self, force: bool) {
+        if force {
+            self.forced.store(true, Ordering::SeqCst);
+        }
+        if !self.draining.swap(true, Ordering::SeqCst) {
+            tracing::warn!(
+                in_flight = self.in_flight.load(Ordering::SeqCst),
+                "Drain requested: health now answers 503; draining requests and shutting down"
+            );
+        }
+        self.changed.notify_waiters();
+    }
+
+    pub(crate) fn is_draining(&self) -> bool {
+        self.draining.load(Ordering::SeqCst)
+    }
+
+    pub(crate) fn set_unhealthy(&self, unhealthy: bool) {
+        if self.unhealthy.swap(unhealthy, Ordering::SeqCst) != unhealthy {
+            self.changed.notify_waiters();
+        }
+    }
+
+    /// Why a drain skips its wait, in Python's words; `None` if it does not.
+    pub(crate) fn force_reason(&self) -> Option<&'static str> {
+        if !self.is_draining() {
+            None
+        } else if self.forced.load(Ordering::SeqCst) {
+            Some("Signal SIGTERM received while force shutdown flag set. Force exiting.")
+        } else if self.unhealthy.load(Ordering::SeqCst) {
+            Some("Signal SIGTERM received while health check failed. Force exiting.")
+        } else {
+            None
+        }
+    }
+
+    fn end(&self) -> Option<DrainEnd> {
+        if !self.is_draining() {
+            None
+        } else if self.force_reason().is_some() {
+            Some(DrainEnd::Forced)

+            if !self.drained.swap(true, Ordering::SeqCst) {

+            }

+        } else {
+            None
+        }
+    }

+    /// Wait until `check` yields a value, re-checking on every state change.
+    async fn wait_until<T>(&self, check: impl Fn(&Self) -> Option<T>) -> T {

+            // Register before checking, so a change between the check and
+            // the await still wakes this waiter.

+            notified.as_mut().enable();

+                return value;
+            }
+            notified.await;
+        }
+    }

+    pub(crate) async fn ended(&self) -> DrainEnd {
+        self.wait_until(Self::end).await

+    }
