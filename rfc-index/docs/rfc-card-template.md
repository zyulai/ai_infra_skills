# RFC 摘要卡模板(重点档)

每张卡对应一个重点档 RFC issue,输出到 `index/<repo>/rfc-cards/rfc-<N>-<slug>.md`。
文件名以 `rfc-<N>-` 开头,slug 取标题(小写、非字母数字转 `-`、≤40 字符);
**out 路径以 agent 清单为准,不要自行改名**。

## 卡片结构(逐节,标题逐字保留)

```markdown
# RFC #<N>: <真实标题>

| 字段 | 值 |
| --- | --- |
| 仓库 | vllm-project/vllm 或 sgl-project/sglang |
| 编号 | [#<N>](原文链接) |
| 作者 | <author> |
| 创建日期 | YYYY-MM-DD |
| 状态 | 🟢 open / ⚪ closed(关闭于 YYYY-MM-DD) |
| labels | 逗号分隔;无则写 (none) |
| 热度 | 👍 <reactions_total> · 💬 <comments> |
| 分类 | <category> |

## 一句话结论
(≤60 字:这个 RFC 提议什么、核心价值是什么)

## 提案动机
RFC 要解决什么问题(2-4 句,来自正文,不臆测)

## 提出的方案
核心设计/接口/架构,3-6 个要点(短列表或紧凑段落)

## 优化点与收益
性能/效率收益在哪。正文有数字(如 `2.5x`、`30%`)则**照抄**并附测试条件
(模型/硬件/workload);没有就写「正文未给出量化数字」。禁止编造或换算。

## 现状与落地
- state=open:仍在讨论/待实现(按正文语气如实描述:活跃讨论 / 已有原型 / 等待评审)
- state=closed:已关闭 —— 若正文或结尾能看出「已实现 / 被替代 / 搁置」则如实写,
  看不出就写「已关闭,落地情况需查关联 PR」;禁止猜测。

## 关联
正文中提到的 RFC/PR/文档链接(≤5 个,没有就写「正文未列出」)

---
> 摘要由 LLM 基于 RFC 正文生成,未经人工核实;准确信息以原帖为准。
```

## 硬性规则

1. **只写 pack 里有的信息**;pack 没有的细节一律不写。
2. 数字**照抄**原文(含单位与条件),不做换算、不四舍五入。
3. 卡片正文 300-800 字(不含元信息表与尾注)。
4. 引用原文 ≤15 行。
5. 文件名 `rfc-<N>-<slug>.md`;已存在则跳过(幂等)。
6. 不要修改脚本、数据文件或其他卡片。
