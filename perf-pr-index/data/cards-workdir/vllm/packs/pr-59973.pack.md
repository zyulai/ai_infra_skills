## Overview

**Decode at c=1 on SPEED-Bench goes from 39.4 to 46.5 tok/s (+18%) with average AL unchanged (-0.4%)** with an NVFP4 draft head, Qwen3.8-Flash-Next-NVFP4 + MTP (k=3), one DGX Spark, measured on three nodes with the SM121 skinny-GEMM plans from #59753. An MTP or EAGLE drafter that shares the target's lm_head reads the whole head once per draft token; on a 248k x 2560 BF16 head that is the largest kernel in a draft step. A new opt-in key gives the drafter a private quantized copy of the head. The target still verifies with its own BF16 head, so outputs are unchanged; only the acceptance length can move.

```bash
vllm serve <model> --speculative-config \
  '{"method": "mtp", "num_speculative_tokens": 3, "draft_lm_head_quantization": "nvfp4"}'
```

## Claims

- `"nvfp4"`: E2M1 weights with an E4M3 scale per 16 values, weight-only on the platform's W4A16 kernel, chosen by `init_nvfp4_linear_kernel` (Marlin on SM12x; activations stay BF16/FP16). `"fp8"`: per-row FP8 weights and per-token FP8 activations, reusing the existing online `Fp8PtpcOnlineLinearMethod` on the platform FP8 kernel (`CutlassFP8ScaledMMLinearKernel` on GB10). CUDA graphs and TP work (each rank quantizes its own shard).
- Decode on GB10: +17.5% to +18.4% at c=1 and +9% to +11% at c=4 (NVFP4, three nodes), +10.8% / +6.5% (FP8, one node). AL within run-to-run noise, including multilingual (every row of the head stays available). GSM8K unchanged (earlier run, below).
- Probabilistic drafting stays exact: the quantized logits are both sampled and used as q.
- Extra memory: about 0.35 GiB (NVFP4) or 0.6 GiB (FP8) for a 248k x 2560 head, created inside model loading, so profiled KV sizing accounts for it. With `--kv-cache-memory-bytes`, leave room for it.

## Details

- Design: the quantization lives with the other online quantization methods, in `vllm/model_executor/layers/quantization/online/lm_head.py`. `quantized_lm_head_copy()` builds a plain `ParallelLMHead` with that quant method and quantizes it straight from this rank's shard of the target head, so no bf16 copy is made and the target head is unchanged. FP8 reuses the existing `Fp8PtpcOnlineLinearMethod`; NVFP4 adds a small weight-only method (`_LMHeadNvfp4Method`) that quantizes the head and hands it to the selected W4A16 kernel. `ParallelLMHead` gains an optional `quant_method` argument, which `VocabParallelEmbedding` already has. vllm-ascend overrides `ParallelLMHead.__init__` without this argument, so the soft-fail Ascend NPU interface check flags it; on Ascend, `draft_lm_head_quantization` needs the override updated. `"nvfp4"` needs a CUDA W4A16 kernel, so on ROCm only `"fp8"` is available and the tests skip the nvfp4 cases there.
- Hook: `load_eagle_model` gives the drafter that head instead of the shared target head, including the MTP per-layer `shared_head.head`.
- Derived state: the copy is kept out of layerwise reload and re-derived in place from the target head whenever the target's weights are replaced (`reload_weights`, weight transfer), so sleep mode, weight reload and weight transfer keep working. During a draft-only weight update the drafter shares the target head again, as on main, and the copy is re-derived when the update finishes.
- Scope: MRV2 drafters loaded through `load_eagle_model` (EAGLE, EAGLE3, MTP) that share an unquantized fp16/bf16 lm_head running in the model dtype; other cases are rejected at config validation or load. Gemma-4 MTP is excluded because it scores a subset of its tied embedding rows directly and has no shared lm_head. DFlash and DSpark can call the same helper in a follow-up.
- Not a duplicate: #56577 (Qwen4Exp only, env var, eager only) and #47584 (DSpark only, env var) add an FP8 draft head for one model or method; this is the generic version behind one config key, with CUDA graphs and NVFP4. #59740 (reduced draft vocabulary) composes with it; both add a draft-head key to `speculative_config` and hook the same place in `load_eagle_model`, so whichever lands second will reuse this quantizer for the list rows (as `draft_token_map_quantization` there) rather than add a second one. #41000, #42124 and #58343 concern heads quantized in the checkpoint, and the online quantization framework (#51285) covers linear and MoE layers but not `ParallelLMHead`.

+def _quantize_nvfp4(
+    weight: torch.Tensor, chunk_rows: int = 8192
+) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor]:
+    """NVFP4-quantize the rows of `weight` without the SM100+ quant kernel.
+
+    Returns packed E2M1 codes (low nibble first), E4M3 scales per 16 values and
+    the fp32 dequantization global scale, in the checkpoint layout.
+    """
+    fp8_max = torch.finfo(torch.float8_e4m3fn).max
+    global_scale = (weight_amax(weight).float() / (FLOAT4_E2M1_MAX * fp8_max)).clamp(
+        min=1e-12
+    )
+    inv_global_scale = (1.0 / global_scale).reshape(())
+    # E2M1 magnitudes 0, 0.5, ..., 6 doubled to integers, mapped to their codes.
+    code_of = torch.zeros(13, dtype=torch.uint8, device=weight.device)
+    code_of[torch.tensor([0, 1, 2, 3, 4, 6, 8, 12])] = torch.arange(
+        8, dtype=torch.uint8
+    ).to(weight.device)
+    n, k = weight.shape
+    packed = torch.empty(n, k // 2, dtype=torch.uint8, device=weight.device)
+    scales = torch.empty(n, k // 16, dtype=torch.float8_e4m3fn, device=weight.device)
+    for start in range(0, n, chunk_rows):
+        rows = slice(start, start + chunk_rows)
+        values, block_scales = ref_nvfp4_quant(weight[rows], inv_global_scale, 16)
+        codes = code_of[(values.abs() * 2).long()] | ((values < 0).to(torch.uint8) << 3)
+        packed[rows] = codes[:, 0::2] | (codes[:, 1::2] << 4)
+        scales[rows] = block_scales.to(torch.float8_e4m3fn)
+    return packed, scales, global_scale
