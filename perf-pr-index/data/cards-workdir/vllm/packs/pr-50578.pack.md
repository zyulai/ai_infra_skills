## PR body
```markdown
## Purpose

On `ROCM_AITER_MLA`, MLA decode with fewer than 16 query heads per rank runs the Gluon
decode kernel (`AiterMLAHelper.use_gluon_decode`). Gluon parallelizes only over heads, so a
single workgroup marches through the whole KV cache and per-token latency scales linearly
with context length. The faster asm *persistent* decode requires `num_heads >= 16`; smaller
head counts are padded up to 16, but `get_mla_padded_q` / `get_mla_unpadded_o` only handle
**divisors** of 16 (`repeat_interleave`), so **non-divisor** counts fall back to Gluon.

Kimi-K3 has 96 attention heads over `kv_lora_rank=512`, i.e. **12 heads/rank at TP8** — a
non-divisor of 16 — so its long-context decode is stuck on Gluon and degrades badly with KV
length.

This PR pads non-divisor head counts to 16 by appending the leading query heads and routes
those decodes through the asm persistent kernel. The padding is **exact**: MLA attention is
independent per query head over the shared KV, so the appended heads `[num_heads:16]` cannot
change heads `[0:num_heads]`, and they are sliced back off in `get_mla_unpadded_o`. Divisor
counts and the `max_qo_len > 1` small-head verify path are unchanged (still Gluon).

## Test Plan

Kimi-K3 (mxfp4), 8×MI355X (gfx950), TP8. `AiterMLAHelper` on the PR base is byte-identical to
the build used for validation (`5f76ae224`).

```bash
VLLM_ROCM_USE_AITER=1 VLLM_ROCM_USE_AITER_MLA=1 \
vllm serve <kimi-k3> --served-model-name kimi-k3 --trust-remote-code \
  --tensor-parallel-size 8 --gpu-memory-utilization 0.96 --moe-backend aiter

# decode latency vs context length (greedy, single stream)
vllm bench serve --model <kimi-k3> --served-model-name kimi-k3 --dataset-name random \
  --ignore-eos --temperature 0 --max-concurrency 1 \
  --random-input-len 32768 --random-output-len 1024 --num-prompts 2
```

## Test Result

Mean TPOT (ms/token), concurrency 1:

| prefill / output | before (Gluon) | after (asm pad) | speedup |
|---|---:|---:|---:|
| 1K / 1K   | 22.9 | 22.8 | 1.00× |
| 1K / 32K  | 33.4 | 23.3 | 1.43× |
| 32K / 1K  | 43.8 | 23.6 | 1.86× |
| 32K / 32K | 54.1 | 23.6 | 2.29× |

Decode is flattened to ~23.5 ms at every context length (no short-context regression, up to
2.3× faster at long context); output is unchanged (greedy). A rank-0 trace confirms the asm
path is active — the decode reduce kernel is `kn_mla_reduce_v1_...Li512ELi16E...` (16 padded
heads) and `_mla_gluon` no longer appears.
