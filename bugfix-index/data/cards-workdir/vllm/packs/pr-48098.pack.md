## 正文(PR 描述)

## Purpose
Fixes #48097.

Sending `"parallel_tool_calls": null` to the Responses API (`/v1/responses`) caused `from_request()` to pass `None` to `ResponsesResponse.parallel_tool_calls` (typed as `bool`, non-optional), raising a Pydantic `ValidationError` during response construction. vLLM's error handling catches this and returns a **400** with a raw Pydantic error message, instead of resolving to the documented default like the request-side field does.

Fix: resolve `None` to the documented default (`True`) in `from_request()`, mirroring the fix applied to the ChatCompletion path in PR #44955.

> **Note:** this is distinct from #44955 — the Responses API never calls `maybe_filter_parallel_tool_calls` from `tool_calls_utils.py` (zero hits across `vllm/entrypoints/openai/responses/`). The crash is in `from_request()` in `responses/protocol.py`, a separate code path.

## Test Plan
```bash
python3 -m pytest tests/tool_use/test_responses_request_validations.py -v
```

Also verified end-to-end against a live server (`vllm serve Qwen/Qwen2.5-0.5B-Instruct --dtype=half`, T4 GPU via Colab), both before and after the fix, since a reviewer initially couldn't reproduce this via the OpenAI Python SDK (which excludes `None`-valued fields during serialization by default, so the bug only surfaces when `"parallel_tool_calls": null` is explicitly present in the raw request body — e.g. via curl or a client that doesn't drop nulls).

## Test Result
```
21 passed, 21 errors in 4.99s
```
The 21 errors are pre-existing teardown failures from the `cleanup_dist_env_and_memory` fixture trying to clear GPU memory on a CPU-only environment. They are present in all tests in this file before our changes and are unrelated to this PR.

**Before fix (live server, `main`):**
```bash
curl -X POST http://localhost:8000/v1/responses \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen/Qwen2.5-0.5B-Instruct", "input": "test", "parallel_tool_calls": null}'
```
```
HTTP_STATUS:400
{"error":{"message":"1 validation error for ResponsesResponse\nparallel_tool_calls\n  Input should be a valid boolean [type=bool_type, input_value=None, input_type=NoneType]","type":"BadRequestError","param":null,"code":400}}
```

**After fix (same server, same request):**
```
HTTP_STATUS:200
```
`"parallel_tool_calls":true` present in the response body, request completes normally.
