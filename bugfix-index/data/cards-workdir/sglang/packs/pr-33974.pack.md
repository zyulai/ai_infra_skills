## 正文(PR 描述)

## Motivation

`--enable-unified-memory` currently hard-blocks speculative decoding (`server_args.py`: `assert self.speculative_algorithm is None`). This PR wires chain DSPARK through the unified pool and fixes the two real NaN/corruption root causes found while validating it end to end on Kimi-K3 (TP8, 2x4 GB300) and Kimi-Linear-48B (TP1 x8 B300-class). Other speculative algorithms (EAGLE / tree / DFLASH / NGRAM) remain blocked pending their own virtual-vs-dense loc audits.

## Modifications

Five commits, reviewable independently:

1. **`unified-memory: wire DSPARK chain speculative decoding`**
   - `server_args.py`: relax the unified gate to `speculative_algorithm in (None, "DSPARK")`, chain only (`speculative_eagle_topk in (None, 1)`).
   - `trtllm_mla_backend.py`: extend the capture-stable DENSE write-loc fill from `is_decode_or_idle()` to `is_target_verify()`, and route the `forward_extend` KV write through it (`loc_is_dense=True`) when set — the verify graph must not capture a translate allocation (same class as the decode path that already exists).
   - `mamba_state_scatter_triton.py`: replace the blanket `dst.is_contiguous()` asserts with the kernels' true contract (arbitrary layer/slot strides — already consumed via real int64-promoted strides — with contiguous trailing entry dims), so the unified pool's envelope-strided conv/temporal views pass. CPU layout-contract tests + a CUDA envelope-dst end-to-end test added.
   - `hybrid_linear_attn_backend.py`: `update_mamba_state_after_mtp_verify` translates the ScheduleBatch-side (VIRTUAL) `mamba_track_indices` to physical at a single point (identity on static pools) — using them raw silently mis-addresses within bounds on the unified pool.
   - `kv_cache_configurator.py`: size the DSPARK draft pool by the shared unified allocator's virtual-id space (`size_full`, page-aligned up) instead of `max_total_num_tokens` — the draft pool is direct-indexed by virtual ids which range over the whole virtual space; keep the draft pool on the plain contiguous layout (page-major is a target-pool layout choice).

2. **`debug(unified): SGLANG_DEBUG_POISON_POOL`** — env-gated: fill the pool with bf16-NaN bit patterns at boot instead of zeros. Turns the "does freed GPU heap happen to contain NaN patterns" boot lottery into a deterministic switch; kept as the permanent regression harness for the class of bug below (zero default overhead).

3. **`fix(unified): zero page envelopes on allocator hand-out`** — root cause 1. The trtllm-gen MLA kernel reads whole pages and masks rows beyond `seq_len` arithmetically (NaN-unsafe); the unified pool zeroes its raw buffer only at boot, so page recycling re-exposes historical bytes and NaN in a request's last partial page tail leaks into the attention output. Speculative decoding amplifies exposure (every verify window lands on a fresh page at the sequence tail). Static pools are safe by construction (`torch.zeros` + only finite KV ever written); this gives the shared pool the same guarantee at the alloc boundary. Cost: one contiguous page-envelope memset per handed-out page on the schedule stream — benched at zero (below).

4. **`fix(kda_decode_mtp): promote slot ids to int64 before state-stride multiplies`** — root cause 2, and the reason this presented as a "weird" load-dependent heisenbug. The DSPARK KDA verify kernel (`nv_cutedsl` fast path) compiles with STATIC CuTe layouts: state-pool strides are compile-time constants. On the unified pool the envelope-strided KDA state views carry slot strides of ~14M (fp32 ssm) / ~28M (bf16 conv) elements; each constant individually fits int32, so it folds into 32-bit arithmetic and `slot * stride` silently wraps mod 2^32 once slot ids exceed ~153 (conv) / ~306 (ssm) — reads land inside other slots' bytes (silent state corruption on a CLEAN boot: GSM8K 0.120, fake accept-rate bursts) or fly off the allocation (illegal access). Static contiguous pools never reach the wrap point (slot stride ~197K elements); Kimi-Linear never engages this kernel (head dims fail the 128 contract → triton fallback); cold boots hand out low slot ids — which is exactly why it was unified-only, K3-only, and load-only. Proven with an offline replay sentinel (dump one real in-system call; rebuild states contiguous vs faithful strided replicas with zero/NaN gap fill; sweep slot magnitudes): before — slots ≤75 bit-exact, 100–150 illegal access, ≥155 silent divergence; after — bit-exact everywhere.

5. **`unified+spec: keep lazy compaction ON`** — reverts an over-conservative eager forcing from an earlier draft of commit 1 after verifying the actual ordering: the scheduler registers the in-flight write-set (`set_inflight_forward(forward_done, batch.out_cache_loc)`) AFTER `forward_batch_generation()` returns, and the DSPARK verify executor has by then rebound `ScheduleBatch.out_cache_loc` to the verify-window locs (never restored) — so lazy compaction's write-race classification covers verify writes exactly like decode writes, and the event-gated freed-page reuse orders the hand-out zeroing (commit 3) after the in-flight forward.

## Limitations / follow-ups

- The branch base is an ancestor of current main (no divergence; merge-tree is conflict-free). Happy to rebase before merge — flagging that the accuracy/perf numbers above are bound to the base as validated.
- Compaction MOVE racing an in-flight verify write was not dynamically exercised (short GSM8K sequences free at the watermark frontier → `moves=0` in the stats run); its correctness rests on the verified write-set ordering (commit 5) plus poison acceptance. A fragmenting long-generation stress is a good follow-up before enabling this in latency-critical production lanes.
- fa3 / flashinfer as the target-verify backend under unified+spec are not exercised (K3 lane = trtllm_mla; flashinfer decode is already role-scope-blocked by the allowlist).
- The kernel-owner-side fix for the arithmetic (NaN-unsafe) masked-tail reads remains an upstream flashinfer/trtllm-gen item; commit 3 makes the pool safe regardless.

+    buf_ptr,  # int64 view of the raw pool buffer
+    pages_ptr,  # int64 [M] physical page ids to zero
+    page_words,  # int64 words per page envelope
+    BLOCK: tl.constexpr,

+    pg = tl.load(pages_ptr + m).to(tl.int64)

+    zeroed gap bytes — the unified pool's envelope-strided state layout, scaled

+        return buf._raw[: kvcache._num_pages * kvcache._page_bytes].view(
+            kvcache._num_pages, kvcache._page_bytes
+        )
+
+    def _phys_pages(self, allocator, virt_tokens):
+        return (allocator.translate_kv_loc(virt_tokens) // allocator.page_size).unique()
+
+    def test_fresh_and_recycled_pages_zeroed(self):
+        buf, kvcache, allocator = _build("cuda")
+        env = self._env(buf, kvcache)
+
+        # Fresh hand-out over a poisoned pool (the deterministic form of
+        # "freed GPU heap happened to contain NaN patterns").
+        self._poison(buf)
+        out = allocator.alloc(16)
+        self.assertIsNotNone(out)
+        pages = self._phys_pages(allocator, out)
+        self.assertTrue((env[pages] == 0).all().item())
+        # Untouched pages must still be poisoned, else the assert above is
+        # vacuous (a whole-pool memset would also pass it).
+        wm_page = int(pages.max().item()) + 2
+        self.assertFalse((env[wm_page] == 0).all().item())
+
+        # Recycle: free, re-poison the raw bytes (data only; v2p bookkeeping
+        # is separate storage), re-alloc — recycled pages must be zeroed too.
+        allocator.free(out)
+        self._poison(buf)
+        out2 = allocator.alloc(16)
+        self.assertIsNotNone(out2)
+        pages2 = self._phys_pages(allocator, out2)
+        self.assertTrue((env[pages2] == 0).all().item())
+
+    def test_zeroing_enabled_for_single_layer_multiplier(self):
+        # A shard owning exactly ONE full-attention MLA layer has
+        # kernel_page_multiplier == 1 but its pool is still
+        # UnifiedMLATokenToKVPool with the same NaN-unsafe partial-page
+        # reads — zeroing must key on the pool type, not on multiplier > 1.
+        buf, kvcache, allocator = _build("cuda", kernel_page_multiplier=1)
+        self.assertTrue(allocator._zero_pages_on_alloc)
+        self._poison(buf)
+        out = allocator.alloc(8)
+        self.assertIsNotNone(out)
+        env = self._env(buf, kvcache)
+        pages = self._phys_pages(allocator, out)
+        self.assertTrue((env[pages] == 0).all().item())

+    unittest.main()
