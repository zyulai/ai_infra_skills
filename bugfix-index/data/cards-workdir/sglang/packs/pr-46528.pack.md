## 正文(PR 描述)

## Motivation

With `--attention-backend aiter` (the default for MHA models on ROCm) and an fp8 KV cache, a checkpoint that ships calibrated KV scales produces garbage output: GSM8K drops to 0.

No flag is needed to hit it. With the default `--kv-cache-dtype auto`, `configure_kv_cache_dtype` turns on the fp8 KV cache whenever the checkpoint's quant config declares one (compressed-tensors `kv_cache_scheme`, ModelOpt `kv_cache_quant_algo: FP8`) and loads its scales, e.g. `nm-testing/Llama-3.2-1B-Instruct-FP8-KV`. Checkpoints that do not declare it, such as `amd/Llama-3.1-8B-Instruct-FP8-KV` (per-layer `kv_scale` ≈ 0.025) or the Quark `amd/gpt-oss-20b-MoE-Quant-W-MXFP4-A-FP8-KV-FP8`, hit it with `--kv-cache-dtype fp8_e4m3`, which is how they are meant to be served.

The KV cache itself is written correctly (`K / k_scale`); three attention call sites misuse the scales:

- **default decode (`paged_attention_ragged`)**, the decode kernel for MHA models without a sliding window: the backend-wide unit scales are passed instead of the layer's k/v scales, so the cache is never dequantized.
- **unified-attention decode (`unified_attention`)**, used for sliding-window models such as gpt-oss and with `SGLANG_USE_AITER_UNIFIED_ATTN=1`: q is quantized with `k_scale`, a scale calibrated for K, not q.
- **NHD prefill (`mha_batch_prefill_func`)**, used on gfx942, and on gfx950 where the HD128 ASM prefill does not apply (e.g. head_dim 64): q is cast to fp8 unscaled, but the KV cache `k_scale` is passed as q's descale, so every logit is multiplied by `k_scale` a second time.

Models without KV scales run with `k_scale == 1`, where all three mistakes are invisible.

## Modifications

- `AiterAttnBackend._quantize_q_fp8`: quantizes q with a static unit scale (sglang does not load checkpoint q scales) and returns that scale as `q_descale`. Used by the NHD prefill and the unified-attention decode. This is the convention the gfx950 HD128 ASM prefill already follows ("Q is cast at unit scale"). For checkpoints without KV scales (`k_scale == 1`) the numerics are unchanged, except that the quant kernel saturates where the previous `.to(fp8)` cast produced NaN for |q| > 240 on e4m3fnuz; the FP8-Q unified-attention decode from sgl-project/sglang#31856 keeps the same kernel and cost.
  - The input is made contiguous because q is a strided view into the fused qkv output and aiter's per-tensor quant kernels read their input as contiguous rows (with a strided q they silently read the wrong elements).
- `paged_attention_ragged` decode receives the layer's `k_descale` / `v_descale`, falling back to the unit scales.
- New AMD unit test `test/registered/attention/test_aiter_fp8_kv_scales_paths.py`: runs the default paged decode and the NHD prefill with the real aiter kernels on an fp8 cache whose k/v scales are far from 1, and compares with fp32 attention over the dequantized cache. No model download, about 10 s.
- `test/registered/attention/test_aiter_fp8_q_unified_attention.py`: the unified branch now expects the unit q scale instead of `layer.k_scale`.

Not changed: the gfx950 head_dim-256 fp8 prefill paths (`flash_attn_varlen_fp8_pertensor_func`) pass `k_scale` as q's descale in the same way and are left to a follow-up.

## Reproduce

```bash
# Explicit fp8 KV cache. Use --kv-cache-dtype bf16 for the reference.
SGLANG_USE_AITER=1 python -m sglang.launch_server --model-path amd/Llama-3.1-8B-Instruct-FP8-KV \
  --attention-backend aiter --kv-cache-dtype fp8_e4m3 --port 30000
# Unified-attention decode: add SGLANG_USE_AITER_UNIFIED_ATTN=1 and --page-size 16.
# fp8 KV cache enabled by the checkpoint itself (no --kv-cache-dtype):
SGLANG_USE_AITER=1 python -m sglang.launch_server --model-path nm-testing/Llama-3.2-1B-Instruct-FP8-KV \
  --attention-backend aiter --port 30000

python -m sglang.test.run_eval --port 30000 --eval-name gsm8k --api completion \
  --num-examples 200 --num-threads 128 --max-tokens 512 --num-shots 5 --repeat 3

python -m sglang.bench_serving --backend sglang --port 30000 --dataset-name random \
  --random-input-len 2048 --random-output-len 256 --random-range-ratio 1.0 \
  --num-prompts 256 --max-concurrency 32 --warmup-requests 4 --seed 1
```
