## PR body
```markdown
DCP support for the `FLASHMLA_SPARSE` backend on the `fp8_ds_mla` KV path, including MTP spec decode under full cudagraphs. `fp8_ds_mla` is what the backend selector picks on Hopper for DSA models with small per-rank head counts (GLM-5.2 / DeepSeek-V3.2 at TP4/DCP4), and this path previously refused DCP outright.

Earlier revisions stacked on #46076 and carried the sparse-indexer DCP machinery (global top-k merge, `--dcp-sparse-indexer-mode`); all of that has since landed in main via #46076 and its follow-ups, so the PR is now backend-side only: +234/−34 across `flashmla_sparse.py`, `flashmla.py` and one test file. (#45426 was our earlier standalone version with its own indexer; this supersedes it and reuses the upstream merge machinery instead.)

## Changes

`flashmla_sparse.py`:
- Opt the backend into the shared DCP decode merge (`can_return_lse_for_decode`): the fp8 mixed-batch kernel now returns decode LSE, sliced together with the head padding and reshaped to the `(tokens, heads)` layout the reducer consumes.
- Under DCP the indexer emits global token ids: keep this rank's shard and convert to local `fp8_ds_mla` slots via `triton_filter_and_convert_dcp_index` with `compact_valid_to_front=False` — the scattered `-1`s stay in place and the fp8 kernel masks them natively, skipping the per-call front-pack. Rows where this rank owns none of the selected tokens get `(0, -inf)`, the identity of the cross-rank LSE merge, so they drop out of the reduce.
- Allow varlen decode under DCP (`supports_dcp_with_varlen` when `cp_kv_cache_interleave_size == 1`): causality comes from the indexer's top-k indices, not kernel metadata. This is what makes MTP + DCP work under full cudagraphs.
- Fail-closed guards instead of silent corruption: `ag_rs` comm backend only; fp8 mixed-batch path only (the split prefill/decode path returns LSE for decode tokens only, and the bf16 sparse path is rejected under DCP); a head-envelope guard rejecting configs where local and DCP-gathered head counts pad to different fp8 decode kernel envelopes (e.g. 128 q-heads at TP8/DCP8).

`flashmla.py` (dense FlashMLA decode): flatten the kernel's `[batch, heads, seq_len]` LSE to `[tokens, heads]` for the DCP reducer — matters under spec decode, where `seq_len > 1`.

Tests: `test_fp8_dcp_head_envelope_guard` in `test_sparse_mla_backends.py`, parametrized over local head counts × DCP world sizes, both accepting and rejecting cases.

## Testing

- `test_sparse_mla_backends.py` + `test_indexer_dcp_localize.py`: 140 passed / 0 failed (SM90).
```
