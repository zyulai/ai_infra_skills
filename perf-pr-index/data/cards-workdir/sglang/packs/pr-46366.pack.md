## Motivation

**What**
On gfx1250 (MI450), FLUX.2-dev 720p image generation takes 38.96 s end to end, and this PR brings it to 30.55 s by running the large BF16 diffusion linears on aiter's FlyDSL `gemm_a16w16_gfx1250` kernel instead of the GEMMs torch.compile generates.

**Why**
gfx1250 has no tuned hipBLASLt BF16 kernels, so under torch.compile the DiT linears fall to Inductor's `max-autotune` Triton templates, which reach 610-700 TFLOPS on the large FLUX.2 shapes. GEMMs are 84% of the transformer's kernel time on this model (327 of 388 ms per forward), so the GEMM rate sets the end-to-end time. The FlyDSL a16w16 kernel runs those shapes at 890-960 TFLOPS (1.3-1.5x on every FLUX.2 GEMM, including the small text-stream ones) with one fixed config (`256x256x64` tile, 2x4 warps, 4 LDS buffers, `compute_bound`), and a 128-row tile when 256x256 tiles would not fill the CUs. It is wrapped in a non-mutating custom op so torch.compile treats it as an opaque, side-effect-free call.

## Modifications

- `python/sglang/multimodal_gen/runtime/layers/linear.py`: under `USE_AITER_GFX1250` (gfx1250 with `SGLANG_USE_AITER=1`), register `sglang::flydsl_gfx1250_linear`, a custom op with `mutates_args=()` and a shape-only fake impl that calls `aiter.ops.flydsl.gemm_a16w16_gfx1250.gemm_a16w16`.
- `apply_unquantized_linear` routes to it when `_use_flydsl_linear` holds: bf16/fp16 input and weight with matching dtypes, M >= 256, K >= 256 (the 4-stage pipeline needs at least 3 K tiles), and a unit stride on the last dim of both input and weight. Everything else keeps the existing path. The M >= 256 bound is where this was measured; below it torch.compile fuses the small GEMMs into neighbouring ops (for example the modulation mm with its SiLU), and routing them through an opaque custom op would break that fusion. FlyDSL is also faster than eager hipBLASLt at small M (100 vs 145 us at 1 x 36864 x 6144), so extending the route to small M is a follow-up that needs its own measurement under compile.
- Other platforms: `_use_flydsl_linear` short-circuits on `USE_AITER_GFX1250 = False`, so NVIDIA and non-gfx1250 AMD keep their original kernels and results; the only new work is that one boolean check.
- `python/sglang/multimodal_gen/test/unit/test_gfx1250_flydsl_linear.py`: a large-M linear goes through the FlyDSL kernel and matches an fp32 reference; a small-M linear does not call it. Skipped unless running on gfx1250 with AITER.

## Accuracy Tests

FLUX.2-dev is an image model, so accuracy is image PSNR against an eager reference (eager mode, `F.linear` on hipBLASLt, same prompt and seed). Same command as the benchmark below.

| Run | PSNR vs eager reference |
|---|---|
| baseline, default flags | 25.2 dB |
| baseline, `--offload-during-compile false` | 29.2 dB |
| this PR, default flags | 23.7 dB |
| this PR, `--offload-during-compile false` (run 1 / run 2) | 22.3 / 23.5 dB |
| noise floor: this PR, same config run twice | 28.0 dB |
| noise floor: baseline, the two flag settings against each other | 26.3 dB |

The compiled pipeline is not bitwise reproducible run to run, and 50 denoising steps amplify last-bit GEMM differences, so two identical runs already differ by 28 dB. This PR lands 2-6 dB lower than the baseline against the eager reference; the composition and subjects are identical and only small background details move. At the kernel level, the max abs error against an fp32 reference is 0.016 for both Inductor and FlyDSL on every FLUX.2 shape, checked on rows at both ends of M.

**End to end**

|---|---|---|---|
