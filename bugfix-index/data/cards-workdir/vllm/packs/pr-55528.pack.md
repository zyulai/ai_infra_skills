## 正文(PR 描述)

## Purpose

V3.2 sparse MLA did not publish the physical block-stride alignment its selected kernel requires. This PR sets the existing `block_stride_alignment` contract at the producer, lifts the field to `KVCacheSpec`, and lets the allocator consume it without an MLA type check. HiSparse hot-page and stride constraints are combined in one LCM so sequential rounding cannot invalidate the first constraint.

The requirement is selected by backend and cache format. Flattened-row paths, including FlashInfer sparse, share their predicate with warmup. SM100 FlashMLA paged FP8/NVFP4 additionally require independent native TMA alignment (`fp8_ds_mla`: 656 bytes; `nvfp4_ds_mla`: 352 bytes), without flattened-row warmup. Existing BLHNC/BLNHC support is retained.

This adopts LucasWilkinson’s minimized suggestion in 200lz/vllm#1: six files, +187/-27, including compact alignment/merge tests and the existing producer/allocator/binder contract test. Layout gating/threading, admission/auto-fit rewrites, and HiSparse PP capacity work are outside this PR.

## Scope and validation

This complements #56254’s existing alignment propagation and pool rounding by supplying the missing V3.2 producer requirement; upstream #53781 already fixed the fused-writer issue. Those changes are not duplicated here.
