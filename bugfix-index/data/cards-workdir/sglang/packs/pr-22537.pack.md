## Motivation

Currently, when using `--load-format=runai_streamer` to load a model from Google Cloud Storage (`gs://...`) using the official SGLang Docker image, the server crashes with the following error:

```bash
  File "/usr/local/lib/python3.12/dist-packages/runai_model_streamer/s3_utils/s3_utils.py", line 137, in gcs_pull_files
    raise ImportError("GCS files module not found. Please install the required package.")
ImportError: GCS files module not found. Please install the required package.
```

This happens because the runai-model-streamer package recently separated its cloud provider dependencies into extras. To natively support GCS (and Azure) out of the box, these dependencies need to be explicitly requested during the image build process. 



## Modifications

Updated docker/Dockerfile to install `"runai-model-streamer[s3,gcs,azure]>=0.15.7"`, ensuring all necessary cloud provider dependencies are baked into the image. This PR also fixes a regression that was introduced in PR https://github.com/sgl-project/sglang/pull/22160.

### Regression

I am struggling to build image before or after this PR because I believe PR https://github.com/sgl-project/sglang/pull/22160 caused a regression. I can successfully start up inference server with the inference-server yaml below with image` lmsysorg/sglang:v0.5.10` and image `lmsysorg/sglang:latest`, but when I try with the nightly image `lmsysorg/sglang:nightly-dev-20260410-3aaaf53f` that contains PR 22160, it fails with the error below. PR #22160 restructured the Dockerfile and added the command `&& mv python/kernels.lock /root/.cache/sglang \.` Because the `/root/.cache/sglang` directory does not exist at that stage of the build, the mv command accidentally renames the kernels.lock file to a file named sglang instead of placing it inside a directory. 

Later, when the Run:AI model streamer initializes, it attempts to create its cache folder inside that path `(os.makedirs(os.path.join(base_dir, "model_streamer"), exist_ok=True))`. Because `/root/.cache/sglang` is now a regular file instead of a directory, the OS throws the `NotADirectoryError: [Errno 20].`
