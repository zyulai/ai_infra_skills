This PR is a follow-up to #34148, which introduced SubBlock sparse attention for MiniMax-H3 on SM100. It extends the backend to SM90 GPUs using SGLang's CuTe-DSL block-sparse FlashAttention kernel without changing the existing SM100 path.

## Modifications

This PR extends the existing SubBlock backend to SM90 while preserving the existing SM100 behavior.

- On SM90, the same 64×64 SubBlock routing plan is passed to SGLang's CuTe-DSL block-sparse FlashAttention kernel. The 64×64 compute tile is only selected for `head_dim=128`; other head dimensions keep the existing SM90 tile selection.
- The backend chooses the SM90 CuTe kernel or the existing SM100 FlashInfer kernel once per device. Routed block IDs are sorted explicitly because the SM90 consumer walks each list from the highest slot down.
- SubBlock has no always-dense blocks, so the SM90 path passes `None` for the full-block list. The CuTe producer and consumer handle this mask-only form without compiling the unused full-block branches.
- The CUDA resolver now accepts compute capability 9.0 or 10.0 and checks the corresponding kernel dependency at startup. The backend README and docstrings have been updated for both paths.
- New tests cover device dispatch and caching, unsupported architectures, the SM90 adapter, 64×64 tile selection, and the `head_dim=96` fallback. The existing ragged-tail, varlen-routing, and dense-reproduction tests now run with either the SM90 or SM100 SubBlock kernel.

## Accuracy Tests

All SubBlock runs use `sparsity=0.75`, `n_k=4`, `n_q=4`, `skip_first_steps=10`, `skip_first_layers=0`, and `min_seq_len=4096`.

The following backend and kernel tests passed without skips on both 78-SM and 132-SM SM90 environments:

- `test_full_budget_reproduces_dense`
- `test_ragged_tail_reproduces_dense`
- `test_unsorted_ragged_tail_oversubscribes_sms`
- `test_varlen_routes_each_document`
- `test_routing_finds_the_blocks_that_carry_the_mass`
- `test_subblock_sparse_sm90.py`

The ordering regression uses a single oversubscribed SM90 launch with 516 query-head tiles, a ragged tail, and deliberately unsorted block IDs. Its magnitude-sensitive fixture verifies that the adapter sorts the tail block into the slot consumed with sequence-length masking.

For the end-to-end comparison, each configuration was run once with seeds `0`, `1`, and `2`. SubBlock output was compared with the dense output generated from the same input, seed, and server configuration.

SSIM is computed for every aligned frame in YUV420 space as `(4 × SSIM_Y + SSIM_U + SSIM_V) / 6`. Each value below is the mean ± population standard deviation across the three seeds, where the result for each seed is averaged over all aligned frames.
