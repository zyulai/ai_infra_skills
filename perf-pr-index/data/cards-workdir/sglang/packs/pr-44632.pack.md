## Motivation

SM100 swap-AB decode attention for DeepSeek-V4.1 admits at most 8 query rows. DSpark verify sends 5 rows per request (block size 5), so only batch size 1 takes swap-AB; batch size 2 and up fall back to FlashMLA. FlashMLA pads q to 64 heads and runs split-KV, so its time is flat at about 24 µs across 5–40 rows, while swap-AB is 2.7x faster at 5 rows and grows with the row count.

## Modifications

- `decode_attention_sm100.py`: admit up to 40 rows (`MAX_ROWS`) on SM100, so TP4 verify up to batch size 8 takes swap-AB. The kernel grid is (rows, KV tiles) and no program depends on the row count, so the cap is only a dispatch choice. The gfx950 path keeps its 8-row `MAX_BATCH`.
- `test_swapab_attention.py`: add 20- and 40-row cases and a 40-row CUDA graph replay; the per-row lengths now repeat so they cover any batch.

## Kernel timing

GB300, 16 heads (TP4), one decode layer shape (SWA 128 + extra KV 512), CUDA graph timing, µs per call:

| rows | batch size (verify) | swap-AB | FlashMLA | ratio |
|---|---|---|---|---|
| 5 | 1 | 8.8 | 23.7 | 0.37 |
| 10 | 2 | 9.3 | 23.9 | 0.39 |
| 20 | 4 | 12.5 | 23.9 | 0.52 |
| 24 | — | 13.1 | 23.8 | 0.55 |
| 40 | 8 | 20.1 | 24.2 | 0.83 |

Break-even is near 48 rows; 40 leaves a margin.
