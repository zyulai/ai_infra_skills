## 正文(PR 描述)

## Motivation

After #20796 (`1a8eb890f6`, Kernels community fa3), the multimodal-gen `FlashAttentionBackend` now dispatches through FA3 (`sglang.jit_kernel.flash_attention_v3`), which is CUDA-only. On ROCm, this causes a crash during the text encoder warmup request because:

1. `_is_fa3_supported()` compares `torch.version.cuda >= "12.3"`, but `torch.version.cuda` is `None` on ROCm, causing a **TypeError**
2. Even after guarding the `None` case, the FA3 path raises `NotImplementedError` since FA3 is not available on ROCm

Previously, the ROCm platform could use FA2 via the `flash_attn` package (which supports ROCm). But the new dispatch layer always routes through FA3, making the FlashAttention backend unusable on ROCm.

ROCm 720 CI was unaffected because its Docker image does not have the `flash_attn` package installed, so it naturally fell back to Torch SDPA. ROCm 700 has `flash_attn` installed, triggering the crash.

## Changes

**`python/sglang/jit_kernel/flash_attention_v3.py`** (+2 lines)
- Guard `_is_fa3_supported()` to return `False` early when `torch.version.cuda is None`. This prevents the `TypeError` crash and also benefits XPU or any future non-CUDA platform.

**`python/sglang/multimodal_gen/runtime/platforms/rocm.py`** (+14/-4 lines)
- Add an explicit `_is_fa3_supported()` check in the ROCm attention backend selector. When FA3 is not supported (always true on ROCm), fall back to Torch SDPA instead of selecting the FlashAttention backend.
- The original head-size validation is preserved under a `target_backend == FA` guard for correctness.
