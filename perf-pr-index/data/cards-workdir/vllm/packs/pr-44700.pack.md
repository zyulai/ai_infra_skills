# Description

This PR has 3 changes:

1. **Main: split mixed prefill+decode batches** (see below).
2. **Add MTP eval** config for Qwen3.5-397B NVFP4.
3. **Rename** `fast_kernel` → `aiter_kernel` (`fast_kernel` was too general).

## Problem

GDN attention ran **all** non-spec tokens through `chunk_gated_delta_rule`. Each decode becomes its own chunk padded to `FLA_CHUNK_SIZE=64`, so `D` decodes cost `D` near-empty 64-token chunks of wasted work. The ratio looks like this:

| Case | Kernel | Median (µs) |
|---|---|---|
| A. prefill 8192 | CuteDSL chunk | 464.1 |
| B. decode 953 | fused_sigmoid | 1843.7 |
| Sum | | 2370.8 |
| C. mixed unified (953+7239 → chunk) | CuteDSL chunk | 4361.6 |

With this PR:

| Case | Kernel | Median (µs) |
|---|---|---|
| split (pre+dec, this change) | CuteDSL + fused_sigmoid | 2256.5 |

PS: MTP already goes through this path.

## Solution

When a non-spec batch mixes prefills and decodes, peel the decode front-slice off to the recurrent update kernel `fused_sigmoid_gating_delta_rule_update` and run only the prefill tail through the chunk kernel. The metadata builder rebases chunk metadata to the prefill-only tail; outputs are stitched back in decode-first order.

## Tests

- `test_gdn_forward_core_split.py::test_forward_core_split_matches_unified`: split path matches the unified chunk-only path on `core_attn_out` and SSM-state. **8/8 passed** on B200 (bf16/fp32 × mixed-batch shapes).
- GSM8K (1319 q, 5-shot, B200):

| Model | Threshold | Measured | Pass |
|---|---|---|---|
| Qwen/Qwen3.5-35B-A3B | 0.84 ± 0.03 | 0.8499 | ✅ |
| Qwen/Qwen3.5-35B-A3B-FP8 | 0.79 ± 0.03 | 0.7953 | ✅ |
| nvidia/Qwen3.5-397B-A17B-NVFP4 | 0.88 ± 0.03 | 0.8863 | ✅ |
