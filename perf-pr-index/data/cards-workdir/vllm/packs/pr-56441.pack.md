## PR body
```markdown
Replace the DeepSeek-V4.1 DSpark context insertion call's unused query allocation and query work with a KV-only wrapper. Dispatch the existing CUDA KV math with zero query heads for packed uint8 `fp8_ds_mla`, BF16 and ordinary FP8 e4m3fn caches. Keep projection, `kv_norm`, scheduling and acceptance logic unchanged. Validate device/dtype/layout inputs and preserve padded page strides.

**Rebase validation (2026-09-14):** current head `17127220492339af2d5969003633a7ddbdaf5c45` is based on `main` at `dbf49dad11e30ec5d464be74b715a9a9e31c2c5a`. Rebased across the upstream `deepseek_v4_1` to `deepseek_v41` directory rename and updated the focused test import to the new module path. The original added/removed patch lines are preserved after normalizing that rename; the CUDA source and DSpark caller remain byte-identical. Changed-file pre-commit hooks (`.venv/bin/pre-commit run --files` on all five changed files), `git diff --check`, Python parsing, and a static check of the renamed import target passed. CUDA compilation and GPU/model tests were not rerun for this rebase. GPU/model results below retain the revisions and configurations documented for those earlier runs. AI assistance was used for the rebase, import fix, and validation.

**Related work was found:** #55654 adds uint8 KV-only insertion, fused `kv_norm` and projection changes for V4. There is overlap in the uint8 insertion goal. This PR differs materially by reusing the existing zero-query-head kernel paths across all three cache formats, including BF16/ordinary FP8 paths that #55654 retains as dummy-query fallbacks, and by changing only V4.1 insertion. It does not add another fused norm or projection implementation. The overlapping uint8 API should be consolidated if both approaches proceed. #54674's stacked projections are also a separate operation.

Resubmission of #56320 after `dsv41-feat` merged into `main` in #56214. The original feature-branch PR is closed; this is its existing `main` replacement.
