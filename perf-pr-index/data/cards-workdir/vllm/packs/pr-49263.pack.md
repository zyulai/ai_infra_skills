## PR body
```markdown
## What is the feature about?

Adds dense MHA for short prefill in the ROCm AITER Sparse MLA backend, following #47327. Prefill at or below the sparse top-k threshold (2,048 tokens for DeepSeek-V3.2) uses dense attention; longer prefill and decode retain sparse MQA. The fused DeepSeek-V3.2 path is integrated so mixed prefill/decode batches use the correct metadata.

## Test plan

- Compare BF16/FP8-KV engine outputs and log probabilities against forced sparse MQA; cover unequal/chunked prompts, the 2,048-token boundary, and mixed prefill/decode
- Trace the actual pretrained dense/sparse paths separately from timing; run existing metadata, sparse-attention, and sink tests collected by MI300/MI355 CI
- Compare matched pretrained GSM8K/harder-task accuracy and short/long-prompt serving at concurrency 1/8/32

## Test results

Published `7abb8ef` has the same tree as validated `e34b94e`; baseline: `b538d807`. **187 passed, 116 skipped, 14 warnings; local staged pre-commit passed.** Runtime tracing confirmed dense prefill through 2,048 tokens, sparse at 2,049, and mixed dense-prefill/sparse-decode execution.

Pretrained runs: official DeepSeek-V3.2, 8× AMD gfx950/TP8, FP8 weights, BF16 activations/KV, AITER, eager execution, prefix caching off. ROCm 7.2.3, Torch `2.13.0+git733fca1`, AITER 0.1.23, Triton `3.8.0+git669b31ac`.
