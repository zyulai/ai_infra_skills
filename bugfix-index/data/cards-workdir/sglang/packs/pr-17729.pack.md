## 正文(PR 描述)

## Summary
- Fix `/tag-and-rerun-ci` and `/rerun-failed-ci` to use full workflow rerun when PR has sgl-kernel changes
- This ensures `sgl-kernel-build-wheels` runs again and produces fresh artifacts

## Problem
When a PR modifies sgl-kernel and tests fail:
1. User runs `/tag-and-rerun-ci`
2. `rerun_failed_jobs()` only reruns the failed test jobs, NOT the `sgl-kernel-build-wheels` job
3. Test jobs try to download artifacts, but artifacts are scoped to the original workflow run
4. Test jobs fail with "Found 0 artifact(s)"

Example failure: https://github.com/sgl-project/sglang/actions/runs/21241650161

## Solution
Detect if the PR has sgl-kernel changes (`sgl-kernel/` directory), and if so, use `run.rerun()` instead of `run.rerun_failed_jobs()` to ensure the kernel build job runs again.

## Test plan
- [ ] Verify rerun works correctly for PRs without sgl-kernel changes (should use efficient `rerun_failed_jobs`)
- [ ] Verify rerun works correctly for PRs with sgl-kernel changes (should use full `rerun`)
