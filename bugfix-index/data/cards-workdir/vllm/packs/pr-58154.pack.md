## 正文(PR 描述)

## Purpose

Fix an output-ownership bug in NCCL symmetric-memory AllGather and
ReduceScatter.

#46703 changed these paths to reuse persistent registered scratch buffers, but
returned those buffers directly. A later collective with the same shape and
dtype can therefore overwrite an earlier result that is still live. The
collective itself computes the correct value, but the returned tensor does not
have independent storage.

This can silently produce incorrect model outputs. It was reproduced in a
TP16 Qwen2.5-72B run, where the affected ReduceScatter path disagreed with the
ordinary collective path for all 16 test prompts.

## Changes

- Clone the result of symmetric ReduceScatter before returning it.
- Clone the result of single-tensor symmetric AllGather before returning it.
- Add regression tests that retain two same-key results and verify that they
  have distinct storage and preserve both values.
- Cover the same ownership contract under CUDA graph replay with changed inputs.

Batched AllGather and current AllReduce are unchanged because they already
return fresh output storage.

The fix preserves cached symmetric scratch and window registration. Each
affected generic call allocates fresh result storage and makes one output-sized
device-to-device copy.

Related: #49194 provides caller-owned output for a specialized MoE
ReduceScatter path, while #55211 bounds scratch growth and handles AllReduce
ownership. Neither fixes generic symmetric ReduceScatter or single-tensor
AllGather.

- Current main on 2xGB200: the focused AllGather and ReduceScatter tests passed
  without skips. NCCL logs confirmed that the symmetric algorithms were used.
- Pinned vLLM 0.26.0 controls reproduced retained-result aliasing for both
  operations; clone-out returned distinct storage and preserved both results.
- Qwen2.5-72B TP16 on 16xGB200: clone-out restored 16/16 top-1 output-token
  agreement with the ordinary collective path.
- Ruff formatting, lint, and applicable local hooks passed.
- Exact PR head `cfaf005b6` on 2xGB200 (Blyris job `47152`): the AllGather
  and ReduceScatter CUDA graph tests passed with no skips (`2 passed, 1
  deselected`). Each retained two same-key outputs across two changed-input
  replays. NCCL logs selected symmetric `AllGather_ST` and `ReduceScatter_LD`.
  Runtime: PyTorch 2.14.0a0 (NV 26.09), CUDA 13.4, NCCL 2.31.2. Upstream
  pre-commit remains gated before lint/tests by its author/label pre-run check.
