## Motivation

sgl-project/sglang#24651 added a fused all-reduce + RMSNorm + per-group FP8 quant path for the Qwen3.5 FP8 attention and GDN input projections, and gated the single aiter kernel to gfx95 with `is_gfx95_supported()`. On gfx942 (MI300X / MI325X) the same call falls back to the fused AR + RMSNorm kernel followed by a separate per-1x128 quant kernel, so every layer's input projection pays one extra kernel launch and one extra read and write of the normed activation.

The aiter kernel is not gfx950-specific: it is generic HIP with an arch-selected FP8 type (`e4m3fnuz` on gfx942). aiter's own `op_tests/multigpu_tests/test_fused_ar_rms_per_group_quant.py` passes on 2x MI300X at TP2 for every shape and option combination we ran (below).

## Modifications

- `GroupCoordinator.fused_allreduce_rmsnorm_quant_per_group` (`parallel_state.py`): allow gfx942 alongside gfx95 (`is_gfx95_supported() or is_gfx942_supported()`). Shape, size and world-size checks are unchanged.
- Docstrings in `parallel_state.py` and `layernorm.py` updated to say gfx942 and gfx95.
- `test/registered/unit/distributed/test_parallel_state.py`: unit test that the fused kernel is called on gfx95 and on gfx942 and that other HIP archs still get `None`.

Nothing downstream changes: on gfx942 the two-kernel fallback already handed the same `(fp8, scale)` / `(bf16, fp8, scale)` tuples to the projections, with the same row-major scale layout (the column-major `transpose_scale` path is only taken for the gfx95 bpreshuffle GEMM).

Observable effect: on gfx942 with `--enable-aiter-allreduce-fusion`, Qwen3.5 FP8 attention and GDN input projections now get their FP8 input from the single fused kernel instead of fused AR + RMSNorm plus a separate quant. `SGLANG_DISABLE_FUSED_AR_QUANT=1` still opts out.

## Speed Tests and Profiling

### Decode kernels, 2x MI300X

Qwen3.5-122B-A10B-FP8, TP2, `lmsysorg/sglang-rocm:v0.5.23-rocm10-mi30x-20261109`, `--enable-aiter-allreduce-fusion`, EAGLE MTP, `--page-size 16`, decode-stage torch profile (30 steps, TP rank 1) under an InferenceX AgentX trace replay at concurrency 24. Kernel counts per profiled step:

| kernel | before | this PR |
|---|---:|---:|
| fused AR + RMSNorm, no quant (`allreduce_fusion_kernel_1stage`, 6.45 us) | 49.0 | 25.5 |
| standalone per-group quant (`dynamic_per_group_scaled_quant`, 4.64 us) | 102.0 | 78.5 |
| fused AR + RMSNorm + per-group quant (`allreduce_fusion_kernel_1stage_per_group`, 7.25 us) | 0 | 23.5 |

Each attention/GDN input now takes one 7.25 us kernel instead of 6.45 + 4.64 us, saving ~90 us of GPU time per profiled step, about 1.5% of decode GPU time. The remaining standalone quants feed other projections (attention/GDN output, shared expert) and are not touched here.

The end-to-end differences, including the TTFT increase, are within the run-to-run spread of this replay; this change does not touch prefill compute. The kernel counts above are the direct evidence.
