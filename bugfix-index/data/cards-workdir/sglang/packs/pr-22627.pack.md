## 正文(PR 描述)

## Summary

- Fix crash in `flashinfer_cutlass MoE backend ` when `intermediate_size_per_partition` is not a multiple of 16 (e.g., NemotronH FP8 at TP=8: 7688 / 8 = 961)
- Add 16-byte alignment padding for flashinfer_cutlass in` ModelOptFp8MoEMethod.process_weights_after_loading`, following the same post-load padding pattern as `ModelOptNvFp4FusedMoEMethod` for flashinfer_trtllm
- Move moe_runner_backend auto-resolution (`AUTO` → `FLASHINFER_CUTLASS`) from `server_args.py` into `ModelOptFp8MoEMethod.create_moe_runner,` following the fp8.py pattern so user `--moe-runner-backend` overrides are still respected

## Motivation

- The flashinfer_cutlass MoE kernel requires intermediate_size_per_partition to be a multiple of 16. For models like NemotronH FP8 (Nemotron Nano 30B A3B), moe_intermediate_size = 7688. At TP=8, this gives 7688 / 8 = 961, which is not 16-aligned, causing a hard crash during server launch on flashinfer 0.6.3+.
- On older flashinfer versions, this silently fell back to a slower kernel path. This bug was discovered while investigating the performance characteristics reported in #21307.

## Changes

- `python/sglang/srt/layers/quantization/modelopt_quant.py `(ModelOptFp8MoEMethod)

create_moe_runner: Resolve AUTO → FLASHINFER_CUTLASS and store as self._resolved_backend (user overrides via --moe-runner-backend are respected; only instantiate MoeRunner for TRITON)
process_weights_after_loading: Use self._resolved_backend instead of global get_moe_runner_backend(); pad w13_weight and w2_weight with F.pad when intermediate_size_per_partition % 16 != 0 (same post-load padding approach as ModelOptNvFp4FusedMoEMethod for trtllm 128-alignment)
apply: Use self._resolved_backend for backend dispatch

- `python/sglang/srt/server_args.py`
Remove the NemotronH-specific moe_runner_backend = "flashinfer_cutlass" override entirely (now handled in the quant method per reviewer feedback)


- `python/sglang/srt/layers/moe/fused_moe_triton/layer.py` (FusedMoE)

Remove use_flashinfer_cutlass_padded flag and pre-allocation padding from __init__ (padding is now post-load in the quant method)
Remove use_flashinfer_cutlass_padded from use_padded_loading in _load_w13 and _load_w2

## Impact

Benchmarked on **NVIDIA-Nemotron-3-Nano-30B-A3B-FP8**, TP=8, 8xH100:

| Metric | Before (triton MoE fallback) | After (flashinfer_cutlass + fix) | Improvement |
|--------|------------------------------|----------------------------------|-------------|
| Output tok/s | 140.14 | **207.18** | **+47.8%** |
| ITL (ms) | 7.14 | **4.83** | **-32.4%** |

No accuracy impact -- the fix only pads weight tensors with zeros (same approach as `flashinfer_trtllm` 128-alignment).

## Test plan

- [x] TP=1: No alignment needed (7688 / 1 = 7688, divisible by 16) -- verified no regression
- [x] TP=8: Alignment fix applied (961 -> 976) -- verified crash resolved, +47.8% throughput
- [x] Accuracy validation: lm_eval gsm8k matches baseline
- [ ] CI: Existing MoE tests should pass (fix only activates when `intermediate_size_per_partition % 16 != 0`)

Related: #21307 (discovered this bug while investigating Nemotron TP=8 performance)
