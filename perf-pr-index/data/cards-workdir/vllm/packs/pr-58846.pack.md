## Purpose

Bumps the FlashKDA pin from `b59532f` to `17a037d`, the merge of vllm-project/FlashKDA#13 on its `dev` branch.

Before this change, FlashKDA's K2 kernel stored the KDA recurrent state in bf16 and rounded it after every 16-token tile. On long GLM-5.3-Flash prefills the error builds up across tiles and across chunked-prefill boundaries, and it shows up as corrupted long-context tool-call output. FlashKDA#13 keeps the state in fp32 between tiles, adds missing TMA store waits, and fixes a register-pressure regression on sm_10x.

The only change is the one-line `GIT_TAG` in `cmake/external_projects/flashkda.cmake`. FlashKDA's op schema, `flash_kda.h`, source file list and cutlass submodule are the same at both commits.

Not a duplicate: no other change to the FlashKDA pin is on main since #12, and I found no open PR bumping it.

## Test Plan

All runs used RedHatAI/GLM-5.3-Flash-NVFP4, TP2, with FlashKDA built at the PR #13 content, on B200 (sm_100f, cu130) and H200.

- FlashKDA `tests/test_fwd_full.py`, which is a bitwise comparison against `torch_ref` covering fixed, varlen, batched and up to 1M-token cases.
- Relative error against an fp64 reference, using real GLM-5.3-Flash layer-0 activations.
- A long-context tool-call corruption probe (GLM-5.3-Flash, 34k and 42k-token prompts, salted cold prefills).
- `vllm bench serve` with the random dataset, 16 output tokens, 2k to 32k inputs and concurrency 1 to 64.

## Test Result

- `test_fwd_full`: 580/580 on B200.
- Final-state relative error, 4k to 128k tokens: 0.37-0.39%, previously 0.85-1.24%. Output relative error: 0.47%, previously 0.48%.
- Probe at 42k on B200, 256 samples per arm: 224/256 (87.5%) correct, previously 173/256 (67.6%). At 34k: 253/256 vs 256/256.
- H200 probe at 42k (emulated MoE, to isolate FlashKDA): 31/32, previously 21/32.
- Kernel time on B200: geomean 4.6% faster than the old pin.
- End-to-end serving on B200: throughput within ±1.3% of the old pin, which is within run-to-run noise.

**AI assistance:** Claude (Claude Code) helped with the FlashKDA kernel changes in FlashKDA#13, the benchmarks and quality runs above, and this pin bump and description. I reviewed the change and the results. The commit carries a `Co-authored-by: Claude` trailer.
