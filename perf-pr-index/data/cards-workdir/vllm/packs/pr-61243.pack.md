## PR body
```markdown
## Purpose

HiSparse didn't work on GLM-5.3-Flash. This PR makes it start, serve correctly, and fit 3.4–4.8× more concurrent long requests than serving without HiSparse. Fixes #59176.

Flash is the first hybrid model on HiSparse: 11 of its 45 layers use sparse MLA, the rest use KDA (linear attention).

## Changes

**Getting Flash to start and serve**
- Read the top-k setting from the text config (Flash's top-level config is multimodal).
- Fix a hang during CUDA graph capture.
- One line in the GPU model runner: piecewise CUDA graph steps now give the HiSparse connector the attention metadata, as full-graph steps already do. Without it, Flash overflows a buffer once pages live on the host.
- Fix a crash in `FLASH_ATTN_MLA_SPARSE` on Hopper caused by gaps in the indexer's top-k output.
- Attention backends now declare whether they support HiSparse. FlashInfer on Hopper (wrong results on prefix-cache hits) and on SM120 (unvalidated) opt out.

**Using GPU memory efficiently**

All KV cache groups share one GPU pool whose blocks are sized for the biggest group. On Flash that's a ~1.1 MB KDA state, much bigger than what HiSparse's own groups need, so most of each block was wasted. Now HiSparse groups fill those blocks:
- Hot-cache layers are packed together into each block (22 groups become 4).
- Each indexer block holds several kernel pages instead of one. When the pages don't divide the block evenly, the planner either pads each page or grows the block, whichever leaves more room for requests.
- KDA blocks shrink to 256 tokens so they don't force a larger scheduler block.
- One small change in `worker/utils.py`, so kernels can address padded pages.

**Known gap:** Flash with fp8 KV on Hopper still fails at the first prefill with the FlashMLA backend. That's a separate bug; I'll fix it in a follow-up.
