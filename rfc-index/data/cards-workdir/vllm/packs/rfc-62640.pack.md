## 正文(PRD / 提案全文)

### Motivation.

Hi,

currently, the MTP warning is rather aggressive:
```
(APIServer pid=1) WARNING 10-20 07:22:23 [speculative.py:1375] Enabling num_speculative_tokens > 1
will run multiple times of forward on same MTP layer,which may result in lower acceptance rate
```

Most production deployments will run with `MTP >= 3` and more typically `MTP = 5`. This is even more true considering that this is what many of the official vLLM recipes recommend. 

### Proposed Change.

Having a warning that highlights a risk without concrete recommendations on what to do, feels like an unnecessary papercut. I have a few ideas an would like to know what people think:
1. Reduce the level to `INFO`
1. Improve the message to point at `https://recipes.vllm.ai/` and to mention the draft acceptance rate metric with a target between 60 - 80%.
1. If we keep warning as the level, increase the threshold to `5`
