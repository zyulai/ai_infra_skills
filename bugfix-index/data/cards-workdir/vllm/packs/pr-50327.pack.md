## Purpose

Fix a Model Runner V2 failure in pipeline-parallel hybrid Mamba models when a non-last pipeline rank processes a request:

```text
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018] WorkerProc hit an exception.
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018] Traceback (most recent call last):
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]   File "/usr/local/lib/python3.12/dist-packages/vllm/v1/executor/multiproc_executor.py", line 1010, in worker_busy_loop
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]     output = func(*args, **kwargs)
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]   File "/usr/local/lib/python3.12/dist-packages/vllm/v1/worker/gpu_worker.py", line 999, in sample_tokens
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]     return self.model_runner.sample_tokens(grammar_output)
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]   File "/usr/local/lib/python3.12/dist-packages/vllm/v1/worker/gpu/model_runner.py", line 1445, in sample_tokens
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]     self.model_state.postprocess_state(input_batch.idx_mapping, 0)
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]   File "/usr/local/lib/python3.12/dist-packages/vllm/v1/worker/gpu/model_states/mamba_hybrid.py", line 314, in postprocess_state
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018]     self.num_accepted_tokens_gpu.index_fill_(
(Worker_PP0_TP0 pid=1777) ERROR [multiproc_executor.py:1018] IndexError: index_fill_(): Expected dtype int64 for index.
```

`InputBatch.idx_mapping` is intentionally an `int32` CUDA tensor. The scalar branch of `MambaHybridModelState.postprocess_state` passed that mapping to `Tensor.index_fill_`, which only accepts an `int64` index.

This change adds a dedicated Triton scalar-fill kernel. It consumes the existing `int32` mapping directly, ignores the mapping's negative sentinel entries, and avoids allocating a converted index tensor on every step. A focused CUDA regression test covers both the pipeline-prefill value (`num_sampled=0`, normalized to 1) and a regular sampled-token value.

I searched GitHub issues and open PRs for the exact dtype error, Model Runner V2 pipeline Mamba `index_fill_`, and `postprocess_state`/`idx_mapping`, and found no matching report or fix.

AI assistance was used to author the implementation and regression test. The submitter reviewed every changed line, understands the change, and verified it on H100 hardware.
