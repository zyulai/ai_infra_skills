```markdown
## Purpose

DeepSeek-V4.1-Flash has three attention layer shapes: full CSA2 layers (2/8/14/20) run SWA + compressor + indexer and build a new global KV cache with their own Top-K indices; reindex CSA2 layers (24/28/32/36) run SWA + indexer only, re-scoring Top-K over an earlier layer's global KV cache; all other layers are dense or pure SWA.

The shared v4.1 pipeline overlaps the full CSA2 layers with **three** fork/join pairs per step (input projections; Q/SWA-insert vs compressor; indexer vs cache-insert) and the reindex layers with one. On ROCm each fork/join is a HIP event pair per side stream, so the multi-stream launch cost outweighs the overlap benefit there.

---
This PR gives the ROCm attention layer a layer-type-aware scheme with exactly one fork/join per step:

**Full CSA2 layers (`_forward_csa2_full`)**: one 3-stream fork right after the input norm.

  - default stream: fused wqa+wkv → q/kv split+norm → wq_b → fused qnorm/RoPE/SWA-insert;
  - aux stream 0: the compressor chain (kv_score GEMM → save/compress/norm → RoPE-quant cache insert);
  - aux stream 1: indexer `weights_proj`.

After the single join, the indexer K write (`_produce_k`, whose `wk` consumes the aux-0 latent) and the query path (`forward_q`, whose wq_b consumes the default-stream qr) run serially, followed by the indexer op and sparse MLA.

**Reindex CSA2 layers (`_forward_csa2_reindex`)**: the input projections run serially first (the query path consumes qr, so overlapping the weight projection is not worth it), then one 2-stream fork overlaps the SWA q path with the indexer query path.

**Dense layers**: fully serial (`aux_stream_list` disabled).

---
A new shared helper `execute_in_parallel_default_first` (in `vllm/utils/multi_stream_utils.py`) mirrors `execute_in_parallel` but enqueues the default chain before the aux chains — the default chain is the longest, so starting it first shortens the step tail while the aux streams still only wait on the pre-fork default-stream work.

The fork is gated exactly like the shipped v4.0 multi-stream gate (#51794/#56853): it only runs where the fork/join becomes static graph edges (inside capture, or with non-dict metadata such as the profile run); everywhere else — including MRV1, which keeps its wide eager region (#51430) — the layer falls back to the fully sequential base pipeline.

The CUDA/NVIDIA path is untouched except for a behavior-neutral base refactor: the v4.1 indexer's query path is extracted into `DeepseekV4Indexer.forward_q`, still driven unchanged by the base `forward` (`_produce_k` keeps its private name). This is not a duplicate of #51794/#56853, which cover v4.0: v4.1-flash has a different topology (the indexer derives K from the kv-source compressor's latent, with no indexer-local compressor), so the overlap must differ per layer type.
