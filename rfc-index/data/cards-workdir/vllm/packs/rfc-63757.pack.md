## 正文(PRD / 提案全文)

### Motivation.

Model Runner V2 captures every FULL decode CUDA graph with attention metadata `max_seq_len = max_model_len`, so the graph is valid for any context it replays. Any host-side decision made from `max_seq_len` during capture is therefore made for the longest context and frozen into the graph.

Some models skip work when every context in a step is short, but cannot do so in FULL decode graphs:

- GLM-5-Next's sparse indexer: when all contexts fit `index_topk` (2048 on GLM-5.3-Flash), its top-k is every causal token, so the q projection, head-weight projection, q quantization, paged-MQA logits and top-k are dead work.
- DeepSeek-V4 / V4.1's indexers already skip this work in eager steps, but guard the shortcut with `not torch.cuda.is_current_stream_capturing()` (#52492), so FULL decode graphs never take it.

The rule from #52492 and #59709, no capture-time shortcut that a replay can invalidate, is right. What is missing is a FULL graph whose capture-time `max_seq_len` is smaller and still bounds every replay.

### Proposed Change.

1. **Declare.** A module sets `cudagraph_seq_len_bound: int | None`. The runner collects the distinct values below `max_model_len` from `model.modules()`.
2. **Capture.** Each FULL decode graph gets one copy per bound, captured with `max_seq_len = bound` in every backend's metadata.
3. **Dispatch.** `BatchExecutionDescriptor` gains `max_seq_len`, matched like `max_query_len`. A decode step whose contexts all fit a bound replays the copy (tightest first); any other step replays the default graph. The step's bound comes from the CPU arrays `prepare_inputs` already uses (no device read).
4. **Rule for modules.** Skip only work that `max_seq_len <= bound` makes dead, decided from the metadata the module receives, and only while a FULL graph is being captured.
   - Not in a PIECEWISE capture: that capture runs on the dummy batch's metadata.
   - Not in eager steps, including the warm-up run before each capture: the warm-up must compile and autotune everything its capture runs. Otherwise a cold start can compile or autotune inside the capture, which fails (seen in the reference implementation's first commit under breakable `FULL_AND_PIECEWISE`).

Invariant: **the `max_seq_len` a FULL graph is captured with is an upper bound on every context of every batch it replays** (`max_model_len` for default graphs, the bound for copies). Host decisions made from it at capture hold for every replay.

Scope: off under PCP/DCP; opt-out `CompilationConfig.cudagraph_specialize_seq_len`. PIECEWISE-only deployments, mixed FULL graphs and micro-batched (DBO) graphs get no copies. Steps that cross the bound mid-request switch to the default graph.

#### Evidence

- Reference implementation: #63758 (mechanism + GLM-5-Next's indexer). GLM-5.3-Flash MXFP4, 2x MI355X, TP2, one image per request:
  - `FULL_DECODE_ONLY`: output throughput +2.32 % (SE 0.44 pp) at concurrency 16-64, +12.3 % at 4. Text rows that cross or exceed the bound are within noise. GSM8K unchanged. Cost: one extra graph per capture size and bound (graph memory 0.79 → 1.07 GiB per rank, KV cache −0.03 %).
  - Breakable `FULL_AND_PIECEWISE`: +4.50 % (SE 1.92 pp) at concurrency 16-64.
- Second user, a follow-up PR stacked on the reference implementation: DeepSeek-V4 / V4.1 (V4.1-Flash gets bounds 512 and 1025 from compress ratios 1 and 2).
- Prior art: SGLang selects a dense or sparse DSA decode graph on `max_kv_len <= index_topk` (`python/sglang/srt/layers/attention/graph_variants.py`).

#### Alternatives considered

| Alternative | Why not |
|---|---|
| Kernels read a device-side bound and exit early (or graph conditional nodes) | The q-side GEMMs are library GEMMs with no such predicate; every kernel on every platform would need it. |
| Eager segment around the indexer inside FULL graphs | One graph break per sparse-attention layer (not measured). |
| `ForwardContext` flag set during bounded captures | Repeats what `max_seq_len` carries; every forward-context producer must leave it unset correctly. |
| Model-interface method or attention-builder attribute | One declaration per model class that re-derives per-layer facts; a shared builder would capture copies for models that skip nothing. |
| Serve with `max_model_len <= bound` | No code, but only for deployments capped at the bound. |

#### Open questions

1. **#62749** records FULL decode metadata builds keyed on batch shape, with `max_seq_len = max_model_len`. A step sent to a copy would match a build recorded for the default graph. Whichever lands second either adds `max_seq_len` to that key or keeps bounded steps on the eager build. Which is preferred?
2. **DP.** The bound is per rank, not in the DP sync: a copy has its default graph's token and request counts, which is all ranks agree on, and `max_seq_len`-dependent work is already rank-local in eager steps. A max-over-ranks row would make ranks switch together, at the cost of one long-context rank disabling the copies for all. Untested with DP > 1.
3. **Default on or opt-in.** Default on in the implementation, like `cudagraph_specialize_lora`.
