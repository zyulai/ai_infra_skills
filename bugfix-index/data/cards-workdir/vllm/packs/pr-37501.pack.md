## 正文(PR 描述)

## Purpose

Clamp `dA_cumsum` differences to non-positive before exponentiation in Mamba2 SSD Triton kernels to prevent `Inf`.

When a Mamba2 model has large `|A|` values, `dA_cumsum` reaches magnitudes where float32 ULP exceeds safe range. The parallel prefix scan (`tl.cumsum`) can introduce rounding errors that make `(dA_cs_last - dA_cs_k)` slightly positive instead of the mathematically guaranteed ≤ 0, causing `exp()` to overflow to `Inf`. This `Inf` propagates through SSM state and produces `NaN` in subsequent decode steps.

The fix adds `tl.minimum(..., 0.0)` before `fast_exp()`, matching the upstream Mamba fix (state-spaces/mamba#713) which only addressed the training path. This patch applies the same fix to the vLLM inference kernels.

**Affected kernels:**
- `_chunk_state_fwd_kernel` in `ssd_chunk_state.py`
- `_chunk_scan_fwd_kernel` in `ssd_chunk_scan.py`

## Test plan
- Tested on v0.15.1 (matching our RLVR experiment setup): `NaN` rate becomes 0%
- On main, this specific model/data combination did not reproduce `Inf` (likely due to kernel refactoring in #35397 changing `tl.exp` to `fast_exp` which alters float32 rounding behavior)
- However, the unguarded `fast_exp(dA_cs_last - dA_cs_k)` pattern on main is still mathematically unsafe, different inputs or models with large `|A|` can trigger the same overflow
