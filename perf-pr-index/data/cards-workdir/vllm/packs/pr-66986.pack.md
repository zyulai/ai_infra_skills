## Overview

Run Muse Spark's `gated_residual_rmsnorm` on FlashInfer's CuTe DSL backend instead of the default Cake backend. The Cake programs for 128 rows or fewer read `branch` before `griddepcontrol.wait` (flashinfer-ai/flashinfer#9343). This corrupts the hidden states that DSpark reads, so DSpark output is garbage at DP + EP with TP=1. No open PR addresses this.

## Claims

- Fixes DSpark at DEP8: AIME25 0% → 98.9%, GSM8K 23.1% → 94.8%, sdAL back to 3.7–3.9.
- No end-to-end perf change at TEP4.

## Details

- **Root cause:** DSpark reads 5 auxiliary target hidden states through `norm_then_gated_residual`, which calls `flashinfer.norm.gated_residual_rmsnorm` with `backend="auto"` and `enable_pdl=True`. For 1–128 rows, the Cake PDL programs prefetch `branch` before `griddepcontrol.wait`. When the preceding kernel triggers its dependents early, the norm reads a stale `branch` and emits NaN. The NaN flows through the draft's context K/V into its logits:
  - Most drafts are rejected (sdAL ≈ 1 under greedy GSM8K), but the NaN drafts that do get accepted still derail outputs (GSM8K 23%).
  - With sampling, NaN draft probabilities pass the acceptance test, so every draft is accepted and the output is garbage (AIME25 0%, sdAL 8.00).
- **Why only TP=1:** the same kernel runs at TP>1 without failing there. The trigger depends on which kernel runs just before it. The target's own boundary uses `gated_residual_next_rmsnorm`, whose Cake programs have no PDL, so target-only serving is unaffected.
- **Why CuTe instead of `enable_pdl=False`:** both fix DEP8 and tie end to end. CuTe keeps PDL and is about 0.5 µs faster per decode-size call. Disabling PDL keeps Cake's numerics and is 7–13% faster per call on prefill chunks of 2048 rows or more, which is under 0.05% of a 140k prefill.
- **Support check:** `supports_gated_residual_rmsnorm` is now asked about the CuTe backend too, so shapes that CuTe can't run fall back to the existing Triton path instead of raising.
- **Revert plan:** go back to the default backend once FlashInfer re-renders the Cake programs with the fix.
- **No unit test:** the race needs a producer that triggers its dependents early. The issue has a standalone repro; the end-to-end DEP8 eval above covers the fix.
