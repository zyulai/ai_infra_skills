## Overview

`fused_inv_rope_fp8_quant` applies inverse RoPE to the attention output and quantizes it to block FP8 for `wo_a`. It launched one single-warp program per (token, head), which ran at 1.5 TB/s on B200 and took 8.6% of a 16k-token DeepSeek-V4-Flash prefill step (TP2).

This PR makes each program handle 4 heads of one output group, swaps the RoPE pairs in registers instead of re-loading them, and picks `num_warps` from the grid size. Outputs are bitwise identical to `main`.

## Claims

- Kernel, 16k tokens, 32 heads per rank (V4-Flash TP2): B200 536 → 152 µs (3.53x), H200 631 → 208 µs (3.04x), H100 631 → 293 µs (2.15x). At decode sizes it is at most 0.3 µs slower per call.
- `vllm bench forward`, V4-Flash TP2 + EP on 2×B200: prefill and mixed batches are 6% faster; decode is unchanged.
- `vllm bench serve`, 8k in / 1k out: TTFT p99 drops 5.1–5.6% at concurrency 1 to 128. Throughput stays within run-to-run noise.
- FP8 values and scales are bitwise identical to `main`, gsm8k is unchanged, and there are no runtime JIT compiles.

## Validation

Measured on Modal (CUDA 13.0, torch 2.14.0+cu130, Triton 3.8.0) at base `5f63ea461c`. Rebased onto `71a8275604` (the newest `main` commit with a published precompiled wheel; it does not touch these files) and re-ran the unit tests.

**Correctness**

- Unit tests: 106 passed on B200, including the new `H24_G4` case. They cover both scale layouts, quant groups 32 and 128, `quantize=False` and both `num_warps` branches. On H100 and H200, 93 passed and 8 SM100-only cases were skipped. The 5 `test_einsum_end_to_end` failures there also happen on `main`: the test hard-codes the SM100 einsum recipe, which DeepGEMM rejects on SM90.
- Bitwise comparison with `main`'s kernel on B200, H100 and H200: every (BLOCK_H, num_warps) config, T = 1 to 16384, H = 16/32/64, plus head-padded and offset input views and extreme values. No mismatch.
- gsm8k with the B200 CI config `DeepSeek-V4-Flash-deepgemm-mega-moe.yaml` (TP2 + EP, FP8 KV, MTP), three runs each: `main` 0.9469 / 0.9492 / 0.9507, this PR 0.9492 / 0.9500 / 0.9484. All pass the CI threshold with 0% invalid answers and MTP acceptance length 2.63–2.64.
