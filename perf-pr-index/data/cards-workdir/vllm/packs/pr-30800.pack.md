## Purpose
This PR adds support for interleaved memory allocation when the system is configured with more than one NUMA node. Enabling interleaved allocation helps distribute memory traffic across nodes more evenly, which is particularly beneficial for memory-bound workloads.
In summary, this PR:
- Introduces NUMA-aware interleaved memory allocation when multiple NUMA nodes are present.
- Delivers around **30%** performance uplift on tested AMD EPYC systems for memory-bound workloads.

## Test Plan

export LD_PRELOAD=/usr/lib/x86_64-linux-gnu/libtcmalloc_minimal.so.4:$LD_PRELOAD
export LD_PRELOAD=<env_path>/lib/libiomp5.so:$LD_PRELOAD

vllm bench throughput --input-len 128 --output-len 1024 --model <model_name> --num-prompts 96 --dtype bfloat16 --max-num-seqs 32
## Test Result
I have validated this change on AMD EPYC servers with NPS4-NUMA configurations. Across a range of memory-intensive benchmarks, I observed an average performance improvement of approximately **30%** compared to the baseline (non-interleaved) configuration.
