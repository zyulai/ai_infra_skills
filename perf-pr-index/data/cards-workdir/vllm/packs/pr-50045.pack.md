## Purpose

Add back-pressure detection to the KV cache tiering offloading manager. When a secondary tier (disk, shared storage, P2P) becomes slow, the manager detects saturation via store completion latency and stops cascading new stores to that tier until it recovers. This prevents unbounded job pileup from degrading serving latency.

See associated RFC; https://github.com/vllm-project/vllm/issues/50031

### Design

- **Detection**: An exponential moving average (EMA) of store completion latency is tracked per secondary tier. When the EMA exceeds a high-water mark (1.0s), the tier is marked as under pressure. Pressure clears when the EMA drops below a low-water mark (0.5s). The hysteresis band prevents oscillation.

- **Response**: Stores to pressured tiers are silently dropped — blocks remain in the CPU primary tier subject to normal LRU eviction. Loads from pressured tiers continue normally.

- **Observability**: Two new Prometheus metrics per tier:
  - `vllm:kv_offload_tiering_backpressure_active` (gauge) — 1 when pressure is active
  - `vllm:kv_offload_tiering_backpressure_stores_dropped` (counter) — number of dropped stores

### Changes

- `vllm/v1/kv_offload/tiering/backpressure.py`: Add abstract `BackpressureDetector` and `BackpressurePolicy` APIs. Implement subclasses for EMA and store skipping.
- `vllm/v1/kv_offload/tiering/manager.py`: Add `BackpressureState` dataclass and per-tier tracking. Update `_process_finished_jobs()` to feed the EMA on store completions. Gate store cascades in both `complete_store()` (global tiers) and `_cascade_to_request_level_tiers()` behind pressure checks. Report metrics in `get_stats()`. Reset state in `reset_cache()`.
- `vllm/v1/kv_offload/tiering/base.py`: Add `submit_time` field to `JobMetadata` for latency measurement. Add `BACKPRESSURE_ACTIVE` and `BACKPRESSURE_STORES_DROPPED` metric keys.
- `tests/v1/kv_offload/tiering/test_backpressure.py`: New test suite (12 tests).

### Test plan

The test suite uses a `DelayedSecondaryTierManager` that holds completed jobs until explicitly released, allowing precise control over apparent store latency. It exercises:

1. **EMA updates on store completion** — EMA starts at 0 while jobs are in-flight, updates to `alpha * latency` after a fast completion.
2. **Pressure activates above high water** — Slow store (5x threshold) flips `is_under_pressure` to True.
3. **Pressure clears below low water** — Repeated fast completions decay EMA below low-water mark, deactivating pressure.
4. **Hysteresis prevents oscillation** — Mid-range EMA (between low/high water) does not toggle pressure in either direction.
5. **Stores skipped under pressure** — Blocks land in primary but are not cascaded to the secondary tier.
6. **Stores resume after pressure clears** — After clearing pressure, the next store cascades normally.
7. **Dropped store count tracked** — `stores_dropped` increments correctly per skipped cascade.
8. **Metrics reported via get_stats** — Prometheus gauge and counter appear in reduced stats with correct values; dropped count resets after collection.
9. **Metrics gauge zero when no pressure** — Backpressure gauge reports 0 when inactive.
10. **Reset cache clears backpressure** — `reset_cache()` zeros EMA and clears pressure state.
11. **Request-level tier respects backpressure** — Request-level cascades (via `prepare_store`) also skip pressured tiers.
12. **Loads continue under pressure** — Lookups still return RETRY and initiate promotion; only stores are suppressed.

+class ThrottledDropPolicy(DropAccountingPolicy):
+    """Drop stores proportionally to pressure severity.
+
+    Instead of dropping all stores when pressure is detected, the drop
+    rate scales with how far the EMA exceeds the high watermark::
+
+        overshoot = (ema - high_water) / high_water
+        drop_rate = min(1.0, overshoot / ramp_factor)
+
+    With the default ``ramp_factor=2.0``, stores ramp from 0% drop at
+    the high watermark to 100% drop at 3x the high watermark.  This
+    keeps secondary tiers populated under moderate pressure, reducing
+    cache misses (and therefore recomputation / ITL regression) while
+    still protecting TTFT under severe congestion.
+    """
+
+    def __init__(self, ramp_factor: float = 2.0):
+        super().__init__()
+        self._call_count: int = 0
+        self._ramp_factor = ramp_factor
+
+    def should_store(self, detector: BackpressureDetector) -> bool:
+        # Proportional throttling needs the EMA and high watermark, which
+        # only the EMA detector exposes.
+        assert isinstance(detector, EMABackpressureDetector), (
+            "ThrottledDropPolicy requires an EMABackpressureDetector"
+        )
+        if not detector.is_under_pressure():
+            return True
+        ema = detector.store_latency_ema
+        high = detector._high
+        if high <= 0:
+            return False
+        overshoot = max(0.0, ema - high) / high
+        drop_rate = min(1.0, overshoot / self._ramp_factor)
+        if drop_rate <= 0:
+            return True
+        if drop_rate >= 1.0:
+            return False
+        self._call_count += 1
+        period = max(2, round(1.0 / drop_rate))
+        return (self._call_count % period) != 0

+        super().reset()
+        self._call_count = 0

+            self._healthy_streak += 1
