# 证据卡撰写模板与规范

每张卡对应一个重点档 PR,输出到 `index/<repo>/cards/pr-<N>-<slug>.md`
(slug = 标题小写、非字母数字转 `-`、截 40 字符,`build_index.py` 按前缀
`pr-<N>-` 关联回索引)。

## 撰写素材

`data/cards-workdir/<repo>/packs/pr-<N>.pack.md` 含 PR 元信息、正文、diff
(超长 diff 只保留源码类文件)。需要更多上下文时可读 PR 网页
(`https://github.com/<org>/<repo>/pull/<N>`)。

## 模板(严格遵守结构,中文撰写,术语保留英文)

```markdown
# PR #<N>: <标题原文>

| | |
| --- | --- |
| 仓库 | vllm-project/vllm 或 sgl-project/sglang |
| 作者 | @<author> |
| 合并 | YYYY-MM-DD |
| 分类 | <classify.py 给出的分类> |
| Label | <labels> |
| Diff | +<additions>/-<deletions>,<changed_files> files |
| 链接 | <html_url> |

## 一句话结论

<50 字以内:这个 PR 把什么路径快了多少(或解决什么性能问题)>

## 动机

<2-4 句:PR 之前的问题/瓶颈,为什么值得改。来自 PR 正文,不要编造。>

## 优化点

<核心算法/内核/调度层面的改动,3-6 句。说清楚"改了什么机制"。>

## 关键改动

<列 2-5 个最核心的文件与作用,可含 ≤15 行的关键代码摘录>

```text
<文件路径>: <作用>
```

## 性能声明

<PR 正文中的 benchmark 结果:数字 + 测试条件(模型/硬件/精度/workload)。
没有条件信息就写"PR 未注明测试条件"。严禁脑补。>

## 验证与回归风险

<PR 引入/依赖的测试;可能影响的路径(如其他模型、其他硬件、精度)。>

## 关联

<同区域的其他优化:同分类其他 PR 编号、前序/后续 PR。没有就写"无"。>

---
> 本卡由 PR 正文与 diff 自动素材 + LLM 撰写,性能数字未独立核实。
```

## 硬性规则

1. **只写素材里有的信息**。diff/正文没有的细节不要推断;不确定的写"PR 未注明"。
2. 性能数字必须与 PR 原文一致,保留单位与条件。
3. 代码摘录 ≤ 15 行,选最能说明机制的片段。
4. 全文 300-800 字(不含表格/代码),不写空话。
5. 卡片文件名必须以 `pr-<N>-` 开头(索引关联依赖此约定)。
