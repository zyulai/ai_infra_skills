## Overview

The first PR of the split of #63232. It adds the MiniMax-M3.1-Flash model code (everything under `vllm/models/minimax_m3`, NVIDIA and ROCm, including the DSpark draft) and all kernel changes. The model-runner, sampling and KV cache manager changes from #63232 are left out and will follow as separate PRs (plan under Details).

## Claims

- **Serve MiniMax-M3.1-Flash on Blackwell (SM100/SM103/SM107):** the NVFP4 routed experts of the MXFP8 checkpoint load through the compressed-tensors NVFP4 MoE with per-token FC1 input scales. The KV cache and the index-K cache run in NVFP4 on the MSA CUTLASS Q8KV4 kernels.
- **DSpark speculative decoding:** a draft model that defaults to the checkpoint's `dspark/` subfolder, with fused draft kernels and a `FLASHINFER_TS` backend for non-causal draft blocks.
- **Decode kernels:**
  - fused QKV+indexer MXFP8 GEMM epilogue;
  - SM100 fused dense GEMM1;
  - persistent QK-norm/RoPE/KV-insert kernel;
  - small-batch MoE finalize fused into all-reduce + Gemma norm + MXFP8 quant;
  - DeepGEMM NVFP4 MegaMoE (opt-in, with expert parallelism);
  - opt-in NVFP4 indexer decode context parallelism at TP4.
- **ROCm:**
  - NVFP4 KV + NVFP4 indexer on gfx950;
  - one-launch-per-layer FlyDSL mono decode;
  - small-M MXFP8 linear tuning;
  - gfx942 fallbacks.

## Details

**Shared code this PR touches.** All of it is opt-in or a no-op for other models:
- `FusedMoEConfig.qat_activation_key` (default `None`): a model declares the activation scheme its experts were QAT'd against. `make_nvfp4_moe_kernel` now raises instead of silently dropping `per_token_activation` for a backend that cannot honor it.
- `ModelOptMxFp8Config.moe_quant_algo` (default `None`): routes `moe_quant_algo: NVFP4` experts to the compressed-tensors NVFP4 MoE.
- `Attention(query_pre_quantized=False)`: lets the DSpark draft skip a second query quantization.
- `DraftModelSpeculator.attn_vllm_config`: the draft's metadata builders now see the draft overrides (attention backend, KV cache dtype). The copies are shallow, so engine-resolved state such as `cache_config.kv_cache_layout` survives. Covered by `test_draft_attention_backend_override.py`.
- New `FLASHINFER_TS` attention backend, `attention_config.indexer_decode_cp`, a MiniMax-M3 TP check for NVFP4 KV, and the MSA pin bump (`968061a` → `25c1447`).
- The CuTe DSL primitives of the DeepSeek-V4.1 all-reduce and the Kimi-K3 latent MoE tail move to `vllm/models/common/ops/moe_tail_fusion`, shared with the M3 finalize fusion. Their callers only change import paths.

**For reviewers:**
- The ROCm mono decode here (`VLLM_ROCM_MINIMAX_M3_MONO`) predates and overlaps the upstream M3 MonoKernel (#62712, `kernel_config.monokernel`). The two need reconciling; it can also move to its own PR.
- `attention_config.indexer_decode_cp` (NVFP4 indexer, TP4) sits next to the existing `minimax_m3_indexer_cp` (ROCm bf16 Triton CP).
- The Q8KV4 prefill keeps a per-device split workspace that is only allocated on SM107. It was a stopgap on the source branch.
