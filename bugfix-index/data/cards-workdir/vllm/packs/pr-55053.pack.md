## 正文(PR 描述)

## Summary
Under **speculative decoding (e.g. MTP)** over MoRI-IO PD-disaggregation, the prefill
(producer) KV-cache manager reserves `num_speculative_tokens` lookahead blocks that the
decode (consumer) side never allocates. The producer's local block list therefore ends up
**longer** than the consumer's remote list, and the first prefill→decode KV write crashed
with `ValueError: local_block_ids longer than remote_block_ids` (e.g. 8003 vs 8000 at n=3),
making MTP unusable on MoRI-IO.

## Fix
The surplus is trailing lookahead scratch, not prompt KV, so it must be dropped **before**
the producer saves — not masked at transfer time.

- **Clamp on the WRITE producer save path** (`MoRIIOConnectorScheduler`): a new
  `_clamp_to_prompt_blocks` trims each **full-attention** KV group to its prompt length
  (`ceil(num_prompt_tokens / block_size)`), block-size-agnostic and per-group so it works
  under the hybrid multi-KV-group manager. Sliding-window groups are left untouched.
- **Chunked-prefill final-chunk detection by token progress** (`_is_final_prefill_chunk`):
  the save fires when `num_computed_tokens + num_scheduled >= num_prompt_tokens`, which is
  immune to speculative-lookahead block inflation (a block-count check is not). This also
  correctly handles a final chunk that allocates **no new blocks** (`new_block_ids is None`),
  which previously dropped the save and hung the decode leg.
- **Keep the loud invariant**: `compute_block_transfer_offsets` still raises on a genuinely
  longer-local list — a real bug in READ mode — rather than silently clamping. The relaxation
  lives only in the WRITE save path where the surplus is legitimate.
- **Fail closed on unsupported combos**: MoRI-IO WRITE mode + sliding-window attention (with
  or without spec decode) raises `NotImplementedError`, because the positional prompt-prefix
  save would ship out-of-window null blocks. READ + SWA (+ spec) is unaffected: block ids are
  pre-clipped to computed tokens before the connector sees them.

## Tests
- `tests/v1/kv_connector/unit/test_moriio_connector.py`: WRITE-mode clamp (single- and
  multi-group), chunked-prefill accumulation, the lookahead final-chunk regression (final
  chunk with `new_block_ids=None`), and the WRITE spec+SWA guard (reachable only under a

## Not a duplicate
This is the only open PR addressing MoRI-IO KV block-offset handling under speculative
decoding. It builds on (does not duplicate) the upstream hybrid/multi-KV-group MoRI-IO
refactor: it keeps that connector's structure and guards, and only adds the spec-decode
clamp + lookahead-safe final-chunk detection on top.
