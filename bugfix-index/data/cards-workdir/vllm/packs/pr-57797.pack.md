## 正文(PR 描述)

## Overview

Attention sink writes bypassed parameter `weight_loader` callbacks, leaving stale sink values after layerwise reload during RL weight updates. Register checkpoint-backed sinks with a common TP loader and factory, and route model loading through the registered callbacks.

This consolidates and supersedes #57798, #57801, #57803, #57804, #57805, and #57806.

## Claims

- DeepSeek V4/V4.1, HY-V4, MiMo-V2 (including MTP and Omni MTP), GPT-OSS, Laguna, and Qwen3-DFlash load sinks through their current parameter loader; GPT-OSS preserves MXFP4, Quark and other quantization dispatch.
- The loader partitions global checkpoint heads once, writes the local shard in place, and restores padded heads to `-inf`. The factory initializes sinks to `-inf` and registers the loader.
- Regression coverage checks changed sink values across two layerwise reloads, TP sharding, padding, storage preservation, quantization dispatch and pipeline-stage skips.

## Details

A dedicated sink loader derives shard length from the checkpoint rather than the runtime parameter: DeepSeek pads its runtime sink, so `sharded_weight_loader(0)` would use the wrong shard length. Unpadded sinks use the same loader without reconstructing storage. Checkpoint heads must divide evenly across TP ranks.

The loader keeps the divisibility check and relies on tensor slicing and the default loader for incompatible shapes. Empty checkpoints are no longer explicitly rejected. Lifecycle rationale stays here rather than in long helper docstrings.

Tests in the existing CI-selected `test_reload.py` and `test_weight_utils.py` suites cover actual model dispatch for MiMo MTP/Omni MTP, Laguna, DFlash, GPT-OSS, DeepSeek V4/V4.1 and HY-V4. The DeepSeek/HY-V4 tests replace the current loader and verify the unsliced global checkpoint reaches it exactly once for each load. AST factory-name scanning and redundant empty/padding tests were removed.

No full-model accuracy evaluation, real-checkpoint end-to-end reload, TP>2 or multi-node run was performed. Pipeline parallelism is covered by the skip-path test. Backend-converted sink copies and GPT-OSS expert reload follow-ups are outside this PR; their behavior is unchanged.
