## 正文(PR 描述)

## Motivation

DFlash/DSpark speculative pools corrupt sconv (short-conv) state when the radix cache is enabled for hybrid-SWA models such as Inkling and Inkling-Small.

This is because the mamba tracking was gated on prefill-graph capture, and any requests with a radix cache hit would resolve with all-zero sconv cache tensors.

It would especially affect long-context. We were able to find a 70-problem subset of (SWEBench Verified, SWEBench Pro, and SWEBench Multilingual) where DFlash reduces the pass rate from 55% to 35% due to long-context Inkling rollouts getting stuck and being "forgetful" due to the sconv cache corruption.

After this fix, DSpark / DFlash has parity without speculation on nvfp4.

```
┌─────────────────────────────┬────────┬────────┬───────┐
│ Arm (fixed build, same day) │ Reward │ Tokens │ Turns │
├─────────────────────────────┼────────┼────────┼───────┤
│ DSpark                      │ 0.486  │ 76.3k  │ 110.9 │
├─────────────────────────────┼────────┼────────┼───────┤
│ nospec                      │ 0.471  │ 74.4k  │ 106.9 │
└─────────────────────────────┴────────┴────────┴───────┘
```

## Modifications

1. Drop the `spec_algorithm.is_none()` from mamba index tracking guard
2. Capture-safety in the sconv backend: a capture warmup batch with no tracking metadata substitutes was inert
3. Zero the `mamba_track_*` padding rows in the prefill graph's static input buffers

## Verification

- A/B on one warm DSpark pool: byte-identical 10.5k-token prompts under a fresh vs cache-resumed prefix (cached=8960). Pre-fix: verify logits deviate 0.5–3.0 with greedy top-1 flips from the second step. Post-fix: **bit-identical (0.0000) at every step**, and the donated checkpoints match a non-speculative pool's values exactly.
- 70-problem SWEBench subset, same-day arms on the fixed build: DSpark reward 0.486 vs non-spec 0.471 (parity within noise; pre-fix 0.257 vs 0.457), with matching token/turn counts.
