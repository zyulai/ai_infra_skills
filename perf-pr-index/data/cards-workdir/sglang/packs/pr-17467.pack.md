## Motivation

The `ConsistentHashRing::get_owners` method is called frequently during rate-limit checks. The previous implementation allocated a new `HashSet` and cloned multiple `String`s for every lookup. In high-throughput scenarios, these transient heap allocations caused significant memory churn and increased tail latency ($P99$).

## Modifications

* **Zero-Copy Return:** Changed `get_owners` to return `Vec<&str>` instead of `Vec<String>`, allowing it to return references to existing keys in the ring without allocating new strings.
* **Removed HashSet:** Replaced the `HashSet` used for deduplication with a simple linear scan over the result vector. Since the number of owners is small (fixed at 3), a linear scan is significantly faster and cheaper than hashing overhead.
* **Deterministic Allocation:** Used `Vec::with_capacity` to ensure exactly one allocation per call.
* **Store Updates:** Updated `RateLimitStore` and `check_ownership_transfer` to handle the new reference-based API, cloning strings only when strictly necessary (e.g., when leaving the lock scope).

## Benchmarking and Profiling

benchmark (`benches/consistent_hash_bench.rs`) show a **3.3x to 4.2x** reduction in latency across various cluster sizes:

| Cluster Size | Pre-Fix (ns) | Post-Fix (ns) | Improvement |
| --- | --- | --- | --- |
| 10 Nodes | ~419 ns | ~100 ns | **4.17x faster** |
| 100 Nodes | ~467 ns | ~132 ns | **3.53x faster** |
| 500 Nodes | ~480 ns | ~143 ns | **3.35x faster** |

This change reduces heap allocations from ~5 per call to 1 per call.
