## 正文(PR 描述)

## Overview

Fix loading of nested ModelOpt `MIXED_PRECISION` checkpoints, quantization
settings for DFlash/DSpark drafts, and per-tensor FP8 normalization on FNUZ GPUs.
This incorporates the parser fix from the
earlier closed, unmerged [PR #36312](https://github.com/vllm-project/vllm/pull/36312)
and adds draft-layer name mapping, regression tests, CI coverage and documentation.

## Claims

- Nested `MIXED_PRECISION` metadata selects the existing `modelopt_mixed` backend.
- ModelOpt draft settings match the weight aliases, runtime module prefix and
  decoder layer offset before quantized layers are constructed.
- Per-tensor FP8 weights and static input scales are normalized for FNUZ GPUs
  such as AMD MI300, using the existing conversion helper.
- Other quantization backends retain their existing quantization-config handling.
  No FP8 kernel changes are needed.

## Validation

The current source passes 24 focused CPU checks and changed-file pre-commit,
including mypy and CI selection. CPU checks used Torch 2.13.0+cpu and
Transformers 5.17.0; current main pins Torch 2.14.0.

AMD CI exposed an existing per-tensor FP8 loader omission: both checkpoint
regressions failed during engine initialization at `input.dtype == weight.dtype`
in [MI300 quantization CI](https://buildkite.com/vllm/ci/builds/96958#01a16a9a-8a0e-4f38-8027-3356b1307ef8).
The loader retained FN weights while the activation quantizer selected FNUZ.
The fix applies the existing FN-to-FNUZ normalization before requantization,
including both weight and static input scales. The existing regressions now
require the exact platform dtype and input scale. Fresh AMD validation is
pending CI. A CPU check confirmed the conversion preserves dequantized weights, including
negative zero, while doubling both scales.

GPU validation below used vLLM 0.32.0 with the source fixes backported. The
checkpoint-loading regressions are retained, with shared fixture setup and
the existing speculative-metric reader. GPU tests were not rerun for this
cleanup; the full current-main environment and full suites remain untested.

## Details

There are two failures. Config conversion rejects nested `MIXED_PRECISION`
metadata before the existing backend can load it. After that is fixed, the
draft loader looks up per-layer settings using runtime names such as `model.fc`,
while the checkpoint names the layer `fc`. It builds an unquantized projection
and then fails to load `fc.weight_scale`.

The shared `map_draft_quant_config` helper in `models/utils.py` maps ModelOpt's
draft settings through the existing weight aliases, module prefix and decoder
layer offset before constructing the layers. Apply this
only to ModelOpt: other backends can use semantic configuration keys or suffix
rules that must not receive a module prefix.

Related work has different scope: [#49900](https://github.com/vllm-project/vllm/pull/49900)
handles `draft_model.` prefixes in another proposer path;
[#53122](https://github.com/vllm-project/vllm/pull/53122) configures draft
quantization aliases and context-KV projection, without this runtime-root and
teacher-layer remapping. No equivalent open PR was found.

+def _pack_fp8_weight(weights: dict[str, torch.Tensor], name: str, algorithm: str):
+    value = weights[f"{name}.weight"].float()
+    per_channel = algorithm == "FP8_PER_CHANNEL_PER_TOKEN"
+    amax = value.abs().amax(dim=1) if per_channel else value.abs().max()
+    scale = amax / torch.finfo(torch.float8_e4m3fn).max
+    divisor = scale[:, None] if per_channel else scale
+    weights[f"{name}.weight"] = (value / divisor).to(torch.float8_e4m3fn)
+    weights[f"{name}.weight_scale"] = scale
+    if not per_channel:
+        weights[f"{name}.input_scale"] = torch.tensor(1.0 / 448)
