## Motivation

In `NixlKVManager.__init__`,

```py
        if self.disaggregation_mode == DisaggregationMode.PREFILL:
            # ...
            for i, queue in enumerate(self.transfer_queues):
                # ...
                threading.Thread(
                    target=self.transfer_worker,
                    args=(queue, staging_buffer),
                    daemon=True,
                ).start()
            self._start_bootstrap_thread()
```
`transfer_worker` runs `self.agent.check_xfer_state` and `_start_bootstrap_thread` runs `self.agent.add_remote_agent`. The two functions run with released GIL and race on `std::unordered_map<std::string, nixlRemoteSection> remoteSections_;` in NIXL `src/core/agent_data.h`.

There is a lock protecting `remoteSections_`, but it requires configuring the agent to use the lock
```cpp
nixlAgentData::nixlAgentData(const std::string &name, const nixlAgentConfig &config)
    : name_(name),
      config_(config),
      useEtcd_(detectEtcd()),
      needsCommThread_(useEtcd_ || config.useListenThread),
      lock(effectiveSyncMode(config.syncMode, needsCommThread_)) {
```
where the `lock` argument decides whether to actually lock. The current config is to set `syncMode` to none, meaning no locking. This results in a data race, which is hard to hit unless you have a large disagg setup. When you do, it may manifest as a segfault

## Modifications

Always use `syncMode = NIXL_THREAD_SYNC_STRICT`.
