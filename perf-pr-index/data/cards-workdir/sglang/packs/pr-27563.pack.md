## PR body
```markdown
## Summary

This PR makes the NIXL disaggregation path work with HiSparse decode KV destinations that live in host memory, and exposes the HiSparse swap-in CUDA launch block size through `--hisparse-config`.

The original failure mode was that decode-side HiSparse advertises host-backed KV transfer buffers, but NIXL still registered those pointers as `VRAM`. This patch carries explicit KV memory-kind metadata (`VRAM` / `DRAM`) through the disaggregation registration and transfer path.

## Code Path Walkthrough

NIXL memory-kind plumbing:

- `KVArgs` now carries `kv_data_mem_kinds` alongside KV pointers.
- Prefill KV buffers remain `VRAM`.
- Decode uses `DRAM` for the HiSparse host KV pool, and keeps `VRAM` for normal dense decode KV.
- NIXL validates memory-kind metadata, registers KV buffers in memory-kind buckets, and uses the matching source/destination kinds when building transfer descriptors.
- DeepSeek V4 mixed-memory HiSparse is handled by segmenting transfers by contiguous `(src_kind, dst_kind)` pairs and using multipart completion notifications.

HiSparse swap-in block size:

- `SparseConfig` now has `swap_in_block_size`, defaulting to `512`.
- `--hisparse-config` parses and validates it as an integer in `[1, 1024]`.
- `ModelRunner` passes it into `HiSparseCoordinator`.
- `HiSparseCoordinator` passes it as the JIT kernel `block_size` for `load_cache_to_device_buffer_mla` and the DSV4 variant.

This was turned into a config instead of another hardcoded constant because the B200 reproducer failed with the previous `1024`-thread launch but passed with `512`, `768`, and `960`; defaulting to `512` keeps the working path while leaving room for platform-specific tuning.
