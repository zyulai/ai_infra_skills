## PR body
```markdown
## Motivation

The Mamba2 SSD Triton kernels were adapted from vLLM without their `@triton.autotune` decorators: sglang's original import (#10988) carried them commented out, and #10909 deleted the commented blocks while re-syncing the ops. The launchers still size their grids from `META["BLOCK_SIZE_*"]`, so every kernel silently ran at its signature default of `BLOCK_SIZE_* = 16` -- a 10x+ loss on the prefill kernels. Upstream vLLM has these decorators live today.

## Modifications

- Restore `@triton.autotune` on `ssd_bmm`, `ssd_chunk_scan`, `ssd_chunk_state` and `ssd_state_passing`. The config lists and keys are verbatim from current `vllm/model_executor/layers/mamba/ops/`, so these blocks stay diffable on the next upstream sync.
- `_chunk_state_varlen_kernel` is sglang-only -- vLLM replaced it with `gather_initial_states.py` driven by `cu_chunk_seqlens` -- so it reuses the `_chunk_state_fwd_kernel` list (same tile-shape family).
- Add `**autotune_cache_kwargs` (the existing sglang FLA idiom, `kernels/ops/attention/fla/utils.py`) so a tuning result survives process restarts instead of being re-measured on every server launch.
- Add `prune_configs_by` / `prune_oversized_tiles`, which caps each `BLOCK_SIZE_*` at `next_power_of_2` of the dimension it tiles. A tile wider than its dimension computes a fully masked remainder over the same grid, so it is dominated. This is the fix for the `test_mamba_ssm_ssd.py` CI timeout -- see below.
- Fix `bench_one_batch` on Mamba models: `selective_state_update` dispatches through a process-global backend that only the Scheduler installs, so every Mamba model died during decode CUDA-graph capture inside `load_model`. It is now initialized from a helper shared by `latency_test` and `correctness_test`, so `--correctness-test` is covered too.

## CI cost

The 30-minute timeout on the previous run was real and caused by this PR. Autotuning is per distinct key, and `test_mamba_ssm_ssd.py` spans many: `_chunk_scan_fwd_kernel` alone sees ~22 keys over the CI-reduced matrix (Triton folds the tensor dtypes into the key on top of `chunk_size`/`hdim`/`dstate`), at 23 configs each -- ~500 compile+bench cycles for one kernel, and ~4x that across all six. A persistent cache does not help here, since the cold pytest process never gets a hit.

The prune collapses the small CI shapes to a handful of configs each (`hdim=5, dstate=5, chunk_size=16` -> 1 config; `hdim=32, dstate=32, chunk_size=8` -> 1), without touching the test matrix.

## Accuracy Tests

Autotuning selects `BLOCK_SIZE_K`, which sets the K-split of the fp32 `tl.dot` accumulation, so output is **not** bit-identical to the `BLOCK_SIZE_* = 16` defaults. `lm_eval` GSM8K (5-shot), Nemotron-3-Ultra-550B-A55B-NVFP4, TP4:

| | main | + autotune |
| --- | ---: | ---: |
| flexible-extract | 0.9401 ± 0.0065 | 0.9409 ± 0.0065 |
| strict-match | 0.9378 ± 0.0067 | 0.9393 ± 0.0066 |
```

```diff
+def _tile_footprint(config: triton.Config) -> tuple[int, int, int]:
+    footprint = 1
+    for block in config.kwargs.values():
+        footprint *= block
+    return footprint, config.num_stages, config.num_warps
+
+
+def prune_oversized_tiles(
+    tiled_dims: Mapping[str, Sequence[str]],
+) -> Callable[..., list[triton.Config]]:
+    """Build an `early_config_prune` that drops tiles wider than what they cover.
+
+    A block larger than the dimension it tiles computes a fully masked remainder
+    for the same grid, so it is dominated; `tiled_dims` maps each BLOCK_SIZE_* to
+    the kernel arguments it strides over, and a block is capped by the smallest.
+    """
+
+    def early_config_prune(configs, named_args, **kwargs):
+        # Triton splits the launch into positional args and kwargs; a dimension
+        # can arrive through either.
+        args = {**kwargs, **named_args}
+        caps = {}
+        for block, dims in tiled_dims.items():
+            cap = triton.next_power_of_2(min(args[dim] for dim in dims))
+            caps[block] = max(cap, min(c.kwargs[block] for c in configs))
+        keep = [
+            config
+            for config in configs
+            if all(config.kwargs[block] <= cap for block, cap in caps.items())
+        ]
+        return keep or [min(configs, key=_tile_footprint)]
+
+    return early_config_prune
```
