## 正文(PR 描述)

## Purpose

Two tests in `tests/entrypoints/openai/test_cli_args.py` asserted incorrect contracts and gave false confidence:

1. `test_enable_auto_choice_fails_with_enable_reasoning` claimed that combining `--enable-auto-tool-choice` with `--reasoning-parser` must fail. However, this combination is **documented as supported** in `docs/features/tool_calling.md` (e.g. `--tool-call-parser hunyuan_a13b --reasoning-parser hunyuan_a13b`), and `validate_parsed_serve_args` correctly does **not** reject it. The test only passed because `--tool-call-parser` was omitted, so it actually triggered the unrelated "auto tool choice requires a tool call parser" check — masking that no reasoning-conflict validation exists (and none should). Rewritten to verify the documented combination passes when a tool call parser is set.

2. `test_enable_auto_choice_passes_without_tool_call_parser` was misnamed: its docstring and body assert that validation *fails*. Renamed to `test_enable_auto_choice_fails_without_tool_call_parser` to match its actual behavior.

This is a test-only change; no runtime behavior is modified.

**Not a duplicate:** searched open PRs for `test_cli_args`, `validate_parsed_serve_args`, and `test_enable_auto_choice` — none touch these tests.
