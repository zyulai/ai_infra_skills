## 正文(PRD / 提案全文)

### Motivation.

The Qwen3.5 series introduces Multi-Token Prediction (MTP) to improve decoding efficiency and reduce inference latency. However, in practical deployments that serve multiple LoRA adapters on top of a shared base model, enabling MTP can lead to noticeable performance degradation compared to the non-MTP path. Specifically, some LoRA adapters experience reduced MTP acceptance rates, resulting in lower speculative decoding efficiency and diminished throughput gains when compared to the base model.

### Proposed Change.

To address this limitation, we propose introducing routing mechanisms that direct requests to dedicated MTP models trained separately from the base MTP model. By allowing multiple specialized MTP models to coexist and serve different LoRA adapters or adapter groups, the system can better preserve MTP acceleration benefits while improving performance and scalability for multi-LoRA deployments. Key components of the change include:

MTP Model Modification: Modify the existing model architecture (vllm/model_executor/models/qwen3_5_mtp.py) , so that the MTP can be dynamically switched in graph mode. Add a new LoRA MTP structure to store the weights and corresponding relationships of the LoRA MTP.

Dynamic Routing: Based on the correspondence between the LoRA request and the LoRA MTP, obtain the specific MTP weights and use them for the forward computation of the draft token.
