## Motivation

Two changes to the NPU test suite:

- Four Qwen3.6 accuracy cases used non-zero sampling temperatures (0.2 / 0.6 / 1.0), which makes their accuracy results depend on sampling. Switch them to greedy decoding so the runs are reproducible, and bound how many evaluations each case may consume.
- The DP attention basic-function case was temporarily disabled for DTS2026091464350. Re-enable it now that the issue is resolved.

Note: the removal of the LLaDA2.0-mini basic-function case that this PR originally carried is no longer part of the change set. Upstream renamed that file to `test_npu_llada2_mini_fdfo.py`, so the old path is already gone from `main` and there is nothing left to delete.

## Modifications

### 1. Set `temperature=0` for four Qwen3.6 accuracy cases

All four are `nightly-acc-2-npu-a3` cases.

### 2. Adjust `max_retries` of the affected accuracy cases

`max_retries` is the number of evalscope evaluations a case performs, not the number of extra retries: the case passes as soon as one evaluation reaches the threshold, and fails after the last one. When it is left unset it defaults to 3 for the datasets listed in `DATASET_FLUCTUATION` (`gpqa_diamond`, `aime25`, `aime26`, `gsm8k`) and to 1 otherwise.

| File | Before | After |
| --- | --- | --- |
| `test/registered/npu/accuracy/qwen3_6_27b/test_npu_qwen3_6_27b_1p_gpqa.py` | 1 | 2 |
| `test/registered/npu/accuracy/qwen3_6_27b/test_npu_qwen3_6_27b_w8a8_1p_in3k5_out1k5_50ms_gpqa.py` | 1 | 2 |
| `test/registered/npu/accuracy/qwen3_6_35b_a3b/test_npu_qwen3_6_35b_a3b_1p_aime26.py` | unset (3) | 2 |
| `test/registered/npu/accuracy/qwen3_6_35b_a3b/test_npu_qwen3_6_35b_a3b_1p_in64k_out1k_prefix90_50ms_aime26.py` | unset (3) | 2 |
| `test/registered/npu/accuracy/kimi_k3/test_npu_kimi_k3_w4a8_32p_gpqa.py` | unset (3) | 1 |

The four Qwen3.6 cases are capped at 2 evaluations so a single unlucky evaluation can still be absorbed without letting the worst case grow; the Kimi-K3 case (32 devices, ~3600 s) is pinned to 1 so it fails fast instead of running the default three evaluations.

### 3. Re-enable the DP attention basic-function case

Remove `disabled="Temporarily disable this test case due to DTS2026091464350"` from the `base-b-test-4-npu-a3` registration in `test/registered/npu/basic_function/dp_attn/test_npu_dp_attention.py`.

## Accuracy Tests

These changes touch accuracy test configurations only - no model, kernel or runtime code is modified.

Validated on `main-cann9.1.0-a3` with a four-partition accuracy job ([Run #36510795245](https://github.com/sgl-project/sglang/actions/runs/36510795245), validated at head `934aa80dd1`; the only commit after it reverts temporary CI plumbing):

| Partition | Case | Model / Dataset | Baseline | Threshold | Accuracy | Retries | Case time | Job time |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| p0 | `test_npu_qwen3_6_27b_w8a8_1p_in3k5_out1k5_50ms_gpqa` | Qwen3.6-27B-w8a8 / gpqa_diamond | 0.878 | 0.8527475 | 0.859 | no | 39m47s | 42m26s |
| p1 | `test_npu_qwen3_6_27b_1p_gpqa` | Qwen3.6-27B / gpqa_diamond | 0.878 | 0.8527475 | 0.879 | no | 35m19s | 38m20s |
| p2 | `test_npu_qwen3_6_35b_a3b_1p_aime26` | Qwen3.6-35B-A3B / aime26 | 0.927 | 0.8603333 | 0.900 | no | 52m23s | 55m22s |
| p3 | `test_npu_qwen3_6_35b_a3b_1p_in64k_out1k_prefix90_50ms_aime26` | Qwen3.6-35B-A3B (in64k/out1k, prefix90) / aime26 | 0.927 | 0.8603333 | 0.900 | no | 20m50s | 23m31s |

All four cases pass with greedy decoding (`temperature = 0`) and unchanged thresholds. Thresholds are derived from the baselines as `baseline - DATASET_FLUCTUATION / question_count` (gpqa_diamond: 5/198, aime26: 2/30).

Note for reviewers: the gpqa_diamond thresholds (baseline 0.878) were measured with the previous temperatures, so they are tight under greedy decoding. In the first attempt of the same run, both gpqa cases fell below the threshold on both attempts (p0: 0.843 then 0.849, p1: 0.849 then 0.833) and only passed after a job re-run (0.859 / 0.879). The spread observed for these two cases under greedy decoding is 0.833 - 0.879, which is around one question on either side of the 169/198 threshold, so the two gpqa thresholds may still need re-baselining.
