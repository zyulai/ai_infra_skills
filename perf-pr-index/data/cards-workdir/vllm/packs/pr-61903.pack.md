## Overview

On H100/H200, `GateLinear` runs fp32 router weights above 32 tokens as `F.linear(x.float(), w)`, an fp32 SGEMM on CUDA cores. SM100 has the CuteDSL BF16x3 kernel for this (#47973, #55899) and gfx950 has a hipBLASLt one (#52668). SM90 had nothing. This PR adds a CuteDSL BF16x3 kernel for SM90 behind the existing BF16x3 tier.

Models on main that hit this path on SM90 (fp32 router weight, bf16 activations): MiniMax-M2/M2.5/M3, GLM-4.5/4.6/4.7 and GLM-4.5-Air, Hunyuan-V3/V4, Step-3.5-Flash, ERNIE-4.5, Ling 2.0 (`router_dtype: fp32`), and others. The new models are on it too. Beam-1.0 (#62074) keeps fp32 router weights `(5120, 256)`, and Muse Spark Open (#61879) keeps `(8192, 256)`. Both shapes are in the fp32 GEMV table since #62042 and #62126, so on H200 every batch above its limit runs the fp32 SGEMM.

The first revision of this PR used Triton. It is now CuteDSL, like the other router GEMMs in the tree, and uses the `VllmJitKernel` warmup contract.

## Claims

- Router GEMM on 1xH200, inside CUDA graphs with cold L2, over 10 router shapes: 1.6-3.8x faster at 33-512 tokens and 3.3-7.7x faster at 1024-16384 tokens.
- MAE against an fp64 reference is 0.16-0.73x that of the fp32 SGEMM it replaces, at every shape and token count measured.
- MiniMax-M2.5 FP8, TP2 on 2xH200, with main and PR alternating in one container: TTFT 3-5% lower for 8K and 32K prompts, prefill throughput 4-6% higher, and on a mixed 1K-in/128-out workload 4.6% more output tokens/s and 4% lower TPOT. GSM8K accuracy is unchanged and its wall time is 2.5% lower.
- In eager mode one router call costs 17-18 µs of host time, against 21-36 µs on main.
- Beam-1.0 FP8 on one H200, as one TP8 rank (all 52 layers, dummy weights, main and PR alternating): an 8K prefill chunk takes 14.0% less time (155.3 to 133.5 ms), and a decode step at 64 and 128 requests takes 7.4% and 10.9% less.
- On SM90 the fp32 GEMV now runs up to 24 tokens instead of 32, where the new kernel is faster. The GB200 rule for `(5120, 256)` from #62042 and the B300 rule for `(4096, 352)` from #61727 stay Blackwell-only.
- No change for 24 or fewer tokens on the fp32 GEMV shapes, under `VLLM_BATCH_INVARIANT`, or on other architectures.

```python
"""PR component benchmark: SM90 router GEMM for fp32 gate weights, main vs this PR (1xH200).

main: F.linear(x.float(), W) for M > 32 (fp32 SGEMM). PR: torch.ops.vllm.sm90_bf16x3_router_gemm.
Each number is the per-call time inside one CUDA graph that replays the op on N rotating copies of
(x, W) whose footprint is >= 4x L2, so every call starts with cold weights. MAE is against fp64.
"""

import json
import os
import statistics

import torch

import vllm.model_executor.layers.fused_moe.router.bf16x3_router_gemm_sm90  # noqa: F401

torch.set_float32_matmul_precision("highest")
dev = torch.device("cuda")
L2_BYTES = torch.cuda.get_device_properties(dev).L2_cache_size
print("device", torch.cuda.get_device_name(), "torch", torch.__version__, flush=True)

SHAPES = {
    "MiniMax-M2/M2.5": (3072, 256),
    "MiniMax-M3": (6144, 128),
    "GLM-4.5/4.6/4.7": (5120, 160),
    "GLM-4.5-Air": (4096, 128),
    "Hunyuan-V3": (4096, 192),
    "Hunyuan-V4": (2816, 256),
    "Step-3.5-Flash": (4096, 288),
    "Ling-flash-2.0": (4096, 256),
    "ERNIE-4.5-300B": (8192, 64),
    "Step-5": (4096, 352),
}
MS = [int(m) for m in os.environ.get("MS", "33,64,128,256,512,1024,2048,4096,8192,16384").split(",")]
SCALE = 0.053


def graph_time_us(fns, reps=7):
    for f in fns:
        f()
    torch.cuda.synchronize()
    g = torch.cuda.CUDAGraph()
    with torch.cuda.graph(g):
        for f in fns:
            f()
    g.replay()
    torch.cuda.synchronize()
    times = []
    for _ in range(reps):
        s = torch.cuda.Event(enable_timing=True)
        t = torch.cuda.Event(enable_timing=True)
        s.record()
        g.replay()
        t.record()
        t.synchronize()
        times.append(s.elapsed_time(t) * 1000 / len(fns))
    return statistics.median(times)


def mae(out, ref):
    return (out.double() - ref).abs().mean().item()


def main_path(x, w):
    return torch.nn.functional.linear(x.float(), w)


def pr_path(x, w):
    return torch.ops.vllm.sm90_bf16x3_router_gemm(x, w)


rows = []
for name, (k, e) in SHAPES.items():
    gen = torch.Generator(device=dev).manual_seed(0)
    for m in MS:
        nc = int(min(64, max(4, -(-4 * L2_BYTES // (m * k * 2 + e * k * 4)))))
        xs = [torch.randn(m, k, generator=gen, device=dev).to(torch.bfloat16) for _ in range(nc)]
        ws = [torch.randn(e, k, generator=gen, device=dev) * SCALE for _ in range(nc)]
        ref = xs[0].double() @ ws[0].double().T
        row = {"model": name, "K": k, "E": e, "M": m}
        for label, fn in (("main", main_path), ("pr", pr_path)):
            row[f"{label}_us"] = round(graph_time_us([lambda i=i: fn(xs[i], ws[i]) for i in range(nc)]), 2)
            row[f"{label}_mae"] = mae(fn(xs[0], ws[0]), ref)
        row["speedup"] = round(row["main_us"] / row["pr_us"], 2)
        rows.append(row)
        print(json.dumps(row), flush=True)
        del xs, ws
        torch.cuda.empty_cache()

os.makedirs("control/artifacts", exist_ok=True)
with open("control/artifacts/pr_component.json", "w") as f:
    json.dump({"device": torch.cuda.get_device_name(), "torch": torch.__version__, "rows": rows}, f, indent=1)
```

## Details

**Kernel.** The MMA runs swapped: 64 experts form the wgmma M dimension and tokens the N dimension (32 to 128 per CTA), so small batches still fill the instruction. One TMA warp brings fp32 weight tiles and bf16 token tiles into shared memory. The MMA warpgroup reads each k16 slice of its weight fragment as fp32 and splits it in registers into three bf16 terms. Each term keeps the top 16 bits of what is left, so the three terms sum back to the weight bit for bit. It then issues register-A wgmma against the token tile, and splits the next slice while the current one runs. Products with bf16 activations are exact in fp32, so all error comes from accumulation:
- The first-term products go to a tensor-core partial that starts from zero every K-tile (64 or 128 wide). It is then added into an fp32 register accumulator.
- The second and third terms are about 2^-8 of the output. They keep their own partial across K, as the SM100 kernel does. This is the one numerical change from the Triton revision, which promoted all three terms every K-tile. It makes the largest tiles up to 9% faster. The worst MAE in my checks is 0.87x of the fp32 SGEMM's (GLM-4.7 shape, 7 tokens).

Split-K uses a thread-block cluster of up to 8 CTAs. Each CTA writes its partial tile to its own shared memory, reusing the weight stages, and after a cluster barrier sums one slice of the tile over all peers through DSMEM, in rank order. Results are deterministic, and there is no workspace and no second kernel. There is no host sync and no data-dependent shape, so the op is safe to capture in CUDA graphs.

**Configs.** There is no autotuning. `_pick_config` scores 4 tiles x 4 splits with a fixed cost model: waves times per-CTA time. A wave is one CTA per SM, and clusters of 4 or 8 only fill 15/16 of the SMs (120 of 132; at one CTA per SM, `cuOccupancyMaxActiveClusters` gives 30 clusters of 4 and 15 of 8 on H200). The per-tile costs were fitted to H200 timings. Over 10 shapes and 14 token counts, the rule is within 0.1% (geomean) of the fastest of the 16 configs per cell, and at most 4% slower. Each of the 10 shapes reaches 9-13 configs between 1 and 16384 tokens, at about 1 s of compile each.

**Warmup.** The kernel is a `VllmCuTeDSLJitKernel`. `GateLinear` registers it with its `(K, E)` and `max_num_batched_tokens`, as it does for `ll_fp32w` and as #50177 does for SM100. Warmup traces `dispatch` over 1..max tokens and compiles each key from fake tensors, with no launch. In the end-to-end runs above, the PR arm warmed 13 keys in about 10.5 s at startup. The JIT monitor logged no compile of this kernel while serving; it logged two `fused_moe_kernel` Triton compiles on both arms.

**Host overhead.** Outside CUDA graphs (mixed prefill/decode batches above the capture sizes), the host cost per call matters as much as the kernel. `_pick_config` is cached, and the launch is one TVM-FFI call. Eager host time per call on an idle H200 host:

**Integration.**
- `allow_bf16x3_router_gemm` is now also true on SM90, with the same `K % 8 == 0` condition as SM100. `bf16x3_router_gemm_module()` returns the SM90 module on SM90 and the SM100 module otherwise. The fp32-GEMV dispatch op and tier 4 use it.
- In the fp32-GEMV dispatch op, SM90 bf16 inputs use the fp32 GEMV up to 24 tokens. The `(5120, 256)` GB200 rule from #62042 and the `(4096, 352)` B300 rule from #61727 are in the non-SM90 branch unchanged.
- `bf16x3_router_gemm_cutedsl.py` is renamed to `bf16x3_router_gemm_sm100.py`, next to `bf16x3_router_gemm_sm90.py`.
- The kernel is the custom op `torch.ops.vllm.sm90_bf16x3_router_gemm`, as #55899 does for SM100. The fp32-GEMV shapes keep dispatching on the runtime token count inside `fp32_router_gemm_dispatch`.
- PDL is always on. SM90 supports it.

**Alternatives measured on H200.**
- The Triton revision of this PR. This kernel is 1.25x faster (geomean over 10 shapes and 15 token counts). It is slower only for ERNIE-4.5 (E=64) at 128 or fewer tokens, where 9.6 µs vs 7.2 µs: one 64-expert tile and at most 8 splits leave most SMs idle. It is still 1.55x faster than main there.
- One cuBLAS GEMM over the stacked `(3E, K)` bf16 weight, which is what gfx950 does: MAE 1.4e-6 to 4.3e-6 for the Step-5 shape, worse than the fp32 SGEMM's 3-5e-7.
- A round-to-nearest split, like the SM100 kernel's but without `sub.rn.f32x2` (sm_100 only): 0.5-4% slower than the truncating split at 64-8192 tokens on the Step-5, Beam-1.0, MiniMax-M2.5 and Muse shapes. Both MAEs are well below the fp32 SGEMM's. The other way round, the truncating split in the SM100 kernel on B200 is 0.1-2.3% slower than its own split on the same shapes, so each kernel keeps its own.
- Two bf16 terms (BF16x2): 16 of fp32's 24 significand bits. Even with exact accumulation, that alone gives an MAE of 5.7e-6 to 7.4e-6 at 1024 tokens on the Step-5, Beam-1.0 and MiniMax-M2.5 shapes, against 0.8e-6 to 1.4e-6 for the fp32 SGEMM.
- A pre-split weight kept in memory: needs 1.5x the fp32 router weight per layer (about 760 MB per rank for 88 layers of Step-5). The in-register split needs no extra memory.
- One promoted partial for all three terms per k16 slice, instead of keeping the small terms apart: MAE rose above the fp32 SGEMM's at 33 tokens.
- Two MMA warpgroups per CTA, along the experts or along the tokens (up to 4): not faster than the selected configs in my sweeps.

**Limitations.**
- With one token, cuBLAS's fp32 GEMV is more accurate than this kernel for 3 of the 10 shapes (for example MiniMax-M3: MAE 3.1e-7 vs 4.7e-7). From 2 tokens up, all 10 shapes beat it. In eager mode those batches stay on the fp32 GEMV or `ll_fp32w`. The test starts at 8 tokens.
- As on SM100, generic shapes reach tier 4 through tier 3's Python check on `x.shape[0]`. Under vLLM's guard-free `torch.compile`, that branch can be fixed at the first traced size, the issue #60681 fixes for tier 1. Small batches of those shapes may then run this kernel, which is still faster than the `F.linear` path main would freeze.
- The cost model was fitted on H200 (132 SMs). Other SM90 parts get correct results and an SM-count-aware choice, but the choice may not be the fastest.
- #61727 lowers the fp32 GEMV cutoff for Step-5 to 11 tokens when `allow_bf16x3_router_gemm` is set, based on B300. On H200 the fp32 GEMV is still faster at 16 tokens for that shape, so that rule belongs in the non-SM90 branch next to the GB200 one.
- The Beam-1.0 numbers come from a one-rank proxy with dummy weights. A full TP8 run needs #62074 merged and 8xH200.

+        "and.b32 n0, r0, 0xffff0000;\n\t"
+        "and.b32 n1, r1, 0xffff0000;\n\t"
+        "sub.f32 l0, r0, n0;\n\t"
+        "sub.f32 l1, r1, n1;\n\t"
+        "prmt.b32 $1, r0, r1, 0x7632;\n\t"
+        "prmt.b32 $2, l0, l1, 0x7632;\n\t"
+        "}\n",
+        "=r,=r,=r,f,f",
+        has_side_effects=False,
+        is_align_stack=False,
+        loc=loc,
+        ip=ip,
+    )
+    return (
+        Uint32(llvm.extractvalue(T.i32(), out, [0], loc=loc, ip=ip)),
+        Uint32(llvm.extractvalue(T.i32(), out, [1], loc=loc, ip=ip)),
+        Uint32(llvm.extractvalue(T.i32(), out, [2], loc=loc, ip=ip)),
+    )
+
+
+@dsl_user_op
+def _ld_dsmem_v4_f32(smem_ptr, peer_rank: Int32, *, loc=None, ip=None):
+    """Load four fp32 at the same shared-memory offset of a cluster peer."""
+    addr = Int32(
+        cute.arch.map_dsmem_ptr(smem_ptr, peer_rank, loc=loc, ip=ip).toint(
+            loc=loc, ip=ip
+        )
+    )
+    out = llvm.inline_asm(
+        llvm.StructType.get_literal([T.f32(), T.f32(), T.f32(), T.f32()]),
+        [addr.ir_value(loc=loc, ip=ip)],
+        "ld.shared::cluster.v4.f32 {$0, $1, $2, $3}, [$4];",
+        "=f,=f,=f,=f,r",
+        has_side_effects=True,
+        is_align_stack=False,
+        loc=loc,
+        ip=ip,
+    )
+    return tuple(
+        Float32(llvm.extractvalue(T.f32(), out, [i], loc=loc, ip=ip)) for i in range(4)
+    )
+

+class _Sm90BF16x3RouterGemm:
+    """One MMA warpgroup (64 experts x block_t tokens) and one TMA warp."""
+
+    def __init__(
+        self,
+        block_t: int,
+        block_k: int,
+        num_stages: int,
+        split_k: int,
+    ) -> None:
+        # Slices alternate between two register buffers, so a K-tile holds an
+        # even number of k16 slices.
+        assert block_k in (64, 128)
+        assert block_t % 8 == 0 and block_t <= 256
+        # Portable cluster sizes; every split reduces whole float4 chunks.
+        assert split_k in (1, 2, 4, 8)
+        assert _BLOCK_E * block_t % (4 * split_k) == 0
+        self.block_t = block_t
+        self.block_k = block_k
+        self.num_stages = num_stages
+        self.split_k = split_k
+        self.num_mma_threads = 128
+        self.producer_warp = 4  # after the MMA warpgroup, which must be aligned
+        self.threads = self.num_mma_threads + 32
+
+    @cute.jit
+    def __call__(
+        self,
+        mX: cute.Tensor,
+        mW: cute.Tensor,
+        mOut: cute.Tensor,
+        stream: CUstream,
+    ):
+        bE, bT, bK = _BLOCK_E, self.block_t, self.block_k
+        tiled_mma = sm90_utils.make_trivial_tiled_mma(
+            BFloat16,
+            BFloat16,
+            warpgroup.OperandMajorMode.K,
+            warpgroup.OperandMajorMode.K,
+            Float32,
+            (1, 1, 1),
+            (bE, bT),
+            warpgroup.OperandSource.RMEM,
+        )
+        w_layout = sm90_utils.make_smem_layout_a(
+            utils.LayoutEnum.ROW_MAJOR, (bE, bT, bK), Float32, self.num_stages
+        )
+        x_layout = sm90_utils.make_smem_layout_b(
+            utils.LayoutEnum.ROW_MAJOR, (bE, bT, bK), BFloat16, self.num_stages
+        )
+        tma_w, mW_tma = cpasync.make_tiled_tma_atom(
+            cpasync.CopyBulkTensorTileG2SOp(),
+            mW,
+            cute.slice_(w_layout, (None, None, 0)),
+            (bE, bK),
+        )
+        tma_x, mX_tma = cpasync.make_tiled_tma_atom(
+            cpasync.CopyBulkTensorTileG2SOp(),
+            mX,
+            cute.slice_(x_layout, (None, None, 0)),
+            (bT, bK),
+        )
+        # The split-K partial tile reuses the weight stages after the mainloop.
+        assert self.split_k == 1 or cute.cosize(w_layout) >= bE * bT
+        if const_expr(isinstance(mW.shape[1], int)):
+            assert self.split_k <= cute.ceil_div(mW.shape[1], bK)
+
+        @cute.struct
+        class SharedStorage:
+            mbar: cute.struct.MemRange[cutlass.Int64, self.num_stages * 2]
+            sW: cute.struct.Align[
+                cute.struct.MemRange[Float32, cute.cosize(w_layout)], 1024
+            ]
+            sX: cute.struct.Align[
+                cute.struct.MemRange[BFloat16, cute.cosize(x_layout)], 1024
+            ]
+
+        self.shared_storage = SharedStorage
+        self.kernel(
+            tma_w, mW_tma, tma_x, mX_tma, mOut, tiled_mma, w_layout, x_layout
+        ).launch(
+            grid=[
+                cute.ceil_div(mW.shape[0], bE),
+                cute.ceil_div(mX.shape[0], bT),
+                self.split_k,
+            ],
+            block=[self.threads, 1, 1],
+            cluster=[1, 1, self.split_k],
+            stream=stream,
+            use_pdl=True,
+        )
+
+    @cute.jit
+    def _split_slice(
+        self,
+        sW_slice: cute.Tensor,
+        rW: cute.Tensor,
+        w_hi: cute.Tensor,
+        w_mid: cute.Tensor,
+        w_lo: cute.Tensor,
+    ):
+        """Read one k16 slice of the fp32 weight fragment and split it."""
+        cute.autovec_copy(sW_slice, rW)
+        hi = cute.recast_tensor(w_hi, Uint32)
+        mid = cute.recast_tensor(w_mid, Uint32)
+        lo = cute.recast_tensor(w_lo, Uint32)
+        for i in cutlass.range_constexpr(cute.size(rW) // 2):
+            terms = _split_fp32x2_to_3xbf16x2(rW[2 * i], rW[2 * i + 1])
+            hi[i] = terms[0]
+            mid[i] = terms[1]
+            lo[i] = terms[2]
+
+    @cute.jit
+    def _tile_mma(
+        self,
+        tiled_mma: cute.TiledMma,
+        acc_hi: cute.Tensor,
+        acc_res: cute.Tensor,
+        rW: cute.Tensor,
+        hi0: cute.Tensor,
+        mid0: cute.Tensor,
+        lo0: cute.Tensor,
+        hi1: cute.Tensor,
+        mid1: cute.Tensor,
+        lo1: cute.Tensor,
+        tCsW: cute.Tensor,
+        tCrX: cute.Tensor,
+    ):
+        """Issue every k16 slice of one K-tile.
+
+        Slice kb uses register buffer kb % 2; the caller has split slice 0. The
+        next slice is split while the current one runs, and the last slice is
+        left in flight so the caller can prepare the next K-tile.
+        """
+        num_kb = cute.size(tCsW, mode=[2])
+        bufs = [(hi0, mid0, lo0), (hi1, mid1, lo1)]
+        for kb in cutlass.range_constexpr(num_kb):
+            w_hi, w_mid, w_lo = bufs[kb % 2]
+            x_slice = tCrX[(None, None, kb)]
+            warpgroup.fence()
+            tiled_mma.set(warpgroup.Field.ACCUMULATE, True)
+            cute.gemm(tiled_mma, acc_res, w_lo, x_slice, acc_res)
+            cute.gemm(tiled_mma, acc_res, w_mid, x_slice, acc_res)
+            tiled_mma.set(warpgroup.Field.ACCUMULATE, kb != 0)
+            cute.gemm(tiled_mma, acc_hi, w_hi, x_slice, acc_hi)
+            warpgroup.commit_group()
+            if const_expr(kb + 1 < num_kb):
+                # Slice kb - 1 is done, so its buffer can take slice kb + 1.
+                warpgroup.wait_group(1)
+                n_hi, n_mid, n_lo = bufs[(kb + 1) % 2]
+                self._split_slice(tCsW[(None, None, kb + 1)], rW, n_hi, n_mid, n_lo)
+        return tiled_mma
+
+    @cute.jit
+    def _advance(self, state: pipeline.PipelineState):
+        # A fresh state keeps it a plain local across staged control flow.
+        state = state.clone()
+        state.advance()
+        return state
+
+    @cute.jit
+    def _add(self, acc: cute.Tensor, part: cute.Tensor):
+        for i in cutlass.range_constexpr(cute.size(acc)):
+            acc[i] = acc[i] + part[i]
+
+    @cute.kernel
+    def kernel(
+        self,
+        tma_w: cute.CopyAtom,
+        mW: cute.Tensor,
+        tma_x: cute.CopyAtom,
+        mX: cute.Tensor,
+        mOut: cute.Tensor,
+        tiled_mma: cute.TiledMma,
+        w_layout: cute.ComposedLayout,
+        x_layout: cute.ComposedLayout,
+    ):
+        bE, bT, bK = _BLOCK_E, self.block_t, self.block_k
+        tidx, _, _ = cute.arch.thread_idx()
+        bid_e, bid_t, bid_s = cute.arch.block_idx()
+        warp_idx = cute.arch.make_warp_uniform(cute.arch.warp_idx())
+
+        smem = cutlass.utils.SmemAllocator()
+        storage = smem.allocate(self.shared_storage)
+        tx_bytes = cute.size_in_bytes(
+            Float32, cute.slice_(w_layout, (None, None, 0))
+        ) + cute.size_in_bytes(BFloat16, cute.slice_(x_layout, (None, None, 0)))
+        mainloop = pipeline.PipelineTmaAsync.create(
+            barrier_storage=storage.mbar.data_ptr(),
+            num_stages=self.num_stages,
+            producer_group=pipeline.CooperativeGroup(pipeline.Agent.Thread),
+            consumer_group=pipeline.CooperativeGroup(pipeline.Agent.Thread, 4),
+            tx_count=tx_bytes,
+            cta_layout_vmnk=cute.make_layout((1, 1, 1, 1)),
+            defer_sync=True,
+        )
+        pipeline_init_arrive(cluster_shape_mn=(1, 1), is_relaxed=True)
+
+        sW = storage.sW.get_tensor(w_layout.outer, swizzle=w_layout.inner)
+        sX = storage.sX.get_tensor(x_layout.outer, swizzle=x_layout.inner)
+        gW = cute.local_tile(mW, (bE, bK), (bid_e, None))  # (bE, bK, k_tiles)
+        gX = cute.local_tile(mX, (bT, bK), (bid_t, None))  # (bT, bK, k_tiles)
+        tWsW, tWgW = cpasync.tma_partition(
+            tma_w,
+            0,
+            cute.make_layout(1),
+            cute.group_modes(sW, 0, 2),
+            cute.group_modes(gW, 0, 2),
+        )
+        tXsX, tXgX = cpasync.tma_partition(
+            tma_x,
+            0,
+            cute.make_layout(1),
+            cute.group_modes(sX, 0, 2),
+            cute.group_modes(gX, 0, 2),
+        )
+        # Even K-tile ranges; the host keeps split_k <= k_tiles, so none is empty.
+        k_tiles = cute.size(gW, mode=[2])
+        k_begin = bid_s * k_tiles // self.split_k
+        k_end = (bid_s + 1) * k_tiles // self.split_k
+        pipeline_init_wait(cluster_shape_mn=(1, 1))
+        cute.arch.griddepcontrol_wait()
+
+        if warp_idx == self.producer_warp:
+            cpasync.prefetch_descriptor(tma_w)
+            cpasync.prefetch_descriptor(tma_x)
+            state = pipeline.make_pipeline_state(
+                pipeline.PipelineUserType.Producer, self.num_stages
+            )
+            for kt in range(k_begin, k_end):
+                mainloop.producer_acquire(state)
+                bar = mainloop.producer_get_barrier(state)
+                cute.copy(
+                    tma_w, tWgW[(None, kt)], tWsW[(None, state.index)], tma_bar_ptr=bar
+                )
+                cute.copy(
+                    tma_x, tXgX[(None, kt)], tXsX[(None, state.index)], tma_bar_ptr=bar
+                )
+                mainloop.producer_commit(state)
+                state.advance()
+            mainloop.producer_tail(state)
+
+        if warp_idx < self.producer_warp:
+            thr_mma = tiled_mma.get_slice(tidx)
+            tCsW = thr_mma.partition_A(sW)  # fp32 view in A-fragment order
+            tCrX = tiled_mma.make_fragment_B(thr_mma.partition_B(sX))
+            a_shape = tCsW[(None, None, 0, 0)].shape
+            rW = cute.make_rmem_tensor(a_shape, Float32)
+            hi0 = cute.make_rmem_tensor(a_shape, BFloat16)
+            mid0 = cute.make_rmem_tensor(a_shape, BFloat16)
+            lo0 = cute.make_rmem_tensor(a_shape, BFloat16)
+            hi1 = cute.make_rmem_tensor(a_shape, BFloat16)
+            mid1 = cute.make_rmem_tensor(a_shape, BFloat16)
+            lo1 = cute.make_rmem_tensor(a_shape, BFloat16)
+
+            # The accumulator holds out^T [E, M]; view the output that way.
+            num_t, num_e = mOut.shape
+            mOutT = cute.make_tensor(
+                mOut.iterator, cute.make_layout((num_e, num_t), stride=(1, num_e))
+            )
+            tCgOut = thr_mma.partition_C(
+                cute.local_tile(mOutT, (bE, bT), (bid_e, bid_t))
+            )
+            tCcOut = thr_mma.partition_C(
+                cute.local_tile(
+                    cute.make_identity_tensor(mOutT.shape), (bE, bT), (bid_e, bid_t)
+                )
+            )
+            acc = cute.make_rmem_tensor(tCgOut.shape, Float32)
+            acc_hi = cute.make_rmem_tensor(tCgOut.shape, Float32)
+            acc_res = cute.make_rmem_tensor(tCgOut.shape, Float32)
+            acc.fill(0.0)
+            acc_res.fill(0.0)
+
+            read_state = pipeline.make_pipeline_state(
+                pipeline.PipelineUserType.Consumer, self.num_stages
+            )
+            release_state = pipeline.make_pipeline_state(
+                pipeline.PipelineUserType.Consumer, self.num_stages
+            )
+            mainloop.consumer_wait(read_state)
+            stage = read_state.index
+            read_state = self._advance(read_state)
+            self._split_slice(tCsW[(None, None, 0, stage)], rW, hi0, mid0, lo0)
+            for _ in range(k_end - k_begin - 1):
+                tiled_mma = self._tile_mma(
+                    tiled_mma,
+                    acc_hi,
+                    acc_res,
+                    rW,
+                    hi0,
+                    mid0,
+                    lo0,
+                    hi1,
+                    mid1,
+                    lo1,
+                    tCsW[(None, None, None, stage)],
+                    tCrX[(None, None, None, stage)],
+                )
+                # Split the next K-tile's first slice while this tile's last
+                # slice runs, then promote this tile's first-term partial.
+                warpgroup.wait_group(1)
+                mainloop.consumer_wait(read_state)
+                next_stage = read_state.index
+                read_state = self._advance(read_state)
+                self._split_slice(tCsW[(None, None, 0, next_stage)], rW, hi0, mid0, lo0)
+                warpgroup.wait_group(0)
+                mainloop.consumer_release(release_state)
+                release_state = self._advance(release_state)
+                self._add(acc, acc_hi)
+                stage = next_stage
+            tiled_mma = self._tile_mma(
+                tiled_mma,
+                acc_hi,
+                acc_res,
+                rW,
+                hi0,
+                mid0,
+                lo0,
+                hi1,
+                mid1,
+                lo1,
+                tCsW[(None, None, None, stage)],
+                tCrX[(None, None, None, stage)],
+            )
+            warpgroup.wait_group(0)
+            mainloop.consumer_release(release_state)
+            self._add(acc, acc_hi)
+            self._add(acc, acc_res)
+
+            if const_expr(self.split_k == 1):
+                for i in cutlass.range_constexpr(cute.size(acc)):
+                    if cute.elem_less(tCcOut[i], mOutT.shape):
+                        tCgOut[i] = acc[i]
+            else:
+                # Partial tile, expert-contiguous, for the cluster reduction.
+                sRed = cute.make_tensor(
+                    storage.sW.data_ptr(), cute.make_layout((bE, bT), stride=(1, bE))
+                )
+                tCsRed = thr_mma.partition_C(sRed)
+                for i in cutlass.range_constexpr(cute.size(acc)):
+                    tCsRed[i] = acc[i]
+
+        if const_expr(self.split_k > 1):
+            # Each CTA sums one chunk of the tile over all peers, in rank order.
+            # The second barrier keeps every CTA's smem alive until its peers
+            # have read it.
+            cute.arch.cluster_arrive()
+            cute.arch.cluster_wait()
+            if warp_idx < self.producer_warp:
+                rank = cute.arch.block_idx_in_cluster()
+                chunk = bE * bT // self.split_k
+                red_base = storage.sW.data_ptr()
+                num_t, num_e = mOut.shape
+                for v in cutlass.range_constexpr(
+                    (chunk // 4 + self.num_mma_threads - 1) // self.num_mma_threads
+                ):
+                    local = (v * self.num_mma_threads + tidx) * 4
+                    if local < chunk:
+                        idx = rank * chunk + local
+                        s0 = Float32(0.0)
+                        s1 = Float32(0.0)
+                        s2 = Float32(0.0)
+                        s3 = Float32(0.0)
+                        for peer in cutlass.range_constexpr(self.split_k):
+                            a0, a1, a2, a3 = _ld_dsmem_v4_f32(
+                                red_base + idx, Int32(peer)
+                            )
+                            s0 = s0 + a0
+                            s1 = s1 + a1
+                            s2 = s2 + a2
+                            s3 = s3 + a3
+                        e = bid_e * bE + idx % bE
+                        t = bid_t * bT + idx // bE
+                        if t < num_t:
+                            if e < num_e:
+                                mOut[t, e] = s0
+                            if e + 1 < num_e:
+                                mOut[t, e + 1] = s1
+                            if e + 2 < num_e:
+                                mOut[t, e + 2] = s2
+                            if e + 3 < num_e:
+                                mOut[t, e + 3] = s3
+            cute.arch.cluster_arrive()
+            cute.arch.cluster_wait()
+
+        cute.arch.griddepcontrol_launch_dependents()
+
+
+# Candidate tiles as (block_t, block_k, num_stages) -> (fixed_us, us_per_k64):
+# the time of one CTA running alone on an SM, fitted to cold-L2 CUDA-graph
+# timings on H200. Every tile is offered with split_k 1, 2, 4 and 8.
+_TILE_COST = {
+    (32, 128, 3): (3.72, 0.383),
+    (64, 64, 4): (4.18, 0.475),
+    (96, 128, 2): (5.11, 0.513),
+    (128, 128, 2): (5.88, 0.568),
+}
+
+
+@cache
+def _pick_config(num_tokens: int, K: int, E: int, num_sms: int) -> tuple:
+    """Return the (block_t, block_k, num_stages, split_k) with the lowest
+    estimated time: waves times the per-CTA time.
+
+    A wave is one CTA per SM. Clusters of 4 or 8 CTAs only fill 15/16 of the
+    SMs, which on H100/H200 is 120 of 132.
+    """
+    e_tiles = math.ceil(E / _BLOCK_E)
+    best = None
+    for tile, (fixed_us, us_per_k64) in _TILE_COST.items():
+        block_t, block_k, num_stages = tile
+        k_tiles = math.ceil(K / block_k)
+        for split_k in (1, 2, 4, 8):
+            if split_k > k_tiles:
+                continue
+            slots = num_sms if split_k <= 2 else num_sms * 15 // 16 // split_k * split_k
+            ctas = e_tiles * math.ceil(num_tokens / block_t) * split_k
+            k64_per_cta = math.ceil(k_tiles / split_k) * block_k // 64
+            cost = math.ceil(ctas / slots) * (fixed_us + us_per_k64 * k64_per_cta)
+            if best is None or cost < best[0]:
+                best = (cost, (block_t, block_k, num_stages, split_k))
+    assert best is not None
+    return best[1]
+

+    VllmCuTeDSLJitKernel["Sm90BF16x3RouterGemmKernel.CompileKey"]

+        k: int
+        block_t: int
+        block_k: int
+        num_stages: int
+        split_k: int

+    def kernel(compile_key: CompileKey) -> Any:

+            block_k=compile_key.block_k,

+        num_tokens: int,
+        K: int,
+        E: int,

+    ) -> CompileKey:

+            num_tokens=M,

+            E=E,
+            num_sms=num_compute_units(x.device.index),
