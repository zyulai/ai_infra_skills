## 正文(PR 描述)

## Purpose

Fix `AttributeError: 'list' object has no attribute 'zero_'` when calling `/wake_up` after `/sleep` on hybrid models that use Mamba, DeltaNet, or other `MambaSpec`-based layers with quantized KV cache.

Fixes #41564

## Root Cause

`init_fp8_kv_scales()` (called via `post_kv_cache_wake_up()` → `wake_up()`) iterates `self.kv_caches` and calls `.zero_()` on each entry, assuming every entry is a `torch.Tensor`:

```python
for cache_tensor in kv_caches:
    if cache_tensor is not None:
        cache_tensor.zero_()
```

But for hybrid models, `MambaSpec` layers store their per-layer state as a **list of tensors** rather than a single tensor (see `_initialize_kv_cache_tensors`, L6717–6740):

```python
elif isinstance(kv_cache_spec, MambaSpec):
    state_tensors = []
    ...
    kv_caches[layer_name] = state_tensors  # list, not tensor
```

These lists are appended to `self.kv_caches` via `bind_kv_cache()`. So `self.kv_caches` contains a mix of `torch.Tensor` (attention layers) and `list[torch.Tensor]` (Mamba/DeltaNet layers). When the loop hits a list, `.zero_()` fails.

**Why Gemma-4 survives:** It uses pure interleaved SWA (all `FullAttentionSpec`/`SlidingWindowSpec`), so every `kv_caches` entry is a tensor.

## Approach

Check whether each entry is a list or a tensor and handle both:

```python
for cache_entry in kv_caches:
    if cache_entry is None:
        continue
    if isinstance(cache_entry, list):
        for t in cache_entry:
            t.zero_()
    else:
        cache_entry.zero_()
```
