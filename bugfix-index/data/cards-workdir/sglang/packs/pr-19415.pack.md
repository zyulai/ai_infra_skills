## 正文(PR 描述)

When using `--mamba-scheduler-strategy extra_buffer` with EAGLE speculative decoding, mamba_track_mask and mamba_track_seqlens were never reset after prepare_for_extend(). This caused an illegal GPU memory access during the TARGET_VERIFY phase.

Root cause:
- `prepare_for_extend() `sets all three Mamba tracking fields with values sized for the full prefill sequence (e.g. 1000 tokens).
- `prepare_for_decode()` early-returns for speculative decoding, leaving all three fields untouched.
- ` prepare_for_verify()` correctly updates mamba_track_indices to the ping-pong slot indices, but left mamba_track_mask and `mamba_track_seqlens` stale.
- During TARGET_VERIFY, `_track_mamba_state_extend()` uses the stale `mamba_track_mask` to index into h, which only has `draft_token_num` rows (typically 5-7). The stale indices (e.g. 512, 576, ...) are far out of bounds, causing cudaErrorIllegalAddress and a segfault.

Fix:
Explicitly set `batch.mamba_track_mask = None` and `batch.mamba_track_seqlens = None` in `prepare_for_verify()`, _since TARGET_VERIFY does not need prefix-cache Mamba state tracking._
