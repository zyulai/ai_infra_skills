# Context
Currently, adaptive verification (AV) is only enabled for DSpark speculators that have a confidence head. This PR enables it for ALL draft-model-based speculator types (MTP, EAGLE3, DFlash 1&2), including DSpark when a confidence head is not available.

NOTE: The attention backend(s) of the base model must still support variable length verification, which is the existing prerequisite for DSpark AV. This PR depends on #52992, which extends that support to the backends used here (Inkling sconv / rel-attention, FLASH_ATTN, FLASH_ATTN_MLA). All benchmarks below were captured with it applied.

# This PR
This PR implements an online acceptance estimator that learns to predict acceptance probabilities for draft tokens using the draft's logits. AV now works for DFlash, DFlash2, MTP, and any other draft-model speculator, provided that the attention backend(s) of the base model supports variable length verification.

The feature used is `logit(q_max)`, the log-odds of the draft distribution's most likely token.

# How it works

For each drafted token the estimator fits a per-position logistic regression

```
p_accept(k) = sigmoid(w * logit(q_max) + b[k])
```

where `q_max` is the draft model's probability of its most likely token, `w` is a slope shared across draft positions, and `b[k]` is a per-position intercept. Both are refit continuously during serving.

**Prediction happens during draft sampling.** `sample_draft` already materializes the draft logits in order to draw a token, so the estimator scores the same rows in the same pass. Every draft-model speculator routes through that one call site, which is why MTP, DFlash and EAGLE3 need no speculator changes. Only DFlash2, which samples through a selector walk rather than `sample_draft`, scores at its own equivalent point.

The probability is written into two index spaces at once: the persistent request-state slot, where the next step's refit will find it alongside the label the target eventually produces, and the current batch position, which is what AV indexes by. Keeping both avoids a reorder later, since the batch is compacted between the two uses.

**Trimming reuses the existing AV path unchanged.** The estimator only supplies the per-position probabilities that DSpark's confidence head previously supplied. `record_confidences` publishes them and starts an async device-to-host copy, `get_num_tokens` sizes the global draft budget on CPU from the landed copy, and `_assign_draft_token_budget` ranks every `(request, step)` slot on device by its **survival probability** (the running product of that request's per-position confidences) admitting the globally best `draft_budget` slots. Because survival only decreases along a request, a global top-k always admits a prefix of each request's drafts, so `compact_batch` and `reallocate_drafts` can shorten the verification batch without any per-request bookkeeping.

**Per step**, `propose()` folds the previous step's drafts (now graded accepted or rejected by the target) into IRLS sufficient statistics, and every `REFIT_INTERVAL` steps solves for new coefficients. Because the slope is shared by all draft positions, the information matrix is an arrowhead and the solve collapses to a scalar equation, so no per-position matrix inverse is needed.

**Updates are damped by sample count.** Newton steps are scaled by `n / (n + DAMPING_OBSERVATIONS)`, but the slope and the intercepts count different things. The slope learns from every position, so it is damped by the round's total across all of them and is effectively undamped at serving batch sizes. Each intercept is damped by its own position's count, and observations thin out with depth because a deep position only exists when the shallower ones were accepted and admitted, so deeper `b[k]` move more conservatively, and a position nobody reached in a round has `n = 0` and holds still.

**Shared slope, per-position intercepts.** Sharing one slope across positions costs almost nothing (0.0002 AUC, 0.0003 log-loss) and keeps deep positions usable: they see too few labels per round to fit two parameters each, but an intercept alone is well determined.

# Why `logit(q_max)`

Candidate features were compared on three metrics:

- **AUC** measures discrimination: the probability that a random accepted draft scores above a random rejected one (0.5 = chance).
- **log-loss** is the mean negative log-likelihood of the predicted probability. It rewards calibration and penalizes confident mistakes.
- **ECE** measures calibration: predictions are binned, and each bin's mean prediction is compared with its observed acceptance frequency, weighted by bin occupancy.

Held-out scores on ~4.5M labeled drafts from DeepSeek-V4-Flash + DSpark, collected without AV (temp 1.0, top-p 0.95, concurrency 64; SPEED-Bench 2k low/high-entropy, GSM8K, HumanEval, MT-Bench). The last two rows are references, not fitted features.

| feature | lossless | AUC ↑ | log-loss ↓ | ECE ↓ |
|---|---|---|---|---|
| `log(q_max)` | yes | 0.8069 | 0.4813 | 0.0592 |
| `log(q_max) - log(q_2nd)` (top-2 margin) | yes | 0.8156 | 0.4437 | 0.0105 |
| `H(q)` (entropy) | yes | 0.8321 | 0.4577 | 0.0638 |
| `-log(-log(q_max))` | yes | 0.8336 | 0.4289 | 0.0103 |
| **`logit(q_max)` (shipped)** | **yes** | **0.8336** | **0.4284** | **0.0100** |
| `logit(q_sampled)` | **no** | 0.8553 | 0.4040 | 0.0152 |
| `-log(-log(q_sampled))` | **no** | 0.8554 | 0.4075 | 0.0193 |
| *`q_max` used directly as the probability (no fit)* | *yes* | *0.8259* | *0.4880* | *0.0736* |
| *trained confidence head* | *yes* | *0.8191* | *0.4449* | *0.0052* |

### Takeaways:
- **Losslessness rules out `q_sampled`.** The `q_sampled` features rank best, about 0.022 AUC above the best lossless feature, but they score the token the drafter actually drew. Trimming on them makes the decision to verify position `i` depend on `x_i` itself, so the drafts that survive trimming are no longer distributed as `q`, while rejection sampling still corrects with `min(1, p/q)`. The output distribution tilts toward the drafter's confident tokens. For example, with vocabulary `[a, b]`, `p = [0.5, 0.5]`, `q = [0.2, 0.8]`, and trimming when `q(x) < 0.5`, the output is `a` with probability 0.4 instead of 0.5. `q_max` depends only on the draft distribution, so the trim decision is fixed before `x_i` is drawn and the sampler's precondition holds. Under greedy drafting, the drawn token is the argmax, so the two features are identical.
- **The fit is what provides calibration.** Used directly, as EAGLE-2 does when ranking its draft tree, raw `q_max` already ranks drafts better than the trained head (0.8259 vs 0.8191 AUC). But it is overconfident: its mean prediction is 0.784 against an observed acceptance rate of 0.723, and its ECE is 7× the fitted estimator's. AV's budget decision sums these probabilities against a measured cost table, so it needs calibrated values. Fitting on the target's accept/reject decisions provides them, and the result holds when scored prequentially, with each prediction using only coefficients fit on earlier steps, as in serving (ECE 0.0105).
- **Discrimination is not calibration.** Entropy ranks nearly as well as `logit(q_max)` (0.8321 vs 0.8336 AUC) but is far worse calibrated (ECE 0.0638 vs 0.0100).

Among the lossless features, `logit(q_max)` matches or beats every other fitted feature on all three metrics, needs no extra vocab pass (unlike the top-2 margin), and shares the log-odds scale of the quantity it predicts.

## Versus a trained confidence head

DeepSeek-V4-Flash + DSpark ships a trained confidence head, so it serves as the baseline. On the same held-out drafts:

| | AUC ↑ | log-loss ↓ | ECE ↓ |
|---|---|---|---|
| estimator, `logit(q_max)` | **0.8336** | **0.4284** | 0.0100 |
| trained confidence head | 0.8191 | 0.4449 | **0.0052** |

The estimator ranks drafts better, and the head is slightly better calibrated, with no trained weights needed for the estimator. The ranking advantage comes from deeper positions: the head leads at the first draft position, and the estimator leads from the second onward, by up to 0.08 AUC at the deepest. Excluding the first position, the two are nearly tied on calibration (ECE 0.0103 vs 0.0090). Since survival is a running product, the first position is rarely the one trimmed, so the estimator is strongest where trimming actually happens.

+# The feature is a log-odds, log(q / (1 - q)), which a row carrying all of its
+# mass on one token sends to infinity. Clamp it symmetrically.
+_MAX_LOG_ODDS = 40.0
+
+# Cold-start coefficients: the median slope and intercept fitted online across
+# DeepSeek-V4-Flash, Muse-Glimmer-30B, MiMo-V2.5-Pro, Inkling and Kimi-K2.5.
+# Log-loss is flat near the optimum, so one starting point serves all of them
+# and a real fit replaces it within a refit or two.
+_INIT_SLOPE = 0.5
+_INIT_BIAS = -0.2
+
+
+@triton.jit
+def _accumulate_kernel(
+    info_ptr,
+    grad_ptr,
+    idx_mapping_ptr,
+    num_sampled_ptr,
+    num_rejected_ptr,
+    features_ptr,
+    features_stride,
+    pred_ptr,
+    pred_stride,
+    counts_ptr,
+    num_reqs,
+    BLOCK_R: tl.constexpr,
+):
+    step = tl.program_id(0).to(tl.int64)
+    req_block = tl.arange(0, BLOCK_R)
+    req_mask = req_block < num_reqs
+    req_state_block = tl.load(idx_mapping_ptr + req_block, mask=req_mask, other=0).to(
+        tl.int64
+    )
+
+    num_sampled = tl.load(num_sampled_ptr + req_block, mask=req_mask, other=0).to(
+        tl.int64
+    )
+    # Subtract bonus token.
+    num_accepted = tl.maximum(num_sampled - 1, 0)
+    num_rejected = tl.load(num_rejected_ptr + req_block, mask=req_mask, other=0).to(
+        tl.int64
+    )
+    num_admitted = num_accepted + num_rejected
+
+    feature = tl.load(
+        features_ptr + req_state_block * features_stride + step,
+        mask=req_mask,
+        other=0.0,
+    ).to(tl.float32)
+    pred = tl.load(
+        pred_ptr + req_state_block * pred_stride + step,
+        mask=req_mask,
+        other=0.0,
+    ).to(tl.float32)
+
+    # The accepted tokens and the first rejected draft token (if one exists) are
+    # "observed" and given labels.
+    observed = req_mask & (step <= num_accepted) & (step < num_admitted)
+    label = tl.where(step < num_accepted, 1.0, 0.0)
+    w = tl.where(observed, pred * (1.0 - pred), 0.0)
+    resid = tl.where(observed, label - pred, 0.0)
+
+    # This block's contribution to the normal equations for design row
+    # x = [feature, eₖ]: the XᵀWX entries aₖ, bₖ, cₖ and the Xᵀr entries g₀ₖ, g₁ₖ.
+    # aₖ and g₀ₖ are partials of scalars shared by every position, which
+    # _refit_kernel sums.
+    a_k = tl.sum(w * feature * feature, axis=0)
+    b_k = tl.sum(w * feature, axis=0)
+    c_k = tl.sum(w, axis=0)
+    g0_k = tl.sum(resid * feature, axis=0)
+    g1_k = tl.sum(resid, axis=0)
+    count = tl.sum(tl.where(observed, 1.0, 0.0), axis=0)
+    tl.store(info_ptr + step * 3 + 0, tl.load(info_ptr + step * 3 + 0) + a_k)
+    tl.store(info_ptr + step * 3 + 1, tl.load(info_ptr + step * 3 + 1) + b_k)
+    tl.store(info_ptr + step * 3 + 2, tl.load(info_ptr + step * 3 + 2) + c_k)
+    tl.store(grad_ptr + step * 2 + 0, tl.load(grad_ptr + step * 2 + 0) + g0_k)
+    tl.store(grad_ptr + step * 2 + 1, tl.load(grad_ptr + step * 2 + 1) + g1_k)
+    tl.store(counts_ptr + step, tl.load(counts_ptr + step) + count)
+

+@triton.jit
+def _refit_kernel(
+    slope_ptr,
+    intercepts_ptr,
+    info_ptr,
+    info_row_stride,
+    grad_ptr,
+    grad_row_stride,
+    counts_ptr,
+    NUM_SPECULATIVE_STEPS: tl.constexpr,
+    L2: tl.constexpr,
+    DAMPING: tl.constexpr,
+    BLOCK: tl.constexpr,
+):
+    k = tl.arange(0, BLOCK)
+    mask = k < NUM_SPECULATIVE_STEPS
+
+    # Load the stats accumulated over this round to solve (XᵀWX + λI) Δθ = Xᵀr.
+    a_k = tl.load(info_ptr + k * info_row_stride + 0, mask=mask, other=0.0)
+    b_k = tl.load(info_ptr + k * info_row_stride + 1, mask=mask, other=0.0)
+    c_k = tl.load(info_ptr + k * info_row_stride + 2, mask=mask, other=0.0) + L2
+    a = tl.sum(a_k, axis=0) + L2
+    g0_k = tl.load(grad_ptr + k * grad_row_stride + 0, mask=mask, other=0.0)
+    g1_k = tl.load(grad_ptr + k * grad_row_stride + 1, mask=mask, other=0.0)
+    g0 = tl.sum(g0_k, axis=0)
+    n = tl.load(counts_ptr + k, mask=mask, other=0.0)
+
+    # Load the current shared slope and per-position intercepts.
+    w = tl.load(slope_ptr)
+    bias = tl.load(intercepts_ptr + k, mask=mask, other=0.0)
+
+    # Solve for the shared slope delta, Δω, in the following arrowhead system:
+    #   ⎡ a+λ   b₀     b₁    …  bₙ₋₁    ⎤ ⎡  Δω   ⎤   ⎡  g₀   ⎤
+    #   ⎢ b₀    c₀+λ                    ⎥ ⎢  Δβ₀  ⎥   ⎢  g₁₀  ⎥
+    #   ⎢ b₁           c₁+λ             ⎥ ⎢  Δβ₁  ⎥ = ⎢  g₁₁  ⎥
+    #   ⎢ ⋮                  ⋱          ⎥ ⎢  ⋮    ⎥   ⎢  ⋮    ⎥
+    #   ⎣ bₙ₋₁                  cₙ₋₁+λ   ⎦ ⎣ Δβₙ₋₁ ⎦   ⎣ g₁ₙ₋₁ ⎦
+    #               XᵀWX + λI                Δθ        Xᵀ(Y-P)
+    shrink = b_k * b_k / c_k
+    coupling = b_k * g1_k / c_k
+    step_w = (g0 - tl.sum(coupling, axis=0)) / (a - tl.sum(shrink, axis=0))
+
+    # The slope learns from every position, so it is damped by the round's
+    # total sample count.
+    total_n = tl.sum(n, axis=0)
+    step_w *= total_n / (total_n + DAMPING)
+    # Mask out NaNs and steps that would drive the slope negative.
+    step_w = tl.where((step_w == step_w) & (w + step_w >= 0.0), step_w, 0.0)
+    # Update the shared slope.
+    new_w = w + step_w
+
+    # Solve for the per-position intercept deltas, Δβₖ, in the same system.
+    step_bias = (g1_k - b_k * step_w) / c_k
+    # Damp by the position's sample count.
+    step_bias *= n / (n + DAMPING)
+    # Mask out NaNs.
+    step_bias = tl.where(step_bias == step_bias, step_bias, 0.0)
+    # Update the per-position intercepts.
+    new_bias = bias + step_bias
+
+    tl.store(slope_ptr, new_w)
+    tl.store(intercepts_ptr + k, new_bias, mask=mask)
+
+    # Start the round clean by clearing the per-round statistics.
+    tl.store(info_ptr + k * info_row_stride + 0, 0.0, mask=mask)
+    tl.store(info_ptr + k * info_row_stride + 1, 0.0, mask=mask)
+    tl.store(info_ptr + k * info_row_stride + 2, 0.0, mask=mask)
+    tl.store(grad_ptr + k * grad_row_stride + 0, 0.0, mask=mask)
+    tl.store(grad_ptr + k * grad_row_stride + 1, 0.0, mask=mask)
+    tl.store(counts_ptr + k, 0.0, mask=mask)
+
+
+@triton.jit
+def _local_max_sumexp_kernel(
+    local_max_ptr,
+    local_max_stride,
+    local_sumexp_ptr,
+    local_sumexp_stride,
+    logits_ptr,
+    logits_stride,
+    idx_mapping_ptr,
+    idx_mapping_stride,
+    temperature_ptr,
+    num_tokens,
+    vocab_size,
+    BLOCK_SIZE: tl.constexpr,
+):
+    token_idx = tl.program_id(0).to(tl.int64)
+    if token_idx >= num_tokens:
+        return
+
+    block_idx = tl.program_id(1)
+    req_state_idx = tl.load(idx_mapping_ptr + token_idx * idx_mapping_stride).to(
+        tl.int64
+    )
+    if req_state_idx < 0:
+        # Cudagraph-padded requests carry -1. Write an empty partial so the
+        # buffer holds nothing uninitialized; _predict_kernel skips these rows.
+        tl.store(
+            local_max_ptr + token_idx * local_max_stride + block_idx, float("-inf")
+        )
+        tl.store(local_sumexp_ptr + token_idx * local_sumexp_stride + block_idx, 0.0)
+        return
+
+    # Draft logits are pre-temperature, and acceptance is decided on the scaled
+    # distribution the drafter actually sampled from, so scale first. A request
+    # with temp == 0 drafts greedily, so leave its logits alone rather than dividing
+    # by zero, matching what the sampler does.
+    temp = tl.load(temperature_ptr + req_state_idx).to(tl.float32)
+    temp = tl.where(temp > 0.0, temp, 1.0)
+
+    offsets = block_idx * BLOCK_SIZE + tl.arange(0, BLOCK_SIZE)
+    mask = offsets < vocab_size
+    logits = (
+        tl.load(
+            logits_ptr + token_idx * logits_stride + offsets,
+            mask=mask,
+            other=float("-inf"),
+        ).to(tl.float32)
+        / temp
+    )
+    block_max, block_sumexp = _compute_max_and_sumexp(logits)
+    tl.store(local_max_ptr + token_idx * local_max_stride + block_idx, block_max)
+    tl.store(
+        local_sumexp_ptr + token_idx * local_sumexp_stride + block_idx, block_sumexp
+    )
+
+
+@triton.jit
+def _predict_kernel(
+    features_ptr,
+    features_stride,
+    pred_ptr,
+    pred_stride,
+    conf_ptr,
+    conf_stride,
+    slope_ptr,
+    intercepts_ptr,
+    local_max_ptr,
+    local_max_stride,
+    local_sumexp_ptr,
+    local_sumexp_stride,
+    idx_mapping_ptr,
+    idx_mapping_stride,
+    step_ptr,
+    num_tokens,
+    vocab_num_blocks,
+    per_token_step: tl.constexpr,
+    NUM_SPECULATIVE_STEPS: tl.constexpr,
+    MAX_LOG_ODDS: tl.constexpr,
+    PADDED_VOCAB_NUM_BLOCKS: tl.constexpr,
+):
+    token_idx = tl.program_id(0).to(tl.int64)
+    if token_idx >= num_tokens:
+        return
+
+    req_state_idx = tl.load(idx_mapping_ptr + token_idx * idx_mapping_stride).to(
+        tl.int64
+    )
+    if req_state_idx < 0:
+        # Cudagraph-padded requests carry -1. Skip them so that they don't
+        # scatter garbage over a live request's features.
+        return
+
+    # A per-row step means the speculator sampled the whole block in one pass, so
+    # each request owns NUM_SPECULATIVE_STEPS consecutive rows; a step shared by
+    # every row means one row per request. Batch position, unlike req_state_idx,
+    # is only meaningful for the step that computed it, and is what adaptive
+    # verification indexes by.
+    if per_token_step:
+        step = tl.load(step_ptr + token_idx).to(tl.int64)
+        batch_idx = token_idx // NUM_SPECULATIVE_STEPS
+    else:
+        step = tl.load(step_ptr).to(tl.int64)
+        batch_idx = token_idx
+
+    blocks = tl.arange(0, PADDED_VOCAB_NUM_BLOCKS)
+    blocks_mask = blocks < vocab_num_blocks
+    maxes = tl.load(
+        local_max_ptr + token_idx * local_max_stride + blocks,
+        mask=blocks_mask,
+        other=float("-inf"),
+    )
+    sumexps = tl.load(
+        local_sumexp_ptr + token_idx * local_sumexp_stride + blocks,
+        mask=blocks_mask,
+        other=0.0,
+    )
+
+    # The feature, logit(q(m*)) for the row's max draft logit, m*, is:
+    #   q(x) = e^(x - m*) / Σ_z e^(z - m*)
+    #   logit(q(m*)) = log(q(m*) / (1 - q(m*)))
+    #   	= m* - log(Σ_{z≠m*} e^(z - m*)).
+    # It scores the draft distribution, not the token drawn from it, so it is
+    # a function of the prefix alone. Trimming a draft therefore never
+    # conditions on the token being trimmed, and rejection sampling stays
+    # lossless. Scoring the drawn token instead would select on the proposal
+    # and bias the emitted distribution toward the drafter's confident modes.
+
+    # Rescale each block's partial to the global max and sum. The most likely
+    # token contributes exactly e^(m - m) = 1, so removing it leaves the sum
+    # over every other token.
+    global_max = tl.max(maxes, axis=0)
+    total_sumexp = tl.sum(
+        tl.where(blocks_mask, sumexps * tl.exp(maxes - global_max), 0.0), axis=0
+    )
+    complement_sumexp = tl.maximum(total_sumexp - 1.0, 0.0)
+
+    # Shifted by m*, the numerator is e^(m* - m*) = 1, so the feature is just the
+    # negated complement log-sum-exponential. Clamp to the min/max log-odds.
+    feature = -tl.log(complement_sumexp)
+    feature = tl.minimum(tl.maximum(feature, -MAX_LOG_ODDS), MAX_LOG_ODDS)
+    tl.store(features_ptr + req_state_idx * features_stride + step, feature)
+
+    # Predict the acceptance probability from the feature and current coefficients.
