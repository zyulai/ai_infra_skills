## 正文(PR 描述)

## Motivation

**What goes wrong**
Serving a Quark MXFP4 MoE checkpoint with `--ep-size` > 1 on the W4A16 path added in #41389 aborts the GPU with `HSA_STATUS_ERROR_EXCEPTION: An HSAIL operation resulted in a hardware exception. code: 0x1016`. Under expert parallelism the standard dispatcher hands each rank `topk_ids` where experts owned by other ranks are `-1`, and `_apply_triton_w4a16` feeds those ids straight into `counts.scatter_add_(...)`, which writes out of bounds.

**Where it shows up**
Every GPU that takes the W4A16 path with EP > 1. It was reported on #41389 for both gfx1151 and gfx942, and reproduced here on gfx1151. The path was also enabled on every HIP GPU that is not gfx95x or gfx1250 (so gfx942/MI300X as well), although it was written and validated for gfx1151.

**How to fix**
Send `-1` ids to an extra bucket that sorts last, is left out of the ragged expert counts, and is zeroed before the top-k reduction, and enable the path only on gfx1151.

This PR also addresses the review comments on #41389 that were still open at merge time: log once when the W4A4 checkpoint runs as W4A16, register the opt-out env var in `environ.py`, and reject SwiGLU variants the path cannot compute (`gemm1_alpha`, `gemm1_beta`, `gemm1_clamp_limit`, `swiglu_limit`, e.g. gpt-oss, DeepSeek-V4, MiniMax-M3), which previously passed the `activation == "silu"` check and produced silently wrong output.

## Modifications

All runtime changes are in `python/sglang/srt/layers/quantization/quark/schemes/quark_w4a4_mxfp4_moe.py` and only take effect on gfx1151.

- Gate: `_use_triton_w4a16` is now `gfx1151 and SGLANG_ENABLE_QUARK_MXFP4_MOE_W4A16` instead of "HIP and not gfx95x and not gfx1250". gfx942 and other AMD GPUs go back to the AITER path.
- EP fix in `_apply_triton_w4a16`: `-1` ids are mapped to bucket `num_experts`, `counts` gets one extra slot that is dropped before `make_ragged_tensor_metadata`, and the scattered rows of non-local slots are zeroed with `masked_fill` before the sum over `top_k`. Everything stays on device, so CUDA graph capture still works.
- Env var: `SGLANG_QUARK_MXFP4_MOE_W4A16` becomes `SGLANG_ENABLE_QUARK_MXFP4_MOE_W4A16 = EnvBool(True)` in `python/sglang/srt/environ.py` (AMD section), read via `envs.....get()`. The name gains the `ENABLE_` verb required by the env-var conventions; it was only on the #41389 branch, never in a release.
- `_process_weights_triton_w4a16` raises `NotImplementedError` listing the unsupported SwiGLU parameters instead of running plain SwiGLU.
- `logger.info_once` reports that the W4A4 MXFP4 checkpoint runs as W4A16 and how to disable it.
