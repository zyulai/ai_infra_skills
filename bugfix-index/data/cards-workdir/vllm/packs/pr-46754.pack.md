## 正文(PR 描述)

## Purpose

Fixes incorrect attention behavior for prefix-LM multimodal models (e.g., Gemma3) on ROCm. This is a correctness fix. 

**Root cause:** Both `RocmAttentionBackend` and `RocmAiterUnifiedAttentionBackend` overrode
`supports_mm_prefix()` to return `True`, but neither backend actually implements the
`mm_prefix_range_tensor` passing required for bidirectional image-token attention during prefill. As a result,
prefix-LM multimodal models on ROCm were silently falling through with wrong attention masks and
image tokens were not attending to each other bidirectionally as required by models like Gemma3.

**Changes:**
1. **`rocm_attn.py` / `rocm_aiter_unified_attn.py`**: Removed the incorrect
   `supports_mm_prefix() -> True` overrides. Both backends now inherit the base-class default
   (`False`), causing the attention backend selector to correctly defer to Triton unified
   attention for prefix-LM models on ROCm.
2. **`gemma3_mm.py`**: Explicitly sets `config.text_config.is_mm_prefix_lm = True` in the
   multimodal constructor, since the text-only Gemma3 path does not set this flag but the
   multimodal path requires it for correct image-token attention.
3. **`rocm.py`**: Ports the `disable_chunked_mm_input` guard from the CUDA platform path to
   ROCm. For prefix-LM multimodal models, chunked prefill can split a multimodal item and
   break the intended bidirectional attention pattern; this ensures ROCm disables it
   automatically, matching CUDA behavior.
4. **`tests/kernels/attention/test_rocm_attention_selector.py`**: Adds a regression test
   asserting that both ROCm backends do not claim `mm_prefix` support, guarding against this
   being re-introduced silently.
