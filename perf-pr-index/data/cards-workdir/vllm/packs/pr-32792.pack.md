## PR body
```markdown
[CPU Backend] [Perf] Accelerate tensor-parallel/data-parallel inference across NUMA domains on Arm

Fixes: #32786

## Purpose

This PR addresses #32786 by enabling vLLM's custom shared memory communicator for Arm, in favor of torch.distributed which has very high synchronization costs. It also enables auto thread binding for best OOB performance.

## Benchmarks

Here are the results from the benchmarks in #32786 on `c8g.metal.48xlarge`.
These are percentages of the baseline which is: Single NUMA, tp=1 (96 cores), VLLM_CPU_OMP_THREADS_BIND=0-95

| Configuration | req/sec (higher-better) | median TTFT (lower-better) | median TPOT (lower-better) |
|---|---:|---:|---:|
| **2 NUMAs, tp=1** (VLLM_CPU_OMP_THREADS_BIND=0-191) | 134.3% | 55.4% | 83.9% |
| **[Current] 2 NUMA, tp=2 w/ thread binding** (VLLM_CPU_OMP_THREADS_BIND="0-95\|96-191") | 60.2% | 119.3% | 196.4% |
| **[Current] 2 NUMA, tp=2  no thread binding (i.e. OOB)** (VLLM_CPU_OMP_THREADS_BIND=nobind) | 39.8% | 255.4% | 185.0% 
| **With PR: 2 NUMA, tp=2 (191 cores)** (VLLM_CPU_OMP_THREADS_BIND auto-set by vLLM) | **196.3%** | **46.7%** | **53.6%** |

As we can see from the table, when running **`tp=2` on 2 NUMAs**, **with this PR**: 
- **throughput** is **2x higher** and **latency** is **2x lower**, compared to **`tp=1` on a single NUMA**. 
- **OOB throughput** is **4x higher** and **OOB latency** is **4x lower**, compared to **current state in vLLM with `tp=2` and 2 NUMAs**
```
