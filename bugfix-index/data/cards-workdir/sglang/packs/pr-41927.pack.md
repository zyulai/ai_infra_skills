## 正文(PR 描述)

## Why?

With Mamba/KDA, PD decode, and decode radix cache, [PD admission on `main`](https://github.com/sgl-project/sglang/blob/a9c97c9f6973c03e778d1fe1e63a6b9f58a55012/python/sglang/srt/disaggregation/decode.py#L1373-L1387) checks whether **zero** Mamba slots are free. It does not evict cached states when one slot is free, even though a fresh request needs **three** slots with overlap scheduling: one live state and [two tracking buffers](https://github.com/sgl-project/sglang/blob/a9c97c9f6973c03e778d1fe1e63a6b9f58a55012/python/sglang/srt/mem_cache/memory_pool.py#L1450-L1471). The [buffer allocation](https://github.com/sgl-project/sglang/blob/a9c97c9f6973c03e778d1fe1e63a6b9f58a55012/python/sglang/srt/mem_cache/memory_pool.py#L1599-L1613) then asserts and exits the decode worker.

```text
Fresh request: 1 free slot, cached states are evictable
  -> PD admission sees free > 0 and skips eviction
  -> request row and live Mamba state allocate (1 -> 0 free)
  -> two tracking buffers cannot allocate
  -> AssertionError: Not enough space for mamba ping pong idx
```

## What?

- Extract `ensure_mamba_capacity` from the [combined-engine allocation logic on `main`](https://github.com/sgl-project/sglang/blob/a9c97c9f6973c03e778d1fe1e63a6b9f58a55012/python/sglang/srt/mem_cache/allocation.py#L300-L323). It counts the live state and tracking slots each request still needs, evicts enough cached states to cover any shortfall, then rechecks capacity.
- Use that check before PD decode preallocation and before resuming a retracted request. If capacity is still short, leave the request queued rather than partially allocating it.
- Keep combined serving's existing behavior: attempt eviction, then let its allocator run. Only PD uses the capacity check to defer a request.

## Verification?

On one H200 node, two GPUs ran the tiny Kimi Linear model with real weights, NIXL PD, decode radix cache, overlap scheduling, and 16 sequential distinct requests (257 input / 256 output tokens each):

```text
Unpatched, 5 Mamba slots: 3 requests complete; request 4 crashes
                         at 2 free + 3 evictable slots
Patched,   5 Mamba slots: all 16 complete
Unpatched, 128 slots:     all 16 complete (capacity control)
Patched, repeated prompt: request completes with 256 cached tokens
```

Relevant traceback, with framework wrappers omitted:

```text
DecodePreallocQueue.pop_preallocated
  -> DecodePreallocQueue._pre_alloc          (decode.py:2075)
  -> HybridReqToTokenPool.alloc              (memory_pool.py:1471)
  -> HybridReqToTokenPool._alloc_ping_pong_buffer
  -> AssertionError: Not enough space for mamba ping pong idx
```
