## Motivation

SGLang allocates the FlashInfer MoE result in symmetric memory, but older FlashInfer releases did not let the monolithic `trtllm_fp8_block_scale_moe` API write into that buffer. The result therefore required an additional `copy_`, and the first version of this PR used a dual-stream copy/add workaround to hide it.

SGLang now pins FlashInfer 0.6.14. That release exposes an `output` tensor for both the [non-routed and routed FP8 block-scale MoE APIs](https://github.com/flashinfer-ai/flashinfer/blob/v0.6.14/flashinfer/fused_moe/core.py), so both kernels can write directly into the symmetric output buffer without the scheduling workaround.

## Modifications

- Added mutation-only SGLang custom-op wrappers for the routed and non-routed FlashInfer FP8 block-scale MoE `output` paths. Keeping these separate from the allocating wrappers avoids returning a tensor that aliases a mutated custom-op argument.
- Passed `symm_output` directly to both FlashInfer kernels and removed the post-kernel `copy_`.
- Removed the runtime-context and shared-expert dual-stream copy/add workaround.
- Added real FlashInfer regression coverage for both output-buffer paths.

## FlashInfer 0.6.14 Validation

Environment: NVIDIA B200, PyTorch 2.11.0+cu130, FlashInfer 0.6.14.

- The non-routed DeepSeekV3 grouped-routing API returned the supplied output storage and matched the allocating path exactly (`max_abs_diff=0`).
- `pytest test/registered/unit/layers/moe/test_flashinfer_trtllm_moe_output.py -q`: `2 passed`.

Per request, no GLM model test was run, avoiding any model-weight download. The existing accuracy and performance results below are retained.
