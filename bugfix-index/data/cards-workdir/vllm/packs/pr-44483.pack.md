## 正文(PR 描述)

Fixes #44395.
Resume scheduling only once the executor is fully resident. `model_executor.is_sleeping` stays `True` until all sleep tags are awake (`Executor.wake_up` clears it only when `sleeping_tags` is empty), so a weights-only wake keeps the scheduler paused; it resumes at the final/full wake. No behavior change on the full-wake path.


### Reproduction 
```bash
VLLM_SERVER_DEV_MODE=1 vllm serve Qwen3/Qwen3-30B-A3B \
  --tensor-parallel-size 2 --data-parallel-size 2 \
  --enable-expert-parallel --enable-sleep-mode --port 8000

curl -X POST "localhost:8000/sleep?level=1"          # KV released
curl -X POST "localhost:8000/wake_up?tags=weights"   # weights only; KV still asleep
curl -X POST localhost:8000/v1/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"<moe-model>","prompt":"hi","max_tokens":8}'
# before: CUDA illegal memory access  /  after: completes (engine stays paused until kv_cache is woken)
```

### Test plan & results

Validated on **4× A100-80GB**, `Qwen3-30B-A3B` (MoE), vLLM `main` + this patch, launched with
`--tensor-parallel-size 2 --data-parallel-size 2 --enable-expert-parallel --enable-sleep-mode`.

**1. Regression 
full wake still resumes scheduling ，no behavior change on the normal path.
```bash
curl -X POST localhost:8000/sleep?level=1        # 200 OK
curl -X POST localhost:8000/wake_up              # full wake: "wake up tags {'kv_cache','weights'}"
curl -X POST localhost:8000/v1/chat/completions -d '{"model":"...","messages":[{"role":"user","content":"hi"}],"max_tokens":8}'
# -> 200 OK, completion returns normally  ✅
```
**2. Fix 
partial wake no longer crashes, scheduler stays paused until KV is resident:
```bash
curl -X POST localhost:8000/sleep?level=1        # 200 OK
curl -X POST localhost:8000/wake_up?tags=weights # weights only; KV still asleep
curl -X POST localhost:8000/v1/completions -d '{"model":"...","prompt":"hi","max_tokens":8}'
# -> request HANGS (no crash) — the engine stays paused because KV is not resident yet
curl -X POST localhost:8000/wake_up?tags=kv_cache # (separate shell) wake KV
# -> the pending /v1/completions immediately returns 200 OK  ✅
```

```text
         # /v1/completions sent here: NO crash, no worker exception; request stays queued (scheduler paused)

02:54:56 POST /v1/completions HTTP/1.1 200 OK               # the pending request completes right after KV wake
```
Before this patch, the same `sleep → wake_up(tags=["weights"]) → forward` sequence crashed with
`CUDA illegal memory access` (`execute_dummy_batch` / `_compute_slot_mapping_kernel`); see the stacks in #44395.
