## Motivation
1. Deprecate FlashInfer LoRA backend: #7809
2. Optimize prepare_lora_batch to optimize latency as currently there are lots of redundant mem ops, many of which for backward compatibility with FlashInfer: #6961, #8712 

## Modifications

1. Deprecate FlashInfer LoRA backend
2. Refactor weight shape & prepare_lora_batch to reduce redundant memory ops.
  - Store lora B weight as (rank, q + k + v) following triton kernel expectation and industry convention.
  - Eliminate all reshape / copy ops in set_lora
  - Move set_lora() calls from prepare_lora_batch to server initialization phase to avoid overheads per batch
3. ~Fix bug #8939 (TODO: rebase once #8987 is merged)~
