## 正文(PR 描述)

## Motivation

With `SGLANG_USE_AITER_UNIFIED_ATTN=1` on a dense (non-sliding-window) model at the default page size 1, decode produces garbage output when CUDA graph is on. The first token (from prefill) is correct and every decoded token after it is wrong: with greedy sampling, `"The capital of France is"` continues as `" a ( ( ( ( ( ..."` instead of `" a city of romance, art, fashion, and cuisine. Paris is a must"`. GSM8K drops to 0.00. Nothing rejects this configuration, so it fails silently.

In `_apply_cuda_graph_metadata`, the unified-attention page table is copied into the captured `cuda_graph_page_table` only for sliding-window pools or `page_size > 1`. At page size 1 nothing is copied, so `unified_attention` reads an all-zero page table. Sliding-window models and Qwen3-VL (which gets page size 16 from its model override) are not affected. The non-CUDA-graph path builds the page table directly and is not affected either. The SHUFFLE 5D KV layout, the other decode path that reads this page table, requires a page size divisible by 8 (BF16 KV) or 16 (FP8 KV), so it never runs at page size 1. The AMD CI tests and cookbook recipes that enable unified attention all set `--page-size 16` or `64`, so page size 1 had no coverage.

## Modifications

- `aiter_backend.py`: copy the page table for every non-sliding-window configuration. `_transform_table_1_to_real` is the identity at page size 1, so the `page_size > 1` condition only skipped the copy.
- New AMD CI test `test/registered/attention/test_aiter_unified_attention_page_size_1.py`: GSM8K on `DEFAULT_MODEL_NAME_FOR_TEST` with unified attention at page size 1 (threshold 0.65).

## Accuracy Tests

MI355X (gfx950), single GPU, with and without this patch, Llama-3.1-8B-Instruct, `SGLANG_USE_AITER=1 SGLANG_USE_AITER_UNIFIED_ATTN=1 --attention-backend aiter`, CUDA graph on. GSM8K uses the same settings as the new CI test (200 questions, 5-shot, completion API, `max_tokens=512`), 3 runs each.

| Configuration | Before | After |
|---|---|---|
| unified attention, page size 1 | 0.00 / 0.00 / 0.00 | 0.755 / 0.755 / 0.765 |
| unified attention, page size 16 (reference) | — | 0.765 |

A second dense model gives the same picture: Qwen3-8B scores 0.00 before and 0.95 after, the same as page size 16 (0.95).

The new CI test fails on `main` (`np.float64(0.0) not greater than or equal to 0.65`) and passes with this patch: 0.765 on MI355X, and 0.765 on MI300X (gfx942) in this PR's CI.

## Speed Tests and Profiling

No change for configurations other than unified attention at page size 1, which was producing wrong output before. With the patch, page size 1 output throughput is within 2% of page size 16.

MI355X, Llama-3.1-8B-Instruct, `sglang.bench_serving`, random input 2048 / output 256, CUDA graph on, unified attention, patched build:

| Page size | Concurrency | Mean TTFT (ms) | Mean TPOT (ms) | Output tok/s |
|---|---|---|---|---|
| 1 | 1 | 58.79 | 4.24 | 224.5 |
| 16 | 1 | 61.89 | 4.25 | 223.4 |
| 1 | 32 | 572.97 | 7.48 | 3294.8 |
| 16 | 32 | 621.54 | 7.15 | 3342.5 |

## Reproduce

```bash
SGLANG_USE_AITER=1 SGLANG_USE_AITER_UNIFIED_ATTN=1 python -m sglang.launch_server \
  --model-path meta-llama/Llama-3.1-8B-Instruct --attention-backend aiter --page-size 1 --port 30000

python -m sglang.test.run_eval --port 30000 --eval-name gsm8k --api completion \
  --num-examples 200 --num-threads 128 --max-tokens 512 --num-shots 5

python -m sglang.bench_serving --backend sglang --port 30000 --dataset-name random \
  --random-input-len 2048 --random-output-len 256 --random-range-ratio 1 \
  --max-concurrency 32 --num-prompts 128 --seed 1
```
