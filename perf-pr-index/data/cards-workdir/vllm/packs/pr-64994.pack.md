```markdown

## Overview

With `--dcp-comm-backend a2a`, MLA decode all-to-alls each rank's partial latent output and applies `W_UV` after the LSE merge. This PR applies it to all DCP-gathered heads first, so the all-to-all carries 130 instead of 514 bf16 values per head (Kimi-K3, 512/128). The merge is linear per head, so only rounding changes.

## Claims

- `MLADCPManager.v_up_proj_combine` is set only for the NCCL all-to-all without PCP; symmetric-memory and `ag_rs` paths are unchanged.
- `MLAAttention` and Kimi-K3 `MultiHeadLatentAttention` (also the DSpark draft's) use it when `W_UV` is unquantized. On by default.
- Cost per MLA layer: the gathered `W_UV` (+12 MiB for Kimi-K3 at TP8/DCP8, 0.32 GiB per GPU; the local `W_UV` is a view of `kv_b_proj` and adds nothing) and a BMM over N times the heads. Below 8 decode tokens that BMM costs more than the all-to-all saves, so it merges first there.
- Kimi-K3 1P1D on MI355X, TP8/DCP8, decode-bound C16 / C32: throughput +0.6% / +1.1%, 90th-percentile interactivity +1.4% / +2.8%. Decode step -1.1% / -1.7% at 24 / 32 running requests. Prefill-bound C72: interactivity +4%, throughput flat.

## Validation

- Measured here: a new 2-rank test against merge-then-project passes on MI355X, fails with a wrong head order, and runs in the Distributed Features CI steps.
- Measured here: per-layer microbenchmark, 8x MI355X, 96 or 64 heads, cold weights: project-then-merge is +1.1 µs (+4-5%) at 1-4 tokens, even at 8, and -12% to -48% from 16 to 360 tokens.
- Measured here: selection asserts pass; an 8-rank simulation at Kimi-K3 shapes gives both orders the same fp64 relative error, 2.30e-3. pre-commit clean.
- Not from this branch: end-to-end numbers (runtime patch, same math, nightly `3966924d`); GSM8K 0.958 at C32 (both orders), 0.963 at C72.
```

```
## Details

On by default: a2a is opt-in or model-selected, and CUDA with DCP symmetric memory keeps its direct combine. Both orders round twice to the activation dtype.

Limitations: not run on CUDA, or end to end from this branch; the 8-token threshold is measured on MI355X only. DeepSeek-V3.2 attention and direct symmetric-memory A2A keep merge-then-project.

Related: #48196 (draft, conflicting) puts the same projection, for every DCP backend, in a larger sparse-MLA change predating `MLADCPManager`. AI-assisted (Claude in Cursor).
```
