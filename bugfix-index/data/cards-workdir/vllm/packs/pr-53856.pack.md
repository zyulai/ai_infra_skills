## 正文(PR 描述)

## Purpose

ROCm paged attention masks logits for tokens beyond `seq_len`, but its vectorized V-cache loads can still consume unwritten slots in the final block. If one of those slots contains NaN, the subsequent `0 * NaN` accumulation propagates NaNs into the output. K does not need the same treatment because invalid K values are removed before softmax; V must be sanitized before the matrix accumulation.

This PR keeps the vectorized loads and handles only the partial tail:

- gfx9 MFMA16 skips fully invalid V vectors and masks only the vector crossing `seq_len` in the existing consumption loop. The `auto` and FP8 paths remain compile-time separated, and a launch bound of four waves avoids scratch spilling from the added boundary state.
- gfx9 MFMA4 leaves the full-warp hot path unchanged. In the partial tail warp, it skips fully invalid 8-token vectors and masks only the one boundary vector.
- gfx11 and gfx12 use the shared packed-vector padding helper at their V-consumption points.

The fix does not clear the KV cache, reset K/V scales, or add post-wake restoration logic. It follows the former CUDA paged-attention safeguard ([#936](https://github.com/vllm-project/vllm/pull/936), [#641](https://github.com/vllm-project/vllm/issues/641)) and current Triton paged attention: score masking alone is insufficient because `0 * NaN` is NaN.

The existing ROCm paged-attention test gives every sequence a private final physical block, then poisons the slots past that sequence's logical length. The `auto` path uses the cache dtype's NaN and FP8 uses the architecture-correct E4M3 NaN representation. Distinct, non-default K/V scales are retained. This tests the kernel directly without relying on sleep mode, allocator behavior, or random physical-block overlap.

### Scope and duplication

I searched open vLLM PRs for ROCm paged-attention V-padding/NaN fixes and found no overlapping fix. [#54210](https://github.com/vllm-project/vllm/pull/54210) changes which gfx11 GQA shapes enter the CK kernel; it is complementary to this PR, which makes that kernel safe once selected.

## Correctness and compatibility

Commands run on a gfx950 MI350X node:

```bash
pytest -sv tests/kernels/attention/test_attention.py \
  -k "test_paged_attention"
```

Against the unpatched baseline, the updated test was stopped after the first failure in each cache dtype. Both `auto` and FP8 independently reproduce the NaN propagation:

```text
auto: Mismatched elements: 10240 / 14336 (71.4%)
fp8:  Mismatched elements: 10240 / 14336 (71.4%)
Greatest absolute difference: nan
```

After the final implementation:

```text
199 passed, 2 deselected, 15 warnings in 660.64s
```

The run includes 192 BF16/FP16 paged-attention combinations across `auto` and FP8 KV cache, block sizes 16/32, head sizes 64/128, ALiBi on/off, GQA ratios 1/4 (MFMA4) and 8 (MFMA16), and two devices, plus seven unsupported-head-size checks. The poisoned output is compared with the existing reference implementation, so the result checks live-token accuracy as well as absence of NaNs.

`_rocm_C` was compiled from the final source for `gfx942`, `gfx950`, `gfx1100`, and `gfx1200`. Runtime validation is on gfx950. Separate gfx1100 hardware validation of the admitted FP16/BF16 `auto` path exercised all 32 CK rows, fixed all four stock V-poison failures, and introduced no new failure. gfx942 and gfx1200 received compile validation only.

For model-level context, the HunyuanOCR gfx1100 reproducer bypasses this kernel under the current GQA gate, so this PR alone is byte-inert for that workload. With #54210's gate widening, it enters the patched kernel and remains deterministic with byte-identical correct output ([data](https://github.com/vllm-project/vllm/issues/50603#issuecomment-5465499491)).

## Performance evaluation

I A/B benchmarked the direct `ops.paged_attention_rocm` call on an exclusive MI350X (`gfx950`) node. Baseline and candidate were compiled from the same main commit. HIP events time only the kernel operation, excluding allocation and setup, with ABBA process ordering.

The broad discovery matrix contains **399 cases**:

- BF16 and FP16; FP8 and `auto` KV cache
- head sizes 64/128; block sizes 16/32; GQA 1/4/8
- batch sizes 1/4/8/16/32
- sequence lengths around tile/block boundaries and from 15 through 32768
- uniform, ramp, and mixed ragged tails; ALiBi on/off
- both MFMA4 and MFMA16 dispatches

Each discovery case used 20 warmups, 50 samples of 20 invocations, and four independent process medians. Every apparent >5% outlier, plus representative aligned, straddling, small-batch, long-context, `auto`, FP8, MFMA4, MFMA16, and head-128 cases, was then rerun in a 44-case high-precision set with 100 warmups, 50 samples of 200 invocations, and six independent process medians.

High-precision result: **0/44 cases regressed by more than 5%**; the worst observed delta was **+3.48%**.

| Representative high-precision case | Baseline | Candidate | Delta |
| --- | ---: | ---: | ---: |
| MFMA4 FP8, batch 32, mixed ragged tail, GQA 1, seq 4096 | 24.062 us | 24.900 us | +3.48% |
| MFMA16 FP8, batch 32, GQA 8, seq 1023 | 10.944 us | 11.305 us | +3.30% |
| MFMA16 auto, batch 8, head 64, GQA 8, seq 4093 | 15.537 us | 16.029 us | +3.17% |
| MFMA16 auto, batch 8, head 128, GQA 8, seq 4093 | 25.141 us | 25.856 us | +2.85% |
| MFMA4 FP8, batch 8, head 128, GQA 4, seq 4093 | 16.426 us | 16.753 us | +1.99% |
| MFMA4 FP8, batch 1, seq 33 | 10.039 us | 10.002 us | -0.37% |
| MFMA16 FP8, batch 1, seq 32765 | 13.381 us | 13.290 us | -0.68% |

The shorter discovery windows produced three noisy >5% readings; all disappeared in the longer reruns (for example, batch 1 / seq 33 changed from an apparent +6.8% to -0.37%). The remaining stable cost is concentrated in partial-tail handling and is approximately 2-3.5% at direct-kernel granularity; this PR does not claim zero regression.

Profiling also guided the final shape. For the scratch-sensitive MFMA16 `auto`/head-128 case, the final launch bound changes the generated resource use from 96 VGPR / 16 bytes scratch to 104 VGPR / 0 scratch. MFMA4 remains scratch-free; its tail checks are outside the full-warp hot path.
