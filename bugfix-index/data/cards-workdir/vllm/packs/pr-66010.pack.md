## 正文(PR 描述)

## Overview

Level 2 frees GPU memory by not keeping what can be rebuilt, and the only thing rebuilt on wake is what the weight update writes: parameters. Today it discards everything allocated while the model was built, because the weights pool wraps model construction. The rest then has to be rescued one site at a time: buffers by name, and everything held some other way is lost. With this change `sleep(level=2)` states what the caller rewrites and keeps the rest, at the same address. Part of the direct weight reload work (#54477, F11).

This replaces this PR's earlier site-by-site fixes (MXFP4 permute cache, DeepSeek-V4.1 `permute_on_load`, GEMM-RS/AR), which are reverted here because the rule covers them.

## Failures this addresses

All come from non-parameter state in the weights pool. Measured on GB200 without any fix:

| State | How it is held | Failure after a level-2 wake |
|---|---|---|
| GEMM-RS/AR peer pointer table from `symm_mem.rendezvous` | Inside the torch handle | Table reads all zeros, then `CUDA_ERROR_ILLEGAL_ADDRESS` on the first forward. Kimi-K3 placeholder weights, DeepSeek-V4.1-Flash with GEMM-RS |
| DeepSeek-V4.1 `permute_on_load` indices | Weight loader closure | GSM8K 0.90 → 0.0, and later reloads don't repair it |
| MXFP4 TRT-LLM permute cache | Quant method attribute | gpt-oss-20b GSM8K 0.375 → 0.0 |

The same pattern is in code but not measured: Inkling and Beam peer tables, DeepSeek-V4.1 Engram handles (#64922), plain attributes (#60009), attention impl state (#62634).

## Change

- `CuMemAllocator.sleep` and `XpuMemAllocator.sleep` take `discardable`: a weights allocation is discarded only if every live block in it starts at an address in `discardable`. An address that doesn't match keeps the allocation, so a wrong match costs host memory, not state.
- `Worker.sleep(level=2)` passes the storage addresses of the parameters the update rewrites, through `SleepModeBackend.suspend(discardable)`. That replaces `level`, which said the same thing: nothing discardable is level 1. It changes a plugin interface, so an out-of-tree backend must follow.

Kept tensors stay in `weights` and return on `wake_up(["weights"])`, so tags keep their meaning. Level 1 is unchanged.

## Removed

These existed to survive level 2, which now keeps them:

- Model state in the runtime pool (#63548), LoRA state in the runtime pool (#62358), and the MiniMax-M3 MSA prefill workspace in the runtime pool (#64856). All three are built during `load_model`; none is a parameter.
- The CPU copies of `named_buffers()`, on every platform.
- The separate CPU save and restore of `sleep_preserve_parameter_names`. Preserved parameters are now just not discardable, so their backup goes through the allocator: pinned where `PIN_MEMORY` is on, instead of pageable, and kept across wake for reuse.

Left in place: buffers registered for this reason (they are still correct as buffers), and the KV-init and CUDA graph runtime pools, which are outside `load_model`.

## Not covered

- Parameters the update doesn't write, such as those absent from the checkpoint: still discarded, as today. `sleep_preserve_parameter_names` is for those.
- `discard(tags)`: unchanged. Its only caller passes `kv_cache`.
- Weight-derived tensors that post-load processing doesn't refresh now keep old values instead of garbage. That is a separate bug class.
