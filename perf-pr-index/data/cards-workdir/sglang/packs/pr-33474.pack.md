## Motivation

The standard DeepGEMM dispatcher currently selects the masked layout from expert parallelism alone. However, masked workspace grows with the local expert count and padded forward size, so a fixed expert-count threshold can miss safe performance opportunities and can still select shapes that exceed available memory.

This follows the layout-selection discussion in [#33128](https://github.com/sgl-project/sglang/pull/33128#issuecomment-5162601075).

## Modifications

- Add `SGLANG_DEEPGEMM_STANDARD_LAYOUT={auto|masked|compact}`.
- Add `SGLANG_DEEPGEMM_MASKED_MEMORY_BUDGET_FRACTION`, with a default of `0.25`.
- Estimate masked peak workspace from the runtime token count, local expert count, model dimensions, activation dtype, and scale layout.
- Cache a budget from the minimum free memory across ranks after eager buffers are allocated and before graph capture. Capture paths do not query free memory or synchronize.
- Preserve explicit `masked` and `compact` overrides.

## Default Budget Calibration

`Captured M` is the aggregate token dimension of a captured prefill bucket, not the ISL of one request. The masked layout allocates a padded M dimension for every local expert, so its workspace grows approximately linearly with both `Captured M` and the local expert count. The policy estimates the largest live stage as:

```text
estimated_peak = local_experts * padded_M * max(
    input + input_scale + gateup_output,
    gateup_output + down_input + down_scale,
    down_input + down_scale + final_output,
)
masked_budget = capture_start_free_memory * budget_fraction
```

The following matched Qwen3.5-397B serving measurements on GB300 GPUs were used for calibration. All memory values are per GPU. Values marked with `~` are estimated peak workspace; allocation values are taken from the CUDA OOM report.

| Captured M | Local experts / topology | Masked memory | Serving result |
| ---: | ---: | ---: | --- |
| 8K | 512 / EP1 | ~34.2 GiB | Pass |
| 8K | 256 / EP2 | ~17.1 GiB | Pass |
| 8K | 128 / EP4 | ~8.5 GiB | Pass |
| 8K | 64 / EP8 | ~4.2 GiB | Pass |
| 16K | 512 / EP1 | ~67.3 GiB | CUDA Graph capture OOM |
| 32K | 512 / EP1 | 129 GiB allocation | OOM |
| 32K | 256 / EP2 | 64.5 GiB allocation | OOM |
| 32K | 128 / EP4 | ~33 GiB | Pass |
| 32K | 64 / EP8 | ~16 GiB | Pass |
| 128K | 64 / EP8 | 64.1 GiB allocation | OOM |

Immediately before CUDA Graph capture, the measured free memory was 170.48 GiB per GPU. The default follows from the observed boundaries:

1. The largest successful masked workspace was 34.2 GiB: `34.2 / 170.48 = 20.1%`.
2. The smallest masked workspace that failed was 64.1 GiB: `64.1 / 170.48 = 37.6%`.
3. A calibration value should therefore sit above 20.1% to retain every observed successful case and below 37.6% to reject every observed OOM case.
4. `0.25 * 170.48 = 42.62 GiB`, which is 8.42 GiB above the largest observed success and 21.48 GiB below the smallest observed OOM. It leaves 127.86 GiB, or 75% of capture-start free memory, for other graph pools, temporary activations, and allocator fragmentation.

The default is intentionally conservative rather than a universal memory guarantee. `SGLANG_DEEPGEMM_MASKED_MEMORY_BUDGET_FRACTION` remains configurable because model dimensions, dtype, capture buckets, and allocator behavior can move these boundaries.

## Accuracy Tests

This pull request does not change the numerical implementation of either standard DeepGEMM layout. Quantization, scatter, grouped matrix multiplications, activation, down projection, and post-permute are unchanged. It only replaces the previous expert-count selector with the memory-budget gate described above.

The underlying standard DeepGEMM path was already validated in [#33128](https://github.com/sgl-project/sglang/pull/33128) at [commit `02d9f2e642`](https://github.com/sgl-project/sglang/commit/02d9f2e642907ceadb60279165a9359a47d436b4). ## Speed Tests and Profiling

We compared the standard DeepGEMM masked and compact layouts on NVIDIA GB300 GPUs using Qwen3.5-397B-A17B-FP8 shapes. Apart from the explicit layout override, every matched pair used the same topology, workload, backend, and CUDA Graph settings. Only completed, exact-token, zero-error pairs are included. `M` is the aggregate number of MoE input rows.

Across all **50 valid matched comparisons**, masked was faster:

- Isolated standard runner: **24/24**, with **+40.4% to +160.7%** equivalent throughput.
- Full serving, ISL 8192 / OSL 1024: **12/12**, with **+14.34% to +41.39%** total TPS/GPU.
- Prefill, OSL 1: **14/14**, with **+2.69% to +68.25%** total TPS/GPU.
