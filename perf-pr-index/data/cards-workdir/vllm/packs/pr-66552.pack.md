## Overview

Two Engram changes for DeepSeek-V4.1:

1. **128-row lookup tiles.** Large Engram lookups are latency bound on their reads. Once the rows fill the persistent grid with 128-row tiles, the lookup now uses them (with 8 warps) instead of 16-row tiles, so each program keeps 8x the reads in flight. Packed rows are copied 8 bytes per load instead of a byte, with both loads issued before the stores. Smaller lookups keep 16-row tiles. The rows read and written are unchanged.
2. **GPU tables split across engines.** Engines in one NVLink domain, such as the prefill engines of a disaggregated deployment, can now split each Engram GPU table's rows over all of their GPUs:

   ```bash
   --engram-config '{"cpu_offload": false, "peer_group_size": 8,
                     "peer_group_store": "/shared/job-dir/engram-peers"}'
   ```

   Each GPU holds 1/`peer_group_size` of every table, and lookups read the other rows from their owner's HBM through the existing peer-read path (#62091), so no engine's step waits on another's. This frees the host memory of a CPU-offloaded copy per engine (188.8 GiB for DeepSeek-V4.1-Flash's two tables), e.g. for a host KV cache tier, without a whole table on any GPU.

Related: #64609 (closed) used 128-row tiles for sorted host lookups only; this keys the tile size on the row count instead, which also covers unsorted lookups from THP host tables (`use_thp`) and HBM tables. #64082 (draft) shares *host* tables across independent instances through a persistent owner process with leases; this PR instead splits *GPU* tables peer to peer, with no extra process and no coordination after startup.

## Claims

- Tiles: DeepSeek-V4.1-Flash prefill, DEP2 on GB300, Engram `cpu_offload` with `use_thp=true` (the InferenceX GB300 prefill setting): 12-33% faster per step, and the step time no longer swings by 50-70% between samples. With `use_thp=false` (sorted small-page lookups) the step time is unchanged (within 0.07%). Output is bitwise identical.
- Split tables: each GPU holds 188.83 GiB / `peer_group_size` of the tables and the engines keep no host Engram tables. Per GPU of a DEP2 engine:

  | tables | HBM | host |
  |---|---:|---:|
  | GPU, split over the engine's 2 GPUs (`cpu_offload: false` today) | 94.42 GiB | 0 |
  | host, shared by the engine's 2 GPUs (`cpu_offload: true`, the default) | 0 | 94.42 GiB |
  | GPU, split over 8 GPUs of 4 engines (this PR) | 23.60 GiB | 0 |
  | GPU, split over 18 GPUs of 9 engines (this PR) | 10.49 GiB | 0 |

  Measured: going from 4 to 8 GPUs per group gives every GPU 23.57 GiB more KV cache (expected 23.60). Lookups are bit-exact with the reference; GSM8K is unchanged.

## Design (split tables)

- Symmetric memory cannot span engines: they share no process group, and its rendezvous rejects equal device ordinals on one node, which every engine's ranks have. Each GPU therefore allocates its slice with cuMem, exports a FABRIC handle, and maps every other GPU's slice.
- The engines meet once, at startup, through a torch `FileStore` at `peer_group_store`: ranks come from an atomic counter, exchanges are numbered in order (every GPU builds and loads the same tables in the same order), and each GPU publishes its handle. Nothing reads the store after startup. A path on the job's shared filesystem works without knowing any host address at launch.
- `ParallelEngramEmbedding.process_weights_after_loading` synchronizes and waits until every GPU of the group has loaded its rows, since peers read them directly. It now does the same for the existing in-engine peer tables: their test read peers' rows with no wait and passed only on timing.
- Each process unmaps its view of every slice when the table goes away (a finalizer on an object the table and its slice tensor hold), and a slice's HBM is freed once every GPU has done so. While any peer is alive it keeps a dead engine's slice mapped, so restarting one engine means restarting the group.
- Limits: DeepSeek V4.1 (Qwen4Exp is a TODO), TP=1, PP=1 (stages build different tables), tables in HBM, CUDA FABRIC handles (an IMEX channel), and no weight reloads (other engines read the rows at any time; the in-engine peer tables still reload). The store path must not exist before the group starts (its directory is created). The peer slices are allocated outside torch, so "Model loading took" does not include them; the KV cache, sized from free memory, does.

+class EngramPeerGroup:
+    """GPUs of several engines that split each Engram table over their HBM.
+
+    They meet only at startup, through a file store; lookups then read peers'
+    rows directly, so no engine's step ever waits on another's. Every GPU
+    builds and loads the same tables in the same order, so its n-th exchange
+    is every peer's n-th.
+    """
+
+    # Engines load their weights at their own pace before the group can serve.
+    TIMEOUT = timedelta(minutes=30)
+
+    def __init__(self, size: int, path: str) -> None:
+        self.world_size = size
+        os.makedirs(os.path.dirname(os.path.abspath(path)), exist_ok=True)
+        self.store = torch.distributed.FileStore(path, size)
+        self.store.set_timeout(self.TIMEOUT)
+        # Any assignment works: a rank only decides which rows a GPU holds.
+        self.rank_in_group = self.store.add("next_rank", 1) - 1
+        if self.rank_in_group >= size:
+            raise RuntimeError(
+                f"More than {size} GPUs joined the Engram peer group at {path}; "
+                "check peer_group_size and use a fresh store path per launch"
+            )
+        self._step = 0
+
+    def all_gather(self, value: bytes) -> list[bytes]:
+        """Every GPU's value for the next exchange in rank order, once all have
+        set theirs."""
+        self._step += 1
+        key = f"step{self._step}"
+        self.store.set(f"{key}/{self.rank_in_group}", value)
+        keys = [f"{key}/{rank}" for rank in range(self.world_size)]
+        try:
+            self.store.wait(keys)
+        except RuntimeError as exc:
+            missing = [
+                rank for rank, name in enumerate(keys) if not self.store.check([name])
+            ]
+            raise TimeoutError(
+                f"Engram peer GPUs {missing} did not reach startup step "
+                f"{self._step} within {self.TIMEOUT}; every engine of the group "
+                "must start, and none may restart alone"
+            ) from exc
+        return [self.store.get(name) for name in keys]
+
+    def barrier(self) -> None:
+        self.all_gather(b"")
