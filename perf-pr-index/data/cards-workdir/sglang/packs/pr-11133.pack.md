## Motivation

MTP spec decoding top>1 is not supported in Qwen3-Next & FLA. This PR adds the support.

<img width="400" height="87" alt="Screenshot 2025-11-02 at 10 54 05 PM" src="https://github.com/user-attachments/assets/fef1f8b1-f9a6-448b-9f3a-4a3ebefe8150" />

The overall idea of this PR is:
- Build a parent pointer list for each draft token
- Use parent's **State** to calculate the new **State**:  

$$
\mathbf{S}_{[current]} = \mathbf{S}_{[parent]} + \mathbf{V}_{[current]} \mathbf{K}_{[current]}^{\mathsf{T}} \in \mathbb{R}^{d_v \times d_k}
$$




## Modifications

**Eagle Tree Attention Mask Support:**

* Added support for a custom eagle tree attention mask in the fused recurrent attention kernel and _causal_conv1d_update_kernel, including new logic and heuristics for handling parent token relationships [[1]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R320-R343) [[2]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R360-R364) [[3]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R379) [[4]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R406-R415) [[5]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R441-R458) [[6]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R539) [[7]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R558-R567) [[8]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R581-R585) [[9]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R624) [[10]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R641) [[11]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R671) [[12]](diffhunk://#diff-2946e8dc9622cfa2ed512c51247387c92aef622aeab6cda5e72e3760f56bd156R708):
  * e.g. for a sequence of length 4, the eagle tree attention structure is:
  * retrieve_next_token=[1, 3, -1, -1] -> retrieve_next_token[i]: the 1st child token of token i
  * retrieve_next_sibling=[-1, 2, -1, -1] -> retrieve_next_sibling[i]: the 1st tree sibling token of token i
  * retrieve_parent_token=[n/a, 0, 0, 1] -> retrieve_parent_token[i]: the parent token of token i
```
# Tree:
#    0
#   / \
#  1   2
# /
# 3
```
  *  When calculating token 3's convolution & attention, it should conv/attn to token 1 (parent) and token 0 (grand-parent)
  *  When calculating token 2's convolution & attention, it should conv/attn to token 0 (parent)
  * Before this PR, token N can only conv/attn to token N-1, N-2, ... sequentially

**Eagle Worker Logic Adjustments:**

* Adjusted logic for spec decoding state updates to use accepted indices instead of accepted lengths. [[1]](diffhunk://#diff-08c36be6178f7d7b0c98fe35fec32cbc83a50f147c11a0b54e265fa46e567742L567-R641) [[2]](diffhunk://#diff-08c36be6178f7d7b0c98fe35fec32cbc83a50f147c11a0b54e265fa46e567742L586-R663). After eagle verify, we need to pass the last accepted/verified id to hybrid_linear_attn_backend so it can overwrite current seq's mamba related cache with the last accepted/verified token's mamba cache:
  * Before this change, it always overwrite with `accept_length - 1` token's mamba cache. For example, for accepted token IDs [0,1,2,3,4], overwrite the current seq's mamba cache with token ID `accept_length-1=4's` mamba cache works for topk=1
  * However, for topk>1, for one seq, the accepted token IDs may be `[0, 2, 4, 6, 7]` so mamba cache should be updated with token ID `7's` mamba cache instead of token ID `accept_length-1=4's` mamba cache

**Minor Fixes:**

* Commented out a Triton debug barrier that is no longer needed due to compiler bug fixes.
