## 正文(PRD / 提案全文)

### Motivation.

vLLM supports **Prefill/Decode (P/D) disaggregation**, where prefill and decode are executed in separate vLLM instances and communicate via connector abstractions such as `KVConnectorBase_V1`. A key motivation of this design is to prevent prefill work from interrupting decode execution and to improve tail inter-token latency (ITL) under high concurrency.

In the current vLLM v1 design, P/D disaggregation typically transfers **KV cache only** from the prefill worker to the decode worker. As a result, the decode worker must still recompute the **last-token hidden states** in order to sample the first output token. This recomputation is implemented by scheduling a **decoder-side prefix prefill**, leveraging existing prefix caching infrastructure.

While functionally correct, this design introduces performance issues in certain deployment configurations.

### Deployment context

This RFC is motivated by deploying **DeepSeek-R1 (MLA attention)** on Intel accelerators (Gaudi and Intel XPU) with the following configuration:

- **Prefill**: Tensor Parallel (TP)
- **Decode**: Data Parallel (DP)
- **Connector**: NIXL connector with GDR enabled

1. **Decode pipeline interruption**  
   Decoder-side prefix prefill injects prefill-style computation into the decode execution timeline. Hardware event traces show that:
   - steady-state decode steps execute in a stable regime (tens of milliseconds),
   - prefix-prefill injections introduce large step-time spikes (hundreds of milliseconds to seconds),
   - these spikes directly inflate TPOT and tail ITL,
   - the effect worsens with higher concurrency and longer context lengths.

2. **Inefficiency under DP decode for MLA**  
   For MLA models, DP decode is often preferred. However:
   - prefix prefill is also scheduled in DP mode,
   - only one DP rank is required to produce hidden states for sampling,
   - other ranks perform redundant or dummy work,
   - this causes unnecessary token dispatch overhead and scheduler pressure.

These issues contradict the original goal of disaggregated prefilling: **keeping decode execution in a stable steady state**.

The decode worker already has all required information to proceed **if last-token hidden states are available**, making the decoder-side prefix prefill fundamentally avoidable.

### Proposed Change.

This RFC proposes an **optional, backward-compatible enhancement** to `KVConnectorBase_V1` (v1-only) to transfer **last-token hidden states** alongside KV cache under P/D disaggregation.

### High-level design

When enabled, the prefill worker transfers:

- KV cache blocks (existing behavior), and
- **last-token hidden states** corresponding to tokens that are ready for decoding.

The decode worker can then:

1. Receive KV cache and hidden states
2. Perform **sampling only** for the first token
3. Immediately enter steady-state decoding without scheduling a decoder-side prefix prefill

This preserves the existing async scheduling model while eliminating decode pipeline interruptions caused by prefix prefill.

### Hidden states definition

- Tensor: `hidden_states_last`
- Shape: `(num_tokens, hidden_dim)`
- Semantics: final-layer hidden states corresponding to the *last prefill token* for each token ready for decoding
- Dtype: model activation dtype (e.g., bf16 / fp16), consistent with the input to `lm_head`

> `num_tokens` is used instead of `batch_size` to reflect vLLM’s token-centric scheduling model. It may differ from request count due to chunked prefill, prefix caching, or scheduler packing.

### Tensor Parallel prefill considerations

For TP prefill:

- hidden states may be sharded across TP ranks,
- the prefill worker should materialize full `(num_tokens, hidden_dim)` hidden states on a designated producer rank (e.g., TP rank 0),
- only the materialized tensor is transferred to the decode worker.

This avoids requiring TP collectives on the decode side.

### Decode behavior (DP decode)

When hidden states transfer is enabled:

- A single DP rank (e.g., local rank 0) computes logits and performs first-token sampling.
- Sampled token IDs are broadcast to other DP ranks using existing mechanisms.
- The scheduler proceeds with normal decode steps.

No changes are required to async scheduling semantics.

### Configuration and compatibility

- The feature is **opt-in** (disabled by default).
- Applies to **vLLM v1 only** (`KVConnectorBase_V1`).
- Existing behavior is preserved when the feature is disabled or unavailable.
- If hidden states transfer fails at runtime, the system falls back to the existing decoder-side prefix prefill path to preserve correctness.

### Lifecycle considerations

Hidden states are **ephemeral model outputs** and are not managed by an existing cache allocator. Implementations are expected to:

- manage hidden states with a request/token-scoped lifecycle,
- ensure deterministic reclamation after sampling,
- avoid introducing long-lived cache semantics.

One possible implementation approach is to use pre-registered, connector-managed ephemeral buffers (similar in spirit to encoder cache registration in NIXL-based designs), but the exact mechanism is left to implementation.

---

This change aligns with broader vLLM efforts toward richer intermediate tensor transfer (e.g., fully disaggregated pipelines and encoder–prefill disaggregation) while keeping the scope narrowly focused on eliminating unnecessary decoder-side prefix prefill for improved decode latency and efficiency.
