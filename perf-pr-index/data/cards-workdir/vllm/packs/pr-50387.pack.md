## PR body
```markdown
## Purpose

Sync `csrc/cpu/sgl-kernels/` from sglang (`sgl-kernel/csrc/cpu`) to latest upstream `main`, reconciling vLLM-specific patches layered on since the last bump (#41924): MXFP4 W4A16 MoE, AMX GDN dispatch, ISA-portability BLAS fallback, RISC-V scalar/RVV support, chunked-prefill `has_initial_state` fix, DFlash speculative decoding, and batched spec-decode conv-state updates. Also rejects one upstream regression found during merge (a broken `TORCH_CHECK` for MXFP4 scale validation that would have silently weakened a size check).

Adopts SGLang's new pooled-state-indexing `chunk_gated_delta_rule_cpu` signature for GDN prefill: the CPU GDN path now reads/writes the pooled `ssm_state` buffer directly via `initial_state_indices` instead of gathering a local copy first, avoiding an extra copy per prefill call. Made the kernel read `initial_state`'s actual `stride(0)` at runtime (mirroring `conv.cpp`'s `conv_state_slot_stride`) instead of assuming a fully packed layout, since pool buffers can be padded per slot (e.g. Qwen3.5's Mamba cache-align mode).

Not a duplicate of any open PR — searched `gh pr list` for sgl-kernel/CPU-kernel-bump related terms, no matches.

AI assistance (Claude) was used to fetch/diff upstream sglang, reconcile merge conflicts against vLLM-specific patches, and run the validation below. All changes were reviewed and tested by the submitting human.

## Test Plan

- Build: `VLLM_TARGET_DEVICE=cpu python3 setup.py develop` (`_C`, `_C_AVX512`, `_C_AVX2` targets)
- Correctness: `tests/quantization/test_cpu_wna16.py` / `test_cpu_w8a8.py` model list (12 models covering AWQ/GPTQ/compressed-tensors W4A16, FP8 W8A16 dense/MoE, MXFP4, INT8 W8A8 MoE) via offline inference, before vs. after this change
- `Qwen/Qwen3.5-35B-A3B`: multi-sequence prefill, prefix-cache reuse (`has_initial_state=True` path)
- `vllm serve` + `vllm bench serve` before/after on 4 models (w8a8, w4a16, FP8 MoE, Qwen3.5)
- `lm_eval` GSM8K (200 questions, 5-shot, chat template, `max_model_len=16384`, `max_gen_toks=8192`) on `Qwen/Qwen3.5-35B-A3B`, before vs. after

## Test Result

- Build succeeds cleanly on all three CPU ISA targets.
- All 12 quantization models produce coherent output; 10/12 byte-identical to the pre-bump baseline under greedy decoding, 2 diverge after the first token (`gpt-oss-20b` MXFP4, `Qwen3-30B-A3B-GPTQ-Int4`) consistent with quantized-kernel numerics shifting a near-tied argmax, not a functional break.
- Qwen3.5 GDN: coherent generation across fresh-state and prefix-cache-reuse prefill paths.
- Serving benchmarks: throughput/latency within noise (±3%) for the three MoE GEMM paths (w8a8, w4a16, FP8); Qwen3.5 GDN path improved 3-8% across throughput/TTFT/TPOT from the pooled-gather optimization.
- GSM8K: before `0.795/0.785` (flexible/strict exact_match), after `0.835/0.795` — within one standard error, no regression.
```
