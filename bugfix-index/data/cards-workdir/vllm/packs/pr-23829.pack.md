## 正文(PR 描述)

[bugfix, spec-decoding] fix data race in sample_recovered_tokens_kernel (vLLM V1)


## Purpose

This PR resolves a data race bug in the `sample_recovered_tokens_kernel` Triton kernel.

The original implementation temporarily modifies `target_probs_ptr` to zero out a token's probability before restoring it. This is unsafe in a multithreaded environment where multiple GPU threads could concurrently access and modify the same memory address, leading to non-deterministic behavior and correctness issues.

During the development of speculative sampling in vLLM V1, we found that this data race causes different Tensor Parallelism (TP) GPUs to produce inconsistent speculative decoding verification results. Once inconsistent verification results occur, the GPU will hang (ref https://github.com/vllm-project/vllm/pull/17929).

This change replaces the unsafe read-modify-write pattern with a safer, atomic-friendly approach using a mask. Instead of modifying the memory, the kernel now uses a mask during the tl.load operation to directly set the probability of the draft token to 0. This change maintains the original logical intent while eliminating the data race and potentially improving performance.

This bug was identified and fixed during the development of the HistoSpec RL project (https://www.alphaxiv.org/abs/2508.18588v1), where we extended vLLM v1's speculative decoding to accelerate reinforcement learning training for LLMs.

## Test Plan

1. A full integration test with speculative decoding enabled is required to verify its correctness.
2. Deploy LLMs (we test Qwen2.5-7B/14B/32B, Qwen3-8B/14B) with TP>=2 and enable spec decoding to test its correctness when TP>=2.

## Test Result

This modification is internally used for thousands of GPU hours.


1. The change has been locally verified, and the speculative decoding pipeline functions correctly with this modification, without any observed issues or performance degradation.
2. After applying the fix, speculative decoding functions correctly with TP>=2. The issue of GPU hangs caused by inconsistent verification results across different TPs has been resolved.
