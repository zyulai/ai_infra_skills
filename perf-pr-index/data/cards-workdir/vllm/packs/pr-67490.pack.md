## Overview

Enable HY4 sparse-MLA ShardQ prefill by gathering checkpoint-loaded attention sinks in TP head order. Reuse the existing token split, attention kernels and eligibility checks.

## Claims

- Enable token-sharded prefill for the target backbone with MTP3 enabled.
- On 8×H200, prefill-only throughput improves **59.10% at ISL8192** and **62.53% at ISL32768**, with OSL1 and saturated requests.
- Preserve sink values across CPU-staged loading, checkpoint reload and CUDA graph replay.

## Validation

PR source `25227c86327a0acf3e9d502286028df5db57000c` on frozen main `329f93e1909efdd4548524b1500fa2c54ef2cbb0`, rebuilt CUDA extensions, `tencent/Hy4-preview-FP8`, TP8/DP1/EP8, ModelOpt MXFP8, default Humming MoE, `fp8_ds_mla` KV and natural MTP3. Default graph mode, memory utilization and sequence limits, with `max_model_len=262144`.

Tested packages include `torch 2.14.0`, `triton 3.8.0`, `flashinfer-python 0.7.3`, `humming-kernels 0.1.19`.

Same-GPU serial A/B/A, three seeds per arm, warmups excluded and profiling in separate runs. Each run uses 128/32/16 requests at ISL2048/8192/32768, respectively, OSL1 and RPS∞. Means below pool the six main runs and three PR runs. Every request succeeded with the expected input/output token counts.

## Details

ShardQ computes all query heads for each rank's token slice, so HY4's learnable sink must follow the full-head layout during prefill. Gather it once during weight finalization on the TP execution device, and update the cache in place on reload to preserve graph references. Decode uses the local sink layout.

Throughput was measured before the loading-only CPU-staging fix and comment/log cleanup. The final production files were then revalidated with the real checkpoint, 20-shot GSM8K, matching profiles and the sink regression suite.

This extends the shared ShardQ machinery to HY4's model-local sink backend. The earlier norms/A-projection extension covers the DeepSeek-V3.2 / GLM-5.3 model package. [#66549](https://github.com/vllm-project/vllm/pull/66549)

Open-PR searches for HY4/Hy4 ShardQ found zero matching implementations. The open DSv4.1 sink/token-sharding extension and shared route-selection refactor cover separate changes.

AI assistance was used for implementation, review, and validation.
