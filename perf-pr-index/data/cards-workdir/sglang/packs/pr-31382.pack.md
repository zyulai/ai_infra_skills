## Motivation

Qwen3.5 ModelOpt FP4 checkpoints keep the embedded MTP draft expert weights in BF16. `nvfp4_online` converts these weights to NVFP4 during loading, but previously supported only the FlashInfer TRT-LLM MoE runners.

This PR enables the existing FlashInfer CuTe DSL MoE paths for the online-quantized draft model.

## Modifications

- Preserve explicit `nvfp4_online` selection for the embedded Qwen3.5 MTP draft model.
- Support `flashinfer_cutedsl` with FlashInfer A2A or DeepEP `low_latency`.
- Reuse the existing CuTe DSL weight layouts and registered DeepEP runner.
- Resolve speculative MoE backends during FlashInfer autotuning and skip the unsupported DeepEP low-latency dummy dispatch.
- Reject non-floating source expert weights to avoid re-quantizing packed FP4 weights.

No new kernels, server arguments, or checkpoint formats are introduced.

## Accuracy Tests

Qwen3.5-397B-A17B-NVFP4, 4x GB300, TP/DP/EP=4, EAGLE with 3 steps and 4 draft tokens:

| Draft MoE path | Job | GSM8K (100) | Mean accept length | Mean accept rate |
|---|---:|---:|---:|---:|
| DeepEP + DeepGEMM, BF16 draft | `2390431` | 0.990 | 3.4472 | 0.8157 |
| FlashInfer A2A + CuTe DSL, `nvfp4_online` | `2390433` | 0.990 | 3.4206 | 0.8068 |
| Delta | - | 0.000 | -0.77% | -1.09% |

Both jobs completed 100/100 examples with all required CUDA graphs closed and no fallback or runtime errors. Acceptance evidence had 96.1% pair coverage.

Earlier full GSM8K qualification produced:

## Speed Tests and Profiling

4x GB300 aggregate serving, TP/DP/EP=4, CUDA Graph enabled, random 1k input / 1k output, concurrency 64, 64 completed requests per run. M0/M1 values are medians across three runs; M2 is one run.

| Draft MoE path | Jobs | Output tok/s | Mean TPOT | Relative to M0 |
|---|---|---:|---:|---:|
| DeepEP + DeepGEMM, BF16 draft (M0) | `2385387`, `2385486`, `2385488` | 5,377.303 | 8.9780 ms | Baseline |
| FlashInfer A2A + CuTe DSL, `nvfp4_online` (M1) | `2385329`, `2385487`, `2385490` | 5,621.619 | 8.5038 ms | +4.543% throughput, -5.282% TPOT |
| DeepEP low-latency + CuTe DSL, `nvfp4_online` (M2) | `2385485` | 5,662.671 | 8.5514 ms | +5.307% throughput, -4.752% TPOT |

This is an end-to-end MTP treatment: A2A, runner, and draft precision change together, so the deltas are not isolated CuTe DSL-versus-DeepGEMM kernel results.
