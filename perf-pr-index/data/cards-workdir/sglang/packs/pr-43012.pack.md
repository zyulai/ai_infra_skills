## PR body
```markdown
## Motivation

https://github.com/sgl-project/sglang/pull/42297 added `--speculative-use-block-verification` ([Block Verification Accelerates Speculative Decoding](https://arxiv.org/abs/2403.10444), Algorithm 2) for linear EAGLE / EAGLE3 / NEXTN only. The DFlash family (`DFLASH`, `DSPARK`) already verifies sampled drafts through the same Triton chain sampler, but the flag was rejected for these algorithms at startup.

## Modifications

- **Startup gate** (`speculative_hook.py`): accept `DFLASH` and `DSPARK` with `--speculative-use-block-verification` on CUDA/ROCm. NPU stays rejected because `sgl_kernel_npu`'s chain sampler has no block mode. Only EAGLE/EAGLE3 still auto-enable `--speculative-use-rejection-sampling`. DFlash-family sampled paths always pass their proposal distribution and never read that flag.
- **Shared accept path** (`dspark_accept.py`): `AcceptSampling` / `accept_sampling` / `_accept_sampling_core` take an explicit `block_verification` keyword and call `chain_speculative_sampling_triton(..., block_verification=True)` when it is set. The kernel is unchanged from #42297.
- **Callers**:
  - DSpark: `DSparkWorkerV2` passes the flag to `TargetVerifyExecutor`, which forwards it through `accept_draft_tokens` to both the all-sampling branch and the mixed greedy/sampling branch.
  - DFlash: `DFlashWorkerV2._selector_sampling_accept` forwards it. This method serves the candidate-selector drafts and the sampled LiLiCorr drafts (`SGLANG_ENABLE_LILICORR_SAMPLING=1`).
- **Greedy DFlash drafts**: plain DFlash, Domino, and LiLiCorr without sampling propose argmax tokens. The proposal is a point mass, so `q(x_i) = 1`, `r_i = prod p(x_j)`, and token-wise verification already reaches the per-prefix upper bound `P(accept >= i) = r_i`. Block verification therefore accepts the same prefixes, so these paths keep the existing target-only verifier. The worker logs a warning that the flag has no effect.
- Ragged/cutoff verify (`cutoff_verify_lens`) still truncates the sampler's result afterward, as it does in token-wise mode. A prefix of a target-distributed sample is still target-distributed, so the cutoff does not affect correctness.
- Updated the docs and the CLI help.

## Accuracy Tests

- `test_block_verification_args.py`:
  - DFLASH/DSPARK are accepted, and block verification does not switch on rejection sampling for them. The per-algorithm handlers are patched out because they need a real draft checkpoint.
  - DFLASH/DSPARK on NPU are rejected.
  - The rejected-algorithm case moves from DFLASH to NGRAM.
- `test_block_verification.py::test_dflash_family_accept_uses_block_verification` (GPU): calls DSpark's real `accept_draft_tokens`, in both the all-sampling and the mixed-greedy branches. The proposal uses `q(x1) = 1, p(x1) = 1/2` and `q(x2) = 1/2, p(x2) = 1`, so `r_1 = 1/2` and `r_2 = 1`.
  - With block verification, every sampled row accepts both drafts and the bonus token from the target.
  - Without it, each row rejects the first draft with probability 1/2, so the test asserts that at least one of 63 rows does.
