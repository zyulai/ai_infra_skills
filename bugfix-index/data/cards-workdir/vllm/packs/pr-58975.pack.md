## 正文(PR 描述)

## Purpose

Fixes #33865.

When EngineCore reports a multi-modal processor cache miss, it returns a
terminal `FinishReason.ERROR` output with `mm_cache_miss_hashes`. Pooling
requests do not have a detokenizer, but OutputProcessor previously followed
the generation path when the error output did not contain a pooling tensor.
The resulting `req_state.detokenizer is not None` assertion killed the shared
output-handler task and shut down the server.

This PR:

- represents terminal pooling failures with a structured `RequestError`;
- keeps the output handler healthy and allows unrelated requests in the same
  EngineCore output batch to complete;
- propagates the error through embedding, classification, and scoring output
  conversions;
- short-circuits bi-encoder, late-interaction, and Jina scoring post-processing
  before the placeholder tensor can be used in score calculations;
- maps retryable online pooling failures to HTTP 503
  `ServiceUnavailableError` so clients can retry the request;
- invalidates multi-modal cache-miss hashes in synchronous `LLMEngine.step()`,
  matching the existing `AsyncLLM` behavior;
- releases cached late-interaction query embeddings after query/document
  failures or cancellation, including document cache misses before worker
  registration; and
- assigns request-scoped late-interaction document IDs so cleanup cannot abort
  documents from concurrent requests that share an `X-Request-Id`.

## Why this is not duplicate work

The required issue and open-PR searches were rerun immediately before opening
this PR. No open PR implements this pooling OutputProcessor fix.

- #44543 only appears because it mentions #33865 as related work. It fixes
  audio/video cache coupling inside the multi-modal processor cache, not the
  terminal pooling error path.
- #40986 handles zero-token error ordering in Chat/Completion SSE streams. It
  does not change pooling outputs or the pooling OutputProcessor path.

accuracy; it only changes handling of terminal request errors and cleanup of
