## 正文(PRD / 提案全文)

# [RFC][NPU][DLLM] Fused tracker and coreset kernels for LLaDA2 JointThreshold

## Summary

Two NPU-only fused kernels for the LLaDA2.1-mini dLLM JointThreshold decode path on Ascend,
replacing per-layer small-op swarms in MoE expert tracking and coreset keep-mask selection with
single kernels, behind a runtime flag with a pure-Torch fallback. On GSM8K (n=50) they deliver
**+5.14% output throughput at identical accuracy (92.0%)**. This RFC proposes kernel placement and
the kernel → release → integration upstream sequence.

## Motivation

In the JointThreshold decode loop, two operations run per MoE layer per denoising forward:
1. the history-gate tracker max + EMA update, and
2. the per-call coreset keep-mask selection (softmax-sum score → group-balanced top-q).

On NPU these are dispatch-bound: each is a handful of small kernels whose host launch cost
dominates their compute, so the device idles between launches. Fusing each path into one kernel
removes those launches from the decode critical path without changing the selection semantics.

## Proposed kernels

1. **`moe_gate_max_update`** — fuses the per-expert running-max update and the EMA update into
   one NPU kernel (replaces a `torch.maximum(...)` + `mul_`/`add_` pair per layer).
2. **`moe_shortlist_mask`** — computes the per-call coreset selection (bf16-rounded softmax-sum
   score; exact top-q-per-group with lowest-index tie-break, matching `torch.topk(q)`), writes the
   keep-set, and masks dropped experts, in one HBM round-trip (replaces ~6–10 small vector ops per
   layer).

Both are NPU-only and shape-specialized to the current LLaDA2 MoE (E=256, 8 groups). The Python
integration uses them only when enabled; otherwise the existing Torch path runs unchanged.

## Upstream sequence (kernel / release / integration)

Kernel source and the SGLang Python caller land as separate PRs because the kernel package is
released separately:

1. **[sgl-kernel-npu] Kernel source PR** — add the two ops + bindings + a correctness test.
2. **[sgl-kernel-npu] Release** — a maintainer ships a release containing the new ops.
3. **[sglang] Python integration PR** — env-gated NPU-only call sites with Torch fallback, depending
   on the sgl-kernel-npu release that contains the ops.

Target repos: kernels → `github.com/sgl-project/sgl-kernel-npu`; Python → `github.com/sgl-project/sglang`.

## Guarded-fallback design (integration PR)

The integration is NPU-only and guarded; CUDA/default execution is structurally untouched because
the kernels are NPU-only. The call site checks: `device.type == "npu"`, fp32 dtype + contiguity, op
availability (`hasattr(torch.ops.npu, "moe_gate_max_update")` / `"moe_shortlist_mask"`), and
the runtime flag — otherwise it runs the existing Torch path. The model still loads and serves
when the kernels are not present; the Torch path simply runs.

## Evidence

GSM8K (n=50), Ascend 910B3, LLaDA2.1-mini, SGLang dLLM JointThreshold. Control runs the identical
recipe and runtime-flag stack with the two new kernels off (`TRACKER_MAX_UPD_KERNEL=0`,
`PERCALL_KEEP_KERNEL=0`).

| Run | Accuracy | Output TPS | Elapsed |
| --- | ---: | ---: | ---: |
| Control (kernels off) | 46/50 = 92.0% | 355.107 | 42.68 s |
| + tracker-max-update + coreset-keep kernels | 46/50 = 92.0% | 373.346 | 40.60 s |

Δ = **+18.24 tok/s (+5.14%)** at identical accuracy. Next: extend to n ≥ 100 and add a per-op
fallback equivalence test.

Excluded from this RFC: cbout, maxfold, tracker sum-update, and deferred-flush variants. They were
tested locally but were not reproducible release candidates.
