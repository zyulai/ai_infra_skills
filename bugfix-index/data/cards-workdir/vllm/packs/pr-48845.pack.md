## 正文(PR 描述)

## Purpose

The gfx950 AITER MLA persistent-decode regression test
(`tests/kernels/attention/test_rocm_aiter_mla_decode_metadata.py`) started
failing on `main` due to a collision between two bugfixes:

- **#46997** added the test *and* the `dtype_q`/`dtype_kv` forwarding to
  `aiter.get_mla_metadata_v1`. At that point the decode **query** dtype was
  `bf16`, so the test pinned `EXPECTED_Q_DTYPE = torch.bfloat16`.
- **#47276** (a later bugfix, *"Fix memory access fault in AITER MLA backend for
  DPA+FP8 KV"*) intentionally set the decode query dtype to **fp8** on the
  gfx950 DPA + FP8 KV path to avoid a memory access fault. This is the correct
  runtime behavior, but the regression test from #46997 was not updated, so it
  now fails: the builder correctly forwards `dtype_q=fp8`, while the test golden
  still recomputes the split/reduce metadata with `dtype_q=bf16`, producing a
  different layout for fields `work_indptr`, `work_info_set`, `reduce_indptr`,
  `reduce_final_map`, `reduce_partial_map`.

This PR aligns the (stale) test with the current, correct builder behavior: for
the fp8 KV-cache decode path the query dtype forwarded to
`get_mla_metadata_v1` is `fp8`. It updates `EXPECTED_Q_DTYPE` and `EXPECTED_KV_DTYPE` to
`current_platform.fp8_dtype()` and refreshes the accompanying comment to reference
#47276. No production code is changed — this is a test-only fix.

## Test Plan

Run the previously failing regression test on a gfx950 (MI355X) host inside the
ROCm test image:

```bash
pytest -q tests/kernels/attention/test_rocm_aiter_mla_decode_metadata.py::test_persistent_decode_metadata_matches_fp8_golden
```

## Test Result

Before this change the test failed with:

```
AssertionError: AITER MLA persistent decode metadata does not match the fp8/bf16
golden for fields ['work_indptr', 'work_info_set', 'reduce_indptr',
'reduce_final_map', 'reduce_partial_map']; the builder must forward
dtype_q/dtype_kv to get_mla_metadata_v1.
```

After this change the test passes:

```
======================== 1 passed, 16 warnings in 6.52s ========================
```
