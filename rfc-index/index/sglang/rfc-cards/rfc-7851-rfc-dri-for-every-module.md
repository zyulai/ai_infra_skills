## 一句话结论
把每个模块的 DRI(直接责任人)名单公开,解决社区 PR 延迟、贡献者不知联系谁的协作问题。

## 提案动机
SGLang 现在已有大量功能与模块,新功能、优化与 bug 修复多线并行。每个模块内部其实已有 DRI(Directly Responsible Individual),但这些指派从未公开;结果是部分社区 PR 处理延迟,贡献者不知道该联系谁。(pack 正文较短,以上为正文全部动机内容。)

## 提出的方案
- 在接下来两周内公开 DRI 名单。
- 在一个专门的公共 channel 中积极跟进,期待与社区更紧密协作。

正文未给出量化数字。收益属流程/协作改进:缩短社区 PR 的响应路径、明确每个模块的负责人,非性能优化。
