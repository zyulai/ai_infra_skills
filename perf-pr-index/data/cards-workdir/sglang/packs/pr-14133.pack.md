## Motivation

Get inspiration from https://github.com/vllm-project/vllm/pull/29642. Thanks.


This PR optimizes the `moe_align_block_size` kernel with two key improvements:

1. **Parallel filling of `sorted_token_ids`**: Use a separate group of threads to initialize `sorted_token_ids` in parallel, reducing initialization overhead.

2. **Dynamic `max_num_tokens_padded` calculation for small batches**: When the number of tokens is less than the number of experts, use a smaller padding value (`topk_ids.numel() * block_size`) instead of the original formula (`topk_ids.numel() + num_experts * (block_size - 1)`), significantly reducing memory allocation and improving performance.

## Performance Impact

**Small batch scenarios** (tokens < experts):
- **Memory reduction**: Up to 96.8% (e.g., 8 tokens, 256 experts: 32,520 → 1,024 elements)
- **Performance improvement**: 3-5.5% speedup

Example results (num_tokens=1):
| Experts | Before (µs) | After (µs) | Improvement |
|---------|-------------|------------|-------------|
| 8       | 7.93        | 7.53       | 5.0%        |
| 128     | 9.02        | 8.63       | 4.3%        |
| 256     | 9.19        | 8.68       | 5.5%        |

**Medium/Large batch scenarios**: Performance remains stable with no regression.
