```markdown
## Motivation

This PR bumps FlashInfer to 0.7.3. It also brings in @trevor-m's migration of the NVLink one-sided all-to-all to `flashinfer.moe_ep` from #46885, because neither change can land without the other:

- **The bump needs the migration.** FlashInfer 0.7.3 removes `flashinfer.comm.MoeAlltoAll` and `moe_a2a_get_workspace_size_per_rank`, which the current `FlashinferDispatcher` uses (flashinfer-ai/flashinfer#6047, #6621).
- **The migration needs the bump.** #46885 passes `runtime_max_tokens_per_rank` to `flashinfer.moe_ep`, and that argument only exists from 0.7.3. In 0.7.2 it is `max_tokens_per_rank`.

#46926 (0.7.2.post1) stays open for now as a fallback.

## Depends on

- #48467 (DeepSeek-V4 trtllm counter buffer), now merged. Main's `deepseek_v4_trtllm_backend.py` patches `flashinfer.mla._core._get_trtllm_gen_multi_ctas_kv_counter_buffer`. 0.7.3 no longer has that name, so `--dsv4-attn-backend trtllm` fails at init. #48467 works on 0.7.2 and 0.7.3, so it can merge first.

## Modifications

- Commits from #46885, cherry-picked with @trevor-m as author:
  - Switch `NVLinkOneSidedAllToAll` to the `flashinfer.moe_ep` API.
  - Lint fix.
  - Pass `runtime_max_tokens_per_rank` in dispatch.
- Pass the new `last_valid_index` argument to `flashinfer::sampling::DeviceSamplingFromProb` in SGLang's JIT tree speculative-sampling kernel (`sgl_kernel/speculative/sampling.cuh`). flashinfer-ai/flashinfer#5352 (in 0.7.3) added that parameter. Without this change the kernel fails to compile, and the first EAGLE verify step crashes the scheduler. The change mirrors FlashInfer's own chain speculative-sampling kernel, and it only compiles against 0.7.3 headers, so it has to land with the bump.
- Pass the new `fixed_uniform_q_len` argument in the FlashInfer backend's `fast_prefill_plan`. FlashInfer 0.7.3's FA2 paged-prefill `plan()` takes 21 arguments instead of 20. The fast plan also clears `_eagle_verify_fp8kv_sm90_state`, as FlashInfer's own `plan()` now does on every call.
- MiniMax-M3.1's fused NVFP4 KV store now zeroes the payload when a block's scale underflows to zero, to match FlashInfer 0.7.3's quantizer (flashinfer-ai/flashinfer#6996 changed its guard from `amax != 0` to `sf != 0`).
- **Temporary workaround for flashinfer-ai/flashinfer#8831.** FlashInfer 0.7.2.post1 and 0.7.3 include flashinfer-ai/flashinfer#6546, which adds a small-batch MoE finalize kernel for 4 < top-k <= 64. That kernel adds the top-k expert outputs in a different order from the large-batch kernel, so a token's MoE output depends on its batch size, and prefill and decode logprobs stop matching. With `--enable-deterministic-inference`, the pre-routed NVFP4 trtllm MoE path now calls FlashInfer with `do_finalize=False` and sums the outputs with SGLang's `moe_finalize_fuse_shared`, which uses one order at every batch size. `moe_finalize_fuse_shared` gains an `out=` argument so the sum lands in the usual output buffer. Nothing changes outside deterministic mode. Remove this once #8831 is fixed in a FlashInfer release.
- Bump FlashInfer from 0.7.2 to 0.7.3 in `docker/Dockerfile`, `docker/Dockerfile.cu134`, `python/pyproject.toml` and the `engine.py` version check.

0.7.3 requires `nvidia-cutlass-dsl[cu13]>=4.8.0`, and SGLang already pins 4.8.0.
