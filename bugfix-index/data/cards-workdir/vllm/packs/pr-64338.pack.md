## 正文(PR 描述)

## Overview

Fix a deadlock during Flashinfer attention warmup under PP>1.

## Claims

Fix a deadlock that occurs when one PP rank contains only Flashinfer attention groups while another PP rank contains a mix of Flashinfer and non-Flashinfer attention groups.

Most commonly affects models with dflash / dspark drafters on Blackwell, where Flashsinfer is often the default attention backend for the target model.

## Validation

Ran on B200:

```
vllm serve Qwen/Qwen3-4B \
  --pipeline-parallel-size 2 \
  --attention-backend FLASHINFER \
  --enforce-eager \
  --no-enable-flashinfer-autotune \
  --speculative-config '{"method":"dflash","model":"z-lab/Qwen3-4B-DFlash-b16","num_speculative_tokens":2,"attention_backend":"FLASH_ATTN"}'
```

On this PR, we get
```
INFO:     Started server process [771742]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
```

On main, we get stuck after
```
EngineCore pid=813035) INFO 10-28 17:46:40 [shm_broadcast.py:878] No available shared memory broadcast block found in 60 seconds. This typically happens when some processes are hanging or doing some time-consuming work (e.g. compilation, weight/kv cache quantization).
(EngineCore pid=813035) INFO 10-28 17:47:40 [shm_broadcast.py:878] No available shared memory broadcast block found in 60 seconds. This typically happens when some processes are hanging or doing some time-consuming work (e.g. compilation, weight/kv cache quantization).
```

`--enforce-eager` doesn't resolve this because Flashinfer attention warmup is run regardless of enforce eager and compilation mode.

`--no-enable-flashinfer-autotune` doesn't resolve this because it controls Flashinfer autotuning, not Flashinfer attention warmup.

```

  tests/model_executor/test_attention_warmup.py \
  tests/model_executor/test_flashinfer_autotune_warmup.py \
  tests/v1/worker/test_mixed_warmup_gate.py

99 passed, 2 warnings
```

## Details

During `kernel_warmup`, we may call `mixed_batch_attention_warmup` to run "a mixed prefill+decode batch to warm up both attention paths".

This is currently gated under "all attention groups use the Flashinfer backend" because hybrid attention backends may not support the dummy run.

With spec decode, the drafter may choose a different attention backend than the target model. Since the drafter is present on the last PP rank only, different ranks will disagree on whether they should participate in the Flashinfer warmup, causing deadlock.

The current fix synchronizes across PP ranks and only runs the Flashinfer attention warmup if all ranks agree. In effect, warmup behavior is consistent between PP=1 and PP>1.

Related:
- #60791 tracks issues with MiniMax-M3. Item 8 lists "PP where stages differ in running the M3 attention warmup". M3 warmup also uses `mixed_batch_attention_warmup` but it's separate from Flashinfer warmup.
