## 正文(PR 描述)

## Motivation
When running Qwen3.6-35B-A3 (w4a8, MTP enabled) on Ascend NPU with `--mamba-scheduler-strategy extra_buffer`, ceval accuracy was below the expected baseline, and **enabling thinking mode made it worse** — accuracy dropped *and* the model produced repeated / looping reasoning content. **Three** bugs in the NPU hybrid-linear attention graph-mode verify path, the post-verify mamba state tracking, and the EAGLE speculative top-k selection are responsible.

After the fix:
- thinking **off**: ceval ~87.5% → **89.75%**
- thinking **on**: ceval ~86% → **90.71%**, and the repeated-reasoning regression is gone.

## Modifications

- **`ascend_hybrid_linear_attn_backend.py` — SSM state index aliasing fix**:   During graph-mode target verify, `ssm_state_indices` was constructed over only   `(bs - num_padding) * draft_token_num` entries, with the padded tail zero-filled.   This made every padded-row verify write alias real request 0's intermediate   scratch slot; the post-verify state restore (`move_intermediate_cache`) then read   back corrupted data, producing garbage output or token repetition. Fix: construct   the indices over the full graph bucket `bs * draft_token_num` so each padded row   has its own unique scratch slot. The buffer is sized exactly `bs * draft_token_num`   (`init_cuda_graph_state`), so the full-buffer `copy_` is shape-safe, and the padded   scratch slots are never read back by the real-request restore.

- **`ascend_hybrid_linear_attn_backend.py` — mamba state tracking after MTP verify**:   Implement the `mamba_track_indices` / `mamba_steps_to_track` scatter in   `update_mamba_state_after_mtp_verify` that the CUDA path already has   (`hybrid_linear_attn_backend.py`). When `mamba_track_indices` is set (mamba prefix   reuse — which long, thinking-mode sequences trigger), the verify-time SSM   intermediate state is scattered into the persistent track slots via
  `move_intermediate_cache`. Conv state needs NPU-specific handling: unlike CUDA,   NPU keeps **no** per-step `intermediate_conv_window` cache, so the tracked conv   state is reconstructed by copying the working slot's *pre-rollback* conv state into   the track slot, then independently rolling back both the working slots and the   track slots by their respective step counts (`conv_state_rollback`). Without this,   prefix reuse restored a **stale** SSM/conv state, which is what produced the   repeated reasoning content and the thinking-mode accuracy drop.

- **`eagle_draft_extend_cuda_graph_runner.py` / `eagle_worker_v2.py` — NPU top-k fast-path guard**:   The `topk == 1` argmax fast-path was already gated to exclude ROCm with   `not _is_hip` (ROCm guard, added in #26358). NPU's argmax tie-break similarly   diverges from the full `softmax + topk` path on certain logit distributions,   corrupting MTP draft selection. Add `not _is_npu` to the same guard at all three   call sites so NPU takes the numerically-consistent `softmax → fast_topk` path.   (The NPU draft-extend graph runner inherits `run_once` from the CUDA runner, so  the guard in eagle_draft_extend_cuda_graph_runner.py` is live for NPU.)

## Implementation note (NPU conv-state tracking)

Unlike the CUDA path — which scatters the tracked conv state directly from the per-step intermediate_conv_window_cache` — NPU has no per-step conv intermediate. The tracked conv state is therefore reconstructed from the working slot *before* its rollback, then rolled back independently to the desired step. This relies on track slots and working slots being disjoint and on `conv_state_rollback` reproducing the per-step window; both are exercised by the thinking-mode ceval run in Result 2 below (which is the configuration that actually drives `mamba_track_indices` to be non-`None`).

## Accuracy Tests

Model: **Qwen3.5-397B-A17B-w4a8**, MTP enabled, Ascend NPU.
Eval: evalscope, dataset = ceval, 1346 samples.

**Launch command:**
```bash
GDN_ATTN_BACKEND_TRITON=1 SGLANG_ENABLE_SPEC_V2=1 nohup python3 -m sglang.launch_server \
--model-path ${workspace}/Qwen3.6-35B-A3B/ \
--stream-response-default-include-usage \
--attention-backend ascend \
--device npu \
--tp-size 2 \
--chunked-prefill-size 20480 \
--max-prefill-tokens 20480 \
--trust-remote-code \
--host 0.0.0.0 \
--mem-fraction-static 0.75 \
--port 9811 \
--enable-prefill-delayer \
--prefill-delayer-max-delay-passes 30 \
--cuda-graph-bs 1 2 4 6 8 10 16 20 24 \
--max-running-request 24 \
--context-length 262144 \
--mm-attention-backend ascend_attn \
```
