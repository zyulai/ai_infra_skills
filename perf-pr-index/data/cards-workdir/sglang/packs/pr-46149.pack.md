## Motivation

Multi-GPU Wan decode shards the frame height across ranks (`WanDistResidualBlock`, `SpatialParallelCausalConv3d` with halo exchange). That decoder never got the CUDA fast path ("Wan VAE: spatial-parallel decode; skipping fast path."), and its Conv3d weights stayed NCDHW because the channels_last_3d policy only covers `num_gpus == 1`. In the decode profile of Wan2.2 T2V A14B 720p on 4xB300 (fp32 decode, 1.32 s): cuDNN's own `nchwToNhwc` / `nhwcToNchw` conversions around every conv took 111 ms, the unfused RMSNorm + SiLU chains (`BinaryFunctor`, `silu`, `norm`, adds) ~250 ms, and 4114 `direct_copy` kernels 149 ms.

The spatial-parallel blocks only swap in halo-exchanging convs; the halo exchange slices and concatenates along height, which works in either memory layout.

The mid-block attention gathers the full frame height on every rank and attended every query row of it (21 fp32 `fmha_cutlassF` calls, 143 ms per decode), then kept only its own rows.

## Modifications

- `models/vaes/wan_vae_cuda_opt.py`: the installer accepts the spatial-parallel residual block, resample and attention block classes (`residual_block_cls` is now a tuple of classes) and no longer skips parallel decode.
- `loader/component_loaders/vae_loader.py`: Wan configs convert the VAE's Conv3d weights to channels_last_3d at any GPU count (LTX-2 and Cosmos3 keep the one-GPU rule). On more than one GPU the automatic policy converts the decoder only: cuDNN's TF32 convs round differently in channels_last, and an I2V condition latent that differs by ~3e-3 sends a 40-step 14B trajectory elsewhere (the 2-GPU Wan I2V consistency cases fell to 14-24 dB on the last frame). An explicit `SGLANG_DIFFUSION_VAE_CHANNELS_LAST_3D=1` still converts the whole VAE, as before.
- `models/vaes/wanvae.py`: under spatial-parallel decode each rank attends only its own height shard's query rows (the `tensor_split` chunk the output was cut to) against the whole frame's keys and values.

The fast path is the existing "lossless" quality tier (fp32 ops re-associated, nothing lowered); `quality="exact"` requests still run the reference ops.

## Accuracy Tests

- Wan2.2 T2V A14B 720p, 4xB300, same latents, video saved at x264 crf 0: PSNR 63.2 dB, SSIM 0.99999, max |diff| 4/255, mean |diff| 0.02 against the decode without this change (three requests). No seams at the shard boundaries (rows 180/360/540).
- Row-sharded attention: decoded video byte-identical (mp4 md5 at crf 0, three requests).
- Encoder: with the decoder-only rule, Wan2.1-I2V-14B on 2 GPUs encodes bit-identically to main; with `quality="exact"` (and the decoder's channels_last off) the output mp4 md5 equals main's. The 2-GPU Wan I2V consistency cases pass again (wan2_1_i2v_14b_480P 34.6/37.9/37.5 dB, wan2_1_i2v_14b_720P 36.2/35.9/35.3 dB, wan2_2_i2v_a14b 38.4/36.7/35.5 dB); the Animate cfg-parallel case is bitwise to its GT. Decode on 2 GPUs: main 372 ms, decoder-only 277-283 ms (the encoder no longer gets channels_last's ~8% encode speedup).
- `test_vae_loader.py`: the channels_last_3d policy covers multi-GPU Wan; `test_model_fast_paths.py` passes with the tuple form (33 Wan/Qwen cases); `test_wan_vae_attention_rows.py`: a row range equals those rows of the full-frame block output.
