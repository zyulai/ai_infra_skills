## 正文(PR 描述)

## Purpose
Fixes #42322. MiniCPM-O 2.6 crashes on startup with `Expected all tensors to be on the same device`.

This is caused by `Resampler2_5._set_2d_pos_cache` creating the `pos_embed` buffer on CPU during init (found in `minicpmv.py`). Typically, it would be moved to GPU via `MiniCPMVBaseModel._ensure_resampler_device` which is generally called during the `load_weights` of `MiniCPMVBaseModel`. `MiniCPMOBaseModel` overrides the parent's `load_weights` to skip `tts` prefixes, but never calls `_ensure_resampler_device`. The resampler never gets moved to GPU, and the buffer stays on CPU; the profiling run reaches `x + pos_embed` (CUDA and CPU) and crashes. 

The fix is minimal: add `self._ensure_resampler_device()` to `MiniCPMOBaseModel.load_weights` to match the pattern found in `MiniCPMV`. Both `MiniCPMO2_6` and `MiniCPMO4_5` inherit from `MiniCPMOBaseModel` so both are fixed.

## Test Plan
Reproduce the bug in #42322 using the provided command, apply the fix, then re-run:
```bash
vllm serve openbmb/MiniCPM-o-2_6 --trust-remote-code --max-model-len=16000
```
Tested on fresh vLLM install (v0.20.1).

## Test Result
Before the fix, engine core fails to start during the profile run with the same trace as in #42322. 

After applying the fix, the engine core initialises successfully, weights load, and the API server starts and accepts requests.
