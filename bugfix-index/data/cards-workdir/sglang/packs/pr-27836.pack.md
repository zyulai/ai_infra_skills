## 正文(PR 描述)

## Summary
- `update_device_timer` clobbered the `fwd_occupancy` gauge with NaN at every device-timer window start. The window counter advances on all batch results while the decode-log cadence counts decode batches only, so each prefill shifts their phase and the phase freezes during pure decode -- a workload can land every decode log line exactly on the NaN tick and report `fwd occupancy: nan` indefinitely. Concurrent eval workloads (e.g. the ngram spec CI tests) hit this constantly because prefills keep stepping the phase across the bad slot.
- Fix: keep the last published value at window start; NaN is still published when the value is truly stale (idle reset).
- Guard the occupancy division against `cpu_time <= 0` (hold last value), so a non-advancing timer cannot crash the scheduler loop.
- Disable `SGLANG_ENABLE_ASYNC_ASSERT` for the `base-a` CI stage only: it runs the fwd-occupancy sanity kit, and the async-assert probes add GPU work that skews the measurement. Other stages keep the probes on.
- Raise `fwd_occupancy_threshold`: vanilla sanity 97 -> 99, EAGLE3 sanity 97 -> 98 (CUDA; AMD stays 80) -- with NaN-free sampling and probe-free `base-a`, the threshold can sit right under the ~99 measured median so occupancy regressions surface earlier.

All computed occupancy values are bit-identical to before; the fix only changes what is published on ticks that have no new sample.

## Verification
Qwen3-8B + `--speculative-algorithm NGRAM`, `SGLANG_ENABLE_METRICS_DEVICE_TIMER=1`, `--decode-log-interval 10`, H200. Sustained concurrent load (40 rolling requests):

| | decode-line `fwd occupancy: nan` | prefill-line nan |
|---|---|---|
| main | 11 / 268 prints, in consecutive bursts | 30 (idle stale marker) |
| this PR | 2 / 279 prints, isolated, only on the first decode print right after an idle reset (intended stale semantics) | 30 (unchanged, intended) |
