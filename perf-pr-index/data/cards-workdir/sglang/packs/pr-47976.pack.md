## Motivation

On GPUs with two locality domains, DeepGEMM's Mega MoE gives rows `[d * N / 2, (d + 1) * N / 2)` of every expert to domain `d`'s SMs. With `deep_gemm.localize`, those rows also live in domain `d`'s memory, so weight reads stay local. DeepGEMM takes localized weights since sgl-project/DeepGEMM#119 (native CUDA 13.4 locality domains); this PR wires it into SGLang behind an opt-in env var.

`deep_gemm.localize` returns `(domains, experts, N / domains, K)` tensors, but the expert parameters are also read in two places outside Mega MoE:
- The deep-ep path above `SGLANG_OPT_DEEPGEMM_MEGA_MOE_NUM_MAX_TOKENS_PER_RANK` (`DeepseekV2MoE.forward` falls through when `should_use_mega_moe` is false).
- EPLB, which slices every routed-expert parameter by expert. A domain-major tensor fails `filter_moe_weight_param_global_expert`'s `shape[0] == num_local_experts`, so EPLB would silently move the scales but not the weights.

This PR keeps EPLB working and makes the token cap explicit.

## Modifications

- `SGLANG_OPT_DEEPGEMM_MEGA_MOE_LOCALIZE` (default off), applied on compute capability 10.7 only.
- `build_mega_moe_experts_weights`: localizes the interleaved L1 and the L2 weights. The kernel gets the domain-major tensors (`mega_l1_weights` / `mega_l2_weights`); `w13_weight` / `w2_weight` hold the expert-major `(experts, domains, N / domains, K)` view of the same memory, so every `get_moe_weights` keeps slicing by expert. No second copy of the weights.
- `build_mega_moe_shared_weights`: localizes the fused shared expert's L1 / L2 (DeepGEMM requires shared and routed weights to agree).
- `update_expert_weights_single_layer`: P2P needs each expert's slice dense, and a localized expert's halves live in different domains. Such a tensor is sent from a contiguous staging copy (one message per expert, like every other tensor) and received into a contiguous temp buffer; its weight, temp buffer and staging copy are viewed as int64 once when all three allow it. Every other tensor is moved exactly as before.
- `should_use_mega_moe`: with localized weights there is no non-mega fallback, so tokens above the cap assert with the same message pattern as Kimi K3.
- `test/manual/test_expert_location_updater.py`: the exchanged weights include an expert-major view of padded domain-major storage, so staged sends go through P2P. Passes with gloo (8 and 32 ranks) and NCCL (4 GPUs); with the previous updater NCCL rejects it (`Tensors for P2P must be non-overlapping and dense`).

Setting the env var requires sgl-deep-gemm >= 0.2.4 built with CUDA >= 13.4 (the cu134 image builds it from source).
