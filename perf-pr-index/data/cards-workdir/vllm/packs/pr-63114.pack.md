## Overview

Base Labs' decision models mammoth-1 (Qwen3.5-27B) and elephant-1 (9B) ([post](https://www.baseten.co/blog/the-best-decision-models-in-the-world-mammoth-1-and-elephant-1/), [report](https://labs.baseten.co/articles/mammoth-1-and-elephant-1-frontier-decision-models)) were trained with a block-bidirectional mask on their full-attention layers (`modeling_overrides` in `config.json`). Stock vLLM ignores the mask. This PR serves them as trained on `/v1/systemone` and `/v1/decisions`, with prefix caching on.

Related: #63033, #66722, #65222. None duplicates this PR; see [Related work](#related-work).

<img src="https://raw.githubusercontent.com/simon-veitner-redhat/vllm/mammoth-elephant-pr-assets/block-bidirectional-mask.png" width="560" alt="Causal mask vs block-bidirectional mask: inside a block a query also sees the later keys of its block; across blocks the mask stays causal.">

No core model-state file and no `attn_utils.py` change. The model's own state class overrides the existing `prepare_attn`, as `diffusion_gemma.py` and DeepSeek V4.1's model state do. On a prefill step with PrefixLM ranges, `MambaHybridModelState` builds the linear-attention groups and the slot state builds the full-attention groups with `build_attn_metadata(mm_req_doc_ranges=...)`, the path Gemma's image ranges take. It writes no field of a built metadata object and imports no backend class.

## Claims

- On JevBench public (231 tasks), the PR raises accuracy and lowers Brier on both models: mammoth-1 0.9307 → 0.9394 / 0.1165 → 0.0833, elephant-1 0.8571 → 0.9004 / 0.1752 → 0.1296.
- Prefix caching stays on. On a DI 0.3 sample at c64 it makes the masked model 1.58x faster on elephant-1 and 1.48x faster on mammoth-1.
- No change to `scheduler.py`, `request.py`, `kv_cache_manager.py`, `kv_cache_utils.py` or the core model states. A `PrefixLMScheduler` subclass that the model selects holds the rules.
- Two core edits: one deleted assert in `MambaModelConfig`, which lets every hybrid model combine Mamba prefix caching with `--no-enable-chunked-prefill`, and `MAX_LOGPROB_TOKEN_IDS` 128 → 256.
- Qwen3.5-9B with default settings gives bitwise-equal greedy outputs and the same throughput as main.

### How it works

```
request ── SlotLMStrategy ── extra_args["prefix_lm_len"] = P, cache_salt = "prefix-lm:" + sha256(prefix)
             │
             ├─ PrefixLMScheduler: hit capped at P · no shared-prefix junction
             │    └─ stock Scheduler, chunked prefill off: rest of the prompt in one step, or wait at the queue head
             │
             └─ Qwen3_5SlotDecisionModelState.prepare_attn: ranges [(0, P-1), (P, L-1)] on prefill steps
                  → super() builds the GDN groups; build_attn_metadata(mm_req_doc_ranges=ranges) the full-attention groups
```

A prefix token's KV and Mamba state depend on the whole prefix, and a question token's depend on the whole prompt. So a cache hit is valid only up to P and only for the same prefix, and a step must never end inside a block.

| rule | where |
|---|---|
| Hits stop at `min(P, num_tokens - 1)` and respect upstream's `max_cache_hit_length` | `PrefixLMScheduler._get_local_prefix_cache_hit` |
| The hit reports no shared-prefix junction (0), so the Mamba split does not end a step inside the prefix | `PrefixLMScheduler._get_local_prefix_cache_hit` |
| The rest of the prompt is prefilled in one step, or the request waits at the queue head | stock `Scheduler`, with chunked prefill off by the model hook |
| Hits need the same prefix: a missing or forged salt is moved into its own namespace, and causal requests are moved out of it | `PrefixLMScheduler.add_request` |
| Streamed and multimodal requests are read causally (one-time warning), with or without prefix caching | `PrefixLMScheduler.add_request` |
| A step that ends inside a block raises instead of returning a wrong read | model state |
| FULL CUDA graphs run one-token queries, so the model state skips the ranges there | model state |

Why the stock Mamba split has no stop inside a whole prompt:

| stop in `_mamba_block_aligned_split` | why it does not fire here |
|---|---|
| chunk-end alignment | the step already ends at the prompt end |
| mid-block start | cache hits are block-aligned |
| last cacheable block | FlashInfer GDN saves it inside the step |
| partial-hit tail | `--prefix-match-unit` is refused |
| shared-prefix junction | the cap override returns 0 |

Requests without `prefix_lm_len` run through `Scheduler`'s own code. Under async scheduling, `PrefixLMScheduler.__new__` builds `PrefixLMAsyncScheduler`, because the model hook picks the scheduler before async scheduling is decided.

### Refusals

At startup:

- KV connectors, `--kv-offloading-size`, speculative decoding, context parallelism and micro-batching
- any attention backend other than `TRITON_ATTN` for full attention, including through `backend_per_kind`
- `--max-num-scheduled-tokens` below `--max-model-len`
- `--scheduler-cls`, and with prefix caching `--prefix-match-unit`
- unknown `modeling_overrides`, or `n_slots` outside 1-256

Per request (400): `instructions`, `chat_template_kwargs` other than `{"enable_thinking": false}`, media, prompts that do not fit `--max-model-len` with the answer token, scores with more than 10 levels, and `/v1/decisions` options with repeated labels.

If `SlotLMStrategy` cannot start (for example on a non-fp32 head), a warning says why `/v1/systemone` and `/v1/decisions` are off.

### Trade-offs

- **The `MambaModelConfig` assert is deleted for every hybrid model.** `--enable-prefix-caching --no-enable-chunked-prefill` used to fail at startup on any hybrid model and now starts. The assert runs after the model hook, so it cannot be kept for other models without a model-specific case in core. On Qwen3.5-9B the new config matches main's config without chunked prefill bitwise. It is not bitwise equal to the default config on long prompts, because turning chunked prefill off changes results on main too ([Quality](#quality)). No other hybrid model was run this way.
- **Causal requests on this model wait instead of chunking.** A causal prompt that does not fit the remaining budget waits. Mixed traffic showed no TTFT cost at the load tested. The model docs say chunked prefill is off for every request on the server.
- **The step budget is only raised to `--max-model-len`.** While decodes run, a full-length prompt waits at the queue head until they leave room: a 32,514-token read behind 256 decodes waited 13.35 s at a 32,768 budget and 1.07 s at 33,792 (*earlier head*). Set `--max-num-batched-tokens` to `--max-model-len` plus `--max-num-seqs` to avoid the wait.
- **This relies on the stock split's current stops.** `PrefixLMScheduler` overrides one private `Scheduler` method, `_get_local_prefix_cache_hit`. If upstream renames it or adds a stop inside a prompt, the behaviour tests fail and the model-state guard raises instead of returning wrong reads.
- `cache_salt` changes meaning on this server. KV-event consumers see `prefix-lm:<digest>[:<user salt>]`.
- `MAX_LOGPROB_TOKEN_IDS` 128 → 256 (Python and Rust) doubles two buffers sized by it. `LogprobTokenIdsState` on every server grows by 0.5 MiB at 1,024 requests. DiffusionGemma's logprob stash, allocated before memory profiling, grows by `max_num_seqs` x canvas length x 128 x 12 bytes: 48 MiB at 1,024 requests and a 32-token canvas, taken from the KV cache. No other model reads the constant. It measured no step cost (*earlier head*: about 11.7 ms per step for K = 0, 128 and 255 in a mixed batch of 64 slot reads and 64 normal requests). DiffusionGemma was not run.
- Forcing `TRITON_ATTN` costs 2.5% to 5.4% decisions/s against FlashInfer with the mask off, c1 to c64; decode 0.8% to 4.3%; TTFT at c1 the same (*earlier head*).
- The GDN check calls the private `_resolve_gdn_prefill_backend`, as `olmo_gdn_linear_attn.py` already does.

### Alternatives considered

| option | why not |
|---|---|
| rules inside `Scheduler` | about 50 lines in 6 core files, plus a one-model `SchedulerConfig` field |
| prefix caching off | no core change, but loses the 1.58x / 1.48x DI speed-up |
| content keys in block hashes | correct for connectors and offloading by construction, but needs `request.py` / `kv_cache_utils.py` changes and chunked prefill off server-wide |
| a new hook on `DefaultModelState` that the model state overrides | extends the core model-state interface for one model |
| writing the ranges onto the built `TritonAttentionMetadata` | the same reads and 35 fewer source lines, but the model state would edit objects the base class built, and a composite backend would never see the ranges |
| `TRITON_FLASHINFER` (routes PrefixLM steps to Triton, decode to FlashInfer) | the ranges reach it through `mm_req_doc_ranges`, and it gives the same answers on B200, but it measured no gain (*earlier head*: decisions/s at c64 0.8% lower, the same decode tok/s), so the hook refuses it |

### Limitations

- `TRITON_ATTN` only. FlashInfer's native mm-prefix path (#46558) is on main but serves only `is_mm_prefix_lm` models, and was not tried here.
- `Qwen3_5ForSlotDecision` subclasses `model_executor/models/qwen3_5.py` and runs with torch.compile, like the other Qwen3.5 derivatives on main (D3, colqwen3_5, minicpmv4_6). It does not use main's new eager Qwen3.5 model.
- The FULL-graph branch of the model state is not reached on this main: upstream downgrades `cudagraph_mode=FULL` to `FULL_AND_PIECEWISE` with the GDN backend.
- Prefix caching needs FlashInfer GDN prefill. The hook turns it off with other GDN backends.
- `/v1/decisions` reads every question as a choice, so a predicate is rendered as a two-option choice rather than the trained yes/no prompt.
- An explicit large `--max-model-len` is kept. At a 263,168-token budget startup crashes with an illegal memory access, which stock Qwen3.5-9B on main does too (*earlier head*).
- The Rust frontend accepts 256 `logprob_token_ids`, but like the other decision models it does not serve `/v1/systemone` or `/v1/decisions`.
- Not run: TP > 1 and preemption on GPU.
