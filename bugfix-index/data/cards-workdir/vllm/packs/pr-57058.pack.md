## 正文(PR 描述)

## Purpose

Partially addresses #57052 (the `--tokens-only` half; the derender-side stop-string truncation is a separate design discussion tracked there).

A `--tokens-only` server sets `sampling_params.detokenize = False` **after** the request has already passed validation, bypassing the `SamplingParams` guard that forbids `stop` strings without detokenization. Downstream, the tokenizer-less `IncrementalDetokenizer` never calls `check_stop_strings`, so client `stop` strings were **silently ignored** — generation ran to EOS or `max_tokens` with no error, warning, or log line. The failure is easy to miss because `stop_token_ids` still work (they need no detokenization).

This PR rejects the combination with a 400 in `serve_tokens`, mirroring the error a client already gets when it sets `detokenize=False` itself (see the first leg of the existing `test_stop_string_workflow`). The error message points at the documented contract from that same test: check stop strings on the coordinator, or use `stop_token_ids`.

## Why this is not duplicating an existing PR

Checked open PRs before submitting (`gh pr list --search` on "stop", "tokens-only", "include_stop_str_in_output", "derender", plus `57052 in:body`). The closest is #46310, which rejects `stop` when `--skip-tokenizer-init` is set — but that guards `SamplingParams` construction from CLI-level config and does not catch this path, where the request validates cleanly (client-side `detokenize` defaults to `True`) and `force_no_detokenize` flips it afterwards. No open PR touches the scale-out `serve_tokens` validation.

## Test Plan

New test `test_stop_strings_rejected_when_tokens_only` in the existing `tests/entrypoints/scale_out/token_in_token_out/test_serving_tokens.py`, using the file's indirect server parametrization to launch with `--tokens-only`: asserts `stop` → 400 with a "stop strings" error message, and that the identical request with `stop": null` succeeds on the same server.

```bash
.venv/bin/python -m pytest tests/entrypoints/scale_out/token_in_token_out/test_serving_tokens.py::test_stop_strings_rejected_when_tokens_only -v
# regression on the default (non --tokens-only) server:
.venv/bin/python -m pytest "tests/entrypoints/scale_out/token_in_token_out/test_serving_tokens.py::test_generate_endpoint" "tests/entrypoints/scale_out/token_in_token_out/test_serving_tokens.py::test_stop_string_workflow" -v
pre-commit run --files vllm/entrypoints/scale_out/token_in_token_out/serving.py tests/entrypoints/scale_out/token_in_token_out/test_serving_tokens.py
```

## Test Result

All three tests pass locally (macOS CPU build, Qwen3-0.6B; the local runs added `--gpu-memory-utilization 0.25` to the server fixture args purely to fit local RAM — the committed test keeps the standard args):

- `test_stop_strings_rejected_when_tokens_only`: **1 passed**
- `test_generate_endpoint`, `test_stop_string_workflow` (default server, guard must not fire): **2 passed**
- `pre-commit run --files ...` (including `mypy-3.10`): all hooks pass

No model evaluation needed: the change is request validation only; accepted requests produce byte-identical output.
