## 正文(PR 描述)

## Summary

Fix the compact HiSparse KV-row tests added by #58305:

- stop patching `_create_side_stream` / `_create_event`, helpers removed by the platform-backend refactor before #58305 merged;
- construct the gather-prefill runtime with the parameterized KV dtype so FP8 `uint8` caches are bound to a `uint8` runtime instead of the default `float32` runtime;
- exercise staged-prefill backing through a real initialized runtime instead of calling the instance method with `self=None` after the gather path began using runtime cache ops.

## Failure evidence

Nightly main build #97886 and subsequent main builds through #98096 fail the exact H100 and B200 V1 Attention shards:

- `test_hisparse_index_group_preserves_row_width`: `AttributeError` for removed `_create_side_stream`;
- `test_hisparse_gather_prefill_cache_prefers_resident_rows`: runtime expects `torch.float32` but receives the parameterized `torch.uint8` cache;
- `test_hisparse_staged_prefill_cache_backs_min_attention_rows`: `self=None` reaches `self.cache_ops` after the gather implementation changed.

The failures are deterministic test defects introduced by #58305, not failures in the unrelated later main commits.

## Validation

- `git diff --check`
- full file-scoped pre-commit suite for `tests/v1/attention/test_sparse_mla_backends.py`
- first exact build #97912 proves the original two failure families pass; it exposed the third stale test call above
- updated exact H100 and B200 V1 Attention CI required before merge
