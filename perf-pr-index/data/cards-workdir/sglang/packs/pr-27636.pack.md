## Motivation

On MI355X (HIP/ROCm), the shared expert gating in `Qwen2MoeSparseMoeBlock._forward_shared_experts` runs as two separate elementwise kernels:

1. `sigmoid_kernel` (~3.8 us) -- `F.sigmoid(gate)`
2. `elementwise_mul` (~4.6 us) -- broadcast multiply with `shared_output`

Each kernel launch carries ~4 us overhead on MI355X, making these tiny pointwise ops launch-bound. This PR fuses both into a single Triton kernel, eliminating one kernel launch per A-type decode layer.

This is the broadcast variant of the kernel introduced in #27630 (which handles the same-shape attention output gate case). The shared expert gate has shape `(N, 1)` while the output has shape `(N, D)`, requiring a broadcast-aware kernel.

## Modifications

- **New: `python/sglang/jit_kernel/triton/sigmoid_gate_mul.py`**
  - `sigmoid_gate_mul(x, gate)` -- element-wise fused kernel (same-shape, from #27630)
  - `sigmoid_gate_mul_broadcast(x, gate)` -- broadcast fused kernel for `(N, D) * sigmoid((N, 1))`
  - Both promote sigmoid computation to float32 for numerical stability

- **Modified: `python/sglang/srt/models/qwen2_moe.py`**
  - Added `_use_aiter` branch in `_forward_shared_experts()` (line ~403) that calls `sigmoid_gate_mul_broadcast()` instead of separate `F.sigmoid()` + `*`
  - CUDA path remains unchanged; gated behind `_use_aiter` flag

- **New: `python/sglang/jit_kernel/tests/test_sigmoid_gate_mul.py`**
  - 40 unit tests covering both element-wise and broadcast variants
  - Tests across bf16/fp16/fp32 dtypes and multiple tensor shapes
  - Input immutability, output dtype, and contiguity checks
