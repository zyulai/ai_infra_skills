## Summary

Add NVIDIA H200 Triton 3.6 fused-MoE configs for:

- Qwen3.5-35B-A3B-FP8: `E=256,N=512`, block FP8 `[128,128]`, TP1, with separate up/gate and down-projection tables
- Qwen3.6-35B-A3B-FP8: the cached checkpoint requests the same lookup keys and shares the Qwen3.5 FP8 tables
- Qwen3.6-35B-A3B-BF16: `E=256,N=512`, TP1, with separate up/gate and decode-aware down-projection tables

The unsupported Qwen3.8 MoE entry has been removed. Qwen3.8-27B is a dense hybrid-attention model, so it cannot use these MoE tables. Its H200 packed-GDN and ReplaySSM verification candidates were tuned and validated separately; both were end-to-end neutral and are not included in this change.

## Full-model GSM8K validation

All primary comparisons used one H200, SGLang v0.5.17, the official `benchmark/gsm8k/bench_sglang.py`, five shots, temperature 0, a 20-question warmup, ten 200-question repetitions per A/B/A phase, and closed-loop parallelism 64 without a request-rate or TPOT throttle. Changes are against the mean of the A1 and A2 phase medians.

| Model | A1 latency / throughput | Tuned latency / throughput | A2 latency / throughput | Drift-adjusted change | Accuracy A1 / tuned / A2 | Invalid |
|---|---:|---:|---:|---:|---:|---:|

| Qwen3.6 FP8 | 8.793 s / 2965.50 tok/s | 7.999 s / 3128.58 tok/s | 8.403 s / 2879.70 tok/s | **-6.96% latency, +7.05% throughput** | 0.415 / 0.425 / 0.413 | 0% |
| Qwen3.6 BF16 | 14.812 s / 2620.40 tok/s | 14.919 s / 2628.53 tok/s | 14.996 s / 2640.67 tok/s | +0.10% latency, -0.08% throughput | 0.518 / 0.518 / 0.525 | 0% |

## Qwen3.8-27B dense-kernel evaluation

The public Qwen3.8-27B BF16 checkpoint was tested on the same H200:

- Packed-GDN exact shape `(H,HV,K,V)=(16,48,128,128)`: `BV=16`, 4 stages, 1 warp reduced aggregate B4-B32 kernel time by 5.89% (6.26% gain), with exact output and state matches in 14/14 correctness cases. Full-model A/B/A was neutral: **+0.02% throughput, -0.17% latency**. Rejected.
- ReplaySSM MTP verification exact-shape candidate: 3 stages and `NK=4`, compared against stock ReplaySSM-spec with identical EAGLE 3/1/4 settings. Full-model A/B/A was neutral: **+0.20% throughput, -0.15% latency**. Rejected.
- Operationally, enabling non-speculative ReplaySSM with its required `no_buffer` and overlap-disabled settings raised request capacity from 41 to 69 and measured **+16.06% throughput / -13.72% latency** with unchanged GSM8K accuracy. This is a server-configuration result, not a code change in this PR.

## Reproduce the GSM8K results

Use two source trees built from the same SGLang revision:

- `BASE_SOURCE`: the baseline tree
- `TUNED_SOURCE`: the same tree with this PR's diff applied

Run the commands below three times in order: `BASE_SOURCE` (A1), `TUNED_SOURCE` (B), then `BASE_SOURCE` again (A2). Set `SOURCE` accordingly and use a separate `OUTPUT_DIR` for each phase. Set `MODEL` to one of:

```bash
Qwen/Qwen3.5-35B-A3B-FP8
Qwen/Qwen3.6-35B-A3B-FP8
Qwen/Qwen3.6-35B-A3B
```

Start the server:

```bash
export SOURCE=/path/to/sglang-source
export MODEL=Qwen/Qwen3.5-35B-A3B-FP8
export PORT=30000
export DATA=/tmp/gsm8k_test.jsonl
export OUTPUT_DIR=/tmp/gsm8k-qwen
mkdir -p "$OUTPUT_DIR"

export PYTHONPATH="$SOURCE/python"
python -m sglang.launch_server \
  --model-path "$MODEL" \
  --host 127.0.0.1 \
  --port "$PORT" \
  --tp-size 1 \
  --trust-remote-code \
  --random-seed 0 \
  >"$OUTPUT_DIR/server.log" 2>&1 &
SERVER_PID=$!

until curl -fsS "http://127.0.0.1:$PORT/health_generate" >/dev/null; do
  sleep 2
done
```

Run the official SGLang GSM8K warmup and ten measured repetitions:

```bash
python "$SOURCE/benchmark/gsm8k/bench_sglang.py" \
  --backend srt \
  --host 127.0.0.1 \
  --port "$PORT" \
  --data-path "$DATA" \
  --num-questions 20 \
  --num-shots 5 \
  --parallel 64 \
  --max-new-tokens 512 \
  --temperature 0 \
  --top-p 1 \
  --result-file "$OUTPUT_DIR/warmup-result.jsonl" \
  --raw-result-file "$OUTPUT_DIR/warmup-raw.jsonl"

for repeat in $(seq -w 1 10); do
  python "$SOURCE/benchmark/gsm8k/bench_sglang.py" \
    --backend srt \
    --host 127.0.0.1 \
    --port "$PORT" \
    --data-path "$DATA" \
    --num-questions 200 \
    --num-shots 5 \
    --parallel 64 \
    --max-new-tokens 512 \
    --temperature 0 \
    --top-p 1 \
    --result-file "$OUTPUT_DIR/run-$repeat-result.jsonl" \
    --raw-result-file "$OUTPUT_DIR/run-$repeat-raw.jsonl"
done

kill "$SERVER_PID"
wait "$SERVER_PID" || true
```

For the saturated Qwen3.6 BF16 run, change `--parallel 64` to `--parallel 128`, `--num-questions 200` to `--num-questions 1319`, and run three measured repetitions.

For the Qwen3.8-27B operational ReplaySSM comparison, use `MODEL=Qwen/Qwen3.8-27B`. Keep the baseline server command unchanged and add these flags to the optimized server:

```bash
--mamba-radix-cache-strategy no_buffer \
--disable-overlap-schedule \
--enable-linear-replayssm
```

For the isolated ReplaySSM verification-kernel comparison, use the following flags on both baseline and tuned servers:

```bash
--speculative-algorithm EAGLE \
--speculative-num-steps 3 \
--speculative-eagle-topk 1 \
--speculative-num-draft-tokens 4 \
--enable-linear-replayssm-spec
```
