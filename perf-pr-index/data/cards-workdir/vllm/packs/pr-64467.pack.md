## Overview

`prepare_megamoe_inputs` (MXFP8 quantization and top-k repacking before every DeepGEMM MegaMoE layer) uses 32-row tiles from 1024 tokens, keeping 8-row tiles from 64 tokens.

## Claims

- `_prepare_megamoe_inputs` is 1.3–1.6x faster from 1024 tokens on GB200, bit-identical.
- DeepSeek-V4.1-Flash DEP2 prefill: 0.27–0.57 ms less GPU time per forward at 8K–16K new tokens (0.3%).

## Validation

`prepare_megamoe_inputs` at DeepSeek-V4.1-Flash shapes (hidden 5120, top-6, fused shared expert with `shared_block_m=128`), one GB200, CUPTI under a CUDA graph, median of 3 runs; all outputs (x, scales, top-k, shared scales) are bit-identical to main at every size:

| tokens | main, 8-row tiles (us) | This PR, 32-row tiles (us) | Speedup |
|---|---|---|---|
| 512 | 3.1 | 3.0 | (8-row tiles, unchanged) |
| 1024 | 4.7 | 3.7 | 1.27x |
| 2048 | 7.4 | 5.1 | 1.45x |
| 4096 | 13.1 | 8.0 | 1.64x |
| 8192 | 29.8 | 22.5 | 1.32x |
| 16384 | 57.4 | 42.9 | 1.34x |
| 32768 | 113.6 | 84.3 | 1.35x |

`vllm bench forward`, DeepSeek-V4.1-Flash with dummy weights, DEP2 on one GB200 node, FlashMLA MegaAttn with the MXFP4 indexer, `--kv-len-jitter 0 --max-num-batched-tokens 20480`, rank 0 kernel profile (`--profile-dir`), GPU us per forward:

| kernel | 16K new tokens, main | This PR | 128K cached + 8K new, main | This PR | 128K cached + 16K new, main | This PR |
|---|---|---|---|---|---|---|
| `_prepare_megamoe_inputs` (x40) | 1517 | 948 | 761 | 492 | 1475 | 952 |

Accuracy (`vllm serve`, DEP4 on one GB200 node, DSpark K=5 with probabilistic drafting and standard rejection sampling; GSM8K is lm_eval 5-shot, greedy, max 1024 tokens, concurrency 32, strict-match; acceptance length over the GSM8K run; the run had this change and #64466 applied together, both bit-identical): GSM8K strict-match 0.9287, acceptance length 3.447 (reference before these changes, same flags: 0.9265 / 3.451).
