```markdown
## Motivation

MiniMax-M3 currently runs all attention GEMMs in bf16: with `--kv-cache-dtype fp8_e4m3` the fp8 cache is widened back to bf16 on load (widening-dequant contract), and the lightning-indexer cache stays bf16 entirely. On Blackwell, both the MSA fmha_sm100 kernels and trtllm-gen's dense kernels have native fp8 paths, so we can run the sparse / MSA / indexer / dense attention GEMMs in fp8_e4m3 end-to-end: fp8 tensor-core MMAs plus an fp8 index KV cache.

This mainly speeds up prefill — up to **+66% prefill throughput at 32k input** (see Speed Tests) — and frees ~20 GB/GPU of indexer-cache memory at the same KV token budget, with GSM8K accuracy at parity.

The PR is three commits, each independently useful:

1. `minimax_decode_topk`: emit block ids in **ascending order** — a hard requirement of the MSA fmha_sm100 consumer (`kv_block_indexes` must be strictly ascending; its sorted-order early-exit otherwise mis-masks the partial last block).
2. `trtllm_mha`: accept `page_size == 128` via trtllm-gen's dynamic tokens-per-page kernels (flashinfer >= 0.6.12) — M3 needs the 128 sparse block on the dense backend.
3. The fp8 attention-GEMM mode itself.

## Modifications

### Commit 1 — `minimax_decode_topk`: ascending block ids

- Block-id output contract changes from "front-packed, unordered" to "sorted ascending" (O(k^2) rank permutation in smem, k <= 64). The Triton `_gqa_share_sparse_decode_kernel` consumer is order-insensitive; MSA requires ascending.
- `kMaxTopK` 32 -> 64 to keep the existing `topk == 64` test contract; a `RuntimeCheck` now guards the smem sort buffer.

### Commit 2 — `trtllm_mha`: page_size 128

- `_mla_backend_page_constraints` accepts 128 for trtllm_mha.
- `TRTLLMHAAttnBackend.__init__` validates the trtllm-gen precondition (GQA with q_heads/kv_head > 1, equal QK/V head dims, power-of-2 page) so an unsupported combo fails at construction instead of a "Missing TRTLLM-GEN kernel" error during CUDA-graph capture. XQA (SM90/SM120) has native page-128 decode kernels and needs no check.
- **Behavior note:** an explicit `--page-size 128` + trtllm_mha on a non-GQA model previously snapped to 64 with a warning; it now raises at init with the same guidance.

### Commit 3 — fp8 attention GEMMs, derived flaglessly

- **No opt-in flag:** `m3_fp8_attn_gemm_enabled()` (server_args.py) derives the mode from `kv_cache_dtype == fp8_e4m3` + `attention_backend == trtllm_mha` + SM100, and it activates whenever possible. `_minimax_m3_overrides` flips the SM100 backend default to trtllm_mha for fp8_e4m3 KV (page 128); `fp8_e5m2` warns and stays on the widening Triton path (fmha_sm100's variant lookup would silently dispatch the e4m3 kernel for e5m2).
- **Kill switch** for accuracy triage: `SGLANG_DISABLE_M3_FP8_ATTN_GEMM=1` forces the pre-fp8 numerics (bf16 indexer + widening sparse path, bf16 q) and keeps the fa4 backend default, without moving off trtllm_mha for everything else.
- Under the mode: fp8_e4m3 main + lightning-indexer KV pools, q/idx_q fp8-cast in the sparse backend (after the KV store and DP trim), fp8x8 `tl.dot` in the Triton sparse kernels, uniform-e4m3 MSA; dense layers use trtllm_mha's existing fp8-q path.
- Per-tensor scales (q/k/v, idx_q/k/v) plumb end-to-end as `Optional[float] = None` (None = unit), normalized once via `unit_scale()` at the kernel-launch boundary. Triton wrappers fold q_scale into sm_scale (exact: it multiplies both the QK dot and the sink logit, unlike k_scale which must not touch the sink term); MSA passes scales natively to fmha_sm100. No checkpoint loader populates the new RadixAttention scale fields yet; None means unit scale.
- MSA decode under CUDA graph keeps the existing opt-in `SGLANG_OPT_USE_MSA_DECODE_UNDER_GRAPH` gate (unchanged by this PR).

## Speed Tests and Profiling

- The prefill win grows with context, as expected for attention-bound prefill (indexer + sparse GEMMs dominate at long inputs).
```
