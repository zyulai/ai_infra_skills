## Motivation

  MHATokenToKVPool.set_kv_buffer_prefix_valid commits accepted-prefix KV rows after DFLASH verification. With --kv-cache-dtype fp8_e4m3 and checkpoint KV scales, the existing path performs:

  1. In-place scale division for K
  2. In-place scale division for V
  3. K cast to FP8
  4. V cast to FP8
  5. Triton byte-copy/scatter

  This is five GPU kernel launches per layer and introduces full HBM round-trips for the intermediate scaled tensors. Without explicit scales, the path still requires two casts plus the scatter kernel.

  This PR fuses source-dtype scaling, FP8 conversion, and prefix-valid scatter into one Triton kernel.

  ## Modifications

  - Added set_kv_buffer_prefix_valid_tiled_fp8 in cache_move.py.
      - Preserves the existing (batch, row, tile) structure, commit_lens early exit, and loc_2d indirection.
      - Uses element-based offsets and strides rather than byte-based addressing.
      - Receives typed source and FP8 destination pointers.
      - Divides in FP32 registers, rounds back to the source dtype to reproduce eager div_ semantics, then casts directly to the destination FP8 type.
      - Supports BF16, FP16, and FP32 sources.
      - Performs no intermediate allocation, source-tensor write, or HBM round-trip.

  - Added _set_kv_buffer_prefix_valid_impl_fp8 in memory_pool.py.
      - Mirrors the original empty-input and contiguity guards.
      - Computes its grid, strides, and tile sizes in elements.
      - Passes zero-copy FP8 views of SGLang’s uint8-backed KV buffers so Triton infers correctly typed destination pointers.

  - Added narrow dispatch in MHATokenToKVPool.set_kv_buffer_prefix_valid.
      - Fused path requires an E4M3 KV cache and safely resolved K/V scales.
      - Python scalars and CPU scalar tensors are accepted directly.
      - GPU layer scale parameters use their existing k_scale_float/v_scale_float shadows without host synchronization.
      - Unsupported tensor scales, missing scales, non-FP8 caches, CPU execution, and asymmetric K/V rows retain the existing fallback.
      - The eager fallback continues using the original scale objects, including GPU tensors.

  - Threaded the draft model’s resolved quant_config into DFlashAttention’s RadixAttention.
      - This enables the existing Fp8KVCacheMethod for online-FP8 DFLASH drafts.
      - It initializes the KV scale parameters and float shadows required by the fused dispatch.
      - No new scale-loading mechanism or global configuration mutation was added.

  - Unlike the eager div_ path, the fused path does not mutate the input K/V tensors. Intermediate scaled values remain in registers and only the final FP8 cache is written.

  ## Accuracy Tests

  Added test_prefix_valid_fp8.py with coverage for:

  - Exact FP8 byte parity against the eager div_ → FP8 reference for BF16, FP16, and FP32 inputs.
  - Every tile-size branch and masked epilogue rows using row dimensions 63, 2048, and 4097.
  - Mixed per-request commit_lens.
  - Noncontiguous source tensors.
  - Separate K/V scales.
  - Representable FP8 limits, NaN, and signed zero.
  - Untouched destination slots.
  - GPU scale parameters with float shadows.
  - GPU tensor scales without float shadows taking the eager fallback.
  - Missing-scale fallback.
  - Non-FP8 cache fallback.
  - Input non-mutation on the fused path.

  ## Speed Tests and Profiling

### Test configuration

- **GPU:** NVIDIA B200
- **CUDA:** CUDA 13
- **Target model:** `NousResearch/Meta-Llama-3.1-8B-Instruct`
- **Draft model:** `z-lab/LLaMA3.1-8B-Instruct-DFlash-UltraChat`

- **Draft quantization:** `fp8`

- **Output length:** 48 tokens per request
- **Acceptance length:** fixed at 4 to deterministically exercise prefix commits
- **CUDA graphs:** enabled

The benchmark-only baseline retained the same DFLASH quantization configuration and scales, but forced `set_kv_buffer_prefix_valid` through the existing eager fallback.

### Kernel engagement

The profiler recorded 65 prefix commits in both variants:

| Variant | Legacy `set_kv_buffer_prefix_valid_tiled` | Fused `set_kv_buffer_prefix_valid_tiled_fp8` |
| --- | ---: | ---: |
| Eager fallback | 65 | 0 |
| Fused | 0 | 65 |

This confirms that the A/B comparison exercised the intended implementations without mixing the legacy and fused commit paths.

### Prefix-commit GPU time

| Variant | Kernel sequence | Median GPU time per layer |
| --- | --- | ---: |
| Eager fallback | K division + V division + K FP8 cast + V FP8 cast + byte-copy store | 14.528 us |
| Fused | Required source-layout copy + fused FP8 quantize/store | 4.864 us |
| **Speedup** |  | **2.99x** |

The fused Triton kernel alone measured 1.951 us per layer. The 4.864 us result above includes the preceding source-layout copy and is therefore the fair implementation-level comparison.

This establishes a **2.99x improvement in the prefix-valid FP8 commit GPU cluster for this fixed-shape B200 workload**. It is not a claim of a 2.99x end-to-end request speedup.

### End-to-end A/B

A separate process-level benchmark ran 10 alternating A/B pairs. Each variant received 10 warmup batches followed by 100 measured batch-4 requests per pair.

The mean paired request-p50 saving was 0.25 ms, with a 95% bootstrap confidence interval of `[-0.96, +1.11]` ms. Because the confidence interval crosses zero, no statistically significant end-to-end latency improvement is claimed.

+def make_kv_cache(total_slots, row_dim, dtype=fp8_dtype, device="cuda"):
+    store_dtype = torch.uint8 if dtype == fp8_dtype else dtype

+def assert_bytes_equal(actual, expected, label):
+    # Integer comparison preserves NaN encodings and the sign of zero.
+    torch.testing.assert_close(
+        actual.contiguous().view(torch.uint8),
+        expected.contiguous().view(torch.uint8),
+        rtol=0,
+        atol=0,
+        msg=lambda message: f"{label}: {message}",
+    )

+@contextmanager
+def assert_prefix_commit(

+):
+    """Check the whole cache (including untouched slots) against eager division."""
+    rows = torch.arange(loc.shape[1], device=loc.device)
+    valid = (rows[None, :] < lengths[:, None]).reshape(-1)
+    src = torch.nonzero(valid, as_tuple=False).flatten()
+    dst = loc.reshape(-1)[src].long()
+    before = (k.clone(), v.clone())
+    scaled, expected = [], []
