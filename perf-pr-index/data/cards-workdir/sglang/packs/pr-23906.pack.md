## Modifications

### Runner ↔ CudaGraphBackend Interaction (cg-refactor)

Two layers are in scope:

- **Phase runner** — `PrefillCudaGraphRunner` / `DecodeCudaGraphRunner`
  - Both subclass `BaseCudaGraphRunner`
  - Exactly one runner per phase
  - Fixed implementation

- **CG backend** — `BaseCudaGraphBackend` and its subclasses:
  - `FullCudaGraphBackend`
  - `BreakableCudaGraphBackend`
  - `TcPiecewiseCudaGraphBackend`
  - Pluggable per phase
  - Selected at initialization by:
    - `resolve_prefill_backend(model_runner)`
    - `resolve_decode_backend(model_runner)`
  - Backend type comes from:
    - `cuda_graph_config[phase].backend`

---

### Phase Runner API (`BaseCudaGraphRunner`)

Exposed upward to `ModelRunner`.

Each method delegates strategy-specific behavior to `self.backend`.

| Method | Purpose |
|---|---|
| `can_run(forward_batch) -> bool` | Determine whether the current batch can use a captured graph. Performs runner-level filtering before consulting the backend. |
| `capture()` | One-time capture entrypoint. Enumerates all capture shapes and invokes `capture_one_shape()` for each. |
| `capture_one_shape(size, ...)` | Captures a single shape. Builds a dummy forward batch and delegates actual capture to `self.backend.capture_one(...)`. |
| `replay_prepare(forward_batch, **kwargs) -> ForwardBatch` | Pads or reshapes inputs to match a captured shape and returns the static batch used during replay. |
| `replay(forward_batch, ...) -> ModelOutput` | Executes the captured graph via `self.backend.replay(...)`. |

---

### CG Backend API (`BaseCudaGraphBackend`)

Exposed downward to the phase runner.

| Method | Purpose |
|---|---|
| `prepare(runner)` | One-time setup against the owning runner. Wires static buffers, patches the model module, and installs forward hooks. |
| `setup_prefill_state(runner)` *(prefill only)* | Additional one-time initialization for prefill-specific state. |
| `can_run(forward_batch) -> bool` | Strategy-specific runtime gate. Examples: BCG rejects sparse-DP batches; TcPiecewise checks `torch.compile` state. |
| `capture_session(stream)` *(context manager)* | Wraps the entire capture phase. Sets graph-pool ID, capture flags, allocator hints, etc. |
| `capture_one(num_tokens, ...)` | Captures a single shape. The runner provides the dummy batch; the backend performs warmup and recorded forward execution. |
| `has_shape(shape_key) -> bool` | Returns whether a recorded graph exists for the given shape. Used by `runner.can_run()`. |
| `runtime_session()` *(context manager)* | Wraps a replay execution. Sets replay flags, locks caches, and scopes graph resources. |
| `replay(shape_key, forward_batch) -> ModelOutput` | Executes the recorded graph corresponding to the shape key. |
| `populate_prefill_dummy_inputs(...)` *(prefill only)* | Fills capture-time placeholders so recorded graphs observe stable input addresses. |
| `commit_prefill_serving_inputs(forward_batch)` *(prefill only)* | Copies real serving inputs into static buffers immediately before replay. |
| `cleanup()` | Releases graph pools and removes any model patching. |

---

### Runner → Backend Interaction

#### Initialization

Once per runner:

    runner.init
    └─ self.backend = resolve_{prefill,decode}_backend(model_runner)
       ├─ self.backend.prepare(self)
       └─ prefill only:
          └─ self.backend.setup_prefill_state(self)

---

#### Capture

Once, across all capture shapes:

    runner.capture()
    └─ with backend.capture_session(stream):
       └─ for size in capture_shapes:
          └─ runner.capture_one_shape(size)
             ├─ build dummy forward_batch
             │  └─ runner-owned logic
             ├─ prefill only:
             │  └─ backend.populate_prefill_dummy_inputs(...)
             └─ backend.capture_one(num_tokens, ...)
                └─ warmup + recorded forward

---

#### Replay

Per forward, on the hot path:

    ModelRunner.forward(batch)
    ├─ if not runner.can_run(batch):
    │  └─ fall back to eager
    │
    │     runner.can_run() internally consults:
    │     - backend.has_shape(...)
    │     - backend.can_run(...)
    │
    ├─ static_batch = runner.replay_prepare(batch)
    │  └─ prefill only:
    │     └─ backend.commit_prefill_serving_inputs(batch)
    │
    └─ with backend.runtime_session():
       └─ output = backend.replay(shape_key, static_batch)

---

### Backend-Specific Overrides

| Backend | Capture mechanism | Distinct overrides |
|---|---|---|
| `FullCudaGraphBackend` | `torch.cuda.CUDAGraph` over the entire model forward | `capture_session()`, `capture_one()`, `replay()` |
| `BreakableCudaGraphBackend` | Multiple `torch.cuda.CUDAGraph` segments stitched at `eager_on_graph` breakpoints | `capture_one()`, `replay()`, plus per-segment metadata in `attn_metadata_buffers` |
| `TcPiecewiseCudaGraphBackend` | `torch.compile(mode="reduce-overhead")` with FX-level piecewise splits | `prepare()` installs compile hooks; `capture_one()` drives `torch.compile` warmup; no direct graph replay recording because `torch.compile` owns execution |

---

### Where the Seam Matters

The runner/backend boundary is the extensibility point.

Adding a new CUDA Graph strategy requires:

1. Creating a new `BaseCudaGraphBackend` subclass.
2. Registering it in the backend factory.

The phase runner code should remain unchanged.

This refactor replaces the previous design where each strategy required its own runner implementation.

The strict API contract is the runner call points listed above. If a new strategy requires additional coordination, the corresponding hook should be added to `BaseCudaGraphBackend` so that all runners can drive the strategy uniformly.
