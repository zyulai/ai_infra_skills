## Motivation
Fix type mismatch in LoRA batch validation that could cause assertion failures during high-concurrency multi-LoRA inference. The `can_run_lora_batch` method expects list[str] but passes it directly to `validate_lora_batch` which expects `set[str]`, causing potential validation logic failures when the scheduler attempts to merge requests with different LoRA adapters into a single batch.

Scenario: Most beneficial when running benchmarks with multiple LoRA adapters (e.g., --lora-name adapter1 adapter2 ... adapter16) but lora pool size is smaller than lora adapter numbers.  
<!-- Describe the purpose and goals of this pull request. -->

## Modifications
Change: Added type conversion in can_run_lora_batch method to ensure `lora_ids` is converted to a set before passing to `validate_lora_batch`
