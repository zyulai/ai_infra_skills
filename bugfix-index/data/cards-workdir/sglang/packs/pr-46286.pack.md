## 正文(PR 描述)

## Summary

ComfyUI's native `QwenImageTransformer2DModel.forward` passes `attention_mask`, `additional_t_cond` and (via `**kwargs`) `ref_latents_method`. `QwenImageEditAdapter.pack()` in `apps/ComfyUI_SGLDiffusion/executors/qwen_image.py` caught all three in `**kwargs` and never forwarded them: the request sent to the SGLD worker was identical whether or not these were set, so a workflow using them silently ran with the worker's hardcoded defaults instead (the worker's `QwenImagePipeline` fixes `zero_cond_t` per checkpoint at load, and always applies reference latents the way native ComfyUI's default `ref_latents_method="index"` does).

`ZImageAdapter.pack()` (Lumina2 / Z-Image) has the same gap for Z-Image Omni's `siglip_feats` / `ref_contexts` (multi-reference conditioning): the worker's `ZImagePipeline` has no path for either, so a reference-image workflow would silently produce a plain text-to-image result.

This is the same failure mode #43404 fixed for `FluxAdapter`'s `ref_latents`/`control`: instead of a silent wrong result, both `pack()` methods now raise a clear `ValueError`.

I checked native ComfyUI source (`comfy/ldm/qwen_image/model.py`, `comfy/ldm/lumina/model.py`, `comfy/model_base.py`) before picking which kwargs to reject:
- `ref_latents_method` defaults to `"index"` (`self.default_ref_method`); the worker only supports that mode, so only a non-default value (`"index_timestep_zero"`, `"negative_index"`) is rejected.
- `attention_mask` / `additional_t_cond` for Qwen-Image are both genuinely conditional in `QwenImage.extra_conds` (only set when meaningful), so rejecting any non-`None` value cannot false-positive on an ordinary workflow.
- For Z-Image, I deliberately did **not** reject `num_tokens` or `attention_mask`: `Lumina2.extra_conds` sends `num_tokens` on every call (derived from the text context length), and native ComfyUI's own `patchify_and_embed` discards `attention_mask`'s effect regardless, so dropping either already matches native behavior exactly. Only `siglip_feats`/`ref_contexts` (confirmed to arrive only when a reference image is actually wired in) are a real silent-drop bug there.

## Test plan

Extended `test/unit/test_comfyui_adapters.py` (reusing its existing `_qwen_image_edit_adapter()` ComfyUI-stub helper):
- `test_qwen_image_edit_pack_rejects_unsupported_kwargs`: asserts `ValueError` for `attention_mask`, `additional_t_cond`, and `ref_latents_method="negative_index"`; asserts the default method and no extra kwargs still pack successfully.
- `test_zimage_pack_rejects_omni_reference_conditioning`: asserts `ValueError` for `siglip_feats`/`ref_contexts`; asserts `num_tokens`/`attention_mask` (sent on every real call) and absent `siglip_feats`/`ref_contexts` still pack successfully.

The full `sglang` package is too heavy to install for a CPU-only check of this isolated fix, so I verified the exact same logic against the modified source files directly (stubbing only the ComfyUI-side imports, the same technique the existing test file already uses) on Modal CPU: 9/9 checks pass, including regression checks that unchanged default-arg behavior (no new kwargs passed) is unaffected for both adapters.

No GPU run: this is pure Python kwarg validation in `pack()`, no model weights or worker round-trip involved.
