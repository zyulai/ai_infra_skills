## PR body
```markdown
## Motivation

With the `vectorized_5d` KV-cache layout (`SGLANG_AITER_KV_CACHE_LAYOUT=vectorized_5d`) and an fp8 KV cache (`--kv-cache-dtype fp8_e4m3`), `MHATokenToKVPool.set_kv_buffer` divides K and V by their scales and casts them to fp8 in four elementwise launches per layer, and only then runs the 5D writer. This PR moves the divide and the cast into the 5D writer, which quantizes as it writes, so those four launches go away.

## Modifications

- `python/sglang/kernels/ops/kvcache/shuffle_5d_cache.py`: the 5D writer takes optional K and V scales. With an fp8 cache it divides in fp32, saturates to the fp8 range as the other fused fp8 KV writes do, and casts. A scale may be a device tensor (read inside the kernel, so CUDA graph capture needs no host sync), a host tensor or a float. For a cache of the source's dtype the writer is unchanged.
- `python/sglang/srt/mem_cache/memory_pool.py`: with the `vectorized_5d` layout and an fp8 cache, `set_kv_buffer` hands the scales to the writer instead of quantizing first. The caller's K and V are no longer divided in place.
- `python/sglang/srt/layers/attention/aiter_backend.py`: the gfx950 head-dim-256 fresh fp8 prefill reads the K and V it has just written back from the cache, as the head-dim-128 ASM branch does, instead of casting the raw K and V and applying their descales, which assumed the write had divided them in place. It also quantizes q with `_quantize_q_fp8` rather than descaling it by `k_scale`. On main this branch is already wrong with non-unit KV scales, since the NHD fp8 write does not divide in place either.
- `test/registered/attention/test_aiter_fp8_kv_scales_paths.py`: a head-dim-256 fresh-prefill case that runs `forward_extend` with its own cache write into a real pool, with non-unit scales, in both layouts.
- `test/registered/kernels/ops/kvcache/test_shuffle_5d_fp8_write.py` (new, registered for AMD CI): checks the fused write against an fp32 divide, saturate and cast for each way of giving the scales, saturation past the fp8 range, and a bf16 round trip.

## Accuracy Tests

|---|---:|---:|
| meta-llama/Llama-3.1-8B-Instruct | 0.756 | 0.744 |
| Qwen/Qwen3-8B | 0.905 | 0.904 |
| Qwen/Qwen2.5-7B-Instruct | 0.025 | 0.033 |
| amd/Llama-3.3-70B-Instruct-FP8-KV | 0.000 | 0.010 |

The last two rows are already broken on main, and this PR does not change that. Controls on main, same setup:

| Model | NHD, bf16 KV | NHD, fp8 KV | vectorized_5d, bf16 KV | vectorized_5d, fp8 KV |

- Llama-3.3-70B-Instruct-FP8-KV works with an fp8 KV cache in the NHD layout (0.948) and fails only with `vectorized_5d` plus fp8: 0.000 on main and 0.010 with this PR. That combination is broken on main independently of this change and needs its own fix as well: #48434 quantizes q with its own scale in the prefill over a cached prefix. With both PRs it scores 0.945.

Unit tests on the same image: `test_shuffle_5d_fp8_write.py`, `test/registered/attention/test_aiter_fp8_kv_scales_paths.py` and `test/registered/attention/test_fused_fp8_kv_write.py` pass on this branch. +"""The SHUFFLE 5D KV writer's fused fp8 quantization: from bf16 K/V and
+per-tensor scales it writes what an fp32 divide, a saturation to the fp8 range
+and a cast would, for each way a scale can be given, and a cache of the
+source's dtype is written as before."""

+register_amd_ci(est_time=12, stage="jit-kernel-unit", runner_config="amd")

+_HAS_GPU = torch.cuda.is_available()
+NUM_TOKENS, NUM_HEADS, HEAD_SIZE, BLOCK_SIZE, NUM_BLOCKS = 37, 8, 128, 16, 8
+
+
+def _caches(dtype: torch.dtype) -> tuple[torch.Tensor, torch.Tensor]:
+    x = 16 // torch.empty((), dtype=dtype).element_size()
+    shape_k = (NUM_BLOCKS, NUM_HEADS, HEAD_SIZE // x, BLOCK_SIZE, x)
+    shape_v = (NUM_BLOCKS, NUM_HEADS, BLOCK_SIZE // x, HEAD_SIZE, x)
+    return (
+        torch.zeros(shape_k, dtype=dtype, device="cuda"),
+        torch.zeros(shape_v, dtype=dtype, device="cuda"),
+    )
+

+@unittest.skipUnless(_HAS_GPU, "Triton kernels require a GPU")
+class TestShuffle5dFp8Write(unittest.TestCase):
+    def setUp(self):
+        from sglang.kernels.ops.quantization.fp8_kernel import fp8_dtype
+
+        torch.manual_seed(0)
+        self.fp8 = fp8_dtype

+        self.k = 4 * torch.randn(shape, dtype=torch.bfloat16, device="cuda")
+        self.v = 4 * torch.randn(shape, dtype=torch.bfloat16, device="cuda")
+        slots = torch.randperm(NUM_BLOCKS * BLOCK_SIZE, device="cuda")
+        self.loc = slots[:NUM_TOKENS].to(torch.int64)
+
+    def _written(self, k_scale, v_scale) -> tuple[torch.Tensor, torch.Tensor]:
+        """K and V read back from an fp8 cache the fused path wrote."""
+        from sglang.kernels.ops.kvcache.shuffle_5d_cache import (
+            launch_gather_shuffle_5d_to_linear,
+            launch_reshape_and_cache_shuffle_5d,
+        )

+        k_cache, v_cache = _caches(torch.uint8)
+        k_cache, v_cache = k_cache.view(self.fp8), v_cache.view(self.fp8)
+        launch_reshape_and_cache_shuffle_5d(
+            self.k, self.v, k_cache, v_cache, self.loc, k_scale=k_scale, v_scale=v_scale
+        )
+        return launch_gather_shuffle_5d_to_linear(k_cache, v_cache, self.loc)
+
+    def _expected(self, scale: float, x: torch.Tensor) -> torch.Tensor:
+        # A one-element divisor, not a Python float: dividing by a Python float
+        # multiplies by its fp32 reciprocal, which differs from the kernel's
