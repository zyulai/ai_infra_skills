## 正文(PR 描述)

## Purpose

The Transformers backend (`model_impl="transformers"`) passes `mm_token_type_ids` from the cached multimodal features into `model.get_rope_index(...)`. That tensor is **full-sequence** (one entry per prompt token), but it is cached **per multimodal item**, keyed by `mm_hash` (image content) — not by the request.

So when two requests share an identical image (same `mm_hash` → multimodal-processor-cache hit) but have **different prompt lengths**, the second request reuses the first request's `mm_token_type_ids`. Its length no longer matches `input_ids`, and `get_rope_index` crashes:

```
RuntimeError: The expanded size of the tensor (N) must match the existing size (M)
at non-singleton dimension 1.  Target sizes: [3, N].  Tensor sizes: [3, M]
```

Under V1 this kills the engine core for that rank. It affects M-RoPE VLMs run through the Transformers fallback (e.g. Qwen2.5-VL, GLM-4.1V) whenever `mm_processor_cache_gb > 0` (the default).

**Fix:** recompute `mm_token_type_ids` for the current request from its per-request placeholder ranges (`mm_features[*].mm_position`), which are recomputed every request, instead of reading the cached per-image value — and stop gathering it from the cached features.

## Minimal repro

Two requests, same image, different text length. Random weights via `load_format="dummy"` (no checkpoint download — the bug is structural, not weight-dependent).

```python
import os
os.environ["VLLM_ENABLE_V1_MULTIPROCESSING"] = "0"  # in-process -> real traceback

import numpy as np
from PIL import Image
from transformers import AutoProcessor
from vllm import LLM, SamplingParams

MODEL = "Qwen/Qwen2.5-VL-3B-Instruct"
proc = AutoProcessor.from_pretrained(MODEL)
img = Image.fromarray(np.random.default_rng(0).integers(0, 255, (336, 336, 3), dtype=np.uint8))

llm = LLM(model=MODEL, model_impl="transformers", load_format="dummy", enforce_eager=True, max_model_len=4096)
sp = SamplingParams(temperature=0.0, max_tokens=8)

def request(text):
    messages = [{"role": "user", "content": [{"type": "image"}, {"type": "text", "text": text}]}]
    prompt = proc.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    return {"prompt": prompt, "multi_modal_data": {"image": [img]}}

llm.generate(prompts=[request("Describe.")], sampling_params=sp)                       # donor: fills mm cache
llm.generate(prompts=[request("Describe this image in detail, at length.")], sampling_params=sp)  # target: crashes pre-fix
```

- **Before:** donor OK, target raises the `RuntimeError` above (`[3, target_len]` vs `[3, donor_len]`).
- **After:** both succeed.
- **Control:** passing `mm_processor_cache_gb=0` also avoids the crash (confirms the multimodal cache is the trigger).

|-------|--------|-------|
| `Qwen/Qwen2.5-VL-3B-Instruct` | CRASH `[3,174] vs [3,167]` | donor OK, target OK |
