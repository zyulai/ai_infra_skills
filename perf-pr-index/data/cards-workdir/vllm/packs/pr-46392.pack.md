## PR body
```markdown
## Purpose

FlashInfer fused allreduce+RMSNorm is gated by world size in two places, and
neither currently admits `world_size=16`:

- `PassConfig.flashinfer_max_size()` returns `None` unless the world size is in
  `FI_SUPPORTED_WORLD_SIZES` (was `[2, 4, 8]`), and
- it then looks up `FI_ALLREDUCE_FUSION_MAX_SIZE_MB[capability]`, which for SM 10.3
  (GB300) had no `16` entry.

When either is missing, `flashinfer_max_size(16)` is `None`, so both the
`AllReduceFusionPass` and the standalone `FlashInferAllReduce` communicator disable
themselves and TP=16 falls back to a plain all-reduce plus a separate RMSNorm.

This became reachable now that #46001 makes **TEP=16 functional** for DeepSeek-V4
(block-FP8 shared expert sharding). This PR is the perf follow-up that turns the
fused path on at `world_size=16` and supplies the benchmarked threshold — the same
thing #37756 did for `ws=2/4/8`.


## Justification

Benchmarked on a GB300 NVL system — 4 nodes × 4 GPUs in one NVLink domain
(`world_size=16`), bf16, hidden=7168 (DeepSeek-V4-Pro), CUDA-graph, 100 trials. ms/op.

### Standalone all-reduce — `benchmark_device_communicators.py`, ws=16

This is the comparison that sets the value: FlashInfer mnnvl vs `pynccl` (the
multi-node fallback). mnnvl wins through 56 MiB, **ties at 64 MiB**, loses above.

| Tensor Size | flashinfer_mnnvl | pynccl | Winner |
|-------------|-----------------:|-------:|--------|
| 28 MB | 0.122 | 0.161 | mnnvl (1.32×) |
| 42 MB | 0.180 | 0.211 | mnnvl (1.17×) |
| 56 MB | 0.238 | 0.249 | mnnvl (1.04×) |
| **64 MB** | **0.271** | **0.271** | **tie** |
| 70 MB | 0.296 | 0.286 | pynccl |
| 84 MB | 0.354 | 0.322 | pynccl |

`64` is the break-even (mnnvl is not worse through 64 MiB) and matches the `ws=2/4`
convention of `64` for "fusion competitive across the swept range." It is also a
lower bound on the true fusion threshold: `FI_ALLREDUCE_FUSION_MAX_SIZE_MB` actually
gates *fused* AR+RMSNorm vs *unfused (AR + a separate RMSNorm kernel)*, and the fused
op does the RMSNorm for free — so the real crossover is at least the AR-only one.
(`56` — the last strict win — is the more conservative alternative; the 56↔64 region
is flat / within noise.)

### Fused AR+RMSNorm — `benchmark_fused_collective.py`, ws=16 (corroboration)

Confirms fusion is strongly beneficial and that the one-shot flag is inert for mnnvl
(one-shot ≡ two-shot at every size):

| Input Size | Standard (compiled) | mnnvl 1shot | mnnvl 2shot |
|------------|--------------------:|------------:|------------:|
| 7 MB | 0.164 | 0.033 (5.0×) | 0.033 (5.0×) |
| 28 MB | 0.386 | 0.125 (3.1×) | 0.125 (3.1×) |
| 56 MB | 0.700 | 0.254 (2.8×) | 0.254 (2.8×) |
| 112 MB | 1.278 | 0.510 (2.5×) | 0.510 (2.5×) |
| 224 MB | 2.419 | 1.017 (2.4×) | 1.017 (2.4×) |

Caveat: in this environment the `nccl_allocator` failed to link (the pip-wheel
`libnccl.so.2` isn't on the linker path), so NVLS/symmetric-memory was disabled and
the `standard` baseline is slower than on a fully-configured node — this inflates the
fused speedup and is why the fused-vs-standard crossover never appears here. The `64`
value is therefore anchored on the standalone-AR table above (mnnvl vs `pynccl`),
which is symmetric-memory-independent, not on this table.

## Relation to existing PRs (not a duplicate)

- **#37756**  — *"Add SM 10.3 all-reduce communicator tuning"* — set these
  same tables for `ws=2/4/8`. This PR extends the identical mechanism to `ws=16`
  using the same two benchmarks. Different world size; not a duplicate.
- **#46001**  — makes TEP=16 *functional* for DeepSeek-V4 (block-FP8 shared
  expert). That PR touches only the V4 model; it does not enable the fused allreduce.
  This PR is the orthogonal perf enablement and depends on TEP=16 being reachable.
- **#40970**  — fixes the FlashInfer allreduce *benchmark* harness; does not
  touch the threshold tables.

`gh pr list --state open --search "FI_ALLREDUCE_FUSION_MAX_SIZE_MB"` and related
searches found no open PR adding a `ws=16` threshold.

## Test Plan

Run on a GB300 NVL system (4 nodes × 4 GPUs = 16 in one NVLink domain), the same two
benchmarks #37756 used:

```bash
# Standalone all-reduce communicator comparison (sets the value)
torchrun --nnodes 4 --nproc_per_node 4 \
    benchmarks/kernels/benchmark_device_communicators.py \
    --num-warmup 10 --num-trials 100

# Fused allreduce+rmsnorm vs standard (corroboration; ws=16 enablement is in this PR)
FI_BACKENDS=mnnvl torchrun --nnodes 4 --nproc_per_node 4 \
    benchmarks/kernels/benchmark_fused_collective.py \
    --hidden-dim 7168 --num-tokens 128 256 512 1024 2048 4096 \
    --quant-modes none --warmup 10 --trials 100
```

Results: tables above. mnnvl all-reduce beats `pynccl` through ~56–64 MiB at `ws=16`;
fused AR+RMSNorm is 2.4–8× over the non-fused path across the swept range.
