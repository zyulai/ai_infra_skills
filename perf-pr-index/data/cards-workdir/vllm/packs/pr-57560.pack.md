## Purpose

Add `aiter_flydsl` as an opt-in GDN prefill backend on ROCm. Supported BF16 GDN layers with 128-dimensional key and value heads route through AITER's optimized VK implementation with both the fused FlyDSL prepare stage and FlyDSL K5 enabled; unsupported platforms, shapes, dtypes, and older AITER builds retain the Triton/FLA path.

This requires the AITER APIs from ROCm/aiter#4532, ROCm/aiter#4598, ROCm/aiter#4694, ROCm/aiter#4732, and the prepare-kernel fix in ROCm/aiter#4952; all merged.

## Test Plan

**Hardware:** 8x MI355X (gfx950), ROCm 7.2.3
**Model:** `amd/Qwen3.8-2.4T-A95B-Quark-MXFP4`, TP8, BF16 GDN, FP8 KV cache

* **Kernel case:** Added `test_aiter_flydsl_prefill_matches_triton_reference`: packed sequences `[70, 130]`, BF16 Q/K/V, FP32 state, 128-dim heads, GQA ratio 2, run on device and compared against the *same* AITER entry point with `use_chunk_flydsl`/`use_prepare_flydsl` off. Using that as the reference means the two calls differ only in the kernels this backend exists to select. Verified passing on MI355X (gfx950).
* **Reference:** AITER `chunk_gated_delta_rule_opt_vk` with Triton prepare and Triton VK K5
* **Unit tests:** `tests/v1/attention/test_gdn_aiter_flydsl.py`, pruned to the cases that guard correctness:
  * `test_aiter_flydsl_prefill_matches_triton_reference[fp32_state|bf16_state]` — the numerical check. Packed sequences `[70, 130]` (both span several 64-token chunks and end in a partial one), BF16 Q/K/V, 128-dim heads, GQA ratio 2, run on device against the *same* AITER entry point with `use_chunk_flydsl`/`use_prepare_flydsl` off, so the two calls differ only in the kernels this backend selects. Parametrized over the SSM state dtype because `--mamba-ssm-cache-dtype` can make it FP32 or BF16 and the backend forwards `initial_state.dtype` to AITER; it also asserts the final state comes back in that dtype, since it is written back into the cache.
  * `test_resolve_aiter_flydsl_gdn_prefill_backend` — the shape/dtype gate. FlyDSL is only taken for BF16 with 128/128 key/value heads; any other combination must stay on Triton rather than reach kernels that don't support it.
  * `test_kda_style_model_cannot_select_flydsl` — Kimi K3 KDA shares this layer but builds its own chunk metadata, which the FlyDSL path skips. This pins that the resolver turns it down before that mismatch can happen.
  * `test_explicit_aiter_flydsl_fails_closed[kernels_missing|not_rocm]` — an explicit `aiter_flydsl` request on a build without the kernels, or off ROCm, raises instead of silently running Triton and reporting the run as FlyDSL.
