## Purpose

Reverts #65201 and its follow-up #65522. #65201 forced the `trtllm` FlashInfer all-reduce backend under HiSparse to avoid the MNNVL fused all-reduce + RMSNorm cluster-barrier race (#64327). The FlashInfer fix, flashinfer-ai/flashinfer#7782, is in FlashInfer 0.7.4, which main now uses (#67042). It was also cherry-picked into 0.7.3. #65522 only kept that override on lazy workspace creation, so it goes too. HiSparse gets the default backend selection again (`mnnvl` on a single node), which is 3–5% faster at TP4/TP8.

## Test Plan

```bash
pytest tests/distributed/test_comm_ops.py -k "flashinfer_auto_backend or workspace_failure or standalone_workspace"
```

The HiSparse GLM-5.3-NVFP4 TP4 B200 multi-turn repro from #65522 with `VLLM_FLASHINFER_ALLREDUCE_BACKEND` unset should log `backend=mnnvl` and finish with no `CUDA error`.
