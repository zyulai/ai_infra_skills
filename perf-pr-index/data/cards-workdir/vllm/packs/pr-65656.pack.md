## Overview
>Thanks to @yeshihai for identifying this optimization opportunity and implementing candidate-decode scoring in Triton in #62463. This PR builds on his work with a CuTe DSL/TMA implementation and extends candidate scoring to long-context prefill. 

Add a model-local CuTe DSL scorer for DeepSeek V4.1 candidate indexers on SM90. It reads candidate keys directly from the paged FP8 cache, supports decode and eligible long-context prefill, and is enabled automatically for supported configurations.

Related to [#61830](https://github.com/vllm-project/vllm/issues/61830). This takes a different implementation approach from [#62000](https://github.com/vllm-project/vllm/pull/62000), which gathers candidate keys before scoring, and [#62463](https://github.com/vllm-project/vllm/pull/62463), which implements Triton decode scoring: this PR uses TMA/WGMMA and shares the scoring path between prefill and decode.

## Claims

- Score the existing candidate pool directly, preserving the model’s candidate-selection policy.
- Share candidate preparation across consumer layers and bound logits scratch memory by `VLLM_SPARSE_INDEXER_MAX_LOGITS_MB`.
- Enable the path through the existing `indexer_sparse_logits` configuration. Supported configurations use it by default; explicit `False` disables it.
- On the tested 512K–approximately 1M workloads, improve end-to-end output throughput by **3.2%**, reduce mean TPOT by **4.6–5.0%**, and reduce ITL P50 by **18.5–28.4%**.

## Details

- **Shared execution:** Prefill and decode use one candidate-scoring path. Candidate row bounds and physical-page mappings are prepared once per step and reused by consumer layers. Scoring reads paged FP8 keys directly with TMA/WGMMA and produces FP32 logits.
- **Prefill selection:** Candidate scoring is selected when the longest compressed prefill context is at least twice both the candidate-pool capacity and the largest compressed query chunk. For V4.1-Flash with query chunks up to 16K, this gives a 32K compressed-context threshold. Other prefill batches use dense scoring for the whole batch, preserving reuse of keys across queries.
