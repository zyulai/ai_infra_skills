## Motivation

Supporting the block FP8 for qwen3.6-35B-A3B.

## Modifications

- Add  block FP8 Linear and MoE support for Qwen3.6 on NPU Ascend 950, without converting weights to MXFP8.
- Add a TP2 + NEXTN GSM8K accuracy test.
- Fix Qwen image/video preprocessing compatibility with Transformers resize APIs.

## Speed Tests and Profiling

Compared block FP8 execution against load-time conversion to MXFP8 on 950DT with TP2 and NEXTN enabled.

**Workload:** ShareGPT, 40 requests, fixed 64,000-token inputs and 1,000-token outputs, maximum client concurrency 10, unlimited request rate, temperature 0, seed 42.

| Metric | Native block FP8 | MXFP8 | Change |
|---|---:|---:|---:|
| Successful requests | 40/40 | 40/40 | — |
| Input throughput | 14,778.37 tok/s | 15,896.43 tok/s | +7.6% |
| Output throughput | 230.91 tok/s | 248.38 tok/s | +7.6% |
| Mean TTFT | 11,768.73 ms | 10,949.59 ms | −7.0% |
| Mean TPOT | 30.66 ms | 28.51 ms | −7.0% |
| Mean E2E latency | 42,402.11 ms | 39,426.63 ms | −7.0% |

Both runs processed 2.56M input tokens and generated 40K output tokens. In this comparison, MXFP8 improved throughput by approximately **7.6%** and reduced mean latency by approximately **7%**.

+"""Ascend arch35 G-B FP8 GEMMs with checkpoint-format FP32 block scales.
+
+Weights remain in [N, K] (or [E, N, K]) checkpoint layout. Only transpose
+views are passed to CANN; neither weights nor scales are requantized to MX.
+The TP deployment path requires nonempty activation batches; individual expert
+groups may be empty.
+"""
+
+from typing import Optional
+
+import torch
+
+
+def _quantize_input(x: torch.Tensor) -> tuple[torch.Tensor, torch.Tensor]:
+    return torch.ops.npu.npu_dynamic_block_quant(
+        x, dst_type=torch.float8_e4m3fn, row_block_size=1, col_block_size=128
+    )
+

+def npu_w8a8_block_fp8_linear(
+    input: torch.Tensor,
+    weight: torch.Tensor,
+    weight_scale: torch.Tensor,
+    bias: Optional[torch.Tensor] = None,
+) -> torch.Tensor:
+    """BF16/FP16 input, 128x128 FP8 weights, and FP32 block scales."""
+    output_dtype = input.dtype
+    output_shape = (*input.shape[:-1], weight.shape[0])
+    x = input.reshape(-1, input.shape[-1]).contiguous()
+    qx, x_scale = _quantize_input(x)
+    output = torch.ops.npu.npu_quant_matmul(
+        qx,
+        weight.t(),
+        scale=weight_scale.t(),
+        pertoken_scale=x_scale,
+        output_dtype=output_dtype,
+        group_sizes=[1, 128, 128],
+    )
+    # CANN's FP8 G-B mode does not accept bias. Add it after the GEMM.
+    if bias is not None:
+        output = output + bias.to(output_dtype)
+    return output.reshape(output_shape)
