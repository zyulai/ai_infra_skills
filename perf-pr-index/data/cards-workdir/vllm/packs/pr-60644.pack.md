## Overview

Speeds up fp16 prefill in `RDNAHybridW4A16LinearKernel` on gfx1151 (Strix Halo). The Triton prefill GEMM dequantizes two 4-bit weights per instruction, and gets tiles tuned for that dequant. Supersedes draft #55711.

## Claims

- fp16 prefill latency on gfx1151: 5–18% faster on Qwen3-4B (symmetric) at every prompt length from 64 to 2048 tokens, and 17–19% faster on Qwen3-8B (asymmetric) from 512 tokens, unchanged below.
- No change for bf16, or on any GPU other than gfx1151.
- No accuracy change: the dequant arithmetic is exact, and kernel output is bit-identical to main in all 1248 configs swept.

## Details

**Packed dequant.** For a 4-bit value `n`, the bits `0x6400 | n` read as fp16 are exactly `1024 + n`. One `v_and_or_b32` (`(x & 0x000F000F) | 0x64006400`) does this for two values at once, instead of the `v_and_b16` + `v_or_b16` per value that Triton emits. The ExLlama shuffle layout already puts paired values 16 bits apart, so no extra shuffling is needed. The kernel subtracts `1024 + zp` instead of `zp`, which is exact because fp16 represents every integer below 2048.

**When it is used.** Only fp16 on gfx1151, the only GPU it was measured on, decided on the host and passed to the kernel as the `PACKED_DEQUANT` constexpr. Asymmetric layers use it only above M = 256: the extra zero-point load made it 1.2–2.4x slower per GEMM below that.

**Tiles.** The packed fp16 path and the scalar bf16 path want different tiles, most visibly `BLOCK_N` 256 vs 64 at deep M. `_select_skinny_gfx1151_config` picks new tiles and `num_stages=1` for fp16 above M = 128 (M = 256 for asymmetric). Everything else keeps the existing ladder and overrides unchanged. `num_stages=1` stays off bf16, where it cost 15.8% end-to-end on an asymmetric model.

**Numerics.** The dequant result is unchanged. The new tiles change `BLOCK_K`, and with it the fp32 accumulation order, so fp16 output is not guaranteed bit-identical. In the kernel sweep it was bit-identical in all 1248 configs.

**Not duplicating.** #57199 changes the HIP decode kernel, not the Triton prefill path. #52637 changes symmetric weight loading in `process_weights_after_loading`. #60710 adds an opt-in (default off) dense weight cache that skips the int4 dequant at M ≥ 256; it edits the same file but leaves the Triton dequant and tile selection alone. No other open PR touches the prefill dequant or the gfx1151 tile selection.
