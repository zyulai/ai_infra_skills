## Modifications

### 1. Fix evalscope accuracy parsing in `python/sglang/test/ascend/e2e/test_npu_accuracy_utils.py`

evalscope 1.11+ reports accuracy as a percentage (e.g. `66.67%`), which was not matched by the existing regex patterns and was not normalized against the baseline.

- Add a new regex pattern  ` Accuracy\s*[↑↓]?\s*│\s*[^│]*│\s*\d+\s*│\s*([\d.]+)%?\s*│` to match the evalscope 1.11+ output format.
- Switch from `re.findall` to `re.finditer` so the full match (used for the `%` detection) and the captured group are both available.
- Normalize percentage-formatted accuracy to a 0-1 fraction (divide by `100.0`) before comparing against the baseline.

### 2. Add request timeout to glm5\_1 aime26 test in `test/registered/npu/accuracy/glm5_1/test_npu_glm5_1_w4a8_1p1d_32p_in64k_out1k_50ms_aime26.py`

Add `--request-timeout-secs 7200` to the `router_args` to prevent the multi-node aime26 accuracy test from timing out during long-running evalscope requests.


### 3. Adjust `--mem-fraction-static` for kimi_k2_6 64k perf test in `test/registered/npu/performance/kimi_k2_6/test_npu_kimi_k2_6_w4a8_16p_in64k_out1k_100ms.py`

Set `--mem-fraction-static` to `0.68`. The previous `0.662` leaves the KV pool too small for 64k input (max allowed length 61050 < 64000), while `0.7` causes prefill OOM in the MLP `down_proj` quantized matmul. `0.68` balances the KV pool (~77000 tokens) and dynamic activation space.

### 4. Switch accuracy‑test metric from 3‑run average to maximum value
`test/registered/npu/accuracy/qwen3_next_80b_a3b_instruct/test_npu_qwen3_next_80b_w8a8_2p_in6k_out1k5_bs16_aime25.py`

run_accuracy_multiple->run_accuracy
