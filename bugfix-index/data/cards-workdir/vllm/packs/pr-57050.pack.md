## 正文(PR 描述)

## Purpose
It is found for Kimi K3, a long request can be rejected admission when loading prefix cache from external KV storage (e.g., Mooncake) and get stuck in the waiting queue forever, causing entire system to stall. Investigation shows the bug is in Mamba's block allocation estimation call `get_num_blocks_to_allocate`, which incorrectly calculates the physical blocks needed for such requests, potentially a regression caused by https://github.com/vllm-project/vllm/pull/53614

Stall reproduction on 8 x B300:
```
export VLLM_SERVER_DEV_MODE=1
export WITH_NVIDIA_PEERMEM=0
export MOONCAKE_CONFIG_PATH=mooncake_config.json
export VLLM_MOONCAKE_BOOTSTRAP_PORT=50052
export MC_ENABLE_DEST_DEVICE_AFFINITY=1

vllm serve moonshotai/Kimi-K3 \
    --load-format fastsafetensors \
    --tensor-parallel-size 8 \
    --decode-context-parallel-size 8 \
    --cp-kv-cache-interleave-size 1 \
    --dcp-comm-backend a2a \
    --kv-cache-dtype fp8 \
    --mamba-ssm-cache-dtype bfloat16 \
    --enable-prefix-caching \
    --prefix-match-unit 128 \
    --max-model-len 1048576 \
    --max-num-batched-tokens 8192 \
    --max-num-seqs 32 \
    --max-cudagraph-capture-size 2048 \
    --compilation-config '{"mode":0}' \
    --no-enable-flashinfer-autotune \
    --gpu-memory-utilization 0.9 \
    --attention-backend TOKENSPEED_MLA \
    --attention-config '{"mla_prefill_backend":"TRTLLM_RAGGED","use_prefill_query_quantization":true}' \
    --language-model-only \
    --trust-remote-code \
    --kv-transfer-config '{"kv_connector":"MooncakeStoreConnector","kv_role":"kv_both","kv_load_failure_policy":"recompute","kv_connector_extra_config":{"load_async":true,"lookup_async":true,"enable_cross_layers_blocks":false}}'
```

Sending a 1M-length request, clear the GPU local kv cache, and send the same request again causes the entire system to stall as the request fails the admission gate.

## Test Plan
Added unit test that checks equality of estimated blocks vs actual allocated blocks for mamba in `tests/v1/core/test_single_type_kv_cache_manager.py`, existing main fail the tests while the branch passes.
