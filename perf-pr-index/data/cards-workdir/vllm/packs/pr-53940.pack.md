## PR body
```markdown
## Summary

- When `VLLM_ROCM_USE_AITER_MOE_SITUV2_A8W4=1` (the existing Kimi-K3 recipe toggle), route SiTU MXFP4 routed experts through AITER's **a4w4** flydsl kernels (`afp4_wfp4_fp4`, `fp4q`) instead of the previous **a8w4** path (`afp8_wfp4_fp8`, `fp8q`, `_gui_` interleave).
- vLLM sets `AITER_SITUV2_A4W4=1` at init and clears any legacy `AITER_SITUV2_A8W4` override (AITER checks A8W4 first, so leaving it set would still pick afp8).
- SiTUv2 gate/up weights use the **separated** layout to match ATOM kernel selection.

No new env flags; the existing recipe variable keeps its name for compatibility.

## AITER requirement

This path needs [ROCm/aiter#4463](https://github.com/ROCm/aiter/pull/4463) (first tagged in **AITER v0.1.20**): `AITER_SITUV2_A4W4` dispatch plus `kimik3_a4w4_{un,}tuned_fmoe.csv`. vLLM `main` already pins `AITER_BRANCH=v0.1.21.post1`, which includes that PR.

On AITER **v0.1.19** (this PR's original docker pin), a4w4 still launches `flydsl_moe1_afp4_wfp4_bf16_*` but logs **heuristic FlyDSL fallback** because the tuned CSV rows are missing. That is not the tuned a4w4 config from #4463.

## Motivation

Trace comparison on Kimi-K3 / MI355X shows vLLM dispatching `mfma_moe1_silu_mul_afp8_wfp4_fp8_*_gui_xcd4_*` while ATOM uses `mfma_moe1_silu_mul_afp4_wfp4_fp4_*_situv2_*`. AITER supports a4w4 via `AITER_SITUV2_A4W4` in #4463; vLLM previously wired the recipe toggle to a8w4. Open PR #50813 adds explicit opt-in a8w4 for Quark checkpoints — this change makes a4w4 the default for the existing SiTUv2 recipe path.

## Results

GSM8K (Kimi-K3 MXFP4, MI355X, TP=8, `VLLM_ROCM_USE_AITER_MOE_SITUV2_A8W4=1`, greedy 5-shot, full test split `n=1319`):

| Filter | Metric | This PR (a4w4) | Prior a8w4 recipe |
|---|---|---|---|
| strict-match | exact_match | **0.9659 ± 0.005** | 0.9666 |
| flexible-extract | exact_match | **0.9659 ± 0.005** | 0.9666 |

No accuracy regression (within stderr). Decode dispatch used `flydsl_moe1_afp4_wfp4_bf16_*` (fp4 activations); no `afp8` / `_gui_` kernels.

`niah_single_2` at 32k (`n=20`): **1.0** on both a4w4 and a8w4.

8k ISL / 1k OSL serving on AITER **without** #4463 tuned CSVs (heuristic a4w4 vs tuned a8w4) is a wash (~0.5% at conc 4/8). Isolated kernel timings in AITER #4463 show a4w4 ahead of a8w4 once the tuned rows are present.
```
