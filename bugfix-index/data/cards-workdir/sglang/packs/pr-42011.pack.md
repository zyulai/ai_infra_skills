## Motivation

Two MoE fixes for DSV4.1-Flash When running it with `--enforce-shared-experts-fusion` on ROCm.
1) Issue: Resolve the shared-expert requant accuracy lost
2) Perf opt: Fused decode routing kernels into one.

## Modifications

- On ROCm, requantize the FP8 shared expert to MXFP4 with round-to-nearest-even (aiter `dynamic_mxfp4_quant` scaling). The old cast rounded midpoints toward zero, which shrank the shared expert by ~5%. Other platforms keep the existing requant (output unchanged).
- `rocm_router_gate` now writes the fused shared-expert columns in the same launch, so decode no longer falls back to reduce + topk + append.
- Use aiter's multi-phase MoE sorting for small batches via `SGLANG_AITER_MOE_SORTING_DISPATCH_POLICY` (default 2; 0 restores aiter's auto policy).
- Update the requant unit test and add `test_rocm_router_gate.py` cases.

## Accuracy Tests

GSM8K 1319 5-shot, TP2 with fusion: 0.891 -> 0.906 (3 runs), matching unfused (0.904 / 0.905). With the router change: 0.897 / 0.901 / 0.900.

## Speed Tests and Profiling

MI355X TP2 + DSpark, per decode step: router -0.41 ms, sorting -0.13 ms.
AgentX: c1 11,371.9 tok/s/GPU, P90 349.5 (+2.6% / +4.8%); c2 11,819.8, P90 324.6 (+2.8% / +10.7%).

+    # Scale as in aiter dynamic_mxfp4_quant: round amax's mantissa at 1.75, then
+    # floor(log2) - 2 (e2m1 emax), saturating the few elements above 6 * scale.
+    amax = x.abs().amax(dim=-1, keepdim=True).clamp_min(torch.finfo(torch.float32).tiny)
