## Overview

Emit CPU attention's final-partition workitems individually so workers can share
an oversized decode remainder.

## Claims

- Prevent the final partition from serializing multiple requests in one task.
- At batch 128 with 95 threads, measured attention latency improves from
  4.31 to 0.92 ms (4.67x throughput).
- Preserve partitioning, KV splits, reductions, and scratchpad sizing.

## Validation

Decode benchmark: BF16 AMX, context 4096, heads 32/4, head size 128, block size 32,
KV splitting enabled, and 95 threads. Results average two per-run medians with
alternating baseline/candidate order, five warmups, and 100 measurements per run
using `benchmarks/kernels/cpu/benchmark_cpu_attn.py`.

| Batch | Baseline ms | Candidate ms | Speedup |
|---:|---:|---:|---:|
| 64 | 0.614 | 0.579 | 1.06x |
| 128 | 4.310 | 0.923 | 4.67x |
| 190 | 1.321 | 1.300 | 1.02x |
| 192 | 1.594 | 1.310 | 1.22x |

Timings cover attention execution, excluding metadata generation and cache
packing. The balanced batch-190 control shows no measured regression.

- `pytest tests/kernels/attention/test_cpu_attn.py -q -k test_amx_spec_decode_gqa_correctness --disable-warnings`:
  12 passed on baseline and candidate, covering BF16/FP8 and both KV split modes.
- `pytest tests/kernels/attention/test_cpu_attn.py -q -k "test_varlen_with_paged_kv_normal_amx and None-128-128-num_heads1 and (seq_lens1 or seq_lens2)" --disable-warnings`:
  six mixed/prefill cases passed.
- At batch 128 with 95 threads, metadata changes from 380 spans, including four
  spans of 34 workitems, to 512 single-item spans. Inspection confirmed exactly-once
  coverage and unchanged workitem and reduction records.
- Fixed-input decode and prefill attention outputs match bit-for-bit.
- CPU `LLM` validation with Qwen2.5-1.5B-Instruct (BF16, 95 threads, 1024 input
  tokens, eight greedy output tokens, batches 64/128): all 192 requests pass
  `check_logprobs_close`; 188 token sequences match exactly. A baseline rerun also
  produces greedy variation (six sequences), passing the same check.
- `pre-commit run --files csrc/cpu/cpu_attn_impl.hpp tests/kernels/attention/test_cpu_attn.py`:
  passed. Commit hooks and `git diff --check` also passed.

The submitter has reviewed the changes. No end-to-end speedup is claimed.

## Details

The final partition accepts all work left by the earlier partition budgets. Reuse
the existing singleton emission path to make that remainder shareable across
workers. Single large prefill workitems remain indivisible;
additional task dispatch can add overhead for small workloads, particularly with
one thread where every workitem belongs to the final partition.

Open PR searches for CPU attention, scheduling, and task spans found no duplicate
fix.

AI assistance was used for implementation, validation, and review.
