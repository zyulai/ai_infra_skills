## Motivation

MOSS-Image joint blocks run three separate Q/K/V GEMMs for every conditional and unconditional denoising pass. This PR packs those projections for `quality=high` and lets the existing ordered RMSNorm+RoPE kernel read their strided Q/K views directly. The latter avoids copying Q and K back to contiguous storage after each packed GEMM.

The measured scope is MOSS-Image-Base, 1024×1024, 50 steps, batch 1 / concurrency 1 on one RTX PRO 6000 Blackwell Server Edition. Four repeated temporal pairs give a geometric-mean E2E speedup of **1.0141× over main** (1.386% lower latency) and **1.0222× over native Omni**; every pair is faster. The primary timed input is the fixed short product-photograph prompt; the long and Chinese prompts are quality checks. This is an eager optimization; it does not add or claim BCG coverage.

- Frozen main baseline: `af21e2b989e482cfdce39689126562f2209d53ac`.
- Tested PR head: `d752066eaa6f5091fa4c8daa2ba1d5d43a3928cd`.
- Native vLLM-Omni comparator: `817d4c17feb702289a2d2b2cbacfd594c262b7a7`.
- Common checkpoint: `OpenMOSS/MOSS-Image-Base@85975793d8b3d432f1b6e27f352abaa4c2a4c0d3`; all downloaded files were verified against the pinned file hashes.

## Modifications

- Reuse the existing checkpoint name mapping to merge Q/K/V in that order into one weight. There is no duplicate model weight or persistent view cache.
- Pass the quality choice through the request's denoising branch. `high` uses one packed GEMM; `exact/lossless` use three separate `F.linear` calls with fresh slices of the packed weight. A later request can change quality without reloading weights or mutating a module-wide mode.
- Extend the existing ordered norm+RoPE kernel to accept contiguous heads with a regular token stride. Reduction order and BF16 rounding in this kernel are unchanged; its result remains contiguous. Other layouts keep the existing fallback.
- Extend existing loading-order, quality-dispatch, offload/stream and numerical/stride tests; document the quality policy in the existing MOSS cookbook.
