## 正文(PR 描述)

### Summary

Fixes #65618.

`DSparkDeepseekV4ForCausalLM` across AMD, NVIDIA, and XPU platforms fuses `gate_up_proj` (from shards `w1`, `w3`) and `fused_wqa_wkv` (from shards `wq_a`, `wkv`) via `stacked_params_mapping`.

However, unlike the target model `DeepseekV4ForCausalLM`, `DSparkDeepseekV4ForCausalLM` omitted `packed_modules_mapping`. Consequently, when quantizers inspect whether layers are skipped via `is_layer_skipped(prefix, ignored_layers, fused_mapping=quant_config.packed_modules_mapping)`, the draft's fused layer prefixes could not be expanded to their constituent shard names.

When a checkpoint leaves these draft linear layers in unquantized BF16 via `quantization_config.ignored_layers`, the draft's fused layers still received `Fp8LinearMethod` with uninitialized weight scales (`weight_scale_inv`), leading to 0% draft token acceptance and invalid output.

### Changes
1. Added `packed_modules_mapping` to `DSparkDeepseekV4ForCausalLM` in:
   - `vllm/models/deepseek_v4/amd/dspark.py`
   - `vllm/models/deepseek_v4/nvidia/dspark.py`
   - `vllm/models/deepseek_v4/xpu/dspark.py`
   - `vllm/models/deepseek_v41/amd/dspark.py`
   - `vllm/models/deepseek_v41/nvidia/dspark.py`
2. Added unit tests in `tests/models/test_deepseek_dspark_packed_mapping.py` verifying that all DSpark draft model entry points define `packed_modules_mapping` and that `is_layer_skipped()` correctly resolves unfused shard names to skip fused draft layers.

### Testing
- `VLLM_TARGET_DEVICE=cpu python -m pytest --noconftest -q tests/models/test_deepseek_dspark_packed_mapping.py` passed all 7 CPU-selected tests with PyTorch 2.14.0 on macOS arm64. These cover the NVIDIA v4 and v4.1 mappings, the XPU mapping, and the NVIDIA `context_wkv_proj` ignored-layer cases. The run verified that the test did not load the ROCm platform or replace `torch.cuda.get_device_properties`.
- The two AMD mapping cases run under ROCm in the existing MI355 Basic Models (Other) job. The updated Buildkite run will verify them on that backend.
- `ruff check` and `ruff format --check` clean.


The NVIDIA context projection now checks that the quantization configuration exists and supports the ignored-layer matching mode before accessing it. This resolves the 10 mypy errors in the prior pre-commit run. The repository mypy hook passed across the Python tree with mypy 1.20.2, Python target 3.11 and Linux platform settings. All-file Ruff lint and format hooks passed.

The prior [CPU Buildkite job](https://buildkite.com/vllm/ci/builds/101629#01a1c839-d9a5-4fea-a212-eb701a3cc489) aborted at collection because importing ROCm from the CPU runner registered the `_C` native extension twice. The test now imports AMD models only on ROCm and no longer patches CUDA device discovery globally.

AI assistance was used for the CI type-checking, test collection and formatting fixes, and local validation.
