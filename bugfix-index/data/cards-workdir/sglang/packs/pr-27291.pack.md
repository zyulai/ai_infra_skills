## 正文(PR 描述)

## Motivation

Currently, such a test does not work with SWA + HiCache L3.:
1) Make a prefill of N tokens (N % page_size == 0)
2) /flush_cache
3) Make a prefill of the same N tokens, see the >= N - page_size cache hit

Prefetch N tokens from storage with a full cache hit due to SWA creates the following tree `(host_len, swa_host_len)`:

```
(N - page_size, null) --> (page_size, page_size)
```

But then after the prefetch, the correction for logprobs is used during the match:
https://github.com/sgl-project/sglang/blob/8e836e7dc9b8ff48987c21fdcf6bcd65b16a9837/python/sglang/srt/managers/schedule_batch.py#L1143-L1148

https://github.com/sgl-project/sglang/blob/8e836e7dc9b8ff48987c21fdcf6bcd65b16a9837/python/sglang/srt/managers/schedule_batch.py#L1082

https://github.com/sgl-project/sglang/blob/8e836e7dc9b8ff48987c21fdcf6bcd65b16a9837/python/sglang/srt/managers/schedule_batch.py#L1093-L1096

Due to the correction, the match does not see a leaf of the tree and as a result, there is no entry into the cache, because we did not prefetch the necessary SWA.

For non-SWA models, this is ok, because we can use the father of the leaf.

## Modifications

We align the match in the prefetch with the subsequent match.

After the fix after prefetch tree looks like:
```
(N - 2 * page_size, null) --> (page_size, page_size)
```
And we can hit `(N - page_size) / (N - 1)` tokens
