## Details

For strucutured output requests, the scheduler-side needs to know about the draft tokens proposed by the workers to compute grammar bitmasks and advance structured outputs grammar.

This is done via the `DraftTokensHandler`, which asynchronously copies draft tokens from the worker-side to the scheduler-side.

When async scheduling is used, the scheduler-side runs ahead of the workers and maintains a batch queue of pending batches, where `batch_queue_size = PP + 1`.

However, on main, `DraftTokensHandler` does not maintain a similar queue of copy synchronization barriers (CUDA events). It uses on barrier only, so the following can occur:
```
Scheduler-side                          Worker-side
---------------------------------------------------
Schedule Batch A with request `p`
                                        Run Batch A
Schedule Batch B
                                        Propose Batch A drafts and `DraftTokenHandler.set_draft_tokens`
                                        Run Batch B
Schedule Batch C with request `p`
                                        Propose Batch B drafts and `DraftTokenHandler.set_draft_tokens`
`DraftTokenHandler.get_draft_tokens` to get draft tokens from Batch A to compute request `p`'s grammar bitmasks.
```

The `get_draft_tokens` call in to get Batch A's draft tokens for Batch C races against the `set_draft_tokens` call from Batch B. Batch C cannot progress until Batch B's copy is complete, despite only needing Batch A's draft tokens. This introduces a pipeline bubble.

Under PP=1, this can occur but is rare. A running request will usually keep being scheduled in consecutive batches. However, skips can occur (see #66081), leading to bubbles.

Under PP>1, skips are not only possible but common. A decode request scheduled in batch `N` cannot be scheduled again until batch `N + PP`. This is enforced by `Request.next_decode_eligible_step`.

This is why E2E perf gains are only significant on PP>1 deployments.

The solution is to maintain one synchronization barrier per batch.
