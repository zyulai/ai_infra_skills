## Motivation

Initial weight loading + quantization processing for large MoE models (e.g., DeepSeek-V2 family with `--quantization fp8`, DeepSeek-V3, DeepSeek-V4-Pro with mxfp4) is expensive and re-runs every time the engine starts with the same parallelism + quantization config. This PR introduces a `presharded` load format that caches the post-`process_weights_after_loading` state on disk so subsequent runs skip the source-shard iteration, the model-specific `post_load_weights` conversion, and the quant-method `process_weights_after_loading` reshape on real data.

## Modifications

New `--load-format presharded` (`LoadFormat.PRESHARDED`). Behavior:

- **First run (dump)**: each rank loads weights normally, runs `post_load_weights`, runs `process_weights_after_loading` to materialize the inference-ready layout, then ranks coordinate to dump a per-rank deduplicated safetensors set under `<model_path>/presharded/<config subfolder>/`.
- **Subsequent runs (reload)** with the same config: each rank initializes the model, runs `process_weights_after_loading` once on uninitialized parameters purely to materialize post-process shapes, then multi-thread reads only the files it needs and `copy_`s dumped values in. Source ckpt is not iterated; `post_load_weights` is not re-run on real data.

Subfolder name is derived from a structural signature over TP/DP/EP/PP, quantization, dtype, EPLB, expert location, and related knobs (e.g. `TP-8-sig-…`).

### Algorithm (rank-coordinated dump)

1. Each rank hashes every tensor in its post-process state with **xxh3-128** over `(shape, dtype, raw little-endian bytes)` and writes a small JSON manifest. CUDA tensors use pinned streaming D2H so multi-GB weights never need a single contiguous host allocation. Hashing is multi-threaded (`hash_num_threads`, default 8); xxhash releases the GIL.
2. Rank 0 reads all manifests, deduplicates by content digest, groups by rank-list signature, and bin-packs into files of at most 20 GiB (balanced across writers). Rank 0 also computes a **per-rank aggregate checksum**: sum (mod 2^64) of per-tensor 64-bit folds of `xxh3(name + ":" + content_digest)`. The plan is published as `checksum.json`.
3. Each rank writes the files it owns (`model-…-common.safetensors` / `model-…-rank-….safetensors`).
4. After a final barrier, rank 0 writes a **`READY`** sentinel last so concurrent readers never observe a half-written dump.

### Reload path (efficiency)

- **Default `verify_on_load=false`**: pure multi-thread safetensors → device `copy_` (no content re-hash).
- **`verify_on_load=true`**: re-hash loaded tensors with xxh3 and compare the rank aggregate against `rank_checksums`.
- **Multi-thread I/O**: same knobs as the HF path — `enable_multithread_load` (default true) and `num_threads` (default 8). Workers only do disk→CPU reads; GPU apply stays on the main thread. Sliding window bounds host RAM to ~`num_threads` in-flight files.
- **No mid-load `empty_cache`**: params are filled with in-place `copy_`, so the caching allocator does not grow file-by-file. One sync + `empty_cache` at end of load matches `DefaultModelLoader`. Per-file `empty_cache` previously dominated large MoE reloads (hundreds of shards).

### Capture timing — why post-process

State is captured **after** both `model.load_weights` (so model-specific `post_load_weights` has run) **and** layer-level `quant_method.process_weights_after_loading` (so e.g. mxfp4 expert weights are already packed).

Reload reproduces the layout by running `process_weights_after_loading` on the initialized model *before* copying dumped values. The transform depends only on shape, not values. Non-`nn.Parameter` Tensor attributes installed by `post_load_weights` (`w_kc`, `w_vc`, `compressor.freqs_cis`, …) are persisted as extras and reinstalled via `setattr`. GemmaRMSNorm non-persistent `gemma_weight` and GDN Parameter aliases are refreshed/rebound after copy.

Post-process capture also avoids memory doubling on large quant models (e.g. DeepSeek-V4-Pro mxfp4: pre-process ~283 GB vs post-process ~223 GB per rank).

### Optional extra-config knobs (`--model-loader-extra-config`)

| Key | Default | Meaning |
|-----|---------|---------|
| `presharded_path` | under model path | Override dump/load directory |
| `max_file_bytes` | 20 GiB | Per-file cap |
| `hash_num_threads` | 8 | Parallel hash workers (dump / optional verify) |
| `verify_on_load` | **false** | Re-hash and check rank checksums |
| `enable_multithread_load` | true | Multi-thread file I/O on reload (and first-time HF load) |
| `num_threads` | 8 | Worker count for multi-thread load |

## Accuracy Tests

**DeepSeek-V4-Pro mxfp4, TP=4 EP=4 DP-attn, 4×GB300**: full param-hash diff between baseline (`--load-format auto`) and presharded reload with `verify_on_load=true`, hashing every `state_dict` entry **and** every non-`nn.Parameter` Tensor attr installed by `post_load_weights`. Result: **9288/9288 params bit-identical across all 4 ranks**.

Also verified on DeepSeek-Coder-V2-Lite-Instruct across TP/quant configs and on Qwen3.5 (including GDN / GemmaRMSNorm rebind) with matching generation text after reload.

Plan corruption (flipping one byte of `rank_checksums["0"]`) is correctly detected when `verify_on_load=true`.

## Speed Tests

Method (unless noted): **weight-load only** — no warmup generate, `disable_cuda_graph=True`, `max_total_tokens=10000`. Metric: scheduler `Load weight end. elapsed=` (max across ranks). Hardware: 8×H200. Reload uses default `verify_on_load=false`. Dump is one-time (source load + hash + write).
