## Motivation

This PR migrates the MSCCL++ integration from a statically-linked C++/CUDA kernel bundled inside `sgl-kernel` to the upstream **MSCCL++ Python package** (`mscclpp`). The new approach:

- **Supports the latest MSCCL++ version** — uses `mscclpp`'s Python-level `Executor`, DSL compiler, and native algorithm collection instead of the old hand-written CUDA kernels.
- **Provides a flexible algorithm interface** — algorithms are configured via `AlgorithmCollectionBuilder` (native) and `mscclpp.language` (DSL), making it easy to add new collective algorithms for different scales (currently TP=8 single-node and TP=16 two-node).
- **Adds auto-tuning** — at initialization, the communicator benchmarks all candidate algorithms × block/thread configurations using CUDA graph capture and selects the best per message size.
- **Integrates correctly with piecewise CUDA graph compilation** — prevents MSCCL++ from being used during compile/capture/replay phases, avoiding `torch.compile` guard invalidation and recompilation.
- **Supports symmetric memory (NVLS)** — enables `default_allreduce_nvls_zero_copy` when `--enable-symm-mem` is active.

## Modifications

### Rewritten `PyMscclppCommunicator` (`python/sglang/srt/distributed/device_communicators/pymscclpp.py`)
- **Complete rewrite**: Replaced the old `sgl-kernel` C++ op-based communicator with a pure-Python implementation using `mscclpp`, `mscclpp.ext`, and `mscclpp.default_algos`.
- Removed old dependencies: `bisect`, `math`, `os`, `IntEnum`, `custom_all_reduce_ops`, `MscclContextSelection`, `mscclpp_convert_to_bytes`, `mscclpp_bench_time`, `SGLANG_MSCCLPP_MAX_BYTES` env var.
- Added `_create_native_algorithms()` with four algorithm types: `nvls_packet`, `packet`, `rsag_zero_copy`, `nvls_zero_copy`.
- Added `_create_dsl_algorithms()` for TP=16 two-node allreduce via the MSCCL++ DSL compiler.
- Added `_tune()` and `_get_time()` for CUDA-graph-based auto-tuning with synchronized timing across ranks.
- `should_mscclpp_allreduce()` now checks piecewise CUDA graph state (`is_in_piecewise_cuda_graph()`, `is_in_pcg_torch_compile()`, `get_pcg_capture_stream()`) to avoid use during graph compilation/capture.
- `all_reduce()` is now in-place (returns the input tensor) and uses the tuned algorithm config.
- Added `destroy()` for proper cleanup of executor, buffers, and algorithm configs.

### Removed MSCCL++ C++/CUDA code from `sgl-kernel`
- **Deleted** `sgl-kernel/csrc/allreduce/mscclpp_allreduce.cu` (~140 lines) and `sgl-kernel/csrc/allreduce/mscclpp_allreduce.cuh` (~779 lines) — the old hand-written allreduce kernels.
- **Deleted** `sgl-kernel/csrc/allreduce/test_mscclpp_allreduce.cu` (~153 lines).
- **Removed** `mscclpp` FetchContent dependency from `sgl-kernel/CMakeLists.txt` and all `mscclpp_static` link targets.
- **Removed** `mscclpp_generate_unique_id`, `mscclpp_init_context`, `mscclpp_allreduce` from `sgl_kernel_ops.h`, `common_extension.cc`, and `sgl_kernel/allreduce.py`.
- **Removed** `IS_MSCCLPP_AR_AVAILABLE` and the MSCCL++ ops region from `custom_all_reduce_ops.py`.

### Removed old MSCCL++ tests
- **Deleted** `sgl-kernel/tests/test_mscclpp.py` (~146 lines) and `test/manual/test_mscclpp.py` (~196 lines).

### Piecewise context manager (`python/sglang/srt/compilation/piecewise_context_manager.py`)
- Added `_piecewise_compiled` flag and `is_piecewise_compiled()` to track whether piecewise compilation has completed, used to prevent enabling MSCCL++ during CUDA graph capture.

### Allreduce dispatch (`python/sglang/srt/distributed/parallel_state.py`)
- In `graph_capture()`: disabled `pymscclpp_comm` after piecewise compilation to avoid invalidating `torch.compile` guards.
- In `all_reduce()`: replaced symmetric memory dispatch condition to use `should_mscclpp_allreduce(input_)` instead of checking `pymscclpp_comm.disabled`, giving MSCCL++ proper per-message-size control.
- Added MSCCL++ fallback guard to the custom allreduce (`ca_comm`) dispatch path.
- Simplified piecewise CUDA graph pynccl fallback condition.
- Added `pymscclpp_comm.destroy()` in `GroupCoordinator.destroy()`.

### Custom allreduce (`python/sglang/srt/distributed/device_communicators/custom_all_reduce.py`)
- Added `None` guard for `ops` in `close()` to prevent errors during shutdown when the module has been garbage-collected.

### Benchmark (`benchmark/kernels/all_reduce/`)
- Added `README.md` with setup/usage instructions for MSCCL++ benchmarking and inference.
- Updated `benchmark_mscclpp.py`: added input snapshot for graph correctness, proper cleanup (`destroy()`, `dist.barrier()`, `cleanup_dist_env_and_memory()`).

### `bench_one_batch.py`
- Added `destroy_model_parallel()` call before `destroy_distributed_environment()`.
- Replaced `maybe_reindex_device_id` with direct local rank calculation for multi-node support.

+

+    ```bash
+    git clone https://github.com/microsoft/mscclpp.git
+    cd mscclpp && mkdir build && cd build
+    cmake .. && make -j && pip install ..
+    ```
+3. Ensure `mscclpp` is importable in your Python environment before running the benchmark or using MSCCL++ for inference.
+
+### Running the Benchmark
+

+torchrun --nproc_per_node 8 \
+    --nnodes 1 \
+    --node_rank 0 \
+    benchmark/kernels/all_reduce/benchmark_mscclpp.py

+    --tp-size 8 \
+    --enable-mscclpp
+```
+
