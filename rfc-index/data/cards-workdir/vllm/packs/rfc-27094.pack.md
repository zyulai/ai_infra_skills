## 正文(PRD / 提案全文)

### Motivation.

E/P/D disaggregation is actively in development from #25233, but the preprocessing of multi-modal inputs is repeated among all workers in the inference path.

Following "Multimodal processing simplification" in the Q4 2025 roadmap #26376, I propose to add something like`image_embeds_dummy` in the content type of the input of LLM.chat and LLM.generate.

Currently, LLM.generate can take `multi_modal_data` with preprocessed raw tensors like the Qwen2-VL example in the [official document page](https://docs.vllm.ai/en/latest/features/multimodal_inputs.html#embedding-inputs), but still it requires to send image values or preprocessed tokens between E-P workers. We may want the request only contain the metadata (e.g. image size, hash value) of the input after the encoding stage.

## Profiler result

To measure the impact of the preprocessor, I ran PyTorch profilers and breakdown each steps of a single request of an 1024x1024px image with a single text token by the E-P-D disaggregation of #25233.
- Model: Qwen/Qwen2.5-VL-3B-Instruct
- Device: 3x RTX3090, AMD EPYC 7F52 16-core
- Interconnection: PCIe (E -> P), NVLink (P -> D)

- End-to-end Mean TTFT: 1014ms (result from `vllm bench serve` with 10 requests)
  - **Preprocess: 143ms (x3)**
    - Request parsing: 14.5ms
    - Base64 image text to PIL Image: 28ms
    - Tokenize text inputs: 4ms
    - Hash multi-modal value: 15ms
    - Run HF multi-modal preprocessor of Qwen2.5-VL (i.e. main preprocessing): 75ms
    - etc. (add request, update input tokens, ...): 6ms
  - **Encoder GPU worker: 176ms**
    - Engine core runtime: 2ms
    - Schedule + mrope: 4ms
    - Store mm value to GPU: 3ms
    - Main encoder: 156ms
    - Save result for ECConnector: 11ms
  - **Prefill GPU worker: 157ms**
    - Engine core runtime: 5ms
    - Schedule + mrope: 5ms
    - ECConnector read: 3ms
    - Main Prefill: 144ms
  - **Decode GPU worker: 105ms**
    - Engine core runtime: 5ms
    - Schedule + mrope: 5ms
    - KVConnector read: 29ms (cf, this is already optimized by #23887)
       - Pure GPU memcpy time: 2ms
    - Main Decode: 65ms

See that the preprocessor occupies half of the inference time (~500ms). 

For the realistic information, HydraInfer (arxiv:2505.12658) set 1 second TTFT as the SLO for Qwen2-VL-7B with TextVQA dataset. Since TextVQA dataset mainly contains 800-1000px images and 10-30 text tokens, we can easily expect that the current vLLM EPD-disaggregation fails to attain the SLO requirement due to the large preprocessing time. 

### Proposed Change.

Add `image_meta` in the multi-modal request types. (inspired `meta` device in PyTorch)

**Before**
```js
// Raw request
{
    "role": "user",
    "content": [
        {
            "type": "image_url",
            "image_url": {"url": "https://example.org/test.png"},
        },
        {
            "type": "text",
            "text": "What's in these images?",
        },
    ],
}

// base64 image repr. prefetched by the EPD router
// this request is spread across all workers in the inference path
{
    "role": "user",
    "content": [
        {
            "type": "image_url",
            "image_url": {"url": "data:image/png;base64, .."},
        },
        {
            "type": "text",
            "text": "What's in these images?",
        },
    ],
}
```

**After**
```js
// After the encoder worker. suppose Qwen2-VL model
{
    "role": "user",
    "content": [
        {
            "type": "image_meta",
            "image_meta": {
                  "mm_hash": "7dc62a0838079866476c3fee6b0f",
                  "pixel_values": {"type": "tensor", "shape": [16, 1176], "dtype": "torch.float32"},
                  "image_grid_thw": {"type": "tensor", "value": [[1, 4, 4]], "dtype": "torch.int64"}
            },
        },
        {
            "type": "text",
            "text": "What's in these images?",
        },
    ],
}
```
Even if `image_meta` results in empty dummy tensors in the PD workers, still it may be required to calculate the length of multi-modal tokens of the request, or just for backward-compatibility.

The `image_meta` value should be included in the result of the encoder worker like `kv_transfer_params` in PD-disaggregation. The router will alter the input image in the original request to that value. 

`mm_hash` may not be required if the actual implementation of this RFC bypasses hash-based multi-modal input handler in the scheduler and the device workers. Although they bypass it, the multi-modal cache must not register the generated dummy tensors to itself.
