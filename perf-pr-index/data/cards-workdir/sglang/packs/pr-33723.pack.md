## PR body
```markdown
## Summary

This PR follows [PR #30553](https://github.com/sgl-project/sglang/pull/30553)
and adds FULL decode CUDA graph recapture after runtime Elastic EP scale-up.
Primary and joiner ranks rebuild their graphs for the expanded topology before
the new EP size is committed.

The existing scale-up API and EPLB lifecycle are unchanged.

## Changes

- Defer initial decode graph capture on joining ranks until they enter the
  expanded world.
- Finish the current sampling step, release the old graph state, and rebuild
  decode graphs with the expanded Mooncake WORLD and NIXL rank mask.
- Require primary and joiner ranks to resolve the same graph mode and capture
  configuration before recapture.
- Reuse SGLang's existing FULL decode graph initializer and synchronize all
  ranks before committing the scale operation.
- Add graph-stable FA3 MLA metadata for the validated DeepSeek path.
- Reject execution modes that do not use the supported decode finalization
  path.

## Configuration

Launch primary and joiner groups with the same resolved graph settings:

```text
--cuda-graph-backend-decode full
--cuda-graph-backend-prefill disabled
--cuda-graph-bs-decode 1 2 4 8 16
```

The scale request and status API are inherited from the base scale-up PR.

## Known Limitations

- Only FULL decode graph recapture is supported. Prefill and piecewise graph
  recapture are outside this PR.
- Primary and joiner groups must use the same resolved CUDA graph
  configuration and effective capture sizes.
- Recapture is synchronous. Configuring more decode batch sizes increases the
  scale-finalization pause.
- The validated DeepSeek MLA path requires FlashAttention 3.
- Speculative decoding, embedding, diffusion, encoder-only execution, forward
  hooks, and PDMux split-prefill are not supported with Elastic EP recapture.
- The topology, scale-direction, and post-scale recovery limitations of the
  base scale-up PR still apply.
- Recapture releases the old decode graph pool before rebuilding. The deployment
  must still leave enough free GPU memory to capture the configured decode graph
  sizes; the manual tests use `--mem-fraction-static 0.5`.

## Test Plan

The manual Elastic EP tests cover direct, single-rank, mixed-cohort, and
repeated scale-up:

- `TestElasticScaleUp4To5CudaGraph`
- `TestElasticScaleUp4To6CudaGraph`
- `TestElasticScaleUp4To8CudaGraph`
- `TestElasticScaleUp4To5To6CudaGraph`

Each test captures decode batch sizes `1 2 4 8 16` and checks post-scale
generation, routed joiner traffic, input logprobs, and GSM8K correctness.

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 \
python -m pytest -v -s \
  test/manual/ep/test_elastic_scale.py::TestElasticScaleUp4To5To6CudaGraph::test_scale_up_on_demand
```

The repeated 4-to-5-to-6 and direct 4-to-6 validations passed with all five
decode graph sizes captured on every participating rank.
