## Motivation

<!-- Describe the purpose and goals of this pull request. -->

Currently, `AscendAttnBackend` inherits `needs_cpu_seq_lens=True`. However, for DSA models that don't actually require `seq_lens_cpu`, we can bypass this dependency to reduce—or even eliminate—the CPU-bound bubbles. This PR sets `needs_cpu_seq_lens=False` for `AscendAttnBackend` when running DSA models.

## Modifications

<!-- Detail the changes made in this pull request. -->

- Added a `needs_cpu_seq_lens` member variable to both `AscendAttnBackend` and `AscendAttnMultiStepDraftBackend`. It is set to False when running DSA models without the HybridSWA feature, which enables the optimization introduced by this PR.
- Added branches for `needs_cpu_seq_lens is False` at device synchronization points within `AscendAttnBackend`, allowing device-side tensors to be used directly in computations.
- Moved the `all_reduce` communication in `EAGLEDraftNpuGraphRunner.can_run_graph` to the CPU to eliminate blocking waits.

~~This PR builds upon PR #36472 and should be merged after it.~~

The predecessor to this PR is #21895. Both aim to eliminate the CPU-bound overhead during Draft execution, and both are exclusively applicable to DSA models. Clearly, directly adapting `needs_cpu_seq_lens=False` is the superior approach, as it introduces no additional computation and preserves the original execution flow.
