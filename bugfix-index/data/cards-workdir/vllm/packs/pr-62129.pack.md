## 正文(PR 描述)

## Overview

Fix a pipeline-parallel startup deadlock in MRV2 speculative decoding introduced by [#59260](https://github.com/vllm-project/vllm/pull/59260).

## Claims

- Ensure all PP stages participate in the additional greedy warmup pass.
- Add regression coverage for matching warmup rounds across PP stages, with speculative decoding enabled and disabled.

## Validation

```bash
.venv/bin/python -m pytest \
  tests/v1/worker/test_mixed_warmup_gate.py \
  tests/v1/worker/test_gpu_warmup_blocks.py -q
```

- **34 passed** in 9.64 seconds. These suites are covered by the existing `V1 Executor + Worker` CI job.
- **GLM-4.7-Flash smoke test passed**: MRV2, TP=2, PP=2, BF16, MTP with one speculative token, JIT warmup and CUDA graphs enabled.
- Warmup completed and generation produced exactly **1,024 tokens** using `temperature=0`, `max_tokens=1024`, and `ignore_eos=True`. Recorded 532 draft tokens and 492 accepted tokens; process exited successfully.
- Ruff lint and formatting checks passed.

The model run validates startup and generation; no accuracy benchmark was performed.

## Details

Only the last PP stage owns a rejection sampler. Previously, the additional greedy warmup pass was gated on its presence, so earlier stages skipped the pass while the last stage waited for their activations.

Gate this pass on `speculative_config` instead, ensuring every PP stage executes matching forwards. The change is limited to the warmup condition and regression tests.
