## Overview

Reduces the per-block Python work on the scheduler's main thread when an async KV load starts, is promoted to running, and finishes. These costs grow linearly with prompt length, and on a DP decode instance a slow `schedule()` on one rank holds up the per-step all-reduce.

Related: #61725 limits load starts per step to contain this cost; this makes each load cheaper. #64379 and #65285 target the repeated reservation sum, which is a separate cost.

## Claims

- For a 140K-token request, start + promote + finish CPU time drops about 50% on a DeepSeek-V4.1-shaped KV layout (2.66 to 1.34 ms) and about 45% with one group at block size 16 (10.55 to 5.79 ms).
- Source changes are net neutral in size (+51/-49 lines), and two properties are removed.
- No behaviour change intended. These paths are shared by all requests, so non-P/D traffic benefits too.

**Not yet shown:** an end-to-end improvement. These are scheduler-only numbers, with no real P/D run, so the effect on `schedule()` time and GPU wait in serving is unmeasured.

## Validation

### Timing

Real `Scheduler` and NIXL scheduler connector, with no GPU or transfer. GB200 host (aarch64), Python 3.12, 32 requests per run. Each value is the median of 3 rounds, each round being the median of 5 runs, interleaved with the baseline on one node. Spread between rounds was about 1-5%. ms per request, 140K tokens:

| Phase | DSv4.1 layout, before | After | Change | One group, block size 16, before | After | Change |
|---|---:|---:|---:|---:|---:|---:|
| Start, fresh blocks | 0.71 | 0.33 | -54% | 2.60 | 1.03 | -60% |
| Promote to running | 1.01 | 0.65 | -36% | 5.97 | 3.76 | -37% |
| Finish | 0.95 | 0.36 | -62% | 1.98 | 1.00 | -50% |
| **Start + promote + finish** | **2.66** | **1.34** | **-50%** | **10.55** | **5.79** | **-45%** |
| Start, evicting cached blocks | 0.99 | 0.72 | -27% | 5.43 | 4.51 | -17% |

The "DSv4.1 layout" is a hand-built model of the KV groups read from the code: compressed MLA at 128 (SM10x), MLA sliding window at 32, one ring block at 8, hash block size 32. **The 128-token window and single compressed group are assumptions**, not confirmed from a real startup log.

These numbers predate the final `get_new_blocks` loop split, which was only measured in isolation: 8,750 fresh blocks, caching on and metrics off, 2.75 to 1.98 ms (-28%), faster in 6 of 6 paired rounds on a noisy x86 laptop with Python 3.13. Treat that size as approximate. The table above is therefore, if anything, slightly conservative for fresh starts.

#!/usr/bin/env python
"""Async KV load CPU cost: real Scheduler + NIXL scheduler connector, no GPU/transfer.
usage: prof.py timing <config> <n> <tokens> | prof.py cprofile <config> <n> <tokens>
Prints one JSON line of ms/request per phase in timing mode."""
import cProfile, gc, json, logging, os, pstats, sys, time
os.environ.setdefault("HF_HUB_DISABLE_PROGRESS_BARS", "1")
import torch
from tests.v1.kv_connector.unit.utils import (create_model_runner_output, create_request,
    create_scheduler, create_vllm_config)
from vllm.v1.kv_cache_interface import (CircularBufferSpec, FullAttentionSpec, KVCacheConfig,
    KVCacheGroupSpec, MLAAttentionSpec, SlidingWindowMLASpec, SlidingWindowSpec)
logging.disable(logging.WARNING)
BS = int(os.environ.get("PROF_BLOCK_SIZE", "16"))

SWA_BS = 32; RING_BS = 8; WINDOW = 128  # DSv4.1 layout; WINDOW is an assumption

def build_dsv41(n, tokens):
    """DeepSeek-V4.1 KV layout: compressed MLA at BS (backend-chosen), MLA SWA fixed at 32, one ring block."""
    c = create_vllm_config(max_num_seqs=128, max_num_batched_tokens=1280, block_size=BS, max_model_len=tokens+1000)
    common = dict(num_kv_heads=1, head_size=512, dtype=torch.uint8)
    num_blocks = (n+1)*(tokens//BS + 2 + WINDOW//SWA_BS + 4)
    kcc = KVCacheConfig(num_blocks=num_blocks, kv_cache_tensors=[], kv_cache_groups=[
        KVCacheGroupSpec(["mla"], MLAAttentionSpec(block_size=BS, **common)),
        KVCacheGroupSpec(["swa"], SlidingWindowMLASpec(block_size=SWA_BS, sliding_window=WINDOW, **common)),
        KVCacheGroupSpec(["ring"], CircularBufferSpec(block_size=RING_BS, head_size_v=0, **common)),
    ])
    assert [g.kv_cache_spec.prefix_cacheable for g in kcc.kv_cache_groups][:2] == [True, True]
    return create_scheduler(c, num_blocks=num_blocks, kv_cache_config=kcc, hash_block_size=SWA_BS)

def build(config, n, tokens):
    if config == "dsv41":
        return build_dsv41(n, tokens)
    c = create_vllm_config(max_num_seqs=128, max_num_batched_tokens=1280, block_size=BS, max_model_len=tokens+1000)
    per_req = tokens // BS + 2
    if config == "one":
        return create_scheduler(c, num_blocks=(n+1)*per_req)
    assert config == "swa"
    # Full attention + a sliding window group: the multi-group shape.
    num_blocks = 2*(n+1)*per_req
    kw = dict(block_size=BS, num_kv_heads=1, head_size=1, dtype=torch.float32)
    kcc = KVCacheConfig(num_blocks=num_blocks, kv_cache_tensors=[], kv_cache_groups=[
        KVCacheGroupSpec(["full"], FullAttentionSpec(**kw)),
        KVCacheGroupSpec(["swa"], SlidingWindowSpec(sliding_window=128*BS, **kw)),
    ])
    return create_scheduler(c, num_blocks=num_blocks, kv_cache_config=kcc)

def reqs(n, tokens, hash_bs=None):
    return [create_request(block_size=hash_bs or BS, num_tokens=tokens, max_tokens=1, do_remote_prefill=True,
                           num_remote_blocks=tokens//BS) for _ in range(n)]

class Phases:
    """Runs start -> promote -> finish -> start-over-evictable, each via `run(name, fn)`."""
    def __init__(self, run, config, n, tokens):
        r = build(config, n, tokens)
        hb = SWA_BS if config == "dsv41" else None
        rs = reqs(n, tokens, hb); rs2 = reqs(n, tokens, hb)
        gc.collect(); gc.freeze()  # as the engine does at startup
        for q in rs: r.add_request(q)
        out = run("start_fresh", r.schedule)
        assert len(r.running) == 0 and sum(q.status.name == "WAITING_FOR_REMOTE_KVS" for q in rs) == n, "not all started"
        r.update_from_output(out, create_model_runner_output([], finished_recving={q.request_id for q in rs}))
        out = run("promote", r.schedule)
        assert len(r.running) == n
        run("finish", lambda: r.update_from_output(out, create_model_runner_output(list(r.running))))
        for q in rs2: r.add_request(q)
        run("start_evict", r.schedule)
        started = sum(q.status.name == "WAITING_FOR_REMOTE_KVS" for q in rs2)
        assert started == n, f"started {started}"

def timing(config, n, tokens, reps=5):
    res = {}
    for _ in range(reps):
        def run(name, fn):
            gc.disable()
            t = time.perf_counter(); o = fn(); d = time.perf_counter()-t
            gc.enable()
            res.setdefault(name, []).append(d*1e3/n)
            return o
        Phases(run, config, n, tokens); gc.unfreeze()
    print(json.dumps({"config": config, "n": n, "tokens": tokens, **{k: round(sorted(v)[len(v)//2], 3) for k, v in res.items()}}))

def prof(config, n, tokens):
    def run(name, fn):
        p = cProfile.Profile(); p.enable(); o = fn(); p.disable()
        print(f"\n## cProfile {config} {name} (n={n}, overhead inflates Python calls)")
        st = pstats.Stats(p, stream=sys.stdout); st.sort_stats("tottime").print_stats(14)
        return o
    Phases(run, config, n, tokens)

mode, config, n, tokens = sys.argv[1], sys.argv[2], int(sys.argv[3]), int(sys.argv[4])
(timing if mode == "timing" else prof)(config, n, tokens)

## Details

| Change | Why it's cheaper | Relies on |
|---|---|---|
| `block_hash` and `block_hash_num_tokens` become plain fields | No Python call per read in hot loops | Fields are now publicly writable. In `vllm/`, they are set through `set_block_hash`, `reset_hash` and one constructor call in the UMBP connector |
| Skip eviction for unhashed blocks in `get_new_blocks`; early return in `_remove_cached_block_hashes` | Most allocated blocks were never cached | A block only has secondary hashes alongside a primary one |
| Separate loops per mode in `get_new_blocks` | No per-block metrics check on the default path | |
| `_insert_block_hash` only checks `contain` when the block already has a hash | One dict lookup instead of two in the common case | A block with no hash has no cache entries |
| Pack the group id once per `cache_full_blocks` call | No `to_bytes` and helper call per block | |
| Reverse scan in `estimate_cached_tokens` | Stops at the last hashed block instead of visiting them all | Hash coverage never decreases along a block table, including partial and Mamba entries |
| `len([...])` instead of `sum(<genexpr>)` in the NIXL pull scheduler | No generator resume per block | |

**Tradeoffs:**
- With `kv_cache_metrics` on (off by default), every block still takes the eviction call so `on_block_evicted` can run, so that path gains less. That mode wasn't measured in the full benchmark, and the isolated measurement above was inconclusive for it.
- `get_new_blocks` now has three near-identical loops.

**The block size assumption matters for evaluating this work.** The 8,750-blocks-per-request figure comes from a block size 16, single-group setup, including part 1 of #61725. By my reading of the code, DSv4.1 on NVIDIA uses 128 or 64 for its main group, chosen by the backend, so a real load costs about a quarter of the block-size-16 figure before this change. For the same reason, changing the default in #63231 shouldn't affect DSv4.1 on NVIDIA. At block size 64 with one group, this change still gives about -42% (3.04 to 1.75 ms).
