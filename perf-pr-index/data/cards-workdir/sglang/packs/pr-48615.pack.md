## PR body
```markdown
Selecting `TORCH_CUDNN_SDPA` for LTX currently puts dense attention outside the breakable CUDA graph even when the layer opts into dense capture. The tested 30-step LTX-2.3 request executes 8,670 graph launches. This adds the explicit cuDNN backend to the existing allowlist, producing one graph segment and 30 serving launches.

The existing opt-in, SP=1, no-varlen and no-attention-metadata guards remain in effect. The change is one runtime line plus an extension of the existing CUDA regression to both SDPA backends and Local/USP attention. The test replays changed Q/K/V tensors and changed masks, checking exact outputs and the expected capture/break segment count.

- Frozen main baseline: `77c3bcbe2c28e1a6d1ad4121ee57231582d39bdc`.
- Final tested head: `b5cf24a03841935cc396b67cdb9522cfed993141`.
- vLLM-Omni baseline: `817d4c17feb702289a2d2b2cbacfd594c262b7a7`.
- Weights: `diffusers/LTX-2.3-Diffusers@8eee8edcf067e838b843f926ec4d4cc9b2be1aaf`.

One B300 SXM6 AC, native audiovisual pipeline, BF16 lossless, batch/concurrency 1, 768×512, 17 frames at 24 FPS, 30 steps, CPU seed 42, video CFG 3, audio CFG 7, STG 1, modality guidance 3, rescale 0.7, STG block 28. No compile or external Diffusers fallback. The archived SDK configuration supplies the checkpoint's LTX-2.3 architecture/parameter-name metadata; model arithmetic and weights are unchanged.

The final cohort freezes 16 engines and 128 saved videos: independent A/A engines for main eager, main explicit-cuDNN BCG, main generic-SDPA BCG and final explicit-cuDNN BCG, followed by a symmetric E/M/G/C/C/G/M/E sequence. Every engine runs short/long warmups and six measured requests. Formal E2E covers the SDK request through completed MP4 saving; hashing, profiler and stage synchronization are outside the timer or disabled. All samples are retained.
