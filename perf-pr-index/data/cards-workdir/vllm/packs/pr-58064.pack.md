## Overview

Transformers' `@dynamic_rope_update` syncs on `torch.max(position_ids)` in every rotary forward, so dynamic-rope models crash during CUDA graph capture on the Transformers backend. Since #53615, this stops Hunyuan V1 dense models (e.g. Hunyuan-7B-Instruct) from starting on `main` with default settings. Completes #23738.

Closes #57890

## Claims

- When `max_model_len <= max_position_embeddings` the update can never fire, so the decoder's dynamic rotary modules are relabelled as `"default"` after init. `inv_freq` is untouched, so outputs are bit-identical.
- These models are now compiled and run with CUDA graphs: 1.7x throughput on Hunyuan-7B-Instruct.
- Unchanged beyond `max_position_embeddings`, or with a `longrope` layer type, where the sync is real.

## Details

- The rope type is relabelled on the modules rather than in the config, because model-specific dynamic inits (e.g. Hunyuan's `alpha`) only run when `rope_type == "dynamic"`.
- `can_enable_torch_compile` runs before the modules exist, so it shares the config-level check with the relabelling.
