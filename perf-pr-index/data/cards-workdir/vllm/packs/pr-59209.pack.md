## Summary

Add HiSparse support for NVIDIA QSA. Main K/V can be offloaded to host; indexer keys, raw-key rings and GDN state stay on GPU.

## Design

QSA reuses the existing HiSparse planner and index-group runtime shared with DSA. Sparse-role fields (cache_role, topk_buffer_width, and is_index_group_leader) now live on AttentionSpec, extending sparse-role metadata from MLA to full K/V attention independently of whether HiSparse is enabled (QSA falls back to its normal backend when HiSparse is off).

The device cache uses a BLNHC layout so each token's K/V across local heads forms one contiguous transfer row. Each TP rank manages a private host pool; host_pool_gib budgets unique KV heads per replica, while padding and replicated heads still consume physical memory.

Fused QSA prepare writes to the resident cache. During decode, the shared resolver maps logical selections to resident/hot physical KV rows (refilling hot-cache misses from host) before BF16/FP8 split-K attention:

QSA logical selections -> HiSparse resolver -> physical KV rows -> BF16/FP8 QSA split-K attention

- **Prefill & split-K:** Prefill reads resident KV directly or via shared staging; split-K honors the backing cache's actual block stride (including padding).
- **MTP & prefix caching:** Target and draft layers reuse logical selections while keeping separate physical-index buffers for CUDA graph replay. Prefix reuse is limited to whole scheduler pages.
- **Warmup:** Covers physical-index decode; BF16 split-K no longer recompiles when the cache-pool block count changes.

NIXL P/D support is split into #68281 (either PR can merge first; QSA P-OFF/D-ON requires both). QSA does not yet support DCP.
