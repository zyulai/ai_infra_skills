## Overview

Add filesystem tiering for native encoder-cache offloading. CPU memory serves as the primary tier, with encoder outputs persisted to filesystem storage for reuse when the working set exceeds CPU-cache capacity.

## Claims

- Support asynchronous CPU-to-filesystem write-through and filesystem-to-CPU promotion.
- Prefetch encoder outputs during request queuing and retry preparation during scheduling admission.
- Support persistent cache reuse across service restarts .
- Reduce replay mean TTFT by **34.41%** and increase request throughput by **25.84%** in the workload below.

## Validation

### Benchmark configuration

- **Model:** Qwen3-VL-8B-Instruct, BF16, TP=1.
- **Hardware:** NVIDIA H800.
- **Cache:** 8 GiB CPU, 128 GiB filesystem; encoder-cache working set of 22.416 GiB.
- **Serving:**  max-model-len=8192, GPU memory utilization=0.8.
- **Clients:** eight processes, total concurrency 48.
- **Workload:** 32 independent warmup images, 1,024 fill requests, followed by three replays of the same images; 100 output tokens per request.
- **Settings:** prefix caching disabled, filesystem backpressure disabled, fsync disabled.

Three configurations were compared: no EC offloading, CPU-only ECCPU, and filesystem tiering.

### Combined replay results

Each configuration completed 3,072 replay requests. Percentiles are calculated from pooled request samples; throughput uses the combined request-window duration.

| Metric | No offloading | CPU-only | Tiering | Tiering vs. no offloading |
|---|---:|---:|---:|---:|
| Mean TTFT (ms) | 1102.80 | 1080.68 | 723.30 | −34.41% |
| p50 TTFT (ms) | 1102.94 | 1082.92 | 712.34 | −35.41% |
| p95 TTFT (ms) | 1657.96 | 1624.19 | 1133.85 | −31.61% |
| Mean TPOT (ms/token) | 14.13 | 13.86 | 12.74 | −9.83% |
| Mean end-to-end latency (ms) | 2501.31 | 2453.23 | 1984.40 | −20.67% |
| Request throughput (req/s) | 18.84 | 19.21 | 23.71 | +25.84% |

### Cache-path verification

All **12,384 requests** across the three configurations, including warmup, completed successfully.

Each tiering replay recorded:
- 1,024 successful filesystem reads.
- 1,024 CPU-load selections.
- Zero recomputation selections.
- Zero filesystem read/write failures.

## Details

### Usage

Enable Model Runner V2 and configure `ECTieringConnector` through `--ec-transfer-config`:

```bash
VLLM_USE_V2_MODEL_RUNNER=1 \
vllm serve Qwen/Qwen3-VL-8B-Instruct \
  --dtype bfloat16 \
  --ec-transfer-config '{
    "ec_connector": "ECTieringConnector",
    "ec_role": "ec_both",
    "ec_connector_extra_config": {
      "ec_cpu_bytes": 8589934592,
      "secondary_tiers": [{
        "type": "fs",
        "root_dir": "/data/ec-cache",
        "capacity_bytes": 137438953472,
        "n_read_threads": 4,
        "n_write_threads": 2,
        "fsync": false,
        "backpressure": {
          "enabled": false
        }
      }]
    }
  }'
```

This configures an **8 GiB CPU cache** and a **128 GiB filesystem tier**. Keep `root_dir` on persistent storage to reuse compatible files after restarting the service.

Filesystem options:

| Option | Description | Default |
|---|---|---|
| `type` | Secondary-tier type; currently `"fs"` | Required |
| `root_dir` | Absolute cache-directory path | Required |
| `capacity_bytes` | Filesystem-cache capacity used for LRU eviction | Required |
| `n_read_threads` | Read-priority worker count | `4` |
| `n_write_threads` | Write-priority worker count | `2` |
| `fsync` | Synchronize file contents before publication | `false` |
| `backpressure.enabled` | Enable adaptive write admission | `true` |
| `backpressure.high_water_s` | Upper threshold for smoothed write latency, in seconds/MiB | `0.010` |
| `backpressure.low_water_s` | Lower recovery threshold, in seconds/MiB | `0.002` |

Backpressure reuses the native KV offloading `EMABackpressureDetector` to adapt cache-write admission to filesystem pressure. 


### Write-through and loading

Encoder outputs first follow the existing ECCPU GPU-to-CPU path. Once a CPU entry is ready, it is pinned while its complete allocated blocks are written asynchronously to a `.ec` file. The write pin is released after completion.

Request arrival initiates CPU-cache checks and filesystem prefetch. Shared prefetch pins protect CPU entries while interested requests remain.

During scheduling admission:
- GPU-cache hits proceed without waiting for lower tiers.
- Ready CPU entries use the ECCPU CPU-to-GPU load path.
- Preparation is retried if arrival-time prefetch could not start.
- CPU allocation failure before read submission permits a cache miss and encoder recomputation.

### Lookup and persistence
A stable namespace identifies compatible files using model identity, revision, dtype, encoder-output dimensions, and file-format version. Startup recovery rebuilds the index and capacity accounting; LRU eviction manages filesystem-cache capacity.

Compatible instances can discover and reuse files in the same directory. Capacity accounting and active-read protection are local to each instance.

+def _get_positive_int(
+    config: dict[str, Any], key: str, default: int | None = None
+) -> int:
+    """Read a required or defaulted positive integer field."""
+    if key not in config:
+        if default is None:
+            raise ValueError(f"filesystem secondary tier '{key}' is required")
+        return default
+
+    value = config[key]
+    if isinstance(value, bool) or not isinstance(value, int) or value <= 0:
+        raise ValueError(
+            f"filesystem secondary tier '{key}' must be a positive integer"
+        )
+    return value
+
+
+def _get_bool(config: dict[str, Any], key: str, default: bool) -> bool:
+    """Read a boolean field, using the given default when it is absent."""
+    value = config.get(key, default)
+    if not isinstance(value, bool):
+        raise ValueError(f"filesystem secondary tier '{key}' must be a boolean")
+    return value
+
+
+def _get_positive_float(config: dict[str, Any], key: str, default: float) -> float:
+    """Read a finite positive numeric field as a float."""
+    value = config.get(key, default)
+    if (
+        isinstance(value, bool)
+        or not isinstance(value, int | float)
+        or value <= 0
+        or not isfinite(value)
+    ):
+        raise ValueError(
+            f"filesystem backpressure '{key}' must be a finite positive number"
+        )
+    return float(value)

+    """Validated top-level configuration for encoder-cache tiering."""
+
+    filesystem_tier: ECFileSystemTierConfig | None

+    @property
+    def filesystem_enabled(self) -> bool:

+    @classmethod
+    def from_vllm_config(cls, vllm_config: VllmConfig) -> ECTieringConfig:
+        """Build tiering configuration from vLLM EC connector settings."""
+        ec_config = vllm_config.ec_transfer_config
+        if ec_config is None:
+            raise ValueError("ECTieringConnector requires ec_transfer_config")
+        if ec_config.ec_role != "ec_both":
+            raise ValueError("ECTieringConnector requires ec_role='ec_both'")
+
+        extra_config = ec_config.ec_connector_extra_config
+        if not isinstance(extra_config, dict):
+            raise ValueError("ec_connector_extra_config must be a dictionary")

+        secondary_tiers = extra_config.get("secondary_tiers", [])
+        if not isinstance(secondary_tiers, list):
+            raise ValueError("secondary_tiers must be a list")
