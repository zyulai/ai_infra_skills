## Overview

Remove `torch.compile` support from the HY4 AMD backbone and use breakable HIP graphs by default, matching the NVIDIA execution approach. This follows #57526 while retaining graph capture for prefill and decode.

## Claims

- Retain HIP graph replay without compiling the AMD backbone.
- Improve output throughput by 18.7% and median TPOT by 15.6% in the measured C8 decode workload.

## Validation

Benchmarked public `tencent/Hy4-preview-FP8` on upstream `b91df5a9`, 8× MI355X, TP8/MRV2, BF16 activations/KV, identical prompts and serving settings, and no speculation or prefix caching. Ran compiled → no compile → compiled, three repeats per arm; the table compares medians of six compiled controls and three no-compile runs.
The client streams `/v1/completions` with seeded synthetic token prompts, temperature 0 and `ignore_eos=true`.

| Workload (concurrency; input/output tokens) | Compiled tok/s | No compile tok/s | Change | Compiled TPOT | No compile TPOT |
| --- | ---: | ---: | ---: | ---: | ---: |
| C1; 1024/256 | 36.77 | 42.62 | +15.9% | 26.26 ms | 21.88 ms |
| C8; 4096/600 | 245.71 | 291.59 | **+18.7%** | 30.65 ms | **25.86 ms (−15.6%)** |
| C8; 4096/16 | 42.91 | 44.89 | +4.6% | 132.25 ms | 127.13 ms |
| C8; mixed 128–6144/32–256 | 181.30 | 206.61 | +14.0% | 36.76 ms | 31.68 ms |

The main C8 throughput ranges were 241.71–249.22 versus 286.54–293.28 tok/s. Mixed-workload TTFT increased 5.5% (555→586 ms).

Compilation freezes prefill-sized MXFP8 GEMM tiles into small-batch decode. Without it, graph capture selects decode-specific tiles: `_mxfp8_linear_kernel.kd` summed duration falls **7.534→2.437 ms per rank/step**, with the same 411 calls. Forcing prefill tiles back reproduces 69% of this kernel-time penalty. Both paths retain HIP graph replay; attention and communication barely change. These kernel sums are not wall-clock latency.

### GPQA-Diamond

Parent `f2ba523d67` versus patch `c4f150d739`, same checkpoint: all 198 questions, zero-shot chat, temperature 0.9/top-p 1.0, matched prompts and seeds, 65,536 output-token limit and concurrency 15. Scores use explicit final-answer exact match; blank/unextractable answers count as wrong.

| Dataset | Compiled | No compile | Difference |
| --- | ---: | ---: | ---: |
| GPQA-Diamond | 91.92% (182/198) | 92.42% (183/198) | +0.51 pp |

Truncations decreased from 5 to 3. Other accuracy discrepancies remain under investigation; this GPQA result alone does not establish overall accuracy parity.

`.venv/bin/python -m pytest tests/models/test_hyv4_rocm.py -v -s`: **6 passed** on AMD. The new default-graph regression fails on the unmodified parent and passes with this patch.

No duplicate removal PR was found during the HY4 compile/breakable-graph search. AI assistance was used for implementation and validation.
