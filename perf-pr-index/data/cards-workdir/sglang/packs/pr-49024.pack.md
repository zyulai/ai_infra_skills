## Motivation

Wan 2.2's normalization, gated residual and scale/shift chains can use existing FlyDSL fused kernels on ROCm. These kernels lower some FP32 operands and residuals to BF16, so enabling them must respect the request's numerical-quality contract.

This PR makes the standard Wan path eligible for this optimization only when **both** `SGLANG_USE_ROCM_FLYDSL=1` and `quality="high"` allow it. Default `lossless` requests retain the reference path even when the environment flag is enabled.

## Modifications

- Register `WAN_ROCM_FLYDSL_NORM_SCALE_SHIFT` with the existing request-scoped `QualityGatedFusion` mechanism for standard Wan transformer blocks and output normalization.
- Mount the fusion at batch boundaries for `high` requests and unmount it for `exact` and `lossless` requests.
- Preserve the unvalidated video sparse attention path and other models' existing explicit opt-in behavior.
- Reuse the existing FlyDSL normalization and scale/shift kernels, including the gated-residual variant; **introduce no new kernel.**

## Accuracy Tests

### Request-quality routing on MI350X

Runtime instrumentation verified the actual request quality and dispatch, rather than relying only on the configured environment:

| Request quality | `SGLANG_USE_ROCM_FLYDSL` | Steps | Observed dispatch | Result |
|---|---:|---:|---|---|
| Omitted → default `lossless` | 1 | 1 | Native at all 121 visited marked sites; no FlyDSL entry | Pass |
| `high` | 0 | 40 | Native at all 242 visited marked sites; no FlyDSL entry | Pass |
| `high` | 1 | 40 | FlyDSL entry at all 242 visited marked sites | Pass |

The default-quality test is a one-step functionality probe at 1280×720 and 81 frames. The two `high` cases are full 40-step generations.

Both full outputs decoded successfully to **81 frames at 1280×720, 16 fps**. Inspected frames 0, 20, 40, 60 and 80 show a coherent cat and dog beside a cake in a kitchen, consistent with the prompt, with no obvious visual collapse or frame corruption. Poses and motion differ visibly. This is a functionality check, not proof of numerical or general visual-quality equivalence.

### Additional model coverage and output similarity

Native `high` and FlyDSL `high` both successfully generated 81-frame, 40-step videos at 832×480 with Wan 2.1 T2V 14B, with the expected dispatch confirmed. Its hidden size of 5120 exercises the fused path rather than the unsupported-dimension fallback.

Wan-Animate-2 currently stays on the native path, including with `quality="high"` and `SGLANG_USE_ROCM_FLYDSL=1`: its custom denoising stage bypasses quality-fusion mounting, so this PR's gated FlyDSL fusion is not activated there.

For each model, FlyDSL `high` (`SGLANG_USE_ROCM_FLYDSL=1`) was compared against **native SGLang `high` (`=0`) as the reference**, using identical model revisions, prompts, seed 42 and generation settings within each pair.

| Model | Resolution | RGB PSNR | Mean RGB SSIM |
|---|---|---:|---:|
| Wan 2.2 T2V A14B | 1280×720 | 16.7063 dB | 0.647476 |
| Wan 2.1 T2V 14B | 832×480 | 15.3451 dB | 0.511038 |

Metrics compare corresponding decoded 8-bit RGB frames across all 81 frames at original resolution. PSNR uses global RGB MSE; SSIM is computed per frame and averaged. The reference is the native SGLang output—not the official Wan implementation or a ground-truth video.

Sampled frames show no obvious catastrophic corruption, but composition and poses visibly differ. These results measure output similarity, not equivalent perceptual quality; coverage is one seed/prompt per model.

Same single MI350X, sequential fresh servers, Wan2.2 T2V A14B Diffusers, 1280×720, 81 frames, 40 steps, seed 42, guidance 4.0/3.0, resident DiT, global `torch.compile` disabled. Both requests use `quality="high"`; only the FlyDSL environment permission differs.

| Configuration | Client end-to-end latency |
|---|---:|

Latency decreased by **15.014 s (2.71%)**, or **1.028× speedup**.

### Historical kernel-only measurements

The following matched, same-process MI350X probes measured the same underlying native and FlyDSL operations before the request-quality gate was added. They used equal Python-call timing boundaries, gradients disabled, five warmups, and three rounds of 30 GPU-event-timed calls per path.

| Shape | Native eager | FlyDSL | Speedup |
|---|---:|---:|---:|
| 7,800 × 5,120 | 0.2950 ms | 0.0884 ms | 3.34× |
| 75,600 × 5,120 | 2.6025 ms | 0.7262 ms | 3.58× |

These native and FlyDSL paths return FP32 and BF16 respectively. Their differences include operand/output precision changes, which is why this fusion is restricted to the approximate `high` tier.
