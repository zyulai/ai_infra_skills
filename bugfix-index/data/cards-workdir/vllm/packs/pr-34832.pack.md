## Summary

Reverts PR #33192 which introduced a query dtype mismatch regression in P/D disaggregation on Blackwell GPUs, while the bug it aimed to fix was already resolved.

This reverts commit bbe0574d8e51c1c5935aeff9e92040c61d1d59c5.

@NickLucche @robertgshaw2-redhat 

<!-- markdownlint-disable -->

## Purpose
PR #33192 globally disabled TRTLLM attention when KV transfer is enabled, intending to fix an `is_strictly_contiguous(kv_cache_permute)` assertion failure. However:

- **The original bug no longer exists.** The original was introduced after PR #30207, it had a problem that made `prefer_cross_layer_blocks` returns True. The cross-layer allocation produced non-contiguous KV cache views when permuted for TRTLLM attention. However, later this PR was reverted by PR #33241, which fixed the bug. 
- **PR #33192 introduces a regression.** It sets `can_use_trtllm = False` globally (so `q_data_type = bfloat16`), but per-layer `FlashInferImpl` independently enables FP8 query quantization on Blackwell GPUs, causing:
  ```
  AssertionError: Query dtype mismatch: expected torch.bfloat16, got torch.float8_e4m3fn
  ```
  This breaks P/D disaggregation with FP8/NVFP4 models on B200.


## Test Plan & Test Result

| Scenario | Setup | Result |
|---|---|---|
| New bug (with #33192) | `nvidia/Qwen3-32B-NVFP4`, P/D on B200 | Query dtype mismatch |
| New bug after revert (without #33192) | `nvidia/Qwen3-32B-NVFP4`, P/D on B200 | Pass (no dtype mismatch) |
| Original bug after revert (without #33192) | `Qwen/Qwen3-0.6B`, P/D on B200 | Pass (no contiguity error) |
