## PR body
```markdown
## Summary

- parallelize batched MoE token and block-ID output writes across cooperative thread groups
- retain the original serial specialization for small capacities and high batch counts
- expand correctness coverage and add a batched alignment benchmark matrix

The production caller is currently `BatchedMarlinExperts`, used with the batched activation format for supported expert-parallel configurations.

## Why this is not a duplicate

PRs #35435 and #40370 proposed similar cooperative writes, but both were closed unmerged after becoming out of date. No open PR references either proposal or matches the current optimization.

This implementation is rebased on current `main`, preserves `size_t` output indexing, allocates the extra shared state only in the cooperative specialization, and uses an H200-tuned launch guard to retain the original path where coordination overhead regressed performance.

## Performance

On an NVIDIA H200 (SM90), the guarded raw-kernel benchmark matrix measured approximately 1.10x to 8.00x speedups for workloads selecting the cooperative path. Workloads below the guard use the original specialization; inspection of the built binary confirmed its original 48-register and 5,280-byte shared-memory profile.

## Validation

- `TORCH_CUDA_ARCH_LIST=9.0 cmake --preset release`
- `TORCH_CUDA_ARCH_LIST=9.0 cmake --build --preset release --target install`
- `.venv/bin/python -m pytest tests/kernels/moe/test_moe_align_block_size.py -q` (`525 passed`)
- `.venv/bin/pre-commit run --files benchmarks/kernels/benchmark_moe_align_block_size.py csrc/libtorch_stable/moe/moe_align_sum_kernels.cu tests/kernels/moe/test_moe_align_block_size.py` (passed)

Model evaluation was not run because the change preserves the alignment operator's exact outputs and does not change model numerics.

AI assistance was used for implementation, testing, benchmarking, and drafting this PR. The human submitter will review and be responsible for the change end to end.
```
