## Motivation

KDA's safe-gate diagonal kernels use different normalization anchors: the fused path uses the first token of each 16-token subchunk, while the unfused path uses its midpoint. The anchor cancels algebraically, but changes finite-precision rounding. The grid-size heuristic can therefore change a sequence's output when other sequences join its prefill batch.

KDA selects fused diagonal/recompute kernels only when `B * NT * H <= 256`; larger grids use the unfused path to avoid register-pressure spills. For packed variable-length prefill, `B=1` and `NT=sum(ceil(sequence_length / 64))`, so the trigger depends on total prefill chunks and heads, not request count alone. In our captured Ming ASR case (`H=16`), individual requests used 2-3 chunks (grid 32-48, fused); packing eight requests produced 21 chunks (grid 336, unfused).

Concurrent requests can therefore cross this threshold when grouped into a larger prefill batch. Async decode changes scheduling and can change that grouping; the same switch also occurs on the synchronous baseline.

This surfaced while investigating Ming-3.0-ASR-tiny transcription differences in [sglang-omni#3564](https://github.com/sgl-project/sglang-omni/pull/3564). With identical first-layer inputs and zero initial states, switching only diagonal fusion reproduced the output discrepancy; switching only recompute fusion did not.

## Modifications

Use the subchunk-start gate in both gather and direct-load variants of the unfused safe-gate diagonal kernel, matching the existing fused path. Keep the fusion heuristic and batched prefill enabled.

This complements #47413, which selects a fixed path in batch-invariant mode. This change aligns the anchors when normal-mode execution switches paths; it does not claim universal bitwise batch invariance.
