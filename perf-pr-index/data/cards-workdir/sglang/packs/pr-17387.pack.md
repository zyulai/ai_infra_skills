## Motivation

The current implementation of `StopSequenceDecoder` uses a naive nested loop to search for stop sequences and special tokens. This results in $O(N \times M)$ time complexity (where $N$ is text length and $M$ is the number of tokens), causing spikes as the number of stop sequences increases.

## Modifications

* Replaced the nested `.find()` and `.starts_with()` loops in `src/tokenizer/stop.rs` with a single-pass **Aho-Corasick automaton**.
* Combined hidden and visible stop sequences into a single automaton pass.
* Added `visible_boundary_idx` to efficiently distinguish between hidden and visible matches based on the pattern index.
* Updated the `StopSequenceDecoder` struct to pre-compile and store the automaton during initialization.

+    for token in special_tokens {
+        let mut start = 0;
+        while let Some(pos) = text[start..].find(token) {
+            let actual_pos = start + pos;
+            boundaries.push((actual_pos, actual_pos + token.len()));

+        }
