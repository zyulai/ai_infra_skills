## Motivation

- On ROCm, Kimi-K3 has a fused KDA decode kernel: `f_b` projection + convolution + recurrent update + gated RMSNorm in one gfx950 launch per KDA layer.
- With the `aiter` backend it never turns on for the deployed Quark checkpoint (`amd/Kimi-K3-Quark-MXFP4-AttnFP8`), so decode silently runs the unfused chain and pays the extra launches every step:

| Blocker | Cause |
|---|---|
| Wrong AITER module | `SGLANG_K3_FLYDSL_SOURCE=aiter` imports a module no AITER build ships; ROCm/aiter#6026 publishes the kernel under another name |
| BF16 recurrent state rejected | the adapter accepts FP32 only, but the recommended `--mamba-ssm-dtype bfloat16` pool is BF16 |
| FP8 `f_b` | the checkpoint stores `f_b` as per-channel FP8; the kernel takes dense BF16 |

- The two fused-decode env vars were read with raw `os.environ`, outside `Envs`.

## Modifications

- Bind `flydsl_kda_decode_with_f_b` from `aiter.ops.flydsl.linear_attention_kernels`; if AITER lacks ROCm/aiter#6026, warn once and fall back.
- Arm a fused kernel only if it takes the pool's state dtype (the AITER op advertises `state_dtypes`); otherwise warn once and keep the unfused path.
- Dequantize the Quark per-channel FP8 `f_b` to a BF16 copy once, for the fused kernel only; the FP8 layer keeps serving the unfused path.
- Mirror AITER's cache-slot and stride rules in `covered()`, so an unsupported layout falls back instead of raising.
- Warm up only the pool's state dtype before graph capture; log the armed kernel and dtype.
- With a ReplaySSM ring (`--enable-linear-replayssm` or `--enable-linear-replayssm-spec`), decode no longer defers `f_b`:
  - either flag allocates the KDA ring, and the KDA backend skips the fused kernel on it (`replayssm_d is not None`), so a deferred `f_b` reached the recurrence as the raw `f_a`;
  - the kernel still arms and warms (static args, ops); only decode's deferral checks the ring, read from `get_exec().mamba`;
  - the KDA backend (`kda_backend.py`) is unchanged from `main`.
- Scope: ROCm only. CUDA is unchanged.

Arming rules:

| Backend | State dtype | Other conditions | Result |
|---|---|---|---|
| `gfx950` (default) | FP32 | gfx950 | armed |
| `gfx950` | BF16 | - | not armed, one-time warning |
| `aiter`, source `auto` / `sglang` (vendored kernel) | FP32 | gfx950 | armed |
| `aiter`, source `auto` / `sglang` | BF16 | - | not armed, one-time warning |
| `aiter`, source `aiter` | FP32 or BF16 | AITER with ROCm/aiter#6026 | armed |
| `aiter`, source `aiter` | any | AITER without #6026 | not armed, one-time warning |
| any | any | Quark `f_b` already post-processed (`ShardedStateLoader`, `RemoteModelLoader`) | not armed, one-time warning |
| any | any | `--enable-linear-replayssm` or `--enable-linear-replayssm-spec` | armed, but decode does not defer `f_b`; it runs the unfused ring decode |

Env vars (moved into `Envs`; the old names keep working with a `DeprecationWarning`):

| Name | Deprecated alias | Default | Effect |
|---|---|---|---|
| `SGLANG_USE_HIP_K3_KDA_FUSED_BACKEND` | `SGLANG_ROCM_K3_KDA_FUSED_BACKEND` | `gfx950` | `gfx950`: SGLang HIP kernel; `aiter`: FlyDSL boundary; other values: unfused decode |
| `SGLANG_USE_HIP_K3_FLYDSL_SOURCE` | `SGLANG_K3_FLYDSL_SOURCE` | `auto` | FlyDSL module behind `aiter`: `auto` prefers the vendored copy, `sglang` / `aiter` pin one |

- Docs: both vars in the AMD & ROCm env-var table; the Kimi-K3 cookbook documents the FP8 dequant and the state-dtype rule (it keeps the old names for its pinned image).
