## 正文(PRD / 提案全文)

## Summary

This RFC proposes Phase 1 of agent-aware KV cache support in SGLang.

The goal of this phase is to add a minimal, backward-compatible metadata path for agentic workloads so workflow information can flow from the API layer into runtime requests and KV cache nodes, and optionally affect radix cache eviction.

This is intentionally a foundation/prototype phase, not a full workflow-aware cache system.

## Motivation

Current KV cache eviction policies such as LRU, LFU, and SLRU treat requests mostly independently. That works well for standard chat/completion workloads, but it misses reuse opportunities in agentic workflows, where requests often share:

- repeated prompt prefixes across planner/tool/worker steps
- parent/child step relationships
- short-term reuse after tool calls
- workflow-level TTL or reuse intent

Without workflow-aware signals, cache entries that are likely to be reused by upcoming steps may be evicted too early.

## Proposal

Phase 1 introduces:

- an optional `agent_hints` field in OpenAI-compatible requests
- propagation of `agent_hints` through the internal request pipeline
- lightweight workflow DAG tracking in the scheduler
- radix cache node annotation with workflow metadata
- a new optional radix eviction policy: `agent_aware`

Initial `agent_hints` fields include:

- `workflow_id`
- `agent_id`
- `step_id`
- `step_index`
- `total_steps`
- `parent_step_id`
- `children_step_ids`
- `tool_name`
- `expected_tool_duration_ms`
- `cache_ttl_ms`
- `shared_prefix_hash`
- `reuse_hint`

## Scope

Phase 1 is intended to cover:

- request schema support
- metadata plumbing
- scheduler-side workflow tracking
- cache node metadata annotation
- a prototype workflow-aware eviction strategy

Phase 1 does **not** attempt to fully solve:

- `shared_prefix_hash`-driven reuse
- HiCache / storage-layer metadata inheritance
- cross-process workflow coordination
- production-tuned scoring for all agent topologies

## Backward Compatibility

- `agent_hints` is optional
- existing clients do not need to change
- existing eviction policies continue to work unchanged
- the new behavior is opt-in

## Testing

Expected validation for Phase 1:

- schema tests for `agent_hints`
- propagation tests from API request to internal request objects
- workflow DAG tests for step registration and distance computation
- radix cache node annotation tests
- eviction ordering tests for `agent_aware`
- backward-compat tests when `agent_hints` is omitted

How to Run
Start SGLang with the new eviction policy:
```
curl http://127.0.0.1:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "messages": [{"role": "user", "content": "hello"}],
    "agent_hints": {
      "workflow_id": "wf-1",
      "agent_id": "planner",
      "step_id": "step-1",
      "children_step_ids": ["step-2"],
      "cache_ttl_ms": 60000,
      "reuse_hint": "keep"
    }
  }'
```

Prototype validation already exists with dedicated unit tests for the metadata path.

## Open Questions

- Should `shared_prefix_hash` remain a hint, or become a stronger reuse primitive in a later phase?
- Should TTL be a hard protection or only a ranking signal?
- How should workflow-aware metadata eventually interact with HiCache and storage backends?
- What observability should be added next: workflow hit rate, protected eviction count, step-distance metrics?

## Requested Feedback

Feedback is especially useful on:

- the proposed `agent_hints` schema
- whether scheduler-local DAG tracking is the right Phase 1 boundary
- whether `agent_aware` should land as an experimental eviction policy first
- what should be included in Phase 2
