## 正文(PR 描述)

The original fix is by @ywang96, with a follow-up refinement by @ivanium

## Summary

`truncate_computed_blocks()` asserts that every KV cache group holds at least
`num_computed_tokens // block_size` blocks. For a hybrid (full-attention + Mamba) model
served with a KV connector, a Mamba group can legitimately hold fewer: its blocks are whole
recurrent state, not per-token KV, and an external hit can supply the state at a boundary the
local group no longer covers. The assert turns that benign divergence into an engine-fatal
`AssertionError`, killing the prefill workers mid-run.

Fix: keep both asserts for groups that must cover the endpoint, and clamp only `MambaSpec`
groups.

```python
assert num_computed_tokens % manager.block_size == 0
num_blocks = num_computed_tokens // manager.block_size
if isinstance(group.kv_cache_spec, MambaSpec):
    num_blocks = min(num_blocks, len(group_blocks))
else:
    assert num_blocks <= len(group_blocks)
```

A blanket `min()` over all groups would also stop the crash, but would silently mask a short
attention group — a real bug if it ever happens. Scoping to `MambaSpec` keeps that loud.

## Root cause

`truncate_computed_blocks()` has one caller, `Scheduler.schedule()`:

```python
if partial_tail and ext_tokens > partial_tail:
    new_computed_blocks = self.kv_cache_manager.truncate_computed_blocks(
        new_computed_blocks, block_aligned_local
    )
```

Both conditions must hold, which is why this is not hit by ordinary prefix caching:

- `partial_tail != 0` — the local hit ends on a prefix-match boundary that is not a block
  boundary. Requires `--prefix-match-unit` finer than the KV block size. For Kimi-K3 the
  platform raises the attention block to 1536 so the attention page covers the Mamba page,
  and `--prefix-match-unit 128` then makes a non-zero tail the common case.
- `ext_tokens > partial_tail` — the connector must hold *more* of the prefix than the local
  cache retains. `get_num_new_matched_tokens()` reports tokens beyond `block_aligned_local`,
  so when store and local cache hold the same prefix length the two are equal and the
  harmless `elif partial_tail:` branch runs instead. Divergence needs local eviction while
  the external store retains.

Both are satisfied by long chunked prefills: the request re-enters scheduling per chunk and
re-runs the lookup against its own earlier chunks, while concurrent requests churn the GPU
pool that the external store outlives.

Introduced in #49502, which added both the function and its caller. Still present on `main`.

## Reproduction

A PD deployment on 6 nodes (prefill 2 x TP8, decode 4 x TP1 -> DP16/EP16), MultiConnector
with NIXL plus MooncakeStore, `--enable-prefix-caching --prefix-match-unit 128`, attention
block 1536, 800 GB store against a 1,980,479-token GPU pool.

16 requests of 98,944 prompt tokens each (`64 * 1536 + 640`, so the tail is
128-aligned and not 1536-aligned), raw token-id prompts, concurrency 8. Prefill died 7
requests in:

```
vllm/v1/core/sched/scheduler.py:797   in schedule
    self.kv_cache_manager.truncate_computed_blocks(
vllm/v1/core/kv_cache_manager.py:792 in truncate_computed_blocks
    assert num_blocks <= len(group_blocks)
AssertionError
```

All 7 requests that reached prefill logged external loads. The store was at 78% with zero
`insufficient space` warnings, so capacity pressure is not involved.

<details>
<summary>Reproduction script (bash + curl, no deps)</summary>

Two passes: the first populates the connector, the second replays the same prompts against
it. A single pass on a cold store writes but never reads (`Get=0`) and cannot reach the
guarded branch, so it would pass misleadingly — the script reads
`vllm:external_prefix_cache_hits_total` and reports INCONCLUSIVE rather than PASS when no
external hit occurred. Prompts are raw token-id lists so prefix lengths are exact.

```bash
#!/usr/bin/env bash
# Usage: ./repro_truncate_assert.sh <router_port> [num_prompts] [prompt_tokens]
#   METRICS_URL=http://<prefill-host>:<port>/metrics  # recommended; else INCONCLUSIVE
# Exit: 0 fix verified, 1 reproduced (non-200), 2 inconclusive (no external reads).
set -uo pipefail

PORT=${1:?usage: repro_truncate_assert.sh <router_port> [num_prompts] [prompt_tokens]}
NPROMPTS=${2:-16}
BLOCK=${BLOCK:-1536}          # attention block size the platform picks for the hybrid model
LEN=${3:-$((64 * BLOCK + 640))}   # 640 = multiple of the 128 match unit, not of 1536
CONC=${CONC:-8}
MAXTOK=${MAXTOK:-4}
URL="http://127.0.0.1:$PORT/v1/completions"
MODEL=${MODEL:-moonshotai/Kimi-K3}

WORK=$(mktemp -d); trap 'rm -rf "$WORK"' EXIT

# x stays below 2^31 so x*1103515245 fits a 64-bit signed int exactly.
gen_tokens() {
  local seed=$1 n=$2 x i; local -a a
  x=$((seed * 7919 + 13))
  for ((i = 0; i < n; i++)); do
    x=$(((x * 1103515245 + 12345) & 0x7FFFFFFF))
    a[i]=$((1000 + x % 90000))
  done
  local IFS=,; printf '%s' "${a[*]}"
}

ext_hits() {
  [ -n "${METRICS_URL:-}" ] || return 0
  curl -fsS --max-time 5 "$METRICS_URL" 2>/dev/null \
    | awk '/^vllm:external_prefix_cache_hits_total/{print $2; exit}'
}

send() {
  local i=$1 t0 code dt
  t0=$(date +%s)
  code=$(curl -sS -o "$WORK/resp_$i.json" -w '%{http_code}' --max-time 1800 \
              -H 'Content-Type: application/json' \
              --data-binary "@$WORK/body_$i.json" "$URL" 2>"$WORK/err_$i")
  dt=$(($(date +%s) - t0))
  printf 'req %3d  HTTP %s  %4ds' "$i" "$code" "$dt"
  [ "$code" != 200 ] && printf '   <<< FAILURE  %s' \
    "$(head -c 200 "$WORK/resp_$i.json" 2>/dev/null | tr -d '\n')"
  printf '\n'
}
export -f send; export WORK URL

echo "prompts: $NPROMPTS x $LEN tokens, concurrency $CONC, tail mod $BLOCK = $((LEN % BLOCK))"
[ $((LEN % BLOCK)) -eq 0 ] && { echo "!! block-aligned: partial_tail would be 0" >&2; exit 2; }

for ((i = 0; i < NPROMPTS; i++)); do
  { printf '{"model":"%s","prompt":[' "$MODEL"; gen_tokens "$i" "$LEN"
    printf '],"max_tokens":%d,"temperature":0}' "$MAXTOK"; } > "$WORK/body_$i.json"
done

fails=0; declare -A delta
for pass in 1 2; do
  echo; echo "--- pass $pass ---"
  before=$(ext_hits)
  seq 0 $((NPROMPTS - 1)) | xargs -P "$CONC" -I{} bash -c 'send {}' | tee "$WORK/p$pass.txt"
  after=$(ext_hits)
  n=$(grep -c FAILURE "$WORK/p$pass.txt" || true); fails=$((fails + n))
  [ -n "$before" ] && [ -n "$after" ] && \
    delta[$pass]=$(awk -v a="$before" -v b="$after" 'BEGIN{printf "%d", b-a}')
  echo "  external hits this pass: ${delta[$pass]:-unknown}   non-200: $n"
  [ "$n" -gt 0 ] && break
done

echo
[ "$fails" -gt 0 ] && { echo "REPRODUCED -- $fails non-200; check prefill for the assert"; exit 1; }
[ -z "${METRICS_URL:-}" ] && { echo "INCONCLUSIVE -- no METRICS_URL, cannot prove the connector was read"; exit 2; }
[ "${delta[2]:-0}" -le 0 ] && { echo "INCONCLUSIVE -- pass 2 had no external hits; raise num_prompts"; exit 2; }
echo "PASS -- $((NPROMPTS * 2)) requests, 0 failures, pass 2 served ${delta[2]} tokens externally"
```

## Test

End-to-end, same recipe and workload, only the patched file differing:

| | before | after |
|---|---|---|
| requests completed | 7 of 16, engine dead | 16 of 16, twice |
| `num_blocks <= len(group_blocks)` asserts | 1 | 0 |
| external loads logged | 28 (7 reqs x 4 ranks) | 64 (16 reqs x 4 ranks) |
| store reads | — | `Get: Req=256/256, Item=7168/7168` |
| connector clients | 8 -> 4 (ranks died) | 8, unchanged |

The second pass is the one that matters: a cold store is written but never read
(`Get=0`), so it cannot exercise the branch. Re-running against the warm store produced
external hits on all 16 requests — more store read traffic than the run that crashed —
with the engine intact.

Unit tests, run inside the built aarch64 image so `vllm._C` is present:

```

```

The 4 cover both parameterizations of `test_hybrid_fa_deeper_hit_uses_external_mamba_state`
and of `test_hybrid_per_group_hit_divergence_with_connector`. They need network for
`ModelConfig("facebook/opt-125m")`; with `HF_HUB_OFFLINE=1` and that config uncached they

The first returns nothing: no open PR touches this function. The second returns adjacent
work, none of it this fix:

- #49502 (@Dao007forever) introduced both the function and its caller. **Merged**
  2026-07-27, not open.
- #50507 (@chaunceyjiang, open) extends partial-tail prefix reuse for hybrid models via the
  lookup and restore paths. It does not touch these asserts.
- #46453 (@howarlii, open) reports per-group hit divergence for hybrid + connector, but
  through `find_longest_cache_hit_per_group` convergence and different asserts
  (`num_new_tokens > 0`, `num_locally_computed_tokens <= ...`), and predates #49502.
- #50454 (@gdevenyi, open) is the same class of failure on the native offloading connector,
  asserting in `offloading/scheduler.py`, not through `truncate_computed_blocks`.
- #50630 (@mosafariuk, open) describes the adjacent design gap: no capability flag declares
  which KV kinds may be peeked past a candidate boundary, so each implementation excludes
  Mamba by hand.

No open PR or issue reports this assert.
