## Motivation

Qwen/Qwen3.8-Flash-Next (generic model support merged into `main` via #37500)
introduces several architectural features new to SGLang — a sparse-attention
indexer (QSA), HyperConnection (gated multi-stream residual mixing), a
PLE/N-gram auxiliary embedding, and MTP/NEXTN speculative decoding on top of
a hybrid linear+full attention backbone. This work enables the model
end-to-end on the XPU backend, since the current implementation of these
new features assumes CUDA in several places.

## Plan

Staged enablement:
1. **Functionality ready** (this PR) — model runs E2E on XPU without errors, exercising every new feature at least once, using existing portable (Triton/torch) kernels where a custom SYCL kernel isn't required.
2. **Acceptable performance** (future) — remove the worst algorithmic bottlenecks (unbatched ops, Python-loop fallbacks) without necessarily writing new SYCL kernels.
3. **Peak performance** (future) — write/optimize dedicated SYCL kernels in sgl-kernel-xpu for any remaining hot paths.

This PR covers Stage 1.

## Current Status

Stage 1 (functional E2E correctness) is complete. Per-component implementation status:

| Component | Status | Implementation on XPU |
|---|---|---|
| QSA sparse-attention indexer | Fixed a real OOB gather bug in compressed-KV update (`update_key_state_and_compress`), plus added a `forward_xpu` dispatch | Reuses the existing device-generic Triton/torch fallback path (same code CUDA falls back to when its fast custom kernel isn't applicable); underlying dense attention math uses sgl-kernel-xpu's existing FMHA SYCL kernel |
| HyperConnection (gated residual mixing) | Fixed hardcoded `cuda` device selection | Pure torch-native, no custom kernel needed |
| PLE / N-gram embedding | Works out of the box, no changes needed | Pure torch embedding lookup + all-reduce |
| MTP / NEXTN speculative decoding | Fixed 4 device-portability bugs: hardcoded CUDA device in the Mamba state pool, hardcoded CUDA sync calls, a missing kernel arg in the GDN Triton wrapper, and an int64-overflow bug when packing XPU pointers into scatter-kernel metadata | Uses existing Triton GDN kernel and Triton-based Mamba-state-scatter kernel; no new SYCL kernel required |
| MoE (routed + shared experts) | Verified working | Existing sgl-kernel-xpu `moe_align_block_size` SYCL kernel |
| Vision encoder | Verified working | Existing sgl-kernel-xpu non-paged-prefill FMHA SYCL kernel |

Stage 2 (performance tuning) has not started yet.

Re-verified (all scenarios above, BF16 + FP8, 1×B60 + TP=4) after rebasing
onto `main` on two machines. One new requirement surfaced by the rebase:
QSA's forced `page_size=64` conflicts with the mamba radix-cache's
`no_buffer` strategy, and `extra_buffer` is currently unsupported on XPU
(`supports_mamba_cache_extra_buffer()` hardcodes `False` for XPU regardless
of model) — so `--disable-radix-cache` is required on XPU for this model
until that gap is addressed (tracked in `docs/KNOWN_ISSUES.md`).
