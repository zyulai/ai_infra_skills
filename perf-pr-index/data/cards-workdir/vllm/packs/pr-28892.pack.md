## Purpose
This PR is created for two purposes:
1. Add trtllm fp4 kernel to be used in compressedtensorw4a4 method
2. Create a mutually used function for modelopt and compressedtensorw4a4 path to call flashinfer trtllm moe fp4 kernel



## Test Plan
### Accuracy test
Tested all code paths before and after the code change, including:
1. modelopt + trtllm fp4 moe
2. modelopt + flashinfer cutlass moe
3. compressedtensor + cutlass moe
4. compressedtensor + flashinfer cutlass moe
5. compressedtensor + flashinfer trtllm fp4 moe
The eval task is gsm8k and results are listed below 

The eval is based on nvfp4 ckpoint generated by llm-compressor for Qwen3-VL-235B-A22B for compressed tensors path and nvidia/Qwen3-235B-A22B-FP4 on modelopt path. The serving command is 

`vllm serve model_name    --tensor-parallel-size 2   --mm-encoder-tp-mode data --enable-expert-parallel --async-scheduling&
`
and eval command is 
`lm_eval --model local-completions --tasks gsm8k --model_args model=model_name,base_url=http://0.0.0.0:8000/v1/completions,max_retries=3,tokenized_requests=False,timeout=1200,max_gen_toks=2048,max_length=8192 --batch_size 2048 --trust_remote_code --limit 0.5`

### Perf test

Perf test is done at single GB200 and TEP=2 at GB200

The checkpoint used is RedHatAI/Qwen3-VL-235B-A22B-Instruct-NVFP4, server start command is 
`vllm serve RedHatAI/Qwen3-VL-235B-A22B-Instruct-NVFP4 --host 0.0.0.0 --port 46503 -tp <tp_size> -dp 1 --mm-encoder-tp-mode data --enable-expert-parallel --async-scheduling --max-model-len 32768 --cudagraph-capture-sizes 1 2 4 8 16 24 32 40 48 56 64 72 80 88 96 104 112 120 128 136 144 152 160 168 176 184 192 200 208 216 224 232 240 248 256 272 288 304 320 336 352 368 384 400 416 432 448 464 480 496 512 1024 2048 4096 8192 --max-num-seqs 1024`
