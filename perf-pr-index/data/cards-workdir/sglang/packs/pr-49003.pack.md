## Motivation

#49001 runs carv2 on MI450 (gfx1250) with a FABRIC-handle workspace and a push-only table, on one node. FABRIC handles also map between hosts of one UALink/UALoE fabric clique (VPOD), so a TP group spanning those hosts can use the same push kernels. Today it never gets there: on ROCm a multi-node group goes to the NVML clique query, which always answers no, and the gfx1250 table stops at 8 ranks.

This PR admits a multi-node group on gfx1250 when every rank is in one VPOD, frees its workspace in an order that is safe across hosts, and adds a TP16 row (two DPX hosts). At TP16 carv2 is 12-71% faster than RCCL from 4 KB to 64 MB (CUDA-graph mode). In DeepSeek-V4-Flash serving across the two hosts (TP8, 4+4), carv2 raises output throughput by 13-31% over RCCL at concurrency 4-64. Dispatch stays opt-in through `SGLANG_OPT_USE_CUSTOM_ALL_REDUCE_V2=1`. No kernel changes; CUDA paths are untouched.

## Modifications

**Fabric clique probe** (`device_communicators/gfx1250_fabric.py`, new)
- `probe_fabric_clique(group, device)` is collective. Each rank reads the UALink record of its accelerator from sysfs (`/sys/class/drm/card*/device/ualink` of PCI function 0, shared by every DPX/CPX partition) and the FABRIC handle attribute; all ranks reach the same answer.
- A rank qualifies when it is gfx1250, the link is UALink/UALoE and active, PPOD UUID, VPOD ID and VPOD size are present, and its accelerator is in the VPOD's active list. Missing fields fail closed.
- The group qualifies when all ranks share PPOD, VPOD and VPOD size, and the distinct accelerators fit the VPOD size (DPX partitions count once).

**Workspace** (`srt/utils/hip_vmm_utils.py`)
- `HipSymmetricBuffer(require_fabric=True)` exports FABRIC handles regardless of `SGLANG_HIP_VMM_HANDLE_TYPE`, since POSIX fds do not cross hosts.
- With `require_fabric`, ranks agree on the peer-mapping outcome, so an import that fails on some ranks only raises on every rank and `parallel_state` falls back to RCCL everywhere (the failure mode #48554 fixed for NVLink). Single-node allocation is unchanged.
- `close(group)` releases every import before any rank releases its own allocation, so no exporter revokes a FABRIC handle a peer on another host still maps. The barrier is bounded (60 s); if a peer never arrives, the allocation is left to process exit.

**`CustomAllReduceV2`** (`custom_all_reduce_v2.py`, `parallel_state.py`, `scheduler.py`)
- On ROCm, `can_use_custom_all_reduce_v2` admits a multi-node group through `probe_fabric_clique` instead of `is_one_nvlink_clique`. A multi-node group allocates with `require_fabric=True`.
- `close()` of a multi-node ROCm communicator frees the workspace only after every rank's kernels have drained (barrier, synchronize, barrier). If a barrier times out it neither synchronizes nor unmaps.
- Graceful scheduler exit aborts the process groups instead of destroying them, so `close_custom_all_reduce()` (ROCm only, multi-node carv2 only, groups in name order) closes these communicators first. Single-node and CUDA shutdown are unchanged.

**gfx1250 table** (`configs/custom_all_reduce_v2.py`)
- World size 16 (two DPX hosts, the only 16-rank layout on gfx1250): `1shot_push` to 256 KB, `2shot_push` to 64 MB, push grid of 96 blocks (one per CU). World sizes 2-8 keep the #49001 row; 9-15 stay unsupported.

**Tests**
- `test_gfx1250_fabric.py` (new, CPU): sysfs lookup, PCI function 0, clique validation (VPOD / VPOD size mismatch, per-rank failures, DPX partitions counted once), probe agreement when a peer's probe raises.
- `test_custom_all_reduce_v2_capability.py`: a multi-node ROCm group uses the fabric probe and never the NVML query. The CUDA topology test and the #48554 zero-UUID test pin the CUDA path, so they also pass on a ROCm host.

**How the TP16 row was chosen** (graph mode, back to back and with a late rank, also with a decode-sized GEMM before each all-reduce):
- `1shot_push` vs `2shot_push`: back to back they tie at 384 KB (28.9 vs 29.0 us); with a late rank `2shot_push` already wins at 384 KB (46.6 vs 42.9). Across hosts `2shot_push` pays two fabric hops, about 20 us even at 4 KB, so `1shot_push` stays ahead to 256 KB, not 64 KB as on one node.
- Push grid 64 vs 96 at 2-32 MB with 256/512/1024 threads: the existing thread rule (256 to 4 MB, 1024 above) is best for both grids; 96 blocks are faster from 4 MB (32 MB: 279 -> 243 us back to back, 292 -> 257 with a late rank) and not slower at small sizes. Unlike TP8 on one node (#49001), 96 blocks do not lose with a late rank here. Grids above the CU count stay excluded.
- `2shot_push` beats RCCL to 64 MB in every mode measured, so the RCCL fallback moves from 8 MB to 64 MB. The push slot grows to 8 MB, a 256 MB FABRIC workspace per rank at TP16.

**End to end.** DeepSeek-V4-Flash cannot run pure TP16 (`o_groups=8`), so it runs TP8 across the two hosts (4+4 DPX GPUs). That 8-rank group uses the #49001 TP8 row, which was tuned on one host. +def validate_fabric_clique(
+    capabilities: Iterable[FabricCapability],
+) -> tuple[bool, tuple[str, ...]]:
+    capabilities = tuple(capabilities)
+    if not capabilities:
+        return False, ("no fabric capability records",)
+    reasons = [
+        f"rank {c.rank} ({c.hostname}): {reason}"
+        for c in capabilities
+        for reason in c.reasons
+    ]
+    for name in ("ppod_id", "vpod_id", "vpod_size"):
+        values = {getattr(c, name) for c in capabilities}
+        if len(values) != 1:
+            reasons.append(f"ranks disagree on {name}: {sorted(values, key=str)}")
+    # VPOD size counts physical accelerators, and DPX/CPX partitions of one
+    # accelerator share its ID, so a group may hold more ranks than that
+    accels = {c.accel_id for c in capabilities if c.accel_id is not None}
+    vpod_size = capabilities[0].vpod_size
+    if vpod_size is None or len(accels) > vpod_size:
+        reasons.append(f"{len(accels)} accelerators exceed the VPOD size {vpod_size}")
+    return not reasons, tuple(reasons)

+    """Whether every rank of ``group`` is in one gfx1250 fabric clique.

+    """

+        local: object = probe_local_fabric_capability(index, rank=rank)
+    except Exception as e:
+        local = f"rank {rank}: fabric probe failed: {e!r}"

+    dist.all_gather_object(capabilities, local, group=group)

+        (False, failures) if failures else validate_fabric_clique(capabilities)
+    )
+    if not supported and rank == 0:
+        logger.warning(
+            "CustomAllReduceV2 has no fabric clique; falling back to RCCL: %s",
+            reasons,
+        )
+    return supported
