# Bug 修复卡模板(重点档)

每张卡对应一个重点档 bug-fix PR,输出到 `index/<repo>/fix-cards/pr-<N>-<slug>.md`。
文件名以 `pr-<N>-` 开头,slug 取标题(小写、非字母数字转 `-`、≤40 字符);
**out 路径以 agent 清单为准,不要自行改名**。

## 卡片结构(逐节,标题逐字保留)

```markdown
# PR #<N>: <真实标题>

| 字段 | 值 |
| --- | --- |
| 仓库 | vllm-project/vllm 或 sgl-project/sglang |
| 编号 | [#<N>](原文链接) |
| 作者 | <author> |
| 合并日期 | YYYY-MM-DD |
| labels | 逗号分隔;无则写 (none) |
| 热度 | 👍 <reactions_total> · 💬 <comments> |
| 分类 | <category> |
| bug 类型 | <bug_type> |

## 一句话结论
(≤60 字:什么 bug、什么影响、怎么修的)

## 问题现象
症状与触发条件(什么场景下出现、影响面多大),来自 PR 正文/复现描述。
正文没写就写「正文未描述具体现象」。

## 根因
PR 正文披露的根因分析;没写就如实写「正文未披露根因」,禁止从 diff 反推编造。
可以从 diff **描述**改动所暗示的机制,但必须标注「(由 diff 推断)」。

## 修复方案
改了什么(文件/函数/逻辑),可引用 ≤15 行关键 diff 摘录。

## 影响与回归风险
- 影响窗口:受影响的版本/提交范围(正文说了才写,没说不写)
- 回归面:这次改动可能影响哪些路径(按 diff 实际改动如实陈述)

## 关联
正文提到的 issue/PR 链接(≤5 个,没有就写「正文未列出」)

---
> 修复卡由 LLM 基于 PR 正文与 diff 生成,未经人工核实;以原帖与实际代码为准。
```

## 硬性规则

1. **只写 pack 里有的信息**(正文 + diff);pack 没有的一律不写。
2. 版本号、复现条件、日志等**照抄**原文。
3. 卡片正文 300-800 字(不含元信息表与尾注)。
4. diff 摘录 ≤15 行。
5. 根因只能来自正文;从 diff 推断必须标注「(由 diff 推断)」。
6. 文件名 `pr-<N>-<slug>.md`;已存在则跳过(幂等)。
7. 不要修改脚本、数据文件或其他卡片。
