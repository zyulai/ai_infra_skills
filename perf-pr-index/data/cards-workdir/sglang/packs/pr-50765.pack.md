## Motivation

PyTorch’s default BF16 GEMM leaves substantial performance headroom for the small-M projections in Cosmos3-Nano-Sim-Bimanual on SM120. On RTX PRO 6000 Blackwell Server Edition:

| GEMM shape (M, N, K) | PyTorch latency | Effective BF16 peak utilization |
|---|---:|---:|
| 224 × 4096 × 4096 | 63.04 µs | 41.3% |
| 448 × 6144 × 4096 | 139.01 µs | 56.2% |
| 448 × 24576 × 4096 | 472.92 µs | 66.0% |

Utilization is `2MNK / complete GPU call time / dense BF16 peak`, using 288.8 TFLOP/s at the requested 1.5 GHz SM clock (188 SMs). It includes reduction kernels and is not an NCU instruction-throughput percentage.

## Modifications

- Add opt-in `SGLANG_OPT_COSMOS3_SM120_GEMM=1` for Cosmos3 GEN BF16, TP=1, on the tested 188-SM SM120 configuration.
- Select QuACK for gate/up projections and FlashInfer’s cuBLASLt backend for selected QKV, output and down projections. Keep backend selection in Cosmos3; share execution, first-use library tuning and safe native fallback in `gemm/sm120_bf16.py`.
- Tune outside CUDA Graph capture, reuse library tuning results, and use allocator-managed scratch for independent calls/graphs.
- Propagate request quality through the rollout: allow the optimized paths at `quality=lossless`, while `quality=exact` retains native PyTorch GEMM.

## Accuracy Tests

| Quality | Validation | Result |
|---|---|---|
| `lossless` | 15 real-activation GEMMs: five enabled shapes from GEN layers 0, 12 and 23, compared with FP64 | Worst candidate/native RMS error ratio: **0.8203**; maximum absolute-error ratio: **1.0106**. All pass the 1.5× error gate. |
| `exact` | Native fallback compared with `torch.nn.functional.linear` | **Bitwise identical** (`torch.equal`); optimized backends are not invoked. |

Tests also cover special values, unsupported inputs, backend-specific warmup, cold/hot CUDA Graphs, independent scratch, and model/TP dispatch. These are GEMM-level accuracy checks; `lossless` does not mean bit-identical generated videos.
