## 正文(PRD / 提案全文)

To reduce the complexity of the quantization and attention backend paths, we plan to deprecate these two features.

| Feature | What it is | Why it's removable |
| :--- | :--- | :--- |
| **GPTQ (non-Marlin)** | Original desc_act/exllama-style GPTQ CUDA kernel (`gptq_gemm`, `gptq_shuffle` in `sgl-kernel/csrc/gemm/gptq`), only reached when a GPTQ checkpoint isn't Marlin-compatible | `GPTQMarlinConfig` already auto-upgrades any Marlin-compatible checkpoint to `gptq_marlin` by default, which is the actively maintained path (fully migrated to JIT). This plain kernel only serves the shrinking set of checkpoints that fall outside Marlin's supported bits/group_size/desc_act combinations, and it has no JIT/Triton replacement of its own. |
| **Dual Chunk Flash Attention** | Sparse attention kernels (`fwd_sparse`, `varlen_fwd_sparse`, `convert_vertical_slash_indexes`/`_mergehead`) backing `--attention-backend dual_chunk_flash_attn`, added for Qwen/Qwen2.5-14B-Instruct-1M 1M-context support | Purely opt-in — no model registers or auto-selects this backend. The underlying kernel hasn't had a functional change in about a year. Now we have many more options for efficient sparse attention. |

Feedback time: 3 weeks.
