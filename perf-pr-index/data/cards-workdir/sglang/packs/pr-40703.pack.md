## Motivation

In PD serving, decode can reserve a request's destination KV slots while its
prefill is still running. Long prefills can therefore occupy decode capacity
that other requests could use.

Add `--disaggregation-decode-allocation-policy prefill_complete` to delay
per-request destination KV reservation until the accepted final prefill result
is ready. Global KV pool creation and size are unchanged. The policy is opt-in;
`early` remains the default.

This policy targets workloads where decode KV capacity is constrained and
prefill completion times vary—for example, concurrent short and long prompts.
Early reservation lets unfinished long prefills occupy decode slots before they
can generate tokens, potentially delaying other requests that are ready.
Deferring reservation makes that capacity available until prefill finishes; it does
not make allocation itself or decode kernels faster.

## Modifications

- Add a Mooncake readiness control protocol with request ownership/nonces,
  subscription retry backoff, bounded waits, failure propagation, and
  pre-allocation cancellation.
- Signal readiness after accepting the final prefill result and preparing its
  output/logprob/speculative sidecars. Gate decode admission on that signal.
- Preserve the existing destination-metadata handshake and abort/drain protocol
  after destination pointers have been published.
- Keep exhausted optimistic retries eligible for prefill, and dispatch true
  retraction/rebootstrap recomputation before waiting for source readiness.
- Validate matching policies and supported configurations; add registered CPU
  regressions, a two-GPU lifecycle suite, and documentation.

Initial support is Mooncake (including TCP), the Python bootstrap registry, and
attention TP1/CP1/PP1 per rank, including attention DP. Prefill HiCache support is
limited to L2 `write_back` without storage. Decode radix/HiCache, staging,
runtime role switching, PD multiplexing, encoder disaggregation, decoupled
speculation, HiSparse, and non-DSA auxiliary state pools are excluded.

Enable the option on **both roles**. Upgrade all communicating workers with
`early` still enabled before switching policies; old decode workers cannot
enforce the new policy-mismatch check. Prefill resolves zero optimistic attempts
to one; model/cache configurations that disable optimistic prefill are rejected.

## Speed Tests and Profiling

Historical GLM-5.2-NVFP4 ABBA comparison: real MTP3, 12 Rubin GPUs, two prefill
replicas and one decode replica, each TP4/DP4/EP4, with FP8 KV and Mooncake.
Only the allocation policy differed; optimistic prefill was 1 in both policies.
Decode KV was deliberately capped at 163,840 tokens/rank to test capacity
pressure, rather than a production-default configuration.

| Mixed-workload metric | Early, two runs | Prefill-complete, two runs | Change in mean |
| --- | --- | --- | --- |
| Output tokens/s, system | 458.88 / 435.98 | 616.39 / 518.39 | +26.81% |
| TTFT p95, seconds | 71.22 / 79.97 | 36.03 / 41.27 | -48.87% |
| Mean TPOT, ms | 4.108 / 3.869 | 4.204 / 3.943 | +2.13% |
| ITL p99, ms | 34.40 / 12.03 | 46.40 / 43.10 | +92.77% |

Changes compare arithmetic means of the two per-run metrics, including
percentiles, not pooled percentiles or confidence intervals.

The throughput/TTFT gain comes with a worse ITL tail. Delayed allocation also
retains source KV longer and removes overlap between chunked prefill and KV
transfer. A separate Qwen3-8B policy-only comparison showed approximately 1%
throughput differences within run variation, without a clear mixed-workload
short-request tail improvement. These workload-dependent tradeoffs are why the
policy remains opt-in.

+The transfer backend still owns the destination-pointer handshake and abort

+class BootstrapRoom:
+    owner: object | None = None
+    endpoint: tuple[str, int] | None = None

+class DeferredBootstrap:
+    def __init__(self, timeout: float):
+        self.timeout = timeout
+        self.rooms: dict[int, BootstrapRoom] = {}
+        self.lock = threading.Lock()
+        self._next_cleanup = 0.0
+
+    def _room(self, room: int) -> BootstrapRoom:
+        now = time.monotonic()
+        if now >= self._next_cleanup:
+            # Active senders own their lifetime. Unmatched endpoints and closed
+            # rooms expire, including cancellation before the sender exists.
+            self.rooms = {
+                key: state
+                for key, state in self.rooms.items()
+                if state.owner is not None or state.expires_at > now
+            }
+            self._next_cleanup = now + min(1.0, self.timeout)
+        return self.rooms.setdefault(room, BootstrapRoom(expires_at=now + self.timeout))
+
+    @staticmethod
+    def _notification(state: BootstrapRoom) -> BootstrapNotification:
+        if state.endpoint is not None:
+            if state.failed:
+                return state.endpoint, True
+            if state.ready and not state.ready_notified:
+                # One readiness message per transfer. Decode must consume it
+                # before publishing destinations, so none can trail Success
+                # and accidentally admit the next transfer using this room.
+                state.ready_notified = True
+                return state.endpoint, False
+        return None
+
+    def open(self, room: int, owner: object) -> BootstrapRoom | None:
+        with self.lock:
+            state = self._room(room)
+            if state.owner is not None:
+                return None
+            state.owner = owner
+            return state
+
+    def register(self, room: int, endpoint: tuple[str, int]) -> BootstrapNotification:
+        with self.lock:
+            state = self._room(room)
+            if state.endpoint is not None and state.endpoint != endpoint:
+                # A room identifies one request, not a reusable allocation slot.
+                # Reject another receiver without replacing the first endpoint.
+                return endpoint, True
+            state.endpoint = endpoint
+            return self._notification(state)
+
+    def complete(self, room: int, owner: object) -> BootstrapNotification:
+        with self.lock:
+            state = self.rooms.get(room)
+            if state is None or state.owner is not owner or state.failed:
+                return None
+            state.ready = True
+            return self._notification(state)
+
+    def fail(self, room: int) -> BootstrapNotification:
+        with self.lock:
+            state = self._room(room)
+            if state.failed:
+                return None
+            state.failed = True
+            return self._notification(state)
