## PR body
```markdown
The XPU FP8 kernel's process_weights_after_loading unconditionally transposed weights, but W8A8 quant methods (modelopt, fp8) already transpose weights via .t() before calling the kernel. This caused a double-transpose, producing incorrect output dimensions and split_with_sizes errors (e.g., QKV split expecting 6144 but getting 4096).

Fix by checking weight contiguity: checkpoint weights are always contiguous [out, in] and need transposing, while pre-transposed weights from W8A8 methods are non-contiguous views and should be left as-is.

Tested with:
- CT W8A16 (RedHatAI/Meta-Llama-3.1-8B-Instruct-FP8-dynamic): ✅
- ModelOpt W8A8 (nvidia/Llama-3.1-8B-Instruct-FP8): ✅
- ModelOpt W8A8 + FP8 KV cache + Triton attention: ✅
```
