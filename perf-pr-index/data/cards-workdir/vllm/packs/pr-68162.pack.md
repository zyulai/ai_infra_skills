## Disclosure

AI assistance was used. The changes were reviewed and tested manually.

## Overview

Single-GPU layer tests do not need real distributed process groups when parallelism is irrelevant. A single-rank stand-in avoids the initialization and teardown overhead of `dist_init` when tests only need rank metadata; targeted cleanup skips further reduce unit-test runtime.

This PR extracts the existing shared-expert single-rank stand-in into `tests/single_rank_group.py` and reuses it in quantization, shared-expert, routing, expert-substitution and zero-expert tests instead of `dist_init` and individual TP rank/world-size patches. Its generator-aware decorator also supports yielding fixtures. Eligible unit tests use `skip_global_cleanup` to avoid redundant teardown.

Extracted from #67529 as a standalone PR. Searches for open single-rank/faster-parallel-test PRs found no other matching implementation. There are no production-code or user-visible behavior changes.

## Claims

- `SingleRankGroup` supplies rank 0, world size 1 and identity collectives without FileStore/backend or model-parallel group initialization. The context/decorator restores all eight groups on return or exception; yielding fixtures retain the override through teardown, with signatures preserved for pytest.
- Adoption only adds decorators/cleanup marks and removes obsolete single-rank setup. Test bodies, assertions, tolerances and platform skips are otherwise unchanged; TP>1 simulation patches remain intact.
- Eligible tests skip redundant global teardown without rewriting their existing cleanup implementations. The online FSE module retains its original cleanup, and the MoE hook recognizes decorated tests to preserve clean-entry isolation.
- The full PR is approximately 2.6× faster than the pinned main baseline on the measured selection (487.79 s → 190.87 s), with 301 passed and 63 skipped in all three configurations. Most of the gain is teardown: `dist_init` runs `cleanup_dist_env_and_memory()` (a full `gc.collect()`) on top of the autouse cleanup, so main pays it twice per test; the decorators remove one and `skip_global_cleanup` the other (example in Details).
- Quantization CUDA/ROCm, CUDA Quantized Models, AMD model-executor and MoE CUDA/ROCm CI jobs list the helper in `source_file_dependencies`.

Left to other PRs:
- [ ] CUDA/XPU timing and multi-rank validation are not measured here; this change targets single-rank unit-test setup, not distributed correctness.

## Details

The stand-in was already present in the shared-expert tests:
https://github.com/vllm-project/vllm/blob/fa6c77f5954ef22e705cd82456cc731ba67d0ae9/tests/model_executor/layers/test_fused_shared_expert.py#L1327-L1416

Example, `tests/quantization/test_online.py::test_online_quantization_targets[linear_regex]` (unchanged body), median of 7 runs per configuration:

| Configuration | Setup | Body | Teardown | Total | `cleanup_dist_env_and_memory()` calls |
| --- | ---: | ---: | ---: | ---: | ---: |
| main | 323 ms | 348 ms | 850 ms | 1513 ms | 2 |
| This PR, no additional `skip_global_cleanup` | 17 ms | 350 ms | 403 ms | 771 ms | 1 |
| This PR, single-rank decorators and additional `skip_global_cleanup` | 3 ms | 360 ms | 2 ms | 365 ms | 0 |

On main the test pays the cleanup twice: the `dist_init` fixture calls `cleanup_dist_env_and_memory()` after its `yield`:
https://github.com/vllm-project/vllm/blob/fa6c77f5954ef22e705cd82456cc731ba67d0ae9/tests/conftest.py#L225-L250
and the autouse `cleanup_fixture` calls it again unless `skip_global_cleanup` is set:
https://github.com/vllm-project/vllm/blob/fa6c77f5954ef22e705cd82456cc731ba67d0ae9/tests/conftest.py#L275-L279
Each call is dominated by a full `gc.collect()` (~0.4 s over ~1M live objects), while the `dist_init` setup itself is cheap once warm. The decorators remove the first call; `skip_global_cleanup` removes the second.

The aggregate gain from the decorators alone is smaller than this example suggests: only 131 of the 301 passed tests used `dist_init` on main (113 already used a fake group, 57 need neither), and run-to-run variation is large. An earlier run on a different device measured 339 s on main versus 336–363 s without the additional cleanup skips, i.e. within noise, whereas the cleanup skips gave a consistent ~2.5×.

This is deliberately test-only and does not emulate real communication or asynchronous collectives. An attempted module-wide cleanup skip in the online FSE suite caused its checkpoint-weight equality test to fail, so that module retains its original cleanup policy. No AITER finalizer rewrite or assertion changes are included.

+# SPDX-License-Identifier: Apache-2.0
+# SPDX-FileCopyrightText: Copyright contributors to the vLLM project
+"""A single-rank stand-in for the parallel groups, to build layers in unit tests
+without initializing `torch.distributed`."""
+
+from contextlib import ContextDecorator
+from functools import wraps
+from inspect import isgeneratorfunction
+from typing import Any
+
+import torch
+
+import vllm.distributed.parallel_state as parallel_state
+
+_GROUP_NAMES = ("_WORLD", "_TP", "_ETP", "_DCP", "_PP", "_DP", "_EP", "_PCP")
+
+
+class SingleRankGroup:
+    """No-op single-rank stand-in for a compiled `GroupCoordinator`."""
+
+    world_size = 1
+    rank_in_group = 0
+    local_rank = 0
+    is_first_rank = True
+    is_last_rank = True
+
+    @property
+    def device_group(self):
+        return self
+
+    @property
+    def cpu_group(self):
+        return self
+
+    @property
+    def device_communicator(self):
+        return self
+
+    def rank(self) -> int:
+        return 0
+
+    def size(self) -> int:
+        return 1
+
+    def all_reduce(self, input_: torch.Tensor, *args: Any, **kwargs: Any):
+        return input_
+
+    def all_gather(self, input_: torch.Tensor, dim: int = 0):
+        return input_
+
+    def all_gatherv(self, inputs: Any, dim: int = 0, sizes: Any = None):
+        return inputs
+
+    def reduce_scatter(self, input_: torch.Tensor, dim: int = 0):
+        return input_
+
+    def reduce_scatterv(self, input_: Any, dim: int = 0, sizes: Any = None):
+        return input_
+
+    def broadcast(self, input_: torch.Tensor, src: int = 0):
+        return input_
+
+    def send(self, *args: Any, **kwargs: Any) -> None:
+        return None
+
+    def recv(self, *args: Any, **kwargs: Any) -> None:
+        return None
+
+    def barrier(self) -> None:
+        return None
+
+    def destroy(self) -> None:
+        return None
+
+
+class _ParallelGroupOverride(ContextDecorator):
+    def __init__(self, group: SingleRankGroup):
+        self.group = group
+        self.saved: list[dict[str, Any]] = []
+
+    def __enter__(self) -> None:
+        self.saved.append(
+            {name: getattr(parallel_state, name) for name in _GROUP_NAMES}
+        )
+        for name in _GROUP_NAMES:
+            setattr(parallel_state, name, self.group)
+
+    def __exit__(self, *exc: Any) -> None:
+        for name, value in self.saved.pop().items():
+            setattr(parallel_state, name, value)
+
+    def _recreate_cm(self) -> "_ParallelGroupOverride":
+        return _ParallelGroupOverride(self.group)
+
+    def __call__(self, function):
+        if isgeneratorfunction(function):
+
+            @wraps(function)
+            def wrapped(*args: Any, **kwargs: Any):
+                with self._recreate_cm():
+                    return (yield from function(*args, **kwargs))
+        else:
+            wrapped = super().__call__(function)
+
+        decorated: Any = wrapped
+        decorated._uses_single_rank_groups = True
+        return decorated
+
+
+def override_parallel_groups(group: SingleRankGroup) -> _ParallelGroupOverride:
+    """Use `group` for all parallel groups, including across generator yields."""
+    return _ParallelGroupOverride(group)
