## Motivation

This pull request fixes a CUDA graph replay crash that occurs when running with `--enable-mixed-chunk` and Piecewise CUDA Graph (PCG) enabled. Command: `python -m sglang.launch_server --model /models/Qwen3-8B --trust-remote-code --host 0.0.0.0 --port 30000 --enable-mixed-chunk --chunked-prefill-size 8192 --max-running-requests 256 --enable-metrics --attention-backend flashinfer` reports an error:
<img width="1700" height="503" alt="image" src="https://github.com/user-attachments/assets/77e0f1f8-fa27-4678-880c-2533b9e5a85b" />

The reason is when mixed-chunk prefill is on, the scheduler sets `forward_mode=ForwardMode.MIXED` for runtime batches, but PCG graphs are always captured under `ForwardMode.EXTEND`, causing TorchDynamo’s strict guards on `forward_mode` to fail and trigger an unexpected runtime recompilation. During this recompilation, CUDA graph capture is attempted again, but `get_pcg_capture_stream()` returns `None` outside of the dedicated PCG capture phase, leading to an `AssertionError: PCG capture stream is not set`.

The goal of this PR is to align replay-time `forward_mode` with the capture-time mode in mix chunk prefill condition so that replay uses the pre-captured graphs instead of forcing a recompilation path that cannot recapture safely.

## Modifications

- Updated `replay_prepare()` in `sglang/python/sglang/srt/model_executor/piecewise_cuda_graph_runner.py` so that `static_forward_batch` is normalized to use `ForwardMode.EXTEND` when the incoming `forward_batch.forward_mode` is `ForwardMode.MIXED`.

## Accuracy Tests

- Verified that enabling `--enable-mixed-chunk` no longer triggers TorchDynamo recompilation or `AssertionError: PCG capture stream is not set` and produces correct results.
