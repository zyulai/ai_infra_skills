## 正文(PR 描述)

## Motivation

Follow-up to #29742's Z-Image accuracy fix. In review, [the reviewer asked](https://github.com/sgl-project/sglang/pull/29742#pullrequestreview-4600915803) whether this class of bug (dynamic batching silently corrupting output when requests have different real caption lengths) is Z-Image-specific. It isn't — `ernie_image` and `wan` (T2V) have the same underlying gap:

- **Ernie-Image**: `_prepare_cond_kwargs` hardcoded `txt_seq_lens = [prompt_embeds[0].shape[1]]` (a single-element list regardless of real batch size), and the DiT `forward()` had no attention-mask parameter at all — nothing kept cross-attention off the padded tail of a shared, padded `encoder_hidden_states` tensor.
- **Wan T2V**: `WanT2VCrossAttention.forward()`/`WanI2VCrossAttention.forward()` already declare a `context_lens` parameter that's clearly meant for exactly this, but every call site hardcodes `context_lens=None` — dead code. The real per-request lengths were even computed once in `t5_postprocess_text` and then discarded.

Both are fixed here by wiring in the same `require_text_seq_lens` / `build_varlen_mask_meta` primitives already used correctly by `qwen_image.py` and `krea2.py`, and (for Wan) by the same `TextConditioningOutput` pattern Z-Image and Qwen-Image already use.

**SD3 has the same class of bug but is intentionally out of scope for this PR.** Its DiT wraps diffusers' `JointTransformerBlock`/`JointAttnProcessor2_0` directly, and that stock processor accepts an `attention_mask` argument but never actually uses it (confirmed by reading the installed diffusers source: it calls `F.scaled_dot_product_attention(query, key, value, ...)` with no mask, regardless of what's passed in `joint_attention_kwargs`). A real fix needs a custom `AttnProcessor` backed by SGLang's own attention layer — materially higher risk/scope, and a separate PR.

## Modifications

**Ernie-Image** (`configs/pipeline_configs/ernie_image.py`, `runtime/models/dits/ernie_image.py`):
- Tokenizer padding changed from `False` to `"longest"` so a dynamic batch of different-length prompts can actually be tokenized into one tensor.
- `ernie_image_postprocess_text` now extracts each request's real (unpadded) span via the tokenizer's attention mask and re-pads via `pad_text_embeddings_with_mask`, returning `TextConditioningOutput` (mirrors `qwen_image_postprocess_text`/`zimage_postprocess_text`).
- `_prepare_cond_kwargs` now reads real per-request lengths via `require_text_seq_lens` instead of assuming batch-size 1, and builds an `encoder_hidden_states_mask`.
- DiT `forward()` accepts `encoder_hidden_states_mask`, builds the joint `[image, text]` mask + `build_varlen_mask_meta`, and threads it through the block/self-attention call chain into the existing `USPAttention`.

**Wan T2V** (`configs/pipeline_configs/wan.py`, `runtime/models/dits/wanvideo.py`):
- `t5_postprocess_text` now returns `TextConditioningOutput` (real lengths were already computed from the T5 attention mask, just discarded before).
- `WanT2V480PConfig.prepare_pos_cond_kwargs`/`prepare_neg_cond_kwargs` now build an `encoder_hidden_states_mask` via `require_text_seq_lens`.
- `WanTransformer3DModel.forward()` threads the mask through `WanTransformerBlock`/`WanTransformerBlock_VSA` into the cross-attention `context_lens` parameter (previously always `None`), which now actually masks padding via `build_varlen_mask_meta`.
- `WanI2VCrossAttention` gets the same wiring for consistency, though I2V isn't currently reachable via dynamic batching (task type outside the admission allowlist) so this is inert today.
