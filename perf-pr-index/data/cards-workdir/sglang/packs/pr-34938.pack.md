## Motivation

For Qwen MoE models using CUDA and DeepEP, the shared expert currently runs on the default stream before the routed-expert path. This serializes two independent computations and leaves an available alternate stream unused.

This PR adds an opt-in path that overlaps the Qwen shared expert with routed-expert/DeepEP execution.

## Modifications

- Add `SGLANG_QWEN_DEEPEP_SHARED_OVERLAP` (default: `false`).
- When enabled on CUDA, enqueue the shared expert on `alt_stream`, execute the routed-expert path on the current stream, and wait on an event immediately before accumulating the shared output.
- When breakable CUDA graph is active, skip this optimization and retain the existing serial shared-expert path; cross-segment overlap across the eager DeepEP break is out of scope.
- Document the new environment variable.

The accuracy evidence below was collected on predecessor `38f714d28e1fa01ae5b1ce38ce576373b8293722`, based on upstream main `0c072235f44fce4b89e594c2d3348e4f48e774b8`, with a clean source tree. Current head `76815b3766deb3a3c9aceef1cb346093f691d976` differs only by making breakable CUDA graph use the pre-existing serial fallback instead of an alternate-stream path with an immediate wait; the non-breakable overlap implementation measured below is unchanged.

## Speed Tests and Profiling

The performance A/B exercised the same overlap mechanism on the benchmark stack before this upstream-main port. The upstream-main commit listed in the accuracy section was validated separately through CUDA graph capture and GSM8K.

The end-to-end A/B comparison used the same configuration and differed only in the job name and `SGLANG_QWEN_DEEPEP_SHARED_OVERLAP=true`.

Configuration: `nvidia/Qwen3.5-397B-A17B-NVFP4`, 24x GB300 disaggregated serving (four TP4/DP4/EP4 prefill replicas and one TP8/DP8/EP8 decode replica), FP4 weights, FP8 KV cache, NEXTN draft length 6, concurrency 896, fixed accepted length 4.8, and a 3,600-second AgentX replay.
