## Motivation
The decode cuda graph may not have run (for example, if the batch size was too large). This grabs the correct tensors based on whether the cuda graph was run.  

Also, some questions:
Also, the hidden states differ at every MTP step in `self.eagle_worker.chain_mtp_hidden_states` , so I'm not very convinced the logic is correct as it currently stands. You would need to store the hidden states for every step. So while this prevents crashing / OOB memory access, I don't think it's fully correct. I am also lacking context/understanding of why these last hidden states need to be stored and rerun through the graph, with an expanding seq len (as opposed to the `rotate_input_ids` in the non-cuda graph path).
