## Purpose

DSV4.1 decode (TP4, `0 < M <= 16`, FULL CUDA graphs) closes every sublayer with a fused TP all-reduce + mHC kernel. After an MoE, that boundary is preceded by FlashInfer's MoE finalize (top-k weighted sum) and a separate shared-expert add. This PR folds the finalize and the shared add into the boundary:

- **Vendored FlashInfer LL kernels.** `vllm/models/deepseek_v41/nvidia/ops/cute_dsl/` copies FlashInfer's CuTe DSL low-latency MNNVL all-reduce (`flashinfer/comm/mnnvl_cutedsl/kernel_ll`, flashinfer-ai/flashinfer@139af6f6, the H5120 presets):
  - `_SharedOnlyPublishDeviceKernel` and `_group_leader_block_sum` are byte-identical to upstream.
  - `_QuadFinalizePublishDeviceKernel` is upstream's plus an `fp32_weights` option. DSV4.1's router emits FP32 top-k weights with the routed scaling folded in; FlashInfer loads BF16.
  - `_LamportMHCDeviceKernel` is upstream's `_LamportResidualRMSNormDeviceKernel`. Its residual add and copy are replaced by the mHC post-mix of the hc streams (stored as the new residual) and their pre-mix collapse, which the unchanged RMSNorm then normalizes. This replaces `torch.ops._C_custom_ar.all_reduce_mhc` (#57643) on the overlap path. That CUDA kernel has no other user, so this PR deletes `csrc/libtorch_stable/all_reduce_mhc.cu` and its CMake entry. #57643's boundary wiring (`reduce_results`, `fuse_mhc_all_reduce`, `supports_mhc_all_reduce`) is kept and reused.
- **MoE left unfinalized, via #58635.** For layers whose experts are the modular TRTLLM MXFP4 ones, DSV4.1 requests deferral once at model build with `moe_config.defer_moe_finalize(MHC_OVERLAP_MAX_TOKENS)`. Per call, `should_defer_moe_finalize(M)` picks the path, and the experts return a single `UnfinalizedMoEOutput`. This PR touches no fused-MoE code.
- **DSV4.1 wiring (model file only, no new runner).**
  - A layer defers when its successor opens with the fused boundary: 37/40 layers on DSV4.1-Flash. The last layer and the layers before an engram layer finalize as before.
  - `DeepseekV4MoE.forward_unfinalized` runs the runner's `_forward_impl` directly, since the custom op returns tensors only. It hands `MoEOutput(routed=UnfinalizedMoEOutput, shared_output=...)` to the next layer.
  - `mhc_shifted_post_pre` calls `AllReduceMHC.finalize`, so top-k reduce, shared add, all-reduce and mHC post/pre run as two PDL-chained kernels.
  - Outside FULL graphs (eager/PIECEWISE), the next mixes run inline instead of on the side stream.
  - `MHC_OVERLAP_MAX_TOKENS` (16), the side-stream design and the M > 16 path are unchanged.

Duplicate check: #58635 (merged) supplies the modular-path deferral this builds on. #52601 (MoE tail all-reduce fusion for MiniMax-M3, last updated 2026-09-02) targets a different model and kernel. No open PR fuses the DSV4.1 MoE finalize into the mHC boundary.

## Notes

- Like upstream, `_QuadFinalizePublishDeviceKernel` reads the routing metadata before `griddepcontrol.wait`. That is safe only if the preceding GEMM2 triggers its dependents after its own wait. The graph-mode check saw no mismatch; a wait-first variant measured about 0.08 ms/step slower at concurrency 1 (on a different node) with no accuracy difference.
- Moving the prenorm GEMM + Sinkhorn onto the critical path instead of the side stream was measured: +17–20 µs per decoder layer at M = 1–32, with the mixes inline or with TileLang's fused post + prenorm GEMM. So the side stream stays.

+@cute.jit
+def _group_leader_block_sum(
+    value: Float32,
+    warp_sums: cute.Tensor,
+    warps: cutlass.Constexpr[int],
+    leader_stride: cutlass.Constexpr[int],
+) -> Float32:
+    lane = cute.arch.lane_idx()
+    warp = cute.arch.warp_idx()
+    for offset in cutlass.range_constexpr(1, WARP_SIZE):
+        if cutlass.const_expr(offset >= leader_stride and (offset & (offset - 1)) == 0):
+            value = value + cute.arch.shuffle_sync_bfly(
+                value,
+                offset=offset,
+                mask=-1,
+                mask_and_clamp=31,
+            )
+    if lane == 0:
+        cute.arch.store((warp_sums + warp).llvm_ptr, value)
+    cute.arch.barrier()
+
+    result = Float32(0.0)
+    if warp == 0:
+        if lane < Int32(warps):
+            result = cute.arch.load(
+                (warp_sums + lane).llvm_ptr,
+                Float32,
+            )
+        result = cute.arch.warp_reduction_sum(result)
+        if lane == 0:
+            cute.arch.store(warp_sums.llvm_ptr, result)
+    cute.arch.barrier()
+    return cute.arch.load(warp_sums.llvm_ptr, Float32)
