## 正文(PR 描述)

## Summary

#43492 temporarily reverted #42540 because #43480 looked like a humming import issue, but #43528 shows the same `pytest` failure still happens after humming was removed. The shared root cause is that `vllm-openai:nightly` installs KV connectors by default, `lmcache` pulls the recently released `cupy-cuda13x==14.1.0`, and that CuPy release imports `pytest` from `cupy.testing._random` when PyTorch custom-op registration walks loaded modules via `inspect`.

This constrains KV connector installs to `cupy-cuda13x < 14.1.0`, which resolves to `14.0.1`, and restores humming with `humming-kernels[cu13]==0.1.2` plus the CUDA 12 extra rewrite. I checked dependency resolution and the relevant import order with `pytest` blocked: `torch -> cupy 14.0.1 -> humming` succeeds.
