## PR body
```markdown
## Motivation

KDA already computes packed Q/K/V convolution in one call. Its token-major output leaves the three channel slices non-contiguous, so the FlashInfer prefill path materializes three copies before consuming them. At the GLM-5.3-Flash TP4 16K-token shape, those copies cost more than the convolution itself.

## Modifications

Add an optional split-output layout to the existing Triton convolution. The convolution stores directly into contiguous Q/K/V planes in one allocation, using the runtime total-token count as the plane pitch. Arithmetic and convolution-state updates are unchanged.

Both eager KDA prefill and captured KDA prefill enable it only for FlashInfer with equal Q/K/V widths. Other backends and unequal widths retain the original layout. There are no server-argument, graph-size, precision, MoE or memory-budget changes, and no dependency on the separate empty-view fix #46737 or community PRs #45369/#45583.

Related work: #32474 packs convolution with a separate output-layout kernel; #34299 integrates a native checkpoint backend; #45992 handles copies in the Triton KDA normalization path. This patch changes the existing convolution producer's store for the existing FlashInfer path, including graph execution.

## Accuracy Tests

This does not establish the cause or an accuracy pass for this individual patch.

## Speed Tests and Profiling

Single B300, BF16 input, FP32 width-4 weights, no bias, local Q/K/V width 2048 each, input row stride 6416. CUDA-event medians of nine samples, alternating baseline/candidate order; each sample includes 100 invocations through CUDA-graph replay. Both arms use the same patched operator: the original output mode plus three contiguous copies versus the new split-output mode.

| Total tokens | Original convolution + Q/K/V copies | Split-output convolution | Speedup |
| ---: | ---: | ---: | ---: |
| 1024 | 24.945 us | 10.272 us | 2.43x |
| 8192 | 180.952 us | 68.585 us | 2.64x |
| 16384 | 347.838 us | 130.748 us | 2.66x |

These new-main measurements cover this local path, not full-model latency or request throughput. The convolution-only kernel is not claimed to be 2.66x faster; eliminating the three layout copies supplies the improvement. No combined serving-throughput result is attributed to this PR.

    out = causal_conv1d_fn(
        x.T, w, None, states[int(split)], cu, lengths, slots, initial,
        output_split_size=h if split else 0,
    )
    return tuple(out.unbind(0)) if split else tuple(
        t.contiguous() for t in out.T.chunk(3, dim=-1)
    )

before, after = run(False), run(True)
for a, b in zip(before, after):
    torch.testing.assert_close(a, b, rtol=0, atol=0)
torch.testing.assert_close(states[0], states[1], rtol=0, atol=0)
graphs = []
for split in (False, True):
    for _ in range(5):
        run(split)
    torch.cuda.synchronize()
    graph = torch.cuda.CUDAGraph()
    with torch.cuda.graph(graph):
        for _ in range(10):
            run(split)
    graphs.append(graph)
samples = [[], []]
for repeat in range(9):
    for index in ([0, 1] if repeat % 2 == 0 else [1, 0]):
        start, end = (torch.cuda.Event(enable_timing=True) for _ in range(2))
        start.record()
        for _ in range(10):
            graphs[index].replay()
        end.record()
        end.synchronize()
        samples[index].append(start.elapsed_time(end) * 1000 / 100)
print("baseline_us, split_us:", *map(statistics.median, samples))
