## 正文(PR 描述)

# Motivation

`sgl-model-gateway`'s dp-aware mode injects `data_parallel_rank` into every request it forwards ([`DPAwareWorker::prepare_request`](https://github.com/sgl-project/sglang/blob/7adf2f4a9a4389d1c021a2caf128cf7e2f4adb35/sgl-model-gateway/src/core/worker.rs#L1106-L1118); the worker's own unit test [asserts this exact spelling](https://github.com/sgl-project/sglang/blob/7adf2f4a9a4389d1c021a2caf128cf7e2f4adb35/sgl-model-gateway/src/core/worker.rs#L1806)). On the native `/generate` path, current servers silently drop that field, so the gateway's routing decision never reaches the DP controller and dispatch falls back to load balancing. **dp-aware routing over native `/generate` is currently a silent no-op.**

## How this happened

- #19268 renamed `GenerateReqInput.data_parallel_rank` → `routed_dp_rank`, keeping a deprecated alias that mapped to `routed_dp_rank` (with a `DeprecationWarning`) in `normalize_batch_and_arguments()`.
- #29214 (a cleanup, merged 2026-06-25) removed that alias from `GenerateReqInput` — but the gateway still emits the old spelling, and the alias still exists on the two other ingress paths: the OpenAI-compat layer ([`_migrate_deprecated_dp_rank`](https://github.com/sgl-project/sglang/blob/7adf2f4a9a4389d1c021a2caf128cf7e2f4adb35/python/sglang/srt/entrypoints/openai/protocol.py#L303-L315)) and [`Engine.generate()`](https://github.com/sgl-project/sglang/blob/7adf2f4a9a4389d1c021a2caf128cf7e2f4adb35/python/sglang/srt/entrypoints/engine.py#L313-L325). Native HTTP `/generate` is the only entrypoint that lost it.

## Why it's silent

FastAPI parses `GenerateReqInput` as a (pydantic) dataclass that ignores unknown keys, so nothing errors; `routed_dp_rank` stays `None`; and the DP controller has a legitimate fallback for that case — [load balancing](https://github.com/sgl-project/sglang/blob/7adf2f4a9a4389d1c021a2caf128cf7e2f4adb35/python/sglang/srt/managers/data_parallel_controller.py#L736). The failure mode is pure performance (prefix-cache hit rate and routing quality quietly degrade), which makes it hard to notice and hard to bisect.

We hit this in production on a dp=4 deployment with the gateway in dp-aware mode (session-keyed manual routing): prefix-cache hit rate was ~0.49 with the routing silently dropped vs ~0.97 with the rank honored, roughly 2x decode throughput on an agentic workload. Verified mechanically: `/generate` with `routed_dp_rank=2` moves only rank 2's prefill counters, while `data_parallel_rank=2` moves whichever rank load balancing picks.

# Modifications

Restore exactly what #29214 removed from `GenerateReqInput`: the deprecated `data_parallel_rank` field, plus the mapping in `normalize_batch_and_arguments()` (explicit `routed_dp_rank` wins) with the original `DeprecationWarning`. This mirrors the aliases still present in `protocol.py` and `engine.py`.

Unit tests in `test/registered/unit/managers/test_io_struct.py`: alias maps to `routed_dp_rank`, alias does not override an explicit `routed_dp_rank`, alias propagates to batch items.

# Alternatives considered

We recognize a deprecated alias is not the cleanest end state, so laying out the option space explicitly:

1. **Fix the gateway instead: emit `routed_dp_rank`.** The right long-term spelling, but insufficient alone. The gateway/router is released and deployed separately from the server, so every already-shipped gateway keeps emitting the old name; and a gateway that emits *only* the new name still leaves servers built between #29214 and this fix broken. The server-side alias repairs **all released gateway versions at once** on the next server upgrade. Compatibility matrix:

   | server version \ gateway | emits `data_parallel_rank` (all released) | emits both (proposed follow-up) |
   |---|---|---|
   | #19268 → #29214 | works (alias) | works |
   | #29214 → this fix | **silently broken** | works |
   | ≥ this fix | works (alias restored) | works |

   We'd suggest a follow-up where the gateway emits **both** spellings for a deprecation window, then switches to `routed_dp_rank` only — happy to send that PR.

2. **Map the alias at the HTTP boundary (`http_server.py`) instead of the dataclass.** Keeps `io_struct` clean, but `/generate` is not the only constructor of `GenerateReqInput` (Vertex endpoint, engine API), and `normalize_batch_and_arguments()` is the existing normalization choke point — it's also where #19268 originally put this exact mapping.

3. **Reject unknown fields on native `/generate`.** Strict parsing would have turned this silent no-op into a loud 422 and would catch future drift between what the gateway injects and what the server accepts. It's a breaking change for clients that send extra keys, so out of scope here, but possibly worth a separate discussion.

4. **Do nothing and require clients to migrate.** Leaves every deployed dp-aware gateway silently broken on the native path.

If maintainers prefer option 1 with a hard break (no server-side alias), we're glad to rework — but the gateway change should then land and be *released* before the alias is (re-)removed, i.e. the ordering that #29214 missed. A cheap recurrence guard would be a test asserting that every key `DPAwareWorker::prepare_request` injects is accepted by `GenerateReqInput`; happy to add one if there's appetite.
