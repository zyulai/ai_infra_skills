## 正文(PR 描述)

This pull request has the following changes:
(1) Fixed the cmake build bug which did not build correct kernels for various GPU targets. As a result, vllm generated garbage and impacted MI300x users.
(2) Refactor Dockerfile.rocm based on @WoosukKwon 's feedback.

[Context]
The customer (cc @hliuca) reported that garbage was generated after vllm v0.4.0 on MI300x with ROCm6.1 docker (rocm/pytorch:rocm6.1_ubuntu22.04_py3.10_pytorch_2.1.2).

[Fix]
After a couple days of debugging of the issue using main branch on MI300x, I found that the current cmake did not use the correct HIP target, or gpu architecture.
It displays like below:
```
-- HIP target arches: gfx906
-- Punica target arches: gfx906
```
There are several problems of this bug:
(1) Correctness: It compiled the CudaExtension (vllm kernels), Punica kernels, MoE kernels using the above arch, which was wrong and vllm behaved badly and generate garbages on MI300x (gfx942).
(2) Expandability: It only builds kernels with one gpu target while we expect to support multiple gpu archs. The reason to build for multiple archs is expandability and time saving, as one docker image built on one type of build machine can be used in multiple gpu platforms without needing to rebuild on every gpu platform.
(3) Other impacts might include that benchmarking will produce wrong numbers.

After the fix, the correct target is displayed:
```
#20 26.62 -- HIP target arches: gfx908;gfx90a;gfx942;gfx1100
#20 29.32 -- Punica target arches: gfx908;gfx90a;gfx942;gfx1100
```
and it no longer generates garbage on MI300x.
