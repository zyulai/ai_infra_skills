## Motivation

When changing default LoRA backend to CSGMV, I noticed a bug in the kernel caching optimization caused by incorrect kernel key: Triton implicitly specializes on `num_segs` parameter even though it was not declared `tl.constexpr`, resulting in incorrect specialization caching. 

The issue wasn't caught before because most of our existing CI only runs against the default LoRA backend (triton). It will be addressed in: https://github.com/sgl-project/sglang/pull/11488
