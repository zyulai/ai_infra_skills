```markdown
## Overview

MiMo-V2.6 has asymmetric K/V head dims (192 / 128), which today pins it to the DiffKV attention backends: any other `--attention-backend` is silently replaced by the DiffKV auto-pick, and the native KV-cache write would copy V with K's head width. This PR makes `--attention-backend ROCM_AITER_UNIFIED_ATTN` usable for the model (opt-in, defaults unchanged) and fixes the write kernel.

## Claims

- `--attention-backend ROCM_AITER_UNIFIED_ATTN` now selects unified attention for every MiMo-V2.6 layer instead of being dropped; verified on Flash (TP2, TP4, TP8) and on Pro (TP8, gsm8k n=100 parity).
- `reshape_and_cache_flash` writes V with its own head size and head stride. Symmetric callers run the same code as before: the new checks live in the asymmetric branch, and the existing kernel is byte-identical to `main`.
- Accuracy and speculative-decoding parity with the default backend (gsm8k at n=1319, MTP x3 acceptance).
- At long context prefill is 1.43x faster at 128k and 1.21x at 32k, with decode 1.17x faster per token (TPOT p50 2.94 vs 3.45 ms) and output throughput up 21-45%. At 8k with concurrency 8 the two are at parity. Measured with `--block-size 16` on both arms, which tested better than the backend's default for this shape. On Pro at TP8 the same benchmark gives 1.13x prefill and 1.66x lower inter-token latency.

### Tests

```
# kernel fix: main's cache_kernels.cu vs this one
pytest tests/kernels/attention/test_cache.py -k asymmetric        # 33 failed -> 33 passed
# model change: main's backend selection vs this one (either kernel)
pytest tests/models/test_mimo_v2_attention_backend.py             # 2 failed, 5 passed -> 7 passed
```

The asymmetric kernel test runs MiMo's geometry (K 192 / V 128, 4 KV heads) at both block sizes the model uses (16 and 64) over a parametrized token count, in both layouts unified attention hands the kernel, for bf16 and fp8 caches and per-tensor and per-head scales. The whole file stays green (694 passed, 602 skipped).

The model test gained two checks: the selected backend's *impl* has to be unified attention's, not just its enum; and the cache the layer writes has to match a cache built in torch, per slot, with K in the first `head_dim` columns of a row and V in the remaining `v_head_dim`. Both fail on `main`. The kernel test's buffers carry slack past the cache, so a regressed kernel fails that comparison instead of writing out of bounds.

## Details

`reshape_and_cache_flash_kernel` derived one head size, one page stride, one head stride and one element count from key/key_cache and reused all of them for the value side:

```cpp
cache_t* v_dst_h = value_dst + head * head_stride;             // K's stride
vectorize_with_alignment(value_src, value_dst, n_elems, ...);  // K's width
```

Every caller until now was symmetric, so this was invisible. Unified attention is the first caller that passes `v_head_size != head_size` (MiMo is 192 / 128, packed as one `(head_size + head_size_v)` content dim per KV head), and for it V was read at K's per-head offset, copied at K's width - 64 elements past the end of each head - and written past the end of the cache on the last slot. The asymmetric case now gets its own kernel that addresses V with the value side's own head stride and length; the existing kernel and its NHD fast path are untouched, so symmetric callers run the same code as before.

Model side: the attention backend is chosen per layer, and the gate now consults a backend capability (`supports_head_size_v`) rather than listing backend names. DiffKV declares that it can serve any K/V width relation; unified attention declares `v <= k`, because it splits the page with `split(head_size)`. A backend that cannot serve the shape still gets the previous behaviour: a warning and the DiffKV auto-pick.

Known limitations:

- Requires aiter >= 0.1.25 for the V-dim-masked unified-attention kernels; `main` pins 0.1.26.
- Unified attention serves V narrower than K, not wider (`v_head_dim > head_dim` cannot be expressed by its page split); such a request falls back to the DiffKV auto-pick with a warning.
