## 正文(PR 描述)

## Motivation

The third cleanup pass, after #44690, #48366 and #48399, and the first one done with the code-cleanup skill (#49163). It covers code and environment variables together: the srt runtime, layers and models, kernels, diffusion, every env var, CLI flags, and the docs that describe them. Each finding cites the skill's pattern and survived its "not this pattern" cases; items an open PR is already changing were left to that PR.

**261 files, +986 / -5,217.** About 600 of the additions are new regression tests and test edits.

## Bugs fixed (please review these first)

| Area | Problem | Fix |
|---|---|---|
| LoRA | `--lora-backend torch_native` raised `TypeError` on every single-projection `ReplicatedLinear` (fc*_latent_proj, DSA indexer projections, `fused_qkv_a_proj_with_mqa` without q_lora): the call omitted `output_offset_cpu`. | Pass it; test with the real backend. |

| `configure_logging` helper | The documented "change log level at runtime" command also turned off `--log-requests` and started dumping request contents to `/tmp/sglang_request_dump`: the helper sent defaults for every key. | Send only the keys the user passed; test. |

## Deleted or merged

- **Dead code with string-aware proofs (A1):** the jump-forward leftovers from #4032 (`outlines_jump_forward.py` and the `try_jump_forward` / `jump_and_retokenize` plumbing in every grammar backend, -381); the `show_time_cost` timers; `startup_func_log_and_timer.py`; dead manager methods and never-constructed IPC structs; Inkling banded and one-shot ssconv-norm kernels nothing calls (-920 incl. the CUDA range); `gpu_tensor_hash` (its last caller moved to blake3 in #47120); the Qwen-Image 2.1 Q/K RMSNorm path whose kernel and tests stayed alive only through test calls; Hunyuan3D's never-wired FlashVDM decoder (-477); unreferenced definitions across layers and models; shadowed duplicate definitions (F811); always-None `getattr` gates on fields nothing sets; dead locals.
- **Dead branches for removed features (A6):** `hybrid_linear_attn` draft-backend entries (backend removed in #10816), a second ModelOpt loader dispatch that the first already covers (proven over all inputs), `is_weights_quantized` skips nothing defines, diffusion fallbacks reading removed config fields, `accept_output_buffer` on 21 attention backends.
- **One copy (B1):** `is_health_check_request` (four identical copies), `round/ceil/floor_by_factor`, `get_abs_pos`, `_get_feat_extract_output_lengths`, `yarn_get_mscale`, Cosmos3 sharding helpers, the ModelOpt FP8 scale predicates; each pair AST-identical.
- **Gates (D1):** `_is_sm10x` -> `current_arch().is_sm(10)`; a `capability >= 9` probe that was also true on gfx950 -> `is_sm(9)`.
- **Relocations (pure moves, no shims):** `silu_mul_fp8_group_quant` -> `ops/activation`; the KV canary benchmark cases -> `sglang.test.kernels`.
- **Env vars:** the eight tombstones, `SGLANG_DISABLE_OUTLINES_DISK_CACHE` (only the dead module read it), a stale doc row and CI flag for a variable removed in #28755, a router image `ENV` the router never reads (and its `EXPOSE` now matches the default port).
- **A deprecated route client:** the remote-instance loader called `/get_remote_instance_transfer_engine_info` (deprecated since March), logging a warning per rank; it uses the new route.

## For the owners (not changed here)

- `--modelopt-quant` is documented but ignored: the loader tests `hasattr(model_config, "modelopt_quant")`, which `ModelConfig` never defines, so `--modelopt-quant fp8` alone serves the model unquantized.
- `--decoupled-spec-role` and the `--decoupled-spec-*` endpoints do nothing until #22520 lands.
- `sglang:func_latency_seconds` is registered and documented but nothing observes it.
- `/update_weights_from_disk` accepts `is_async`, `keep_pause` and `token_step` and ignores them; `min_dynamic_patch` and `max_tool_calls` are accepted and ignored.
- Penalizers restart from zero after a retract (their state is not seeded from `output_ids`).
- A failed checkpoint-engine post-processing step is logged and reported as success.
- DeepSeek-V4 Triton MoE on HIP without EP asserts on a switch that no longer exists.
- Deprecations warned with `DeprecationWarning`, hidden by default: `data_parallel_rank`, `MultiPlatformOp`, the parallel getters, `skip_attn_backend_init`, the `nsa` alias.
- The AOT `apply_shuffle_mul_sum` op has no caller (an `sgl_kernel` wheel API removal).
- Default-off fast paths the cookbook enables on one platform only, and kill switches of default-on paths with no doc or CI use, are listed in the audit for owners to decide; no defaults changed here.
- NPU dead code (sparse KV offload buffers, routed-stream helpers, write-only fields) and NPU tests that set variables nothing reads.
