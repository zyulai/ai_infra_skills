## Overview

Upgrade FlashInfer from `0.7.0.post1` to `0.7.1` for standard CUDA and Rubin builds. Explicitly select the CuTe DSL KDA prefill backend to avoid the inference-tensor crash observed in the B200 Kimi K3 CI job.

## Claims

- Update the shared `flashinfer-python` pin to `0.7.1`, retaining upstream's common `flashinfer download-kernels` installation flow for CUDA and Rubin.
- Keep KDA prefill on FlashInfer with inference mode enabled. No FlashInfer modifications, metadata copies, or test changes are required.

## Validation

On an allocated NVIDIA GB300 node with FlashInfer 0.7.1, PyTorch 2.13.0+cu130, and nvidia-cutlass-dsl 4.8.0, using an isolated checkout and the existing environment:

- Reproduced all three original KDA failures before the fix; all three passed afterward (prefill correctness, near-collinear keys, and cross-stream breakable CUDA graph).
- `pytest -v tests/models/kimi_k3 --ignore=tests/models/kimi_k3/test_prefix_cache.py tests/kernels/attention/test_kimi_k3_mla_fused_epilogue.py` — **260 passed, 154 skipped**. This is the B200 Kimi K3 CI test selection, executed on GB300. Tests used the environment's `.venv/bin/python -m pytest`.
- `.venv/bin/python -m pre_commit run --files requirements/cuda.txt vllm/models/kimi_k3/nvidia/kda.py` — passed after rebasing.
- `git diff --check` — passed.

GPU tests were run before the final rebase; the rebase did not change Kimi implementation or test files. B200 execution, full model accuracy evaluations, and standard/Rubin container builds have not been performed for this revision. The earlier MI250 EAGLE3 acceptance failure remains unresolved and should be reassessed in CI; it is not established to be an existing main failure.

## Details

FlashInfer's automatic small-BH prefill path caches packed sequence metadata using `cu_seqlens._version`. Inference tensors have no version counter, so this raises before kernel launch. Explicit `backend="cute-dsl"` avoids that path without changing PyTorch inference mode.

This bypasses the small-BH optimization. GB300 CUPTI microbenchmarks (BF16, D128, bounded gate, cold L2, eager GPU timing; median of three blocks of 20 samples) measured:

| Heads / tokens | FlashKDA (us) | FlashInfer auto (us) | Explicit CuTe DSL (us) |
| --- | ---: | ---: | ---: |
| 12 / 128 | 45.7 | 31.3 | 23.6 |
| 12 / 2,048 | 118.6 | 71.5 | 80.4 |
| 12 / 8,192 | 355.4 | 214.1 | 270.1 |
| 96 / 8,192 | 863.7 | 459.5 | 459.1 |

Auto was measured with ordinary metadata tensors to avoid the crash. Explicit CuTe DSL was faster than FlashKDA for these cases, but 12–26% slower than working auto selection for the two longer H12 cases. These are microbenchmarks, not end-to-end serving measurements. Output and final-state correctness were checked before timing.

Rebased onto upstream main `838526c7e5`. Upstream removed separate cubin/JIT-cache pins in favor of `flashinfer download-kernels`; this PR preserves that change. Rubin continues to use the shared FlashInfer pin.

The initial duplicate-work search found no other open PR implementing this version upgrade; this updates the existing PR rather than opening a duplicate. No associated issue. AI assistance (Codex) was used for implementation, investigation, and validation.
