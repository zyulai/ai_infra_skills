## Motivation

Root Cause

In pause_generation, after calling filter_batch on last_batch, merge_batch was called unconditionally — unlike get_next_batch_to_run which has an is_empty() guard.

When the extend last_batch has all requests finished:

* filter_batch sets last_batch.reqs = [] but returns early without updating tensors (seq_lens, req_pool_indices, output_ids, etc. still have M=1 element)
* merge_batch then torch.cats the stale M-element tensors into running_batch, yielding seq_lens.shape[0] = N+1 while len(reqs) = N
* The invariant len(reqs) == seq_lens.shape[0] is broken. The next filter_batch call in update_running_batch computes keep_indices
* from range(len(reqs))=range(N), finds len(keep_indices)==N==len(reqs), and early-returns again without fixing the tensor sizes.
* The extra slot then corrupts KV-cache allocations and surfaces as the shape mismatch in grouped_foreach_copy:

```
RuntimeError: The size of tensor a (652) must match the size of tensor b (651)
```

Fix

Added the same is_empty() guard that get_next_batch_to_run already uses (line 2149), replacing the unconditional merge_batch call with:

```
if not self.last_batch.is_empty():
if self.running_batch.is_empty():
self.running_batch = self.last_batch
else:
self.running_batch.merge_batch(self.last_batch)
```

same code has already existing in get_next_batch_to_run
