## Motivation

Depends on #46600 (the CUDA MoE noise fix, which fixes #46461). This PR will be rebased on it once it lands, so the fix commit below will drop out of the diff.

Changes for HunyuanImage-3 (the prefix K/V cache is the main one; the opt-in FA3 attention and the `cot_text` fix are described under Modifications):

1. **Fix: generation on CUDA produced a noise texture** (on main too). The MoE block ran the routed experts before the shared MLP. On CUDA the Triton `FusedMoE` path runs in place (`inplace=True` by default) and overwrites `hidden_states` with the expert output, so the shared MLP read the expert output instead of the layer input and every MoE layer was wrong. The NPU path (AscendTPDispatcher) is not in place, which is likely why the original NPU validation in #36311 did not see it; the cookbook also marks the CUDA recipe as unverified. srt's own Hunyuan model already runs the shared MLP first.
2. **Perf: cache the text prefix K/V across denoising steps.** HunyuanImage-3 recomputes the whole text prefix through every layer (attention and MoE) on every step, even though that prefix never changes. The proposal this implements:

> **P1. Prefix KV cache** (`hunyuan_image3.py`: `ImageKVCacheManager`, `forward_block`)
> The text prefix is causal and step-invariant. At `first_step`, keep the per-layer prefix K/V; on later steps feed only the image tokens as queries and attend to [cached prefix K/V, image K/V]. Replace the dense 4-D bool-mask SDPA with FA varlen (prefix causal + image full) or flex.
> Removes L_text/(L_text+L_img) of the MoE compute per step. Large for long or "think" prompts; also recovers FlashAttention.

This PR does the prefix K/V cache with the dense SDPA as the default, plus the FA varlen part as an opt-in (`--attention-backend fa3`), since FA3 is not bitwise equal to SDPA. The official model does the same caching at inference (later steps feed only the timestep and image tokens against a static KV cache).

## Modifications

**Fix (commit 2)**
- `hunyuan_image3.py`: `HunYuanSparseMoeBlock.forward` runs the shared MLP before the in-place experts.
- `pipelines/hunyuan_image3.py`: match the official `FlowMatchDiscreteScheduler` schedule, `shift(linspace(1, 0, N + 1))[:-1]` (`use_uniform_sigmas=True`). The old setup shifted the training-sigma range a second time; for 10 steps the last timestep was 8.93 instead of 250.

**Prefix K/V cache (commit 1)**
- `hunyuan_image3_utils.py`: `ImageKVCacheManager` stores each layer's prefix K/V on step 0, keyed by a cache slot, and on later steps prepends it to the suffix K/V. Adds `split_suffix_inputs` and `pad_prefix_rows`.
- `hunyuan_image3.py`: `forward_block` takes `prefix_len` and `cache_slot`. Step 0 runs the full sequence; later steps run only the suffix rows and pad the output back to full length, so callers see the same shape.
- `ar_stage.py`: computes the prefix once as the rows before the first noisy-image or timestep token, and returns no prefix (full compute) when a clean image block straddles that boundary. `first_step` is now `step_idx == 0` (it was always `True`, and nothing read it). CFG cond and uncond use separate cache slots, since they run as two backbone calls on the same modules.
- Falls back to the current path when CLA is on, when the cache-dit adapter drives the blocks, or when no safe prefix exists.

Why the cache is exact: the mask is causal, so every row before the first varying token only sees prompt and clean conditioning tokens. Clean conditioning images before the noisy block are cached too, so the saving is a bit larger than L_text/(L_text+L_img).

Memory cost of the cache: `bs x P x kv_heads x head_dim x 4 bytes` per layer per CFG slot. Measured 156 MB per GPU for a 1,248-token prefix with both CFG slots (exactly the formula); the reported peak is unchanged.

**Opt-in FA3 segment attention (`--attention-backend fa3`)**
- `hunyuan_image3_utils.py`: `build_attention_segments` splits the mask (causal text, bidirectional image blocks) into `(start, end, causal)` segments; `segmented_attention` runs one FA3 varlen call per segment with bottom-right causal alignment, for both full and cached-suffix steps. GQA is native, so no `repeat_kv`. Hopper only; elsewhere the masked SDPA path is kept.
- `ar_stage.py` / `pipelines/hunyuan_image3.py`: segments are built only when `attention_backend == "fa"` (what `fa3`/`fa4` resolve to). The default path is unchanged and still bitwise identical to main + fix.
- 2x H200: 22.6 s vs 26.8 s for the default path (1.55x vs main + fix). Not bitwise: PSNR 21-24 dB vs SDPA, same composition. On GPU the segments reproduce the attention mask exactly over 384 calls and FA3 vs SDPA differs by at most one bf16 ulp per call, so the drift is kernel rounding compounding over layers and steps. Details and images: https://github.com/sgl-project/sglang/pull/46454#issuecomment-6422227024

**Fix: `cot_text` from the image API**
- `configs/sample/hunyuan_image3.py`: declare `bot_task`, `system_prompt` and `cot_text` in `image_request_extra_fields`. The image endpoint only forwards declared fields, so think/recaption text was silently dropped. With it, think prompts are 1.32x to 1.50x faster than main + fix (the reasoning text lands in the cached prefix), outputs identical: https://github.com/sgl-project/sglang/pull/46454#issuecomment-6422648092

## How the noise bug was found

On 2x H200 TP2 with debug-only instrumentation (not in this PR):
- Checked the port line by line against the official `modeling_hunyuan_image_3.py` and `hunyuan_image_3_pipeline.py` shipped with the checkpoint. 2D RoPE, QKV split, QK norm order, SwiGLU half order, residual flow, UNetDown/UNetUp, timestep embedders, CFG, Euler step and VAE decode all match.
- Compared real decoder layers at step 0 against an fp32 reference transcribed from the official layer, with weights read straight from the checkpoint shards:

| layer | attention cos / rel err | MoE cos / rel err |
|---|---|---|
| 0 | 0.99999 / 0.004 | 0.738 / 0.94 |
| 1 | 0.99999 / 0.005 | 0.608 / 0.80 |
| 31 | 0.99999 / 0.003 | 0.166 / 1.02 |

- Inside the MoE everything feeding the kernel was correct: router logits matched exactly, top-k ids agreed 100%, and every expert `w13`/`w2` shard and the shared MLP weights matched the checkpoint slices. That left execution order, and `FusedMoE` turned out to be in place.

## Accuracy Tests

CPU unit tests in `test_hunyuan_image3_tp_broadcast.py`, all 11 in the file pass:
- Fix regressions: the shared MLP sees the layer input when the experts run in place; timesteps follow the official schedule. With only the two fixed source files reverted, exactly these two fail.
- Prefix cache: a cached suffix-only step matches full recompute; CFG slots do not overwrite each other; the prefix ends at the first varying token and is `None` when a clean image block straddles it.
- FA3 segments: segment attention equals masked SDPA for full and suffix-only steps; overlapping blocks fall back.
- Image API: `cot_text` and `bot_task` reach the sampling params.
