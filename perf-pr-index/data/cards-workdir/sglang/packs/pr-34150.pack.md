## Summary

- add Triton 3.7.1 BF16 fused-MoE configurations for `E=256`, `N=512` on NVIDIA H200
- tune the gate/up and down projections separately
- enable TMA for the down projection at the tuned `M=512` and `M=1024` tiers
- preserve the existing heuristic configuration at `M=256`

The target shape is used by LLaDA2.1-mini. Without these files, SGLang logs a missing-config warning and falls back to the generic Triton heuristic.

## Tuning methodology

These values were selected by measurement rather than copied or chosen manually.

- swept the existing heuristic plus 21 curated candidates at each `M=256`, `M=512`, and `M=1024` tier
- varied `BLOCK_SIZE_M/N/K`, `GROUP_SIZE_M`, warp count, and pipeline stages
- benchmarked gate/up and down projections independently while requiring the same `BLOCK_SIZE_M`
- measured both non-TMA and TMA down-projection paths
- used randomized top-k routing inputs, CUDA-graph warmup, and repeated kernel timing
- retested the selected pair through the complete fused-MoE runtime before serving tests

| Tier | Existing heuristic | Best swept pair | Latency change | Selected configuration |
|---|---:|---:|---:|---|
| `M=256` | 390.0 us | 386.9 us | -0.8% | Keep existing heuristic; the gain was too small |
| `M=512` | 545.5 us | 394.2 us | **-27.7%** | Up: `M32/N128/K128/G32/w8/s3`; down: `M32/N64/K128/G32/w4/s3 + TMA` |
| `M=1024` | 585.5 us | 409.6 us | **-30.0%** | Up: `M64/N64/K64/G1/w4/s3`; down: `M64/N128/K64/G1/w4/s3 + TMA` |

The complete runtime benchmark independently confirmed the `M=1024` selection at 650.1 us versus 448.3 us (**31.0% lower latency**).

This was a bounded denoise-focused sweep rather than an exhaustive search over every possible tile. No separate `M=8192` prefill sweep was performed; the 500-request 8K-prefill serving test below was neutral and confirmed that the nearest tuned profile did not regress that workload materially.

## Performance

Environment:

- one NVIDIA H200
- LLaDA2.1-mini, BF16, TP1/EP1
- JointThreshold + FDFO + vectorized decoding
- FlashInfer attention and Triton MoE
- concurrency 32, identical seeds and requests
- baseline first, server restarted between arms
- shape warmup and `/flush_cache` before every measurement

The full fused-MoE microbenchmark at `M=1024` improved from 650.1 us to 448.3 us (**31.0% lower latency**).

### 500-request serving tests

| Workload | Metric | Default | Tuned | Change |
|---|---|---:|---:|---:|
| 512 input / 512 output | Output throughput | 1,650.96 tok/s | 1,766.32 tok/s | **+7.0%** |
|  | Mean TPOT | 17.09 ms | 15.95 ms | **-6.7%** |
|  | P95 TPOT | 27.89 ms | 25.85 ms | **-7.3%** |
| 128 input / 2,048 output | Output throughput | 4,155.39 tok/s | 4,687.85 tok/s | **+12.8%** |
|  | Mean TPOT | 6.94 ms | 6.14 ms | **-11.5%** |
|  | P95 TPOT | 21.53 ms | 19.36 ms | **-10.1%** |
| 8,192 input / 128 output | Output throughput | 100.06 tok/s | 100.31 tok/s | +0.3% |
|  | Mean TPOT | 222.92 ms | 223.52 ms | +0.3% |
|  | P95 TPOT | 354.69 ms | 354.62 ms | ~0% |

The decode-heavy workload benefits most. The long-prefill workload is neutral, as expected when MoE denoising is not the dominant cost.

All six 500-request arms completed successfully, produced every requested output token, and reported no request errors. Server logs confirmed that the default arms used the fallback heuristic and the tuned arms loaded both new configuration files.
