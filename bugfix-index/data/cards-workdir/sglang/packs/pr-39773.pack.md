## 正文(PR 描述)

On Mistral3 models, `tool_choice: "auto"` never produces a tool call — the model emits one token, EOS, and returns empty content. `tool_choice: "required"` works, which makes it look like a tool-calling bug. It isn't: the prompt is corrupted for every request.

`_render_and_encode_chat_template` renders the chat template to a string and re-encodes it. mistral_common tokenizers emit control tokens that have no text form, so that round-trip destroys them. Comparing the server's prompt token ids against `apply_chat_template(tokenize=True)` for the same request:

```
server:   ['<s>', '<', 's', '>[', 'A', 'VAIL', 'ABLE', '_TO', 'OL', 'S', '][', ...]   103 tokens
template: ['<s>', '[AVAILABLE_TOOLS]', '[', ...]                                       82 tokens
```

`[AVAILABLE_TOOLS]` (control token id 5) comes back as the letters `A`,`VAIL`,`ABLE`,`_TO`,`OL`,`S`, and a second BOS is prepended. The model never sees the tool block as a control structure. transformers warns about exactly this: `MistralCommonBackend.apply_chat_template(..., tokenize=False)` is unsafe and may lead to unexpected behavior. Please consider using `tokenize=True` instead and don't encode the output manually.

The margin is thin, which is why it reads as arbitrary: the first sampled token is `</s>` at logprob -1.413 with ` [` right behind at -1.476. `required` hides it by constraining the output.

Every request takes the text path because `_engine_prompt` sends text whenever the model `is_multimodal`, and Mistral3 carries a `vision_config`.

This patch probes once at startup whether the render-then-encode round-trip reproduces `tokenize=True`, and when it does not, encodes straight to ids and sends those. Requests carrying media keep the text path, since the multimodal processor still has to tokenize it to expand placeholders.

Verified on Ministral-3-3B (same `Mistral3ForConditionalGeneration` class and tekken tokenizer as Mistral Medium 3.5):

| | before | after |
|---|---|---|
| `tool_choice: "auto"` | no tool call, 1 token generated | `get_weather{"location": "Paris, France"}` |
| prompt | 103 tokens, doubled BOS | 82 tokens, control tokens intact |
| plain chat, no tools | 21 tokens, reply began `<s>[EVAL]` | 12 tokens, clean reply |

The last row is the wider point: this degraded ordinary chat too, not only tool calls.

The probe discriminates correctly — Ministral-3-3B renders to 12 junk tokens against 4 correct ones (`<s>[INST]x[/INST]`) and is flagged lossy; Qwen3-0.6B round-trips to identical ids and keeps the existing path.
