## PR body
```markdown
## Purpose

Add support for DeepSeek-V4 AMD Quark mixed-quantized checkpoints, where different parts of the model may use different quantization layouts, including per-block FP8 linear layers and NVFP4 MoE experts.

This PR focuses on the Quark/DeepSeek-V4 model-side pieces needed to correctly identify and load these mixed-quantized checkpoints. It avoids changing generic weight-loading behavior and keeps DeepSeek-V4-specific mappings out of the base `QuarkConfig`.

## Main Changes

- Add a dedicated `QuarkW8A8Fp8PerBlock` scheme for Quark per-block FP8 weights.
  - Keeps the existing `QuarkW8A8Fp8` path focused on per-tensor/per-channel FP8.
  - Derives activation group size from `block_size[1]` instead of hardcoding it independently.
  - Requires per-block FP8 configs to provide `block_size`.

- Move DeepSeek-V4-specific fused module mappings to the DeepSeek-V4 AMD model path.
  - Handles mappings such as `gate_up_proj -> [w1, w3]` and `fused_wqa_wkv -> [wq_a, wkv]` without injecting architecture-specific knowledge into generic `QuarkConfig`.

- Add DeepSeek-V4 AMD checkpoint name handling for scale tensors.
  - Supports checkpoint/vLLM parameter naming differences needed by the mixed Quark layout.

- Align Quark NVFP4 MoE fused `w13` global-scale handling with existing NVFP4 MoE implementations.
  - When `w1/w3` global scales differ, warn and use the `w1` scale for fused `w13`, matching the existing ModelOpt and compressed-tensors NVFP4 MoE convention.
  - This avoids introducing a new `max(w1, w3)` scale-selection policy in this PR.

- Keep generic loader behavior unchanged.
  - The previous diagnostic/debug changes to `parameter.py` were reverted.
  - The PR no longer modifies generic weight-loader logic.

## Out of Scope

- This PR does not introduce a new generic NVFP4 scale-selection policy.
- This PR does not claim full E2E coverage for a future Quark-exported per-block FP8 checkpoint until such a checkpoint is available.
- Broader refactoring of shared NVFP4 MoE scale handling can be done in a separate follow-up PR.

## Test Plan

- Inspect DeepSeek-V4 checkpoint tensor shapes and quantization configs.
- Verify Quark quantization config routing for DeepSeek-V4 fused layers.
- Run lightweight Quark regression tests:

```bash

  -k "deepseek_v4_fused_mappings or preserves_existing_packed_modules_mapping or detects_per_block_config or rejects_per_block_static_input or per_block_requires_block_size"
```
