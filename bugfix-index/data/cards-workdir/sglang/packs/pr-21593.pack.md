## 正文(PR 描述)

## Summary

When a model-specific `--tool-call-parser` is configured (e.g. `kimi_k2`, `deepseekv3`, `qwen25`), `tool_choice="required"` previously:
1. Forced a **generic JSON schema** constraint that conflicted with the model's native tool call format (special tokens like `<|tool_calls_section_begin|>`)
2. Tried to parse the model output as **plain JSON**, which failed for models using special token formats, resulting in `tool_calls: null`

### Changes

**Constrained decoding (`function_call_parser.py`):**
- For `required`/named `tool_choice`: use `structural_tag` constraint with `at_least_one=True`, forcing the grammar to produce at least one tool call from the first token (no free text). Schema is included when `strict=true`, empty when `strict=false` per OpenAI protocol
- For `auto`: behavior unchanged (uses `triggered_tags` with `at_least_one=False`, allowing free text until trigger)

**Grammar backend (`xgrammar_backend.py`):**
- Pass `at_least_one` from legacy structural_tag format to xgrammar's new `StructuralTag` API, enabling forced tool call generation for `required` mode

**Protocol (`protocol.py`):**
- Add `at_least_one: bool = False` field to `LegacyStructuralTagResponseFormat`

**Response parsing (`serving_chat.py`):**
- Non-streaming: check `supports_structural_tag()` before using native parser for `required` mode, mirroring the streaming path logic
- Fall back to JSON array parsing for `required` when detector doesn't support structural_tag

**Streaming fix (`base_format_detector.py`):**
- Fix `if cur_arguments:` to `if cur_arguments is not None:` -- empty dict `{}` is falsy in Python, causing streaming tool calls with unconstrained schemas to produce empty argument strings

**DeepSeekV3 fix (`deepseekv3_detector.py`):**
- Fix `structure_info()` to include full format prefix with wrapping special tokens, so the streaming parser can recognize tool calls

**Test updates (`test_tool_choice.py`):**
- `test_complex_parameters_required_non_streaming`: add `strict=True` since the test asserts specific parameter contents
- `test_required_streaming_arguments_chunks_json`: add `strict=True` since the test asserts arguments are a dict

### Behavior matrix

| tool_choice | strict | supports_structural_tag | Constraint | Grammar mode | Parameters |
|---|---|---|---|---|---|
| `required` | `true` | Yes | structural_tag + schema | `at_least_one=True` | Schema-enforced |
| `required` | `false` | Yes | structural_tag + `{}` | `at_least_one=True` | Best-effort |
| `required` | any | No | json_schema | N/A | Schema included |
| `auto` | `true` | Yes | structural_tag + schema | `at_least_one=False` | Schema-enforced |
| `auto` | `false` | any | None | N/A | Best-effort |

### OpenAI protocol compliance

Per [OpenAI docs](https://platform.openai.com/docs/guides/function-calling):
- `tool_choice="required"`: model **must** call a tool (enforced via `at_least_one=True` in grammar)
- `strict: true`: arguments **must** match schema via constrained decoding
- `strict: false` (default): schema is best-effort guidance only, no parameter constraint

These are orthogonal controls. This PR respects that separation.

### Affected models
All models with native tool call formats: kimi_k2, deepseekv3, deepseekv31, deepseekv32, qwen25, llama3, mistral, hermes, trinity, interns1, qwen, etc.
