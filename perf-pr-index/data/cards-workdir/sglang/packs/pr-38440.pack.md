## PR body
```markdown
## Motivation

DSpark on the Ascend DSV4 backend currently falls back to a uniform verify window or eager-side post-processing for parts of speculative decoding. This leaves two sources of avoidable overhead:

1. the target model verifies the full draft window even when the SPS policy selects a shorter per-request verify length;
2. accept/finalize and hidden/KV commit remain outside the target verify graph.

This PR enables the compact DSpark path on NPU, adds token-tiered graph replay for ragged target verify, and folds the eligible verify epilogue into the graph.

## Modifications

### 1. DSpark compact verify on NPU

- Build packed/ragged verify windows from per-request verify lengths selected by the DSpark planner.
- Add NPU-safe compact row mapping, verify-ID gathering, cache-location handling, and compact-to-strided scatter.
- Construct DSV4 SWA, sparse-attention, C4/C128 compressor, position, state, and page-table metadata from the live compact layout.
- Preserve eager fallback when the selected attention backend does not support ragged verify graphs.

### 2. Compact target-verify graph

- Advertise ragged verify graph support for the DSV4 Ascend backend.
- Select target-verify graphs by compact token tier while retaining fixed graph-owned buffers.
- Refresh query indptr, sequence lengths, cache/page tables, compressor locations/state, and sparse indices before replay.
- Add an NPU-local bucketed-layout cache so the Ascend and DSV4 metadata consumers reuse the same derived layout.
- Use the safe last-location Triton path for DSV4 NPU allocation metadata.

### 3. Verify epilogue graph

- Add a DSV4 NPU-specific target-verify tail hook that uses the committed/live prefix lengths from DSV4 metadata.
- Fold greedy accept/finalize and eligible hidden/KV commit into the compact target-verify graph.
- Keep sampling, grammar-constrained decoding, logits adjustments, and other ineligible cases on the existing eager epilogue path.
- Keep the adaptation NPU/DSV4-specific so the existing CUDA behavior remains unchanged.

## Accuracy Tests

- GPQA-Diamond accuracy: **0.91** with DSpark on Ascend NPU.
- The compact path preserves the target-model verification result; it changes the number of draft tokens verified and where graph-safe post-processing executes.

## Speed Tests and Profiling
The expected gain comes from reducing target-verify tokens according to the SPS-selected compact lengths and removing eligible verify epilogue launches from the host path.
| Metric | Compact | Static | Delta |
|--------|---------|--------|-------|
| Output throughput (tok/s) | 2027.13 | 1949.98 | Compact +4.0% |
| Mean TPOT (ms) | 20.87 | 26.27 | Compact -20.6% |
| Mean TTFT (ms) | 36563.48 | 38385.26 | Compact -4.7% |
