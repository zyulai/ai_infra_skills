## Overview

DeepSeek-V4.1-Flash served as DP8 attention + EP8 MoE (TP1 dense linears) on 8x MI355X runs its 32x32 block-scaled MXFP8 linears on the Triton block32 GEMM. That GEMM has no TP1 tuning (`_default_config`) and reaches 21-31% of MXFP8 peak. On gfx950 with AITER enabled, this PR runs those linears and the grouped `wo_a` BMM on AITER's FlyDSL GEMMs, which AITER picks per M from its tuned tables. It also makes the MXFP8 activation quant about 2x faster, with bit-identical output.

## Claims

- **End to end** (InferenceX aiperf agentic, CONC=256, DSpark 5 tokens): **throughput_per_chip 26,714 tok/s/GPU, P90 interactivity 4.61 tok/s/user**. Both are within run-to-run noise of the previous revision of this PR on the same node (27,385 / 4.60), which measured +11.1% / +10.9% over main.
- **Dense GEMMs offline**, weighted by the calls per engine step of the profiled run: **prefill 189.8 -> 106.7 ms per step (1.78x)**, **decode 4544 -> 2822 us per step (1.61x)**.
- **MXFP8 activation quant**: 357 -> 172 us at M = 32768, K = 8192.
- **No extra memory**: weights are preshuffled in place, so the model stays at 52.1 GiB per GPU.
- **Accuracy unchanged**: GSM8K 0.9735 (main) vs 0.9727 (this PR), strict-match, ±0.0045.

## What changes

- **`RocmDotScaledMxfp8LinearKernel`**: a layer qualifies when AITER linear is on, the GPU is gfx950, the model is bf16, the weight has 32x32 scale blocks with K % 64 == 0, and AITER has tuned 32x32 rows for its shape (`rocm_aiter_ops.is_mxfp8_block32_bpreshuffle_gemm_tuned`). Such a layer is (16, 16)-preshuffled in place at load and exposed as `layer.weight_preshuffled`.
- **`rocm_mxfp8_block32_gemm(_quant)`**: given `weight_preshuffled`, calls AITER's `gemm_a8w8_blockscale_bpreshuffle`. The FlyDSL kernels use 32-bit offsets, so rows run in 2 GiB chunks. Without it, the existing Triton paths are unchanged.
- **`rocm_dsv41_mxfp8_wo_a_bmm`**: given `weight_preshuffled`, calls AITER's `batched_gemm_a8w8_mxscale_bpreshuffle`.
- **Mono decode (gfx950)** reads the dense linears row-major. When it is selected, it marks the linears it reads with `keep_row_major_weight`; those keep their weight and get a preshuffled copy.
- **`_mxfp8_quant_triton_kernel`**: each program handles a [4, 512] tile instead of one [64, 32] block. The arithmetic is unchanged.
- **Unchanged paths**: every other layer and configuration — 1x32-scaled models, untuned shapes, non-gfx950 including gfx1250, AITER off, and `VLLM_BATCH_INVARIANT`.
