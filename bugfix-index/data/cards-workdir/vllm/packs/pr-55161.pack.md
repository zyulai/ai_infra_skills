## 正文(PR 描述)

## Purpose

Fixes #55158.

`LoRAConfig` accepts `max_lora_rank` values above 128, but the non-fully-sharded
MoE LoRA dispatch unconditionally selected the one-shot Triton kernel, whose
rank dimension is limited to 128. This caused engine initialization to fail
during CUDA graph warm-up even when the loaded adapter's actual rank was only
4, because the MoE LoRA buffers are padded to the configured maximum rank.

This change:

- keeps ranks up to 128 on the existing one-shot fast path;
- routes larger ranks to the existing two-kernel shrink/expand path;
- lets that fallback preserve the existing `add_inputs=False` contract used by
  dual-stream and other MoE LoRA callers; and
- retains the one-shot assertion as a defensive kernel-local guard.

Rank tiling could extend the one-shot kernel in the future, but the existing
fallback is a smaller correctness-first fix and avoids changing the kernel's
register-pressure/performance characteristics.

## Duplicate check

No exact open issue or fix PR was found after searching for the assertion text,
function name, `max_lora_rank=256`, and MoE LoRA rank fallback. PR #42290's
review did identify both the missing rank fallback and the dual-stream risk,
but those comments were not addressed before merge and current main still has
the mismatch. Related issues and PRs are listed in #55158.

The targeted numerical test compares the Triton result with a PyTorch
reference across:

- rank 128 (one-shot boundary) and 256 (fallback);
- `add_inputs=True` and `False`; and
- one and two LoRA slices, covering both TMA descriptor layouts on supported
  GPUs.

An end-to-end check starts the public Nemotron MoE model from #55158 with
`--max-lora-rank 256` and verifies that CUDA graph warm-up completes and a LoRA
request returns HTTP 200.

- Ruff format: passed.
- Ruff lint: passed.
- Python syntax and custom-op real/fake signature checks: passed.
- Targeted numerical test on an NVIDIA A100-SXM4-80GB: passed
  (`8 passed, 417 deselected`). This covers rank 128/256,
  `add_inputs=True/False`, and one/two LoRA slices.
- End-to-end test on 2x NVIDIA A100-SXM4-80GB with TP=2: passed. At commit
  `29a6af589`, the public Nemotron MoE model and rank-4 dummy adapter started
  with `--max-lora-rank 256`; both PIECEWISE and FULL CUDA graph capture
  completed, `/health` returned HTTP 200, and a request to the `dummy` LoRA
  model returned HTTP 200.

GPU test environment: PyTorch 2.13.0+cu130, CUDA runtime 13.0, compute
capability 8.0.
