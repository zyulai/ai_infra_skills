## PR body
```markdown
## Summary
- Set `Wan2_2_T2V_A14B_Config.dit_config.torch_compile_mode` to `default`.
- This follows the same compile-mode finding as #28050, but applies it to Wan2.2 T2V A14B.
- The change is validated on both H100 and B200 with clean torch compile caches.

## Benchmark
Clean-cache rerun with the diffusion benchmark/profile runner:

```bash
PYTHONPATH=python python3 python/sglang/multimodal_gen/.claude/skills/sglang-diffusion-benchmark-profile/scripts/bench_diffusion_denoise.py --model wan-t2v --label <label> --output-dir <dir>
```

For each compile mode I used fresh `TORCHINDUCTOR_CACHE_DIR`, `TRITON_CACHE_DIR`, and `CUDA_CACHE_PATH`. The runs stayed on the native SGLang diffusion path; the logs do not contain `Falling back to diffusers backend`, `Using diffusers backend`, or `Loaded diffusers pipeline`.

H100, 4 GPUs, benchmark preset:

| compile mode | denoise | e2e | peak memory |
| --- | ---: | ---: | ---: |
| `max-autotune-no-cudagraphs` | 217.8232s | 220.6501s | 15.23 GB |
| `default` | 206.0693s | 208.8785s | 14.00 GB |

`default` is +5.70% faster on denoise and +5.64% faster end-to-end.

B200, 4 GPUs, benchmark preset, clean-cache rerun:

| compile mode | denoise | e2e | peak memory |
| --- | ---: | ---: | ---: |
| `max-autotune-no-cudagraphs` | 110.3138s | 112.8339s | 19.04 GB |
| `default` | 105.0979s | 107.5709s | 18.00 GB |

`default` is +4.96% faster on denoise and +4.89% faster end-to-end on B200.
