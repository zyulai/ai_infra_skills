## Motivation

<!-- Describe the purpose and goals of this pull request. -->

With `--enable-decoder-swa-bounded-replay`, DeepSeek-V4.1's decoder layers only process the last 128 prompt tokens of each request during prefill. Layer 20 (the first decoder layer) still has to write the KV cache for every token, but it does not need to run the indexer, attention, and MoE on all of them. Currently, The amd code path still runs all of layer 20 on every token.

Nv enabled the skip in #42901. Amd was left out because its fused layer path runs the whole layer 20 in one call, so the KV write could not be split from the rest of the layer.

This PR enables it on amd. Layer 20 writes the KV cache for every token first, then runs the rest of the layer on the last 128 tokens only.

## Modifications

<!-- Detail the changes made in this pull request. -->

No change on nv. All changes are in `deepseek_v4_backend_hip_radix.py` or under `_is_hip`.

- **`deepseek_v4.py`**
  - Set `tail_writes_source_kv` to `True` on amd, so the tail starts at layer 20 instead of layer 21.
  - Get layer 20's input for the KV write from `fused_boundary_attn_input`.
- **`deepseek_v4_platform_stage.py`**
  - The fused boundary delays each layer's mHC post to the start of the next layer, so it has not run yet when layer 20 starts.
  - Add `fused_boundary_attn_input`, which runs that pending mHC post and builds layer 20's attention input for every token.
- **`deepseek_v4_backend_hip_radix.py`**
  - Reuse `DeepseekV4AttnBackend.write_tail_source_kv` to write layer 20's KV cache for every token.
  - Layer 20 now runs its indexer on the last 128 tokens only, and writes data straight into the tail buffers.
  - Remove the code that copied these results out of the full-token buffers, since it is no longer needed.
