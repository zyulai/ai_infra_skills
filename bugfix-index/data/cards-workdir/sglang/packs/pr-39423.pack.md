## 正文(PR 描述)

## Motivation

#36472 introduced the in-tree `NPUSRTPlatform` and made NPU machines resolve to it instead of the base `SRTPlatform`. Unlike the base default (`is_pin_memory_available=False`), the new class returns `True`, silently switching hot paths such as the next-token-logits copies and the xgrammar bitmask allocation to pinned memory with `non_blocking` H2D copies.

torch_npu's pinned-memory + async-copy semantics are not verified against CANN on this stack. The correctness of `non_blocking` H2D depends on a stream-ordering guarantee that has not been established for NPU, and under DP attention — where compute, copy, and HCCL communication streams run concurrently — inference intermittently hangs (deadlock) with DeepSeek-V2.

Two independent reproductions confirm this:

- The #36472 author observed DeepSeek-V2 hanging during normal DP-attention inference with pin_memory enabled.
- We reproduced the same hang on Ascend 910C under DP-attention retraction stress (`TestDPRetract`, i.e. `SGLANG_TEST_RETRACT=1` + a small KV budget).

Both hang and disappear with `is_pin_memory_available=False`. Since the per-step benefit of pinning is limited to KB-scale decode-path buffers, disabling it is the safe choice until the async-copy stream semantics are validated.

## Modifications

- `python/sglang/srt/platforms/npu.py`: force `is_pin_memory_available` to return `False`, restoring the pre-#36472 behavior. Re-enable only after the pinned-memory async-copy semantics are validated against CANN (optionally behind a debug env var first).
- `test/registered/unit/platforms/test_platform_interface.py`: align the NPU pin-memory unit test with the restored behavior.

## Accuracy Tests

Reran the `TestDPRetract` stress repro (DP attention + 4500-token KV budget + radix retract stress + regex/JSON constrained generation) multiple times on NPU: all passed with this change, while the server previously hung intermittently during DP-attention inference.
