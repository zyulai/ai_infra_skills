## 正文(PR 描述)

## Purpose

Fix layerwise reload corrupting non-persistent buffers that alias checkpoint-loaded
parameters.

Layerwise reload records a module's parameters and buffers before restoring the
module to meta tensors, then materializes and copies processed tensors back into
the original kernel tensor storage. That is correct for independent buffers, but
it is unsafe for non-persistent buffers that are only views/aliases of model
parameters.

This already affects same-module aliases, and it also affects a more realistic
Mamba/Nemotron shape:

- `MambaMixer2` registers `conv_weights` as a non-persistent buffer.
- `conv_weights` aliases the child parameter `conv1d.weight`.
- `MambaMixer2` also owns direct parameters such as `A`, `D`, and `dt_bias`.
- During reload, the parent `MambaMixer2` can be materialized/finalized for
  those direct parameters.
- If `conv_weights` is captured as an independent buffer, the materialized
  buffer can be copied back into the original buffer storage.
- Because that buffer storage aliases `conv1d.weight`, this can overwrite the
  child conv weight after it was loaded.

The first important boundary is metadata capture: the alias check must look
through `layer.parameters(recurse=True)`, not only `layer._parameters`, so
non-persistent buffers aliasing parameters anywhere in the layer subtree are
excluded from layerwise restore metadata.

There is a second boundary during copy-back. `initialize_layerwise_reload` saves
the original kernel tensors before the module is restored on meta tensors. Those
saved kernel tensors still include the original alias buffer so it can be
re-registered later. But after metadata capture intentionally omits the alias
buffer, the temporary materialized layer does not have that buffer anymore. The
copy-back path must therefore skip only the omitted alias-buffer case instead of
blindly calling `getattr(layer, name)`.

## Changes

- Skip non-persistent buffers that share storage with any parameter in the
  current module subtree during layerwise reload metadata capture. Parameter
  storage pointers are precomputed once per layer to avoid rescanning the
  subtree for each buffer.
- During copy-back, skip original kernel buffers that are absent from the
  materialized layer. This preserves omitted alias buffers for re-registration
  without copying from a missing or independently-materialized temporary buffer.
- Add a direct same-module alias regression test.
- Add a parent-buffer/child-parameter alias regression test matching the
  `MambaMixer2.conv_weights -> MambaMixer2.conv1d.weight` pattern.

## Production context

We hit this while debugging NaN generations after repeated checkpoint-format
weight reloads for `nvidia/NVIDIA-Nemotron-3-Super-120B-A12B-BF16`.

Out-of-tree instrumentation in a production-style 5-node PrimeRL run confirmed
the relevant alias shape in live vLLM workers:

- `layer_class=MambaMixer2`
- `buffer_name=conv_weights`
- `non_persistent=true`
- `alias_matches=[conv1d.weight]`
- `direct_param_names=["A", "D", "dt_bias"]`

Across the 8 TP workers in that run, the recursive guard detected and skipped
320 `MambaMixer2.conv_weights` buffers. The old direct-parameter-only check would
not detect this parent-buffer/child-parameter alias.
