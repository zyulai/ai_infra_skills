## Summary

- bump `flashinfer_python`, `flashinfer-cubin`, and the optional JIT cache from 0.7.0.post1 to 0.7.1 ([release notes](https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.7.1))
- point `scripts/release/bump_flashinfer_version.py` at the files that actually carry the pin: add `docker/Dockerfile.cu134` (bumped by hand last time) and drop `python/sglang/srt/utils/common.py`, whose versioned docstring example was removed in #40709 and which made the script fail validation
- drop the SM120 Sage source-install step from the SubBlock sparse attention README: 0.7.1 contains flashinfer-ai/flashinfer#4691, so the default install now has `bsa_attn_sm120_blk64_sage_fwd` and `quantize_sage_qkv_sm120`

## Compatibility

None of the APIs called out in the 0.7.1 upgrade notices are used in sglang (`cute_dsl_fused_moe_bf16`, `CuteDslBf16MoEWrapper`, `moe_a2a_dispatch`, FlashInfer's `fp8/fp4_paged_mqa_logits`, the removed PrimTS decode entry points). The new dependency floors are already met by our pins (`nvidia-cutlass-dsl[cu13]==4.8.0`, `apache-tvm-ffi==0.1.11`, `cuda-tile==1.6.0rc5`); `nvidia-cudnn-frontend>=1.30.0` resolves transitively to 1.31.0.

## Validation

- `bump_flashinfer_version.py 0.7.1` updates and validates all 4 pin files
- `uv pip compile python/pyproject.toml` (py3.12, x86_64, cu130 torch index) resolves to `flashinfer-python==0.7.1`
- `flashinfer-cubin==0.7.1` and `flashinfer-jit-cache==0.7.1` (cu129 and cu130, x86_64 and aarch64) are published on flashinfer.ai/whl
- the 0.7.1 wheel contains `flashinfer/cute_dsl/sparse/bsa_attn_sm120.py` and `bsa_utils/sage_quant_sm120.py` with the two symbols imported by `subblock_sparse_attn.py`
- repository pre-commit hooks

GPU model E2E tests were not run locally; relying on CI.
