## 正文(PR 描述)

## Overview

`MooncakeConnector` does not opt into `supports_divergent_local_hybrid_hits` (#50344), so a hybrid-model decode (attention plus Mamba, GDN or KDA) drops its local attention hit and pulls the whole prompt from P every turn. This opts the `kv_consumer` role in, as MoRIIO READ and NIXL already do.

## Claims

- On a hybrid model, a Mooncake decode keeps its local attention prefix and pulls only the uncached suffix plus the recurrent state.
- `kv_producer` and `kv_both` keep the current lookup.

## Validation

- Kimi-K3 1P1D on MI355X, Mooncake RDMA, multi-turn agentic replay at concurrency 48: decode local prefix hit rate 0.0% to 93.9%; draft acceptance 58.78% to 58.79% (MoRIIO READ 58.79%).
- The new scheduler test fails on main and passes here. Mooncake unit tests: 164 passed. pre-commit clean.

<details><summary>Request flow, test output and serving numbers</summary>

Turn k of a session whose prompt extends turn k-1:

1. The router sends the request to P with `do_remote_decode`; P prefills and pushes KV.
2. On D, the attention blocks pulled in turn k-1 are still cached. Mamba has no state at any block boundary, since D never computes those positions.
3. Before: `get_computed_blocks` returns the hit every group shares, 0 tokens. Mooncake asks for N-1 tokens and pulls every attention block plus the state slot.
4. After: `get_computed_blocks_for_connector` returns the attention hit H. Mooncake asks for N-1-H tokens and pulls the suffix blocks plus the state slot; P pairs the last blocks of each group.
5. D decodes from the recurrent state P computed at N-1.

## Details

A decode never computes the block boundaries of a pulled prompt, so it caches attention blocks but no recurrent state. With the opt-in, the scheduler keeps the attention hit, and `update_state_after_alloc` already pulls every transfer group's unhashed blocks, the state slot included. With nothing to pull, the scheduler falls back to the reconciled lookup (#50344).

Only `kv_consumer` opts in: the per-group lookup reports a shared-prefix boundary of 0, which would disable junction checkpoints on roles that prefill locally.

Limitations:
- Serving runs used vLLM 81198e97 with this property forced to True on the decode, matching this PR; not re-run on main.
- Under `MultiConnector` every child must opt in until #63041.
- TTFT did not change on this workload.

Not a duplicate: the open Mooncake PRs (#53730, #63420, #63425) do not touch this property. AI assistance (Claude in Cursor) was used to write the change, the test and this description.
