## Purpose

With k draft tokens, each decode request verifies k + 1 query tokens. On `ROCM_AITER_FA` these batches go through AITER `unified_attention`, which dominates the decode step at long context; plain decode (`paged_attention_v1`) also waits for the longest request. This PR adds a FlyDSL split-KV kernel for layers with head size 64 and 8 query heads per KV head, on gfx950 with an FP8 KV cache, for plain decode and 1-7 draft tokens:

- full-attention layers: a length-balanced grid, so time tracks total KV rather than the longest request while there are well under two requests per CU (each request takes at least one workgroup); the metadata builder maps the work once per step;
- sliding-window layers: the window mask with equal splits per request.

The kernel is adapted from sgl-project/sglang#47371. Any other batch, layer or model keeps the existing path.

## Notes

- **Gate.** Head size 64, GQA 8, at most 16 KV heads per rank, no sinks / soft cap / ALiBi, FP8 e4m3 KV (default layout), gfx950, the same q_len (1-8) for every decode request (host metadata), and for full attention fewer than two requests per CU. Sliding-window layers on the kernel need no window-trimmed block tables, so the builder skips them. Among common checkpoints this matches Muse Spark (and TinyLlama-1.1B); gpt-oss has the shape but uses sinks.
- **Draft model.** Draft layers with the same shape take the kernel too. Muse Spark's five DSpark layers are sliding-window layers with 7 query tokens per request, so they run the sliding-window kernel; with no full-attention layer the drafter builds no work map.
- **Block size.** The kernel reads 16- or 32-token kernel blocks, so it works with the default block size and changes nothing about the KV cache.
- **Dependency.** FlyDSL, through its public API and vLLM's FlyDSL helpers; without it the existing path is used, with a warning. Tested with flydsl 0.4.2 and aiter 0.1.28.post1; aiter v0.1.29, which vLLM's ROCm image pins, requires the same flydsl 0.4.2.
- **Compilation.** One FlyDSL compile per q_len, page size and grid: two full-attention grids (one or two workgroups per CU, switching at 24 requests, or at 3 with two or fewer KV heads per rank) and one sliding-window grid. The Triton map and reduce kernels specialize on the request count's power-of-two bucket and the split count. CUDA-graph capture compiles the variants of the captured sizes; any other, such as an eager batch above the largest captured size, compiles once while serving and is cached on disk.
- **Follow-ups.** Other ROCm backends.
- **Related.** The drafts #66741 / #66743 (@sawsa307) also target verify; they are stacked on #66741, which needs an AITER change not yet released. On identical inputs (TEP4 shapes, 1-128 requests at 100k), this PR's full-attention verify took 1.2-1.5x less time than #66743's at q_len 8 (1.3-1.6x at q_len 4). Their ideas this PR doesn't cover (e.g. ragged q_len batches) are complementary and can follow on top once a suitable AITER is integrated into vLLM.

+def graph_replay_time_us(fns, iters: int = 20) -> float:
+    """Median time of one captured graph that runs every `fns` entry once, per
+    entry, in microseconds."""
+    stream = torch.cuda.Stream()
+    stream.wait_stream(torch.cuda.current_stream())
+    with torch.cuda.stream(stream):
+        for fn in fns:
+            fn()
+    torch.cuda.current_stream().wait_stream(stream)
+    graph = torch.cuda.CUDAGraph()
+    with torch.cuda.graph(graph):
+        for fn in fns:
+            fn()
+    for _ in range(3):
+        graph.replay()
+    times = []
+    for _ in range(iters):
+        start = torch.cuda.Event(enable_timing=True)
+        end = torch.cuda.Event(enable_timing=True)
+        start.record()
+        graph.replay()
+        end.record()
+        end.synchronize()
+        times.append(start.elapsed_time(end) * 1e3 / len(fns))
+    return sorted(times)[len(times) // 2]

+def _reference(q, k, v, lens, table, heads, kv_heads, window, scale, ql):
+    out = torch.zeros(q.shape, dtype=torch.float32, device=q.device)
+    group, page = heads // kv_heads, k.shape[1]
+    for i, n in enumerate(lens):
+        if n == 0:
+            continue
+        pages = table[i, : (n + page - 1) // page].long()
+        kk = k[pages].float().reshape(-1, kv_heads, HD)[:n] * K_SCALE
+        vv = v[pages].float().reshape(-1, kv_heads, HD)[:n].nan_to_num()
+        qq = q[i * ql : (i + 1) * ql].float()
+        s = torch.einsum("thd,lhd->htl", qq, kk.repeat_interleave(group, dim=1)) * scale
+        pos = torch.arange(n, device=q.device)
+        qpos = n - ql + torch.arange(ql, device=q.device)
+        hidden = pos[None, None, :] > qpos[None, :, None]
+        if window > 0:
+            hidden |= qpos[None, :, None] - pos[None, None, :] >= window
+        p = torch.softmax(s.masked_fill(hidden, float("-inf")), dim=-1)
+        out[i * ql : (i + 1) * ql] = torch.einsum(
+            "htl,lhd->thd", p, vv.repeat_interleave(group, dim=1)
+        )
+    return out * V_SCALE

+@dataclass
+class _Case:

+    k: torch.Tensor
+    v: torch.Tensor

+def _make_case(
+    lens,
+    heads,
+    kv_heads,
+    window,
+    ql=QL,
+    num_pages=None,
+    seed=0,
+    page=PAGES[0],
+    pin_last_page=False,
+) -> _Case:
+    device = "cuda"
+    gen = torch.Generator(device=device).manual_seed(seed)
+    total = sum((n + page - 1) // page for n in lens)
+    num_pages = num_pages or max(2 * total, 64)
+    pool, k, v = _cache(num_pages, kv_heads, device, page)
+    perm = torch.randperm(num_pages - 1, device=device, generator=gen)[:total]
+    if pin_last_page:
+        perm[0] = num_pages - 1
+    width = max(1, max((n + page - 1) // page for n in lens))
+    table = torch.zeros((len(lens), width), dtype=torch.int32, device=device)
+    offset = 0
+    for i, n in enumerate(lens):
+        pages = (n + page - 1) // page
+        table[i, :pages] = perm[offset : offset + pages].to(torch.int32)
+        offset += pages
+    _fill(pool, perm, gen)
+    # Stale bytes past each request's last token (NaN encodings) must not leak in.
+    for i, n in enumerate(lens):
+        if n % page:
+            last = table[i, n // page].long()
+            k[last, n % page :] = float("nan")
+            v[last, n % page :] = float("nan")
+    q = (torch.randn((len(lens) * ql, heads, HD), device=device, generator=gen) * 2).to(
+        torch.bfloat16
+    )
+    meta = _Meta(
+        query_start_loc=torch.arange(len(lens) + 1, device=device, dtype=torch.int32)
+        * ql,
+        seq_lens=torch.tensor(lens, dtype=torch.int32, device=device),
+        block_table=table,
+    )
+    layer = _Layer(
+        torch.tensor(K_SCALE, device=device), torch.tensor(V_SCALE, device=device)
+    )
+    out = torch.full(q.shape, float("nan"), dtype=torch.bfloat16, device=device)
+    return _Case(q, k, v, out, meta, layer, heads, kv_heads, window, ql)

+def _rel_l2(got: torch.Tensor, ref: torch.Tensor) -> float:
+    return ((got.float() - ref.float()).norm() / ref.float().norm()).item()
+
+
+def _check(out: torch.Tensor, ref: torch.Tensor, lens, ql: int) -> None:
+    live = torch.tensor([n > 0 for n in lens for _ in range(ql)], device=out.device)
+    got = out.float()
+    assert torch.isfinite(got).all()
+    # Zero-length requests (CUDA-graph padding) are written as zeros.
+    assert (got[~live] == 0).all()
+    rel_l2 = _rel_l2(got[live], ref[live])
+    assert rel_l2 < 5e-3, f"relative L2 error {rel_l2:.2e}"
