## PR body
```markdown
## Purpose

Conformer relative attention currently materializes the content scores, adds
the shifted positional scores, and then launches a separate in-place scale.
This PR uses standard `torch.baddbmm` to accumulate the scaled content scores
directly into the scaled positional scores:

```text
before: {bmm: 2, add: 1, mul_: 1}
after:  {bmm: 1, baddbmm: 1}
```

This removes one score-sized intermediate and the separate add/scale kernels.
It keeps one portable PyTorch path with no custom kernel, architecture gate,
device branch, or device-specific tuning.

Across all 120 CUDA Graph rows, the geometric-mean speedup was approximately
1.11x; the median was 1.09x and the observed minimum was 1.03x. All 240
eager/CUDA Graph rows passed numerical validation with zero OOM rows and zero
harness-reported allocation regressions.

The non-contiguous Q/K operands require the same two reshape copies in both the
old `matmul` path and the new path. The measured allocation reduction comes
from removing the additional score-sized add result. FP16/BF16 changed-input
CUDA Graph replay and a focused `torch.compile(fullgraph=True)` smoke check also
passed.

The standalone harness, raw CSV, and gate output are available in the

## Limitations

Conformer throughput. No performance claim is made for other architectures or
backends. Full upstream cross-backend CI still requires a maintainer `ready` or
`verified` label. The positional tensor uses batch `B` in the performance
harness; the real-module regression test separately covers production batch-1
broadcasting.
