## 正文(PR 描述)

An AbortReq echoed back from the scheduler can race the request's normal completion in the TokenizerManager handle_loop: a batch output may have already finished the request and deleted its rid_to_state entry before the abort echo is processed. Indexing rid_to_state directly then raises KeyError, which propagates out of handle_loop and is treated as fatal (the process is killed), taking down the whole server over a benign race.

This is common under mass client disconnects, and is amplified by the scheduler matching rids by prefix / abort_all, which fans a single abort out into many echoed AbortReqs.

Use dict.get() and return early when the state is already gone — there is nothing left to abort since the completion path already resolved the request.
