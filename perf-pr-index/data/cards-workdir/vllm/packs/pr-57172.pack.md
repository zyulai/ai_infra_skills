## PR body
```markdown
## Purpose

  vllm-xpu-kernels exposes fused SYCL kernels for standard (non-RMS) LayerNorm ([vllm-xpu-kernels#577](https://github.com/vllm-project/vllm-xpu-kernels/pull/577)) - `layer_norm`, `fused_add_layer_norm`, `nemotron_layer_norm`, `fused_add_nemotron_layer_norm` - but nothing in vLLM dispatched to them yet. Every model with a bare
  `nn.LayerNorm` fell back to torch-xpu-ops' generic kernel on XPU.

  - Adds `StandardLayerNorm`, a `CustomOp` (registered `"layer_norm"`) - drop-in for a bare `nn.LayerNorm`, dispatching via `forward_native`/`forward_cuda`/`forward_xpu`, matching `RMSNorm`/`GemmaRMSNorm` in the same file.
  - Reworks `NemotronLayerNorm1P` (Nemotron's "+1 to weights" variant) from an `nn.LayerNorm` subclass into a `CustomOp` sibling (`"nemotron_layer_norm"`); its XPU path also dispatches the fused-residual-add kernel when a residual is present.
  - Wires both into GPT-2, GPT-J, OPT, SigLIP (PaliGemma's vision tower), and Nemotron.
  - Adds `replace_layernorm_class` (`transformers/utils.py`), matching `replace_linear_class`/`replace_conv_class`/`replace_embedding_class`, so the Transformers modeling backend's generic recursive module-replace picks this up too - covers StarCoder2-style models with no dedicated vLLM model file.
  - Kernel calls are wrapped as real `torch.ops.vllm.xpu_*` custom ops (`_xpu_ops.py`, via `direct_register_custom_op`), the same way `GemmaRMSNorm` wraps its kernel - compile-safe by construction, gated only by the standard `CustomOp` `+`/`-custom_ops` toggle.
  - Every dispatch path is `hasattr(torch.ops._C, ...)`-guarded and falls back to native `F.layer_norm` when the op isn't present - currently a no-op everywhere, since no `vllm-xpu-kernels` release yet contains #577 (just merged) and `requirements/xpu.txt`'s pin predates it.

  ## Test Plan

  - `ruff check`, `ruff format`, full `pre-commit` (incl. `mypy`) on every touched file.
  - Kernel correctness on Intel B70 hardware: parametrized cases across hidden sizes (incl. non-power-of-2), bf16/fp16, weight/bias/weight_bias combinations, plus fused-add cases, for both `layer_norm` and `nemotron_layer_norm`/`fused_add_nemotron_layer_norm`, checked against a plain-PyTorch fp32 reference.
  - End-to-end serve (`--enforce-eager`) on the same hardware, per affected model.
  - End-to-end performance via the official `vllm bench serve`/`throughput`/`latency`, baseline vs patched, N=3 median.
  - Not yet added: a correctness test in the repo (`tests/kernels/core/test_layernorm.py` covers `RMSNorm`/`GemmaRMSNorm`, nothing exercised plain LayerNorm before this PR). Not yet done: lm_eval accuracy check for any affected model. A reproducible kernel-level benchmark (`benchmark/benchmark_layer_norm.py`) is already
  committed on the vllm-xpu-kernels PR itself.

  ## Test Result

  **Correctness:** 64 parametrized cases + 2 fused-add cases, all pass vs plain-PyTorch fp32 reference.

  **Kernel microbenchmark** (native `F.layer_norm` vs SYCL, bf16, hidden_size=4096):

  | tokens | native | SYCL | speedup |
  |---|---|---|---|
  | 1 | 8.35us | 3.60us | 2.32x |
  | 128 | 9.63us | 3.70us | 2.60x |
  | 512 | 28.20us | 5.90us | 4.78x |
  | 1024 | 51.73us | 10.83us | 4.78x (peak) |
  | 2048 | 103.91us | 56.61us | 1.84x |

  **End-to-end serve:** GPT-J, GPT-2, OPT-125m, Nemotron/Minitron-8B, PaliGemma (SigLIP), and StarCoder2-3B all served and generated correctly with `--enforce-eager`; SYCL dispatch confirmed firing inside the real engine, not just via a direct standalone op call.

  **End-to-end performance:**

  | Model | Path | Throughput | Latency | Serve |
  |---|---|---|---|---|
  | GPT-2-124M | direct swap | **+9.1%** | -9.5% (faster) | **+5.3%** |
  | OPT-125M | direct swap | **+9.2%** | -1.2% (faster) | **+9.4%** |
  | GPT-J-405M | direct swap | **+6.1%** | -4.4% (faster) | **+9.2%** |
  | StarCoder2-3B | generic swap | +1.0% | -1.2% (faster) | +1.3% |
  | Minitron-8B (Nemotron) | direct swap | +0.8% | -0.9% (faster) | +0.5% |


  **Caveat:** the above was measured against an earlier revision of this dispatch code (direct `torch.ops._C.*` calls, gated by `torch.compiler.is_compiling()`). This PR wraps those same calls through `torch.ops.vllm.xpu_*` instead, for `torch.compile` safety - a thin pass-through to the identical kernel call, so behavior should
  be unchanged, but hasn't itself been re-run on hardware.
```

```diff
+@CustomOp.register("layer_norm")
+class LayerNorm(CustomOp):
+    """Standard (mean-centered) LayerNorm.
+
+    Drop-in for a bare `nn.LayerNorm` that dispatches to a fused XPU kernel
+    when one is available, and to the native implementation otherwise.
+
+    Normalization runs in the wider of the input and parameter dtypes and the
+    result is cast back to the input dtype, so `dtype=torch.float32` gives an
+    fp32 reduction for a lower-precision input.
+    """
+
+    def __init__(
+        self,
+        hidden_size: int,
+        eps: float = 1e-5,
+        elementwise_affine: bool = True,
+        bias: bool = True,
+        dtype: torch.dtype | None = None,
+    ) -> None:
+        super().__init__()
+        self.normalized_shape = (hidden_size,)
+        self.eps = eps
+        weight_dtype = dtype or torch.get_default_dtype()
+        self.weight: nn.Parameter | None = None
+        self.bias: nn.Parameter | None = None
+        if elementwise_affine:
+            self.weight = nn.Parameter(torch.ones(hidden_size, dtype=weight_dtype))
+            if bias:
+                self.bias = nn.Parameter(torch.zeros(hidden_size, dtype=weight_dtype))
+
+    def _compute_dtype(self, x: torch.Tensor) -> torch.dtype:
+        if self.weight is None:
+            return x.dtype
+        return torch.promote_types(x.dtype, self.weight.dtype)
+
+    def forward_native(self, x: torch.Tensor) -> torch.Tensor:
+        compute_dtype = self._compute_dtype(x)
+        if compute_dtype != x.dtype:
+            return F.layer_norm(
+                x.to(compute_dtype),
+                self.normalized_shape,
+                self.weight,
+                self.bias,
+                self.eps,
+            ).type_as(x)
+        return F.layer_norm(x, self.normalized_shape, self.weight, self.bias, self.eps)
+
+    def forward_cuda(self, x: torch.Tensor) -> torch.Tensor:
+        return self.forward_native(x)
+
+    def forward_xpu(self, x: torch.Tensor) -> torch.Tensor:
+        import vllm._xpu_ops  # noqa: F401 registers torch.ops.vllm.xpu_layer_norm
+
+        if (
+            self.weight is None
+            or self.bias is None
+            or not hasattr(torch.ops._C, "layer_norm")
+            # The kernel reduces in the input dtype, so a widened reduction
+            # takes the native path.
+            or self._compute_dtype(x) != x.dtype
+        ):
+            return self.forward_native(x)
+        # empty_like preserves x's strides, but the kernel requires a
+        # contiguous out (unlike x, which it can handle non-contiguous).
+        out = torch.empty(x.shape, device=x.device, dtype=x.dtype)
+        torch.ops.vllm.xpu_layer_norm(out, x, self.weight, self.bias, self.eps)
+        return out
+
+    def extra_repr(self) -> str:
+        return f"hidden_size={self.normalized_shape[0]}, eps={self.eps}"
```
