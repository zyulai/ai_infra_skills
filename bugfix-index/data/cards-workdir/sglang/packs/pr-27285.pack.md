## 正文(PR 描述)

## Motivation

HiCache does not work well with PP.  It leads to server crash. 

I have tried to solve the PP + HiCache L2+ L3 in a single patch #27010.  But that patch became larger and larger when I try to deal with `UnifiedRadixCache` and `HybridCacheController`.  Let me divide that patch into smaller ones.

This patch fixes PP + L2 only, leaving L3 unsolved.

## Modifications

The reason to server crash is due to lack of synchronization beteeen scheduler threads of PP0 and PP1.  The details are discussed in #22607. 

This patch introduced a new synchrnoization mechanism called **pp_sync** for scheduler threads.  

PP0's scheduler thread determine the number of completion events in its local queues (ack_load_queue, ack_prefetch_queue, etc). Then, PP1 must consume the exact same number of events from its queues. This prevents divergence.

## Tests

### Reproduce

A minimal reproduce step for "PP + L2 => crash" issue:

```sh
sglang serve \
  --model-path=Qwen/Qwen3-32B \
  --pp-size=2 \
  --enable-hierarchical-cache \
  --max-total-tokens=$((256*1024))

python -m sglang.bench_serving --num-prompts 1000

Got this error:
RuntimeError: shape '[3013, -1, 128]' is invalid for input of size 8192000                                                                                                                                                                                                                                                                                                                                          
```

This patch fixes that crash.

### Effectiveness of L2 cache

I tested Qwen3-32B the following configuration:
- pp-size=4
- tp-size=2
- \#tokens in L1 = 256K
- \#tokens in L2 = 512K
