## 正文(PR 描述)

## Purpose

This PR fixes a bug in Hunyuan-V3 (`hy_v3` / `hy_v3_mtp`) MoE model execution where the router selection bias `expert_bias` was allocated in the serving dtype instead of `torch.float32` (closes #47777).

`HYV3MoEFused` allocated `expert_bias` as:
```python
self.expert_bias = nn.Parameter(torch.empty(config.num_experts))
```
Under default torch dtypes like `torch.bfloat16`/`torch.float16`, this parameter was allocated in 16-bit precision. During checkpoint weight loading, the true float32 bias tensor from the checkpoint was silently downcast to 16-bit by `param.data.copy_()`. Because this bias is critical for top-k routing decisions, downcasting flips routing choices on boundary tokens.

This PR explicitly pins `expert_bias` to `torch.float32` (matching `deepseek_v2.py` and Hugging Face's `_keep_in_fp32_modules_strict` settings):
```python
self.expert_bias = nn.Parameter(
    torch.empty(config.num_experts, dtype=torch.float32)
)
```

No duplication: We verified that there are no open PRs addressing this expert bias issue for `hy_v3`.

AI-assisted contribution: This contribution was prepared with the assistance of Claude and Gemini.
