## Purpose

Two changes to `DecodeBenchConnector`, one commit each:

- **Fix fp8 fill values.** fp8 KV caches are stored as `uint8`, and the fill used `torch.full(fill_mean, dtype=uint8)`, which truncates to 0. So the dummy prompt KV was all zeros, and random fill (`fill_std > 0`) raised.
  - Plain fp8 `uint8` caches now get the fill encoded in their fp8 dtype (platform e4m3, or e5m2 for `fp8_e5m2`).
  - Random values are sampled in float32 and clamped to the finite range.
  - Packed `uint8` layouts with scales or metadata (e.g. `fp8_ds_mla`, NVFP4) keep the zero fill, now with a one-time warning.
- **Add an opt-in `startup_fill` option** (`kv_connector_extra_config`).
  - Today's per-request fill runs inside the decode steps that admit new requests. For every layer it copies block IDs to the device, filters them with a boolean mask (a device sync) and builds a temporary tensor.
  - With `startup_fill`, the worker fills the KV cache once in `register_kv_caches` and skips the per-request fill.
  - Circular-buffer groups, and attention groups whose new blocks the engine zeroes (hybrid Mamba, mixed precision), keep the per-request fill, so the dummy KV is never left as zeros.
  - The fill isn't redone after sleep mode. The default behavior is unchanged.
- No open PR covers either change. #57751, which fixes Mamba state filling in the default mode, is complementary.

## Test Plan

- `pytest tests/v1/kv_connector/unit/test_decode_bench_connector.py`. New tests:
  - read-back as fp8 for `fp8` / `fp8_e5m2` `uint8` caches and a `float8_e4m3fn` cache, with constant and random fill;
  - a packed layout stays zero;
  - startup fill of strided, padded and fp8 caches;
  - no per-step fill;
  - circular-buffer and engine-zeroed groups keep the per-request fill.
- KV read-back on the workers, in the default mode and with `startup_fill`:
  - `Qwen/Qwen3-0.6B` with `--kv-cache-dtype fp8`;
  - `MiniMaxAI/MiniMax-M3-MXFP8` TP4 with fp8 main KV and fp8 indexer KV.
- Decode-only A/B with `--kv-transfer-config '{"kv_connector":"DecodeBenchConnector","kv_role":"kv_both"[,"kv_connector_extra_config":{"startup_fill":true}]}'` and `vllm bench serve --dataset-name random --ignore-eos`: a warmup, then 3 runs per mode.
  - Qwen3-0.6B on 1× GB200, 3584 in / 256 out, concurrency 4.
  - M3 TP4 GB200 (`--language-model-only --block-size 128 --max-num-seqs 88 --max-num-batched-tokens 512 --kv-cache-dtype fp8 --attention-config '{"indexer_kv_dtype":"fp8"}' --compilation-config '{"cudagraph_mode":"FULL_DECODE_ONLY"}'`), 32000 in / 256 out, concurrency 32.
