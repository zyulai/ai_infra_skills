## 正文(PR 描述)

## Purpose

Fix a bug where vLLM engine processes become zombies when KV cache initialization fails. Previously, if `_initialize_kv_caches` raised an exception, the executor was never shut down and the front-end would hang waiting for a ready message that never arrives.

This PR adds three changes:
- **EngineCore**: Catch exceptions during KV cache init and shut down the model executor before re-raising
- **Handshake**: Send a `FAILED` status over ZMQ when init fails, so the front-end detects the failure immediately via ZMQ instead of waiting for the process sentinel (which may be delayed by cleanup)
- **Front-end**: Handle the new `FAILED` status in the handshake response and raise a clear error

## Test Plan

1. Simulate a KV cache initialization failure (e.g., request more GPU memory than available)
2. Verify the engine process shuts down cleanly instead of hanging
3. Verify the front-end receives the FAILED status and raises `RuntimeError` promptly

## Test Result

Engine processes no longer hang on init failure; front-end receives immediate failure notification.
