## 正文(PR 描述)

## Summary

With `--mm-encoder-tp-mode data`, ranks that get no images all-gather placeholder embeddings whose dtype comes from `next(vision_model.parameters())`. Since #64111, MiniMax-M3 keeps its patch embedding in fp32 while the tower outputs bf16. Ranks with images then gather bf16 and ranks without gather fp32, so the all-gather mismatches and startup hangs.

This uses the vision model's `dtype` attribute when it has one, and falls back to the first parameter's dtype otherwise. Other models are unchanged: their `dtype` either matches the first parameter or isn't defined.

## Test plan

- `amd/MiniMax-M3-MXFP4` with `-tp 4 --mm-encoder-tp-mode data` now starts and serves image requests. Before the fix, it hung after the encoder profile run.
- Ongoing coverage comes from the nightly MiniMax-M3 evals, which run with `--mm-encoder-tp-mode data`.
