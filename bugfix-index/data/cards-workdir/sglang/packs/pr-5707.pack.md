## Motivation
We found bugs while using MTP and `-n-share-experts-fusion` together.
1. While using `--n-share-experts-fusion ${TP_SIZE}` with MTP, there will be weight loading error:
![image](https://github.com/user-attachments/assets/9aead75a-0ad5-448f-8e5c-dd8856f87731)

2. While using `--n-share-experts-fusion 0` with MTP, the result could be wrong according to different configurations. For example, sometimes we see the following log which means that `n-share-experts-fusion` is turn on automatically. However, in `deepseek_nextn.py` the state may not be always constant with it.
![image](https://github.com/user-attachments/assets/48fddb04-05ef-4312-b3c7-226247da1754)
Finally, the inference result is totally wrong.
![image](https://github.com/user-attachments/assets/450f5538-4798-40f1-9adb-c31c12800bd4)


<!-- Explain the purpose of this PR and the goals it aims to achieve. -->

## Modifications

1. Add similar logic in `DeepseekV2ForCausalLM.load_weights` of cloning shared expert。
2. Put the code of determining `self.n_share_experts_fusion` into a function`DeepseekV2ForCausalLM.determine_n_share_experts_fusion` and call it in `DeepseekV3ForCausalLMNextN`.
