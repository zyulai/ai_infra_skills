## 正文(PR 描述)

## Summary

When a node's host ionic provider is newer than the container's rdma-core, the in-container libibverbs rejects the provider — `Driver ionic does not support the kernel ABI ... No IB devices found` — and RDMA fails, taking that node out of the disagg nightly pool (observed on `mia1-p01-g20`).

`launch_mi355x.sh`'s `docker run` mounted only `/it-share` and `$HOME`. The disagg container script (`scripts/ci/amd/amd_ci_start_container_disagg.sh`) already handles this by mounting the host ionic/ibverbs userspace into the container; this ports the same mount set to the Slurm launcher.

## How
- Generate `$WORKDIR/ionic_mounts.sh` (literal heredoc) that resolves the host ionic provider + provider dir + `/etc/libibverbs.d` + libnl/libmnl and exports `IONIC_MOUNTS`.
- The prefill/decode/bench role scripts `source` it before `docker run` and pass `$IONIC_MOUNTS`.
- Detection runs on the compute node (the ionic `.so` version is node-specific), is existence-guarded (no-op on a host without ionic), mounts only the provider (not core `libibverbs.so`), and leaves `DOCKER_COMMON` / `EXTRA_DOCKER_ARGS` unchanged.

## Test plan
- [ ] 1P1D leg pinned to include g20, no manual ionic mount: no `No IB devices found`, `ibv_devinfo` lists the ionic HCAs, GSM8K gate passes.
- [ ] p02-only run unchanged (no regression).
