### **Purpose**

Per https://github.com/vllm-project/vllm/issues/28427, https://github.com/vllm-project/vllm/issues/28316, TRTLLM has `fp8_gemm_kernel_swapAB` kernel for blockscale FP8 gemm in linear layer. This PR https://github.com/vllm-project/vllm/pull/29213 (and FlashInfer PR https://github.com/flashinfer-ai/flashinfer/pull/2131) brings the gemm kernel and quant kernel (to get FP8 scaling) in VLLM.

Description:
M < 32 uses DeepGEMM swapAB from FlashInfer, M>=32 uses DeepGEMM from https://github.com/deepseek-ai/DeepGEMM. Any other fallback (FlashInfer not installed) would be the rest of the gemms (DeepGEMM/Cutlass/etc).

**Note:** The reason of not using all FlashInfer Blockscale FP8 kernels for linear layer is we're seeing accuracy drop from 95% to 88% when running GSM8K. There's an internal logic in CPP that uses non-swapAB kernel for M>=32 gemms. Therefore an alternative way is only use swapAB in M<32 scenario, leveraging torch.cond to switch between FlashInfer and DeepGEMM while torch.compile captures the condition. The accuracy for the larger gemm in FlashInfer FP8 may be resolved in future PR since currently from acc benchmark there's no accuracy drop now.

+
