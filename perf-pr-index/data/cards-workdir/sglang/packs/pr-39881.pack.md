## Motivation

The unfused MXFP4 W4A8 MoE chain runs three kernels per MoE layer for the gate/up projection: gmm1, a separate swiglu activation kernel, and a dynamic MX requant. NPU A5 already provides `npu_grouped_matmul_swiglu_quant_v2`, which folds all three into a single aclnn kernel.

## Modifications

- `NPUW4A8MXFP4MoEMethod` gains `apply_fused_gmm1_swiglu`, mirroring `NPUMXFP8MoEMethod`: same fused-kernel call shape, with the FP4 weight dtype and e8m0 weight/x scale dtypes. `pertoken_scale` handling matches the class's existing unfused `apply()` (quantize on the DeepEP bf16 path; pair-reshape when a scale is handed over).
- The Ascend MoE runner replaces the `NPUMXFP8MoEMethod` isinstance check with a `_uses_fused_gmm1(kernel)` probe, so both MXFP8 and MXFP4 W4A8 skip the separate activation step; the fail-loudly semantics of  `self.activation = None` are preserved.

## Speed Tests and Profiling

### Before modification

Serving benchmark (128 requests, 16K input tokens per request, request rate 0.4, max concurrency 32, 300s):

| Metric | Value |
|---|---|
| Mean TTFT (ms) | 2901.01 |
| Median TTFT (ms) | 2556.05 |
| P90 TTFT (ms) | 4096.08 |
| P95 TTFT (ms) | 4710.71 |
| P99 TTFT (ms) | 7413.64 |
| Input token throughput (tok/s) | 6810.63 |

Per-operator latency of the unfused MoE chain (`gmm1` + `swiglu` + `mxquant` + `gmm2`): **1.15 ms**

### After modification

| Metric | Value | Δ |
|---|---|---|
| Mean TTFT (ms) | 2676.64 | -7.7% |
| Median TTFT (ms) | 2487.71 | -2.7% |
| P90 TTFT (ms) | 3841.38 | -6.2% |
| P95 TTFT (ms) | 4066.67 | -13.7% |
| P99 TTFT (ms) | 4624.62 | -37.6% |
| Input token throughput (tok/s) | 6811.22 | +0.01% |

Per-operator latency of the fused chain (`gmm1_swiglu_mxquant` + `gmm2`): **0.98 ms** (-14.8%)

The fused kernel cuts the per-layer MoE operator latency by ~15%, which translates into consistent TTFT improvements across all percentiles — most notably a 37.6% drop at P99, indicating the fusion also removes tail-latency spikes from kernel launch overhead and intermediate activation traffic.
