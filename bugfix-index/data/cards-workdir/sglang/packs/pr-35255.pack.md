## 正文(PR 描述)

## Summary

  This PR fixes an issue where a request could continue decoding after the client disconnected, wasting GPU resources and repeatedly logging:

```text
  Received output for rid=... but the state was deleted in TokenizerManager.
```

## Root Cause

When a request handler was cancelled after dispatch, TokenizerManager removed its `rid_to_state` entry immediately. The disconnect abort path checks this state before sending an AbortReq, so the abort was skipped while the request continued running in the scheduler.

 A related race also existed for chunked-prefill requests: if a request moved out of the chunked-prefill slot before its deferred abort was processed, the abort could be lost.

 ## Changes
  - Track whether each request has been dispatched to the scheduler.
  - Remove undelivered request states locally on handler failure.
  - Abort dispatched requests and retain their state until scheduler cleanup completes.
  - Deduplicate abort requests and abort metrics.
  - Preserve retry behavior when abort dispatch fails.
  - Track generated request IDs used by parallel sampling.
  - Retry deferred chunked-prefill aborts after a request moves to another scheduler queue.
  - Add regression tests for disconnect cleanup, abort deduplication, dispatch failures, parallel sampling, and chunked-prefill transitions.
