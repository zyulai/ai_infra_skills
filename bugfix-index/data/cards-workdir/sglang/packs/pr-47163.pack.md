## 正文(PR 描述)

## Human

QUICK REDUCE QUANTIZATION has been reported by multiple community maintainers & folks deploying in production an signficiant  drop in quality for end-user production workloads in addition to their private & public 800k+ long context evals.  On 1 eval, community maintainers and us ran, it drops the 800k+ long context eval by over relatively 10% from 34% baseline to 30.4%.

this shouldn't be an surprise to AMD as AMD has noted the accuracy effect of this option too in vllm recipes https://github.com/vllm-project/recipes/blame/e38b528a540f3bf79674960cae78173e775e7fdc/models/moonshotai/Kimi-K3.yaml#L710

since this is an accuracy effecting flag, it shouldnt be set as default

## Motivation

The ROCm image currently sets `ROCM_QUICK_REDUCE_QUANTIZATION=INT8` for every workload. Remove this image-level override so deployments opt into INT8 QuickReduce explicitly.

## Modifications

Delete `ENV ROCM_QUICK_REDUCE_QUANTIZATION=INT8` from `docker/rocm.Dockerfile`. No other defaults or runtime code change.

When the variable is unset, `QuickAllReduce.init_quick_all_reduce()` defaults to `NONE` and disables QuickReduce. Users can still enable it explicitly at container launch.

## Accuracy Tests

- Verified that the diff contains only the requested ENV deletion.
- Verified that the runtime fallback remains `NONE`.
- No image build or GPU accuracy tests were run.

## Speed Tests and Profiling

Not run. Removing the implicit INT8 QuickReduce setting may affect collective performance for workloads that previously inherited it.
