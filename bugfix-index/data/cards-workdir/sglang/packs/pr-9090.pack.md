## Motivation

In `server_args.py`, we set [the default `mem-fraction-static` as 0.88](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/server_args.py#L354) when it's not set at the command line. This is well applied for accelerator devices, yet need to be adjusted for CPU servers in which the memory is shared among all the TP ranks.

On CPU, the absence of `--mem-fraction-static` setting or a straightforward setting (e.g. 0.8, 0.9) without `--max-total-tokens` specified may lead to OOM.

## Modifications

For CPU, inquire the per-numa available memory amounts with the APIs provided in `py-libnuma`.
Since the per-rank memory status is unavailable if user specify `SGLANG_CPU_OMP_THREADS_BIND`, warning message are added in both doc and code to inform that the user should take care of the memory status and avoid OOM.

Update: Due to the compatibility issue of `py-libnuma` (it does not work with py311/py313), The per-numa free memory inquiry approach has changed to invoking the APIs in `libnuma.so` directly.
