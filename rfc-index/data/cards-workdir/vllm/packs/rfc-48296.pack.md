# [RFC] Speculative Decoding Lifecycle for RL Rollout

## Problem

RL frameworks cannot use vLLM's speculative decoding (MTP / EAGLE / suffix) for rollout acceleration because:

1. **Config not exposed**: verl's `vllm.LLM` wrapper does not pass through `speculative_config` ([verl#4526](https://github.com/verl-project/verl/issues/4526))
2. **MTP weight sync broken**: after RL training updates MTP head weights, `load_weights` does not reload MTP parameters — they go stale ([verl#6947](https://github.com/verl-project/verl/issues/6947))
3. **Draft model lifecycle**: EAGLE/EAGLE3 draft models need weight reload during sleep/wake, currently only verifier weights are updated ([#46725](https://github.com/vllm-project/vllm/pull/46725), already tracked in Section 1.1)

## Downstream demand

- [verl#5925](https://github.com/verl-project/verl/pull/5925): EAGLE/EAGLE3 for RL rollout (verl PR, open)
- [verl#6342](https://github.com/verl-project/verl/pull/6342): Suffix spec decode in vLLM rollout (verl PR, open)
- [verl#4791](https://github.com/verl-project/verl/issues/4791): Suffix + LSTM spec decode RFC
- [SkyRL#1832](https://github.com/NovaSky-AI/SkyRL/pull/1832): MTP training support (P0 in SkyRL Q3 roadmap)

## Exit criterion

- verl can configure `speculative_config` for vLLM rollout without error
- MTP head weights correctly reload after `load_weights` / `finish_weight_update`
