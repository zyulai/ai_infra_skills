## Motivation
  
The LongCat-Image DiT runs tanh-GELU as a separate op after its FFN up-projection GEMM, in both the dual-stream FFN (`ff` / `ff_context`) and the single-stream block's `proj_mlp`. sglang already ships the AOT cublasLt `linear_gelu_tanh` epilogue that folds bias-add and tanh-GELU into the GEMM (used today by FLUX.1, Qwen-Image, GLM-Image, LTX-2, HunyuanVideo), but LongCat never marked its sites, so the fusion could not engage. These sites execute 4000 times per generation on LongCat-Image-Edit (50 steps x 80 sites), which makes the standalone activation a measurable slice of denoise time.
   
This PR wires LongCat-Image into that existing mechanism.

## Modifications

Single file, `python/sglang/multimodal_gen/runtime/models/dits/longcat_image.py`:
- `_LongCatFFN.__init__`: `mark_fused_gelu_site(self.net[0], "proj")`, covering `ff` and `ff_context` in every dual-stream block. The marked module is the `ModuleDict` that holds `proj` in `_modules`, so `getattr` resolves it for the fusion helper.
- `_LongCatFFN.forward`: take `fused_linear_gelu_tanh` when `fused_gelu_active()` and `can_use_linear_gelu()` both hold; otherwise fall back to the original `proj` + `nn.GELU(approximate="tanh")` chain, unchanged.
- `_SingleTransformerBlock.__init__` / `.forward`: the same treatment for `proj_mlp` / `act_mlp`.
No kernel, gate, or mount code is touched. `mount_fused_linear_gelu` `unmount_fused_linear_gelu` in the denoising stage already discover marked sites at batch boundaries, all-or-nothing per transformer, and `quality` already participates in the dynamic-batch signature.

## Speed Tests and Profiling
Same case (LongCat-Image-Edit, A800, 50 steps, seed 42). The GELU region was measured with temporary instrumentation bracketing "up-proj GEMM + tanh-GELU", removed before submitting:

| Config | GELU region (50-step total) | Per call | vs baseline |
| --- | --- | --- | --- |
| `lossless` (un-fused) | 9638 ms | 2.410 ms | - |
| `high` (fused) | 9044 ms | 2.261 ms | -594 ms / -6.2% |

- 4000 calls per generation (50 steps x 80 sites); two repeats, variance < 0.2%.                                                                                                                                            
- The GELU region itself is 6.2% faster, saving 0.148 ms per call.

End-to-end denoise, 5 runs per config:

| Config | Denoise (mean) | vs baseline |                                                                                                                                                                                   
| --- | --- | --- |
| `lossless` | 45.496 s | - |
| `high` | 44.812 s | -0.68 s / -1.50% |
