```markdown
## Purpose

Route eligible ROCm AITER fused all-reduce + RMSNorm prefill calls through the new AITER QuickReduce + RMSNorm fused kernel added in ROCm/aiter#4104. 

> For reviewers: this lazily creates an AITER QR communicator and caches it on the vLLM device communicator for reuse; it is intentionally not created per call. 

**NB! The fusion only applies until `max_num_batched_tokens<=8192`. The `max_num_batched_tokens>8k` cases need subsequent vLLM-side changes that are beyond the scope of this PR.**

## Test Plan

* Expanded the existing QR test coverage with:
  - prefill-sized input dispatches to `aiter.qr_all_reduce_rmsnorm`
  - decode-sized input keeps using the 1-stage AITER custom all-reduce path

  
* Run GSM8K accuracy and performance A/B benchmarks.

## Test Result

> Upgrade AITER to include https://github.com/ROCm/aiter/pull/4104 . This is included in the concurrent `vllm-openai-rocm` docker nightlies using AITER>=v.0.19.0
