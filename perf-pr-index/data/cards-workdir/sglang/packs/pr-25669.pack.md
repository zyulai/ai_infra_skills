## Motivation

The EPD encoder server (`encode_server.py`) processes image preprocessing
(PIL resize + normalize via `image_processor()`) synchronously on the asyncio
event loop. Under N concurrent requests, all preprocessing is serialized —
each request waits for the previous one to finish. Additionally, after
preprocessing completes, each request triggers its own individual ViT forward
pass rather than batching across concurrent requests arriving at the same time.

## Modifications

### 1. Async image preprocessing (`preproc_executor`)

Moves `image_processor()` calls off the asyncio event loop into a dedicated
`ThreadPoolExecutor` via `run_in_executor`. N concurrent requests now
preprocess images in parallel without blocking request acceptance or each other.

A separate executor (`preproc_executor`) is used instead of the existing
`self.executor` (which handles ZMQ sends) to prevent contention under high
concurrency.

Configurable via `SGLANG_ENCODER_PREPROC_WORKERS` (default: 8).

### 2. Cross-request ViT batching (`_vit_batch_loop`)

Adds an asyncio queue (`_vit_queue`) and a background coroutine
(`_vit_batch_loop`) that collects concurrently preprocessed images and runs
them as a single batched ViT forward pass instead of N separate ones.

**Adaptive sleep:** when the queue already has items the loop yields
immediately (`asyncio.sleep(0)`); it only waits `SGLANG_ENCODER_BATCH_TIMEOUT_MS`
(default: 20 ms) when the queue is empty, avoiding unnecessary latency for
staggered arrivals while still allowing batch accumulation.

Configurable via:
- `SGLANG_ENCODER_BATCH_SIZE` (default: 8) — max requests per ViT batch
- `SGLANG_ENCODER_BATCH_TIMEOUT_MS` (default: 20) — batch accumulation window

Unit tests added in `test/registered/unit/disaggregation/test_encode_server_perf.py`.

## Accuracy Tests

No change to model outputs. Preprocessing and ViT inference are unchanged;
only the scheduling of when they execute changes.

## Speed Tests and Profiling

Benchmarked with `sglang.bench_serving` on AMD MI355X, Qwen/Qwen3.6-35B-A3B, EPD 1E1P.
`output_len=1` isolates the encoder path (preprocessing + ViT + ZMQ + PD prefill); no decode pressure — metric is end-to-end request latency.

```bash
python3 -m sglang.bench_serving \
    --backend sglang \
    --host 127.0.0.1 \
    --port <pd_port> \
    --model Qwen/Qwen3.6-35B-A3B \
    --dataset-name image \
    --image-count 8 \
    --image-resolution 720p \
    --num-prompts 100 \
    --random-input-len 128 \
    --random-output-len 1 \
    --max-concurrency 16
```

Encoder env (as measured): `SGLANG_ENCODER_BATCH_SIZE=16`. Note: `SGLANG_ENCODER_PREPROC_WORKERS` was at its then-default of 32, but `--max-concurrency 16` caps in-flight requests, so effective preproc parallelism is 16 — any value ≥16 reproduces these numbers. The default is now **8** (per @ShangmingCai review): for this workload that means ~2 preprocessing waves instead of 1, still well clear of stock's 16-wide event-loop serialization (the source of the gain). Tunable via the env var.

| Config | Median E2E Latency | Throughput | vs Stock |
|---|---:|---:|---:|
| Stock (no patch) | 5,820 ms | 2.59 req/s | — |
| This PR | 4,705 ms | 3.19 req/s | **−19% latency, +23% tput** |

Both changes are platform-agnostic (standard Python asyncio + `concurrent.futures`).

## Update 2026-05-26: Scope narrowed to async preprocessing only

Per reviewer feedback from @liusy58, this PR is narrowed to keep only the
async preprocessing change. Cross-request ViT batching is dropped because
PR #25964 covers it at a coarser layer (its `EncoderScheduler` +
`batch_encode` fuses the HF processor call too). The two changes compose:
async preprocessing keeps the event loop free so #25964's batch worker
actually sees concurrent requests, instead of seeing them arrive
one-at-a-time after each blocking processor call.

**Removed:** `_vit_queue` / `_vit_task` / `_vit_batch_loop` /
`_ensure_vit_batch_loop`, `SGLANG_ENCODER_BATCH_SIZE` and
`SGLANG_ENCODER_BATCH_TIMEOUT_MS` env vars, `TestViTBatchQueue` test class
(4 tests).

**Kept:** `preproc_executor`, `SGLANG_ENCODER_PREPROC_WORKERS`
(now in `sglang.srt.environ`, default 8), `run_in_executor` wrapping for
image / video / audio preprocessing.

### Performance note

The narrowed scope does **not** lose measurable perf on this benchmark.
The "This PR" row was measured with ViT batching included. Re-measuring
the same workload with ViT batching removed (async preprocessing only)
gives −18% lat / +26% tput — essentially the same as the table row,
within run-to-run noise. The current benchmark setup doesn't exercise
the ViT-batching improvement enough to show a distinguishable delta.
