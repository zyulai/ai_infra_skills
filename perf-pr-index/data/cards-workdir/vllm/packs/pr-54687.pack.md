## PR body
```markdown
## Summary

- Reuse the existing Qwen4Exp HC combine kernels for MTP input instead of maintaining an MTP-only add-and-norm kernel.
- Treat `injection_logits=None` as unit injection. Triton specializes directly on the optional `inj_ptr`, so the MTP path performs no injection load or sigmoid.
- Pass `fc_embedding` into the normal decoder as a pending HC block output. The existing combine-norm kernel then fuses the BF16 broadcast add and grouped Gemma RMSNorm.
- Generalize both HC combine variants to the same optional-injection contract, and remove `_forward_mtp_layer` plus the duplicated MTP kernel.

This does not duplicate #54560, which targets the general Qwen4Exp `M=1` SM90 decode path; this change targets the MTP entry residual add and grouped RMSNorm for arbitrary token counts.

## Data flow

```text
target / feedback hidden                 new token
          |                                  |
 pre-norm + fc_hidden                embed + pre-norm
          |                                  |
 residual [T, HC, H]               fc_embedding [T, H]
          |                                  |
          |                         pending block output
          |                         injection = None
          +------------------+---------------+
                             |
                 Qwen4ExpDecoderLayer.forward
                             |
                  attn_hc.combine_and_mix
                             |
             hc_combine_norm[inj_ptr=None]
                    /                    \
       residual + embedding          grouped RMSNorm
                    \                    /
                     +--------+----------+
                              |
                  normal HC mix and decoder
                              |
                     Attention -> MLP
```

## Final kernel specialization

Following review, the final implementation keeps the optional-pointer design while minimizing special-case code:

- Residual and block loads are issued before FP32 conversion and arithmetic.
- Gated and unit-injection paths share the same two-dimensional tiled layout and RMSNorm reduction.
- Both paths use one flattened token-major launch grid, keeping the streams for each token adjacent without an injection-specific grid branch.
- The only unit-injection-specific scheduling is issuing the norm-weight load before the reduction; the gated path keeps the load after the reduction to limit its live range.

## Kernel microbenchmark

NVIDIA B200, CUDA 13.0, PyTorch 2.13.0+cu130, BF16, `H=2560`, `HC=4`; CUPTI medians with CUDA graphs and cold L2. All baseline and current callables are captured with `torch.compile(fullgraph=True)`, and both materialized BF16 outputs are checked before timing.

The without-injection baseline is main's separate broadcast add followed by grouped Gemma RMSNorm. The with-injection baseline is main's existing injected HC combine-norm path. Thus each optional-pointer specialization is compared with the corresponding main compiled behavior.
