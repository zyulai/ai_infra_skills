## Motivation

Address https://github.com/sgl-project/sglang/issues/12838
This PR cooperates closely with @yhyang201 . 

Per comparing the SGLang and vLLM performance on VLM, one of the key influencing factors is supporting piecewise CUDA graph. Piecewise CUDA graph can significantly reduce small kernels' launch time in prefill mode, so as to reduce TTFT.

<img width="2968" height="1604" alt="image" src="https://github.com/user-attachments/assets/6b089294-b65e-455a-9a01-87d3ce8bef7d" />

<img width="2958" height="1530" alt="image" src="https://github.com/user-attachments/assets/4a713fc6-d714-4d97-9f9a-be00537cdda4" />


From the Torch Profiling, we can find that with piecewise CUDA graph feature, the CUDA Command Buffer Full disappear. The GPU is working more efficiently. The buffer is because the recv_obj cycle in CPU. If we coordinate the CUDA IPC feature along with Piecewise CUDA Graph, the performance would be even better.

SGLang works by calling embed_mm_inputs, which allocates a brand-new inputs_embeds tensor each time. Because of this, the device address cannot remain fixed, preventing us from capturing the entire vision-language model with a single CUDA graph.
In contrast, vLLM handles it differently — its encode step is performed in the _preprocess function inside the model runner. This allows it to skip the ViT CUDA graph and instead perform piecewise CUDA graph execution directly within the LLM.
https://github.com/vllm-project/vllm/blob/main/vllm/model_executor/models/qwen2_5_vl.py#L1596

This PR splits logic of general_mm_embed_routine() into two part, one is general_mm_embed, another is lang_model processing. For the former part, move it outside VL model. For the lang_model part, keep it remanent in the VLM model. So as the piecewise CUDA graph can avoid to take effect on ViT logic and only focus on LLM.
