> Generated by Claude.

## Motivation

Every JIT collective in `csrc/distributed` and `csrc/kimi_k3/comm` took one flat `CommunicatorObj` that carried every buffer any of them might want: `2 * world_size` push slots, a pull workspace, per-block semaphores, a rank-local counter, and one of the three multicast addresses. Consequences:

- The other two multicast addresses travelled out of band. `ws_mc_base` was an `int64_t` argument repeated at five call sites, always the same constant; `pull_sem_mc_ptr` went through a per-world-size Python dict populated by `register_comm()`, duplicated in three modules.
- A push-only owner (the fused qk-norm instances in `minimax_m2`) had to allocate a placeholder 1 KB pull buffer plus one semaphore purely to satisfy the constructor.
- Only `custom_all_reduce.cuh` ever read `pull_workspaces` / `pull_bytes` / `pull_mc_workspace`. The K3 pull kernels reduce in place on the caller's own symmetric input and borrow the plane just to barrier on, so half the object was dead weight for most callers.
- `custom_all_reduce.cuh` defined helpers at `namespace sglang` scope and was `#include`d by three K3 files across directories, so renaming anything inside it silently broke downstream kernels.

## What changed

Split the object by lifetime rather than by direction:

| | contents |
|---|---|
| `sgl.distributed.PushPlane` | zero-filled symmetric push slots, rank-local phase counter, multicast base |
| `sgl.distributed.PullPlane` | symmetric pull buffers + per-block semaphores, both multicast bases. Either half may be a 0-element tensor |
| `sgl.distributed.Communicator` | the two planes (either optional) + the pull launch widths; what every kernel takes |

Both *fixed* multicast addresses now live on the planes. That deletes the `ws_mc_base` parameter from five entry points and the `_PULL_SEM_MC_MAP` registry from three modules. The *per-call* multicast address — a slice of the caller's own symmetric buffer, so it changes every call — stays a plain `intptr_t`, which is what it should be.

`PullPlane`'s optional halves replace the placeholder-buffer trick: `minimax_m2` now constructs `Communicator(push=..., pull=None)` and a kernel that needs a missing plane fails with a message instead of reading a dummy buffer.

### Shared vocabulary moved under `include/`

- **`include/sgl_kernel/distributed/ptx.cuh`** collects the inline PTX the collectives share into `sglang::device::ptx`, which `mbarrier.cuh` and the two K3 files reopen. Removed: three identical copies of the multimem flag increment, three copies of the "multicast alias of a semaphore's flag" helper (now `Semaphore::mc_flag`), and the 16B access helpers that were defined at `namespace sglang` scope inside `custom_all_reduce.cuh`. `csrc/kimi_k3/comm/ptx_sys.cuh` is deleted. The five communication kernels now contain zero inline PTX.
- **`Barrier` / `McBarrier`** (unicast fan-out and one-`multimem.red` variants of the same window protocol) and **`LamportTrait`** (the pos-zero marker) live next to the planes, so each protocol has one implementation instead of one per kernel.
- The three `csrc` → `csrc` includes of `custom_all_reduce.cuh` are gone. What they actually used — `reduce_vec`, the marker traits — moved under `include/`.
- `alloc_workspace_tensor` moved to `host::ffi`, so `utils.cuh` no longer depends on `ffi.h`.

`tp_qknorm`'s 8B `ld.volatile` / `st.volatile` pair became `ld_relaxed_8B` / `st_relaxed_8B` at `.sys` scope (PTX defines volatile as relaxed at system scope, and the store is cross-GPU). Load scope measured identical at `.gpu`, so the `.gpu` load variant was dropped and the vocabulary has one scope.

**Performance** — kernel time only, measured by replaying a CUDA graph of 20 chained calls so host dispatch is excluded; three interleaved rounds per arm, per-arm spread under 1 %:

| variant | delta vs merge base |
|---|---|
| `1shot_push` / eager (dispatched ≤ 768 KB) | **−2.7 % … −6.2 %** |
| `2shot_pull` / multicast (dispatched > 768 KB) | −0.03 % … +0.39 % |
| `1shot_pull` eager and multicast | −1.1 % … +0.6 % |
| `2shot_pull` / eager | +0.5 % … +0.9 % |

33 points: median +0.32 %, worst +0.92 %. On the path the tuned SM100/world-8 config actually dispatches: median **−3.30 %**, worst +0.39 %.

One note on how that number was reached. An earlier revision of this branch regressed `2shot_pull` eager by 7–18 %. Bisecting with self-contained reference kernels showed the params layout, the `Barrier` object and the `Impl` abstraction were all innocent — an exact transplant of the old body still regressed. The cause was the address form: folding the shard offset into the eight base pointers as a typed 32-bit vector index keeps the peer table on the uniform datapath (`UIMAD.WIDE` off a constant-bank base), whereas biasing `vid` per access, or using a 64-bit byte offset, makes all eight addresses thread-varying and costs ~12 registers per thread. Also, binding a params array address to a named local that stays live across the kernel breaks the same proof. Both are noted in comments at the point of use, since either one silently costs ~10 %.
