## Overview

Pass optional `sorted_expert_ids` through Cutlass MXFP4 MoE activation quantization so each sorted token row uses a direct expert index instead of searching expert offset tables.

## Claims


- Kernel: sorted_expert_id path is bitwise identical to offset_search on microbenchmark cases; up to ~3.3× lower median latency at 256 experts for representative input / intermediate_fused shapes.
- E2E: On RedHatAI/GLM-5.3-MXFP4 (TP=4, no spec), ~+5.7% output tok/s vs main.
- API change: Optional sorted_expert_ids on mxfp4_experts_quant, silu_and_mul_mxfp4_experts_quant, and get_cutlass_moe_mm_data; wired from Cutlass MXFP4 MoE when routing metadata exists.

## Details

- Motivation: After MoE routing, activation rows are grouped by expert. The original path resolves each row’s expert via offset-table search; when sorted_expert_ids is already available from Cutlass MoE metadata, that search is redundant and scales poorly with expert count (microbench ~7 µs → ~2.2 µs at 256 experts).

- Design: sorted_expert_ids is optional; when omitted, behavior matches offset_search. 


Possible follow-up: remove redundant shared-memory expert_offsets staging in the large-m_topk MXFP4 quant kernel when sorted_expert_ids is set, and extend the microbenchmark to prefill-sized batches that hit that kernel variant.

+def routing_offsets(
+    num_experts: int,
+    rows: int = ROUTED_ROWS,
+) -> tuple[torch.Tensor, torch.Tensor, torch.Tensor, int]:
+    """32 rows, two assignments on experts 0..15 (production-like small decode)."""
+    if rows != ROUTED_ROWS:
+        raise ValueError(f"expected {ROUTED_ROWS} routed rows, got {rows}")
+    if num_experts < 16:
+        raise ValueError("expert sweep must use at least 16 experts")
+
+    counts = [0] * num_experts
+    counts[:16] = [2] * 16
+
+    row_offsets = [0]
+    scale_offsets = [0]
+    expert_ids: list[int] = []
+    for expert, count in enumerate(counts):
+        expert_ids.extend([expert] * count)
+        row_offsets.append(row_offsets[-1] + count)
+        scale_offsets.append(scale_offsets[-1] + ((count + 127) // 128) * 128)
+    assert row_offsets[-1] == rows
+    return (
+        torch.tensor(row_offsets, dtype=torch.int32, device="cuda"),
+        torch.tensor(scale_offsets, dtype=torch.int32, device="cuda"),
+        torch.tensor(expert_ids, dtype=torch.int32, device="cuda"),
+        scale_offsets[-1],
+    )

+def decode_topk_ids(rows: int = ROUTED_ROWS) -> torch.Tensor:
+    """Two picks per expert 0..15 across 4 tokens (topk=8); shuffled (fixed seed)."""
+    if rows % TOPK != 0:
+        raise ValueError(f"routed rows {rows} must be divisible by topk {TOPK}")
+    expert_ids: list[int] = []
+    for expert in range(16):
+        expert_ids.extend([expert, expert])
+    assert len(expert_ids) == rows
+    gen = torch.Generator(device="cuda")
+    gen.manual_seed(0)
+    perm = torch.randperm(rows, generator=gen, device="cuda")
+    ordered = torch.tensor(expert_ids, device="cuda", dtype=torch.int32)
+    return ordered[perm].view(rows // TOPK, TOPK)
