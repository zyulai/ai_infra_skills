## 正文(PRD / 提案全文)

This RFC proposes integrating Attention-FFN disaggregation (AFD) through a sequence of smaller PRs. The complete implementation is available in [SGLang PR #45562](https://github.com/sgl-project/sglang/pull/45562), together with accuracy results, performance measurements, and reproduction commands. The first implementation PR is [#45958](https://github.com/sgl-project/sglang/pull/45958). We welcome feedback on the runtime interfaces, PR boundaries, and validation requirements.

## Motivation and design

AFD places attention and routed experts on separate GPU groups. Multiple attention instances can share one FFN group and its routed-expert weights, allowing attention and expert capacity to be provisioned independently. Pooling tokens across attention instances can improve expert batching, while microbatch overlap can hide part of the communication and remote execution latency. The benefit depends on workload, resource allocation, and communication overhead.

Requests continue to use SGLang's serving APIs on attention instances. AFD is opt-in through `--afd-role`.

### Runtime boundaries

| Boundary | Responsibility |
| --- | --- |
| Attention workers (A) | Own request scheduling, KV cache, attention, routing, shared experts, residual processing, and sampling. Speculative draft execution stays on A. |
| FFN workers (F) | Execute routed experts and return their outputs. F does not schedule generation requests or maintain KV cache. |
| Startup handshake | Check model, expert layout, quantization, and topology compatibility; negotiate communication and graph capacities for asymmetric A/F groups. Membership is fixed at startup. |
| Forward coordination | Agree on execution mode, token shapes, active sessions, and graph variants. Staged backends batch compatible sessions on F; Direct backends coordinate a common execution plan across A/F ranks. |
| Model integration | Replace routed-expert execution with a remote call while preserving routing, shared-expert, scaling, and residual semantics. Microbatch execution maintains separate child state. |

The implementation is concentrated in [`srt/afd`](https://github.com/sunfanyi/sglang/tree/932ba87c338f31888c4da8e823112ad67b0aa2fc/python/sglang/srt/afd), with integration points in role-specific loading, scheduling, graph execution, and model forward paths. A and F capture local CUDA graphs with coordinated shapes; they do not share a graph object across processes.

Staged NCCL provides the initial transport using standard SGLang dependencies. NVSHMEM adds GPU-side communication and synchronization. Direct DeepEP and MegaMoE M2N route tokens from A to expert-owning F ranks, reducing staged transfers; their prefill path continues to use staged execution. Optional components are loaded only for the selected backend.

The complete implementation covers Qwen3 MoE, DeepSeek V3/V3.2/V4, and GLM-5 MoE DSA, with EAGLE/MTP, DSpark, and composition with PD disaggregation through A's decode role. Support remains subject to the combinations and restrictions documented in #45562. Initial constraints include fixed membership, homogeneous attention instances, attention TP1 within each DP group, and pure EP on F for Direct backends. Dynamic membership, F-side pipeline parallelism, and EPLB remain follow-up work.

## Proposed PR sequence

These capabilities are already implemented in #45562. The table describes how we propose to submit them for review; it is not a list of features to implement from scratch. The boundaries and order are open to maintainer feedback. Each PR will include the relevant tests and documentation.

| Order | PR scope | Main review focus | PR |
| --- | --- | --- | --- |
| 1 | Core AFD and asymmetric parallelism | A/F roles, loading, startup handshake, NCCL execution, capacity derivation, and model hooks for a complete single-attention-instance prefill/decode path. | [#45958](https://github.com/sgl-project/sglang/pull/45958) |
| 2 | CUDA Graph execution | Coordinated capture/replay, buffer lifetime, graph buckets, and eager fallback without microbatch overlap. | — |
| 3 | Decode microbatch overlap | Child state, scheduling and execution order, parent graphs, and shared-expert overlap. | — |
| 4 | Multiple attention instances sharing F | Session scheduling, cohort batching, aggregate capacity, and the NCCL compute-graph/eager paths. | — |
| 5 | NVSHMEM transport | Provider integration into `sgl-kernel`, isolated runtime loading and packaging, topology, arena buffers, synchronization, and NVSHMEM-specific graph/cohort integration. | — |
| 6 | Direct execution and DeepEP | Common Direct execution plans, idle-rank coordination, the DeepEP adapter, and associated layout, quantization, and shared-expert handling. | — |
| 7 | Direct MegaMoE | M2N integration using the common Direct runtime. | — |
| 8 | EAGLE/MTP and DSpark | Local draft execution, remote target verification, graph/microbatch metadata, and DSpark hidden-state capture. | — |

The existing component PRs remain separate and can be reviewed in parallel:

- [ ] [DeepEP #14: disaggregated expert dispatch and combine](https://github.com/sgl-project/DeepEP/pull/14).
- [ ] [DeepGEMM #110: MegaMoE M2N execution](https://github.com/sgl-project/DeepGEMM/pull/110).

The optional NVSHMEM provider is available in [sunfanyi/afd-nvshmem](https://github.com/sunfanyi/afd-nvshmem/tree/15a7764608f8211e6a564270608fb53e23e5a591). We propose moving its native implementation into `sgl-kernel` as part of the NVSHMEM transport PR, with a separately loaded extension that preserves runtime isolation from DeepEP. AFD protocol and runtime ownership remain in `srt/afd`. The existing repository and releases remain available for reproducing earlier results; packaging and release details will be agreed during review.

We will keep #45562 as the complete implementation and benchmark reference while preparing the smaller PRs, and link them here as they become available. New model integrations and other roadmap work below will be developed separately from this initial integration.

Qwen3.5 MoE is planned as a separate model integration PR after EAGLE/MTP and DSpark. Its hybrid attention state handling depends on the graph, microbatch, and speculative execution paths above; it will not expand the core AFD PR.

## Validation

The accuracy and performance results in the original PR description remain tied to their measured revisions: SGLang `34a32688a4d29082f936a7a068e579aa7465b82c` and DeepGEMM `d52c4444086268983f9ee55ba6543b26dd509838`. They describe the complete implementation at those revisions; they are not results for the intermediate PRs or a newer upstream baseline.

Each incremental PR will provide validation for its own code and affected paths. Graph changes require eager/replay and fallback checks; overlap changes require single/multiple-microbatch comparisons; shared-F changes require active/idle-session and capacity coverage. Backend and speculative changes need their corresponding numerical and model-output checks. Performance-sensitive changes will include representative timing or throughput comparisons. Model-specific paths will be covered where they change.

We propose reusing the existing test and evaluation tools, with targeted correctness and performance checks per PR and broader evaluation at selected integration points. Performance comparisons will use the same baseline and environment on both sides. Upstream changes will be assessed for additional validation, with the scope agreed during review.

## Follow-up work

### Model architectures

Model targets and integration status are listed below. Priorities depend on model demand and available hardware. For each model, track AFD integration, accuracy, and performance separately, with text generation and multimodal support qualified independently.

| Model target | Architecture | AFD integration status / next step |
| --- | --- | --- |
| [Qwen3.5 MoE](https://huggingface.co/Qwen/Qwen3.5-397B-A17B) | Hybrid Gated DeltaNet and full attention with MoE | AFD integration, with recurrent state on A, remote experts, graphs, microbatch overlap, and MTP. |
| [DeepSeek-V4.1-Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) | Causal encoder-decoder with MoE | Adapt the A/F execution schedule and layer mapping to the encoder-decoder structure. |
| [GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash) | Hybrid sparse/linear attention and mHC | Integrate the hybrid attention state and residual path with remote expert execution. |
| [Kimi K3](https://huggingface.co/moonshotai/Kimi-K3) | KDA/MLA, Attention Residuals, and latent MoE | Handle latent expert inputs/outputs, model state, and the required expert kernels. |
| [MiniMax M3](https://huggingface.co/MiniMaxAI/MiniMax-M3) | MiniMax Sparse Attention and MoE | Integrate the expert boundary with the sparse-attention execution path. |

### Quantization and kernels

- [ ] Extend coverage of existing FP8, MXFP4, and ModelOpt NVFP4 paths across model families and supported devices, with accuracy checks for each new combination.
- [ ] Extend quantization support according to target checkpoint requirements. Evaluate MXFP8 and reuse native F MoE runners where applicable.
- [ ] Improve communication/computation overlap and shared-F efficiency using measured bottlenecks; contribute component changes upstream where possible.

### Serving and deployment

- [ ] Publish representative heterogeneous A/F configurations and optimize them. A and F have been run on different GPU types internally; broader backend qualification and performance measurements are pending hardware access.
- [ ] Support F-side pipeline parallelism (PP), partitioning expert layers across F groups and pipelining microbatches across stages.
- [ ] Support expert parallel load balancing (EPLB) in AFD, coordinating expert placement, weight migration, and routing updates across A/F workers.
- [ ] Support elastic A/F scaling, starting with attention instances joining and leaving shared FFN groups at runtime.
- [ ] Extend PD + AFD validation to broader length distributions and changing request rates, including latency under sustained load.
- [ ] Provide practical A:F and microbatch sizing guidance from measurements and simulation, together with useful A/F timing and utilization metrics.

## Maintenance and collaboration

We will follow up on issues and regressions, maintain compatibility with upstream SGLang, and help review community contributions. We plan to maintain representative correctness and performance regression cases as coverage expands. Contributions of model integrations, reproducible workloads, and hardware access for heterogeneous testing are welcome.

Implementation PRs and contributors will be linked here as work progresses. We also plan a technical report on the implementation, engineering experience, A:F sizing methodology, and broader performance results.
