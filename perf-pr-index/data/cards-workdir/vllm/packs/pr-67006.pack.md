## PR body
```markdown
## Purpose

Add `nvfp4_weight_only`, online NVFP4 weight-only quantization for dense linear layers: FP16/BF16 weights are quantized at load time and run on the existing W4A16 kernel selector, with no NVFP4 checkpoint needed. MoE layers are unchanged. It is selected like the other online methods: the whole model (`--quantization nvfp4_weight_only`), chosen layers (`quantization_config.targets`), or only the drafter (`"quantization": "nvfp4_weight_only"` in `--speculative-config`).

The main use is a BF16 spec-decode drafter on bandwidth-bound GPUs: **+13.1% decode on DGX Spark and +14.1% on RTX PRO 6000 at c=1** for Qwen3.8-27B-NVFP4 + DFlash2, with acceptance length unchanged.

Also in this PR:
- W4A16 kernel selection takes the activation dtype. The CuTe-DSL and b12x kernels are BF16 only, so FP16 goes to Marlin (before, FP16 could select a BF16-only kernel on SM100/103).
- Quantization uses `scaled_fp4_quant` when available and the torch packer otherwise. Both give identical scales; codes differ only on exact E2M1 ties, with the same error.
- The global scale is reduced over TP, as online FP8 does since #49764, so the quantized weights don't depend on TP size. **This changes `draft_lm_head_quantization: "nvfp4"` numerics at TP > 1.**

Not a duplicate of #49060, which builds Marlin directly instead of using the W4A16 selector and predates the `OnlineLinearBase` requantization contract.

## Results

Qwen3.8-27B-NVFP4 + DFlash2 (k=7), BF16 drafter vs `nvfp4_weight_only` drafter, SPEED-Bench coding, OSL 8K, nightly f5d93296c8, decode tok/s:

| GPU | c=1 | c=4 | c=8 | GSM8K-256 |
|---|---|---|---|---|
| DGX Spark (GB10) | +13.1% | +22.7%* | +4.9% | 0.965 -> 0.961 |
| RTX PRO 6000 Max-Q | +14.1% | +16.2% | +1.4% | 0.961 -> 0.969 |
| GB300 | +0.1% | -2.4% | +2.9% | 0.969 -> 0.961 |

\*The c=4 arms produced different output lengths; read it as about +15 to 20%. AL is within noise in every row (GB10 c=1: 3.838 -> 3.934). Against an FP8 per-channel drafter, GB10 c=1 is +7.6%.

Whole model, Qwen3-8B: 15.27 -> 5.99 GiB, GSM8K-256 within noise of BF16 on all three GPUs, in BF16 and FP16.

TP=2 on 2x GB200: each rank's global scale equals the TP=1 scale for column- and row-parallel layers, and fails as expected when forced per rank.

Numbers are from b291bae1e0. Later commits are main merges and a docstring fix.
```
