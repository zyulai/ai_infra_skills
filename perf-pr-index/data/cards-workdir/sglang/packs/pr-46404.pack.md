## PR body
```markdown
## Motivation

With `SGLANG_SIMULATE_ACC_LEN` set, DSpark replaces the accepted length with the simulated value `c`. The bonus token, however, stays the one the real accept computed for its own length: the target argmax at the real first-mismatch row, or the rejection-sampled token at the real reject row. That token is committed after `drafts[:c]`, at a position the target never predicted it for. It is also the anchor of the next draft block. The committed text degenerates as a result, and verify batches route to fewer experts than at the same acceptance length under real verification. Simulated-acceptance throughput is therefore overstated.

The only configuration that was correct is `SGLANG_SIMULATE_ACC_GREEDY=1` with temperature-only requests, which has been opt-in since #45433. EAGLE/MTP and DFlash already take the bonus from the target at the forced row.

## Modifications

Under simulation, the bonus is the target's token at verify row `c`, drawn with the request's sampling law.

- `dspark_worker_v2.py`: every sampled batch now passes its sampling info as `simulate_bonus_sampling_info`. Before, only `SGLANG_SIMULATE_ACC_GREEDY=1` with temperature-only batches did. The flag now only selects the greedy draft/accept, under the same eligibility checks as before.
- Sampling-accept region graph (`SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH`): it stays eligible under simulation for the same batches as in real serving (all-sampled, temperature-only, no logit adjustments or grammar), so a simulated run keeps the graph that real serving uses.
  - Before the region runs, the worker stages the step's temperatures and seed with `begin_sim_bonus`.
  - Inside the region, the bonus is drawn at row `c` with the epilogue's graph-safe sampler (`sim_bonus`, renamed from `_sim_bonus`), the same kernel `SGLANG_DSPARK_SIMULATE_FOLD` uses.
  - The region's rejection accept still runs, as it does in real serving; under simulation only its length and bonus are replaced.
- `build_accept_outs`: when no sampled bonus is supplied, the bonus is the argmax of row `c`. This covers greedy batches on the eager accept and on the folded greedy accept (`DsparkVerifyEpilogue._accept` without `SGLANG_DSPARK_SIMULATE_FOLD`).
- `sample_simulated_bonus`: top-k/top-p batches sample row `c` from `build_speculative_verify_target_probs`, the target distribution the sampling accept uses. Greedy requests in a mixed batch have top_k=1, so they stay argmax. Temperature-only batches keep the existing Gumbel kernel.
- `static_accept_tail` (Triton kernel and torch reference): the argmax-id bonus is read at the committed length rather than the matched length.
- A sampled simulated bonus is broadcast on the `DSPARK_ACCEPT_SAMPLE` TP sync site, so the `rng` preset keeps ranks consistent.
- `test_dspark_simulated_bonus.py`: the sampling-info stand-in gains `need_top_k_sampling` / `need_top_p_sampling`.

Scope of the sampling law under simulation:
- Temperature and top-k/top-p are applied by the bonus sampler.
- Logit adjustments (penalties, logit bias) and grammar masks are honoured only because they are already in the verify logits when the bonus is drawn: `run_non_compact` / `run_compact` apply the adjustments and the worker applies the grammar mask. The sampler itself does neither.
- Batches with adjustments or grammar never use the region graph.
- min-p is not applied. The non-simulated sampling accept does not apply it either.

Simulated acceptance is a benchmark-only mode.

TP: a sampled bonus is broadcast from rank 0 when the `DSPARK_ACCEPT_SAMPLE` site is enabled. Without it, ranks draw from identical seeds, the same assumption the simulated-length draw and the non-simulated rejection sampler already make.

Non-simulated paths are unchanged. Every new branch is behind `simulated_correct_len is not None`, and the tail kernel's non-simulated length is still `num_correct`.

## Accuracy / correctness

Unit-level checks on GB300 run the real kernels, with drafts rejected at row 0 and simulated `c = 3`:

| path | before | after |
|---|---|---|
| eager accept, greedy batch | bonus = row-0 argmax | row-3 argmax |
| folded greedy accept, eager call and inside a CUDA graph | row-0 argmax | row-3 argmax |
| fused static accept tail (Triton) | row-0 argmax | row-3 argmax |
| top-p bonus distribution (T=0.8, p=0.7), max abs diff vs. the renormalized target, 200k draws | 0.21 | 0.0016 |
| non-simulated fused tail | unchanged | unchanged |
| sampling-accept region under simulation, bs 1/1, 3/3, 3/4 (padded); eager warm-up, capture, replays at fixed seeds | rejection bonus at the real row | equals the eager row-`c` draw; drafts at `[:c]`, bonus at `[c]` |
| region bonus distribution, 6,000 replays (T=0.8), max abs diff vs. softmax(row `c` / T) | 0.65 | 0.0099 |

Existing tests, before and after: `test_dspark_accept_tail.py`, `test_dspark_sampling_accept_graph.py` and `test_dspark_sim_draw_ahead.py` pass. `test_dspark_simulated_bonus.py::test_bf16_full_vocab_low_temperature` fails identically with and without this change on NVIDIA. It is registered for AMD CI only.

End to end: DeepSeek-V4.1-Flash FP4, DSpark block 5, TP2 EP2, GB300, AgentX-style agentic traces at 32 concurrent, temperature 1, `SGLANG_SIMULATE_ACC_LEN=3.51` (match-expected). The committed text is re-tokenized; about 1,500 turns are shared across runs.

After the fix, the remaining difference from real acceptance is in the drafted tokens. Simulation accepts them unconditionally, so repeats 2-3 tokens apart rise from 0.027 to 0.096 of tokens. Immediate repeats (0.0008 vs 0.0024) and repeats 4-6 tokens apart match real acceptance. An independent simulated-acceptance implementation that commits the target's token at the forced position measures the same statistics on this workload (0.148 / 0.182 / 0.087).

## Benchmarking and Profiling

The size of the change depends on the point: it is largest where MoE is a big share of the step and the degenerate text cut the distinct experts the most.

**TP2 EP2, 32 concurrent** (the end-to-end setup above), 3600 s:

| | total tok/s/GPU | output tok/s/GPU | ITL p50 / p90 (ms) | interactivity p50 / p90 (tok/s, 1000/ITL) |
|---|---|---|---|---|
| simulated, before | 122.2K | 697 | 3.43 / 4.40 | 291.5 / 227.3 |
| simulated, after | 118.9K | 683 | 3.85 / 4.92 | 259.7 / 203.3 |

Both runs measure AL 3.51. The "after" run is 2.7% lower in total throughput and 11% lower in p90 interactivity (11% higher p90 ITL). This is expected: the "before" run's degenerate text made MoE about 1 ms/step cheaper at B=4-10. Each number is a single run, on different nodes. These two runs applied the same change to an earlier nightly and use the eager accept (no sampling-accept graph).

**TP4 EP1, 1 concurrent, NVIDIA megakernel**, `SGLANG_OPT_DSV41_SAMPLING_ACCEPT_GRAPH=1`, `SGLANG_SIMULATE_ACC_LEN=3.51`, same traces, 1800 s, AL 3.51 in every run. At batch 1 with the experts sharded across four GPUs, MoE is a small share of the step, so the change costs about 1%. This table also shows why the sampling-accept region change is needed:

| | region graph replays | interactivity p50 / p90 (tok/s, 1000/ITL) |
|---|---|---|
| this PR | ~110k per rank | 976 / 949 |
| this PR without the region change (sampled simulated steps fall back to the eager accept) | 0 | 939 / 863 |
| before this PR (region graph with the misplaced bonus), 3600 s | captured | 987 / 954 |

Keeping the region in the graph is worth 4% / 10% at p50 / p90. The remaining ~1% to "before" is within what the text change and the shorter run can explain.
```
