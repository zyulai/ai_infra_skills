## Purpose
Flashinfer has a new allreduce API: https://github.com/flashinfer-ai/flashinfer/pull/2130
and a `mnnvl` backend for allreduce optimized for multi-node NVLink cases (https://github.com/flashinfer-ai/flashinfer/pull/1213).
The `mnnvl` backend performs [same/better](https://github.com/flashinfer-ai/flashinfer/blob/d5eaa429b1c2c3cc51fe078028551fef10ca9cc9/flashinfer/comm/allreduce.py#L261-L267) than the old `trtllm` backend that vLLM currently uses.
The new API allows choosing between the two backends. As of flashinfer 0.6.2, when `backend` is `auto`, `mnnvl` will always be chosen.

This PR 
- ~updates the allreduce fusion pass to use the new API.~ Already done by https://github.com/vllm-project/vllm/pull/33985, but 33985 only uses `trtllm` backend.
- Add env var to choose between backends. `VLLM_FLASHINFER_ALLREDUCE_BACKEND`: `[auto, mnnvl, trtllm]` (default `auto`)
- Allow flashinfer allreduce to be used standalone in the absence of rmsnorm (e.g., MoE+TP). Turn on with `VLLM_ALLREDUCE_USE_FLASHINFER=1` (default 0)
