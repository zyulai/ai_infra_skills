## PR body
```markdown
MXFP8 dense GEMM picked its backend from the blockwise-FP8 setting, so on SM120 (`auto` -> `cutlass`) it fell through to Triton. This GEMM is created earlier this year and can't achieve good perf in most shapes.

Resolve the MXFP8 dense backend separately: SM120 keeps `cutlass` for blockwise FP8, MXFP8 goes to FlashInfer CUTLASS. Delete the Triton MXFP8 dense kernel; the DeepGEMM shape/dtype fallback now uses FlashInfer.

### Benchmark

Speedup of FlashInfer CUTLASS over the deleted Triton path, on `Qwen/Qwen3.6-27B-FP8` dense linear shapes at TP=1 (assuming MXFP8 weights). 1x RTX PRO 6000 Blackwell Server Edition (sm120).
```
