## PR body
```markdown
- `window_layout` now computes each history slot's source row (`history_src`: `row_loc` of the slot's request and position, or the zero row when invalid) once per batch and stores it in `WindowLayout`, instead of `RequestWindow.buffer` recomputing it in every layer through `_history_src`. It takes the window's `zero_row` to do so.
- `WindowLayout.copy_` copies the new field, so a captured layout refreshed in place for graph replay carries the current batch's rows.
- The two `window_layout` callers (the CUDA and HIP DeepSeek V4 backends) and the tests that build a layout pass `zero_row`.
- DeepSeek V4.1 Flash on GB300, DEP4: `row_loc` and `_history_src` take 4.1-4.8% and up to 2.9% of the scheduler thread at 4K tokens per rank, and 3.2% and 1.7% in a multi-turn prefill workload at 640 concurrent sessions, all per layer under `get_swa_raw_buffer`. With this change and the V4.1 index-K slot snapshot (#45577) together, the 4K step goes from 106-110 to 98.7 ms (one run per arm); this change alone was not measured.

No behavior change; only applies with encoder SWA bounded replay.
```
