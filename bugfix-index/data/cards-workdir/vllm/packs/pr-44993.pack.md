## 正文(PR 描述)

### Purpose

Fixes #43388. Fixes #48228. Fixes #34650.

Under async scheduling + speculative decoding + a Qwen-style reasoning parser, `should_advance` in `vllm/v1/structured_output/__init__.py` silently fails for JSON/regex/choice constraints. Two distinct bugs interact:

**Bug 1: the delta window misses the marker.** The delta window computed from `num_computed_tokens - num_output_placeholders` skips `</think>` whenever some drafts are rejected, because the placeholder count stays greater than zero. As a result `reasoning_ended` never flips, the grammar is never enforced, and the output contains Markdown fences or arbitrary prose.

**Bug 2: post-marker tokens never reach the FSM.** Even after `reasoning_ended` flips, the post-marker content tokens produced in the marker step never enter the grammar FSM. On the next step the bitmask is prepared with the grammar at its initial state, the model emits the opening token again, and `response_format=json_object` returns `{{...}` content — HTTP 200, but the body fails to parse on the client (the exact symptom reported in #48228).

This PR closes the inter-step state leak in `should_advance`. The sibling intra-step bitmask leak in `grammar_bitmask` was fixed by #44297 (merged); the patch sites are independent, and together they cover the full reasoning → content boundary under async + speculative decoding.

### Design

One unified boundary path for **all** constraint types (final shape reached through review with @yzong-rh):

1. `should_advance` accepts an optional `new_token_ids` argument from the scheduler call site and uses it as the exact delta window (fixes Bug 1). The two draft-validation call sites keep the placeholder fallback; their behavior is unchanged.
2. At the boundary, `should_advance` records `reasoning_end_token_index` and returns `True` for every constraint type. The scheduler then uses `trim_reasoning_for_advance()` + `accept_tokens()` to advance only the verified post-marker suffix (fixes Bug 2). `should_advance` no longer mutates the grammar — it only updates reasoning-boundary state and decides whether the scheduler should advance.

Earlier revisions used a conservative inline drain for JSON/regex/choice (advance inside `should_advance`, return `False`) while `STRUCTURAL_TAG` under spec decode used the scheduler's trim-and-advance path — two paths for the same boundary. The final revision removes that split: post-marker positions inside a speculative window are already constrained by `grammar_bitmask`, and rejection sampling prevents grammar-invalid drafts from being committed, so the committed suffix reaching `accept_tokens` is grammar-valid. Net effect on vLLM-side complexity: no per-constraint-type branching, no grammar side effects outside the scheduler, and a single boundary mechanism that any future backend-side delegation would migrate as one unit.

One intentional semantics change: an `accept_tokens` rejection at the boundary (not expected in the normal flow, per the invariant above) now terminates the request through the scheduler's standard error path instead of warn-and-continue, matching the existing non-reasoning path.

### Why this is not duplicating an existing PR

- #36138 (merged) fixed the spec-decode × structured-output bypass for single-token markers, but its placeholder math underflows past the marker under async scheduling + draft rejection (Bug 1) — #43388 still reproduced on Qwen3.5 + MTP.
- #43526 (closed) took the same first step but was closed by its author because post-marker tokens in the same batch were left unobserved by the FSM; this PR closes that gap.
- #43424 (open) targets multi-token markers (gpt-oss Harmony) via a different code path (`precommit_filter_tokens`); the scopes are complementary and can land in either order.

Client sends 50 requests asking for a JSON object describing Seoul, with `response_format={"type":"json_object"}` and `enable_thinking=true`, without forbidding Markdown (so the model falls back to its training-time formatting habit). Each response is classified as `ok` (raw JSON, parses, has required keys), `markdown_fence`, `leading_garbage`, `bad_json`, etc.

````python
import json, os, re, time
from collections import Counter
from openai import APIStatusError, OpenAI

BASE_URL = os.environ.get("VLLM_BASE_URL", "http://127.0.0.1:8000/v1")
MODEL = os.environ.get("VLLM_MODEL", "qwen3.5-35b-a3b")
TRIALS = int(os.environ.get("TRIALS", "50"))

MESSAGES = [{"role": "user", "content": "Give me a JSON object describing Seoul, with keys city, country, and population."}]
REQUIRED_KEYS = ("city", "country", "population")

def classify(content):
    if not content or not content.strip():
        return "empty", ""
    raw = content
    s = content.strip()
    if s.startswith("```"):
        return "markdown_fence", s[:120]
    if raw[0] != "{":
        return "leading_garbage", repr(raw[:40])
    m = re.search(r"\{.*\}", s, re.DOTALL)
    if not m:
        return "no_json", repr(s[:80])
    if m.group(0) != s:
        return "prose_wrapped", s[:120]
    try:
        obj = json.loads(s)
    except json.JSONDecodeError as e:
        return "bad_json", str(e)
    for k in REQUIRED_KEYS:
        if k not in obj:
            return "bad_json", "missing " + repr(k)
    return "ok", json.dumps(obj, ensure_ascii=False)[:120]

def main():
    client = OpenAI(base_url=BASE_URL, api_key="EMPTY", max_retries=0, timeout=120.0)
    counts = Counter()
    t0 = time.time()
    print("target:", BASE_URL, "model:", MODEL, "trials:", TRIALS)
    for i in range(1, TRIALS + 1):
        try:
            r = client.chat.completions.create(
                model=MODEL, messages=MESSAGES,
                response_format={"type": "json_object"},
                extra_body={"chat_template_kwargs": {"enable_thinking": True}},
                temperature=0.6, top_p=0.95, max_tokens=4096,
            )
            kind, detail = classify(r.choices[0].message.content or "")
        except APIStatusError as e:
            kind, detail = "http_error", "HTTP " + str(e.status_code)
        except Exception as e:
            kind, detail = "client_error", type(e).__name__
        counts[kind] += 1
        print("[%3d/%d] %-20s %s" % (i, TRIALS, kind, detail), flush=True)
    print("\nsummary (%.1fs):" % (time.time() - t0))
    for k, n in counts.most_common():
        print("  %-20s %d" % (k, n))
    bug = counts["markdown_fence"] + counts["prose_wrapped"] + counts["no_json"] + counts["bad_json"] + counts["leading_garbage"]
    print("\nFAIL %d/%d" % (bug, TRIALS) if bug else "\nPASS %d/%d" % (counts["ok"], TRIALS))

if __name__ == "__main__":
    main()
````
