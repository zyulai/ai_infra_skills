## PR body
```markdown
## Motivation

With `ep_dispatch_algorithm=static`, every EPLB rebalance rebuilds the per-rank dispatch map in `compute_logical_to_rank_dispatch_physical_map`. It calls `_find_nearest_expert` in Python once per (layer, logical expert, rank). For DeepSeek-V4.1-Flash at DEP32 that is 40 x 384 x 32 calls, which take 250-290 ms on every rank on each rebalance while the whole DP group waits.

## Modifications

- `_compact_candidates`: move each row's valid physical ids to the front, keeping their original order.
- `_nearest_expert_dispatch`: pick the same-GPU replica, otherwise the same-node replica when it narrows the candidate set, using tensor ops over the replica slots. Rows with a single replica broadcast it. This is the same rule as `_find_nearest_expert`, which still serves the startup collapse in `_compute_logical_to_all_physical_map`.
- Only the (layer, expert, rank) entries left unresolved still go through `_fair_choices` with the seeded `random.Random`, in the same row-major order. The output is therefore bitwise identical to the previous implementation.
- Scratch tensors are created on the input map's device, and `_logical_to_all_physical_raw`, which lost its last caller, is removed.

## Accuracy

Placement is unchanged. Bitwise comparisons against the previous function, all equal:

- 96 cases: 12 layouts x 2 shapes x 4 ranks, scattered -1 padding, with and without the node topology.
- 17,430 random layouts x ranks: ep 1-16, 1-8 nodes, scattered -1 padding, duplicate ids, int32/int64.
- 12,910 random layouts x ranks at the head: ep 1-32, 1-8 nodes, shuffled candidate order (so first-match order is exercised, not just smallest id), scattered -1 padding, duplicate ids, int32/int64, node preference on and off.

## Performance

Time per call:

| shape | before | after |
|---|---:|---:|
| 40 layers x 384 logical / 416 physical, ep 32 | 255 ms | 39 ms |
| 3 layers x 128 logical / 160 physical | 5.6 ms | 9.1 ms |

The small shape gets a few ms slower from tensor-op overhead; the large one, where the time matters, is 6.5x faster.

End to end, DeepSeek-V4.1-Flash disaggregated serving on GB300 (DEP32 decode, 8 nodes), EPLB every 15000 iterations, AgentX 3600 s at concurrency 3018, one same-day run per arm:

| | before | after |
|---|---:|---:|
| rebalance pause p50 | 0.734 s | 0.467 s |
| total token throughput per GPU | 458.7k | 466.6k (+1.7%) |
| interactivity mean (tok/s/user) | 346.2 | 354.4 (+2.4%) |
| interactivity p90 (tok/s/user) | 326.7 | 339.8 (+4.0%) |
| TTFT p95 | 9.33 s | 7.81 s |

The rebalance pause shrinks by 0.27 s, in line with the per-call saving; that is the effect of this change. At one rebalance per 15000 iterations the pause is a small share of the run's wall time, so the throughput, interactivity, and TTFT deltas, from a single run per arm, are larger than the removed pause alone accounts for and should not be read as its effect. The gain grows with rebalance frequency and EP size.
