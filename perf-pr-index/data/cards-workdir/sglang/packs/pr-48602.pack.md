## Port of #48414

This port takes the Kimi-K3.1 branch's opt-in DSA backend `--dsa-prefill-backend prims_ts` / `--dsa-decode-backend prims_ts`. It runs FlashInfer's Prims-TS sparse MLA (`BatchSparseMLADecodePagedTSWrapper`: D576, native E4M3 KV, E4M3 query, FP8 MMA, natural-log LSE) instead of trtllm-gen, on the existing `trtllm` DSA route. The route stays the same end to end (raw FP8 MLA cache, q quantize/concat, KV store, top-k transforms, row plan, DCP page-table localization); only the attention kernel call changes. It is faster than trtllm-gen and FlashMLA at decode, and its cache needs fewer bytes per token than FlashMLA's (see Speed). The defaults do not change.

It needs FlashInfer 0.7.4 (#49771), which ships Prims-TS D576 native-FP8 sparse MLA: flashinfer-ai/flashinfer#7410 and flashinfer-ai/flashinfer#7984, plus flashinfer-ai/flashinfer#8186 for SM107.

It takes all of the branch's `prims_ts` code that main now has a base for. That includes Kimi-K3.1, under its sharded index-K DCP, now that main has that DCP and Kimi-K3.1's opt-in `trtllm` DSA backend. It also includes SM107 (Rubin) support.

What changed against the raw port:
- **Main's row plan.** `_forward_prims_ts` restores rows with `_restore_live_rows(row_plan)`, as main's `_forward_trtllm` does, as the branch now does too.
- **Tests.** The branch's `prims_ts` tests lived in its sharded-DCP test file, which main does not have. Here they are a new file, `test_dsa_prims_ts.py`, with the same cases:
  - the DCP8 partial merge at 24 rows (exact plan) and 1025 rows (packed plan);
  - the combine's LSE base per DCP mode, patched at `layers/dcp/layout.py`, where main keeps `is_mla_dcp_lse_base_on_e`.

  The file is registered on B200 rather than `1-gpu-large` (H100), since the kernel needs SM100/SM103/SM107. With FlashInfer 0.7.4 pinned, a planning failure on those GPUs now fails the test instead of skipping it.
- **Docs.** The two DSA backend tables list `prims_ts`.
- **KV scale.** `_forward_prims_ts` rejects a checkpoint KV scale (`k_scale != 1`). The raw FP8 store writes K/V unscaled, and `trtllm` applies `k_scale` to the logits only, so the branch's output scaling by `k_scale` would make `prims_ts` diverge from `trtllm`. Kimi-K3.1 has no KV scale.
- **Overlap check.** `DSAInterleaveCPIndexerOverlap._can_overlap` unwraps `TboAttnBackend` and narrows the backend with `isinstance(DeepseekSparseAttnBackend)` instead of a `getattr` of `dsa_prefill_impl`.
- **The SM107 change.** Its FlashInfer overlay in the branch's container image is not taken: main installs FlashInfer 0.7.4 as a package.

Left for the port of the branch's fused FP8 q builder (`_trtllm_q_fp8`): its no-head-padding mode for `prims_ts` (`pad_heads=not use_prims_ts`). Without the builder, `prims_ts` reads q from main's FP8 quantize path, which already keeps the layer's head count; main pads heads only right before trtllm-gen.

Left for the port of the branch's alt-stream decode absorb: its raw-FP8 branch in `forward_mla.py`, which skips the adjacent bf16 q buffer.

## Modifications

- `layers/attention/dsa/prims_ts.py` (new):
  - `PrimsTSSparseMLA` holds the planned launches. Plans are exact per row count up to 1024 rows and use power-of-two packed capacities above that.
  - Plans are made on eager calls; the CUDA-graph warmups plan every captured row count, and replays call `run(validate=False)`.
  - `check_prims_ts_sparse_mla_support` is the startup check (D576 MLA, SM100/SM103/SM107, and an installed FlashInfer that can plan the kernel). If FlashInfer refuses, its reason is part of the error.
- `dsa_backend.py`:
  - `prims_ts` joins `_DSA_IMPL_T`.
  - `uses_raw_fp8_dsa_kv_layout(backend)` (`trtllm` or `prims_ts`) replaces the `== "trtllm"` layout checks.
  - Backend init rejects a non-`fp8_e4m3` KV cache, a GPU or FlashInfer that cannot run the kernel, and replicated index-K DCP (`_validate_prims_ts_dcp`). That DCP combine merges base-2 LSE partials, while Prims-TS returns a natural-log LSE. Under Kimi-K3.1's sharded index-K the combine merges non-trtllm partials base e, so `prims_ts` is accepted there.
  - `_forward_trtllm(use_prims_ts=...)` hands off to `_forward_prims_ts` once the q, KV store, row plan and page table are ready. Prims-TS runs any head count, so q is not padded.
  - Under DCP, `_forward_prims_ts` returns the partial and its LSE for the merge. A sharded-DCP decode partial keeps the owned-row lengths from the localized page table.
  - `_forward_prims_ts` rejects `k_scale != 1` (see above).
- `arg_groups/fields/exec_.py`: adds `prims_ts` as a choice for both DSA backend flags.
- `arg_groups/overrides.py`:
  - `prims_ts` needs CUDA and `--kv-cache-dtype fp8_e4m3`.
  - Kimi-K3.1 admits `prims_ts` next to `flashmla_kv` and `trtllm`. It warns that the numerics differ from the reference `fp8_ds_mla`, and that PD peers must both use a raw-FP8-KV backend.
- `mem_cache/kv_cache_configurator.py`, `forward_mha.py`, `forward_mla.py` (`_fuse_rope_for_trtllm_mla`), `layers/cp/interleave.py`: treat `prims_ts` like `trtllm` through `uses_raw_fp8_dsa_kv_layout`. The interleave overlap check narrows the backend by type.

An unset phase gets a layout-compatible backend:
- For Kimi-K3.1, it follows the set phase.
- On other Blackwell FP8 models, it defaults to `trtllm`, which uses the same 576 B/token layout.

In PD disaggregation, both servers need a raw-FP8-KV backend (`trtllm` or `prims_ts`).

## Accuracy

All measured on the Kimi-K3.1 branch (#48414):
- **Kernel against an FP32 reference** on its own inputs: 1.1-1.6% relative L2 (FlashMLA: 0.2%). The error comes from rounding the softmax probabilities to E4M3. The LSE matches to 2e-6.
- **Prims-TS against FlashMLA:** 4.1-4.5% output error. There were no NaN/Inf mismatches. A row with no keys gives zero output and a -inf LSE.
- **GSM8K** (all 1319 questions; only the backend flag changed): 0.9704 with Prims-TS vs 0.9697 with FlashMLA.

## Speed

Kernel time per DSA layer (us), measured on the Kimi-K3.1 branch: GB300, 96 heads, about 256 keys per row (one DCP8 rank's share of 2048 top-k), 6 query rows per request, cold L2, CUDA graph.

| Requests | FlashMLA (`flashmla_kv`) | Prims-TS (`prims_ts`) | Speedup |
|---:|---:|---:|---:|
| 1 | 16.0 | 11.7 | 1.37x |
| 4 | 21.2 | 9.9 | 2.14x |
| 16 | 35.2 | 14.5 | 2.43x |
| 32 | 62.6 | 18.7 | 3.35x |
| 64 | 97.8 | 29.5 | 3.32x |

- trtllm-gen takes 13-38 us over this range, so Prims-TS is 1.15-1.8x faster than it.
- Compared with FlashMLA, the kernel reads the FP8 cache without dequantizing it, makes one pass for up to 128 heads, and is a single kernel from 24 rows up.
- The raw cache takes 576 B per token instead of fp8_ds_mla's 656 B. On Kimi-K3.1 that gave about 9% more KV tokens.
- End to end on Kimi-K3.1 (agg TP8/DCP8): sparse-MLA time per decode step fell from 891 us to 332 us, about 1.7% of a ~32 ms step.

Not yet covered:
- An eager batch with an unseen row count (up to 1024 rows) plans and keeps one more plan. Its workspace is allocated after `--mem-fraction-static` has sized the KV pool.
- The first use compiles the kernels (about 100 s extra in CUDA-graph capture). Point `FLASHINFER_WORKSPACE_BASE` at a persistent path to keep the cache.
- Prefill speed against the other prefill backends has not been measured.

+"""FlashInfer Prims-TS sparse MLA for the DSA backend (``prims_ts``).
+
+The kernel reads the raw FP8 MLA cache rows that the ``trtllm`` DSA backend writes
+(576 B/token: 512 NoPE + 64 RoPE E4M3, one per-tensor scale) with an E4M3 query
+and FP8 QK/PV MMA, and returns BF16 output with a natural-log LSE. It shares the
+``trtllm`` route's query preparation, KV store, top-k transforms and DCP slot
+localization; only the attention kernel differs.
+"""
+
+from __future__ import annotations
+
+from typing import Optional
+
+import torch
+
+# Each row count up to this gets its own kept plan, for graph shapes and eager
+# batches alike; larger batches share power-of-two capacity plans.
+_EXACT_PLAN_MAX_ROWS = 1024
+
+# B200, B300/GB300 and Rubin; SM107 needs flashinfer-ai/flashinfer#8186.
+_SUPPORTED_DEVICE_CAPABILITIES = ((10, 0), (10, 3), (10, 7))
+
+
+def _plan_capacity(rows: int) -> Optional[int]:
+    """None plans exactly ``rows`` fixed rows; otherwise the packed row capacity."""
+    if rows <= _EXACT_PLAN_MAX_ROWS:
+        return None
+    return 1 << (rows - 1).bit_length()
+
+
+def check_prims_ts_sparse_mla_support(
+    *, device: torch.device, num_heads: int, kv_lora_rank: int, qk_rope_head_dim: int
+) -> None:
+    """Fail at startup, not at the first forward, when the installed FlashInfer
+    cannot plan the D576 native-E4M3 sparse MLA this backend needs."""
+    if (kv_lora_rank, qk_rope_head_dim) != (512, 64):
+        raise ValueError(
+            "--dsa-*-backend prims_ts supports D576 MLA "
+            f"(kv_lora_rank 512, qk_rope_head_dim 64); got {kv_lora_rank}, "
+            f"{qk_rope_head_dim}."
+        )
+    if torch.cuda.get_device_capability(device) not in _SUPPORTED_DEVICE_CAPABILITIES:
+        raise ValueError("Prims-TS sparse MLA requires SM100, SM103 or SM107.")
+    try:
+        from flashinfer.attention.prims_ts import (
+            get_prims_ts_sparse_mla_decode_workspace_size,
+        )
+
+        get_prims_ts_sparse_mla_decode_workspace_size(
+            device,
+            1,
+            num_heads,
+            max_topk=2048,
+            q_dtype=torch.float8_e4m3fn,
+            qk_rope_head_dim=qk_rope_head_dim,
+            kv_cache_format="native",
+            return_lse=True,
+        )
+    except (ImportError, TypeError, ValueError, NotImplementedError) as exc:

+            "--dsa-*-backend prims_ts needs FlashInfer Prims-TS with D576 native-FP8 "

+                q=q8,
+                kv_cache=cache,
+                indices=table,
+                lengths=lens,
+                sm_scale=SM_SCALE,
+                kv_scale=1.0,
+            )
+
+        full, full_lse = attend(kv, slots, counts)
+        outs, lses = [], []
+        for rank in range(dcp):
+            table, lens = _localize(slots, dcp, rank)
+            o, lse = attend(kv[rank::dcp].contiguous(), table, lens)
+            if rank:
+                self.assertTrue(torch.isneginf(lse[0]).all().item())
+                self.assertFalse(o[0].any().item())
+            outs.append(o.float())
+            lses.append(lse)
+        # (rows, heads, width, packed) plan keys: rows past the exact limit pack
+        packed = rows > _EXACT_PLAN_MAX_ROWS
+        self.assertEqual({key[3] for key in runner._plans}, {packed})
+        lse = torch.stack(lses)  # natural log
+        w = torch.exp(lse - lse.max(0).values)
+        merged = (w.unsqueeze(-1) * torch.stack(outs)).sum(0) / w.sum(0).unsqueeze(-1)
+        merged_lse = torch.log(w.sum(0)) + lse.max(0).values
+
+        qf, kvf = q8.float(), kv.float()
+        ref = torch.empty_like(full, dtype=torch.float32)
+        ref_lse = torch.empty_like(full_lse)
+        for r in range(rows):
+            k = kvf[slots[r, : counts[r]].long()]
+            s = (qf[r] @ k.T) * SM_SCALE
+            ref_lse[r] = torch.logsumexp(s, dim=-1)
+            ref[r] = torch.softmax(s, dim=-1) @ k[:, :KV_LORA]
+
+        def rel(a):
+            return ((a.float() - ref).norm() / ref.norm()).item()
+
+        self.assertLess(rel(full), 0.03)
+        self.assertLess(rel(merged), rel(full) * 1.2)
+        torch.testing.assert_close(full_lse, ref_lse, atol=2e-2, rtol=2e-3)
+        torch.testing.assert_close(merged_lse, full_lse, atol=1e-3, rtol=1e-3)
+
+    def test_dcp8_partials_merge_to_full(self):
+        self._check_dcp8_partials_merge_to_full(rows=24)
+
+    def test_packed_rows_dcp8_partials_merge_to_full(self):
+        # Past the exact-plan limit: power-of-two packed capacity with qo_indptr.
+        self._check_dcp8_partials_merge_to_full(rows=_EXACT_PLAN_MAX_ROWS + 1)
