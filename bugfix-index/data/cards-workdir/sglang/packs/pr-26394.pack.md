## Motivation

  When `poll_and_all_reduce` returns `KVPoll.Success`, it only confirms KV cache transfer completion. The data written via a separate RDMA op may not have landed on all ranks yet. If one rank sees metadata ready and removes the request from its queue while another rank keeps it, the queues diverge across TP ranks. Subsequent all-reduce calls operate on misaligned tensors, causing hangs or silent corruption.

## Modifications
  - Add `_apply_metadata_gate()` helper that downgrades `Success → Transferring` for requests whose `bootstrap_room` field is still zero (the "not yet written" sentinel) on the decode side, no need to allreduce the metadata checksum
  - Call it inside `poll_and_all_reduce` and `poll_and_all_reduce_with_staging` (opt-in via new optional params) before the single all-reduce
