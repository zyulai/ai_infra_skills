## Motivation
#33576 added four Lean persistent-grid buffers to `ForwardMetadata`, but filled them in at only 2 of the 5 construction sites. The spec-decode capture path (`triton_backend.py:667`) is decode-mode, so it reaches the Lean kernel — with `locks=None`. `locks.zero_()` then kills the scheduler, and both EAGLE test files report 0 tests run on AMD CI:
```
File "python/sglang/kernels/ops/attention/decode_attention.py", line 2004, in _decode_lean_attention_fwd
    locks.zero_()
AttributeError: 'NoneType' object has no attribute 'zero_'
```
ROCm-only, since the Lean dispatch is `_is_hip`-gated.
## Modifications
- `triton_backend.py`: pass the same `cuda_graph_lean_*` buffers the non-spec capture path already passes.
- `decode_attention.py`: require `lean_locks is not None` to select Lean, so a missing buffer falls back to the standard kernel instead of crashing.
## Accuracy Tests
Not applicable — restores a code path that currently aborts. Lean numerics unchanged.
## Speed Tests and Profiling
Not applicable.
## Test
On MI355X, `decode_attention_fwd` with `enable_lean=True` and the buffers absent: reproduces the `AttributeError` before, returns finite output after.
Addresses the EAGLE failures in `test_adaptive_speculative.py` and `test_eagle_constrained_decoding.py`.
