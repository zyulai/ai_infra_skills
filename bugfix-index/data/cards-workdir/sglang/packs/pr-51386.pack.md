## 正文(PR 描述)

## Motivation

#50740 turned the per-request DFLASH draft KV ring on by default for all-sliding-window MHA drafts (on top of the MLA ring from #49664). Each PD role decides whether to use the ring from its own launch flags only. So when one role can't serve the ring and the other can, the two servers register different state entries and the decode scheduler crashes at bootstrap.

This is what breaks `test_glm53_cp_bcg_dflash.py` on main (extra-b-test-8-gpu-b300, [run](https://github.com/sgl-project/sglang/actions/runs/44196383565/job/134439923646)):
- The prefill runs `--attn-cp-size 4 --enable-prefill-cp`, so the ring turns itself off ("an MHA draft's ring has no context-parallel layout").
- The decode has no CP, so its ring turns on.
- The decode then fails with:

```
RuntimeError: PD state entry mismatch: only the decode server registers a DFLASH draft KV ring
```

Heterogeneous-TP PD deployments fail the same way.

## Modifications

- `SGLANG_ENABLE_DFLASH_DRAFT_KV_RING` now defaults to `False`, so the ring is opt-in.
- `_resolve_dflash_draft_kv_ring`: if the switch is set and the launch can't serve the ring, the server now raises a `ValueError` at launch. Before this change, an unset switch fell back silently, and only an explicit `=1` raised. With the new default that silent-fallback branch can never run, and a silent fallback on one PD role is exactly what causes the mismatch above.
- The PD mismatch message now tells the user to unset the switch on the side that registers the ring, or to set it on both sides.
- Updated the `speculative_dflash_draft_kv_ring` help text, the Kimi-K3.1-Pro cookbook notes, and the Kimi K3.1 mamba-ratio calculator. The calculator now counts the ring only when `=1` is set.
- Unit tests: added tests that the ring is off by default, and changed the "off for unsupported launch / draft" cases so they now expect the launch-time error under an explicit opt-in.

## Behavior change

The MLA ring (Kimi-K3.1 DFLASH on `trtllm_mla` / `cutedsl_mla`) is now off by default too. Deployments that want the ~15% extra target KV need to set `SGLANG_ENABLE_DFLASH_DRAFT_KV_RING=1` on both PD roles.

To keep the recommended Kimi-K3.1-Pro deployment unchanged, the cookbook's DFLASH option now sets `SGLANG_ENABLE_DFLASH_DRAFT_KV_RING=1` on every NVIDIA cell, including both PD roles. MI350X / MI355X are left alone because they use the Triton draft backend, which has no ring. I rendered every Kimi cell to confirm this. Two things are deliberately left unchanged:
- The generated AgentX snippet (`docs/src/snippets/agentx/...`): it is synced from InferenceX and pins its own image.
- Muse-Spark-Open (MHA ring): it stays off by default.
