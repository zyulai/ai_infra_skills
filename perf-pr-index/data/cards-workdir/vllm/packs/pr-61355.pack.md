## Overview

Tune the existing Triton packed GDN decode launch on SM100-family GPUs. Smaller value tiles improve utilization at small batches and reduce per-CTA work with FP32 recurrent state.

## Claims

- **1.34–1.74× faster kernel** at B=1–64 for the Qwen3.8-Flash-Next TP4 layout with FP32 state on GB300; **1.21–1.34×** at B=1/2/4 with BF16 state.
- **1.0–2.2% higher output throughput** in Qwen3.8-Flash-Next-FP8 serving, with unchanged full GSM8K and C=8 check scores.
- A 12-line dispatch change; existing kernel math and interfaces are preserved. FlashInfer is benchmarked as a comparison candidate only and is **not integrated by this PR**.

## Validation

```python
import importlib.util
import json
import random
import statistics
import subprocess
import tempfile
from pathlib import Path

import torch
from flashinfer.gdn_decode import gated_delta_rule_decode_pretranspose
from flashinfer.testing import bench_gpu_time_with_cupti
from vllm.third_party.flash_linear_attention.ops.fused_recurrent import (
    fused_recurrent_gated_delta_rule_packed_decode as tuned,
)

BASE = '28d679e762a0b6ed560d767a76ebe02699bf5c46'
FILE = 'vllm/third_party/flash_linear_attention/ops/fused_recurrent.py'
source = subprocess.check_output(['git', 'show', f'{BASE}:{FILE}'], text=True)
with tempfile.TemporaryDirectory() as directory:
    path = Path(directory) / 'baseline.py'
    path.write_text(source)
    spec = importlib.util.spec_from_file_location(
        'vllm.third_party.flash_linear_attention.ops._gdn_baseline', path
    )
    baseline = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(baseline)

    generator = torch.Generator(device='cuda').manual_seed(1234)
    order_rng = random.Random(1234)
    for state_dtype in [torch.float32, torch.bfloat16]:
        for batch in [1, 2, 4, 8, 16, 32, 64]:
            mixed = torch.randn(batch, 2560, device='cuda',
                                dtype=torch.bfloat16, generator=generator) * .1
            a = torch.randn(batch, 12, device='cuda', dtype=torch.bfloat16,
                            generator=generator)
            b = torch.randn(batch, 12, device='cuda', dtype=torch.bfloat16,
                            generator=generator)
            al = torch.zeros(12, device='cuda')
            dt = torch.zeros_like(al)
            ids = torch.arange(1, batch + 1, device='cuda', dtype=torch.int32)
            initial = torch.randn(batch + 1, 12, 128, 128, device='cuda',
                                  dtype=state_dtype, generator=generator) * .1
            # FlashInfer ideal case: Q/K/V layout conversion is outside timing.
            q = mixed[:, :512].view(batch, 1, 4, 128).contiguous()
            k = mixed[:, 512:1024].view(batch, 1, 4, 128).contiguous()
            v = mixed[:, 1024:].view(batch, 1, 12, 128).contiguous()
            states = {name: initial.clone() for name in ['main', 'PR', 'FI']}
            outputs = {name: torch.empty(batch, 1, 12, 128, device='cuda',
                                        dtype=torch.bfloat16) for name in states}
            calls = {}
            for name, fn in [('main', baseline.fused_recurrent_gated_delta_rule_packed_decode),
                             ('PR', tuned)]:
                calls[name] = lambda fn=fn, name=name: fn(
                    mixed, a, b, al, dt, 128**-.5, states[name], outputs[name], ids, True
                )
            calls['FI'] = lambda: gated_delta_rule_decode_pretranspose(
                q=q, k=k, v=v, state=None, A_log=al, a=a.view(batch, 1, 12),
                dt_bias=dt, b=b.view(batch, 1, 12), scale=128**-.5,
                output=outputs['FI'], use_qk_l2norm=True,
                initial_state=states['FI'], initial_state_indices=ids,
                backend='flashinfer',
            )
            for call in calls.values():
                for _ in range(10):
                    call()
            torch.testing.assert_close(outputs['PR'], outputs['main'], atol=0, rtol=0)
            torch.testing.assert_close(states['PR'], states['main'], atol=0, rtol=0)
            torch.testing.assert_close(outputs['FI'], outputs['main'], atol=1e-3, rtol=1e-3)
            tol = (1e-5, 1e-5) if state_dtype == torch.float32 else (1e-3, 1e-2)
            torch.testing.assert_close(states['FI'], states['main'], atol=tol[0], rtol=tol[1])
            times = {name: [] for name in calls}
            for _ in range(7):
                order = list(calls)
                order_rng.shuffle(order)
                for name in order:
                    states[name].copy_(initial)
                    for _ in range(30):
                        calls[name]()
                    times[name].append(statistics.median(bench_gpu_time_with_cupti(
                        calls[name], dry_run_iters=5, repeat_iters=40,
                        use_cuda_graph=True, cold_l2_cache=True,
                    )) * 1000)
            print(json.dumps(dict(batch=batch, state=str(state_dtype),
                                  us={name: statistics.median(t) for name, t in times.items()})))
```

## Details

For `K=V=128` on CUDA SM100-family GPUs, select BV4 when `B × HV <= 64`, BV8 otherwise for FP32 recurrent state, and retain BV32 otherwise. Warps and stages stay at 1 and 3. The baseline launches `4 × B × HV` CTAs; BV4 provides eight times as many at small batches. Larger batches with 16-bit state keep BV32 because smaller tiles regressed those workloads in tuning.

The capability query uses the input tensor's device. Existing MRv2 warmup/graph capture compiles the reachable variants; no extra warmup, GPU synchronization, or online autotuning is introduced. Prefill and speculative verification use separate paths.

The serving A/B used baseline `28d679e762` and the PR's GDN module in fresh processes on the same node, with identical diagnostics. GPU validation was collected before rebasing onto `e2ad0ce5f5`; all three patches and the changed GDN source/test files are unchanged. Post-rebase lint passed; no further serving sweep was run.

Duplicate checks found no open PR implementing this SM100-family policy. Related [#54181](https://github.com/vllm-project/vllm/pull/54181) tunes SM120, [#60400](https://github.com/vllm-project/vllm/pull/60400) tunes ROCm, and [#60403](https://github.com/vllm-project/vllm/pull/60403) adds opt-in FlashInfer decode; their hardware/backend scope differs.
