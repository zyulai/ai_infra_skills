## Motivation

This PR is to fill gaps in FA4 path on Blackwell:
1. **The softmax row max ignores an sm_103 instruction.** Blackwell Ultra adds `tcgen05.ld.red`, a TMEM load that also returns a per-thread reduction of the loaded values. We can use it to get each row's max for free while reading S out of TMEM. Currently SGLang FA4 forward does not: on B300 every softmax step still reduces 128 values per row with FMNMX3.
2. **ViT attention on B300 falls back to Triton.** #25570 switched the default multimodal attention backend on SM103 from `fa4` to `triton_attn` because "FA4 is not yet validated on B300". Measured on B300, FA4's kernel is 2–20x faster than the Triton kernel on ViT shapes (head dims 64/72/80/128) and matches it numerically, so B300 ViTs pay a large, avoidable cost.
3. **The ViT CUDA graph runners do not support `fa4`.** `SGLANG_VIT_ENABLE_CUDA_GRAPH=1` only handles `triton_attn` and `fa3`; with `fa4` (already the default on SM100) the server dies at startup with `AssertionError: cu_seqlens must be a torch.Tensor`. Changing the SM103 default without fixing this would break every B300 deployment that turned the ViT graph on. The graph is also what removes FA4's per-call host overhead for small images (see Speed Tests).


## Modifications

- `flash_fwd_sm100.py`: on sm_103, build a second TMEM copy with `tcgen05.LdRed32x32bOp(redOp=MAX)`. In `softmax_step`, tiles that need no masking (`mask_fn is None`) in kernels without `score_mod`/bias load S with it — one `cute.copy_atom_call` per 32-column chunk, each also returning that chunk's max — and pass the reduced max to the softmax. Masked tiles keep the plain load and the software max, because the hardware max is taken over the raw S. On the tiles where it is used the hardware max equals the software reduction exactly, so **outputs are bit-identical** to the current kernel. The first-iteration tile is always masked (`mask_seqlen=True`), so only steady-state tiles change.
- `softmax.py`: `SoftmaxSm100.update_row_max` accepts an optional precomputed `tile_row_max`; everything after the max (fast `exp2`, rescale threshold) is unchanged.
- `interface.py`: `SGLANG_FA4_TMEM_LOAD_RED_MAX` (default `1`; `0` restores the FMNMX reduction). It is part of the compile key, so both variants can coexist in one process. The flag is ignored on non-sm_103 GPUs.
- `vision.py`: the platform default multimodal attention backend is `fa4` for all compute capability 10.x (SM100 and SM103). Explicit `--mm-attention-backend` and per-model overrides (e.g. Kimi-K3-VL's own SM103 heuristic) are unchanged.
- `vision.py` (`VisionFlash4Attention`): accepts the graph runners' `[cu_seqlens, max_seqlen]` list. Unlike the fa3/triton wrappers it keys off the argument type, not the env var, so models without a graph runner keep passing tensors when `SGLANG_VIT_ENABLE_CUDA_GRAPH=1` is set globally.
- `vit_cuda_graph_runner.py`, `internvl_vit_cuda_graph_runner.py`: pass `fa4` the same layout as `fa3`. FA4 JIT-compiles a kernel variant the first time it sees a configuration, which must not happen inside stream capture; for windowed ViTs (Qwen2.5-VL) the generic runner therefore warms up both the windowed and the full-attention layout before capturing (it previously warmed up only block 0's layout). The InternVL runner already warms up every layer eagerly.
- `test_vision_backend_selection.py`: covers the CUDA default per compute capability (9.0→fa3, 10.0→fa4, 10.3→fa4, 12.0→triton_attn) and `VisionFlash4Attention` with list-form and tensor seqlens, with the graph env var on and off.

## Accuracy Tests

All on 8x B300 (sm_103, 148 SMs), CUDA 13.0, torch 2.13.0, nvidia-cutlass-dsl 4.6.2.

**FA4 kernel, bit-exactness.** 16 configurations run on the unpatched tree and on this branch with the flag on; outputs and LSE are identical in every case (`torch.equal`): causal / non-causal, varlen, chunked prefill (q < k), GQA and `pack_gqa`, head dims 64 / 96 / 128 / (192,128) (incl. the 2-CTA path), sliding window, learnable sink, softcap (reducing load disabled there), split-KV, paged KV (page 128 TMA and page 64 cp.async), and fp8 e4m3 with descales. The compiled PTX (`.target sm_103a`) contains 4 `tcgen05.ld.red` instructions with the flag on and none with it off.

**FA4 unit tests.** `test/registered/kernels/ops/attention/test_flash_attention_4.py`: 330 passed, 24 skipped, 0 failed.

**ViT attention, FA4 vs Triton.** sglang's own `VisionFlash4Attention` and `VisionTritonAttention` on the same inputs: max abs difference 5e-4 – 1.6e-2 in bf16 across GLM-5.3 / DeepSeek-V4.1 shapes (d=64) and Qwen2.5-VL shapes (d=80, windowed and full attention), consistent with bf16 rounding.
