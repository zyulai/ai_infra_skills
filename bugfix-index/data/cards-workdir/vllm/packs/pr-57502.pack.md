## 正文(PR 描述)

## Summary
`tests/v1/distributed/test_dbo.py::test_dbo_dp_ep_gsm8k[deepep_low_latency]` started crashing at engine init (memory profiling) on ROCm (MI300X) with DP+EP+DBO.

Root cause: after https://github.com/vllm-project/vllm/pull/5607, in the V1 `GPUModelRunner._dummy_run`, the MoE padding mask (`is_padding`) was computed **after** `num_tokens_padded` had been shrunk to a single microbatch for DBO forward-context bookkeeping. The mask only spanned one microbatch, so the DBO ubatch wrapper sliced an out-of-range (empty) mask for the trailing microbatch. That desynchronized the DeepEP low-latency combine across the two microbatches and crashed with:

```
AttributeError: 'NoneType' object has no attribute 'recv_hook'
ValueError: torch.cat(): expected a non-empty list of Tensors
```

## Fix
- Compute `is_padding` against the **full** padded token count, before the single-ubatch adjustment, so every microbatch gets a correctly sized mask.
- Route the dummy tokens through the experts during a **profile** run (instead of masking them all as padding), mirroring the ModelRunner V2 behavior so MoE memory is measured and the MoE kernels are exercised.

## Test
Verified on MI300X (2x, DP=2, EP, DBO, DeepEP built from ROCm/DeepEP):
- `test_dbo_dp_ep_gsm8k[deepep_low_latency]` -> PASSED
- `test_dbo_dp_ep_gsm8k[deepep_high_throughput]` -> PASSED
