## 正文(PRD / 提案全文)

### Motivation.

**I (@algebra-MCX) propose to enable zero-copy DeepEP low-latency combine, safe under DBO, and will lead the implementation and validation, subject to maintainer feedback.**

DeepEP LL combine currently runs with `zero_copy=False`, so DeepEP first copies the expert output into its communication buffer. That copy happens on every MoE layer of every decode step, which is the latency-critical path LL is designed for. With zero-copy, the experts write their output directly into the next combine buffer.

### Proposed Change.

**First slice:** CUDA, DeepEP LL with batched experts whose output layout matches DeepEP's combine buffer (`[num_local_experts, num_ranks * max_tokens_per_rank, hidden]`, BF16), DBO off and on.

1. **Provide the output buffer.** Implement `allocate_fused_expert_output` in the DeepEP LL prepare/finalize to return a view of DeepEP's next low-latency combine buffer (`get_next_low_latency_combine_buffer(handle)`) when the layout and dtype match, and `None` (current copy path) otherwise.
2. **Combine with `zero_copy=True`** only when the experts wrote into that buffer.
3. **DBO buffer ownership.** DeepEP alternates LL buffers per call. Under DBO the peer microbatch can issue an LL dispatch between this microbatch's buffer allocation and its combine, which would change which buffer is "next". The design must pin the buffer used by each microbatch (or fall back to the copy path under DBO) so that a microbatch never writes into a buffer the peer is using. This is the main open question, and it decides whether DBO is included in the first slice.

Out of scope: changes to DeepEP itself, DeepEP v2 and HT backends.

#### Completion criteria

- [ ] Default behavior unchanged when the layout does not match.
- [ ] Unit / kernel tests: zero-copy and copy paths produce identical combine results; buffer ownership with interleaved microbatch calls.
- [ ] 2×H200 DP2/EP2 with DeepSeek-V2-Lite (BF16 and FP8): identical outputs/logprobs with zero-copy on/off, with DBO on and off, and with FULL CUDA graphs.
- [ ] Per-layer combine time and decode TPOT, zero-copy on/off.
