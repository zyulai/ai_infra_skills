## Overview

Streaming a Qwen3 XML tool call re-parses the whole argument on every delta: `_qwen3_arg_converter`, then `_safe_arg_prefix`, a per-character Python loop over the full JSON. A long parameter value, such as a file written by a coding agent, costs quadratic CPU on the API server. This adopts the `arg_value_extender` hook from #61253 (GLM) and #61494 (Gemma4) for the Qwen3 grammar.

## Claims

- Parser cost per delta no longer grows with argument length: 1.1 ms at 12 KB and 2.2 ms at 25 KB become about 4 us at every size.
- A 12 KB `write_file` call (2,788 Qwen3 tokens) goes from 2.1 s to 11 ms of parser time. A 25 KB call goes from 8.4 s to 22 ms.
- Streamed deltas are unchanged, including newline trimming, schema coercion and truncated calls.
- Covers every parser on `qwen3_config` (qwen3_coder, qwen3_xml, Seed-OSS, Step3p5, Nemotron-v3, Granite thinking, MiniCPM-V). MiMo gets a variant without newline trimming, since its converter keeps values verbatim.

## Validation

`pytest tests/parser/engine`: 6026 passed. Also passed: the qwen3coder, step3p5 and minicpm5xml tool parser tests, the qwen3, nemotron_v3, granite_thinking and step3p5 reasoning tests, and `tests/parser/test_streaming.py`, `test_parse.py` and `test_abstract_parser.py`. ruff and mypy pass on the changed files.

New tests in `TestArgValueExtender`: long Qwen3 and MiMo calls with escapes, blank lines and prefixes of the closing tags stream the same arguments as `extract_tool_calls`; converter calls stay constant from 20 to 200 lines (they grow on `main`); a closer split across deltas and a split next `<parameter=`; and the cases where no extender is created.

A local differential fuzz streamed 27,500 random Qwen3 and MiMo calls with and without the extender: random chunk sizes, schemas with string, integer, boolean, object and nullable keys, repeated keys, whitespace-variant closers, tag fragments inside values, and truncated calls. Every per-delta `DeltaMessage` was identical, and about 194K deltas went through the extender. Breaking the newline hold-back, the split-closer window or the leading-newline strip made the fuzz fail.

Benchmark: `Qwen3Parser.parse_delta`, one real Qwen3 token per delta, Apple M5, Python 3.12, 7 alternating runs.

| Argument size | `main` | This PR |
| --- | --- | --- |
| 3 KB | 187-192 us | 3.9-4.1 us |
| 12 KB | 1.09-1.44 ms | 3.8-4.6 us |
| 25 KB | 2.21 ms | 3.8 us |

A short three-parameter call also gets about 10% faster (338 us to 304 us), because each delta skips a conversion. I couldn't run a GPU server end to end; model output is unchanged by construction.

## Details

The extender reads the open value with the same regexes as the converter. It refuses when the open key repeats an earlier one, since that key keeps its first position in the JSON. A delta that completes `</parameter>` or the next `<parameter=` (whitespace variants included, even split across deltas) returns None, and the converter takes over again. A future change to `_PARAM_RE` needs a matching change to `_PARAM_VALUE_END_RE`.

+def _param_value_extender(
+    raw_args: str, trim_newlines: bool

+    """Extend the open trailing ``<parameter=...>`` value of *raw_args*.
+
+    The extender streams exactly what the converter would for the same text.
+    With *trim_newlines* it follows ``_trim_wrapping_newlines``: it drops a
+    leading newline of the value and holds back a trailing one.
+    """
+    match = _PARTIAL_PARAM_RE.search(_PARAM_RE.sub("", raw_args))
+    if match is None:
+        return None
+    name, value = match.group(1), match.group(2)
+    # A repeated key keeps its first position, so its value is not last.
+    if any(m.group(1) == name for m in _PARAM_RE.finditer(raw_args)):
+        return None
+
+    window = _param_value_end_window(value)
+    started = bool(value)
+    held = "\n" if trim_newlines and value.endswith("\n") and value != "\n" else ""
