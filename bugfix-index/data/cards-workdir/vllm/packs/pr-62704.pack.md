## 正文(PR 描述)

## Overview

`ImageMediaIO.load_bytes` now catches Pillow's `SyntaxError` ("broken PNG file"), so a request containing a structurally-corrupted PNG fails with HTTP 400 instead of an unhandled HTTP 500.

Fixes #62703. Related: #60303 / #60308 cover the sibling `DecompressionBombError` case in the same except clause; this change covers the `SyntaxError` case, which that PR does not address.

## Claims

- A chat completion containing a corrupt PNG returns **HTTP 400** `BadRequestError: Failed to load image: broken PNG file (chunk ...)` instead of **HTTP 500** `InternalServerError` with the raw Pillow message.
- No behavior change for valid images, or for corrupt inputs already handled by the `OSError` / `UnidentifiedImageError` branches (they keep returning the same 400s).

## Details

**Root cause:** `ImageMediaIO.load_bytes` wraps decode failures in a client-facing `ValueError` (`"Failed to load image: ..."`), but its except clause only catches `(OSError, Image.UnidentifiedImageError)`. Pillow raises a plain `SyntaxError` for corrupted chunk structures — it is neither of those — so it escaped unwrapped. The request-level error mapper (`vllm/entrypoints/serve/exception_handling/error_response.py`) promotes `ValueError` to `BadRequestError` (400) but maps unmapped exceptions to `InternalServerError` (500), which is exactly what clients observed.

**Fix:** add `SyntaxError` to the existing except tuple. The wrapping pattern — and therefore the 400 path — already existed and is proven by the A/B table above. A genuine Python `SyntaxError` cannot occur inside this try block (it only calls Pillow and plain attribute reads), so the widened catch cannot mask unrelated failures.

**Not a duplicate:** #60308 (open) adds `DecompressionBombError` to the same clause but does not handle `SyntaxError`; searches of open issues/PRs for "broken PNG" return no results. The two changes compose trivially if both merge.

**Model evaluations:** not applicable — the change only affects how invalid client input is surfaced (HTTP status/message of the error path); it cannot alter model output for accepted requests.

**AI assistance:** this change was prepared with AI assistance (GLM-5.3 via OpenCode) under the direction of, and fully reviewed line-by-line by, the human submitter, who ran all tests and end-to-end validations above.
