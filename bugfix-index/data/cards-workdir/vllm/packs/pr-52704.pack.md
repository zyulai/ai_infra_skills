## 正文(PR 描述)

## Purpose

`OCP_MXQuantizationEmulationTritonExperts` overrides the `quant_dtype` property with a scheme→dtype map built in `__init__`. For the four mxfp6-activation schemes that map produced `"mxfp6"` — not a key `moe_kernel_quantize_input` dispatches on, which knows `"mxfp6_e3m2"` and `"mxfp6_e2m3"`. Those schemes therefore fall through to the dispatcher's closing `else: return A, A_scale` and run with **unquantized activations**. Nothing raises; the emulation just quietly stops emulating, and accuracy numbers for these schemes come out optimistic.

Affected schemes:
- `w_mxfp4_a_mxfp6_e3m2`
- `w_mxfp4_a_mxfp6_e2m3`
- `w_mxfp6_e3m2_a_mxfp6_e3m2`
- `w_mxfp6_e2m3_a_mxfp6_e2m3`

### Solution

Map each scheme to the concrete dtype, and extract the mapping into `activation_quant_dtype` so it can be tested without standing up a full `FusedMoEConfig`. The chain also had no arm for `w_mxfp6_e2m3_a_fp8`, which left `_quant_dtype` unset and would raise `AttributeError` from the `quant_dtype` property; it now takes the fp8 path with its siblings, and an unhandled scheme raises `NotImplementedError` instead of falling through.

### End-to-end failure

Two MoE forwards through `FusedMoEModularKernel` with `OCP_MXQuantizationEmulationTritonExperts`:
- one for `w_mxfp4_a_mxfp6_e3m2`
- one for the weight-only `w_mxfp4`
same quantized weights, same activations, same routing, only the scheme differs. The first is supposed to fake-quantize
activations and the second is not, so their outputs must differ. 
However, on `main` they are bit-identical:

```
E   AssertionError: w_mxfp4_a_mxfp6_e3m2 MoE output is bit-identical to the weight-only
E   w_mxfp4 scheme (max|diff| = 0.0): the emulation never fake-quantized the activations
E   assert 0.0 > 0.0
FAILED test_a_mxfp6_e3m2_moe_fake_quantizes_activations_end_to_end
1 failed in 7.63s
```

With this PR the QDQ reaches the layer output (E=8, topk=2, hidden=256, intermediate=256, 64 tokens, bf16, MI325X):

```
max|a_mxfp6_e3m2 - w_mxfp4| = 1.875   mean|diff| = 0.2942
|w_mxfp4| max = 26.2500  mean = 3.1170   ->  9.44% mean shift
1 passed in 8.24s
```

That ~9% mean shift in the MoE output is precisely the emulation error these schemes are meant to model, and were not.

## Test Plan

Add a test case `test_emulation_activation_quant_dtype_is_dispatchable` in `tests/kernels/moe/test_ocp_mx_moe.py`
