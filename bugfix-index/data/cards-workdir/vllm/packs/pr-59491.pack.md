## 正文(PR 描述)

## Purpose

Fixes an off-by-one in `get_cached_tokenizer`'s `max_token_id`. Reported as GHSA-q97c-p368-75c4; the VMT rated it moderate and asked for a public PR.

`max_token_id` is the largest valid token id, inclusive:

- `InputProcessor._validate_model_input` rejects prompt ids above `max(tokenizer.max_token_id, model_vocab_size - 1)`.
- `SamplingParams` rejects `token_id > tokenizer.max_token_id` and reports the vocab size as `max_token_id + 1`.
- `MistralTokenizer` sets `_max_token_id = vocab_size - 1`, and `KimiAudioTokenizer` returns `n_vocab - 1`.

`vllm/tokenizers/hf.py` instead takes `max(max(get_vocab().values()), tokenizer.vocab_size)`. `vocab_size` is a count, so for tokenizers whose largest id is `vocab_size - 1` (Llama-2 family, GPT-2, ...) it returns `vocab_size`, one past the last id.

For a model whose embedding has exactly `vocab_size` rows (32000 is a multiple of the 64-row padding, so Llama-2-family models get no padding rows), a prompt containing id `vocab_size` passes the engine's check. At TP=1 the embedding does not mask the index, and the lookup fails with a CUDA device-side assert.

The fix uses `vocab_size - 1`. `max(get_vocab().values())` stays the primary source, so tokenizers whose added tokens sit above `vocab_size` (e.g. Qwen2.5) are unchanged.

| Tokenizer | `max_token_id` before | after |
| --- | --- | --- |
| TinyLlama/TinyLlama-1.1B-Chat-v1.0 (vocab 32000) | 32000 | 31999 |
| openai-community/gpt2 (vocab 50257) | 50257 | 50256 |
| Qwen/Qwen2.5-1.5B-Instruct | 151664 | 151664 |

I found no open PR for this.
