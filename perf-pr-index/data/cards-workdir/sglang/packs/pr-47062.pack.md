## Motivation

<!-- Describe the purpose and goals of this pull request. -->
AITER varlen routed every varlen call on gfx942 to AITER's Triton kernel, working around a hang on MiniMax-H3's packed sequences reported in #33275. The condition was architecture alone, with no shape, length or head-count qualifier, so MI300X/MI325X never reached the FAv3 kernel for any model or any shape.

The hang does not reproduce. 
Across every varlen shape H3 submits, all four Ulysses degrees, 28K to 104K rows, including the zero-length second segment that occurs whenever the used length is a multiple of 64, the FAv3 kernel completes and is 6.6-27% faster (median 15.1%), matching the Triton output to bf16 accumulation noise. 

Also enables RTZ rounding mode for varlen as well, similar to how it's enabled for non-varlen. Affects only gfx942 and gives a boost in perf like in #28650. Safe to enable for non-gfx942 systems as well - it's just ignored.
