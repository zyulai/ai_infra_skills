## Overview

Fixes #53477. DFlash and DSpark preserve the target KV cache and do not require the EAGLE-style trailing prefix-cache block drop. Scoping that drop correctly restores reusable Mamba checkpoints in `--mamba-cache-mode align` and prevents full-context recomputation on subsequent replies.

## Claims

- DFlash/DSpark no longer drop the last prefix-cache block solely because `SpeculativeConfig.use_eagle()` also matches those methods.
- Existing EAGLE/EAGLE3/MTP behavior is unchanged, including the `disable_eagle_block_drop` opt-out and its warning.
- `use_eagle()` remains unchanged for encoder shift, lookahead budgeting, and other existing specification-decoding behavior.

## Details

### Root cause

`SpeculativeConfig.use_eagle()` is a broad predicate for speculative decoding that reads target hidden states, and it intentionally matches `eagle`, `eagle3`, `mtp`, `dflash`, and `dspark`. #53388 derived `use_eagle_block_drop()` from that broad predicate.

EAGLE-style drafters construct a position's draft KV from the target hidden state **and the next token**. DFlash/DSpark construct it from the target hidden state alone. Therefore only EAGLE/EAGLE3/MTP need the trailing EAGLE block drop; both DFlash and DSpark preserve the target KV cache.

For a prompt shorter than two Mamba blocks, the spurious back-off produced this sequence:

1. `last_cache_position == 0`, so the prompt was a single chunk ending off the Mamba block grid.
2. Mamba align mode only materializes a reusable recurrent state at a block-aligned chunk end.
3. `HybridKVCacheCoordinator.find_longest_cache_hit()` converged the next turn's hit to zero, causing full-context recomputation.

### Implementation

- `vllm/config/speculative.py`: add `needs_eagle_block_drop()` for the precise EAGLE/EAGLE3/MTP capability, and compose `use_eagle_block_drop()` from it plus `disable_eagle_block_drop`.
- `vllm/v1/core/sched/scheduler.py`: reuse `needs_eagle_block_drop()` in the warning condition. The existing split back-off, `KVCacheManager(use_eagle=...)`, offloading, and Mooncake paths now receive `False` for DFlash/DSpark without changing `use_eagle()`.
- `tests/test_config.py`: parameterize the existing config test over EAGLE3/MTP (drop) and DFlash/DSpark (no drop), both with the opt-out enabled and disabled.
- `tests/v1/core/test_scheduler.py`: set the now-separate `use_eagle_block_drop` scheduler value in the Mamba-align EAGLE fixture.

The change is limited to the prefix-cache trailing-block policy. EAGLE/EAGLE3/MTP retain the previous default behavior, and the existing explicit opt-out remains available.
