## Motivation

Qwen-Image-Edit's Hopper profile contains repeated QK normalization/RoPE and joint-QKV concatenations in the DiT, plus 96 separate SDPA window calls per window-attention layer in the vision encoder. Reuse the existing Qwen QKV epilogue on Hopper and process packed vision windows through PyTorch's public varlen attention API.

On one H200 with main's PyTorch 2.13 dependencies, lossless eager engine E2E falls from **32.8171 s to 32.3141 s (1.533%)**. All saved before/after images are byte-identical within each quality mode. This is a modest combined full-model gain; the much larger microbenchmark ratios do not represent E2E speedups.

## Modifications

- Enable the existing BF16, batch-one, head-dimension-128 QKV epilogue for eligible unquantized SM90 Qwen attention. Support independent image/text token strides; retain mask, shard/padding, layout and alignment fallbacks and the existing environment opt-out.
- Vectorize adjacent RoPE-cache loads and paired V-head copies, and move Q/K/V dispatch into the grid's second dimension. Explicit `fmaf`/`fmul` preserves the original RoPE contraction and intermediate rounding. Odd head counts retain a smaller final copy.
- Use public `torch.nn.attention.varlen.varlen_attn` for eligible Hopper Flash SDPA inference with packed windows. No token reordering or padding. CPU/HIP/MPS, other SDPA subclasses, compilation, gradients, dropout, missing API, and unsupported inputs retain the existing path. The new SDPA dispatch is SM90-only; the shared QKV kernel also serves the existing SM100 path, whose B200 regression now passes CI (14 QKV epilogue tests).
- Update the kernel inventory's SM90 capability and extend the existing kernel, model-path and registry tests.

### Kernel and profile evidence

The initial trace identified actual DiT shapes of 8,152 image tokens and 1,365/1,358 text tokens, 24 heads, head dimension 128. Vision attention has 5,400 tokens over 96 ragged windows, 16 heads, dimension 80. Measurements below are cumulative GPU kernel durations from separate tiny Torch 2.11 traces, excluding CPU launch gaps; they are not full request timings.

| Production operation | Baseline kernels / device time | Candidate kernels / device time |
| --- | ---: | ---: |
| QK norm + RoPE + joint QKV, 8,152 + 1,365 tokens | 7 / 179.617 µs | 1 / 109.023 µs |
| Packed vision SDPA, 5,400 tokens / 96 windows | 96 / 517.984 µs | 2 / 38.240 µs |

The two SDPA kernels are FlashAttention and an auxiliary zero-RNG fill; dropout is zero and no random numbers are consumed. Copy events are separate from kernel counts. QKV input restoration is outside the timed interval; the reference's packed-input materialization cost is conservatively excluded.

NCU localized 7,309,056 excess L2 sectors to four stride-two scalar RoPE-cache loads. Vector loads remove those sectors, but alone do not improve duration (121.248 → 121.760 µs). Paired V-head copies alone regress to 131.840 µs; hoisting dispatch/index work into `grid.y` reduces it to **112.544 µs**, with 63,691,368 executed instructions and 93.204% occupancy. Explicit FMA operations are necessary to retain bit-exact arithmetic. These are NCU diagnostics with clock/cache control disabled, not E2E measurements.

The final matched Torch 2.13 full-stage captures contain two denoising steps each. Overlapping image-encoding GPU annotations are unioned before counting each kernel once; no boundary-crossing kernels were found.

| Rank-0 stage, two-step request | A kernels → B kernels | A cumulative GPU time → B |
| --- | ---: | ---: |
| Denoising | 7,113 → 5,673 | 1,233.223 → 1,221.776 ms |
| Image encoding | 11,042 → 5,778 | 190.449 → 164.337 ms |

Other stage kernel counts are unchanged. The vision reduction is 56 window-attention invocations × (96 − 2) = 5,264 launches. These short instrumented requests establish the changed paths; the full 50-step unprofiled ABBA establishes E2E.
