## PR body
```markdown
- Build `persistent_topk`, its FilteredTopK and sampled_topk tiers, and the shared exact overflow recovery from #62936 with hipcc (wave64-safe `TOPK_*` ballot/shuffle macros, HIP acquire load, clang-compatible `exact_topk_rescan` defaults).
- On gfx950 (at least 144 KiB of LDS), run every batch through `sampled_topk_kernel`, one workgroup per row, and cut clustered rows at the exact sampled rank. gfx942 keeps the persistent kernel. Return early on an empty batch.
- Place the decode logits of `rocm_fp8_paged_mqa_logits` after the top-k workspace, so `persistent_topk`'s row states no longer overwrite them.
- Allow the explicit `persistent` sparse-indexer backend on ROCm; `auto` still resolves to `per_row`.
- Route `cooperative` / `persistent` through `SparseIndexerTopk._row_ends`, so `(B,)` `seq_lens` with `next_n > 1` no longer raise "lengths size mismatch".
- Run the `persistent_topk` tests on ROCm, including #62936's candidate-overflow cases, add a test for the logits overlap, and add `persistent` to `benchmark_top_k_per_row_decode.py`.
- Document `persistent` on ROCm in the `KernelConfig` docstring, and run the persistent top-k tests in the MI355 DeepSeek V4 kernels step (MI300 already runs the file).

On ROCm the sparse indexer could only use the in-tree `per_row` top-k or AITER, and asking for `persistent` failed because the op was compiled out. This PR builds it on top of #62936, which is now merged and makes the persistent and filtered paths exact on candidate overflow, so the ROCm-only rescan forks from earlier revisions are gone and ROCm shares that code. Wiring it into GLM-5.3-Flash showed that its decode logits and the top-k workspace both start at offset 0 of the shared workspace, which corrupts row 0 whenever the multi-CTA path runs (gfx942). CUDA is not affected, because its paged MQA logits are not workspace views, and ROCm on main is not either, because it rejects this backend. The backend stays opt-in, so default ROCm top-k selection does not change, but on gfx942, gfx950 and RDNA the decode logits now sit 1 MiB further into the workspace for every backend. On MI355X with k=2048 it is 2.2-2.6x faster than `per_row` and on par with AITER, and in GLM-5.3-Flash serving on this revision it selects exactly what `per_row` selects, with unchanged GSM8K 25-shot accuracy and throughput. This branch is stacked on #62298 (head b47c6178f1), so until that merges the diff against main includes #62298; this PR's own changes are `a2f04ca777..11871cef49` and `2fe6f7e5df`, plus merges of main and #62298.
```

```
**gfx942 dispatch (persistent kernel).** On MI300X (`sharedMemPerBlockOptin` is 64 KiB, so the persistent kernel runs instead of `sampled_topk`), the persistent group gave 176 passed, 80 skipped in 10 of 10 runs; the skips are the sampled-top-k tests that need 144 KiB of LDS and the CUDA-only backends. Before MI300X was available, a local build that capped `max_smem_per_block` and occupancy at 64 KiB on MI355X gave the same counts, and the stress run on it gave 2,000 cases with 0 failures. The cap was never committed.

**Logits overlap.** `rocm_fp8_paged_mqa_logits` returned its logits at workspace offset 0, the same place `SparseIndexerTopk` takes the `persistent_topk` workspace from. On the multi-CTA path the op clears its per-group row states there (`cudaMemsetAsync` in `topk.cu`) and then keeps barrier counters and histograms in them. In GLM-5.3-Flash serving with gfx942 dispatch this made 17,346 of 18,964 calls return wrong rows, all in row 0. The logits now come from the same `get_simultaneous` call as a top-k slot in front of them, and the profiling reservation uses the same layout. `test_persistent_topk_on_rocm_paged_mqa_logits` changed 3,088 logits (four groups' row states) with gfx942 dispatch before the fix and none after. On MI300X the test fails the same way with the logits moved back to offset 0 and passes with the fix:

```
pytest tests/kernels/test_top_k_per_row.py -k test_persistent_topk_on_rocm_paged_mqa_logits   # MI300X
1 failed: Tensor-likes are not equal! Mismatched elements: 3088 / 327680 (0.9%)   # logits at offset 0
1 passed                                                                          # this PR
```

Native gfx950 never runs that path, so there it passes either way; ROCm CI runs `test_top_k_per_row.py` on MI300, and the persistent group on MI355.
```
