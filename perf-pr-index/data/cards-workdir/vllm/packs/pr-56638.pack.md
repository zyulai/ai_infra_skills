## PR body
```markdown
## Purpose

ROCm's V4.1 sparse prefill combines the top-k and sliding-window indices with ordinary Torch indexing, about ninety small ops per call. This sends it to the shared `combine_topk_swa_indices` kernel the CUDA path already uses: one launch, and it brings the SWA bounded-replay bound, the SWA-only guard and the JIT warmup with it. The ROCm-only Triton kernel and the Torch path are removed.

## What changes

- `amd/rocm.py`: prefill calls `combine_topk_swa_indices` from `common/ops/cache_utils.py`.
- The shared kernel gains two guards that leave well-formed input untouched:
  - both lengths clamp at 0. Warmup batches reach it with a negative position, and the Torch path had `clamp_min(0)` for that;
  - a negative top-k index stays -1 instead of becoming `M * b - 1`, a row of the previous request.

## Tests

`tests/kernels/attention/test_rocm_triton_attn_dsv4.py` compares the kernel against the Torch path it replaces, copied over unchanged so the reference cannot drift toward the kernel: `seq_len` below `query_len`, `seq_len == 0`, `compress_ratio == 0`, a non-zero `query_start_loc[0]`, -1 candidates, and windows 64/128/256. It also checks that ROCm dispatches to the shared kernel. `test_v41_combine_topk_swa_stops_at_replay_start` covers the replay bound on that kernel. It runs on ROCm as well, and now includes the shorter replay chunk from #59136 (co-authored by @yuzhouo7), so #59136 is no longer needed.
