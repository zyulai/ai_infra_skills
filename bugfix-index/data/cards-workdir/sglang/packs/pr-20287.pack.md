## Motivation
During initialization the wait loop only monitored the rank it was currently reading from, so if another rank was killed the process would block on recv() indefinitely, causing the entire launch to hang.

### How to Reproduce
1. Create a case where some ranks get killed but rank 0 stays alive—e.g., run the container with a memory limit far below the total --hicache-size across all TP workers.
`docker run --gpus all --memory=100g --memory-swap=100g ...`
2. launch sgl
```bash
 python -m sglang.launch_server \
    --model-path Qwen/Qwen3-32B-FP8 \
    --enable-hierarchical-cache \
    --mem-fraction-static 0.1 \
    --tp 8 \
    --hicache-size 15
```
As workers allocate memory one by one, the OS OOM killer silently SIGKILLs some of the later workers. However, the launcher only blocks on pipe.recv() for rank 0 in iteration order — if rank 0 happens to survive while a higher-rank process is killed, the launcher hangs indefinitely waiting for a response that will never come, with no error message.
