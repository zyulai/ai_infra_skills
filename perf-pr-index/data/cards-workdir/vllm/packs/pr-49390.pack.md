## Summary

Raise the default `max_cudagraph_capture_size` ceiling from 512 to 1024 on data center Blackwell GPUs (compute capability 10.x). Other platforms retain the 512 default, and explicit user configuration remains unchanged.

The existing `max_num_seqs * decode_query_len * 2` bound still applies, so workloads whose calculated capture size is 512 or smaller are unaffected.

## Motivation

On B300, a DeepSeek-V4-Flash DSpark workload with fixed verification (7 draft tokens; adaptive/confidence-based verification disabled) ran substantially faster when the CUDA graph capture ceiling was raised from 512 to 1024.

| Concurrency | 512 output tok/s | 1024 output tok/s | Change |
| ---: | ---: | ---: | ---: |
| 64 | 1,127 | 7,559 | +571% |
| 128 | 904 | 5,101 | +464% |
| 256 | 977 | 4,812 | +393% |

At concurrency 128, mean TPOT improved from 98.77 ms to 18.38 ms. Capturing up to 1024 took 80 seconds and 4.88 GiB per GPU in this configuration.

Hardware tested: NVIDIA B300 SXM6 AC. B200 validation is still pending, which is why this PR is being opened as a draft.

## Duplicate-work check

I searched open PRs for `max_cudagraph_capture_size 1024`, Blackwell CUDA graph capture sizing, and B200/B300 CUDA graph defaults. No PR changes this default. #46324 is related but addresses speculative-decode capture-size alignment, not the maximum capture ceiling.

## Tests

## Model evaluation

No accuracy evaluation was run because this changes CUDA graph coverage rather than model computation or sampling behavior. The serving benchmark completed all 256 requests with zero failures at each measured concurrency.
