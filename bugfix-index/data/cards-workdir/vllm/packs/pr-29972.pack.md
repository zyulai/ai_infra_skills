## 正文(PR 描述)

## Purpose

Fixes #24170 

Resolves `ValueError: Unknown recipient: None` crash in `harmony_utils.py` when gpt-oss models generate commentary channel preambles (explanatory text before tool calls) without a specific recipient.

**Root Cause**: 
Per [Harmony format docs](https://cookbook.openai.com/articles/openai-harmony), the commentary channel can contain "preambles to calling multiple functions." When instructions prompt the model to generate explanation text alongside tool calls, gpt-oss-120b generates these preambles in the commentary channel with `recipient=None` (since they're not addressing a specific function). The parser crashed because it only handled commentary with specific recipients like `functions.X`, `python`, `browser`, or `container`.

**Impact**: 
Stream terminates prematurely after successfully sending reasoning chunks, never sending `response.completed`. Clients see "Premature end of chunk coded message body: closing chunk expected."

## Solution

Modified `parse_output_message()` in `vllm/entrypoints/harmony_utils.py` to handle `recipient=None` in commentary channel by treating it as reasoning text (semantically correct since preambles are explanatory content).

**Code Change**:
```python
elif message.channel == "commentary":
    if recipient is not None and recipient.startswith("functions."):
        # ... create function call ...
    elif recipient is None or (  # ← Added recipient is None
        recipient.startswith("python")
        or recipient.startswith("browser")
        or recipient.startswith("container")
    ):
        # ... create reasoning item ...
    else:
        raise ValueError(f"Unknown recipient: {recipient}")
```
