## 正文(PR 描述)

## Summary

Expand ROCm CI coverage by exposing tests to the `amdproduction` mirror hardware signal, and fix a heap corruption bug in GPU memory queries that was causing flaky failures on MI325.

## AMD production CI coverage

Added `amdproduction` to `mirror_hardwares` across test labels in `test-amd.yaml` so that the external AMD CI pipeline can optionally pick up and run a broader set of tests. This gives production validation visibility into tests that were previously only running on `amdexperimental` or not mirrored at all.

## amdsmi thread-safety fix

Distributed tests on ROCm intermittently crash with:
```
malloc(): unsorted double linked list corrupted
Fatal Python error: Aborted
  File "amdsmi_interface.py", line 1901 in amdsmi_init
```

The `_nvml()` context manager in `tests/utils.py` was calling `amdsmi_init()`/`amdsmi_shut_down()` on every GPU memory query. When `RemoteOpenAIServer` queries memory from concurrent threads during server startup/teardown, these non-thread-safe calls race and corrupt the heap.

Fix: initialize `amdsmi` once at module import, register shutdown via `atexit`. Applied the same pattern to `pynvml` for consistency. No changes to caller interfaces.
