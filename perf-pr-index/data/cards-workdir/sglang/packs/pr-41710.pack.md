```markdown
## Motivation

Triton compiles one variant of a kernel per class of each integer argument it specializes: divisible by 16, equal to 1, or neither. Sequence lengths and row counts change with the resolution, the prompt and the input image, so a request whose sizes fall into a class the server's warmup did not hit compiles kernels on the spot.

Qwen-Image-Edit shows it on the nightly's first request. The server warmup conditions on a square image, giving 8192 tokens; the nightly's 1024×704 input gives a count not divisible by 16. With a cold Triton cache (a fresh machine or container), that first request spent 1.95 s in its first denoising step against 0.34 s for later steps. The Triton cache shows what compiled during that request: the select-0/1 LayerNorm modulation kernel, its residual variant and the LayerNorm-modulate kernel, each a second variant whose TTIR signature differs from the warmup's only in `seq_len` and `stride_i_b` losing `tt.divisibility = 16`.

## Modifications

The per-request sizes of these kernels go into `do_not_specialize`:

| Kernel | Arguments |
| --- | --- |
| `_fused_layernorm_scale_shift_gate_select01_kernel`, `_fused_residual_layernorm_scale_shift_gate_select01_kernel` | `seq_len`, `stride_i_b` |
| `_fused_scale_shift_4d_kernel` | `seq_len`, `num_frames`, `frame_seqlen` |
| `fuse_scale_shift_kernel_blc_opt` | `B`, `L` |
| `_layernorm_modulate_kernel` | `seq_len`, `n_rows` |
| `_qk_ln_head_kernel` | `n_rows` |
| `_temb_table_slices_kernel` | `rows` |
| `_pack_qkv_destination_major_kernel` | `rows` |
| `_cat_pad_cl3d_kernel` (Wan VAE) | `T`, `H`, `W`, `out_t`, `out_h`, `out_w` |
| `_dup_up3d_add_kernel` (Wan VAE) | `out_t`, `out_h`, `t_offset` |

Each of these arguments only feeds a row index or a row mask, while the loads and stores vectorize along the hidden dimension (the channels, for the VAE kernels), whose size and strides stay specialized. The arithmetic is unchanged and outputs are bit-identical. `mrope.py` and `vision_rope.py` already do the same for their sequence lengths.

The Wan VAE kernels keep more of their arguments specialized: the channel count, the element total and the strides, which the channel vectorization relies on, and the per-layer padding and cache length, whose constant folding is worth 1.5% of the cat/pad kernel's time. In the channels-first traversal of the DupUp3D kernel the output width is the contiguous dimension, so it stays specialized too. With channels a multiple of 16, those arguments stay in one class at every resolution.

## Accuracy Tests

- New `test/registered/kernels/ops/diffusion/test_shape_specialization.py`: each launch runs at a length divisible by 16, then at 57 and at 1 (frames only, for the VAE kernels), and a `triton.knobs.runtime.jit_post_compile_hook` asserts that the last two compile nothing. All 11 cases fail on main and pass with this change.
- The existing tests of these kernels pass unchanged (`test_modulate.py`, `test_layernorm_modulate.py`, `test_layout.py`, `test_wan_temb_table_slices.py`), including the bitwise cat/pad, DupUp3D and chunked causal-conv tests.
- Specialized and unspecialized variants give `torch.equal` outputs on the same inputs.
```
