## 正文(PRD / 提案全文)

### Motivation.

The Bailing Ling-2.6-flash model from Ant Group features a Multi-Token Prediction (MTP) mechanism, which is effective in accelerating inference by predicting multiple tokens in a single pass.

I noticed that while this architecture is currently supported in sglang, there does not appear to be native support for this MTP mechanism in vLLM yet. I hope that implementing this could serve as a modest yet helpful addition to vLLM for users who rely on this model family. I would greatly appreciate your feedback on whether this aligns with the project's development direction.

### Proposed Change.

The goal is to implement Bailing-native MTP (Multi-Token Prediction) support by integrating the draft generation logic into vLLM's existing speculative decoding pipeline. Key components of the change include:

Model Architecture Definition: Implement BailingMTPModel to handle the specific tensor shapes and the auxiliary MTP head required by Ling-2.6-flash.

Registry & Mapping: Register the new model architecture in vllm/model_executor/models/registry.py to allow the framework to correctly dispatch the model to the MTP-aware draft worker.

Draft Worker Integration: Extend the speculative decoding worker to support the specific state-passing mechanism required for Bailing’s MTP, ensuring consistency with vLLM’s existing PagedAttention and KV-cache architecture.

Weight Mapping: Add a conversion script to map Bailing’s MTP-specific weights to vLLM’s internal format, ensuring the hybrid architecture (main model + MTP head) is loaded correctly.
