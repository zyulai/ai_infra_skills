## What

Generalizes the persistent MXFP4 decode MoE kernel from #48638 (Kimi-K3.1 TP8 only) to any per-rank shape it covers, and wires it into the DeepSeek-V4 / V4.1 MXFP4 path as well. Still opt-in.

- Kernel (`moe/mxfp4_decode/moe_mxfp4.cuh`, moved from `moe/k31_decode/`): shape traits `<E, top-k, H, I, BlockN>` instead of hard-coded K3.1 constants. The FC1 activation is a template function argument: `situ<beta, linear_beta>` or `swiglu<limit>` (clamped SwiGLU, as flashinfer's fused FC1 epilogue). Routing reads ids flat (any top-k) and takes an EP expert offset; non-local and `-1` ids get `expanded_idx = -1`. One host entry launches routing + MoE with one workspace. The FC1 / FC2 claim prefetch is a template argument.
- Small-T scheduling: a CTA holds at most two FC1 items (early CTAs no longer hoard the queue), and the routing kernel is instantiated for the bitmask words a call needs.
- Op `sglang.kernels.ops.moe.mxfp4_decode_moe` (replaces `k31_decode_moe`): `activation` + `activation_constants`, `expert_offset`, `is_supported_shape()`.
- Engine: one flag `SGLANG_USE_CUDA_MXFP4_DECODE_MOE` (default off; `SGLANG_K31_DECODE_MOE` kept as a deprecated alias). Every layer whose shape, activation and MXFP8 activations the kernel covers uses it for calls with <= 256 tokens; anything else runs flashinfer. Wired into `Mxfp4MoEMethod` (SiTU, now with EP) and `Mxfp4FlashinferTrtllmMoEMethod` (DeepSeek-V4 / V4.1 SwiGLU limit), sharing `run_cuda_mxfp4_decode_moe`.
