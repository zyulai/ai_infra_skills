## Motivation

As reported by GLM team @zRzRzRzRzRzRzR , when processing large videos (>100MB), GLM-4xV model is extremely slow and is very likely to OOM.

## Modifications

The issue is `preprocess_video` logic implemented in SGLang is not as optimized as the one implemented in transformer: [[1]](https://github.com/huggingface/transformers/blob/266d3b05684ed5968c613f00b208909f03c72c0e/src/transformers/models/glm4v/video_processing_glm4v.py#L151) [[2]](https://github.com/huggingface/transformers/blob/266d3b05684ed5968c613f00b208909f03c72c0e/src/transformers/models/qwen3_vl/video_processing_qwen3_vl.py#L174)

I think ideally we should reuse the preprocess_video logic implemented by model owners in transformer if possible instead of duplicating the logic in SGLang which may easily get out-dated and cause tricky performance issues
