## 正文(PRD / 提案全文)

### Motivation.

Recent work has made tree-based drafting a major direction in speculative decoding. By proposing multiple continuations per step, a draft tree can increase the number of tokens accepted in one target verification pass. [PCTree](https://arxiv.org/abs/2608.02123), [DARTree](https://arxiv.org/abs/2608.13524), [PRESTO](https://arxiv.org/abs/2607.22634)

This RFC builds on [vLLM RFC #65813](https://github.com/vllm-project/vllm/issues/65813) and details how vLLM schedules, verifies, and commits draft trees, drawing on the Ascend prototype. [vLLM-Ascend RFC #18797](https://github.com/vllm-project/vllm-ascend/issues/18797)

### Proposed Change.

### Execution flow

| Stage | Responsibility |
| --- | --- |
| Propose | Produce a bounded tree of candidate continuations. Publish flattened candidate token IDs and retain their topology with the matching worker request state. |
| Schedule and prepare inputs | Account for the candidate rows and their KV slots. When trimming a tree to fit, retain an ancestor-closed subset. Keep the flat candidates and topology associated with the same request and draft step. |
| Verify | Assign position IDs by depth and distinct temporary KV slots by node. Each query can attend to the committed prefix and its own path through the tree, including itself. |
| Select a path | Starting from the root, match each token selected by the target to a child. Stop at a missing match or a leaf and emit the target token, subject to normal stop and length handling. |
| Commit | Keep the root and commit the accepted nodes in path order. Update request state and gather any target hidden states needed for the next draft in that same order. |
