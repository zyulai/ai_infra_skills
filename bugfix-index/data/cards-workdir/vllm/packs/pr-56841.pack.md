## 正文(PR 描述)

Fixes `ExampleHiddenStatesConnector` abort-path crash.

## Purpose

`ExampleHiddenStatesConnector.request_finished()` crashes `EngineCore` when a
request is aborted while still **waiting** (i.e. before it was ever scheduled) —
the common case when an API client times out and cancels queued requests.

`_request_filenames` is only populated in `build_connector_meta()` for
`SchedulerOutput.scheduled_new_reqs`. A request aborted before its first
schedule never reaches that code, but `Scheduler.finish_requests()` still calls
`request_finished()` for waiting requests, where the unconditional
`self._request_filenames.pop(req_id)` raises:

```
example_hidden_states_connector.py request_finished
    filename = self._request_filenames.pop(req_id)
KeyError: 'cmpl-b98ee80d8ff99a38-0-8e7006c7'
```

The `KeyError` becomes `EngineCore encountered a fatal error`; every API server
process then dies and clients see a storm of `APIConnectionError`.

This is the connector-side counterpart of the scheduler-side stale-completion
crash tracked upstream:
- https://github.com/vllm-project/vllm/issues/46240
- https://github.com/vllm-project/vllm/pull/46304
- https://github.com/vllm-project/vllm/pull/53079

### Changes

1. `request_finished` uses `pop(req_id, None)`; when no filename was recorded
   (aborted before scheduling) it drops residual `_pending_saves`/`_lock_fds`
   state and returns `(False, None)` — no hidden states to save, no blocks to
   delay.
2. `request_finished_all_groups` no-ops when the per-group block table is
   missing instead of indexing out of bounds.
3. `get_finished` only reports `finished_sending` for requests it actually
   tracked (a submitted DtoH copy); abort/never-scheduled requests no longer
   trip `assert req_id in self.requests` in `_update_from_kv_xfer_finished()`.
4. `get_finished_count()` returns `1`: only TP rank 0 writes hidden states, so
   exactly one completion notification is expected per request; without this,
   `KVOutputAggregator` waits for `world_size` notifications.

(3) and (4) are coupled: (3) alone would never complete a request; (4) alone
would let non-writer ranks report before rank 0's copy finishes, freeing KV
blocks too early.

## Test Plan

New CPU-only unit test
`tests/v1/kv_connector/unit/test_hidden_states_connector_abort.py`:

```bash
python -m pytest tests/v1/kv_connector/unit/test_hidden_states_connector_abort.py -q --noconftest
```

Covers:

- `request_finished` on a never-scheduled request returns `(False, None)` (no `KeyError`)
- `request_finished_all_groups` handles a missing group table
- `get_finished` does not report an untracked/aborted request
- `get_finished` reports a tracked request once its copy completes
- `get_finished_count() == 1`

## Test Result

```
$ python -m pytest tests/v1/kv_connector/unit/test_hidden_states_connector_abort.py -q --noconftest

```

End-to-end: on vLLM 0.26.0 + vllm-ascend (Ascend NPU) during online DSpark
hidden-state training, aborting queued requests (client timeouts) previously
fataled `EngineCore` with the `KeyError` above; with this change the engine
survives abort storms and training runs to completion. Reproducer: send a batch
of long-prompt requests, let some time out and get aborted while queued.
